# Learning Skill

## Overview

Acquire new technical knowledge efficiently and retain it for long-term use. This skill provides strategies for learning new languages, frameworks, tools, and concepts effectively.

## Core Competencies

- **Rapid Surveying**: Map a new technology's scope, prerequisites, and core concepts in under an hour
- **Active Recall & Spaced Repetition**: Use evidence-based techniques to retain knowledge long-term
- **80/20 Focus**: Identify and prioritize the 20% of features used 80% of the time
- **Deliberate Practice**: Target weak areas with focused exercises and mini-projects
- **Knowledge Transfer**: Teach what you've learned to solidify understanding and reveal gaps

## When to Use

- Starting with a new programming language or framework
- Exploring unfamiliar libraries or APIs
- Understanding complex systems or architectures
- Preparing for a project requiring new skills
- Staying current with evolving technologies

## The Learning Framework

### Phase 1: Survey (Map the Territory)

**Goal:** Get a high-level understanding before diving deep.

**Actions:**
1. **Read the documentation homepage** - Understand the purpose and scope
2. **Scan the table of contents** - See what topics are covered
3. **Look at examples** - Get a feel for the syntax and patterns
4. **Check the community** - GitHub stars, Stack Overflow questions, Discord/Slack activity
5. **Identify prerequisites** - What do you need to know first?

**Questions to Answer:**
- What problem does this solve?
- What are the core concepts?
- How does it compare to alternatives?
- What's the learning curve?

**Timebox:** 30-60 minutes maximum

### Phase 2: Foundation (Build Core Knowledge)

**Goal:** Learn the essential concepts needed to be productive.

**The 80/20 Rule:** Focus on the 20% of features used 80% of the time.

**For a Programming Language:**
- Syntax basics (variables, operators, control flow)
- Data structures (arrays, objects, maps)
- Functions and scope
- Error handling
- Module/import system

**For a Framework:**
- Project structure
- Configuration
- Core abstractions
- Common patterns
- Development workflow

**Learning Techniques:**

#### Active Recall
Test yourself instead of re-reading:
```
❌ Passive: Re-read the chapter on closures
✅ Active: Close the book and write down everything you remember about closures
```

#### Spaced Repetition
Review material at increasing intervals:
- Day 1: Learn concept
- Day 2: Review
- Day 7: Review again
- Day 30: Review once more

#### Feynman Technique
Teach the concept to someone else (or pretend to):
1. Choose a concept
2. Explain it in simple terms
3. Identify gaps in your understanding
4. Review and simplify

### Phase 3: Practice (Apply Knowledge)

**Goal:** Convert theoretical knowledge into practical skills.

**Practice Strategies:**

#### Build Something Small
Create a mini-project that uses the core features:
```
Learning React? → Build a todo list
Learning Python? → Write a data scraper
Learning SQL?    → Design a database for a blog
```

#### Code Katas
Repeat small exercises to build muscle memory:
- FizzBuzz
- String reversal
- Array manipulation
- Basic algorithms

#### Modify Existing Code
- Clone a tutorial project
- Add a new feature
- Break it intentionally, then fix it
- Refactor to improve it

#### Deliberate Practice
Focus on your weak points:
```
Weak with async code?
→ Do 5 exercises specifically on promises/async-await

Struggle with recursion?
→ Solve 10 recursive problems
```

### Phase 4: Deepen (Expand Understanding)

**Goal:** Move beyond basics to intermediate/advanced topics.

**Activities:**
- Read source code of popular libraries
- Study design patterns and best practices
- Learn performance optimization techniques
- Understand internal architecture
- Explore edge cases and gotchas

**Resources:**
- Advanced tutorials and courses
- Conference talks
- Technical blog posts
- Books on the subject
- Open source contributions

### Phase 5: Teach (Solidify Knowledge)

**Goal:** Reinforce your learning by helping others.

**Ways to Teach:**
- Write a blog post explaining a concept
- Answer questions on Stack Overflow
- Create a tutorial or video
- Mentor someone learning the same technology
- Give a talk at a meetup or to your team

**Why Teaching Works:**
- Forces you to organize your thoughts
- Reveals gaps in your understanding
- Requires you to anticipate questions
- Builds confidence in your knowledge

## Learning Resources

### Documentation Types

| Type | Purpose | When to Use |
|------|---------|-------------|
| **Tutorials** | Learning-oriented, step-by-step | First time learning |
| **How-to Guides** | Goal-oriented, problem-solving | Solving specific problems |
| **Reference** | Information-oriented, comprehensive | Looking up details |
| **Explanation** | Understanding-oriented, conceptual | Deepening understanding |

### Effective Resource Usage

**Video Tutorials:**
- ✅ Good for: Visual learners, seeing workflows
- ❌ Watch out for: Outdated content, passive watching
- **Tip:** Code along, don't just watch

**Interactive Courses:**
- ✅ Good for: Hands-on practice, immediate feedback
- ❌ Watch out for: May not cover real-world complexity
- **Tip:** Supplement with personal projects

**Books:**
- ✅ Good for: Comprehensive coverage, deep understanding
- ❌ Watch out for: Can be outdated quickly
- **Tip:** Check publication date and edition

**Documentation:**
- ✅ Good for: Authoritative reference, latest features
- ❌ Watch out for: May assume prior knowledge
- **Tip:** Start with "Getting Started" guides

## Common Pitfalls

| Pitfall | Impact | Prevention |
|---------|--------|------------|
| Tutorial hell | Endless following without building anything original | Build something different after each tutorial |
| Shiny object syndrome | Jumping between technologies without mastering any | Commit to one technology for at least 3 months |
| Perfectionism paralysis | Waiting until you "know enough" before building | Start building on day one, learn by doing |
| Copy-paste coding | Using code without understanding it | Type manually and comment every line |
| Learning in isolation | No feedback, no accountability | Join communities, find study partners |

## Best Practices

1. **Code every day**: Even 30 minutes of daily practice beats weekend marathons
2. **Build projects that interest you**: Intrinsic motivation sustains learning through difficulty
3. **Use active recall**: Close the book and write down what you remember before re-reading
4. **Connect to prior knowledge**: Relate new concepts to things you already understand
5. **Teach what you learn**: Writing a blog post or explaining to a peer reveals gaps
6. **Embrace the struggle**: Difficulty means you're learning; confusion is part of the process

## Tools & Resources

- **Anki** - Spaced repetition flashcards for long-term retention
- **Obsidian/Notion** - Build a personal knowledge base with linked notes
- **Exercism.org** - Practice problems with mentor feedback
- **FreeCodeCamp** - Structured, project-based learning paths
- **Stack Overflow** - Real-world problems and solutions from the community

## Example Application

**Scenario:** Learning Rust for a performance-critical backend service

**Application:**
1. **Survey** (1 hr): Read Rust book overview, scan docs, check community activity
2. **Foundation** (1 week): Learn ownership, borrowing, lifetimes, basic syntax — the 20% used 80% of the time
3. **Practice** (2 weeks): Build a small CLI tool, then a REST API with Actix-web
4. **Deepen** (ongoing): Read Tokio source code, study async patterns, contribute a small PR
5. **Teach**: Write a blog post "Rust for Backend Developers" and present to the team

**Outcome:** Productive in Rust within 6 weeks. Team gained a new skill. Blog post became internal onboarding resource.

## Success Indicators

You've mastered learning when you can:

- ✅ Become productive in a new technology within 4-6 weeks
- ✅ Build something original without following a tutorial
- ✅ Explain core concepts to someone who doesn't know the technology
- ✅ Debug common errors independently
- ✅ Connect new knowledge to existing mental models across domains
