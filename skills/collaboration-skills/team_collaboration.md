# Team Collaboration Skill

## Overview
The ability to work effectively with others toward common goals, leveraging diverse strengths while managing conflicts and maintaining positive team dynamics.

## Core Competencies

### 1. Communication & Coordination
- **Clear Articulation**: Express ideas concisely and precisely
- **Active Listening**: Fully understand before responding
- **Status Updates**: Keep team informed of progress and blockers
- **Documentation**: Create shared understanding through writing
- **Meeting Effectiveness**: Run and participate in productive meetings

### 2. Relationship Building
- **Trust Development**: Build reliability and psychological safety
- **Empathy**: Understand colleagues' perspectives and challenges
- **Inclusivity**: Ensure all voices are heard and valued
- **Recognition**: Acknowledge others' contributions
- **Social Awareness**: Read team dynamics and morale

### 3. Conflict Resolution
- **Early Detection**: Identify tensions before escalation
- **Constructive Dialogue**: Address issues directly but respectfully
- **Mediation**: Help resolve disputes between team members
- **Compromise**: Find win-win solutions when possible
- **Agree to Disagree**: Move forward despite differences

### 4. Collective Problem Solving
- **Brainstorming Facilitation**: Generate ideas collaboratively
- **Decision Making**: Participate in group decisions effectively
- **Consensus Building**: Align team around solutions
- **Retrospectives**: Learn from successes and failures together

## Frameworks & Methods

### Tuckman's Stages of Group Development
```
1. FORMING    → Polite, uncertain, dependent on leader
       ↓
2. STORMING   → Conflict, competition, testing boundaries
       ↓
3. NORMING    → Cooperation, roles clear, cohesion develops
       ↓
4. PERFORMING → High productivity, autonomy, flexibility
       ↓
5. ADJOURNING → Closure, recognition, transition
```

### Five Dysfunctions of a Team (Lencioni)
```
        ▲
        │
     [5] Inattention to Results
        │
     [4] Avoidance of Accountability
        │
     [3] Lack of Commitment
        │
     [2] Fear of Conflict
        │
     [1] Absence of Trust
        │
Foundation: Team members must trust each other first
```

### RACI Matrix for Role Clarity
| Task/Deliverable | Responsible | Accountable | Consulted | Informed |
|------------------|-------------|-------------|-----------|----------|
| Feature Design   |             |             |           |          |
| Code Review      |             |             |           |          |
| Deployment       |             |             |           |          |
| Documentation    |             |             |           |          |

**Definitions:**
- **R**esponsible: Does the work
- **A**ccountable: Ultimately answerable (only one per task)
- **C**onsulted: Provides input before decision
- **I**nformed: Updated after decision/action

## Common Pitfalls

### ❌ What to Avoid
- Silent disagreement (not voicing concerns)
- Blame language ("you" statements)
- Meeting without agenda or clear purpose
- Excluding team members from relevant discussions
- Taking credit for team work
- Ignoring cultural differences
- Over-relying on synchronous communication
- Not documenting decisions
- Letting conflicts fester
- Dominating conversations

### ✅ Best Practices
- Assume positive intent
- Over-communicate rather than under-communicate
- Create psychological safety for risk-taking
- Rotate meeting facilitation roles
- Celebrate team wins publicly
- Address issues privately, praise publicly
- Be reliable and meet commitments
- Ask for help when needed
- Offer help proactively
- Respect different working styles

## Example Application

### Scenario: Cross-Functional Feature Launch

**Team Composition:**
- 2 Backend Engineers
- 2 Frontend Engineers
- 1 Designer
- 1 Product Manager
- 1 QA Engineer

**Collaboration Approach:**

1. **Kickoff Meeting**
   - Align on goals and success metrics
   - Establish working agreements
   - Define roles using RACI matrix

2. **Regular Cadence**
   - Daily standup (15 min): Progress and blockers
   - Weekly design review: Ensure UX consistency
   - Bi-weekly demo: Show progress to stakeholders

3. **Communication Channels**
   - Slack: Day-to-day questions and updates
   - GitHub PRs: Code review and discussion
   - Notion: Documentation and decisions
   - Email: External stakeholder updates

4. **Conflict Prevention**
   - Clear API contracts defined early
   - Design system reduces UI debates
   - Regular check-ins surface concerns quickly

5. **Launch Coordination**
   - Go/no-go decision checklist
   - Rollback plan documented
   - On-call rotation scheduled
   - Post-launch retrospective planned

## Success Indicators
- Team meets commitments consistently
- Low turnover and high engagement scores
- Quick conflict resolution
- Positive peer feedback
- Stakeholders report smooth collaboration
- Knowledge is shared, not siloed
- Team improves velocity over time
