# 資料結構與演算法
資料結構是我們在記憶體中組織資料的方式，以便對其進行高效的操作。算法是解決問題的逐步過程。它們共同構成了電腦科學的基礎——您使用過的每個程式都依賴它們。選擇正確的資料結構可以將一個極其緩慢的程序變成一個快速的程序，而了解正確的演算法可以將一個無法解決的問題變成一個微不足道的問題。
---

## 基本資料結構
### 線性結構
|結構|存取 |搜尋 |插入|刪除|使用案例|
|------------|--------|--------|--------|--------|---------|
| **陣列** | O(1) 依索引 | O(n) | O(n) | O(n) |固定大小的集合；隨機存取|
| **連結清單** | O(n) | O(n) | O(1) 頭部 | O(1) 頭部 |動態尺寸；插入/刪除|
| **堆疊** | O(n) | O(n) | O(1) 推入/彈出 | O(1) 彈出 |函數呼叫；撤消；解析 |
| **隊列** | O(n) | O(n) | O(1) 入隊 | O(1) 出隊 |任務調度；廣度優先搜尋；訊息佇列|
| **雙端佇列** |兩端 O(1) | O(n) |兩端 O(1) |兩端 O(1) |推拉窗；偷工減料 |
### 基於哈希的結構
|結構|搜尋 |插入|刪除|使用案例|
|------------|--------|--------|--------|---------|
| **哈希表** | O(1) 平均 | O(1) 平均 | O(1) 平均 |鍵值查找；快取；套|
| **哈希集** | O(1) | O(1) | O(1) | O(1) | O(1) | O(1) |會員資格測試；重複資料刪除 |
**哈希衝突**：當兩個鍵哈希到同一個槽時，它們儲存在鍊錶（連結）或下一個可用槽（開放尋址）中。好的雜湊函數可以最大限度地減少衝突。
### 樹狀結構
|結構|搜尋 |插入|刪除|使用案例|

## 演算法複雜度（Big-O）
Big-O 表示法描述了演算法的時間或空間需求如何隨著輸入大小的增加而成長。
|複雜性 |名稱 |範例|
|------------|------|---------|
| **O(1)** |恆定|雜湊表查找；依索引存取數組 |
| **O(log n)** |對數 |二分查找；平衡樹操作|
| **O(n)** |線性|線性搜尋；迭代數組 |
| **O(n log n)** |線性|歸併排序；堆排序；最高效的通用排序 |
| **O(n²)** |二次 |冒泡排序；相同資料上的巢狀迴圈 |
| **O(2^n)** |指數|暴力子集生成；樸素遞歸斐波那契 |
| **O(n!)** |階乘|旅行推銷員（暴力）；排列|
### 常見誤解
|誤解|現實|
|--------------|---------|
| “O(n) 總是比 O(n²) 快”|對於較小的 n，常數因子更重要 |
| “降低大 O 總是更好” |存在時空權衡； O(1) 查找使用 O(n) 內存 |
| “Big-O 告訴你準確的速度”|它描述的是增長率，而不是絕對時間 |

## 排序演算法
|演算法|最佳|平均 |最差|空間|穩定|就地|
|------------|------|---------|--------|--------|--------|----------|
| **冒泡排序** | O(n) | O(n²) | O(n²) | O(1) | O(1) |是的 |是的 |
| **插入排序** | O(n) | O(n²) | O(n²) | O(1) | O(1) |是的 |是的 |
| **選擇排序** | O(n²) | O(n²) | O(n²) | O(1) | O(1) |沒有 |是的 |
| **合併排序** | O(n log n) | O(n log n) | O(n log n) | O(n log n) | O(n log n) | O(n log n) | O(n) |是的 |沒有 |
| **快速排序** | O(n log n) | O(n log n) | O(n log n) | O(n log n) | O(n²) | O(log n) |沒有 |是的 |
| **堆排序** | O(n log n) | O(n log n) | O(n log n) | O(n log n) | O(n log n) | O(n log n) | O(1) | O(1) |沒有 |是的 |
| **蒂姆·索特** | O(n) | O(n log n) | O(n log n) | O(n log n) | O(n log n) | O(n) |是的 |沒有 |
**實用建議**：使用您語言的內建排序（Python 的`sorted()`、JavaScript 的`Array.sort()`）。他們使用高度最佳化的演算法（Tim Sort、Introsort）來處理所有邊緣情況。

## 搜尋演算法
|演算法|資料結構|複雜性 |需求 |
|----------|--------------|---------|-------------|
| **線性搜尋** |任何 | O(n) |無 |
| **二分查找** |排序數組 | O(log n) |資料必須排序|
| **哈希表查找** |哈希表| O(1) 平均 |良好的哈希函數 |
| **BFS*（廣度優先搜尋）|圖/樹| O(V + E) |未加權最短路徑 |
| **DFS**（深度優先搜尋）|圖/樹| O(V + E) |尋路；循環偵測|
| **迪傑斯特拉** |加權圖 | O((V + E) log V) |非負權重；最短路徑|
| **A* 搜尋** |加權圖 | O((V + E) log V) |啟發式引導；具有可接受的啟發式的最優 |

## 關鍵演算法模式
|圖案|描述 |範例問題 |
|--------|-------------|-----------------|
| **分而治之** |將問題分解為子問題；遞歸求解；結合|歸併排序；快速排序；二分查找|
| **動態規劃** |分解為重疊的子問題；緩存結果 |斐波那契；背包;最長公共子序列|
| **貪婪** |每一步做出局部最優選擇 |迪傑斯特拉的；霍夫曼編碼；活動選擇|
| **回溯** |嘗試各種可能性；撤銷錯誤的選擇；嘗試替代方案 |數獨解算器； N-皇后；排列|
| **滑動窗** |維護一個元素視窗；將其滑過資料 |大小為 K 的最大和子數組；最長的無重複子字串 |
| **兩個指標** |使用兩個指標朝彼此或向同一方向移動 |排序數組中的對和；刪除重複項 |
| **對答案進行二分搜尋** |二分找出答案空間 |分配最小頁數；好鬥的乳牛|

## 何時使用什麼
|問題 |資料結構|演算法|
|--------|----------------|------------|
|快速鍵值查找 |哈希表/字典|哈希 |
|維護排序順序 |平衡 BST（TreeMap、std::set）|樹操作|
|基於優先權的處理 |堆/優先權佇列|堆操作 |
|最短路徑（未加權）|圖（鄰接表）| BFS |
|最短路徑（加權）|圖（鄰接表）| Dijkstra 的 / A* |
|會員測試|哈希集/布林過濾器|哈希 |
|前綴匹配 |特里樹 | Trie 遍歷 |
|範圍查詢 |線段樹/芬威克樹|樹操作|
| LRU 快取 |雜湊圖+雙向鍊錶|聯合經營 |
|連接元件|不相交集並集（並尋找）|聯合與查找 |

＃＃ 概括
資料結構和演算法不僅僅是面試主題——它們是高效軟體的構建塊。數組和哈希表可以滿足大多數日常需求。樹和圖處理層次結構和關係資料。排序和搜尋已解決標準庫中的問題。演算法模式——分而治之、動態規劃、貪婪、回溯——是解決新問題的可重複使用策略。關鍵技能不是記住演算法，而是記住演算法。它識別哪種模式適合給定的問題並為工作選擇正確的資料結構。
