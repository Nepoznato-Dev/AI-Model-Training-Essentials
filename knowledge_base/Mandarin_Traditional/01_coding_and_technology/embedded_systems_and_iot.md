# 嵌入式系統與物聯網
嵌入式系統是隱藏在其他設備中的電腦——汽車的引擎控制單元、洗衣機的控制器、智慧恆溫器中的微控制器。與通用電腦不同，它們是為特定任務而設計的，通常對功耗、記憶體和處理速度有嚴格的限制。物聯網 (IoT) 透過將嵌入式系統連接到網路來擴展嵌入式系統，從而實現遠端監控、控制和資料收集。它們共同代表了與物理世界互動的數十億運算設備。
---

## 嵌入式系統基礎知識
### 嵌入式有何不同
|方面|通用計算機|嵌入式系統|
|--------|------------------------|-----------------|
| **目的** |運行任何軟體|執行特定任務 |
| **資源** |足夠的CPU、RAM、儲存|有限（KB 到 MB RAM；MHz 到低 GHz）|
| **電源** |已插入電源或高電池 |通常由電池供電或能量收集|
| **作業系統** |完整作業系統（Windows、Linux、macOS）| RTOS、裸機或嵌入式 Linux |
| **使用者介面** |豐富（螢幕、鍵盤、滑鼠）|最少（LED、按鈕、感應器）或無 |
| **實時** |盡力|實時期限往往很嚴格|
| **終生** | 3-7年| 10-25+ 歲 |
### 微控制器與微處理器
|特色 |微控制器 (MCU) |微處理器 (MPU) |
|--------------------|--------------------------------|---------------------|
| **整合** | CPU + RAM + Flash + 週邊整合在一顆晶片上 |僅CPU；外部 RAM 和儲存 |
| **性能** |低到中（MHz 範圍）|高（GHz 範圍）|
| **電源供應器** |非常低（μA 至 mA）|較高（數百毫安培至安培）|
| **成本** | 0.10 美元 - 10 美元 | $5 - $100+ |
| **範例** | STM32、ESP32、Arduino（ATmega）、nRF52 |樹莓派（BCM2835）、i.MX、全志 |
| **用例** |感測器、執行器、簡單控制|顯示、複雜處理、Linux |

## 即時作業系統 (RTOS)
RTOS 保證關鍵任務在定義的時間視窗內完成。
|即時作業系統 |許可證|最適合 |
|------|---------|----------|
| **FreeRTOS** |麻省理工學院 |最常見；廣泛的 MCU 支援 |
| **西風** |阿帕契2.0 |現代的; Linux 基金會；不斷發展的生態系統|
| **ThreadX (Azure RTOS)** |麻省理工學院 |安全認證；物聯網 |
| **embOS** |商業|工業的;認證 |
| **RT 線程** |阿帕奇2.0 |中國生態系統；全球成長|
### RTOS 與裸機
|方面|裸機 |即時作業系統 |
|--------|------------|------|
| **複雜性** |簡單任務簡單|複雜的並發任務所需 |
| **日程安排** |手冊（主循環+中斷）|具有優先順序的搶佔式調度|
| **可擴展性** |難以新增功能|輕鬆新增任務 |
| **記憶體** |最小的開銷|開銷小（幾KB）|

## 通訊協定
### 有線協議
|協定|速度|距離 |使用案例|
|----------|------|----------|----------|
| **UART** |高達 1 Mbps |短（板載）|調試控制台； GPS模組|
| **SPI** |高達 100 MHz |短（板載）|高速週邊（顯示器、快閃記憶體）|
| **I²C** |高達 3.4 MHz |短（板載）|感測器；低引腳數通訊 |
| **可以** |高達 1 Mbps |長達 1 公里 |汽車；工業|
| **乙太網路** | 10 Mbps - 100 Gbps |長達 100 m |連網;工業（含擴充）|
| **USB** |高達 40 Gbps (USB4) |長達 5 m |週邊設備；充電|
### 無線協議
|協定|範圍 |電源|速度|使用案例|
|----------|---------|--------|--------|----------|
| **無線網路** | 〜100公尺|高|高達 Wi-Fi 7（理論值 46 Gbps）|高頻寬物聯網；串流媒體 |
| **藍牙經典** | 〜100米|中等| 1-3 Mbps |聲音的;檔案傳輸 |
| **BLE**（藍牙低功耗）| 〜100米|非常低| 1-2 Mbps |可穿戴設備；信標；感測器|
| **紫蜂** | ~100 m（網格）|低| 250 kbps | 250 kbps家庭自動化；工業感測器|
| **Z 波** | ~100 m（網格）|低| 100 kbps | 100 kbps家庭自動化 |
| **LoRa / LoRaWAN** |長達 15 公里 |非常低| 0.3-50 kbps |農業;公用事業；全市感測器|
| **窄頻物聯網** |蜂窩覆蓋 |低| 250 kbps | 250 kbps計量；資產追蹤 |
| **主題/主題** | ~100 m（網格）|低|中|智慧家居（蘋果、谷歌、亞馬遜）|
| **蜂窩網路（4G/5G）** |全球|高|高|連網車輛；遠端監控|

## 物聯網架構
### 物聯網堆疊
|層|功能|範例 |
|--------|----------|---------|
| **裝置** |感測器、致動器、微控制器 | ESP32、STM32、樹莓派 |
| **連線性** |網路協定| MQTT、HTTP、CoAP、LoRaWAN |
| **邊緣運算** |裝置附近處理| AWS Greengrass、Azure IoT Edge |
| **雲端平台** |資料擷取、儲存、處理 | AWS IoT、Azure IoT 中心、Google Cloud IoT |
| **應用** |儀表板、分析、警報 | Grafana，客製化網路應用程式 |
### 物聯網通訊協議
|協定|圖案|最適合 |
|----------|---------|----------|
| **MQTT** |發布/訂閱；輕量化|大多數物聯網應用；低頻寬|
| **HTTP/REST** |請求/回應 |當簡單很重要時；網路整合|
| **CoAP** |請求/回應；基於UDP |受限設備；低功耗|
| **AMQP** |訊息佇列|企業物聯網；可靠的交付 |
| **WebSocket** |雙向；持久連接 |即時儀表板；即時數據|
### MQTT 詳細信息
|概念 |描述 |
|---------|-------------|
| **經紀人** |路由訊息的中央伺服器（Mosquitto、EMQX、HiveMQ）|
| **主題** |分層位址（例如`home/living-room/temperature`）|
| **服務品質** | 0（最多一次）、1（至少一次）、2（剛好一次）|
| **保留訊息** |關於某個主題的最後一則訊息；交付給新訂閱者|
| **最後遺囑** |客戶端意外斷線時所發布的訊息 |

## 邊緣運算
在來源附近處理數據，而不是將所有內容傳送到雲端。
|效益 |說明 |
|---------|-------------|
| **減少延遲** |無需往返雲；立即做出決定|
| **節省頻寬** |只發送摘要或異常情況 |
| **隱私** |敏感資料保留在本地
| **可靠性** |網路中斷時也能運作 |
|平台|描述 |
|----------|-------------|
| **AWS Greengrass** |在邊緣設備上運行 Lambda 函數 |
| **Azure IoT Edge** |在邊緣設備上運行容器 |
| **NVIDIA Jetson** | GPU 加速的邊緣 AI（Orin、Nano）|
| **樹莓派** |輕量級邊緣運算 |

＃＃ 概括
嵌入式系統和物聯網代表了軟體與實體世界的交叉點。從控制馬達的微控制器到連接雲端的感測器網絡，它們需要與網路或應用程式開發不同的思維方式：資源有限、即時要求、長壽命以及錯誤對物理世界的影響。生態系統已經非常成熟——ESP-IDF和Zephyr等框架使專業開發變得容易，而AWS IoT和Azure IoT Hub等平台則負責雲端處理。關鍵技能是了解硬體介面、通訊協定、電源管理以及編寫必須在無需幹預的情況下可靠運行多年的軟體的規則。
