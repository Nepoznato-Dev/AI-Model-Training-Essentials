# 雲端架構
雲端運算從根本上改變了組織建置、部署和擴展軟體的方式。您無需購買和維護實體伺服器，而是可以按需配置運算資源，按使用量付費，並在幾分鐘內進行全球擴展。該文件涵蓋了您需要了解的核心概念、架構模式、服務和最佳實踐。
---

## 雲端運算基礎知識
### 什麼是雲端運算？
透過網路按需交付運算資源（伺服器、儲存、資料庫、網路、軟體），並採用按需付費的定價方式。
### NIST 基本特徵
|特點|意義|
|----------------|---------|
| **按需自助服務** |無需人工互動即可提供資源 |
| **廣泛的網路存取** |透過標準機制在網路上可用 |
| **資源池** |多租用戶模式；資源動態分配|
| **快速彈性** |快速向外和向內擴展 |
| **測量服務** |使用情況受到監控併計費 |
### 部署模型
|型號|說明 |何時使用 |
|--------|-------------|-------------|
| **公有雲** |由供應商擁有；共享基礎設施（AWS、Azure、GCP）|大多數工作負載；性價比|
| **私有雲** |致力於單一組織|監管要求、敏感資料 |
| **混合雲** |公私結合|彈性+合規性|
| **多雲** |使用多個公有雲供應商 |避免供應商鎖定，同類最佳 |
### 服務模式
|型號|提供 |範例 |使用案例 |
|--------|----------|----------|------------|
| **基礎架構即服務** |虛擬機器、儲存、網路、作業系統 | AWS EC2、Azure 虛擬機器、GCP 運算引擎 |直接遷移、完全控制 |
| **PaaS** |開發平台、資料庫、中介軟體| Heroku、Google App Engine、AWS Elastic Beanstalk | App開發、API部署|
| **SaaS** |透過網路完成申請 | Salesforce、Google Workspace、Microsoft 365 |電子郵件、CRM、協作 |
| **FaaS / 無伺服器** |事件驅動函數執行 | AWS Lambda、Azure 函數、GCP 雲端函數 | API、事件處理、排程任務 |

## 架構模式
### 架構良好的框架
所有三大供應商都發布了圍繞五個支柱構建的架構良好的框架：
|支柱|關鍵原則|
|--------|----------------|
| **卓越運作** |自動化操作；經常進行可逆的改變；預見失敗|
| **安全性** |強大的身份基礎；在每一層應用安全性；保護傳輸中和靜態的資料|
| **可靠性** |測試恢復程序；故障自動恢復；水平縮放 |
| **效能效率** |使用無伺服器；幾分鐘內走向全球；經常實驗|
| **成本優化** |採用消費模式；使用託管服務；停止在無差別的工作上花錢|
### 常見模式
|圖案|描述 |好處 |挑戰|
|---------|-------------|----------|------------|
| **微服務** |將應用程式分解為小型、獨立的服務 |可擴展、故障隔離、獨立部署 |分散式複雜性，資料一致性 |
| **事件驅動** |元件透過事件進行通訊 |鬆散耦合、即時處理 |調試複雜性、最終一致性|
| **無伺服器** |無需伺服器管理；按執行付費|成本效益、快速部署 |冷啟動、供應商鎖定、執行限制 |
| **分層（N 層）** |表示→業務邏輯→資料存取→資料庫|關注點分離、可維護性 |可以成為整體|
| **天基** |跨虛擬化記憶體節點的分散式資料 |處理高並發、低延遲 |設計與管理複雜 |

## 核心服務
### 計算
|服務類型 |詳情 |
|-------------|---------|
| **虛擬機器** |通用、運算最佳化、記憶體最佳化、GPU。定價：按需、預留、現貨。 |
| **容器** | Docker 運行時；透過 Kubernetes（EKS、AKS、GKE）進行編排。註冊表：ECR、GCR、ACR。 |
| **無伺服器功能** |事件觸發，無狀態。執行時間、記憶體、並發性的限制。 |
＃＃＃ 貯存
|類型 |特點 |範例 |最適合 |
|------|----------------|----------|----------|
| **物件** |扁平結構、HTTP 存取、元資料豐富 | S3、雲端儲存、Azure Blob |靜態資產、備份、資料湖 |
| **封鎖** |附加到虛擬機器的原始磁碟區 | EBS、持久磁碟、Azure 磁碟 |資料庫、啟動磁碟區 |
| **檔案** |共用檔案系統（NFS/SMB）| EFS、檔案儲存、Azure 檔案 |內容管理、共用設定 |
| **存檔** |成本最低，檢索延遲| S3 冰川、Azure 存檔 |合規，長期備份|

## 網路
### 虛擬網絡
每個雲端部署都位於虛擬私有雲 (VPC / VNet) 內 - 您使用 CIDR 區塊、子網路（公有或私人）、路由表和閘道定義的隔離網路。
### 負載平衡和 CDN
|服務 |目的|
|---------|---------|
| **負載平衡器** |跨實例分配流量（L4 網路、L7 應用程式）|
| **CDN** |在邊緣位置快取內容以降低延遲（CloudFront、Cloud CDN、Azure CDN）|
| **DNS** |網域註冊、路由原則、運作狀況檢查（Route 53、Cloud DNS、Azure DNS）|
### 連線選項
|選項 |說明 |
|--------|-------------|
| **網際網路閘道** | VPC 公用網際網路接取 |
| **NAT 閘道** |私有子網路出站存取 |
| **VPN** |到本地的加密隧道 |
| **直接連接/ ExpressRoute** |專用私人連接|
| **VPC 對等互連** |連接帳戶內或帳戶之間的 VPC |

### 共同責任模型
|層|供應商|客戶|
|--------|----------|----------|
| **基礎設施**（硬體、設施）| ✅ | |

服務管理越多，提供者處理的越多。借助 IaaS，您幾乎可以管理一切；對於 SaaS，提供者幾乎可以處理所有的事情。

|概念 |描述 |
|---------|-------------|

## 成本管理
### 定價模型
|型號|描述 |最適合 |
|--------|-------------|----------|
| **點播** |按秒/小時按使用量付費 |可變的短期工作負載 |
| **預留實例** | 1-3年承諾，大幅折扣|穩態工作負載 |
| **現貨實例** |對未使用的容量進行投標；可以被打斷|容錯、靈活的作業 |
| **儲蓄計劃** |靈活的承諾定價|混合使用模式 |
| **免費套餐** |新帳號免費使用限量 |學習、原型製作 |
### 最佳化策略
調整執行個體大小以符合工作負載。使用自動擴展來因應需求高峰。為可預測的負載預留容量。使用競價實例進行批次作業。將不經常存取的資料移至更便宜的儲存層。刪除未使用的資源（孤立快照、空閒負載平衡器、未附加的 IP）。

## 高可用性和災難復原
### 可用性概念
|概念 |描述 |
|---------|-------------|
| **可用區 (AZ)** |區域內物理上獨立的資料中心 |
| **地區** |具有多個可用區的地理區域 |
| **邊緣位置** |內容交付的 CDN 快取位置 |
### 災難復原策略
|戰略|成本| RTO |恢復點目標 |說明 |
|----------|------|-----|-----|------------|
| **備份與恢復** |最低|營業時間 |小時-天 |定期備份，需要時恢復 |
| **指示燈** |低|分鐘–小時 |分鐘 |核心要素始終運行，災難擴大|
| **熱備** |中|分鐘 |秒-分鐘|縮小版始終運作 |
| **多站點主動/主動** |最高|接近零|零|多個地區全面投產|
**RTO**（恢復時間目標）= 最大可接受的停機時間。 **RPO**（復原點目標）= 可接受的最大資料遺失。
