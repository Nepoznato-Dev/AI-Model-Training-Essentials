# 無障礙與包容性設計
可訪問性（通常縮寫為 a11y）是讓軟體可供所有人使用的實踐，包括有視覺、聽覺、運動、認知和神經障礙的人。這是許多司法管轄區的法律要求和標準工程實務。無障礙軟體對每個人來說都是更好的軟體，因為支援殘疾用戶的設計決策——清晰的結構、鍵盤導航、足夠的對比度、可讀的文字——改善了所有用戶的體驗。
---

## 誰從無障礙中受益？
|殘疾類型 |範例 |輔助技術|
|----------------|---------------------|---------------------|
| **視覺** |失明、低視力、色盲|螢幕閱讀器（JAWS、NVDA、VoiceOver）；放大鏡；高對比模式 |
| **聽覺** |耳聾、聽力困難 |字幕；成績單；視覺警報|
| **馬達** |彈性有限、癱瘓、震顫 |僅鍵盤導航；語音控制；開關設備；眼球追蹤 |
| **認知** |閱讀障礙、過動症、自閉症、記憶障礙 |語言清晰；一致的導航；減少干擾 |
| **暫時** |斷臂、明亮的陽光、吵雜的環境|與永久性殘疾相同的住宿條件 |
| **情況** |抱著寶寶，開車，一隻手被佔用|語音介面；大型觸控目標|
**关键见解**：为残疾用户设计的辅助功能可以帮助每个人。路邊坡道（人行道上的坡道）是為輪椅設計的，但也供推著嬰兒車的父母、推著推車的送貨員和帶著行李的旅行者使用。

## 網路輔助功能 (WCAG)
網頁內容可訪問性指南 (WCAG) 是網頁可訪問性的國際標準。
### WCAG 原則 (POUR)
|原理|要求|
|------------|-------------|
| **可感知** |資訊必須以使用者可以感知的方式呈現（文字替代、標題、自適應版面）|
| **可操作** |介面必須可導航且可用（可使用鍵盤、足夠的時間、無引起癲癇發作的內容）|
| **可以理解** |資訊和操作必須是可理解的（可讀、可預測、輸入輔助） |
| **穩健** |內容必須與當前和未來的輔助技術相容 |
### WCAG 一致性級別
|水平|要求|典型目標 |
|--------|-------------|---------------|
| **一個** |最低水平；30 條成功標準 |某些司法管轄區的法定最低限度|
| **AA** |解決最常見的障礙 |大多數組織的標準目標|
| **AAA** |最高等級；並非所有內容都能實現 |專業內容；教育網站|
### 關鍵成功標準（AA 級）
|標準|要求|如何實現 |
|------------|-------------|---------------|
| **1.1.1 非文字內容** |所有圖像都有替代文字 |`alt`屬性；`aria-label`圖示 |
| **1.3.1 訊息與關係** |以程式設計方式傳達的結構 |語意 HTML；標題；清單；地標|
| **1.4.3 對比（最小值）** |文字的對比度至少為 4.5:1 |用對比檢查器進行測試；選擇易於使用的調色板 |
| **1.4.4 調整文字大小** |文字大小可調整至 200% 而不會遺失 |使用相對單位（rem、em）；響應式設計|
| **2.1.1 鍵盤** |所有功能可透過鍵盤實現 |無鍵盤陷阱；可見焦點指示器|
| **2.4.3 焦點順序** |焦點順序保留了意義和可操作性|邏輯 Tab 鍵順序； DOM 順序與視覺順序匹配 |
| **2.4.7 焦點可見** |鍵盤焦點以視覺方式指示 | CSS`:focus-visible`樣式；絕不`outline: none`無需更換 |
| **3.3.2 標籤或說明** |輸入有標籤 |`<label>`元素；`aria-label`|
| **4.1.2 名稱、角色、值** | UI 元件具有可存取的名稱和角色 | ARIA 屬性；語意 HTML |

## ARIA（可存取的富互聯網應用程式）
ARIA 為沒有內建語意的 HTML 元素添加可訪問性資訊。
### ARIA 角色
|角色 |目的|範例|
|------|---------|---------|
|`button`|將元素標識為按鈕 |按鈕樣式的`<div>`|
|`dialog`|模態或非模態對話方塊 |自訂模態元件 |
|`tablist`/`tab`/`tabpanel`|選項卡介面 |自訂選項卡元件 |
|`alert`|動態顯示的重要訊息 |錯誤通知 |
|`progressbar`|進度指示器|載入狀態 |
|`menu`/`menuitem`|選單導覽|下拉選單|
### ARIA 屬性
|屬性 |目的|範例|
|------------|---------|---------|
|`aria-label`|無可見文字時可存取的名稱 |僅圖示按鈕：`aria-label="Search"` |
|`aria-describedby`|將元素連結到其描述 |帶有說明文字的表單欄位 |
|`aria-expanded`|指示某個部分是否已展開 |手風琴;下拉選單 |
|`aria-hidden`|從輔助技術中隱藏元素 |裝飾圖示|
|`aria-live`|宣布動態內容變更 |即時更新；通知 |
|`aria-disabled`|表示元素已停用 |灰色按鈕 |
### ARIA 的第一條規則
> **如果可以使用本機 HTML，請勿使用 ARIA。 **`<button>`已可存取。`<div role="button">`要求您手動新增鍵盤處理、焦點管理和螢幕閱讀器支援。首先使用語意 HTML；僅當原生元素無法完成這項工作時才使用 ARIA。

## 鍵盤導航
|關鍵|預期行為 |
|----------------|--------------------|
| **選項卡** |將焦點移至下一個互動元素 |
| **Shift + Tab** |將焦點移至上一個互動元素 |
| **輸入/空格** |啟動焦點元素（按鈕、連結）|
| **方向鍵** |在元件內導覽（選單、選項卡、單選組）|
| **逃脫** |關閉對話框、選單或彈出視窗 |
| **首頁/完** |跳到清單中的第一項/最後一項 |
### 常見的鍵盤陷阱
|問題 |修復|
|---------|-----|
|焦点进入组件但无法离开 |确保 Tab 将焦点移出；手柄逃生 |
|模态不捕获焦点 |焦点应在模态内循环；返回到关闭时触发|
|自定义组件不响应键盘 |添加 Enter、空格、箭头的按键处理程序 |

## 色彩與視覺設計
|指南|要求|
|------------|-------------|
| **對比** |普通文字為 4.5:1；3:1 用於大文字（18pt+ 或 14pt+ 粗體）|
| **不要只依賴顏色** |除了顏色之外，還可以使用圖示、文字或圖案 |
| **焦點指標** |隨時可見；高對比；切勿在不更換的情況下移除 |
| **調整文字大小** |佈局必須在 200% 縮放下工作 |
| **反應靈敏** |內容必須以 320 像素寬度重排（行動裝置）|
### 色盲注意事項
|類型 |受影響的顏色 |設計技巧|
|------|-----------------|------------|
| **綠盲** |紅綠（最常見）|不要使用紅/綠來傳達狀態；使用圖示+顏色|
| **紅色盲** |紅綠|同上 |
| **藍色盲** |藍黃色|不要使用藍色/黃色作為唯一的區分因素 |

## 測試可訪問性
|方法|工具|它捕捉了什麼|
|--------|------|----------------|
| **自動掃描** |斧頭，燈塔，波浪|缺少替代文字；對比問題； ARIA 錯誤 |
| **鍵盤測試** |手動：拔掉滑鼠，僅使用鍵盤|焦點順序；鍵盤陷阱；失蹤處理程序|
| **螢幕閱讀器測試** | NVDA（免費）、VoiceOver (macOS)、JAWS |缺少標籤；結構差；未宣布的變更 |
| **變焦測試** |瀏覽器縮放至 200%、400% |佈局破損；剪裁的文字；溢出問題|
| **色彩對比** | WebAIM 對比檢查器，Stark 外掛程式 |對比度不足|
| **使用者測試** |與殘疾使用者進行測試 |自動化工具忽略的現實世界障礙|

## 法律要求
|法律 |地區 |要求|
|-----|--------|-------------|
| **ADA**（美國殘疾人法案）|美國 |公共場所的網站必須易於訪問 |
| **第 508 條** |美國（聯邦）|聯邦機構的 ICT 必須無障礙 |
| **EAA**（歐洲無障礙法案）|歐盟（2025+）|產品和服務必須滿足無障礙要求 |
| **EN 301 549** |歐盟| ICT無障礙技術標準|
| **ACA**（加拿大無障礙法案）|加拿大 |政府和受監管行業|
| **2010 年平等法案** |英國 |服務商必須做出合理調整|

## 移動輔助功能
|平台|指南 |關鍵工具|
|----------|------------|------------|
| **iOS** | Apple 人機介面指南（輔助功能部分）|畫外音；動態型；開關控制|
| **安卓** | Android 輔助功能指南 |對講；切換存取；選擇發言 |
|行動關注|解決方案 |
|----------------|----------|
| **觸控目標** |最小 44×44 點 (iOS) / 48×48 dp (Android) |
| **螢幕閱讀器支援** |內容描述；無障礙標籤|
| **運動靈敏度** |尊重`prefers-reduced-motion`；避免自動播放動畫 |
| **動態文字大小** |支援系統字體大小；使用可縮放的文字單元|

＃＃ 概括
可訪問性是一項設計原則，應該從一開始就為每個決定提供信息，而不是在最後添加的功能。使用語義 HTML。確保鍵盤導航正常運作。保持足夠的色彩對比。為非文字內容提供替代文字。使用螢幕閱讀器和殘疾用戶進行測試。結果是軟體能夠更好地適合每個人，包括那些有暫時障礙、環境限制、設備較舊、連接速度慢以及現實世界使用與受控開發環境存在許多不同的人。
