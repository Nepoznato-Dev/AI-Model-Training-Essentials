# 快速工程
提示工程是設計、完善和最佳化輸入提示以從語言模型獲得最佳輸出的實踐。它既是一門藝術，也是一門科學，並且是無需微調即可控制 LLM 行為的主要介面。
---

## 核心原則
### 清晰度和特異性
明確的提示不留任何含糊之處。準確指定您想要的內容，包括格式、長度和視角。
**含糊：**
> “告訴我有關 Python 的信息。”
**具體：**
> “解釋 Python 的全域解釋器鎖 (GIL)。描述它對多線程的影響，給出一種解決方法，並將答案控制在 200 字以內。”
### 提供上下文
當模型了解角色、受眾和目標時，他們的表現會更好。
**沒有上下文：**
> “編寫一個函數對列表進行排序。”
**結合上下文：**
> “您是高級 Python 開發人員。編寫一個函數來按給定鍵對字典列表進行排序。使用類型提示並處理邊緣情況。受眾是初級開發人員。”
### 使用正面的指令
告訴模型要做什麼，而不是要避免什麼。 「不要使用行話」比「使用 10 歲孩子可以理解的簡單語言」弱。
---

## 提示結構
### 系統/使用者/助理角色
大多數 LLM API 支援多輪結構：
- **系統訊息**：設定模型的行為、角色和約束（在整個會話中持續存在）。
- **使用者訊息**：目前查詢或指令。
- **助理訊息**：模型之前的回應（用於連續性）。
**範例（OpenAI API 風格）：**
系統：你是一位有用的程式設計助理。您用簡潔的程式碼範例和簡短的解釋進行回應。切勿提供不安全的代碼。
使用者：編寫一個 Python 函數來從 URL 下載檔案。
### 少量提示
在要求模型执行任务之前，提供 2-3 个所需输入输出格式的示例。這教導了模式。
**範例：**
使用者：將這些句子轉換為被動語態：
輸入：貓追老鼠。
輸出：老鼠被貓追趕。
輸入：廚師做飯了。
輸出：這頓飯是廚師做的。
輸入：風暴摧毀了房子。
輸出：（模型完成）
### 思想鏈 (CoT)
鼓勵模型逐步展現其推理。這提高了算術、邏輯和多步驟任務的準確性。
**沒有 COT：**
> “什麼是 24 × 37？”
**含 COT：**
> “計算 24 × 37。逐步展現你的推理。”
此模型將產生中間步驟，減少算術錯誤。
### 結構化輸出
請求特定格式（例如 JSON、YAML 或 Markdown 表）以使解析可靠。
使用者：列出微服務的三個優點和三個缺點。僅傳回帶有鍵“pros”和“cons”的有效 JSON 對象，每個鍵都是字串數組。

## 先進技術
### 自我一致性
針對相同提示（溫度 > 0）產生多個回應，並對最終答案進行多數投票。這對於推理任務特別有效。
### 思想樹
並行探索多個推理路徑，評估每個路徑，然後選擇最佳的路徑。這是一種研究級技術，但可以透過要求模型「探索替代解決方案」來近似。
### ReAct（推理+行動）
讓模型將推理與工具呼叫交織在一起。它可以思考，然後採取行動（例如，搜尋網絡，運行程式碼），然後根據結果再次思考。
**提示結構：**
您可以使用計算機和搜尋引擎。對於每一步，輸出：
想法：（你的推理）
操作：（工具名稱，輸入）
觀察結果：（工具輸出）
……繼續下去，直到得到最終答案。
### 角色分配
指定一個特定的角色來建立回應。
**範例：**
- “您是 Linux 核心開發人員，向應屆畢業生解釋記憶體管理。”
- “您是一位友好的營養師，為客戶提供一般性建議。”
- “你是一個憤世嫉俗的技術評論家，正在評論一個新產品。”

## 參數調優
- **溫度** (0.0 – 1.0+)：控制隨機性。較低=更具確定性，較高=更具創造性。事實答案使用 0.0–0.3；創意寫作為 0.7–1.0。
- **Top-p**（核採樣）：在某個累積閾值處截斷機率質量。 0.9 表示模型從前 90% 的可能標記中採樣。通常調整溫度或頂部溫度，而不是兩者都調整。
- **最大令牌**：設定最大輸出長度。請記住在上下文視窗中為回應預留空間。
- **頻率懲罰**：減少相同標記的重複。
- **存在懲罰**：鼓勵模型引入新主題。

## 常見陷阱和修復
|問題 |可能的原因 |修復|
|---------|--------------|-----|
|模型忽略部分提示 |提示太長或超載|縮短;把最重要的指令放在最後|
|輸出太冗長|無長度限制 |新增「限制為 3 句」或設定 max_tokens |
|輸出過於簡潔|過度限制 |新增「詳細說明」或降低溫度 |
|事實幻覺|上下文不足或問題不明確 |添加“如果您不確定，請說‘我不知道’”並提供 RAG 上下文 |
|格式不一致 |沒有明確的格式指令|請求 JSON、Markdown 表或項目符號清單 |
|錯誤語言的示範答案 |無語言指導|明確說明“用英語回复”（或您的目標語言）|

## 常見任務的提示模板
### 總結
將以下文字概括為 3 個要點。關注主要論點，避免細節。
文字：[插入文字]

### 程式碼生成
寫一個[語言]函數來[執行X]。
要求：
使用類型提示。
包含文件字串。
處理邊緣情況：[列表]。
除非指定，否則不要使用外部庫。

### 解釋
向[非專家/大學生/兒童]解釋[概念]。在適當的地方使用類比。
### 腦力激盪
為 [主題] 產生 10 個想法。對於每個想法，給出一句話描述和一個潛在的挑戰。
文字
### 分類
將以下客戶回饋分類為[正面、中立、負面]。
提供置信度分數 (0-100) 和簡短原因。
回饋：[插入文字]
### 風格翻譯
將以下英文文字翻譯成西班牙文。使用適合社群媒體貼文的非正式語氣。
文字：[插入文字]

## 提示評估
將提示視為程式碼：對其進行版本控制、測試並迭代。
- **A/B 測試**針對一組保留的查詢的不同提示變體。
- **透過人工評估或自動指標（例如，精確配對、BLEU、自訂評分）衡量成功。
- **保留提示註冊表**（一個簡單的文字檔案或電子表格），其中包含提示、版本和觀察到的效能。
