# 機器學習評估與工作流程
機器學習生命週期的實用指南（從問題框架到生產監控），重點在於指標、驗證和調試。
---

## 機器學習工作流程 (CRISP-ML)
1. **業務理解**：定義目標和成功標準。
2. **數據理解**：探索可用數據，識別品質問​​題。
3. **資料準備**：清理、轉換和分割資料。
4. **建模**：訓練模型，調整超參數。
5. **評估**：根據指標評估績效。
6. **部署**：在生產中提供模型。
7. **監控**：追蹤漂移、效能和異常。
這是一個迭代循環 - 您將根據評估結果重新訪問先前的步驟。
---

## 資料分割
### 訓練/驗證/測試拆分
- **訓練集** (~70%)：用於擬合模型參數。
- **驗證集** (~15%)：用於調整超參數並選擇模型變體。
- **測試集** (~15%)：在最後僅使用一次來估計泛化效能。
**重要提示：** 在最終評估之前，測試集必須保持完全不變，以避免資料外洩。
### 交叉驗證（k 倍）
對於小型資料集，使用 k 折交叉驗證：將資料拆分為 k 折，在 k-1 上進行訓練，對剩餘的進行驗證，然後重複 k 次。平均表現。 k=5 或 k=10 是常見的。
### 分層分裂
對於不平衡類別的分類，請使用分層分割來保留每個子集的類別比例。
### 基於時間的分割
對於時間序列數據，按時間順序分割（訓練過去，測試未來）而不是隨機。

## 評估指標
### 分類指標
|公制|它測量什麼 |最適合 |
|--------|--------------------|------------|
| **準確度** | (TP + TN) / (TP + TN + FP + FN) | (TP + TN) / (TP + TN + FP + FN) |平衡資料集|
| **精確** | TP / (TP + FP) |當誤報代價高昂時（例如垃圾郵件偵測）|
| **回憶** | TP / (TP + FN) |當假陰性代價高昂時（例如癌症篩檢）|
| **F1 分數** |精確率和召回率的調和平均值 |不平衡資料集，單數指標 |
| **AUC-ROC** | ROC曲線下面積； TPR 與 FPR 之間的權衡 |通用分類器效能與閾值無關 |
| **AUC-PR** |精確率-召回率曲線下的面積 |高度不平衡的資料集 |
**定義：**
- TP = 真陽性
- TN = 真陰性
- FP = 誤報（I 類錯誤）
- FN = 假陰性（II 類錯誤）
### 回歸指標
|公制|它測量什麼 |對異常值的敏感度|
|--------|--------------------------------|--------------------------|
| **MSE**（均方誤差）|平均平方差|高|
| **RMSE**（均方根誤差）| MSE 的平方根（與目標單位相同）|高|
| **MAE**（平均絕對誤差）|平均絕對差|低|
| **R²**（決定係數）|變異數比例解釋 |沒有直接影響，但間接對異常值敏感|
### 排名和檢索指標
- **Precision@k**：top-k 推薦中相關項目的比例。
- **Recall@k**：出現在 top-k 中的所有相關項目的分數。
- **NDCG**（標準化折現累積收益）：考慮部位相關性。
- **命中率**：相關項目是否出現在 top-k 中。
### 產生/法學碩士指標
- **困惑度**：模型對保留文字的「驚訝」程度（越低越好）。
- **BLEU**：n-gram 與參考翻譯重疊（注重精度）。
- **ROUGE**：以回憶為導向的重疊進行總結。
- **BERTScore**：使用上下文嵌入的語意相似性（比 BLEU 更強大）。
- **METEOR**：與 WordNet 同義詞和字幹對齊。

## 評估陷阱
### 資料外洩
當測試集中的資訊無意中影響訓練時就會發生。
- **預防：**切勿將測試資料用於特徵工程、標準化或超參數調整。
- **檢測：** 如果您的模型得分可疑高，則懷疑有洩漏。
### 過度擬合
模型在訓練資料上表現良好，但在驗證/測試上表現不佳。
- **緩解：** 使用正規化、提前停止、簡化架構或收集更多資料。
### 欠擬合
模型在訓練和驗證方面都表現不佳。
- **緩解：** 使用更複雜的模型，增加功能或減少正規化。
### 資料不平衡
- **緩解：** 使用類別權重、過採樣 (SMOTE)、欠採樣或使用適當的指標（F1、AUC-PR）而不是準確性。
### 時間漂移（概念漂移）
特徵和目標之間的關係隨著時間的推移而變化。
- **緩解：** 定期重新訓練、監控效能、使用漂移偵測演算法。
---

## 超參數調優
- **網格搜尋**：徹底嘗試一組預先定義超參數的所有組合。簡單但計算成本昂貴。
- **隨機搜尋**：從分佈中抽取隨機組合樣本。比高維度空間的網格搜尋更有效。
- **貝葉斯最佳化**：建立目標函數的機率模型並智慧選擇超參數。庫：Optuna、Hyperopt、scikit-optimise。
- **自動調整**：使用 Optuna、Ray Tune 或 Weights & Biases Sweeps 等工具進行分散式調整。
**常見超參數的建議搜尋範圍：**
|參數|建議範圍（對數刻度）|
|------------|----------------------------|
|學習率| 1e-5 至 1e-1 |
|批量大小| 16、32、64、128、256 |
|層數 (NN) | 2 至 6 |
|神經元數 (NN) | 32 至 1024 |
|正則化（L2）| 1e-6 至 1e-2 |
|樹深度（XGBoost）| 3 至 12 |

## 模型選擇與驗證
1. **基準模型**：從簡單的啟發式或簡單模型（例如邏輯迴歸、平均值預測器）開始建立下限。
2. **候選模型**：訓練多個模型系列（例如隨機森林、XGBoost、神經網路）。
3. **交叉驗證**驗證集上的每個候選者。
4. **比較指標**（與信賴區間）並選擇最佳候選者。
5. 對保留的測試集進行**最終評估**。
6. **錯誤分析**：查看模型出錯的範例。識別模式（例如，稀有類別、模糊輸入）並將見解回饋到資料準備或特徵工程。
---

## 部署和監控
### 服務模式
- **大量推理**：離線處理大量資料（例如，每晚建議）。
- **線上推理**：透過 API 進行即時預測（例如信用評分、詐欺檢測）。
- **串流推理**：事件驅動、即時、低延遲（例如，物聯網感測器警報）。
### 模型監控
- **效能監控**：追蹤即時資料隨時間變化的準確性/F1（當地面真實情況可用時）。
- **資料漂移**：監控輸入特徵分佈的變化（例如，使用 PSI – 群體穩定性指數）。
- **概念漂移**：監控輸入和輸出之間關係的變化。
- **預測漂移**：追蹤預測輸出的分佈。
- **延遲和吞吐量**：確保滿足 SLA（服務等級協定）。
### 日誌記錄和警報
- 記錄所有預測請求和回應（匿名）。
- 設定警報：
  - 性能顯著下降。
  - 遺失或無效輸入的比例很高。
  - 模型輸出超出預期範圍。
### 模型版本控制與登錄
- 使用模型註冊表（例如 MLflow、權重和偏差、Sagemaker 模型註冊表）來儲存和版本模型、元資料和評估結果。
- 將訓練程式碼和資料版本（透過 DVC 或 Git LFS）與模型一起儲存。

## 實用工作流程清單
- [ ] 問題架構與成功指標定義。
- [ ] 執行資料探索（缺失值、離群值、分佈）。
- [ ] 建立訓練/驗證/測試拆分（如果需要則分層）。
- [ ] 建立基線模型。
- [ ] 候選模型經過訓練和驗證。
- [ ] 超參數調整。
- [ ] 透過交叉驗證選擇最佳模型。
- [ ] 測試集的最終評估。
- [ ] 執行錯誤分析。
- [ ] 部署計畫就緒（服務基礎架構）。
- [ ] 監控儀表板設定。
- [ ] 文件（資料卡、型號卡）已完成。
