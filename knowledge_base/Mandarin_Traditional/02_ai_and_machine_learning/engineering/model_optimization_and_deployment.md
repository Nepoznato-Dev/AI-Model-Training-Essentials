# 模型最佳化和部署
訓練大型人工智慧模型是一項重大成就，但有效部署它是需要大部分工程工作的地方。對於大多數實際應用程式來說，需要 10 秒響應或需要 8 個 A100 GPU 的模型是不切實際的。模型最佳化是使模型更小、更快、更具成本效益的過程，同時保持可接受的品質。該文件涵蓋了量化、修剪、蒸餾以及在生產中部署模型的實用工具。
---

## 為什麼要優化？
|關注|影響 |
|---------|--------|
| **延遲** |使用者期望在 1 秒內得到回應；每增加 100 毫秒，參與度就會降低 |
| **成本** | GPU 推理成本高昂；70B 模型在雲端硬體上每 100 萬代幣的成本約為 0.05-0.15 美元 |
| **記憶體** | FP32 中的 7B 型號需要 28 GB VRAM；大多數消費性 GPU 具有 8-24 GB |
| **能源** |運行大型模型會消耗大量電力；對於移動和邊緣很重要|
| **規模** |為數百萬用戶提供服務需要適合可用硬體的型號 |
---

## 量化
量化將模型權重的精確度從 32 位元浮點 (FP32) 降低到更小的格式，如 INT8、INT4 甚至更低。
### 精確格式
|格式|每重量位數| 7B 型號記憶體 |品質 |
|--------------------|----------------|--------------------|---------|
| **FP32** | 32 | 32 28GB|基線（全精度）|
| **FP16 / BF16** | 16 | 16 14GB|與 FP32 幾乎相同 |
| **INT8** | 8 | 7GB|品質損失非常小 |
| **INT4** | 4 | 3.5 GB | 3.5 GB中等品質損失；還能用|
| **INT3 / INT2** | 3-2 | 3-2 2.6-1.75 GB |嚴重的質量損失；研究階段|
### 量化方法
|方法|當它發生時 |它是如何運作的 |品質 |
|--------|----------------|--------------|---------|
| **訓練後量化 (PTQ)** |訓練完成後 |在小資料集上校準模型；找到最佳尺度|適用於 INT8；INT4 時降級 |
| **GPTQ** |訓練後|使用近似二階資訊進行 GPU 友善的 INT4 量化 | INT4 品質優良 |
| **AWQ**（激活感知權重量化）|訓練後|根據激活幅度保護顯著權重 | INT4 優於 GPTQ |
| **GGUF**（llama.cpp 格式）|訓練後| CPU友善的量化；每層混合精度|針對 CPU 推理進行最佳化 |
| **量化感知訓練 (QAT)** |訓練期間 |在訓練期間模擬量化，以便模型學會應對 |極品;需要再訓練|
### 實際影響
|型號| FP16 尺寸 | INT4 尺寸 |加速|品質損失|
|--------|---------|------------|---------|------------|
| **駱駝 7B** | 14GB| 3.5 GB | 3.5 GB 2-4x |基準測試的約 1-2% |
| **駱駝 70B** | 140 GB | 140 GB 35GB| 2-3x |基準測試的約 2-3% |

## 修剪
剪枝從訓練模型中刪除不必要的權重或神經元。
|類型 |描述 |優點 |挑戰|
|------|-------------|------------|------------|
| **非結構化** |刪除單一權重（設定為零）|最高壓縮比 |需要稀疏的硬體支援 |
| **結構化** |刪除整個神經元、注意力頭或層 |直接縮小模型尺寸 |可能會失去更多品質|
| **基於幅度** |刪除絕對值最小的權重 |簡單的;效果很好|可能會錯過重要的小重量|
| **基於重要性** |根據權重對輸出的貢獻來刪除權重 |更好的品質保存 |計算成本更高 |
### 修剪管道
|步驟|描述 |
|------|-------------|
| 1. 火車 |正常訓練完整模型 |
| 2. 分數 |計算每個權重/神經元的重要性分數 |
| 3.修剪|刪除最不重要的元素 |
| 4.微調|重新訓練以恢復失去的準確度 |
| 5.重複|迭代剪枝和微調以實現更高的壓縮 |

## 知識蒸餾
訓練小型「學生」模型來模仿大型「教師」模型。
|組件|角色 |
|------------|------|
| **老師** |大型高品質模型 |
| **學生** |向老師學習的小模型|
| **蒸餾損失** |學生嘗試匹配老師的輸出分佈（軟標籤）|
### 蒸餾類型
|類型 |描述 |範例|
|------|-------------|---------|
| **基於 Logit** |學生與老師的輸出機率相符 |辛頓的原始蒸餾|
| **基於功能** |學生與老師的中間表示相符|健身網 |
| **基於關係** |學生配對樣本之間的關係 | RKD（關係知識蒸餾）|
| **無資料** |無需原始訓練資料；用師之輩| DAFL、深度反演 |
### 著名的蒸餾範例
|老師|學生|結果 |
|--------|---------|--------|
| **GPT-4** | GPT-3.5-turbo（傳聞）|較小的型號，具有 GPT-4 的大部分品質 |
| **BERT-大** |蒸餾伯特 |體積縮小 40%，速度提高 60%，性能達到 BERT 的 97% |
| **駱駝 70B** | LLaMA 7B（透過蒸餾）|開源小模型接近大模型品質 |

## LLM 特定優化
### KV-快取優化
大型語言模型會快取先前標記中的鍵值對以避免重新計算。
|技術|描述 |影響 |
|------------|-------------|--------|
| **多查詢注意力（MQA）** |所有註意力頭共享一對 KV |減少記憶力；輕微的質量損失|
| **分組查詢注意力（GQA）** |頭組共享 KV 對 | MQA 與標準注意力之間的平衡 |
| **滑動視窗注意** |只專注於最後的 W 令牌 |減少長上下文的 KV 快取大小 |
### 推測解碼
|步驟|描述 |
|------|-------------|
| 1 |一個小型「草稿」模型快速產生 K 個代幣 |
| 2 |大型模型在一次前向傳遞中驗證所有 K 個令牌 |
| 3 |保留已接受的代幣；被拒絕的被再生|
結果：生成速度提高 2-3 倍，且沒有品質損失（大模型始終擁有最終決定權）。
### 閃光注意
|特色 |描述 |
|---------|-------------|
| **問題** |標準注意力需要 O(n²) 記憶體來儲存注意力矩陣 |
| **解** |以區塊為單位計算注意力；永遠不要在記憶體中具體化完整的矩陣|
| **結果** |速度提高 2-4 倍；啟用更長的上下文視窗
| **變體** | Flash Attention 2（更快）、FlashDecoding（針對推理進行了優化）|

## 部署模式
|圖案|說明 |何時使用 |
|---------|-------------|----------|
| **邊緣部署** |在手機、物聯網設備或嵌入式硬體上運行模型 |低延遲；離線；隱私 |
| **雲端API** |在雲端 GPU 上託管模型；透過 API 提供服務 |最大運算量；按使用付費|
| **混合** |設備上的小模型；雲端中的大型模型|兩全其美 |
| **無伺服器** |縮放至零；僅在使用時付費 |零星交通；成本敏感 |
| **批量推理** |按計劃批量處理資料 |當不需要即時時 |

## 基準測試
|公制|它測量什麼 |
|--------|-----------------|
| **每秒令牌數** |產生吞吐量（越高越好）|
| **第一個令牌的時間 (TTFT)** |第一個輸出標記出現之前的延遲 |
| **每個請求的延遲** |從輸入到完成輸出的總時間|
| **記憶體使用情況** |推理過程中消耗的 VRAM 或 RAM |
| **吞吐量** |每秒處理的請求數 |
| **每 100 萬個代幣的成本** |處理 100 萬個代幣的美元成本 |

## 實用技巧
- **從量化開始。 ** INT4 量化（AWQ 或 GPTQ）提供最佳的品質與尺寸權衡。大多數 7B 型號可以在 INT4 的單一消費級 GPU 上輕鬆運作。
- **使用 vLLM 進行 LLM 服務。 ** 它是用於高吞吐量 LLM 推理的最快開源選項。
- **優化前的設定檔。 ** 衡量實際花費時間的地方。瓶頸通常是記憶體頻寬，而不是計算。
- **將模型與任務配對。 ** 7B 模型適用於大多數任務。當 7B 就可以時，不要使用 70B。
- **考慮蒸餾。 ** 如果您需要一個小型、快速的模型進行生產，請從較大的模型中進行蒸餾，而不是從頭開始訓練。
- **持續監控。 ** 隨著資料分佈的變化，模型效能可能會隨著時間的推移而降低。追蹤延遲、吞吐量和品質指標。
---

＃＃ 概括
模型最佳化是研究和生產之間的橋樑。量化可將模型縮小 4-8 倍，同時將質量損失降至最低。修剪可以消除自重。蒸餾將知識從大模型轉移到小模型。 Flash Attention 和 KV 快取技巧讓推理速度更快。這些技術共同將需要資料中心的模型轉變為在筆記型電腦或手機上運行的模型。該領域正在快速發展——去年需要 8 個 A100 的任務如今可以在消費級 GPU 上運行。
