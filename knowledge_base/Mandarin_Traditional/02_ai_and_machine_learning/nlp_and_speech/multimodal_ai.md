# 多模態人工智慧
多模式人工智慧系統同時處理和組合來自多種類型資料（文字、圖像、音訊、視訊等）的資訊。雖然早期的人工智慧系統通常是單模態（僅文字、僅圖像），但最強大的現代系統是多模態的。 GPT-4V同時讀取圖像和文字； Gemini 原生處理文字、圖像、音訊和視訊；像 Sora 這樣的系統可以根據文字描述產生視訊。該文件介紹了多模式人工智慧的工作原理、背後的架構，以及為什麼組合模式如此強大。
---

## 為什麼是多式聯運？
|效益 |描述 |範例|
|---------|-------------|---------|
| **更豐富的理解** |不同的方式提供補充訊息|影片能夠傳達僅靠文字無法傳達的動作、聲音和背景 |
| **更好的概括** |跨模式學習創造更強大的表徵 |看過“貓”的圖像和文字描述的模型可以更好地理解這個概念 |
| **更自然的互動** |人類透過多種管道進行溝通|語音助理可以看到你所指的內容 |
| **跨模式轉乘** |來自一種方式的知識有助於另一種方式 |圖像理解可以改善文本生成，反之亦然 |
---

## 核心架構
### 視覺語言模型 (VLM)
同時處理圖像和文字的模型。
|建築|它是如何運作的 |範例 |
|-------------|-------------|---------|
| **雙編碼器** |圖像和文字分開的編碼器；稍後合併|剪輯、對齊 |
| **融合編碼器** |圖像和文字標記交織並一起處理 |火烈鳥，雙子座|
| **交叉關注** |文字標記關注圖像特徵（反之亦然）|火烈鳥、可口可樂|
| **統一標記器** |圖像被轉換為標記並與文字標記一起處理 |雙子座、變色龍|
### 視覺語言模型如何運作
|步驟|描述 |
|------|-------------|
| **1.編碼影像** |視覺編碼器（ViT、SigLIP）將影像轉換為一組特徵向量 |
| **2.編碼文字** |語言編碼器處理文字標記 |
| **3.熔斷方式** |影像特徵被投影到語言模型的嵌入空間中 |
| **4.生成** |語言模型根據圖像和文字輸入生成文本
### 關鍵視覺語言模型
|型號|開發商|建築|顯著特點|
|--------|---------|-------------|------------------|
| **剪輯** |開放人工智慧 |雙編碼器（ViT + 文字編碼器）|透過文字進行零樣本影像分類 |
| **拉瓦** |開源| LLaMA + CLIP 視覺編碼器 |開源VLM；強大的社群|
| **GPT-4V/4o** |開放人工智慧 |統一多式聯運|一起處理文字、圖像、音訊 |
| **雙子座** |Google DeepMind |來自訓練的原生多模式 |從頭開始為多式聯運而打造 |
| **克勞德** |人擇 |視覺+文字|擅長文檔和圖表理解 |
| **Qwen-VL** |阿里巴巴 |開放重量 VLM |與封閉機型競爭|
| **實習生VL** |開源|多尺度視覺編碼器 |強大的開源選項|

## 音訊和語音模型
### 語音辨識 (ASR)
|型號|建築|顯著特點|
|--------|-------------|-----------------|
| **耳語** (OpenAI) |編碼器-解碼器變壓器|經過 68 萬小時的多語言音訊訓練；堅固耐用 |
| **符合者** |卷積+自註意力|結合本地和全球特徵 |
| **wav2vec 2.0** |自我監督|從未標記的語音中學習 |
| **USM**（Google）|通用語音模型 | 200萬小時的標記資料；300 多種語言 |
### 文字轉語音 (TTS)
|型號|方法|顯著特點|
|--------|----------|-----------------|
| **VALL-E**（微软）|神经编解码器 |从 3 秒样本克隆声音 |
| **树皮** (Suno) |基于变压器|多种语言;包括非语音 |
| **十一实验室** |商业|高品质语音克隆|
| **聊天TTS** |开源|具有自然韵律的对话式演讲 |
| **魚語** |開源|多種語言;快速推理 |
### 音訊理解
|型號|能力|
|------|----------|
| **音訊LDM** |從文字產生音效 |
| **MusicGen**（元）|文字轉音樂生成 |
| **Qwen-音訊** |音訊理解（語音、音樂、環境聲音）|
| **鮭魚** |語音、音訊、語言、音樂和噪音理解 |

## 影片模型
視訊結合了圖像、音訊、文字和時間——使其成為最複雜的模式。
|型號|類型 |能力|
|--------|------|-------------|
| **索拉** (OpenAI) |文字轉視頻|高達 1080p；懂物理 |
| **雙子座** |視訊理解 |可以分析帶有音訊的長視頻 |
| **影片-LLaVA** |影片+文字|開源影片理解|
| **跑道第三代** |文字/圖像轉影片 |商業影片生成 |
| **克林** |文字轉影片|長影片生成 |
### 影片理解挑戰
|挑戰|描述 |
|------------|-------------|
| **時間推理** |了解隨時間推移發生的事件 |
| **長上下文** |影片可能長達數小時；處理所有幀的成本很高|
| **視聽同步** |將所說的與所顯示的連結起來 |
| **因果關係** |了解影片序列中的因果關係 |

## 跨模態檢索
跨不同方式尋找相關內容。
|任務|描述 |範例|
|------|-------------|---------|
| **文字→圖像** |尋找與文字查詢相符的圖像 |在照片庫中搜尋「山上的日落」|
| **圖像 → 文字** |尋找與圖像相關的文字 |為圖像產生標題 |
| **文字 → 音訊** |尋找與描述相符的聲音 |聲音設計：「碎石上的腳步聲」|
| **圖像→圖像** |尋找視覺上相似的圖像 |按圖片搜尋產品|
### 用於跨模式檢索的 CLIP
CLIP 的共享嵌入空間可實現零樣本跨模態檢索：
|步驟|描述 |
|------|-------------|
| 1 |使用視覺編碼器對所有影像進行編碼 |
| 2 |使用文字編碼器對文字查詢進行編碼 |
| 3 |計算文字嵌入與所有影像嵌入之間的餘弦相似度 |
| 4 |傳回相似度最高的影像 |
這無需任何特定於任務的訓練即可工作——這種特性稱為「零射擊」能力。

## 體現人工智慧
具身人工智慧將多模態感知與身體動作結合。
|系統|模態 |應用 |
|--------|----------|-------------|
| **RT-2**（Google）|視覺+語言→機器人動作|透過文字指令進行通用機器人控制 |
| **奧克托** |開源機器人政策|使用不同的機器人資料進行訓練 |
| **特斯拉擎天柱** |視覺+語言→體力任務|用於一般任務的人形機器人|
| **圖01** |視覺+語言+言語|具有對話能力的人形機器人|
### 嵌入式人工智慧的挑戰
|挑戰|為什麼很難 |
|------------|--------------|
| **模擬與真實的差距** |模擬並不能完美地捕捉現實世界的物理現象
| **靈巧** |精細動作控制（手、手指）極為困難 |
| **安全** |物理機器人會造成真正的傷害|
| **即時處理** |必須在毫秒內感知、決定並採取行動 |
| **概括** |接受過拿起紅色杯子訓練的機器人可能會無法拿起藍色杯子

＃＃ 概括
多模態人工智慧代表了從單一用途模型到能夠感知和推理所有形式數據的系統的轉變。 GPT-4V和Gemini等視覺語言模型可以同時理解圖像和文字； Whisper 和 VALL-E 等語音模型處理音訊；視訊模型開始處理帶有聲音的動作影像的全部複雜性。趨勢很明顯：未來最強大的人工智慧系統將是原生多模式的，同時處理所有類型的信息。數據對齊、計算成本、評估和具體部署等挑戰是巨大的，但 2024 年至 2026 年的進展很快。
