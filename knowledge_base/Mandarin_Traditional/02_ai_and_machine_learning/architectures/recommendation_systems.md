# 推薦系統
推薦系​​統預測使用者接下來想要看到、購買或互動的內容。它們為社交媒體上的內容提要、電子商務網站上的產品建議、串流平台上的電影精選以及搜尋結果提供支援。儘管大多數用戶看不見，但它們是世界上最具商業影響力的人工智慧系統之一——Netflix 估計，其推薦引擎透過減少用戶流失，每年節省超過 10 億美元。
---

## 為什麼推薦很難
|挑戰|描述 |
|------------|-------------|
| **規模** |數百萬用戶 × 數百萬商品 = 數十億可能對 |
| **稀疏性** |每個使用者都與一小部分可用項目進行了互動 |
| **冷啟動** |新用戶和新物品沒有交互歷史 |
| **動態首選項** |使用者品味隨時間而變化|
| **超越準確度** |推薦也必須是多樣化的、新穎的和偶然的 |
| **業務目標** |最大化參與度≠最大化使用者福祉|
---

## 核心方法
### 協同過濾
這個想法是：如果使用者 A 和 B 過去同意，他們將來也可能會同意。
|類型 |它是如何運作的 |範例|
|------|-------------|---------|
| **基於使用者** |尋找相似的使用者；推薦他們喜歡的 | 「喜歡這個的使用者也喜歡...」 |
| **基於專案** |尋找與使用者已經喜歡的類似的項目 | 「因為你看了…」 |
| **矩陣分解** |將使用者-項目交互矩陣分解為潛在因素 | SVD、ALS（交替最小平方法）|
|實力|弱點|
|----------|----------|
|無需了解物品本身|冷啟動問題：無法推薦新商品|
|捕捉複雜、隱含的偏好 |需要大量互動資料 |
|適用於任何內容類型 |流行度偏差：推薦已經流行的商品 |
### 基於內容的過濾
根據商品特徵推薦與使用者已經喜歡的商品相似的商品。
|特徵類型|範例|
|-------------|---------|
| **文字** |類型、描述、關鍵字、演員 |
| **音頻** |節奏、流派、情緒（音樂）|
| **視覺** |調色盤、風格（圖像/時尚）|
| **元資料** |價格、品牌、類別 |
|實力|弱點|
|----------|----------|
|專案無冷啟動（功能已知）|無法推薦超出使用者現有口味的商品 |
|使用較少的互動資料即可工作 |需要良好的特徵工程 |
|可解釋（“推薦，因為它與 X 類似”）|更少的偶然性|
### 混合方法
大多數生產系統結合了協作和基於內容的方法。
|混合戰略|描述 |
|----------------|-------------|
| **加權** |合併多個模型的分數 |
| **切換** |對於新使用者使用基於內容的方式，對於舊用戶使用協作方式 |
| **級聯** |首先使用一個簡單的模型，然後使用複雜的模型進行細化 |
| **功能組合** |將協作和內容功能合併到單一模型中 |
| **元學習** |了解如何組合不同的推薦器 |

## 現代深度學習方法
### 兩塔模型
大規模推薦的主導架構（YouTube、Pinterest、Spotify 使用）。
|組件|角色 |
|------------|------|
| **用戶塔** |將使用者特徵和歷史記錄編碼到嵌入中的神經網路 |
| **物品塔** |將項目特徵編碼到嵌入中的神經網路 |
| **相似性** |使用者與項目嵌入之間的點積或餘弦相似度 |
|步驟|描述 |
|------|-------------|
| 1 |訓練兩個塔為互動的使用者-專案對產生類似的嵌入 |
| 2 |在服務時，預先計算項目嵌入 |
| 3 |對於使用者要求，計算使用者嵌入|
| 4 |使用近似最近鄰 (ANN) 搜尋來尋找最相似的項目 |
### 推薦序列模型
使用者行為是連續的—您昨天觀看的內容會影響您今天觀看的內容。
|型號|方法|
|--------|----------|
| **GRU4Rec** |用於基於會話的推薦的基於 GRU 的模型 |
| **SASRec** |基於自註意力的順序推薦器 |
| **BERT4Rec** |用於順序建議的雙向變壓器 |
| **YouTube DNN** |深度神經網路將觀看歷史記錄視為一個序列 |
### 檢索與排名
現代系統將建議分為兩個階段：
|舞台|目的|方法|
|--------|---------|--------|
| **檢索（候選生成）** |將數百萬個項目縮小到約 1,000 個候選者 |兩塔模型；人工神經網路搜尋；快速但近似|
| **排名（評分）** |精準評分並排序候選人 |具有多種特徵的深度模型；較慢但準確 |
| **重新排名** |針對多樣性、業務規則、新鮮度進行調整 |上下文強盜；約束優化|

## 評估指標
|公制|它測量什麼 |何時使用 |
|--------|-----------------|-------------|
| **精準@K** |相關的 Top-K 建議的比例 |當您關心首選的準確性時 |
| **回憶@K** |在 top-K 中找到的相關項目的比例 |當你在意不要錯過好單品時 |
| **NDCG**（標準化折現累積增益）|排名品質；獎勵將相關項目提升到更高水準 |當排名順序很重要時 |
| **MAP**（平均精度）|所有用戶的平均精確度 |綜合排名品質|
| **命中率@K** | top-K 中是否至少出現一項相關項目 |二元相關場景|
| **涵蓋範圍** |獲得建議的項目比例 |多元化與公平 |
| **機緣巧合** |意想不到但相關的建議 |使用者滿意度 |

## 冷啟動問題
|場景|挑戰|解決方案 |
|----------|------------|------------|
| **新使用者** |沒有互動歷史 |使用人口統計資料；顯示熱門商品；使用情境訊號（位置、裝置、時間） |
| **新項目** |尚未有人與之互動 |使用內容特徵；探索-利用策略；強盜演算法 |
| **新系統** |沒有資料 |來自相似領域的遷移學習；規劃初始內容 |

## 探索與利用
|戰略|描述 |權衡|
|----------|-------------|------------|
| **ε-貪婪** |以機率 ε 顯示隨機項目 |簡單但低效|
| **湯普森採樣** |物品品質後驗分佈的樣本 |有原則；良好的理論特性 |
| **信賴上限 (UCB)** |偏好具有高度不確定性的項目 |勘探與開採的良好平衡|
| **情境強盜** |以使用者情境為條件的探索 |比盲目探索更有效率 |
| **多樣性注入** |故意包含多樣化或新穎的項目 |簡單的;可能會減少短期參與|
---

## 偏見與公平
|偏移類型|描述 |影響 |
|------------|-------------|--------|
| **受歡迎程度偏差** |熱門商品獲得更多推薦，變得更受歡迎 |長尾產品服務不足 |
| **選擇偏差** |模型從觀察到的交互中學習，而不是所有可能的交互偏向活躍用戶|
| **位置偏差** |無論品質如何，顯示在較高位置的項目都會獲得更多點擊次數 |鞏固頂級地位 |
| **曝光偏差** |已顯示的項目會獲得更多訓練訊號 |回饋循環|
| **人口偏見** |不同人群的建議存在不公平的差異 |歧視;一些團體的體驗不佳|
### 緩解策略
|戰略|描述 |
|----------|-------------|
| **逆傾向權重** |減重訓練中熱門項目|
| **去偏層** |為模型加入去偏組件 |
| **公平約束** |增加約束以確保公平待遇 |
| **多樣化推薦** |明確優化多樣性和相關性 |
| **審計與監控** |定期檢查建議是否有跨群體偏差 |

＃＃ 概括
推薦系​​統是業界最具影響力的人工智慧應用之一。該領域已從簡單的協作過濾發展到結合用戶歷史、專案內容、上下文訊號和業務目標的深度學習架構。現代系統使用檢索-排名-重新排名管道，具有用於快速候選生成的兩塔模型和用於精確評分的深度模型。冷啟動、偏差、探索以及平衡用戶滿意度與業務目標等挑戰仍然是研究和工程的活躍領域。
