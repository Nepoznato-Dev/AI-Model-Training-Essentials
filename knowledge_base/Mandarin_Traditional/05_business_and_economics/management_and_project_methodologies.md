# 管理和專案方法
管理人員和專案是任何組織中最艱鉅的職責之一。技術技能提供了入口，但領導團隊、決策、有效溝通和交付結果的能力決定了目標是否實現。該文件涵蓋了高效的管理者和專案領導者應用的框架、方法和實踐技能。
---

## 領導風格
沒有單一的「正確」的領導方式。最好的風格取決於團隊、任務和環境。
|风格|描述 |最佳时间 |风险|
|--------|-------------|----------|-----|
| **獨裁** |領導者以最少的投入做出決策 |危機;團隊缺乏經驗；時間壓力|士氣低落；對領導者的依賴|
| **民主** |領導徵求意見；團隊具有真正的影響力|技術精湛的團隊；需要支持的複雜決策|決策速度較慢；可能會感到猶豫不決|
| **自由放任** |領導提供方向；團隊自我管理 |高技能、自我激勵的專家 |缺乏協調；責任不明確|
| **變革** |領導者激發願景和個人成長|改變舉措；建立高績效文化|如果執行不落地，可能會被燒毀|
| **僕人式領導** |領導者優先考慮團隊的需求和發展 |知識工作者；建立信任和忠誠度 |在等級文化中可能被視為弱者 |
| **情況** |領導者根據團隊成熟度和任務調整風格 |最真實的情況|需要高情商|
### 偉大的管理者其實是做什麼的
研究（尤其是來自 Google 的 Project Oxygen）確定了高效能管理者的主要行為：
1. **是一位好教練** — 提出問題，幫助人們思考，而不僅僅是給出答案
2. **賦予團隊權力**－有意義地授權；不進行微觀管理
3. **創造包容的環境**－心理安全；每個人都可以做出貢獻
4. **有成效且以結果為導向** — 讓團隊專注於重要的事情
5. **是優秀的溝通者** - 傾聽、分享背景、給予明確的方向
6. **支持職涯發展**——談論成長，而不僅僅是任務
7. **有清晰的願景和策略** - 知道團隊要去哪裡以及為什麼
8. **擁有關鍵技術技能** - 可以提供建議並理解工作（即使不做）

## 專案管理方法
### 傳統（瀑布）
|相|活動 |
|------|----------|
| **要求** |收集並記錄需要建造的內容 |
| **設計** |建築、規格、計劃|
| **實施** |建構事物 |
| **測試** |驗證其依規定工作 |
| **部署** |發佈給生產/使用者|
| **維護** |修復問題；持續支援|
**最適合**：建築業、製造業、受監管的行業，這些行業的要求是固定的，而改變的成本很高。
### 敏捷
敏捷是一種心態，而不是一種方法論。它來自[Agile Manifesto](https://agilemanifesto.org/)(2001)：
> *個人和互動*超過流程和工具
> *工作軟體*勝過全面的文檔
> *客戶合作*勝過合約談判
> *回應變化*而不是遵循計劃
|敏捷原則|這在實務上意味著什麼？
|----------------|--------------------------------|
|經常交付工作軟體 |短迭代（1-4 週）|
|歡迎變更需求 |即使在開發後期|
|企業與開發者攜手合作|日常協作，不只是在開始與結束時 |
|圍繞積極主動的個人建構專案 |給他們所需的環境和信任 |
|面對面交談 |最有效的訊息傳達方式 |
|可用的軟體是衡量進度的主要標準 |不是文件，不是計劃|
|可持續步伐|無限期；沒有死亡行軍|
|持續關注技術卓越|良好的設計和簡潔的程式碼 |
|簡單 |最大化未完成的工作 |
|自組織團隊|最好的架構和設計從中誕生|
|經常反思與調適|回顧；持續改進|
### Scrum
Scrum 是使用最廣泛的敏捷框架。
|元素|描述 |
|---------|-------------|
| **衝刺** |定長迭代（通常2週） |
| **產品負責人** |定義待辦事項並確定優先順序；代表利害關係人 |
| **Scrum 大師** |促進過程；消除障礙；保護團隊|
| **開發團隊** |跨職能、自組織（理想規模為 5-9 人）|
| **產品待辦事項** |可能需要的所有內容的優先清單 |
| **衝刺積壓** |為當前衝刺選擇的項目 + 交付它們的計劃 |
| **每日站立** | 15 分鐘同步：我做了什麼？我該怎麼辦？有攔截器嗎？ |
| **衝刺回顧** |向利害關係人示範工作軟體；收集回饋|
| **衝刺回顧** |團隊反思如何改善流程|
### 看板
看板是一種基於流程的方法，專注於視覺化工作並限制正在進行的工作。
|實踐|描述 |
|----------|-------------|
| **視覺化工作流程** |有列的板子（待辦事項 → 進行中 → 審核 → 已完成）|
| **限制在製品** |設定每列的最大項目數 |
| **管理流程** |測量週期時間；識別並消除瓶頸|
| **明確政策** |每個人都同意每列的「完成」意義 |
| **協作改進** |使用數據和回饋來改進流程 |
**Scrum 與看板**：
| | Scrum |看板|
|---|--------|--------|
| **節奏** |固定衝刺（2 週）|連續流|
| **角色** | PO、Scrum Master、團隊 |沒有規定的角色 |
| **改變** |衝刺中期沒有變化 |隨時更改|
| **指標** |速度（每個衝刺的故事點）|週期時間、吞吐量|
| **最適合** |定期發布產品開發 |支援團隊；持續交付|

## OKR 和 KPI
### OKR（目標和關鍵結果）
OKR 是 Google、Intel、Spotify 和許多其他公司使用的目標設定框架。
|組件|描述 |範例|
|------------|-------------|---------|
| **目標** |高品質、雄心勃勃、鼓舞人心 | “成為小型企業會計的首選平台” |
| **關鍵結果 1** |可測量；證明目標正在實現|將每月活躍用戶從 1 萬增加到 5 萬 |
| **關鍵結果 2** |可測量| NPS 分數達到 60+ |
| **關鍵結果 3** |可測量|將入職時間從 30 分鐘減少到 5 分鐘 |
**OKR 最佳實踐**：
- 每季設定 3-5 個目標
- 每個目標有 2-5 個關鍵結果
- 目標是 70% 的成就（100% 意味著目標太容易了）
- OKR 與績效評估是分開的
- 透明：每個人都可以看到其他人的 OKR
### KPI（關鍵績效指標）
|类别 | KPI 示例 |
|----------|-------------|
| **财务** |收入、毛利率、净利润、EBITDA |
| **客戶** | NPS、CSAT、流失率、CLV |
| **产品** | DAU/MAU、功能采用、价值实现时间 |
| **工程** |部署频率、交付周期、MTTR、变更失败率 |
| **营销** | CAC、ROAS、转化率、有机流量 |
| **人** |员工 NPS、保留率、聘用时间 |

## 利害關係人管理
|利害關係人類型 |他們關心什麼 |如何參與 |
|----------------|---------------------|------------------------|
| **執行贊助商** |投資報酬率、策略調整、風險 |每月更新；專注於結果 |
| **最終用戶** |易用性、可靠性，解決他們的問題 |用戶研究；測試版程式；支援頻道|
| **技術團隊** |程式碼品質、架構、技術債 |架構評論；技術講座；參與決策|
| **外部客戶** |交貨時間、品質、價值 |定期演示；清晰的溝通； SLA |
| **監管機構/合規性** |法律要求、審計追蹤 |文件；積極參與 |
### 權力/利益網格
| |低利息 |高興趣 |
|---|-------------|---------------|
| **高功率** |保持滿意 |密切管理（關鍵人物） |
| **低功耗** |監控（最少的努力）|隨時了解情況 |

## 通訊框架
|框架|結構|何時使用 |
|------------|----------|----------|
| **準備** |重點 → 原因 → 範例 → 要點 |有說服力的溝通；會議 |
| **星星** |情境→任務→行動→結果|面試；績效評估|
| **虛張聲勢** |底線在前面|發送給高階主管的電子郵件；狀態更新|
| **SBAR** |情境→背景→評估→建議|交接；事件通訊 |
| **7 Cs** |清晰、簡潔、具體、正確、連貫、完整、禮貌 |一般書面溝通 |
### 提供回饋
|方法|描述 |
|----------|-------------|
| **SBI**（情況-行為-影響）| 「在昨天的會議（情況）中，你打斷了客戶（行為），這讓他們關閉了（影響）。」 |
| **前饋** |專注於未來的行為，而不是過去的錯誤。 「下次，試試看…」 |
| **激進的坦率** (Kim Scott) |親自關懷+直接挑戰。不太友善（毀滅性的同理心），也不太嚴厲（令人討厭的侵略）。 |

## 決策模型
|型號|描述 |最適合 |
|--------|-------------|----------|
| **快速** |推薦、同意、執行、輸入、決定 — 明確誰做什麼 |涉及眾多利害關係人的複雜決策 |
| **RACI** |負責、負責、諮詢、知情－角色清晰 |專案任務與可交付成果 |
| **艾森豪威爾矩陣** |緊急/重要網格 - 確定任務的優先級 |個人生產力；任務分類|
| **決策矩陣** |根據加權標準對選項進行評分 |在替代方案之間進行選擇|
| **OODA 循環** |觀察→定位→決定→行動－快速決策週期|競爭情境；事件回應|
| **六顶思考帽** |从 6 个角度看待决策（事实、情感、风险、收益、创造力、过程）|团体决策；避免群体思维|
### 艾森豪威爾矩陣
| |緊急|不緊急 |
|---|--------|------------|
| **重要** | **先做** — 危機、截止日期、關鍵問題 | **時間表** — 策略規劃、關係建立、學習 |
| **不重要** | **代表** — 一些電子郵件、會議、打擾 | **消除** — 浪費時間、忙碌的工作、過度瀏覽 |

## 風險管理
|步驟|描述 |
|------|-------------|
| **1.辨識風險** |集體討論可能出問題的地方（技術、日程、資源、外部）|
| **2.評估機率和影響** |對每種風險進行評級：高/中/低 |
| **3.優先** |關注高機率、高影響的風險 |
| **4.計畫回應** |避免、減輕、轉移或接受每個風險 |
| **5.監控** |定期回顧；風險隨著專案的發展而改變|
### 風險因應策略
|戰略|描述 |範例|
|----------|-------------|---------|
| **避免** |改變計劃消除風險|使用經過驗證的技術而不是實驗 |
| **緩解** |降低機率或影響 |增加緩衝時間；僱用額外員工 |
| **轉讓** |將風險轉移給第三方|保險;外包；固定價格合約|
| **接受** |如果發生的話，承認併計劃 |應急基金；後備計劃|

## 遠端團隊管理
|挑戰|解決方案 |
|------------|----------|
| **溝通差距** |預設為書面；過度溝通背景；使用非同步優先工具 |
| **隔離** |常規1:1；虛擬社交活動；偶爾的面對面聚會|
| **時區** |輪替會議時間；記錄決定；最小化同步依賴性|
| **可見性** | DM 上的公共管道；書面狀態更新；共用儀表板 |
| **信任** |衡量結果，而不是時間；避開監控軟體|
| **入職** |結構化的好友系統；記錄的流程；明確的第一週目標|
### 有效的會議
|會議類型 |持續時間 |頻率|目的|
|------------|---------|------------|---------|
| **每日站會** | 15 分鐘 |每日 |同步；表面阻斷劑 |
| **衝刺計畫** | 1–2 小時 |每次衝刺 |協調下一步要建構的內容 |
| **衝刺回顧** | 1 小時 |每一次衝刺 |示範；收集回饋|
| **回顧** | 45–60 分鐘 |每一次衝刺 |流程改善|
| **1:1** | 30 分鐘 |每週/每兩週 |個人支持與成長|
| **全體人員** | 30–60 分鐘 |每月 |公司/團隊更新；問答 |
**會議規則**：每次會議都需要議程。準時開始。準時結束。與所有者分配行動項目。如果可以是電子郵件，請將其設為電子郵件。

## 組織架構
|結構|描述 |優點 |缺點 |
|------------|-------------|------|-----|
| **功能性** |按專業（工程、行銷、銷售）組織 |深厚的專業知識；清晰的職業道路 |筒倉；緩慢的跨職能工作|
| **部門** |依產品、市場或地理位置組織 |重點;問責制 |重複的資源；不一致的做法|
| **矩陣** |人們向職能經理和專案經理報告工作|彈性;資源共享|優先事項相互衝突；關於誰負責的混亂|
| **扁平/合弄制** |最小的層級結構；自組織團隊 |速度;自治;創新|決策不明確；擴展性不好 |
| **團隊拓樸** (Skelton/Pais) |流對齊團隊+平台團隊+使能團隊+複雜子系統團隊|與實際工作流程保持一致 |需要周到的設計；不是靈丹妙藥|

## 產品管理基礎知識
產品管理是一門決定要建構什麼、為誰建構以及為何建構的學科，並確保其創造價值。
|責任|描述 |
|----------------|-------------|
| **發現** |使用者研究、市場分析、競爭情報 |
| **策略** |產品願景、路線圖、優先架構 |
| **執行** |編寫規格/使用者故事；從事工程和設計工作 |
| **啟動** |上市規劃；定位；銷售支援 |
| **迭代** |分析指標；收集回饋；決定下一步改進的優先順序 |
### 優先權框架
|框架|它是如何運作的 |
|------------|-------------|
| **莫斯科** |必須有/應該有/可以有/不會有|
| **米** |影響力 × 影響力 × 信心 ÷ 努力 |
| **卡諾模型** |將功能分為基本功能、性能功能或愉悅功能 |
| **價值與努力矩陣** |在 2×2 網格上繪圖；優先考慮高價值、省力的項目 |
| **機會評分** |重要性減去滿意度；尋找服務不足的需求|

＃＃ 概括
管理是透過他人實現目標的實踐。高效率的管理者將清晰的思考（框架、方法、指標）與人際溝通能力（傾聽、同理心、信任）結合。沒有任何方法可以取代良好的判斷，但良好的判斷可以透過健全的框架來增強。這些應該作為實踐指南而不是僵化的學說來應用。
