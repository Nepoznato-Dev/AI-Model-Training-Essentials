# 管理和项目方法
管理人员和项目是任何组织中最艰巨的职责之一。技术技能提供了入口，但领导团队、决策、有效沟通和交付结果的能力决定了目标是否实现。该文件涵盖了高效的管理者和项目领导者应用的框架、方法和实践技能。
---

## 领导风格
没有单一的“正确”的领导方式。最好的风格取决于团队、任务和环境。
|风格|描述 |最佳时间 |风险|
|--------|-------------|----------|-----|
| **独裁** |领导者以最少的投入做出决策 |危机;团队缺乏经验；时间压力|士气低落；对领导者的依赖|
| **民主** |领导征求意见；团队具有真正的影响力|技术精湛的团队；需要支持的复杂决策|决策速度较慢；可能会感到犹豫不决|
| **自由放任** |领导提供方向；团队自我管理 |高技能、自我激励的专家 |缺乏协调；责任不明确|
| **变革** |领导者激发愿景和个人成长|改变举措；建设高绩效文化|如果执行不落地，可能会被烧毁|
| **仆人式领导** |领导者优先考虑团队的需求和发展 |知识工作者；建立信任和忠诚度 |在等级文化中可能被视为弱者 |
| **情况** |领导者根据团队成熟度和任务调整风格 |最真实的情况|需要高情商|
### 伟大的管理者实际上是做什么的
研究（尤其是来自 Google 的 Project Oxygen）确定了高效管理者的主要行为：
1. **是一位好教练** — 提出问题，帮助人们思考，而不仅仅是给出答案
2. **赋予团队权力**——有意义地授权；不进行微观管理
3. **创造包容的环境**——心理安全；每个人都可以做出贡献
4. **富有成效且以结果为导向** — 让团队专注于重要的事情
5. **是一个优秀的沟通者** - 倾听、分享背景、给出明确的方向
6. **支持职业发展**——谈论成长，而不仅仅是任务
7. **有清晰的愿景和战略** - 知道团队要去哪里以及为什么
8. **拥有关键技术技能** - 可以提供建议并理解工作（即使不做）

## 项目管理方法
### 传统（瀑布）
|相|活动 |
|------|----------|
| **要求** |收集并记录需要构建的内容 |
| **设计** |建筑、规格、计划|
| **实施** |构建事物 |
| **测试** |验证其按规定工作 |
| **部署** |发布给生产/用户|
| **维护** |修复问题；持续支持|
**最适合**：建筑业、制造业、受监管的行业，这些行业的要求是固定的，而改变的成本很高。
### 敏捷
敏捷是一种心态，而不是一种方法论。它来自[Agile Manifesto](https://agilemanifesto.org/)(2001)：
> *个人和互动*超过流程和工具
> *工作软件*胜过全面的文档
> *客户合作*胜过合同谈判
> *响应变化*而不是遵循计划
|敏捷原则|这在实践中意味着什么？
|----------------|--------------------------|
|经常交付工作软件 |短迭代（1-4 周）|
|欢迎变更需求 |即使在开发后期|
|企业与开发者携手合作|日常协作，不仅仅是在开始和结束时 |
|围绕积极主动的个人构建项目 |给他们所需的环境和信任 |
|面对面交谈 |最有效的信息传达方式 |
|可用的软件是衡量进度的主要标准 |不是文件，不是计划|
|可持续步伐|无限期；没有死亡行军|
|持续关注技术卓越|良好的设计和简洁的代码 |
|简单 |最大化未完成的工作 |
|自组织团队|最好的架构和设计从中诞生|
|经常反思与调整|回顾；持续改进|
### Scrum
Scrum 是使用最广泛的敏捷框架。
|元素|描述 |
|---------|-------------|
| **冲刺** |定长迭代（通常2周） |
| **产品负责人** |定义待办事项并确定优先级；代表利益相关者 |
| **Scrum 大师** |促进进程；消除障碍；保护团队|
| **开发团队** |跨职能、自组织（理想规模为 5-9 人）|
| **产品待办事项** |可能需要的所有内容的优先列表 |
| **冲刺积压** |为当前冲刺选择的项目 + 交付它们的计划 |
| **每日站立** | 15 分钟同步：我做了什么？我该怎么办？有拦截器吗？ |
| **冲刺回顾** |向利益相关者演示工作软件；收集反馈|
| **冲刺回顾** |团队反思如何改进流程|
### 看板
看板是一种基于流程的方法，专注于可视化工作并限制正在进行的工作。
|实践|描述 |
|----------|-------------|
| **可视化工作流程** |带有列的板（待办事项 → 进行中 → 审核 → 已完成）|
| **限制在制品** |设置每列中的最大项目数 |
| **管理流程** |测量周期时间；识别并消除瓶颈|
| **明确政策** |每个人都同意每列的“完成”含义 |
| **协作改进** |使用数据和反馈来改进流程 |
**Scrum 与看板**：
| | Scrum |看板|
|---|--------|--------|
| **节奏** |固定冲刺（2 周）|连续流|
| **角色** | PO、Scrum Master、团队 |没有规定的角色 |
| **改变** |冲刺中期没有变化 |随时更改|
| **指标** |速度（每个冲刺的故事点）|周期时间、吞吐量|
| **最适合** |定期发布产品开发 |支持团队；持续交付|

## OKR 和 KPI
### OKR（目标和关键结果）
OKR 是 Google、Intel、Spotify 和许多其他公司使用的目标设定框架。
|组件|描述 |示例|
|------------|-------------|---------|
| **目标** |高品质、雄心勃勃、鼓舞人心 | “成为小型企业会计的首选平台” |
| **关键结果 1** |可测量；证明目标正在实现|将每月活跃用户从 1 万增加到 5 万 |
| **关键结果 2** |可测量| NPS 得分达到 60+ |
| **关键结果 3** |可测量|将入职时间从 30 分钟减少到 5 分钟 |
**OKR 最佳实践**：
- 每季度设定 3-5 个目标
- 每个目标有 2-5 个关键结果
- 目标是 70% 的成就（100% 意味着目标太容易了）
- OKR 与绩效评估是分开的
- 透明：每个人都可以看到其他人的 OKR
### KPI（关键绩效指标）
|类别 | KPI 示例 |
|----------|-------------|
| **财务** |收入、毛利率、净利润、EBITDA |
| **客户** | NPS、CSAT、流失率、CLV |
| **产品** | DAU/MAU、功能采用、价值实现时间 |
| **工程** |部署频率、交付周期、MTTR、变更失败率 |
| **营销** | CAC、ROAS、转化率、有机流量 |
| **人** |员工 NPS、保留率、聘用时间 |

## 利益相关者管理
|利益相关者类型 |他们关心什么 |如何参与 |
|-----------------|---------------------|---------------|
| **执行赞助商** |投资回报率、战略调整、风险 |每月更新；关注结果 |
| **最终用户** | Ease of use, reliability, solving their problem |用户研究；测试版程序；支持渠道|
| **技术团队** |代码质量、架构、技术债务 |架构评论；技术讲座；参与决策|
| **外部客户** |交货时间、质量、价值 |定期演示；清晰的沟通； SLA |
| **监管机构/合规性** |法律要求、审计追踪 |文档；积极参与 |
### 权力/利益网格
| |低利息 |高兴趣 |
|---|-------------|---------------|
| **高功率** |保持满意 |密切管理（关键人物） |
| **低功耗** |监控（最少的努力）|随时了解情况 |

## 通信框架
|框架|结构|何时使用 |
|------------|----------|----------|
| **准备** |要点 → 原因 → 示例 → 要点 |有说服力的沟通；会议 |
| **明星** |情况→任务→行动→结果|面试；绩效评估|
| **虚张声势** |底线在前面|发送给高管的电子邮件；状态更新|
| **SBAR** |情况→背景→评估→建议|交接；事件通讯 |
| **7 Cs** |清晰、简洁、具体、正确、连贯、完整、礼貌 |一般书面沟通 |
### 提供反馈
|方法|描述 |
|----------|-------------|
| **SBI**（情况-行为-影响）| “在昨天的会议（情况）中，你打断了客户（行为），这让他们关闭了（影响）。” |
| **前馈** |关注未来的行为，而不是过去的错误。 “下次，尝试一下……” |
| **激进的坦率** (Kim Scott) |亲自关怀+直接挑战。不太友善（毁灭性的同理心），也不太严厉（令人讨厌的侵略）。 |

## 决策模型
|型号|描述 |最适合 |
|--------|-------------|----------|
| **快速** |推荐、同意、执行、输入、决定 — 明确谁做什么 |涉及众多利益相关者的复杂决策 |
| **RACI** |负责、负责、咨询、知情——角色清晰 |项目任务和可交付成果 |
| **艾森豪威尔矩阵** |紧急/重要网格 - 确定任务的优先级 |个人生产力；任务分类|
| **决策矩阵** |根据加权标准对选项进行评分 |在替代方案之间进行选择|
| **OODA 循环** |观察→定位→决定→行动——快速决策周期|竞争情况；事件响应|
| **六顶思考帽** |从 6 个角度看待决策（事实、情感、风险、收益、创造力、过程）|团体决策；避免群体思维|
### 艾森豪威尔矩阵
| |紧急|不紧急 |
|---|--------|------------|
| **重要** | **先做** — 危机、截止日期、关键问题 | **时间表** — 战略规划、关系建立、学习 |
| **不重要** | **代表** — 一些电子邮件、会议、打扰 | **消除** — 浪费时间、忙碌的工作、过度浏览 |

## 风险管理
|步骤|描述 |
|------|-------------|
| **1.识别风险** |集体讨论可能出问题的地方（技术、日程、资源、外部）|
| **2.评估概率和影响** |对每种风险进行评级：高/中/低 |
| **3.优先** |关注高概率、高影响的风险 |
| **4.计划回应** |避免、减轻、转移或接受每种风险 |
| **5.监控** |定期回顾；风险随着项目的发展而变化|
### 风险应对策略
|战略|描述 |示例|
|----------|-------------|---------|
| **避免** |改变计划消除风险|使用经过验证的技术而不是实验 |
| **缓解** |降低概率或影响 |添加缓冲时间；雇用额外员工 |
| **转让** |将风险转移给第三方|保险;外包；固定价格合同|
| **接受** |如果发生的话，承认并计划 |应急基金；后备计划|

## 远程团队管理
|挑战|解决方案 |
|------------|----------|
| **沟通差距** |默认为书面；过度沟通背景；使用异步优先工具 |
| **隔离** |常规1:1；虚拟社交活动；偶尔的面对面聚会|
| **时区** |轮换会议时间；记录决定；最小化同步依赖性|
| **可见性** | DM 上的公共渠道；书面状态更新；共享仪表板 |
| **信任** |衡量结果，而不是时间；避开监控软件|
| **入职** |结构化的好友系统；记录的流程；明确的第一周目标|
### 有效的会议
|会议类型 |持续时间 |频率|目的|
|------------|---------|------------|---------|
| **每日站会** | 15 分钟 |每日 |同步；表面阻滞剂 |
| **冲刺计划** | 1–2 小时 |每一次冲刺 |协调下一步要构建的内容 |
| **冲刺回顾** | 1 小时 |每一次冲刺 |演示；收集反馈|
| **回顾** | 45–60 分钟 |每一次冲刺 |流程改进|
| **1:1** | 30 分钟 |每周/每两周 |个人支持与成长|
| **全体人员** | 30–60 分钟 |每月 |公司/团队更新；问答 |
**会议规则**：每次会议都需要议程。准时开始。准时结束。与所有者分配行动项目。如果可以是电子邮件，请将其设为电子邮件。

## 组织结构
|结构|描述 |优点 |缺点 |
|------------|-------------|------|-----|
| **功能性** |按专业（工程、营销、销售）组织 |深厚的专业知识；清晰的职业道路 |筒仓；缓慢的跨职能工作|
| **部门** |按产品、市场或地理位置组织 |重点;问责制 |重复的资源；不一致的做法|
| **矩阵** |人们向职能经理和项目经理汇报工作|灵活性;资源共享|优先事项相互冲突；关于谁负责的混乱|
| **扁平/合弄制** |最小的层次结构；自组织团队 |速度;自治;创新|决策不明确；扩展性不好 |
| **团队拓扑** (Skelton/Pais) |流对齐团队+平台团队+使能团队+复杂子系统团队|与实际工作流程保持一致 |需要周到的设计；不是灵丹妙药|

## 产品管理基础知识
产品管理是一门决定构建什么、为谁构建以及为何构建的学科，并确保其创造价值。
|责任|描述 |
|----------------|-------------|
| **发现** |用户研究、市场分析、竞争情报 |
| **策略** |产品愿景、路线图、优先级框架 |
| **执行** |编写规格/用户故事；从事工程和设计工作 |
| **启动** |上市规划；定位；销售支持 |
| **迭代** |分析指标；收集反馈；确定下一步改进的优先顺序 |
### 优先级框架
|框架|它是如何运作的 |
|------------|-------------|
| **莫斯科** |必须有/应该有/可以有/不会有|
| **大米** |影响力 × 影响力 × 信心 ÷ 努力 |
| **卡诺模型** |将功能分为基本功能、性能功能或愉悦功能 |
| **价值与努力矩阵** |在 2×2 网格上绘图；优先考虑高价值、省力的项目 |
| **机会评分** |重要性减去满意度；寻找服务不足的需求|
---

＃＃ 概括
管理是通过他人实现目标的实践。高效的管理者将清晰的思维（框架、方法、指标）与人际交往能力（倾听、同理心、信任）结合起来。没有任何方法可以取代良好的判断，但良好的判断可以通过健全的框架得到增强。这些应该作为实践指南而不是僵化的学说来应用。
