# 无障碍和包容性设计
可访问性（通常缩写为 a11y）是让软件可供所有人使用的实践，包括有视觉、听觉、运动、认知和神经障碍的人。这是许多司法管辖区的法律要求和标准工程实践。无障碍软件对每个人来说都是更好的软件，因为支持残疾用户的设计决策——清晰的结构、键盘导航、足够的对比度、可读的文本——改善了所有用户的体验。
---

## 谁从无障碍中受益？
|残疾类型 |示例 |辅助技术|
|----------------|---------------------|---------------------|
| **视觉** |失明、低视力、色盲|屏幕阅读器（JAWS、NVDA、VoiceOver）；放大镜；高对比度模式 |
| **听觉** |耳聋、听力困难 |字幕；成绩单；视觉警报|
| **电机** |灵活性有限、瘫痪、震颤 |仅键盘导航；语音控制；开关设备；眼球追踪 |
| **认知** |阅读障碍、多动症、自闭症、记忆障碍 |语言清晰；一致的导航；减少干扰 |
| **临时** |断臂、明亮的阳光、嘈杂的环境|与永久性残疾相同的住宿条件 |
| **情况** |抱着宝宝，开车，一只手被占用|语音接口；大型触摸目标|
**关键见解**：为残疾用户设计的辅助功能可以帮助每个人。路边坡道（人行道上的坡道）是为轮椅设计的，但也供推着婴儿车的父母、推着推车的送货员和带着行李的旅行者使用。

## 网络辅助功能 (WCAG)
网页内容可访问性指南 (WCAG) 是网页可访问性的国际标准。
### WCAG 原则 (POUR)
|原理|要求|
|------------|-------------|
| **可感知** |信息必须以用户可以感知的方式呈现（文本替代、标题、自适应布局）|
| **可操作** |界面必须可导航且可用（可使用键盘、足够的时间、无引起癫痫发作的内容）|
| **可以理解** |信息和操作必须是可理解的（可读、可预测、输入辅助） |
| **稳健** |内容必须与当前和未来的辅助技术兼容 |
### WCAG 一致性级别
|水平|要求|典型目标 |
|--------|-------------|---------------|
| **一个** |最低水平； 30 条成功标准 |某些司法管辖区的法定最低限度|
| **AA** |解决最常见的障碍 |大多数组织的标准目标|
| **AAA** |最高级别；并非所有内容都能实现 |专业内容；教育网站|
### 关键成功标准（AA 级）
|标准|要求|如何实现 |
|------------|-------------|---------------|
| **1.1.1 非文本内容** |所有图像都有替代文本 | `alt`属性； `aria-label`图标 |
| **1.3.1 信息和关系** |以编程方式传达的结构 |语义 HTML；标题；列表；地标|
| **1.4.3 对比度（最小值）** |文本的对比度至少为 4.5:1 |用对比检查器进行测试；选择易于使用的调色板 |
| **1.4.4 调整文本大小** |文本大小可调整至 200% 而不会丢失 |使用相对单位（rem、em）；响应式设计|
| **2.1.1 键盘** |所有功能均可通过键盘实现 |无键盘陷阱；可见焦点指示器|
| **2.4.3 焦点顺序** |焦点顺序保留了意义和可操作性|逻辑 Tab 键顺序； DOM 顺序与视觉顺序匹配 |
| **2.4.7 焦点可见** |键盘焦点以视觉方式指示 | CSS`:focus-visible`样式；绝不`outline: none`无需更换 |
| **3.3.2 标签或说明** |输入有标签 | `<label>`元素； `aria-label`|
| **4.1.2 名称、角色、值** | UI 组件具有可访问的名称和角色 | ARIA 属性；语义 HTML |

## ARIA（可访问的富互联网应用程序）
ARIA 向没有内置语义的 HTML 元素添加可访问性信息。
### ARIA 角色
|角色 |目的|示例|
|------|---------|---------|
| `button`|将元素标识为按钮 |按钮样式的`<div>`|
| `dialog`|模态或非模态对话框 |自定义模态组件 |
| `tablist`/`tab`/`tabpanel`|选项卡界面 |自定义选项卡组件 |
| `alert`|动态显示的重要消息 |错误通知 |
| `progressbar`|进度指示器|加载状态 |
| `menu`/`menuitem`|菜单导航|下拉菜单|
### ARIA 属性
|属性 |目的|示例|
|------------|---------|---------|
| `aria-label`|无可见文本时可访问的名称 |仅图标按钮：`aria-label="Search"` |
| `aria-describedby`|将元素链接到其描述 |带有帮助文本的表单字段 |
| `aria-expanded`|指示某个部分是否已展开 |手风琴;下拉菜单 |
| `aria-hidden`|从辅助技术中隐藏元素 |装饰图标|
| `aria-live`|宣布动态内容变更 |实时更新；通知 |
| `aria-disabled`|表示元素已禁用 |灰色按钮 |
### ARIA 的第一条规则
> **如果可以使用本机 HTML，则不要使用 ARIA。**`<button>`已可访问。`<div role="button">`要求您手动添加键盘处理、焦点管理和屏幕阅读器支持。首先使用语义 HTML；仅当原生元素无法完成这项工作时才使用 ARIA。

## 键盘导航
|关键|预期行为 |
|----------------|--------------------|
| **选项卡** |将焦点移至下一个交互元素 |
| **Shift + Tab** |将焦点移至上一个交互元素 |
| **输入/空格** |激活焦点元素（按钮、链接）|
| **方向键** |在组件内导航（菜单、选项卡、单选组）|
| **逃脱** |关闭对话框、菜单或弹出窗口 |
| **首页/完** |跳转到列表中的第一项/最后一项 |
### 常见的键盘陷阱
|问题 |修复|
|---------|-----|
|焦点进入组件但无法离开 |确保 Tab 将焦点移出；手柄逃生 |
|模态不捕获焦点 |焦点应在模态内循环；返回到关闭时触发|
|自定义组件不响应键盘 |添加 Enter、空格、箭头的按键处理程序 |

## 色彩和视觉设计
|指南|要求|
|------------|-------------|
| **对比度** |普通文本为 4.5:1； 3:1 用于大文本（18pt+ 或 14pt+ 粗体）|
| **不要仅仅依赖颜色** |除了颜色之外，还可以使用图标、文本或图案 |
| **焦点指标** |始终可见；高对比度；切勿在不更换的情况下移除 |
| **调整文本大小** |布局必须在 200% 缩放下工作 |
| **反应灵敏** |内容必须以 320 像素宽度重排（移动设备）|
### 色盲注意事项
|类型 |受影响的颜色 |设计技巧|
|------|-----------------|------------|
| **绿盲** |红绿（最常见）|不要使用红/绿来传达状态；使用图标+颜色|
| **红色盲** |红绿|同上 |
| **蓝色盲** |蓝黄色|不要使用蓝色/黄色作为唯一的区分因素 |

## 测试可访问性
|方法|工具|它捕获了什么|
|--------|------|----------------|
| **自动扫描** |斧头，灯塔，波浪|缺少替代文本；对比问题； ARIA 错误 |
| **键盘测试** |手动：拔掉鼠标，仅使用键盘|焦点顺序；键盘陷阱；失踪处理程序|
| **屏幕阅读器测试** | NVDA（免费）、VoiceOver (macOS)、JAWS |缺少标签；结构差；未宣布的变更 |
| **变焦测试** |浏览器缩放至 200%、400% |布局破损；剪裁的文本；溢出问题|
| **色彩对比** | WebAIM 对比度检查器，Stark 插件 |对比度不足|
| **用户测试** |与残疾用户进行测试 |自动化工具忽略的现实世界障碍|

## 法律要求
|法律 |地区 |要求|
|-----|--------|-------------|
| **ADA**（美国残疾人法案）|美国 |公共场所的网站必须易于访问 |
| **第 508 条** |美国（联邦）|联邦机构的 ICT 必须无障碍 |
| **EAA**（欧洲无障碍法案）|欧盟（2025+）|产品和服务必须满足无障碍要求 |
| **EN 301 549** |欧盟| ICT无障碍技术标准|
| **ACA**（加拿大无障碍法案）|加拿大 |政府和受监管行业|
| **2010 年平等法案** |英国 |服务商必须做出合理调整|

## 移动辅助功能
|平台|指南 |关键工具|
|----------|------------|------------|
| **iOS** | Apple 人机界面指南（辅助功能部分）|画外音；动态型；开关控制|
| **安卓** | Android 辅助功能指南 |对讲；切换访问；选择发言 |
|移动关注|解决方案 |
|----------------|----------|
| **触摸目标** |最小 44×44 点 (iOS) / 48×48 dp (Android) |
| **屏幕阅读器支持** |内容描述；无障碍标签|
| **运动灵敏度** |尊重`prefers-reduced-motion`；避免自动播放动画 |
| **动态文本大小** |支持系统字体大小；使用可缩放的文本单元|
---

＃＃ 概括
可访问性是一项设计原则，应该从一开始就为每个决定提供信息，而不是在最后添加的功能。使用语义 HTML。确保键盘导航正常工作。保持足够的色彩对比度。为非文本内容提供替代文本。使用屏幕阅读器和残疾用户进行测试。其结果是软件能够更好地适合每个人，包括那些有暂时障碍、环境限制、设备较旧、连接速度慢以及现实世界使用与受控开发环境存在许多不同的人。
