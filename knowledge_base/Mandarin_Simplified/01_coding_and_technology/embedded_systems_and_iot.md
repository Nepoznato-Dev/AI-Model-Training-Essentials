# 嵌入式系统和物联网
嵌入式系统是隐藏在其他设备中的计算机——汽车的发动机控制单元、洗衣机的控制器、智能恒温器中的微控制器。与通用计算机不同，它们是为特定任务而设计的，通常对功耗、内存和处理速度有严格的限制。物联网 (IoT) 通过将嵌入式系统连接到网络来扩展嵌入式系统，从而实现远程监控、控制和数据收集。它们共同代表了与物理世界交互的数十亿计算设备。
---

## 嵌入式系统基础知识
### 嵌入式有何不同
|方面|通用计算机|嵌入式系统|
|--------|------------------------|-----------------|
| **目的** |运行任何软件|执行特定任务 |
| **资源** |充足的CPU、RAM、存储|有限（KB 到 MB RAM；MHz 到低 GHz）|
| **电源** |已插入电源或大电池 |通常由电池供电或能量收集|
| **操作系统** |完整操作系统（Windows、Linux、macOS）| RTOS、裸机或嵌入式 Linux |
| **用户界面** |丰富（屏幕、键盘、鼠标）|最少（LED、按钮、传感器）或无 |
| **实时** |尽最大努力|实时期限往往很严格|
| **终生** | 3-7年| 10-25+ 岁 |
### 微控制器与微处理器
|特色 |微控制器 (MCU) |微处理器 (MPU) |
|--------------------|----------------------|---------------------|
| **整合** | CPU + RAM + Flash + 外设集成在一颗芯片上 |仅CPU；外部 RAM 和存储 |
| **性能** |低到中（MHz 范围）|高（GHz 范围）|
| **电源** |非常低（μA 至 mA）|更高（数百毫安至安培）|
| **成本** | 0.10 美元 - 10 美元 | $5 - $100+ |
| **示例** | STM32、ESP32、Arduino（ATmega）、nRF52 |树莓派（BCM2835）、i.MX、全志 |
| **用例** |传感器、执行器、简单控制|显示、复杂处理、Linux |

## 实时操作系统 (RTOS)
RTOS 保证关键任务在定义的时间窗口内完成。
|实时操作系统 |许可证|最适合 |
|------|---------|----------|
| **FreeRTOS** |麻省理工学院 |最常见；广泛的 MCU 支持 |
| **西风** |阿帕奇2.0 |现代的; Linux 基金会；不断发展的生态系统|
| **ThreadX (Azure RTOS)** |麻省理工学院 |安全认证；物联网 |
| **embOS** |商业|工业的;认证 |
| **RT 线程** |阿帕奇2.0 |中国生态系统；全球增长|
### RTOS 与裸机
|方面|裸机 |实时操作系统 |
|--------|------------|------|
| **复杂性** |简单任务简单|复杂的并发任务所需 |
| **日程安排** |手册（主循环+中断）|具有优先级的抢占式调度|
| **可扩展性** |难以添加功能|轻松添加任务 |
| **内存** |最小的开销|开销小（几KB）|

## 通信协议
### 有线协议
|协议|速度|距离 |使用案例|
|----------|------|----------|----------|
| **UART** |高达 1 Mbps |短（板载）|调试控制台； GPS模块|
| **SPI** |高达 100 MHz |短（板载）|高速外设（显示器、闪存）|
| **I²C** |高达 3.4 MHz |短（板载）|传感器；低引脚数通信 |
| **可以** |高达 1 Mbps |长达 1 公里 |汽车；工业|
| **以太网** | 10 Mbps - 100 Gbps |长达 100 m |联网;工业（带扩展）|
| **USB** |高达 40 Gbps (USB4) |长达 5 m |外围设备；充电|
### 无线协议
|协议|范围 |电源|速度|使用案例|
|----------|---------|--------|--------|----------|
| **无线网络** | 〜100米|高|高达 Wi-Fi 7（理论值 46 Gbps）|高带宽物联网；流媒体 |
| **蓝牙经典** | 〜100米|中等| 1-3 Mbps |声音的;文件传输 |
| **BLE**（蓝牙低功耗）| 〜100米|非常低| 1-2 Mbps |可穿戴设备；信标；传感器|
| **紫蜂** | ~100 m（网格）|低| 250 kbps | 250 kbps家庭自动化；工业传感器|
| **Z 波** | ~100 m（网格）|低| 100 kbps | 100 kbps家庭自动化 |
| **LoRa / LoRaWAN** |长达 15 公里 |非常低| 0.3-50 kbps |农业;公用事业；全市传感器|
| **窄带物联网** |蜂窝覆盖 |低| 250 kbps | 250 kbps计量；资产追踪 |
| **主题/主题** | ~100 m（网格）|低|中等|智能家居（苹果、谷歌、亚马逊）|
| **蜂窝网络（4G/5G）** |全球|高|高|联网车辆；远程监控|

## 物联网架构
### 物联网堆栈
|层|功能|示例 |
|--------|----------|---------|
| **设备** |传感器、执行器、微控制器 | ESP32、STM32、树莓派 |
| **连接性** |网络协议| MQTT、HTTP、CoAP、LoRaWAN |
| **边缘计算** |设备附近处理| AWS Greengrass、Azure IoT Edge |
| **云平台** |数据摄取、存储、处理 | AWS IoT、Azure IoT 中心、Google Cloud IoT |
| **应用** |仪表板、分析、警报 | Grafana，定制网络应用程序 |
### 物联网通信协议
|协议|图案|最适合 |
|----------|---------|----------|
| **MQTT** |发布/订阅；轻量化|大多数物联网应用；低带宽|
| **HTTP/REST** |请求/响应 |当简单很重要时；网络集成|
| **CoAP** |请求/响应；基于UDP |受限设备；低功耗|
| **AMQP** |消息队列|企业物联网；可靠的交付 |
| **WebSocket** |双向；持久连接 |实时仪表板；实时数据|
### MQTT 详细信息
|概念 |描述 |
|---------|-------------|
| **经纪人** |路由消息的中央服务器（Mosquitto、EMQX、HiveMQ）|
| **主题** |分层地址（例如`home/living-room/temperature`）|
| **服务质量** | 0（最多一次）、1（至少一次）、2（恰好一次）|
| **保留消息** |关于某个主题的最后一条消息；交付给新订阅者|
| **最后遗嘱** |客户端意外断开连接时发布的消息 |

## 边缘计算
在源附近处理数据，而不是将所有内容发送到云端。
|效益 |描述 |
|---------|-------------|
| **减少延迟** |无需往返云；立即做出决定|
| **节省带宽** |只发送摘要或异常情况 |
| **隐私** |敏感数据保留在本地
| **可靠性** |互联网中断时也能工作 |
|平台|描述 |
|----------|-------------|
| **AWS Greengrass** |在边缘设备上运行 Lambda 函数 |
| **Azure IoT Edge** |在边缘设备上运行容器 |
| **NVIDIA Jetson** | GPU 加速的边缘 AI（Orin、Nano）|
| **树莓派** |轻量级边缘计算 |

## 固件更新（OTA）
通过无线更新，您可以修复错误并向已部署的设备添加功能。
|关注|解决方案 |
|---------|----------|
| **可靠性** |双组闪存；失败时回滚|
| **安全** |签名图像；加密传输|
| **尺寸** | Delta 更新（仅更改部分）|
| **连接性** |设备上线时的队列更新 |

＃＃ 概括
嵌入式系统和物联网代表了软件与物理世界的交叉点。从控制电机的微控制器到连接云的传感器网络，它们需要与网络或应用程序开发不同的思维方式：资源有限、实时要求、长寿命以及错误对物理世界的影响。生态系统已经非常成熟——ESP-IDF和Zephyr等框架使专业开发变得容易，而AWS IoT和Azure IoT Hub等平台则负责云端处理。关键技能是了解硬件接口、通信协议、电源管理以及编写必须在无需干预的情况下可靠运行多年的软件的规则。
