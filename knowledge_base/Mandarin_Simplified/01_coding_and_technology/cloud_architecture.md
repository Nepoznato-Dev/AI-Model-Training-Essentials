# 云架构
云计算从根本上改变了组织构建、部署和扩展软件的方式。您无需购买和维护物理服务器，而是可以按需配置计算资源，按使用量付费，并在几分钟内进行全球扩展。该文件涵盖了您需要了解的核心概念、架构模式、服务和最佳实践。
---

## 云计算基础知识
### 什么是云计算？
通过互联网按需交付计算资源（服务器、存储、数据库、网络、软件），并采用按需付费的定价方式。
### NIST 基本特征
|特点|意义|
|----------------|---------|
| **按需自助服务** |无需人工交互即可提供资源 |
| **广泛的网络访问** |通过标准机制在网络上可用 |
| **资源池** |多租户模式；资源动态分配|
| **快速弹性** |快速向外和向内扩展 |
| **测量服务** |使用情况受到监控并计费 |
### 部署模型
|型号|描述 |何时使用 |
|--------|-------------|-------------|
| **公共云** |由提供商拥有；共享基础设施（AWS、Azure、GCP）|大多数工作负载；性价比|
| **私有云** |致力于单一组织|监管要求、敏感数据 |
| **混合云** |公私结合|灵活性+合规性|
| **多云** |使用多个公共云提供商 |避免供应商锁定，同类最佳 |
### 服务模式
|型号|提供 |示例 |使用案例 |
|--------|----------|----------|------------|
| **基础设施即服务** |虚拟机、存储、网络、操作系统 | AWS EC2、Azure 虚拟机、GCP 计算引擎 |直接迁移、完全控制 |
| **PaaS** |开发平台、数据库、中间件| Heroku、Google App Engine、AWS Elastic Beanstalk | App开发、API部署|
| **SaaS** |通过互联网完成申请 | Salesforce、Google Workspace、Microsoft 365 |电子邮件、CRM、协作 |
| **FaaS / 无服务器** |事件驱动函数执行 | AWS Lambda、Azure 函数、GCP 云函数 | API、事件处理、计划任务 |

## 架构模式
### 架构良好的框架
所有三大提供商都发布了围绕五个支柱构建的架构良好的框架：
|支柱|关键原则|
|--------|----------------|
| **卓越运营** |自动化操作；经常进行可逆的改变；预见失败|
| **安全** |强大的身份基础；在每一层应用安全性；保护传输中和静态的数据|
| **可靠性** |测试恢复程序；故障自动恢复；水平缩放 |
| **性能效率** |使用无服务器；几分钟内走向全球；经常实验|
| **成本优化** |采用消费模式；使用托管服务；停止在无差别的工作上花钱|
### 常见模式
|图案|描述 |好处 |挑战|
|---------|-------------|----------|------------|
| **微服务** |将应用程序分解为小型、独立的服务 |可扩展、故障隔离、独立部署 |分布式复杂性，数据一致性 |
| **事件驱动** |组件通过事件进行通信 |松耦合、实时处理 |调试复杂性、最终一致性|
| **无服务器** |无需服务器管理；按执行付费|成本效益、快速部署 |冷启动、供应商锁定、执行限制 |
| **分层（N 层）** |表示→业务逻辑→数据访问→数据库|关注点分离、可维护性 |可以成为整体|
| **天基** |跨虚拟化内存节点的分布式数据 |处理高并发、低延迟 |设计和管理复杂 |

## 核心服务
### 计算
|服务类型 |详情 |
|-------------|---------|
| **虚拟机** |通用、计算优化、内存优化、GPU。定价：按需、预留、现货。 |
| **容器** | Docker 运行时；通过 Kubernetes（EKS、AKS、GKE）进行编排。注册表：ECR、GCR、ACR。 |
| **无服务器功能** |事件触发，无状态。执行时间、内存、并发性的限制。 |
＃＃＃ 贮存
|类型 |特点 |示例 |最适合 |
|------|----------------|----------|----------|
| **对象** |扁平结构、HTTP 访问、元数据丰富 | S3、云存储、Azure Blob |静态资产、备份、数据湖 |

| **存档** |成本最低，检索延迟| S3 冰川、Azure 存档 |合规，长期备份|

## 网络
### 虚拟网络
每个云部署都位于虚拟私有云 (VPC / VNet) 内 - 您使用 CIDR 块、子网（公共或私有）、路由表和网关定义的隔离网络。
### 负载均衡和 CDN
|服务 |目的|
|---------|---------|
| **负载均衡器** |跨实例分配流量（L4 网络、L7 应用程序）|
| **CDN** |在边缘位置缓存内容以降低延迟（CloudFront、Cloud CDN、Azure CDN）|
| **DNS** |域注册、路由策略、运行状况检查（Route 53、Cloud DNS、Azure DNS）|
### 连接选项
|选项 |描述 |
|--------|-------------|
| **互联网网关** | VPC 公共互联网接入 |
| **NAT 网关** |私有子网出站访问 |
| **VPN** |到本地的加密隧道 |
| **直接连接/ ExpressRoute** |专用私人连接|
| **VPC 对等互连** |连接账户内或账户之间的 VPC |

＃＃ 安全
### 共同责任模型
|层|供应商|客户|
|--------|----------|----------|
| **基础设施**（硬件、设施）| ✅ | |
| **计算、存储、网络** | ✅（托管）| ✅（自我管理）|
| **数据、应用程序、身份** | | ✅ |
服务管理得越多，提供商处理的就越多。借助 IaaS，您几乎可以管理一切；对于 SaaS，提供商几乎可以处理所有的事情。
### 身份和访问管理 (IAM)
|概念 |描述 |
|---------|-------------|
| **用户** |个人身份 |
| **团体** |用户收藏|
| **角色** |服务或用户的临时凭证 |
| **政策** |定义权限的文档 |
| **原理** |最小特权、职责分离 |
### 数据保护
- **静态加密**：KMS、客户管理的密钥、HSM。
- **传输中加密**：TLS/SSL、HTTPS。
- **秘密管理**：Secrets Manager、Key Vault — 切勿对秘密进行硬编码。

## 成本管理
### 定价模型
|型号|描述 |最适合 |
|--------|-------------|----------|
| **点播** |按秒/小时按使用量付费 |可变的短期工作负载 |
| **预留实例** | 1-3年承诺，大幅折扣|稳态工作负载 |
| **现货实例** |对未使用的容量进行投标；可以被打断|容错、灵活的作业 |
| **储蓄计划** |灵活的承诺定价|混合使用模式 |
| **免费套餐** |新帐户免费使用有限 |学习、原型制作 |
### 优化策略
调整实例大小以匹配工作负载。使用自动扩展来应对需求高峰。为可预测的负载预留容量。使用竞价实例进行批处理作业。将不经常访问的数据移动到更便宜的存储层。删除未使用的资源（孤立快照、空闲负载均衡器、未附加的 IP）。

## 高可用性和灾难恢复
### 可用性概念
|概念 |描述 |
|---------|-------------|
| **可用区 (AZ)** |区域内物理上独立的数据中心 |
| **地区** |具有多个可用区的地理区域 |
| **边缘位置** |内容交付的 CDN 缓存位置 |
### 灾难恢复策略
|战略|成本| RTO |恢复点目标 |描述 |
|----------|------|-----|-----|------------|
| **备份和恢复** |最低|营业时间 |小时-天 |定期备份，需要时恢复 |
| **指示灯** |低|分钟–小时 |分钟 |核心要素始终运行，灾难扩大|
| **热备** |中等|分钟 |秒-分钟|缩小版始终运行 |
| **多站点主动/主动** |最高|接近于零|零|多个地区全面投产|
**RTO**（恢复时间目标）= 最大可接受的停机时间。 **RPO**（恢复点目标）= 可接受的最大数据丢失。
