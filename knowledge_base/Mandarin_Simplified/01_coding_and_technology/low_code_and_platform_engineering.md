# 低代码和平台工程
低代码平台让人们可以用最少的手写代码构建应用程序——通常通过拖放界面、可视化工作流程和预构建的连接器。平台工程是构建内部开发人员平台 (IDP) 的学科，使产品团队可以轻松地自助服务基础设施、CI/CD 和操作工具。这两种趋势都是对同一问题的回应：软件需求与能够构建软件的开发人员的供应之间的差距。
---

## 低代码平台
### 低代码实际上意味着什么
|方面|描述 |
|--------|-------------|
| **视觉开发** |拖放式 UI 构建器；可视化工作流程编辑器；表单设计师|
| **预构建组件** |现成的小部件、连接器、模板和集成 |
| **声明性逻辑** |通过规则和条件而不是编写代码来配置行为 |
| **可扩展性** |当平台的内置功能不够时，能够添加自定义代码 |
| **托管基础设施** |平台处理托管、扩展、安全补丁|
### 流行的低代码平台
|平台|实力|典型用例|
|----------|----------|-----------------|
| **微软 Power Platform** |深度 Microsoft 365/Azure 集成； Power Apps、Power Automate、Power BI |企业工作流程；内部工具|
| **Salesforce 平台** | CRM 原生；用于扩展的 Apex；流程生成器 |面向客户的应用程序；销售工作流程 |
| **立即服务** | IT服务管理；工作流程自动化 |信息技术运营；人力资源；设施 |
| **亚庇** |流程挖掘；案例管理 |业务流程复杂；合规|
| **外部系统** |全栈网络和移动设备；企业级|客户门户；移动应用程序 |
| **重组** |内部工具构建器；连接到数据库和 API |管理面板；仪表板；操作工具|
| **气垫** |电子表格-数据库混合；自动化|项目跟踪；轻量级CRM |
### 当低代码运行良好时
|场景 |为什么低代码适合？
|----------|--------------------|
| **内部工具** |快速构建；用户是内部用户，因此 UI 灵活性不太重要 |
| **表格和批准** |可视化工作流程构建器在这方面表现出色 |
| **CRUD 应用程序** |大多数低代码平台都针对创建-读取-更新-删除模式进行了优化 |
| **原型制作** |在数小时而不是数周内验证一个想法 |
| **公民发展** |业务分析师可以利用 IT 治理构建自己的解决方案 |
### 当低代码达不到要求时
|限制|影响 |
|------------|--------|
| **供应商锁定** |应用程序无法轻易地从平台迁移出去 |
| **性能上限** |不适合高吞吐量或延迟敏感的应用程序 |
| **用户界面限制** |定制设计很困难；您仅限于平台支持的内容 |
| **集成复杂性** |无论如何，连接到不寻常的 API 或遗留系统可能需要自定义代码 |
| **规模成本** |随着使用量的增长，每用户或每应用程序的定价可能会变得昂贵 |
| **调试难度** |视觉抽象使得诊断复杂问题变得困难 |

## 平台工程
### 平台工程解决的问题
|没有平台工程|与平台工程|
|------------------------------|----------------------------|
|每个团队管理自己的基础设施 |自助服务平台抽象基础设施|
|跨团队的工具不一致 |标准化工具链；黄金之路|
|开发人员等待运营商提供资源 |开发者按需提供资源|
|知识孤岛；部落知识|记录在案；自动化；可发现|
|新工程师入职缓慢|新工程师第一天就可以部署 |
### 内部开发者平台的核心组件
|组件|目的|示例工具 |
|------------|---------|---------------|
| **服务目录** |所有服务及其所有者的中央登记处|后台;港口;皮质|
| **模板化脚手架** |从批准的模板生成新服务 |后台软件模板；饼干切割机|
| **自助服务基础设施** |开发者无需提交工单即可配置云资源 |地形模块；普鲁米；十字平面|
| **CI/CD 管道** |标准化构建、测试、部署管道 | GitHub 操作；亚搏体育appGitLab持续集成；阿尔戈CD |
| **环境管理** |按需提供临时开发/登台环境 | V簇；命名空间；吉特波德 |
| **可观察性** |每个服务中内置的日志记录、指标和跟踪 |普罗米修斯；格拉法纳；打开遥测；数据狗 |
| **秘密管理** |凭证的安全存储和轮换 |保险库； AWS 秘密管理器；标准操作规程 |
| **身份和访问** |单点登录；基于角色的访问；服务到服务的身份验证奥克塔；钥匙斗篷；斯皮夫 |
### 黄金之路
黄金之路是受支持的、固执己见的做某事的方式。这是阻力最小的道路——如果你遵循它，一切都会顺利。你可以偏离正轨，但你只能靠自己。
|黄金之路|它提供什么 |
|----------|------------------|
| **新服务** |模板仓库；持续集成/持续交付；监控；日志记录；部署配置 |
| **新数据库** |配置实例；秘密中的连接字符串；备份配置|
| **新前端** |建设管道； CDN；预览环境；灯塔检查|
| **数据管道** |编排；模式验证；监控；警报|
### 构建与购买决策
|因素|构建定制|使用现有工具 |
|--------|-------------|--------------------|
| **核心能力** |您的业​​务独一无二；竞争优势 |商品;每个公司都需要它|
| **维护负担** |你有能力维护它 |工具由供应商/社区维护良好 |
| **整合需求** |需要与内部系统深度集成 |标准 API 和连接器就足够了 |
| **成本** |建造成本比许可更便宜许可比建造更便宜|

## 低代码与平台工程的关系
|尺寸|低代码 |平台工程|
|------------|----------|---------------------|
| **目标用户** |商业用户；公民开发商|专业软件工程师|
| **目标** |减少代码；提高速度|减少认知负荷；增加自主权|
| **抽象级别** |非常高；视觉|中等的;基于代码但经过简化 |
| **灵活性** |受平台能力限制 |充分的灵活性；你可以编写任何代码 |
| **治理** |平台执行规则 |平台提供黄金通道|
它们是互补的：平台工程使专业开发人员更快，而低代码使非开发人员能够构建简单的应用程序。它们共同从不同角度解决了软件交付差距。
---

＃＃ 概括
低代码平台和内部开发人员平台都旨在增加能够交付软件的人员数量。低代码通过完全抽象代码来实现这一点——可视化构建器、预构建连接器、声明性逻辑。平台工程通过提供自助服务基础设施、黄金路径和标准化工具为专业开发人员做到这一点，使他们花在运维工作上的时间更少，而将更多的时间花在产品功能上。两者都不是灵丹妙药：低代码具有供应商锁定和性能限制，并且平台工程需要持续投资来维护。但当应用于正确的问题时——内部工具、CRUD 应用程序、标准化服务交付——两者都可以大大缩短从想法到生产的时间。
