# 移动开发
移动开发是为智能手机和平板电脑构建应用程序的实践——主要针对 iOS (Apple) 和 Android (Google)。它涵盖了从小屏幕的 UI 设计到管理电池寿命、处理网络不稳定以及通过商店分发应用程序的一切。该领域已经显着成熟，跨平台框架现在在大多数用例中与本机开发竞争。
---

## 跨平台框架
构建一次，即可部署到 iOS 和 Android。
|框架|语言 |渲染|性能|最适合 |
|------------|----------|------------|-------------|----------|
| **颤动** |飞镖 |定制发动机（Skia/叶轮）|近乎原生 |丰富的自定义UI；跨平台一致的外观 |
| **反应本机** | JavaScript/TypeScript |通过桥的本机组件 |好（新架构改进了这一点）|具有 Web/JS 经验的团队 |
| **Kotlin 多平台** |科特林 |每个平台的本机 UI |本地 |共享业务逻辑；原生用户界面 |
| **毛伊岛** (.NET) | C# |原生控件|好 | .NET 团队；企业应用程序 |
| **离子/电容器** | HTML/CSS/JS |网页视图 |降低|简单的应用程序；网络团队|
### Flutter 与 React Native
|方面|扑动|反应本机 |
|--------|---------|-------------|
| **语言** |飞镖 | JavaScript/TypeScript |
| **UI渲染** |自行绘制所有内容（跨平台一致）|使用本机组件（特定于平台的外观）|
| **热重载** |优秀|好 |
| **生态系统** |成长迅速；基于小部件 |大的; npm 生态系统 |
| **学习曲线** |需要学习Dart |让 Web 开发人员更轻松 |
| **平台集成** |原生代码的平台渠道 |通过桥接的本机模块 |
| **性能** |出色的;近乎原生 |好的;桥梁开销（通过新架构减少）|

## 移动架构模式
|图案|描述 |何时使用 |
|---------|-------------|----------|
| **MVC** |模型-视图-控制器 |简单的应用程序； Web 开发人员熟悉 |
| **MVVM** |模型-视图-视图模型；数据绑定|最现代的移动应用程序 |
| **MVI** |模型-视图-意图；单向数据流 |复杂的状态管理； Flutter（使用 BLoC/Riverpod）|
| **干净的架构** |具有依赖倒置的层 |大型团队；复杂的业务逻辑|

## 主要移动问题
### 离线优先设计
移动应用程序必须在没有可靠互联网的情况下运行。
|战略|描述 |
|----------|-------------|
| **本地数据库** |在设备上存储数据（SQLite、Room、CoreData、Realm）|
| **同步策略** |在线时与服务器同步；解决冲突|
| **乐观的用户界面** |立即更新UI；当服务器响应时进行协调 |
| **缓存** |缓存 API 响应；离线时从缓存提供服务 |
＃＃＃ 表现
|关注|解决方案 |
|---------|----------|
| **应用程序启动时间** |延迟加载；最大限度地减少初始化工作|
| **内存使用情况** |图像压缩；避免内存泄漏；使用分析工具|
| **电池耗尽** |减少后台工作；批量网络请求；使用高效的定位服务|
| **网络效率** |压缩有效负载；使用分页；积极缓存|
| **列表滚动** |回收视图；对图像使用延迟加载 |
＃＃＃ 安全
|关注|解决方案 |
|---------|----------|
| **静态数据** |加密敏感数据（iOS 上的 Keychain、Android 上的 EncryptedSharedPreferences）|
| **网络** |始终使用 HTTPS；敏感应用程序的证书固定|
| **身份验证** |生物识别（面部识别、指纹）； OAuth；代币存储|
| **代码混淆** |适用于 Android 的 ProGuard/R8； iOS 的位码 |
| **越狱/root检测** |检测受感染的设备；限制功能|

## 应用程序生命周期
|状态 |描述 |做什么 |
|--------|-------------|------------|
| **前台（活动）** |用户正在与应用程序交互 |正常运行 |
| **背景** |应用程序不可见但仍在内存中 |暂停动画；保存状态 |
| **暂停** |操作系统已冻结应用程序以节省资源 |没有什么;应用程序被冻结 |
| **终止** |操作系统杀死了应用程序以释放内存 |下次启动时恢复状态 |

＃＃ 概括
移动开发提供了本机（最佳性能、特定于平台）和跨平台（共享代码库、更快迭代）之间的选择。 Flutter 和 React Native 已经成熟到跨平台是大多数应用程序的正确选择。无论框架如何，核心挑战仍然相同：离线优先设计、有限硬件上的性能、电池效率、不受信任设备上的安全性以及导航应用程序商店审查流程。该领域奖励那些首先考虑用户体验的开发人员——快速启动、平滑滚动以及优雅地处理不良连接。
