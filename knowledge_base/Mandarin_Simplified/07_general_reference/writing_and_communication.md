# 写作和沟通基础知识
写作和沟通是清晰有效地传达想法的技能——无论是通过电子邮件、报告、文档、演示还是对话。大多数知识工作从根本上来说都是沟通工作：您需要解释您的想法、说服他人、记录决策、编写规范、展示发现以及跨团队协作。你的意思和别人理解的之间的差距是大多数问题的根源，而更好的沟通可以缩小这种差距。
---

## 清晰写作的原则
### 核心原则
|原理|描述 |示例|
|------------|-------------|---------|
| **清晰度** |准确地说出你的意思；避免歧义 | “系统将在 UTC 下午 3 点重新启动”而不是“系统将很快重新启动”|
| **简洁** |使用最少的文字 | “我们需要”→ 只是说明需要什么 |
| **特异性** |使用具体的细节，而不是含糊的语言 | “第三季度收入增长 15%”而不是“收入大幅增长”|
| **主动语态** |对象执行该动作 | “团队发布了该功能”而不是“该功能已发布”|
| **每句话一个想法** |不要让句子过多 |将长而复杂的句子拆分为较短的句子 |
| **并行结构** |对列表中的项目使用相同的语法形式 | “跑步、游泳和骑自行车”而不是“跑步、游泳和骑自行车”|
| **观众意识** |为你的读者而不是你自己写作|工程师的技术文档；高管摘要|
### 常见写作问题
|问题 |描述 |修复 |
|---------|-------------|-----|
| **名词化** |将动词变成名词（使散文变得死气沉沉）| “我们决定”而不是“我们做出了决定”|
| **对冲** |不必要地削弱你的信息 | “这表明”→“这表明”（当你有证据时）|
| **行话过多** |与非技术读者一起使用技术术语 |解释术语；使用类比|
| **黄鼠狼的话** |模糊的限定词破坏了意义|删除“非常”、“相当”、“有点”、“可以说”|
| **埋铅** |隐藏要点|将最重要的信息放在第一位 |
| **花园小路句子** |导致读者错误解读的句子 |重组以求清晰 |

## 专业写作的类型
### 技术文档
|类型 |目的|观众|主要特点|
|------|---------|----------|------------|
| **自述文件** |项目概况 |新用户；贡献者|快速启动；它做什么；如何安装 |
| **API 文档** |如何使用API​​ |开发商|端点；参数;例子；错误代码 |
| **架构决策记录（ADR）** |记录做出决定的原因 |未来的开发商；利益相关者 |语境;决定;后果|
| **运行手册/剧本** |分步操作流程|运营团队|准确的命令；预期产出；回滚步骤|
| **RFC（征求意见）** |提出改变；征求反馈|团队;利益相关者 |问题;提议;替代方案；权衡|
| **尸检** |解决事件后进行分析 |团队;管理 |时间轴；根本原因；行动项目|
### 商务写作
|类型 |目的|主要特点|
|------|---------|-------------|
| **电子邮件** |与同事、客户沟通 |清晰的主题行；每封电子邮件一个请求；号召性用语|
| **报告** |目前的调查结果或分析 |执行摘要;结构化部分；数据可视化|
| **提案** |说服某人批准或资助某事 |问题;解决方案;好处;成本;时间线|
| **会议记录** |记录决策和行动项目|做出的决定；谁做什么；到什么时候|
| **状态更新** |沟通进展 |做了什么；下一步是什么？阻滞剂|

## 结构化信息
### 金字塔原理（芭芭拉·明托）
|水平|描述 |
|--------|-------------|
| **结论/建议** |从答案开始 |
| **关键论点** |支持结论的3-4个理由|
| **支持证据** |每个论点的数据、示例、分析 |
**为什么有效**：忙碌的读者首先想要答案，然后是推理。如果他们只阅读第一段，他们就会明白要点。
### 倒金字塔（新闻）
|水平|描述 |
|--------|-------------|
| **领先** |最重要的信息（人物、事件、时间、地点、原因）|
| **身体** |重要细节；语境;报价|
| **尾巴** |背景;不太重要的信息 |
### SCQA 框架
|元素|描述 |示例|
|---------|-------------|---------|
| **情况** |当前状态 | “我们的应用程序每秒处理 10,000 个请求”|
| **并发症** |问题或改变| “流量每月增长 30%”|
| **问题** |我们应该做什么？ | “我们如何处理 10 倍的流量？” |
| **答案** |推荐| “迁移到具有自动扩展功能的微服务架构”|

## 演讲
### 演示结构
|部分|目的|时间分配|
|--------|---------|-----------------|
| **挂钩** |吸引注意力；陈述问题 | 10% |
| **背景** |为什么这很重要；背景| 15% |
| **主要内容** | 3大要点有据可依 | 60% |
| **结论** |总结;号召性用语| 10% |
| **问答** |解决问题 | 5% |
### 幻灯片设计原则
|原理|描述 |
|------------|-------------|
| **每张幻灯片一个想法** |每张幻灯片传达一个点 |
| **最小文本** |滑轨支撑扬声器；它们不是演示 |
| **视觉胜于言语** |尽可能使用图表、图表、图像来代替要点 |
| **一致的设计** |始终采用相同的字体、颜色、布局 |
| **可读** |文字足够大；足够的对比度|
| **数据可视化** |展示洞察力，而不仅仅是数据 |
### 处理问题
|情况|战略|
|------------|----------|
| **你知道答案** |回答简洁；提供证据|
| **你不知道** | “这是一个很好的问题。我没有确切的数据，但我会跟进” |
| **敌意的问题** |承认顾虑；解决实质问题；不要采取防御措施|
| **不清楚的问题** | “让我确认一下我明白了——你问的是 X 还是 Y？” |
| **题外话** | “这很重要，但超出了本次讨论的范围。让我们把它离线”|

## 说服力和影响力
### 亚里士多德的修辞诉求
|上诉 |描述 |如何使用 |
|--------|-------------|------------|
| **标志**（逻辑）|理由与证据|数据;逻辑论证；案例研究|
| **悲伤**（情感）|情感联系 |故事；生动的例子；共同的价值观|
| **精神**（可信度）|信任与权威|专业知识;往绩记录；参考;诚信|
### 西奥迪尼的说服原则
|原理|描述 |应用 |
|------------|-------------|-------------|
| **互惠** |人报恩 |先分享有用的信息 |
| **承诺和一致性** |人信守承诺|首先获得小协议 |
| **社会证明** |人们跟随别人|表明同行已经在这样做 |
| **权限** |人们追随专家|引用凭据；参考研究|
| **喜欢** |人们对自己喜欢的人说“是” |寻找共同点；真诚 |
| **稀缺** |人们珍视稀有|突出独特优势；时间限制|

## 跨文化交流
|尺寸|描述 |对沟通的影响|
|------------|-------------|------------------------|
| **高语境与低语境** |高：含义是隐含的。低：含义明确 |高语境文化（日本、阿拉伯）期望读者进行推断；低语境（美国、德国）期待所有陈述 |
| **直接与间接** |如何直接传达分歧或坏消息|直接（荷兰、以色列）与间接（日本、泰国）|
| **正式** |沟通的正式程度 |正式（德国、日本）与非正式（澳大利亚、美国）|
| **时间导向** |单一时间（准时）与多时间（灵活）|影响会议期望和截止日期|
| **权力距离** |等级制度如何影响沟通？高权力距离：后辈不会公开挑战前辈 |

＃＃ 概括
清晰的写作和沟通并不是要聪明，而是要被理解。从要点开始（金字塔原理）。使用主动语态、具体语言和短句。结构化信息，以便读者可以找到他们需要的内容。技术文档应该是可浏览的并且由示例驱动。商务写作应该以推荐为主导。演示文稿应该讲述一个故事，每张幻灯片都有一个想法。说服结合了逻辑（logos）、情感（pathos）和可信度（ethos）。跨文化意识可以防止全球团队中的误解。基本技能是受众意识：知道你在为谁写作，他们需要知道什么，以及什么格式可以帮助他们理解。您在更清晰的沟通上投入的每一分钟都可以节省数倍的时间，减少混乱、减少误解并加快决策速度。
