# 模型优化和部署
训练大型人工智能模型是一项重大成就，但有效部署它是需要大部分工程工作的地方。对于大多数实际应用程序来说，需要 10 秒响应或需要 8 个 A100 GPU 的模型是不切实际的。模型优化是使模型更小、更快、更具成本效益的过程，同时保持可接受的质量。该文件涵盖了量化、修剪、蒸馏以及在生产中部署模型的实用工具。
---

## 为什么要优化？
|关注|影响 |
|---------|--------|
| **延迟** |用户期望在 1 秒内得到响应；每增加 100 毫秒，参与度就会降低 |
| **成本** | GPU 推理成本高昂； 70B 模型在云硬件上每 100 万代币的成本约为 0.05-0.15 美元 |
| **内存** | FP32 中的 7B 型号需要 28 GB VRAM；大多数消费类 GPU 具有 8-24 GB |
| **能源** |运行大型模型会消耗大量电力；对于移动和边缘很重要|
| **规模** |为数百万用户提供服务需要适合可用硬件的模型 |
---

## 量化
量化将模型权重的精度从 32 位浮点 (FP32) 降低到更小的格式，如 INT8、INT4 甚至更低。
### 精确格式
|格式|每重量位数| 7B 型号内存 |品质 |
|--------------------|----------------|--------------------|---------|
| **FP32** | 32 | 32 28GB|基线（全精度）|
| **FP16 / BF16** | 16 | 16 14GB|与 FP32 几乎相同 |
| **INT8** | 8 | 7GB|质量损失非常小 |
| **INT4** | 4 | 3.5 GB | 3.5 GB中等质量损失；还能用|
| **INT3 / INT2** | 3-2 | 3-2 2.6-1.75 GB |严重的质量损失；研究阶段|
### 量化方法
|方法|当它发生时 |它是如何运作的 |品质 |
|--------|----------------|--------------|---------|
| **训练后量化 (PTQ)** |培训完成后 |在小数据集上校准模型；找到最佳尺度|适用于 INT8； INT4 时降级 |
| **GPTQ** |训练后|使用近似二阶信息进行 GPU 友好的 INT4 量化 | INT4 品质优良 |
| **AWQ**（激活感知权重量化）|训练后|根据激活幅度保护显着权重 | INT4 优于 GPTQ |
| **GGUF**（llama.cpp 格式）|训练后| CPU友好的量化；每层混合精度|针对 CPU 推理进行优化 |
| **量化感知训练 (QAT)** |训练期间 |在训练期间模拟量化，以便模型学会应对 |极品;需要再培训|
### 实际影响
|型号| FP16 尺寸 | INT4 尺寸 |加速|质量损失|
|--------|---------|------------|---------|------------|
| **骆驼 7B** | 14GB| 3.5 GB | 3.5 GB 2-4x |基准测试的约 1-2% |
| **骆驼 70B** | 140 GB | 140 GB 35GB| 2-3x |基准测试的约 2-3% |

## 修剪
剪枝从训练模型中删除不必要的权重或神经元。
|类型 |描述 |优势 |挑战|
|------|-------------|------------|------------|
| **非结构化** |删除单个权重（设置为零）|最高压缩比 |需要稀疏的硬件支持 |
| **结构化** |删除整个神经元、注意力头或层 |直接缩小模型尺寸 |可能会失去更多品质|
| **基于幅度** |删除绝对值最小的权重 |简单的;效果很好|可能会错过重要的小重量|
| **基于重要性** |根据权重对输出的贡献来删除权重 |更好的品质保存 |计算成本更高 |
### 修剪管道
|步骤|描述 |
|------|-------------|
| 1. 火车 |正常训练完整模型 |
| 2. 分数 |计算每个权重/神经元的重要性得分 |
| 3.修剪|删除最不重要的元素 |
| 4.微调|重新训练以恢复损失的准确性 |
| 5.重复|迭代剪枝和微调以实现更高的压缩 |
---

## 知识蒸馏
训练小型“学生”模型来模仿大型“教师”模型。
|组件|角色 |
|------------|------|
| **老师** |大型高品质模型 |
| **学生** |向老师学习的小模型|
| **蒸馏损失** |学生尝试匹配老师的输出分布（软标签）|
### 蒸馏类型
|类型 |描述 |示例|
|------|-------------|---------|
| **基于 Logit** |学生与老师的输出概率相匹配 |辛顿的原始蒸馏|
| **基于功能** |学生与老师的中间表示相匹配|健身网 |
| **基于关系** |学生匹配样本之间的关系 | RKD（关系知识蒸馏）|
| **无数据** |无需原始训练数据；用师之辈| DAFL、深度反演 |
### 著名的蒸馏示例
|老师|学生|结果 |
|--------|---------|--------|
| **GPT-4** | GPT-3.5-turbo（传闻）|较小的型号，具有 GPT-4 的大部分品质 |
| **BERT-大** |蒸馏伯特 |体积缩小 40%，速度提高 60%，性能达到 BERT 的 97% |
| **骆驼 70B** | LLaMA 7B（通过蒸馏）|开源小模型接近大模型质量 |

## LLM 特定优化
### KV-缓存优化
大型语言模型会缓存先前标记中的键值对以避免重新计算。
|技术|描述 |影响 |
|------------|-------------|--------|
| **多查询注意力（MQA）** |所有注意力头共享一对 KV |减少记忆力；轻微的质量损失|
| **分组查询注意力（GQA）** |头部组共享 KV 对 | MQA 和标准注意力之间的平衡 |
| **滑动窗口注意** |只关注最后的 W 令牌 |减少长上下文的 KV 缓存大小 |
### 推测解码
|步骤|描述 |
|------|-------------|
| 1 |一个小型“草稿”模型快速生成 K 个代币 |
| 2 |大型模型在一次前向传递中验证所有 K 个令牌 |
| 3 |保留已接受的代币；被拒绝的被再生|
结果：生成速度提高 2-3 倍，且没有质量损失（大模型始终拥有最终决定权）。
### 闪光注意
|特色|描述 |
|---------|-------------|
| **问题** |标准注意力需要 O(n²) 内存来存储注意力矩阵 |
| **解决方案** |以块为单位计算注意力；永远不要在内存中具体化完整的矩阵|
| **结果** |速度提高 2-4 倍；启用更长的上下文窗口
| **变体** | Flash Attention 2（更快）、FlashDecoding（针对推理进行了优化）|

## 部署模式
|图案|描述 |何时使用 |
|---------|-------------|----------|
| **边缘部署** |在手机、物联网设备或嵌入式硬件上运行模型 |低延迟；离线；隐私 |
| **云API** |在云 GPU 上托管模型；通过 API 提供服务 |最大计算量；按使用付费|
| **混合** |设备上的小模型；云中的大型模型|两全其美 |
| **无服务器** |缩放至零；仅在使用时付费 |零星交通；成本敏感 |
| **批量推理** |按计划批量处理数据 |当不需要实时时 |

## 基准测试
|公制|它测量什么 |
|--------|-----------------|
| **每秒令牌数** |生成吞吐量（越高越好）|
| **第一个令牌的时间 (TTFT)** |第一个输出标记出现之前的延迟 |
| **每个请求的延迟** |从输入到完成输出的总时间|
| **内存使用情况** |推理过程中消耗的 VRAM 或 RAM |
| **吞吐量** |每秒处理的请求数 |
| **每 100 万个代币的成本** |处理 100 万个代币的美元成本 |

## 实用技巧
- **从量化开始。** INT4 量化（AWQ 或 GPTQ）提供最佳的质量与尺寸权衡。大多数 7B 型号可以在 INT4 的单个消费级 GPU 上轻松运行。
- **使用 vLLM 进行 LLM 服务。** 它是用于高吞吐量 LLM 推理的最快开源选项。
- **优化前的配置文件。** 衡量实际花费时间的地方。瓶颈通常是内存带宽，而不是计算。
- **将模型与任务相匹配。** 7B 模型适用于大多数任务。当 7B 就可以时，不要使用 70B。
- **考虑蒸馏。** 如果您需要一个小型、快速的模型进行生产，请从较大的模型中进行蒸馏，而不是从头开始训练。
- **持续监控。** 随着数据分布的变化，模型性能可能会随着时间的推移而降低。跟踪延迟、吞吐量和质量指标。

＃＃ 概括
模型优化是研究和生产之间的桥梁。量化可将模型缩小 4-8 倍，同时将质量损失降至最低。修剪可以消除自重。蒸馏将知识从大模型转移到小模型。 Flash Attention 和 KV 缓存技巧使推理速度更快。这些技术共同将需要数据中心的模型转变为在笔记本电脑或手机上运行的模型。该领域正在快速发展——去年需要 8 个 A100 的任务如今可以在消费级 GPU 上运行。
