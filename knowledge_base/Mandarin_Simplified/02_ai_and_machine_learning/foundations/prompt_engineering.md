# 快速工程
提示工程是设计、完善和优化输入提示以从语言模型获得最佳输出的实践。它既是一门艺术，也是一门科学，并且是无需微调即可控制 LLM 行为的主要界面。
---

## 核心原则
### 清晰度和特异性
明确的提示不留任何含糊之处。准确指定您想要的内容，包括格式、长度和视角。
**含糊：**
> “告诉我有关 Python 的信息。”
**具体：**
> “解释 Python 的全局解释器锁 (GIL)。描述它对多线程的影响，给出一种解决方法，并将答案控制在 200 字以内。”
### 提供上下文
当模型了解角色、受众和目标时，他们的表现会更好。
**没有上下文：**
> “编写一个函数对列表进行排序。”
**结合上下文：**
> “您是一名高级 Python 开发人员。编写一个函数来按给定键对字典列表进行排序。使用类型提示并处理边缘情况。受众是初级开发人员。”
### 使用积极的指令
告诉模型要做什么，而不是要避免什么。 “不要使用行话”比“使用 10 岁孩子可以理解的简单语言”弱。
---

## 提示结构
### 系统/用户/助理角色
大多数 LLM API 支持多轮结构：
- **系统消息**：设置模型的行为、角色和约束（在整个会话中持续存在）。
- **用户消息**：当前查询或指令。
- **助理消息**：模型之前的响应（用于连续性）。
**示例（OpenAI API 风格）：**
系统：你是一位有用的编码助手。您用简洁的代码示例和简短的解释进行回复。切勿提供不安全的代码。
用户：编写一个 Python 函数来从 URL 下载文件。
### 少量提示
在要求模型执行任务之前，提供 2-3 个所需输入输出格式的示例。这教导了模式。
**示例：**
用户：将这些句子转换为被动语态：
输入：猫追老鼠。
输出：老鼠被猫追赶。
输入：厨师做饭了。
输出：这顿饭是厨师做的。
输入：风暴摧毁了房子。
输出：（模型完成）
### 思想链 (CoT)
鼓励模型逐步展示其推理。这提高了算术、逻辑和多步骤任务的准确性。
**没有 COT：**
> “什么是 24 × 37？”
**含 COT：**
> “计算 24 × 37。逐步展示你的推理。”
该模型将产生中间步骤，减少算术错误。
### 结构化输出
请求特定格式（例如 JSON、YAML 或 Markdown 表）以使解析可靠。
用户：列出微服务的三个优点和三个缺点。仅返回带有键“pros”和“cons”的有效 JSON 对象，每个键都是字符串数组。

## 先进技术
### 自我一致性
针对同一提示（温度 > 0）生成多个响应，并对最终答案进行多数投票。这对于推理任务特别有效。
### 思想树
并行探索多个推理路径，评估每个路径，然后选择最佳的一个。这是一种研究级技术，但可以通过要求模型“探索替代解决方案”来近似。
### ReAct（推理+行动）
让模型将推理与工具调用交织在一起。它可以思考，然后采取行动（例如，搜索网络，运行代码），然后根据结果再次思考。
**提示结构：**
您可以使用计算器和搜索引擎。对于每一步，输出：
想法：（你的推理）
操作：（工具名称，输入）
观察结果：（工具输出）
...继续下去，直到得到最终答案。
### 角色分配
指定一个特定的角色来构建响应。
**示例：**
- “您是一名 Linux 内核开发人员，向应届毕业生解释内存管理。”
- “您是一位友好的营养师，为客户提供一般性建议。”
- “你是一个愤世嫉俗的技术评论家，正在评论一个新产品。”

## 参数调优
- **温度** (0.0 – 1.0+)：控制随机性。较低=更具确定性，较高=更具创造性。对于事实答案使用 0.0–0.3；创意写作为 0.7–1.0。
- **Top-p**（核采样）：在某个累积阈值处截断概率质量。 0.9 表示模型从前 90% 的可能标记中采样。通常调整温度或顶部温度，而不是两者都调整。
- **最大令牌**：设置最大输出长度。请记住在上下文窗口中为响应预留空间。
- **频率惩罚**：减少相同标记的重复。
- **存在惩罚**：鼓励模型引入新主题。

## 常见陷阱和修复
|问题 |可能的原因 |修复|
|---------|--------------|-----|
|模型忽略部分提示 |提示太长或超载|缩短;把最重要的指令放在最后|
|输出太冗长|无长度限制 |添加“限制为 3 句话”或设置 max_tokens |
|输出过于简洁|过度限制 |添加“详细说明”或降低温度 |
|事实幻觉|上下文不足或问题不明确 |添加“如果您不确定，请说‘我不知道’”并提供 RAG 上下文 |
|格式不一致 |没有明确的格式指令|请求 JSON、Markdown 表或项目符号列表 |
|错误语言的示范答案 |无语言指导|明确说明“用英语回复”（或您的目标语言）|

## 常见任务的提示模板
### 总结
将以下文字概括为 3 个要点。关注主要论点，避免细节。
文本：[插入文本]

### 代码生成
编写一个[语言]函数来[执行X]。
要求：
使用类型提示。
包含文档字符串。
处理边缘情况：[列表]。
除非指定，否则不要使用外部库。

### 解释
向[非专家/大学生/儿童]解释[概念]。在适当的地方使用类比。
### 头脑风暴
为 [主题] 生成 10 个想法。对于每个想法，给出一句话描述和一个潜在的挑战。
文本
### 分类

提供置信度分数 (0-100) 和简短原因。
反馈：[插入文字]
### 风格翻译
将以下英文文本翻译成西班牙语。使用适合社交媒体帖子的非正式语气。
文本：[插入文本]

## 提示评估
将提示视为代码：对其进行版本控制、测试并迭代。
- **A/B 测试**针对一组保留的查询的不同提示变体。
- **通过人工评估或自动指标（例如，精确匹配、BLEU、自定义评分）衡量成功。
- **保留提示注册表**（一个简单的文本文件或电子表格），其中包含提示、版本和观察到的性能。
