# 机器学习评估和工作流程
机器学习生命周期的实用指南（从问题框架到生产监控），重点关注指标、验证和调试。
---

## 机器学习工作流程 (CRISP-ML)
1. **业务理解**：定义目标和成功标准。
2. **数据理解**：探索可用数据，识别质量问题。
3. **数据准备**：清理、转换和拆分数据。
4. **建模**：训练模型，调整超参数。
5. **评估**：根据指标评估绩效。
6. **部署**：在生产中提供模型。
7. **监控**：跟踪漂移、性能和异常情况。
这是一个迭代循环 - 您将根据评估结果重新访问之前的步骤。
---

## 数据分割
### 训练/验证/测试拆分
- **训练集** (~70%)：用于拟合模型参数。
- **验证集** (~15%)：用于调整超参数并选择模型变体。
- **测试集** (~15%)：在最后仅使用一次来估计泛化性能。
**重要提示：** 在最终评估之前，测试集必须保持完全不变，以避免数据泄漏。
### 交叉验证（k 倍）
对于小型数据集，使用 k 折交叉验证：将数据拆分为 k 折，在 k-1 上进行训练，对剩余的进行验证，然后重复 k 次。平均表现。 k=5 或 k=10 是常见的。
### 分层分裂
对于不平衡类别的分类，请使用分层分割来保留每个子集中的类别比例。
### 基于时间的分割
对于时间序列数据，按时间顺序分割（训练过去，测试未来）而不是随机。

## 评估指标
### 分类指标
|公制|它测量什么 |最适合 |
|--------|--------------------|------------|
| **准确度** | (TP + TN) / (TP + TN + FP + FN) | (TP + TN) / (TP + TN + FP + FN) |平衡数据集|
| **精确** | TP / (TP + FP) |当误报代价高昂时（例如垃圾邮件检测）|
| **回忆** | TP / (TP + FN) |当假阴性代价高昂时（例如癌症筛查）|
| **F1 分数** |精确率和召回率的调和平均值 |不平衡数据集，单数指标 |
| **AUC-ROC** | ROC曲线下面积； TPR 和 FPR 之间的权衡 |通用分类器性能与阈值无关 |
| **AUC-PR** |精确率-召回率曲线下的面积 |高度不平衡的数据集 |
**定义：**
- TP = 真阳性
- TN = 真阴性
- FP = 误报（I 类错误）
- FN = 假阴性（II 类错误）
### 回归指标
|公制|它测量什么 |对异常值的敏感性|
|--------|--------------------------------|--------------------------|
| **MSE**（均方误差）|平均平方差|高|
| **RMSE**（均方根误差）| MSE 的平方根（与目标单位相同）|高|
| **MAE**（平均绝对误差）|平均绝对差|低|
| **R²**（决定系数）|方差比例解释 |没有直接影响，但间接对异常值敏感|
### 排名和检索指标
- **Precision@k**：top-k 推荐中相关项目的比例。
- **Recall@k**：出现在 top-k 中的所有相关项目的分数。
- **NDCG**（标准化贴现累积收益）：考虑仓位相关性。
- **命中率**：相关项是否出现在 top-k 中。
### 生成/法学硕士指标
- **困惑度**：模型对保留文本的“惊讶”程度（越低越好）。
- **BLEU**：n-gram 与参考翻译重叠（注重精度）。
- **ROUGE**：以回忆为导向的重叠进行总结。
- **BERTScore**：使用上下文嵌入的语义相似性（比 BLEU 更强大）。
- **METEOR**：与 WordNet 同义词和词干对齐。

## 评估陷阱
### 数据泄露
当测试集中的信息无意中影响训练时就会发生。
- **预防：**切勿将测试数据用于特征工程、标准化或超参数调整。
- **检测：** 如果您的模型得分可疑高，则怀疑存在泄漏。
### 过度拟合
模型在训练数据上表现良好，但在验证/测试上表现不佳。
- **缓解：** 使用正则化、提前停止、简化架构或收集更多数据。
### 欠拟合
模型在训练和验证方面都表现不佳。
- **缓解：** 使用更复杂的模型，添加功能或减少正则化。
### 数据不平衡
- **缓解：** 使用类别权重、过采样 (SMOTE)、欠采样或使用适当的指标（F1、AUC-PR）而不是准确性。
### 时间漂移（概念漂移）
特征和目标之间的关系随着时间的推移而变化。
- **缓解：** 定期重新训练、监控性能、使用漂移检测算法。

## 超参数调优
- **网格搜​​索**：彻底尝试一组预定义超参数的所有组合。简单但计算成本昂贵。
- **随机搜索**：从分布中抽取随机组合样本。比高维空间的网格搜索更有效。
- **贝叶斯优化**：构建目标函数的概率模型并智能选择超参数。库：Optuna、Hyperopt、scikit-optimise。
- **自动调整**：使用 Optuna、Ray Tune 或 Weights & Biases Sweeps 等工具进行分布式调整。
**常见超参数的建议搜索范围：**
|参数|建议范围（对数刻度）|
|------------|----------------------------|
|学习率| 1e-5 至 1e-1 |
|批量大小| 16、32、64、128、256 |
|层数 (NN) | 2 至 6 |
|神经元数量 (NN) | 32 至 1024 |
|正则化（L2）| 1e-6 至 1e-2 |
|树深度（XGBoost）| 3 至 12 |

## 模型选择和验证
1. **基线模型**：从简单的启发式或简单模型（例如逻辑回归、均值预测器）开始建立下限。
2. **候选模型**：训练多个模型系列（例如随机森林、XGBoost、神经网络）。
3. **交叉验证**验证集上的每个候选者。
4. **比较指标**（与置信区间）并选择最佳候选者。
5. 对保留的测试集进行**最终评估**。
6. **错误分析**：查看模型出错的示例。识别模式（例如，稀有类别、模糊输入）并将见解反馈到数据准备或特征工程中。

## 部署和监控
### 服务模式
- **批量推理**：离线处理大量数据（例如，每晚推荐）。
- **在线推理**：通过 API 进行实时预测（例如信用评分、欺诈检测）。
- **流式推理**：事件驱动、实时、低延迟（例如，物联网传感器警报）。
### 模型监控
- **性能监控**：跟踪实时数据随时间变化的准确性/F1（当地面真实情况可用时）。
- **数据漂移**：监控输入特征分布的变化（例如，使用 PSI – 群体稳定性指数）。
- **概念漂移**：监控输入和输出之间关系的变化。
- **预测漂移**：跟踪预测输出的分布。
- **延迟和吞吐量**：确保满足 SLA（服务级别协议）。
### 日志记录和警报
- 记录所有预测请求和响应（匿名）。
- 设置警报：
  - 性能显着下降。
  - 丢失或无效输入的比例很高。
  - 模型输出超出预期范围。
### 模型版本控制和注册表
- 使用模型注册表（例如 MLflow、权重和偏差、Sagemaker 模型注册表）来存储和版本模型、元数据和评估结果。
- 将训练代码和数据版本（通过 DVC 或 Git LFS）与模型一起存储。
