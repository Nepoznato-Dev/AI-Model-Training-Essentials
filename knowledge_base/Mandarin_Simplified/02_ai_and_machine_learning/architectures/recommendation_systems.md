# 推荐系统
推荐系统预测用户接下来想要看到、购买或交互的内容。它们为社交媒体上的内容提要、电子商务网站上的产品建议、流媒体平台上的电影精选以及搜索结果提供支持。尽管大多数用户看不见，但它们是世界上最具商业影响力的人工智能系统之一——Netflix 估计，其推荐引擎通过减少用户流失，每年节省超过 10 亿美元。
---

## 为什么推荐很难
|挑战|描述 |
|------------|-------------|
| **规模** |数百万用户 × 数百万商品 = 数十亿可能对 |
| **稀疏性** |每个用户都与一小部分可用项目进行了交互 |
| **冷启动** |新用户和新物品没有交互历史 |
| **动态首选项** |用户品味随时间而变化|
| **超越准确性** |推荐也必须是多样化的、新颖的和偶然的 |
| **业务目标** |最大化参与度≠最大化用户福祉|
---

## 核心方法
### 协同过滤
这个想法是：如果用户 A 和 B 过去同意，他们将来也可能会同意。
|类型 |它是如何运作的 |示例|
|------|-------------|---------|
| **基于用户** |寻找相似的用户；推荐他们喜欢的 | “喜欢这个的用户也喜欢...” |
| **基于项目** |查找与用户已经喜欢的类似的项目 | “因为你看了……” |
| **矩阵分解** |将用户-项目交互矩阵分解为潜在因素 | SVD、ALS（交替最小二乘法）|
|实力|弱点|
|----------|----------|
|无需了解物品本身|冷启动问题：无法推荐新商品|
|捕捉复杂、隐含的偏好 |需要大量交互数据 |
|适用于任何内容类型 |流行度偏差：推荐已经流行的商品 |
### 基于内容的过滤
根据商品特征推荐与用户已经喜欢的商品相似的商品。
|特征类型|示例|
|-------------|---------|
| **文字** |类型、描述、关键词、演员 |
| **音频** |节奏、流派、情绪（音乐）|
| **视觉** |调色板、风格（图像/时尚）|
| **元数据** |价格、品牌、类别 |
|实力|弱点|
|----------|----------|
|项目无冷启动（功能已知）|无法推荐超出用户现有口味的商品 |
|使用较少的交互数据即可工作 |需要良好的特征工程 |
|可解释（“推荐，因为它与 X 类似”）|更少的偶然性|
### 混合方法
大多数生产系统结合了协作和基于内容的方法。
|混合战略|描述 |
|----------------|-------------|
| **加权** |合并多个模型的分数 |
| **切换** |对于新用户使用基于内容的方式，对于老用户使用协作方式 |
| **级联** |首先使用一个简单的模型，然后使用复杂的模型进行细化 |
| **功能组合** |将协作和内容功能合并到单个模型中 |
| **元学习** |了解如何组合不同的推荐器 |

## 现代深度学习方法
### 两塔模型
大规模推荐的主导架构（YouTube、Pinterest、Spotify 使用）。
|组件|角色 |
|------------|------|
| **用户塔** |将用户特征和历史记录编码到嵌入中的神经网络 |
| **物品塔** |将项目特征编码到嵌入中的神经网络 |
| **相似性** |用户和项目嵌入之间的点积或余弦相似度 |
|步骤|描述 |
|------|-------------|
| 1 |训练两个塔为交互的用户-项目对生成类似的嵌入 |
| 2 |在服务时，预先计算项目嵌入 |
| 3 |对于用户请求，计算用户嵌入|
| 4 |使用近似最近邻 (ANN) 搜索来查找最相似的项目 |
### 推荐序列模型
用户行为是连续的——您昨天观看的内容会影响您今天观看的内容。
|型号|方法|
|--------|----------|
| **GRU4Rec** |用于基于会话的推荐的基于 GRU 的模型 |
| **SASRec** |基于自注意力的顺序推荐器 |
| **BERT4Rec** |用于顺序推荐的双向变压器 |
| **YouTube DNN** |深度神经网络将观看历史记录视为一个序列 |
### 检索与排名
现代系统将建议分为两个阶段：
|舞台|目的|方法|
|--------|---------|--------|
| **检索（候选生成）** |将数百万个项目缩小到约 1,000 个候选者 |两塔模型；人工神经网络搜索；快速但近似|
| **排名（评分）** |精准评分并排序候选人 |具有多种特征的深度模型；较慢但准确 |
| **重新排名** |针对多样性、业务规则、新鲜度进行调整 |上下文强盗；约束优化|

## 评估指标
|公制|它测量什么 |何时使用 |
|--------|-----------------|-------------|
| **精准@K** |相关的 Top-K 推荐的比例 |当您关心首选的准确性时 |
| **回忆@K** |在 top-K 中找到的相关项目的比例 |当你在意不要错过好单品时 |
| **NDCG**（标准化贴现累积增益）|排名质量；奖励将相关项目提升到更高水平 |当排名顺序很重要时 |
| **MAP**（平均精度）|所有用户的平均精确度 |综合排名质量|
| **命中率@K** | top-K 中是否至少出现一项相关项 |二元相关场景|
| **覆盖范围** |获得推荐的项目比例 |多元化与公平 |
| **机缘巧合** |意想不到但相关的建议 |用户满意度 |

## 冷启动问题
|场景|挑战|解决方案 |
|----------|------------|------------|
| **新用户** |没有互动历史 |使用人口统计数据；显示热门商品；使用上下文信号（位置、设备、时间） |
| **新项目** |尚未有人与之互动 |使用内容特征；探索-利用策略；强盗算法 |
| **新系统** |没有数据 |来自相似领域的迁移学习；策划初始内容 |
---

## 探索与利用
|策略|描述 |权衡|
|----------|-------------|------------|
| **ε-贪婪** |以概率 ε 显示随机项目 |简单但低效|
| **汤普森采样** |物品质量后验分布的样本 |有原则；良好的理论特性 |
| **置信上限 (UCB)** |偏好具有高度不确定性的项目 |勘探与开采的良好平衡|
| **上下文强盗** |以用户上下文为条件的探索 |比盲目探索更高效 |
| **多样性注入** |故意包含多样化或新颖的项目 |简单的;可能会减少短期参与|
---

## 偏见和公平
|偏置类型|描述 |影响 |
|------------|-------------|--------|
| **受欢迎程度偏差** |热门商品获得更多推荐，变得更受欢迎 |长尾产品服务不足 |
| **选择偏差** |模型从观察到的交互中学习，而不是所有可能的交互偏向活跃用户|
| **位置偏差** |无论质量如何，显示在较高位置的项目都会获得更多点击次数 |巩固顶级地位 |
| **曝光偏差** |已显示的项目会获得更多训练信号 |反馈循环|
| **人口偏见** |不同人群的建议存在不公平的差异 |歧视;一些团体的体验不佳|
### 缓解策略
|策略|描述 |
|----------|-------------|
| **逆倾向权重** |减重训练中热门项目|
| **去偏层** |向模型添加去偏组件 |
| **公平约束** |添加约束以确保公平待遇 |
| **多样化推荐** |明确优化多样性和相关性 |
| **审计和监控** |定期检查建议是否存在跨群体偏差 |

## 行业示例
|公司 |系统|方法|
|---------|--------|----------|
| **Netflix** |电影/电视推荐 |艺术品的两塔检索+深度排名+上下文强盗 |
| **YouTube** |视频推荐|用于候选生成的深度神经网络；单独排名模型|
| **Spotify** |音乐推荐 |协同过滤+播放列表上的NLP+音频分析|
| **亚马逊** |产品推荐|逐项协同过滤；大规模个性化|
| **抖音** |短视频直播 |强化学习；高度重视探索|
| **Pinterest** |视觉推荐 |两塔模型；视觉相似度|

＃＃ 概括
推荐系统是行业中最具影响力的人工智能应用之一。该领域已经从简单的协作过滤发展到结合用户历史、项目内容、上下文信号和业务目标的深度学习架构。现代系统使用检索-排名-重新排名管道，具有用于快速候选生成的两塔模型和用于精确评分的深度模型。冷启动、偏差、探索以及平衡用户满意度与业务目标等挑战仍然是研究和工程的活跃领域。
