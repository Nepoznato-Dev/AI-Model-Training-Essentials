# 数据可视化
精心设计的图表可以揭示数字表隐藏的模式。设计不佳的产品可能会产生误导、混乱或令人厌烦。数据可视化是将数据转化为为决策提供信息的视觉故事的技术。该文件涵盖图表选择、设计原则、常见错误以及使这一切成为可能的工具。
---

## 选择正确的图表
任何可视化中最重要的决定是为您的数据和消息选择正确的图表类型。
### 图表选择指南
|您的目标 |最佳图表类型 |
|------------|------------------|
| **比较类别** |条形图、分组条形图|
| **显示随时间的变化** |折线图、面积图 |
| **显示分布** |直方图、箱线图、小提琴图 |
| **显示关系** |散点图、气泡图|
| **显示构图** |堆叠条形图、饼图（有限切片）、树状图 |
| **显示相关性** |散点图、热图、配对图 |
| **显示排名** |水平条形图|
| **显示地理模式** |等值线图、点图 |
| **随着时间的推移显示部分到整体** |堆积面积图|
### 何时使用每个图表
|图表|优势 |避免何时 |
|--------|---------|------------|
| **酒吧** |跨类别的清晰比较 |类别太多 (>15) |
| **线路** |随时间变化的趋势；连续数据|数据不是连续的 |
| **分散** |两个变量之间的关系 |重叠点太多 |
| **直方图** |一个变量的分布形状 |小样本量 (<20) |
| **Box plot** | Summary statistics + outliers; compare distributions | Audience unfamiliar with them |
| **Heatmap** | Correlation matrices; patterns in 2D data | Too many variables |
| **Pie chart** | Simple composition (2–5 slices) | More than 5 slices; precise comparisons needed |
| **Violin plot** | Distribution density + quartiles | Small audiences unfamiliar with them |
| **Pair plot** | Quick overview of all variable relationships | Many variables (>8) |

## 设计原则
### Tufte 的核心理念
Edward Tufte 的原则仍然是数据可视化的黄金标准：
|原理|描述 |
|------------|-------------|
| **最大化数据墨水比率** |每一滴墨水都应该传达数据。删除所有其他内容。 |
| **消除图表垃圾** |没有 3D 效果、无用的渐变或装饰元素。 |
| **显示数据** |不要歪曲、隐藏或挑选。让数据说话。 |
| **小倍数** |使用重复的小图表进行跨类别比较。 |
| **迷你图** |用于内联趋势数据的小型字大小图表。 |
### 实用设计规则
|规则|为什么 |
|------|-----|
| **y 轴从零开始**（对于条形图）|否则你就会夸大差异|
| **直接标记** |尽可能将标签放在线条/条上，而不是使用图例 |
| **有目的地使用颜色** |突出显示重要的内容；使用灰色作为上下文 |
| **保持简单** |每个图表一条消息；请勿超载|
| **使用一致的尺度** |比较图表时，保持轴相同 |
| **有意义的订购** |按值（不是按字母顺序）对条形图进行排序，除非存在自然顺序 |
| **提供背景** |添加基准、目标或历史平均值 |
### 颜色指南
|使用案例|方法|
|----------|----------|
| **分类** |不同的色调（蓝色、橙色、绿色、红色）——最多 7-8 个类别 |
| **顺序** |从浅到深的一种色调（浅蓝色→深蓝色）|
| **分歧** |具有有意义的中点的数据的二色调梯度（红色←白色→蓝色）|
| **辅助功能** |使用色盲模拟器进行测试；不要仅依赖颜色（添加标签或图案） |

## 用数据讲故事
没有叙述的图表只是一张图片。讲故事将数据转化为洞察力。
### 讲故事的框架
1. **背景**：情况如何？观众已经知道什么？
2. **冲突**：数据中的问题、意外或紧张是什么？
3. **解决方案**：观众应该根据这一见解做什么？
### 实用技巧
|提示 |描述 |
|-----|-------------|
| **以洞察力引领** |用要点而不是数据来命名图表（“收入增长了 30%”而不是“按季度收入”）|
| **标注要点** |为重要事件或转折点添加文本标注 |
| **使用渐进式披露** |一次显示一张图表；一步步构建故事|
| **突出重要的事情** |使用颜色或大小来引起对关键数据点的注意 |
| **提供“那又怎样？”** |每个图表都应该回答一个问题或提示一个行动 |

## 常见错误
|错误|为什么它不好 |修复 |
|---------|-------------|-----|
| **截断的 y 轴** |夸大微小差异|条形图从零开始 |
| **采摘时间范围** |关于趋势的误导|显示完整的可用范围 |
| **颜色太多** |震撼观众|限制为 5-7 个；使用灰色作为上下文 |
| **双 y 轴** |暗示可能不存在的相关性 |使用两个单独的图表 |
| **3D 图表** |扭曲比例 |始终使用 2D |
| **具有 10 多个切片的饼图** |无法比较|使用条形图代替 |
| **缺少标签** |查看者无法理解图表 |始终标记轴、标题和单位 |
| **误导性面积图** |堆叠区域扭曲了单个系列的感知 |使用折线图或小倍数 |

## 仪表板设计
仪表板是可视化的集合，它们共同讲述了有关流程、系统或业务的完整故事。
### 仪表板类型
|类型 |观众|目的|
|------|----------|---------|
| **战略** |行政人员 |高级别 KPI；长期趋势|
| **运营** |经理 |实时监控；日常运营|
| **分析** |分析师 |深度探索；过滤、深入分析 |
### 设计清单
- **了解您的受众**：他们会从此仪表板做出什么决定？
- **5秒法则**：5秒内能否掌握主要内容？
- **布局**：最重要的指标位于左上角（眼睛首先看到的位置）。
- **限制图表类型**：每个仪表板最多 3-4 种类型以保持一致性。
- **默认情况下交互式**：过滤器、日期范围选择器、向下钻取。
- **性能**：加载时间超过 5 秒的仪表板不会被使用。
- **移动**：如果用户在旅途中需要它，请考虑响应式设计。
---

＃＃ 概括
良好的数据可视化涉及清晰度、诚实性和影响力。为您的数据选择正确的图表。删除所有与该消息无关的内容。使用颜色和注释来引导观看者。始终、始终让数据讲述故事，而不是相反。
