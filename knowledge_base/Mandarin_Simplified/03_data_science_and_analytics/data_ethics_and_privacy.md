# 数据伦理和隐私
数据伦理是对数据收集、分析和部署如何影响人们的权利、自主权和福祉的研究。隐私是对谁控制个人信息以及如何共享个人信息的具体关注。这些话题已经从学术辩论变成了头版新闻——GDPR 的执行、影响数十亿用户的数据泄露，以及公众越来越意识到科技公司的数据实践对民主、平等和个人自由产生真正的影响。
---

## 为什么数据道德很重要
|关注|描述 |现实世界的影响 |
|--------|-------------|--------------------|
| **监视资本主义** |公司大规模将个人数据货币化 |失去隐私；操纵行为|
| **算法偏差** |用有偏见的数据训练的模型会重现偏见招聘、贷款、治安方面的歧视 |
| **知情同意** |用户不明白他们同意什么 |为一个目的收集的数据用于另一目的|
| **数据泄露** |敏感数据因安全性差而暴露 |身份盗窃；财务欺诈；名誉受损 |
| **过滤气泡** |个性化提要强化现有信念|政治两极分化；错误信息|
| **深色图案** |旨在诱骗用户共享数据的 UI不需要的订阅；意外的数据共享|

## 隐私框架和法规
### 主要隐私法
|监管 |地区 |关键要求|
|------------|--------------------|-----------------|
| **GDPR**（一般数据保护条例）|欧盟/欧洲经济区 |处理的合法依据；访问权；被遗忘的权利；数据可移植性； 72 小时违规通知；高达全球收入 4% 的罚款 |
| **CCPA / CPRA**（加州隐私权法案）|美国加利福尼亚州 |知情权；删除权；选择停止销售的权利；儿童的有限选择|
| **LGPD**（Lei Geral de Proteção de Dados）|巴西 |与 GDPR 类似；合法依据；数据主体权利；需要 DPO |
| **PIPL**（个人信息保护法）|中国 |需要同意；数据本地化；跨境转账限制|
| **POPIA**（个人信息保护法）|南非 |合法处理的条件；数据主体权利；调节器|
| **DPDP 法**（数字个人数据保护法）|印度 |同意;目的限制；数据主体权利；数据信托义务|
### GDPR 核心原则
|原理|要求 |
|------------|-------------|
| **合法、公平、透明** |合法处理数据；不误导用户；公开您收集的内容 |
| **目的限制** |仅出于指定、明确的目的收集数据 |
| **数据最小化** |只收集您真正需要的 |
| **准确度** |保持数据准确；更正或删除不准确的数据 |
| **存储限制** |数据保留时间不要超过必要的时间 |
| **诚信和保密** |保护数据免遭未经授权的访问和丢​​失 |
| **责任** |证明遵守上述所有规定 |

## 隐私保护技术
|技术|它是如何运作的 |权衡|
|------------|-------------|------------|
| **匿名化** |删除个人身份信息 (PII) |难以完全匿名；重新识别风险 |
| **化名** |用假名替换标识符 |可逆； GDPR 下的个人数据仍然存在 |
| **差异隐私** |将校准噪声添加到查询结果 |降低准确度；提供数学隐私保障|
| **联邦学习** |在设备上训练模型；只分享模型更新|训练速度较慢；通信开销|
| **安全多方计算** |多方在不泄露输入的情况下计算函数 |计算成本昂贵；实施起来很复杂|
| **同态加密** |对加密数据执行计算 |非常慢；有限运营支持|
| **数据脱敏** |隐藏部分数据（例如`***-**-1234`）|简单但有限的保护 |

## 道德数据收集
### 道德收集原则
|原理|描述 |
|------------|-------------|
| **知情同意** |用户了解他们同意什么；不被法律术语埋没|
| **目的透明** |明确说明收集数据的原因以及如何使用数据 |
| **最小收藏** |只收集达到既定目的所需的东西 |
| **用户控制** |让用户访问、更正、下载和删除他们的数据 |
| **保留有限** |不再需要时删除数据 |
| **影响评估** |在收集敏感数据之前评估潜在危害 |
### 常见的深色图案
|图案|描述 |示例|
|---------|-------------|---------|
| **隐私胡闹** |诱骗用户分享超出他们预期的内容 |注册时预先勾选“与朋友分享”|
| **罗奇汽车旅馆** |注册方便；很难取消|帐户删除需要电话或传真|
| **强制连续性** |免费试用版转换为付费版，恕不另行通知 |信用卡上显示订阅费用 |
| **确认羞辱** |让用户感到内疚并选择加入 | “不，谢谢，我不想省钱”|
| **隐藏设置** |隐藏在菜单深处的隐私控制|选择退出隐藏在 5 级设置下 |

## 数据的偏差和公平性
|偏见的来源|描述 |示例|
|----------------|-------------|---------|
| **选择偏差** |数据不代表目标人群|仅根据某一人群的数据训练招聘模型 |
| **历史偏见** |过去的歧视被编码在数据中|逮捕记录反映了有偏见的警务做法|
| **测量偏差** |用作代理的变量是有缺陷的 |使用邮政编码作为信用度的代理 |
| **聚合偏差** |将不同群体视为同质群体 |一种模式适用于所有种族；忽略特定于组的模式 |
| **幸存者偏差** |只看成功案例|研究成功的初创企业，而忽略失败的初创企业 |
### 缓解策略
|战略|描述 |
|----------|-------------|
| **多样化的数据收集** |确保培训数据代表所有受影响群体 |
| **偏差审计** |定期测试模型对不同群体的不同影响 |
| **公平指标** |衡量人口平等、机会均等、赔率均等 |
| **人工审核** |让人类审查高风险决策 |
| **透明度报告** |发布有关跨人口统计模型性能的数据 |
| **社区参与** |让受影响社区参与设计和评估 |

## 数据治理
### 数据治理中的角色
|角色 |责任|
|------|----------------|
| **数据所有者** |负责数据领域的高级领导 |
| **数据管家** |日常管理；质量;分类 |
| **数据保护官 (DPO)** | GDPR 合规性；隐私影响评估；与监管机构联络|
| **数据工程师** |管道；贮存;转型|
| **数据科学家** |分析;造型;报告|
| **数据隐私分析师** |监控合规性；处理数据主体请求 |
### 数据分类
|分类|描述 |处理|
|----------------|-------------|----------|
| **公开** |可以自由分享|无限制 |
| **内部** |仅限员工 |访问控制；没有外部共享|
| **机密** |敏感商业数据 |加密;严格的访问控制；审计日志|
| **受限** |高度敏感；监管（PII、健康、金融）|静态和传输中加密；数据处理；最小访问权限 |
---

＃＃ 概括
数据道德和隐私不再是可选的考虑因素——它们是法律要求、商业要求和道德义务。 GDPR 和类似法规制定了明确的规则：最少收集、透明使用、严格保护并赋予用户控制权。差分隐私、联合学习和加密等隐私保护技术使得在不暴露个人身份的情况下从数据中获取价值成为可能。但仅靠技术还不够。组织需要数据治理结构、偏见审计实践以及将个人数据视为需要管理而不仅仅是被利用的文化。做到这一点的公司将赢得信任；那些不这样做的公司将面临监管罚款、公众强烈反对，以及用户共享数据意愿的缓慢侵蚀。
