# أنظمة قواعد البيانات

## أساسيات قواعد البيانات

### ما هي قاعدة البيانات؟
قاعدة البيانات هي مجموعة منظمة من المعلومات المهيكلة المخزنة إلكترونيًا، مصممة لاسترجاع البيانات وإدراجها وتحديثها وحذفها بكفاءة.

### أنظمة إدارة قواعد البيانات (DBMS)
برمجيات تتفاعل مع المستخدمين النهائيين والتطبيقات وقاعدة البيانات نفسها لالتقاط البيانات وتحليلها. أمثلة: MySQL، PostgreSQL، Oracle، MongoDB.

### المفاهيم الأساسية
- **المخطط (Schema)**: هيكل/تنظيم قاعدة البيانات (الجداول، الحقول، العلاقات)
- **النسخة (Instance)**: البيانات الفعلية المخزنة في لحظة معينة
- **خصائص ACID**: الذرية (Atomicity)، الاتساق (Consistency)، العزل (Isolation)، الديمومة (Durability)
- **نظرية CAP**: الاتساق، التوافر، تحمّل التجزئة (اختر اثنتين)
- **التطبيع (Normalization)**: تنظيم البيانات لتقليل التكرار
- **إلغاء التطبيع (Denormalization)**: إضافة تكرار لتحسين أداء القراءة

## قواعد البيانات العلائقية (SQL)

### المفاهيم الأساسية
- **الجداول**: الصفوف (السجلات) والأعمدة (الحقول)
- **المفتاح الأساسي**: معرّف فريد لكل صف
- **المفتاح الخارجي**: إشارة إلى المفتاح الأساسي في جدول آخر
- **الفهارس (Indexes)**: هياكل بيانات تحسّن سرعة الاستعلام
- **العروض (Views)**: جداول افتراضية مبنية على نتائج الاستعلام
- **الإجراءات المخزنة (Stored Procedures)**: كتل شفرة SQL مُجمّعة مسبقًا
- **المُشغّلات (Triggers)**: إجراءات تلقائية عند تغييرات البيانات

### عمليات SQL (CRUD)
```sql
-- إنشاء
INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com');

-- قراءة
SELECT * FROM users WHERE id = 1;
SELECT name, email FROM users ORDER BY name LIMIT 10;

-- تحديث
UPDATE users SET email = 'new@example.com' WHERE id = 1;

-- حذف
DELETE FROM users WHERE id = 1;
```

### عمليات الربط (Joins)
- **INNER JOIN**: يعيد الصفوف المتطابقة من كلا الجدولين
- **LEFT JOIN**: جميع صفوف الجدول الأيسر، مع المطابقات من الأيمن
- **RIGHT JOIN**: جميع صفوف الجدول الأيمن، مع المطابقات من الأيسر
- **FULL OUTER JOIN**: جميع صفوف كلا الجدولين
- **CROSS JOIN**: الضرب الديكارتي لكلا الجدولين
- **SELF JOIN**: ربط الجدول مع نفسه

### صور التطبيع (Normalization Forms)
- **1NF**: قيم ذرية، لا مجموعات متكررة
- **2NF**: 1NF + لا اعتماديات جزئية (جميع الصفات غير الأساسية تعتمد على المفتاح الأساسي بالكامل)
- **3NF**: 2NF + لا اعتماديات انتقالية (الصفات غير الأساسية لا تعتمد على صفات أخرى غير أساسية)
- **BCNF**: صيغة أقوى من 3NF، كل محدّد هو مفتاح مرشح
- **4NF**: لا اعتماديات متعددة القيم
- **5NF**: لا اعتماديات ربط

### أنظمة إدارة قواعد البيانات العلائقية الشائعة
- **PostgreSQL**: ميزات متقدمة، قابل للتوسيع، متوافق مع ACID
- **MySQL**: واسع الاستخدام، قراءات سريعة، تطبيقات الويب
- **Oracle**: ميزات مؤسسية، قابلية التوسع، مكلف
- **SQL Server**: منظومة مايكروسوفت، أدوات متكاملة
- **SQLite**: مضمّن، بدون خادم، خفيف الوزن
- **MariaDB**: نسخة متفرعة من MySQL، مفتوحة المصدر

## قواعد بيانات NoSQL

### أنواع قواعد بيانات NoSQL

#### مخازن المستندات
- **الهيكل**: مستندات شبيهة بـ JSON (BSON)
- **حالات الاستخدام**: إدارة المحتوى، الكتالوجات، ملفات تعريف المستخدمين
- **أمثلة**: MongoDB، CouchDB، DocumentDB
- **مثال استعلام** (MongoDB):
```javascript
db.users.find({ age: { $gt: 25 } }).sort({ name: 1 });
```

#### مخازن المفتاح-القيمة
- **الهيكل**: أزواج بسيطة من المفتاح والقيمة
- **حالات الاستخدام**: التخزين المؤقت، الجلسات، عربات التسوق
- **أمثلة**: Redis، DynamoDB، Riak
- **الخصائص**: سريعة، بسيطة، استعلام محدود

#### مخازن العائلة العمودية (Column-Family)
- **الهيكل**: أعمدة مجمّعة في عائلات
- **حالات الاستخدام**: البيانات الضخمة، التحليلات، السلاسل الزمنية
- **أمثلة**: Cassandra، HBase، ScyllaDB
- **الخصائص**: محسّنة للكتابة، موزعة، قابلة للتوسع

#### قواعد بيانات الرسوم البيانية
- **الهيكل**: عقد، حواف، خصائص
- **حالات الاستخدام**: الشبكات الاجتماعية، كشف الاحتيال، التوصيات
- **أمثلة**: Neo4j، Amazon Neptune، ArangoDB
- **لغة الاستعلام**: Cypher (Neo4j)، Gremlin

### متى تُستخدم NoSQL
- مخطط مرن/متطور
- متطلبات التوسع الأفقي
- إنتاجية كتابة عالية
- بيانات هرمية/متداخلة
- أنظمة موزعة
- تطبيقات فورية

## تصميم قواعد البيانات

### نمذجة الكيان والعلاقة (ER Modeling)
- **الكيانات**: كائنات/مفاهيم (عميل، منتج، طلب)
- **الصفات**: خصائص الكيانات (الاسم، السعر، التاريخ)
- **العلاقات**: الروابط بين الكيانات (واحد لواحد، واحد لمتعدد، متعدد لمتعدد)
- **الترتيب (Cardinality)**: عدد النسخ في العلاقة

### أنماط تصميم المخطط
- **الوراثة أحادية الجدول**: جميع الأنواع في جدول واحد مع مميّز نوع
- **وراثة جدول الفئة**: جداول منفصلة للفئة الأساسية والفئات الفرعية
- **وراثة الجدول الملموس**: جدول منفصل لكل فئة ملموسة
- **جداول الربط (Junction Tables)**: حل علاقات متعدد لمتعدد
- **جداول التدقيق (Audit Tables)**: تتبع التغييرات (created_at، updated_at، deleted_at)

### استراتيجيات الفهرسة
- **B-Tree**: افتراضي، استعلامات نطاقية، الفرز
- **Hash**: عمليات بحث بالمطابقة الدقيقة
- **Bitmap**: أعمدة منخفضة التنوع (الجنس، الحالة)
- **النص الكامل (Full-Text)**: إمكانيات البحث النصي
- **المكاني (Spatial)**: بيانات جغرافية (GIS)
- **المركّب (Composite)**: عدة أعمدة مجتمعة
- **التغطية (Covering)**: يشمل جميع الأعمدة اللازمة للاستعلام

## تحسين الاستعلامات

### خطط التنفيذ
- فهم كيفية تنفيذ قاعدة البيانات للاستعلامات
- تحديد الاختناقات (المسح الكامل للجداول، الفهارس المفقودة)
- الأدوات: EXPLAIN، EXPLAIN ANALYZE

### تقنيات التحسين
- **استخدام الفهارس**: التأكد من أن الاستعلامات تستخدم الفهارس المناسبة
- **إعادة كتابة الاستعلامات**: تبسيط الاستعلامات المعقدة
- **تحسين الربط (Join)**: اختيار أنواع وترتيب الربط الصحيحة
- **التقسيم (Partitioning)**: تقسيم الجداول الكبيرة (نطاقي، هاش، قائمة)
- **العروض المادّية (Materialized Views)**: نتائج استعلام محسوبة مسبقًا
- **تخزين الاستعلامات مؤقتًا**: تخزين نتائج الاستعلامات المتكررة

### مشكلات الأداء الشائعة
- **مشكلة استعلام N+1**: جلب بيانات مرتبطة بشكل غير فعال
- **الفهارس المفقودة**: مسح كامل للجداول الكبيرة
- **الإفراط في الفهرسة**: كتابة بطيئة بسبب فهارس كثيرة جدًا
- **تنازع الأقفال (Lock Contention)**: معاملات تنتظر الأقفال
- **استعلامات غير فعالة**: SELECT *، عمليات ربط غير ضرورية

## المعاملات والتزامن

### مستويات عزل المعاملات
- **READ UNCOMMITTED**: أدنى مستوى عزل، قراءات قذرة ممكنة
- **READ COMMITTED**: البيانات الملتزم بها فقط مرئية (الافتراضي في معظم قواعد البيانات)
- **REPEATABLE READ**: نفس الاستعلام يعيد نفس النتائج ضمن المعاملة
- **SERIALIZABLE**: أعلى مستوى عزل، المعاملات تُنفذ تسلسليًا

### التحكم بالتزامن
- **القفل المتشائم (Pessimistic Locking)**: قفل الموارد قبل الوصول
- **القفل المتفائل (Optimistic Locking)**: التحقق من الإصدار قبل الالتزام
- **التحكم بالتزامن متعدد الإصدارات (MVCC)**: الاحتفاظ بإصدارات متعددة من الصفوف
- **القفل على مستوى الصف**: قفل صفوف محددة
- **القفل على مستوى الجدول**: قفل الجدول بأكمله

### الجمود (Deadlocks)
- اعتمادية دائرية حيث تنتظر المعاملات بعضها البعض
- الوقاية: ترتيب أقفال متسق، مهلات زمنية، اكتشاف الجمود
- الحل: إلغاء إحدى المعاملات

## التكرار والتوسع

### أنواع التكرار
- **رئيسي-تابع (Master-Slave)**: خادم أساسي واحد، عدة نسخ للقراءة
- **رئيسي-رئيسي (Master-Master)**: خوادم أساسية متعددة، تكرار ثنائي الاتجاه
- **متعدد الرئيسيات**: N خوادم أساسية، يلزم حل التعارضات
- **التكرار المتسلسل (Chain Replication)**: تكرار تسلسلي عبر العقد

### أساليب التوسع
- **التوسع الرأسي**: زيادة موارد الخادم (المعالج، الذاكرة، التخزين)
- **التوسع الأفقي**: إضافة المزيد من الخوادم (التجزئة، التقسيم)
- **نسخ القراءة**: تفريغ حركة مرور القراءة
- **التجزئة (Sharding)**: تقسيم البيانات عبر الخوادم حسب المفتاح/النطاق/الهاش
- **الفدرالية (Federation)**: التقسيم حسب الوظيفة/الخدمة

### نماذج الاتساق
- **الاتساق القوي**: جميع العقد ترى نفس البيانات في نفس الوقت
- **الاتساق النهائي (Eventual Consistency)**: العقد تتقارب مع الوقت
- **الاتساق السببي**: الحفاظ على علاقات السبب والنتيجة
- **قراءة كتاباتك الخاصة (Read-Your-Writes)**: يرى المستخدم تحديثاته الخاصة فورًا

## النسخ الاحتياطي والاسترداد

### استراتيجيات النسخ الاحتياطي
- **النسخ الاحتياطي الكامل**: نسخة كاملة من قاعدة البيانات
- **النسخ الاحتياطي التزايدي**: التغييرات منذ آخر نسخة احتياطية
- **النسخ الاحتياطي التفاضلي**: التغييرات منذ آخر نسخة احتياطية كاملة
- **الاسترداد إلى نقطة زمنية**: الاستعادة إلى لحظة محددة
- **النسخ الاحتياطي المستمر**: تكرار فوري إلى النسخة الاحتياطية

### إجراءات الاسترداد
- **هدف زمن الاسترداد (RTO)**: الحد الأقصى المقبول لوقت التوقف
- **هدف نقطة الاسترداد (RPO)**: الحد الأقصى المقبول لفقدان البيانات
- **خطة التعافي من الكوارث**: إجراءات موثّقة للأعطال
- **الاختبار**: تدريبات استرداد دورية

## الأمان

### التحكم بالوصول
- **المصادقة (Authentication)**: التحقق من هوية المستخدم
- **التفويض (Authorization)**: منح الصلاحيات (GRANT، REVOKE)
- **الأدوار**: صلاحيات مجمّعة لتسهيل الإدارة
- **مبدأ أقل امتياز**: الحد الأدنى الضروري من الوصول

### حماية البيانات
- **التشفير أثناء السكون**: تشفير البيانات المخزنة
- **التشفير أثناء النقل**: TLS/SSL للاتصالات
- **الإخفاء (Masking)**: إخفاء البيانات الحساسة في البيئات غير الإنتاجية
- **الترميز (Tokenization)**: استبدال البيانات الحساسة برموز

### الثغرات الشائعة
- **حقن SQL**: شفرة SQL خبيثة في مدخلات المستخدم
- **تصعيد الامتيازات**: الحصول على وصول غير مصرح به
- **تسجيل التدقيق**: تتبع جميع أنشطة قاعدة البيانات
- **الامتثال**: متطلبات GDPR، HIPAA، PCI-DSS

## تقنيات قواعد البيانات الحديثة

### قواعد البيانات السحابية
- **AWS**: RDS، Aurora، DynamoDB، Redshift
- **Google Cloud**: Cloud SQL، Spanner، Bigtable، Firestore
- **Azure**: SQL Database، Cosmos DB، Synapse
- **الفوائد**: خدمة مُدارة، توسع تلقائي، نسخ احتياطية مشمولة

### قواعد بيانات NewSQL
- تجمع بين اتساق SQL وقابلية توسع NoSQL
- **أمثلة**: CockroachDB، TiDB، YugabyteDB، Google Spanner
- **الميزات**: موزعة، معاملات ACID، توسع أفقي

### قواعد البيانات الزمنية (Time-Series)
- محسّنة للبيانات ذات الطابع الزمني
- **أمثلة**: InfluxDB، TimescaleDB، Prometheus
- **حالات الاستخدام**: إنترنت الأشياء، المراقبة، البيانات المالية

### قواعد البيانات المتجهية (Vector)
- تخزين واستعلام متجهات التضمين (embedding)
- **أمثلة**: Pinecone، Milvus، Weaviate، Qdrant
- **حالات الاستخدام**: البحث الدلالي، أنظمة التوصية، تطبيقات الذكاء الاصطناعي

### قواعد البيانات متعددة النماذج
- دعم نماذج بيانات متعددة في نظام واحد
- **أمثلة**: ArangoDB، OrientDB، Azure Cosmos DB
- **الفائدة**: المرونة دون الحاجة لقواعد بيانات متعددة

## أدوات ORM والوصول إلى البيانات

### الربط العلائقي الكائني (Object-Relational Mapping)
- **الغرض**: ربط جداول قاعدة البيانات بكائنات البرمجة
- **أدوات ORM الشائعة**:
  - بايثون: SQLAlchemy، Django ORM، Peewee
  - جافا سكريبت: Sequelize، Prisma، TypeORM
  - جافا: Hibernate، JPA
  - روبي: ActiveRecord
  - .NET: Entity Framework

### الفوائد
- التجريد عن SQL
- أمان الأنواع (Type safety)
- إدارة الترحيلات (Migrations)
- واجهات برمجة بناء الاستعلامات

### العيوب
- عبء أداء إضافي
- الاستعلامات المعقدة أصعب في الكتابة
- مشكلات استعلام N+1
- منحنى تعلّم

## إدارة قواعد البيانات

### مسؤوليات مدير قاعدة البيانات (DBA)
- التثبيت والإعداد
- ضبط الأداء
- النسخ الاحتياطي والاسترداد
- إدارة الأمان
- تخطيط السعة
- المراقبة والتنبيه
- إدارة التحديثات

### مقاييس المراقبة
- زمن استجابة الاستعلام
- الإنتاجية (المعاملات في الثانية)
- عدد الاتصالات
- نسبة إصابة التخزين المؤقت (Cache hit ratio)
- إدخال/إخراج القرص
- زمن انتظار القفل
- تأخر التكرار (Replication lag)

### مهام الصيانة
- **Vacuum/Analyze**: تحديث الإحصائيات، استعادة المساحة
- **إعادة بناء الفهارس**: إزالة تجزؤ الفهارس
- **تحديثات الإحصائيات**: إبقاء محسّن الاستعلامات على اطلاع
- **تدوير السجلات**: إدارة أحجام ملفات السجل
- **تخطيط السعة**: توقع النمو، التخطيط للترقيات
