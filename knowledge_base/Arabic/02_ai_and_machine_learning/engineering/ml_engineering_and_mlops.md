# هندسة ML وMLOps
إن بناء نموذج للتعلم الآلي هو نصف المعركة فقط. إدخاله في الإنتاج، والحفاظ على تشغيله بشكل موثوق، ومراقبة الانجراف، والتكرار عليه - وهنا يأتي دور هندسة ML وMLOps. يغطي هذا الملف دورة الحياة الكاملة من التجربة إلى نظام الإنتاج.
---

## دورة حياة تعلم الآلة
| المرحلة | الوصف | الأنشطة الرئيسية |
|-------|------------|---------------|
| **1. تعريف المشكلة** | قم بتأطير مشكلة العمل كمهمة ML | تحديد المقاييس والقيود ومعايير النجاح |
| **2. جمع البيانات** | جمع وتسمية بيانات التدريب | ETL، وضع العلامات، التعزيز |
| **3. التجريب ** | تدريب وتقييم النماذج | هندسة الميزات، ضبط المعلمات الفائقة |
| **4. اختيار النموذج** | اختر الموديل الأفضل | قارن المقاييس، وقم بتقييم المفاضلات |
| **5. النشر** | شحن النموذج إلى الإنتاج | خدمة البنية التحتية، API، دفعة |
| **6. الرصد** | انتبه للانجراف والتدهور | انجراف البيانات، انجراف المفهوم، الأداء |
| **7. إعادة التدريب** | تحديث النموذج ببيانات جديدة | إعادة التدريب المجدولة أو المحفزة |
معظم القيمة (والصعوبة) موجودة في المراحل 5-7. النموذج الموجود في دفتر Jupyter لا يخلق قيمة تجارية.

## السجلات النموذجية
سجل النموذج هو مخزن مركزي لإدارة نماذج ML - إصداراتها وبياناتها التعريفية ومقاييسها وحالة النشر الخاصة بها.
| القدرة | الوصف |
|-----------|------------|
| **الإصدار** | تتبع كل إصدار نموذج بمعرف فريد |
| ** البيانات الوصفية ** | بيانات التدريب، المعلمات الفائقة، المقاييس، المؤلف |
| **انتقالات المرحلة** | نقل النماذج عبر المراحل: التدريج → الإنتاج → المؤرشفة |
| **النسب** | تتبع البيانات والكود الذي أنتج كل نموذج |
| أداة | الوصف |
|------|------------|
| **MLflow** | مفتوح المصدر؛ تسجيل النموذج + تتبع التجربة |
| **الأوزان والتحيزات (W&B)** | تجاري؛ تتبع التجربة + تسجيل النموذج |
| **دي في سي** | إصدار البيانات والنماذج باستخدام Git |
| **Azure ML / SageMaker** | إدارة النماذج السحابية الأصلية |

## تتبع التجربة
يجب تتبع كل تجربة تعلم الآلة: ما هي البيانات المستخدمة، وما هي المعلمات الفائقة، وما هي المقاييس الناتجة.
| أداة | الميزات الرئيسية |
|------|------------|
| **MLflow** | مفتوح المصدر، مستضاف ذاتيًا، يتتبع المعلمات/المقاييس/العناصر |
| **W&B** | واجهة مستخدم غنية، وعمليات مسح، وإصدارات مصطنعة، وتقارير |
| **نبتون** | مخزن البيانات الوصفية لـ MLOps |
| ** TensorBoard ** | مدمج في TensorFlow؛ تصور منحنيات التدريب |
### ما يجب تتبعه
| الفئة | أمثلة |
|----------|--------|
| **المعلمات** | معدل التعلم، حجم الدفعة، بنية النموذج، عدد العصور |
| **المقاييس** | الدقة، الخسارة، F1، AUC-ROC (لكل عصر ونهائي) |
| **التحف** | الأوزان النموذجية، مصفوفات الارتباك، عينات التنبؤ |
| **البيانات** | إصدار مجموعة البيانات، النسب المقسمة، خطوات المعالجة المسبقة |
| **البيئة** | نسخة بايثون، إصدارات المكتبة، الأجهزة |

## استراتيجيات نشر النماذج
| استراتيجية | كيف يعمل | خطر |
|----------|------------|------|
| **نشر الظل** | النموذج الجديد يسير جنبا إلى جنب مع القديم. التوقعات مقارنة ولكن لم يتم تقديمها | صفر خطر؛ التحقق قبل البث المباشر |
| **إصدار الكناري** | توجيه نسبة صغيرة من حركة المرور إلى النموذج الجديد؛ زيادة تدريجيا | مخاطر منخفضة التراجع السريع |
| **اختبار أ/ب** | تقسيم المستخدمين بين القدامى والجدد؛ مقارنة مقاييس الأعمال | يقيس التأثير الفعلي |
| **أزرق-أخضر** | بيئتان متطابقتان؛ تبديل كل حركة المرور مرة واحدة | التراجع الفوري؛ تكلفة مضاعفة أثناء الفترة الانتقالية |
| **أعلام الميزات** | تبديل تشغيل/إيقاف النموذج لكل شريحة مستخدم | تحكم دقيق |

## مراقبة أنظمة تعلم الآلة
تحتاج أنظمة تعلم الآلة إلى مراقبة أكثر من البرامج التقليدية لأن البيانات نفسها يمكن أن تتغير.
### أنواع الانجراف
| نوع الانجراف | ما الذي يتغير | مثال |
|-----------|-------------|---------|
| ** انجراف البيانات ** | تغييرات توزيع المدخلات | تتحول التركيبة السكانية للعملاء بعد حملة تسويقية |
| ** مفهوم الانجراف ** | العلاقة بين تغيرات المدخلات والمخرجات | يتغير سلوك المستهلك خلال فترة الركود |
| **انجراف التسمية** | تغييرات التوزيع المستهدف | نسبة الاحتيال ترتفع من 1% إلى 5% |
### ما يجب مراقبته
| الفئة | المقاييس |
|----------|--------|
| **أداء النموذج** | الدقة، الدقة، الاستدعاء، F1، AUC (مقارنة بخط الأساس) |
| **جودة البيانات** | القيم المفقودة، توزيعات الميزات، القيم المتطرفة |
| ** كشف الانجراف ** | الاختبارات الإحصائية (اختبار KS، PSI، تباعد KL) |
| **البنية التحتية** | الكمون، الإنتاجية، استخدام GPU، الذاكرة |
| **مقاييس الأعمال** | معدل التحويل، تأثير الإيرادات، رضا المستخدم |
### أدوات المراقبة
| أداة | اكتب |
|------|------|
| **من الواضح أن الذكاء الاصطناعي** | انجراف البيانات مفتوحة المصدر ومراقبة أداء النموذج |
| **جرافانا** | تصور لوحة المعلومات (يعمل مع بروميثيوس) |
| **لماذا لابس** | منصة مراقبة البيانات |
| **أريز** | إمكانية ملاحظة ML وتحليل السبب الجذري |
| **بروميثيوس + جرافانا** | البنية التحتية ومقاييس التطبيق |

## التدريب القابل للتكرار
تعني إمكانية تكرار النتائج أنه يمكنك إعادة إجراء التجربة والحصول على نفس النتيجة. إنه ضروري لتصحيح الأخطاء والتدقيق والامتثال.
### متطلبات
| المتطلبات | كيفية تحقيق ذلك |
|-------------|------------------|
| **إصدار البيانات** | DVC أو Delta Lake أو لقطات مجموعة البيانات ذات التجزئة |
| **إصدار الكود** | بوابة لجميع كود التدريب |
| **تثبيت البيئة** |  صور`requirements.txt`و`conda env`و Docker مع الإصدارات الدقيقة |
| **إعداد البذور** | إصلاح البذور العشوائية لـ numpy، torch، Tensorflow |
| **إدارة التكوين** | تكوينات Hydra أو OmegaConf أو YAML لجميع المعلمات الفائقة |
| **تتبع القطع الأثرية** | MLflow أو W&B لتسجيل كل تجربة |

## قياس الاستدلال
عندما يحتاج النموذج إلى خدمة ملايين الطلبات يوميًا، يكون الأداء مهمًا.
| تقنية | الوصف |
|-----------|------------|
| **الدفعة** | قم بتجميع طلبات متعددة في تمرير أمامي واحد |
| **التكميم** | قم بتقليل دقة النموذج (FP32 → INT8 أو INT4) لاستدلال أسرع |
| **التقطير النموذجي** | تدريب نموذج أصغر لتقليد نموذج أكبر |
| ** التقليم ** | إزالة الأوزان أو الخلايا العصبية غير المهمة |
| ** التخزين المؤقت ** | قم بتخزين التنبؤات المتكررة لتجنب إعادة الحساب |
| ** تحسين وحدة معالجة الرسومات ** | TensorRT، وقت تشغيل ONNX، Flash Attention |
| **التحجيم الأفقي** | تشغيل نسخ متماثلة متعددة للنماذج خلف موازن التحميل |

## أعلام الميزات لتعلم الآلة
تتيح لك علامات الميزات التحكم في إصدار النموذج الذي يخدم أي مستخدمين، دون إعادة النشر.
| حالة الاستخدام | الوصف |
|----------|------------|
| **طرح تدريجي** | عرض النموذج الجديد على 5% من المستخدمين، ثم زيادة |
| ** مفتاح القتل ** | يمكنك الرجوع فورًا إلى النموذج السابق في حالة اكتشاف مشكلات |
| ** على أساس القطاع ** | نماذج مختلفة لمختلف شرائح المستخدمين |
| **التجريب** | متغيرات نماذج اختبار A/B مع مقاييس الأعمال |
الأدوات: LaunchDarkly، أو Unleash، أو Flagsmith، أو علامات الميزات البسيطة المدعومة بقاعدة البيانات.

|-------|----------------|
| **المستوى 0 — اليدوي** | تدريب يدوي، نشر يدوي، بدون مراقبة |
| **المستوى الأول — التجريب** | تتبع التجارب، وتسجيل النماذج، وCI الأساسي |
