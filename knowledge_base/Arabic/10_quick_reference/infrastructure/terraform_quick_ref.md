# Terraform والبنية التحتية كرمز
Terraform هي أداة البنية الأساسية كرمز (IaC) الأكثر استخدامًا - فهي تتيح لك تحديد البنية التحتية السحابية (الخوادم وقواعد البيانات والشبكات والأذونات) في ملفات التكوين التعريفية التي يمكن إصدارها ومراجعتها واختبارها وأتمتتها. بدلاً من النقر فوق وحدة التحكم السحابية، يمكنك كتابة تعليمات برمجية تصف الحالة المطلوبة للبنية الأساسية لديك، وتكتشف Terraform التغييرات التي يجب إجراؤها.
---

## المفاهيم الأساسية
| المفهوم | الوصف |
|---------|------------|
| **المزود** | مكون إضافي يدير نظامًا أساسيًا سحابيًا محددًا (AWS، وAzure، وGCP، وما إلى ذلك) |
| **المصدر** | كائن البنية التحتية (الخادم، قاعدة البيانات، الشبكة) |
| **الدولة** | سجل Terraform للبنية التحتية الموجودة؛ مخزنة في ملف حالة |
| **الخطة** | معاينة التغييرات التي ستجريها Terraform |
| **تطبيق** | تنفيذ الخطة؛ إنشاء/تحديث/تدمير البنية التحتية |
| **الوحدة** | مجموعة قابلة لإعادة الاستخدام من الموارد |
| **متغير** | معلمة الإدخال للتكوينات |
| **الإخراج** | القيمة المصدرة من الوحدة النمطية أو التكوين |
| ** مصدر البيانات ** | قراءة المعلومات من البنية التحتية الموجودة |
---

## سير العمل الأساسي
| خطوة | الأمر | الوصف |
|------|---------|-------------|
| **1. كتابة التكوين** | قم بإنشاء ملفات`.tf`| تحديد مقدمي الخدمات والموارد والمتغيرات |
| **2. التهيئة** |  `terraform init` | مقدمي التنزيل؛ إعداد الواجهة الخلفية |
| **3. التنسيق** |  `terraform fmt` | توحيد التنسيق |
| **4. التحقق من صحة** |  `terraform validate` | تحقق من بناء الجملة والتكوين |
| **5. الخطة** |  `terraform plan` | معاينة التغييرات (التشغيل الجاف) |
| **6. قدم** |  `terraform apply` | إنشاء أو تحديث البنية التحتية |
| **7. تدمير ** |  `terraform destroy` | هدم كافة البنية التحتية المدارة |
---

## الأوامر المشتركة
| الأمر | الوصف |
|---------|------------|
|  `terraform init` | تهيئة دليل العمل؛ تنزيل موفري الوحدات والوحدات |
|  `terraform plan` | أظهر التغييرات التي سيتم إجراؤها |
|  `terraform apply` | تطبيق التغييرات؛ أضف `-auto-approve` لتخطي التأكيد |
|  `terraform destroy` | تدمير كافة الموارد المدارة |
|  `terraform fmt` | تنسيق ملفات التكوين إلى النمط القياسي |
|  `terraform validate` | التحقق من صحة صيغة التكوين |
|  `terraform output` | إظهار قيم الإخراج |
|  `terraform state list` | قائمة بجميع الموارد في الدولة |
|  `terraform state show <resource>` | عرض تفاصيل مورد محدد |
|  `terraform import <resource> <id>` | استيراد البنية التحتية الحالية إلى الحالة |
|  `terraform taint <resource>` | قم بوضع علامة على المورد للترفيه في التطبيق التالي |
|  `terraform refresh` | تحديث الحالة لتتناسب مع البنية التحتية الحقيقية |
|  `terraform graph` | إنشاء رسم بياني تبعية مرئي (تنسيق DOT) |
|  `terraform console` | وحدة تحكم تفاعلية لاختبار التعابير |
---

## إدارة الدولة
| أفضل الممارسات | الوصف |
|--------------|-------------|
| **الحالة البعيدة** | حالة المتجر في S3 أو GCS أو Azure Blob أو Terraform Cloud - ليس محليًا أبدًا |
| ** قفل الحالة ** | استخدم DynamoDB (الواجهة الخلفية S3) أو القفل الأصلي لمنع التعديلات المتزامنة |
| **تشفير الحالة** | تمكين التشفير غير النشط لملفات الحالة (التي تحتوي على بيانات حساسة) |
| **فصل الدولة** | استخدم ملفات حالة منفصلة لبيئات أو فرق مختلفة |
| **النسخة الاحتياطية للدولة** | حالة الإصدار للواجهات الخلفية البعيدة تلقائيًا؛ إبقاء هذا ممكنا |
| **لا تقم أبدًا بتحرير الحالة يدويًا** | استخدم`terraform state mv`,`rm`,`import`بدلاً من ذلك |

## استكشاف الأخطاء وإصلاحها
| مشكلة | الحل |
|---------|---------|
| **انجراف الدولة** | قم بتشغيل`terraform plan`لرؤية الاختلافات؛  `terraform plan` للتوفيق |
| **حالة القفل** | تحقق من لديه القفل؛ استخدم`terraform force-unlock`إذا كان آمنًا |
| **أخطاء الموفر** | التحقق من أوراق الاعتماد. تحديث إصدار الموفر؛ تحقق من حدود API |
| **تعارضات الاستيراد** | المورد موجود بالفعل؛ استخدم`terraform state rm`أولاً |
| **التبعيات الدائرية** | إعادة هيكلة الموارد؛ استخدم`depends_on`بعناية |
| **دولة كبيرة** | مقسمة إلى وحدات؛ استخدم`-target`للعمليات الجزئية |
---

## ملخص
يدير Terraform البنية التحتية من خلال ملفات التكوين التعريفية. سير العمل هو: كتابة التكوين → الحرف الأول → الخطة → تطبيق. تتتبع الحالة ما هو موجود ويجب تخزينه عن بعد مع القفل. تتيح الوحدات إمكانية إعادة الاستخدام. المتغيرات تحدد التكوينات. المبادئ الأساسية هي: التعامل مع البنية التحتية باعتبارها تعليمات برمجية (التحكم في الإصدار؛ المراجعة؛ الاختبار)؛ لا تقم مطلقًا بتحرير الحالة يدويًا؛ التخطيط قبل التقديم؛ استخدام الحالة البعيدة مع القفل؛ وتكوينات الهيكل مع وحدات للصيانة.
