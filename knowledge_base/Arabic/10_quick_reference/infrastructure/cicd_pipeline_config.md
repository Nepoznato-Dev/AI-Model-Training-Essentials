# تكوين خط أنابيب CI/CD
تعمل مسارات التكامل المستمر (CI) والنشر المستمر (CD) على أتمتة عملية إنشاء البرامج واختبارها ونشرها. يغطي هذا المرجع أنماط التكوين لمنصات CI/CD الأكثر شيوعًا: GitHub Actions وGitLab CI ومبادئ تصميم خطوط الأنابيب العامة.
---

## إجراءات جيثب
### هيكل سير العمل
```yaml
name: CI Pipeline
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up language
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - name: Install dependencies
        run: pip install -r requirements.txt
      - name: Run tests
        run: pytest
      - name: Build
        run: python setup.py build
```

### المحفزات الشائعة
| الزناد | الوصف |
|---------|------------|
| `on: push`| في كل دفعة |
| `on: pull_request`| على العلاقات العامة فتح، تحديث، إعادة فتح |
| `on: schedule`| الجدول الزمني القائم على كرون |
| `on: workflow_dispatch`| الزناد اليدوي |
| `on: release`| عند إنشاء الإصدار |
| `on: workflow_call`| يتم استدعاؤه بواسطة سير عمل آخر (قابل لإعادة الاستخدام) |
### الميزات الرئيسية
| ميزة | الوصف |
|---------|------------|
| **استراتيجية المصفوفة** | قم بتشغيل نفس المهمة بتكوينات مختلفة |
| **أسرار** | متغيرات البيئة المشفرة (`${{ secrets.MY_SECRET }}`) |
| **البيئات** | أهداف النشر مع قواعد الحماية |
| ** التخزين المؤقت ** | تبعيات ذاكرة التخزين المؤقت بين عمليات التشغيل |
| **التحف** | تحميل الملفات من الوظائف (تقارير الاختبار، الإصدارات) |
| ** سير العمل القابل لإعادة الاستخدام ** | مشاركة منطق سير العمل عبر المستودعات |
| **الأفعال المركبة** | دمج خطوات متعددة في إجراء واحد |
### استراتيجية المصفوفة
```yaml
jobs:
  test:
    strategy:
      matrix:
        python-version: ['3.10', '3.11', '3.12']
        os: [ubuntu-latest, macos-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
```

## جيتلاب سي آي
### هيكل خطوط الأنابيب
```yaml
stages:
  - build
  - test
  - deploy

build:
  stage: build
  script:
    - docker build -t myapp:$CI_COMMIT_SHA .
    - docker push myapp:$CI_COMMIT_SHA

test:
  stage: test
  script:
    - docker run myapp:$CI_COMMIT_SHA pytest

deploy:
  stage: deploy
  script:
    - deploy.sh $CI_COMMIT_SHA
  only:
    - main
  when: manual
```

### الكلمات الرئيسية
| الكلمة المفتاحية | الوصف |
|---------|------------|
| `stages`| تعريف مراحل خط الأنابيب وترتيبها |
| `stage`| إسناد وظيفة إلى مرحلة |
| `script`| أوامر للتنفيذ |
| `before_script`| يتم تشغيل الأوامر قبل البرنامج النصي الرئيسي |
| `after_script`| يتم تشغيل الأوامر بعد البرنامج النصي الرئيسي (حتى في حالة الفشل) |
| `only / except`| التحكم عند تشغيل المهام (الفروع، العلامات) |
| `rules`| إصدار أكثر مرونة من فقط/باستثناء |
| `variables`| تعريف متغيرات CI/CD |
| `cache`| ملفات ذاكرة التخزين المؤقت بين خطوط الأنابيب التي يتم تشغيلها |
| `artifacts`| الملفات التي سيتم تمريرها بين الوظائف |
| `environment`| بيئة النشر |
| `when`| التحكم في تنفيذ المهمة (عند_النجاح، عند_الفشل، يدويًا، دائمًا) |
| `needs`| حدد تبعيات الوظيفة (وضع DAG) |
| `extends`| وراثة التكوين من وظيفة أخرى |
| `include`| استيراد ملفات YAML خارجية |
### المتغيرات المحددة مسبقًا
| متغير | الوصف |
|----------|------------|
| `$CI_COMMIT_SHA`| تجزئة الالتزام الحالية |
| `$CI_COMMIT_REF_NAME`| اسم الفرع أو العلامة |
| `$CI_PIPELINE_ID`| معرف خط الأنابيب |
| `$CI_JOB_ID`| معرف الوظيفة |
| `$CI_PROJECT_DIR`| المسار الكامل للمشروع |
| `$CI_REGISTRY`| عنوان URL لتسجيل الحاوية |
| `$CI_DEFAULT_BRANCH`| اسم الفرع الافتراضي |

## أنماط تصميم خطوط الأنابيب
### الأنماط الشائعة
| نمط | الوصف |
|---------|------------|
| ** البناء مرة واحدة، ونشر العديد ** | بناء قطعة أثرية مرة واحدة؛ نشر نفس الأداة في كل بيئة |
| **بوابات الشيكات** | الموافقة اليدوية قبل نشر الإنتاج |
| **أعلام الميزات** | النشر إلى الإنتاج مع الاختباء خلف علامة الميزة |
| **نشر الكناري** | النشر إلى نسبة صغيرة؛ شاشة؛ طرح |
| **النشر الأزرق والأخضر** | بيئتان متطابقتان؛ تبديل حركة المرور |
| **الاختبار الموازي** | قم بتشغيل مجموعات الاختبار بالتوازي لتقليل وقت خط الأنابيب |
| **الوبر أولا** | قم بتشغيل الفلتر قبل الاختبارات باهظة الثمن؛ تفشل بسرعة |
| **تبعيات ذاكرة التخزين المؤقت** | وحدات عقدة التخزين المؤقت، النقطة، Maven لتسريع عمليات الإنشاء |
### مراحل خطوط الأنابيب (نموذجية)
| المرحلة | الغرض |
|-------|---------|
| ** لينت ** | نمط الكود والتحليل الثابت |
| **بناء** | تجميع؛ باقة؛ إنشاء التحف |
| **اختبار الوحدة** | اختبارات سريعة لا تبعيات خارجية |
| **اختبار التكامل** | اختبارات مع قواعد البيانات. واجهات برمجة التطبيقات؛ خدمات خارجية |
| **الفحص الأمني** | نقاط الضعف في التبعية؛ المسح السري؛ ساست |
| **الباقة** | إنشاء صورة عامل الميناء؛ بناء التحف الإصدار |
| **نشر التدريج** | النشر في بيئة التدريج |
| **اختبار E2E** | اختبارات النظام الكاملة ضد التدريج |
| **نشر الإنتاج** | النشر إلى الإنتاج (يدويًا أو تلقائيًا) |
| **اختبار الدخان** | التحقق من صحة النشر |

## استراتيجيات التخزين المؤقت
| اللغة / الأداة | مسار ذاكرة التخزين المؤقت | مثال |
|----------------|----------|---------|
| ** بايثون (نقطة) ** | `~/.cache/pip`| `actions/cache`بمفتاح من تجزئة`requirements.txt`|
| **Node.js (npm)** | `~/.npm`| `actions/setup-node`مع التخزين المؤقت المدمج |
| **جافا (مافن)** | `~/.m2/repository`| ذاكرة التخزين المؤقت مع المفتاح من تجزئة`pom.xml`|
| ** جافا (جرادل) ** | `~/.gradle/caches`| ذاكرة التخزين المؤقت مع المفتاح من تجزئة`build.gradle`|
| **انطلق** | `~/go/pkg/mod`| ذاكرة التخزين المؤقت مع المفتاح من تجزئة`go.sum`|
| **الصدأ (البضائع)** | `~/.cargo/registry`| ذاكرة التخزين المؤقت مع المفتاح من تجزئة`Cargo.lock`|
| ** عامل الميناء ** | التخزين المؤقت لطبقة عامل الميناء | `docker/build-push-action`مع ذاكرة التخزين المؤقت من |

## استكشاف الأخطاء وإصلاحها
| مشكلة | الحل |
|---------|---------|
| **خط الأنابيب بطيء** | تبعيات ذاكرة التخزين المؤقت؛ موازنة الوظائف؛ استخدم صورًا أساسية أصغر |
| **أسرار غير متوفرة** | التحقق من الاسم السري. التحقق من نطاق البيئة؛ تحقق من قيود العلاقات العامة للشوكة |
| **القطعة الأثرية كبيرة جدًا** | استبعاد الملفات غير الضرورية؛ ضغط؛ استخدم فترة احتفاظ أقصر |
| **المصفوفة كبيرة جدًا** | تقليل المجموعات. استخدم`include`/`exclude`|
| **الاختبارات غير المستقرة** | اختبارات الحجر الصحي غير المستقرة؛ إصلاح السبب الجذري؛ أعد المحاولة باستخدام`retry:`|
| **تم رفض الإذن** | التحقق من نطاقات الرمز المميز؛ التحقق من أذونات العداء |

## ملخص
تعمل خطوط أنابيب CI/CD على أتمتة إنشاء البرامج واختبارها ونشرها. تستخدم إجراءات GitHub مسارات عمل YAML التي يتم تشغيلها بواسطة أحداث المستودع؛ يستخدم GitLab CI المراحل والوظائف بقواعد مرنة. تشمل الأنماط الرئيسية ما يلي: البناء بمجرد نشر العديد؛ فحص البوابة قبل الإنتاج؛ الوبر أولاً للحصول على ردود فعل سريعة؛ تبعيات ذاكرة التخزين المؤقت لتسريع عمليات الإنشاء؛ واختبارات موازية. تتقدم مراحل خطوط الأنابيب عادةً من الوبر → البناء → الاختبار → الأمان → الحزمة → النشر → اختبار الدخان. تختلف استراتيجيات التخزين المؤقت حسب اللغة ولكنها تتبع نفس المبدأ: أدلة تبعية ذاكرة التخزين المؤقت التي يتم ربطها بمفتاح تجزئات ملف القفل. الهدف هو تقديم تعليقات سريعة وموثوقة حول كل تغيير وعمليات نشر آمنة وقابلة للتكرار للإنتاج.
