## نموذج OSI (7 طبقات)
إطار مفاهيمي لفهم الاتصالات الشبكية.
| طبقة | الاسم | وظيفة | أمثلة على البروتوكولات |
|-------|------|----------|------------------|
| 7 | التطبيق | خدمات المستخدم النهائي | HTTP، HTTPS، FTP، SMTP، DNS، SSH |
| 6 | عرض | تنسيق البيانات، التشفير، الضغط | TLS، JPEG، ASCII |
| 5 | جلسة | إدارة الاتصال | نيت بيوس، آر بي سي |
| 4 | النقل | التسليم الشامل، تصحيح الأخطاء، التحكم في التدفق | تكب، أودب |
| 3 | الشبكة | التوجيه والعنونة | IP، ICMP، OSPF، BGP |
| 2 | رابط البيانات | التأطير، اكتشاف الأخطاء، عناوين MAC | إيثرنت، واي فاي، PPP |
| 1 | المادية | نقل البت الخام | كابلات إيثرنت، ألياف بصرية، موجات الراديو |
من الناحية العملية، يعد **نموذج TCP/IP** (أربع طبقات: الرابط والإنترنت والنقل والتطبيق) أكثر استخدامًا للإنترنت.

## عنونة IP
### IPv4
- عنوان 32 بت، مكتوب بأربعة ثمانيات:`192.168.1.1`
- الإجمالي: ~4.3 مليار عنوان (لكنها استنفدت عمليًا).
### IPv6
- عنوان 128 بت، مكتوب بالخط الست عشري:`2001:0db8:85a3:0000:0000:8a2e:0370:7334`
- الإجمالي: 2¹²⁸ عنوان (لا نهائي عمليًا).
### نطاقات IP الخاصة (RFC 1918)
هذه ليست قابلة للتوجيه على شبكة الإنترنت؛ المستخدمة داخل الشبكات المحلية:
-`10.0.0.0/8`(10.0.0.0 – 10.255.255.255)
-`172.16.0.0/12` (172.16.0.0 – 172.31.255.255)
-`192.168.0.0/16`(192.168.0.0 – 192.168.255.255)
### تدوين CIDR
`192.168.1.0/24`يعني أن أول 24 بت هي بادئة الشبكة؛ آخر 8 بتات هي المضيفين. ويتضمن العناوين من`192.168.1.0`إلى `192.168.1.255`.

## DNS (نظام اسم المجال)
تعيين أسماء النطاقات (على سبيل المثال،`example.com`) إلى عناوين IP.
### أنواع السجلات
| اكتب | الغرض |
|------|---------|
| **أ** | يعين المجال إلى عنوان IPv4 |
| **آآآ** | تعيين المجال إلى عنوان IPv6 |
| **CNAME** | الاسم المستعار لاسم مجال آخر |
| **مكس** | خادم تبادل البريد |
| **نص** | نص تعسفي (SPF، DKIM، التحقق) |
| **ن** | خادم الأسماء للمجال |
| **SRV** | سجل الخدمة (على سبيل المثال، SIP) |
### الأدوات المشتركة```bash
dig example.com            # DNS lookup (detailed)
nslookup example.com       # DNS lookup (simpler)
host example.com           # Quick lookup
dig -x 8.8.8.8             # Reverse lookup (IP to name)
```

## HTTP وHTTPS
### طرق HTTP
| الطريقة | الوصف |
|--------|------------|
| ** احصل على ** | استرداد مورد (عاجز، آمن) |
| ** مشاركة ** | إرسال البيانات (ليست عاجزة) |
| **ضع** | تحديث/استبدال مورد (عاجز) |
| **التصحيح** | تحديث جزئي |
| **حذف** | إزالة مورد (عاجز) |
### رموز الحالة
| الكود | معنى |
|------|---------|
| **1xx** | إعلامية (100 متابعة) |
| **2xx** | النجاح (200 موافق، 201 تم الإنشاء، 204 لا يوجد محتوى) |
| **3xx** | إعادة التوجيه (301 تم نقله بشكل دائم، 302 تم العثور عليه، 304 لم يتم تعديله) |
| **4xx** | خطأ العميل (400 طلب سيئ، 401 غير مصرح به، 403 محظور، 404 لم يتم العثور عليه، 429 طلبات كثيرة جدًا) |
| **5xx** | خطأ في الخادم (500 خطأ داخلي في الخادم، 502 بوابة سيئة، 503 الخدمة غير متوفرة) |
### رؤوس
| رأس | الغرض |
|--------|---------|
| `Content-Type`| نوع الوسائط (`application/json`,`text/html`) |
| `Authorization`| بيانات الاعتماد (على سبيل المثال،`Bearer <token>`) |
| `Cache-Control`| سياسة التخزين المؤقت |
| رؤوس CORS |  `Access-Control-Allow-Origin`، إلخ. |

## TLS/SSL
تشفير حركة مرور HTTP (HTTPS = HTTP عبر TLS).
- شهادات من المراجع المصدقة (CAs) تصادق على الخادم.
- التحقق من سلسلة الشهادة واسم المضيف من جانب العميل.

## جدران الحماية وNAT
### جدار الحماية
- يقوم بتصفية حركة المرور بناءً على القواعد (عنوان IP المصدر، وعنوان IP المقصود، والمنفذ، والبروتوكول).
- جدران الحماية ذات الحالة الخاصة تتعقب حالات الاتصال.
### NAT (ترجمة عنوان الشبكة)
- يترجم عناوين IP الخاصة إلى IP عام للوصول إلى الإنترنت.
- إعادة توجيه المنفذ: يقوم بتعيين منفذ عام إلى مضيف/منفذ داخلي.

## أوامر الشبكات الشائعة
### اختبارات الاتصال
```bash
ping google.com            # ICMP echo request
ping -c 4 8.8.8.8          # ping 4 times
traceroute google.com      # Trace the route (Linux)
tracert google.com         # Windows version
```

### التوجيه
```bash
ip route show              # Linux: routing table
route -n                   # Older Linux
netstat -r                 # Windows/Mac
```

### واجهات الشبكة
```bash
ip addr show               # List interfaces and IPs
ifconfig                   # Older command
```

### DNS
```bash
dig example.com
nslookup example.com
host example.com
```

### الاتصال بالمنفذ
```bash
nc -zv google.com 443      # Netcat: check if port 443 is open
telnet google.com 443      # Telnet to port
curl -v https://google.com # Verbose output
```

### جدار الحماية (Linux iptables/nftables)
```bash
sudo ufw status            # Ubuntu: simple firewall
sudo iptables -L -n        # List rules
```

### إحصائيات الشبكة
```bash
ss -tulpn                  # Show listening sockets (Linux)
netstat -an                # All sockets (all OS)
```

## قائمة التحقق من استكشاف الأخطاء وإصلاحها
1. هل الرابط المادي موجود؟ (تحقق من الكابلات، واتصال Wi-Fi).
2. هل يمكنك اختبار اتصال البوابة؟ (على سبيل المثال،`ping 192.168.1.1`).
3. هل يمكنك اختبار اتصال IP خارجي؟ (على سبيل المثال،`8.8.8.8`).
4. هل يمكنك حل المجال؟ (`dig google.com`).
5. هل يستمع التطبيق على المنفذ المتوقع؟ (`ss -tulpn | grep 8080`).
6. هل يقوم جدار الحماية بحظر المنفذ؟ (تحقق من`iptables`/`ufw`أو مجموعات الأمان السحابية).
7. هل هناك أي أخطاء في سجلات التطبيق؟
8. هل شهادة TLS صالحة وموثوقة؟ (`openssl s_client -connect example.com:443`).
