#أنظمة قواعد البيانات
## أساسيات قاعدة البيانات
### ما هي قاعدة البيانات؟
قاعدة البيانات عبارة عن مجموعة منظمة من المعلومات المنظمة المخزنة إلكترونيًا، والمصممة لاسترجاع البيانات وإدراجها وتحديثها وحذفها بكفاءة.
### أنظمة إدارة قواعد البيانات (DBMS)
برنامج يتفاعل مع المستخدمين النهائيين والتطبيقات وقاعدة البيانات نفسها لالتقاط البيانات وتحليلها. أمثلة: MySQL، PostgreSQL، Oracle، MongoDB.
### المفاهيم الأساسية
- **المخطط**: هيكل/تنظيم قاعدة البيانات (الجداول، الحقول، العلاقات)
- **المثيل**: البيانات الفعلية المخزنة في لحظة معينة
- **خصائص الحمض**: الذرية، الاتساق، العزلة، المتانة
- **نظرية CAP**: الاتساق، والتوافر، والتسامح مع القسم (اختر 2)
- **التطبيع**: تنظيم البيانات لتقليل التكرار
- **إلغاء التسوية**: إضافة التكرار لتحسين أداء القراءة
## قواعد البيانات العلائقية (SQL)
### المفاهيم الأساسية
- **الجداول**: الصفوف (السجلات) والأعمدة (الحقول)
- **المفتاح الأساسي**: معرف فريد لكل صف
- **المفتاح الخارجي**: إشارة إلى المفتاح الأساسي في جدول آخر
- **الفهارس**: تعمل هياكل البيانات على تحسين سرعة الاستعلام
- **المشاهدات**: جداول افتراضية تعتمد على نتائج الاستعلام
- **الإجراءات المخزنة**: كتل تعليمات SQL البرمجية المترجمة مسبقًا
- **المشغلات**: إجراءات تلقائية عند تغيير البيانات
### عمليات SQL (CRUD)```sql
-- Create
INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com');

-- Read
SELECT * FROM users WHERE id = 1;
SELECT name, email FROM users ORDER BY name LIMIT 10;

-- Update
UPDATE users SET email = 'new@example.com' WHERE id = 1;

-- Delete
DELETE FROM users WHERE id = 1;
```

### الانضمامات
- **INNER JOIN**: إرجاع الصفوف المتطابقة من كلا الجدولين
- **الانضمام الأيسر**: جميع الصفوف من الجدول الأيسر، تطابق من اليمين
- **الانضمام الأيمن**: جميع الصفوف من الجدول الأيمن، تطابق من اليسار
- **الانضمام الخارجي الكامل**: جميع الصفوف من كلا الجدولين
- **CROSS JOIN**: المنتج الديكارتي لكلا الجدولين
- **الانضمام الذاتي**: تم ربط الجدول بنفسه
### نماذج التطبيع
- **1NF**: القيم الذرية، لا توجد مجموعات متكررة
- **2NF**: 1NF + لا توجد تبعيات جزئية (جميع السمات غير الرئيسية تعتمد على المفتاح الأساسي بالكامل)
- **3NF**: 2NF + لا توجد تبعيات متعدية (السمات غير الرئيسية لا تعتمد على السمات غير الرئيسية الأخرى)
- **BCNF**: 3NF أقوى، كل محدد هو مفتاح مرشح
- **4NF**: لا توجد تبعيات متعددة القيم
- **5NF**: لا توجد تبعيات الانضمام
### نظام RDBMS الشهير
- **PostgreSQL**: ميزات متقدمة وقابلة للتوسيع ومتوافقة مع ACID
- **MySQL**: تطبيقات الويب واسعة الاستخدام وسريعة القراءة
- **Oracle**: ميزات مؤسسية، وقابلية للتوسع، ومكلفة
- **SQL Server**: نظام Microsoft البيئي، وأدوات متكاملة
- **SQLite**: مضمن، بدون خادم، وخفيف الوزن
- **MariaDB**: شوكة MySQL، مفتوحة المصدر
## قواعد بيانات NoSQL
### أنواع قواعد بيانات NoSQL
#### مخازن المستندات
- **الهيكل**: مستندات تشبه JSON (BSON)
- **حالات الاستخدام**: إدارة المحتوى، والكتالوجات، وملفات تعريف المستخدمين
- **أمثلة**: MongoDB، CouchDB، DocumentDB
- **مثال للاستعلام** (MongoDB):```javascript
db.users.find({ age: { $gt: 25 } }).sort({ name: 1 });
```

#### متاجر ذات قيمة أساسية
- **الهيكل**: أزواج بسيطة من المفاتيح والقيمة
- **حالات الاستخدام**: التخزين المؤقت، والجلسات، وعربات التسوق
- **أمثلة**: Redis، DynamoDB، Riak
- **الخصائص**: استعلام سريع وبسيط ومحدود
#### متاجر العمود العائلية
- **الهيكل**: الأعمدة مجمعة في عائلات
- **حالات الاستخدام**: البيانات الضخمة، والتحليلات، والسلاسل الزمنية
- **أمثلة**: Cassandra، HBase، ScyllaDB
- **الخصائص**: مُحسَّنة للكتابة، وموزعة، وقابلة للتطوير
#### قواعد بيانات الرسم البياني
- **الهيكل**: العقد، الحواف، الخصائص
- **حالات الاستخدام**: الشبكات الاجتماعية، كشف الاحتيال، التوصيات
- **أمثلة**: Neo4j، Amazon Neptune، ArangoDB
- **لغة الاستعلام**: سايفر (Neo4j)، جريملين
### متى تستخدم NoSQL
- مخطط مرن/متطور
- متطلبات القياس الأفقي
- إنتاجية كتابة عالية
- البيانات الهرمية/المتداخلة
- الأنظمة الموزعة
- تطبيقات في الوقت الحقيقي
## تصميم قاعدة البيانات
### نمذجة العلاقة بين الكيان
- **الكيانات**: الكائنات/المفاهيم (العميل، المنتج، الطلب)
- **السمات**: خصائص الكيانات (الاسم، السعر، التاريخ)
- **العلاقات**: الاتصالات بين الكيانات (واحد إلى واحد، واحد إلى متعدد، متعدد إلى متعدد)
- **الأصلية**: عدد الحالات في العلاقة
### أنماط تصميم المخطط
- **وراثة الجدول الواحد**: جميع الأنواع في جدول واحد مع أداة تمييز النوع
- ** وراثة جدول الفصل **: جداول منفصلة للفئات الأساسية والفرعية
- **وراثة الطاولة الخرسانية**: جدول منفصل لكل فئة خرسانية
- **جداول الوصلات**: حل علاقات متعدد إلى متعدد
- **جداول التدقيق**: تتبع التغييرات (created_at وupdate_at وdelete_at)
### استراتيجيات الفهرسة
- **B-Tree**: الافتراضي، استعلامات النطاق، الفرز
- **التجزئة**: عمليات البحث عن المطابقة التامة
- **صورة نقطية**: أعمدة ذات أصل منخفض (الجنس، الحالة)
- **النص الكامل**: إمكانيات البحث عن النص
- **المكانية**: البيانات الجغرافية (GIS)
- **مركب**: أعمدة متعددة مدمجة
- **التغطية**: تتضمن جميع الأعمدة المطلوبة للاستعلام
## تحسين الاستعلام
### خطط التنفيذ
- فهم كيفية تنفيذ قاعدة البيانات للاستعلامات
- تحديد الاختناقات (مسح الجدول الكامل والفهارس المفقودة)
- الأدوات: اشرح، اشرح وحلل
### تقنيات التحسين
- **استخدام الفهرس**: تأكد من أن الاستعلامات تستخدم الفهارس المناسبة
- **إعادة كتابة الاستعلام**: تبسيط الاستعلامات المعقدة
- **تحسين الانضمام**: اختر أنواع الانضمام الصحيحة وترتيبها
- **التقسيم**: تقسيم الجداول الكبيرة (النطاق، التجزئة، القائمة)
- **المشاهدات المادية**: نتائج الاستعلام المحسوبة مسبقًا
- **التخزين المؤقت للاستعلام**: تخزين نتائج الاستعلام المتكررة
### مشكلات الأداء الشائعة
- **مشكلة استعلام N+1**: جلب البيانات ذات الصلة بشكل غير فعال
- **الفهارس المفقودة**: يتم فحص الجدول بالكامل على الجداول الكبيرة
- **الإفراط في الفهرسة**: الكتابة بطيئة بسبب وجود عدد كبير جدًا من الفهارس
- **التنافس على القفل**: المعاملات التي تنتظر الأقفال
- **استعلامات غير فعالة**: SELECT *، عمليات ربط غير ضرورية
## المعاملات والتزامن
### مستويات عزل المعاملات
- **قراءة غير ملتزم بها**: أقل عزلة، وقراءات قذرة ممكنة
- **القراءة الملتزمة**: البيانات الملتزمة فقط هي المرئية (الافتراضي في معظم قواعد البيانات)
- **قراءة قابلة للتكرار**: نفس الاستعلام يُرجع نفس النتائج ضمن المعاملة
- **قابل للتسلسل**: أعلى مستوى من العزل، ويتم تنفيذ المعاملات بشكل تسلسلي
### التحكم في التزامن
- **القفل المتشائم**: قفل الموارد قبل الوصول إليها
- **القفل المتفائل**: التحقق من الإصدار قبل الالتزام
- **MVCC (التحكم في التزامن متعدد الإصدارات)**: الحفاظ على إصدارات متعددة من الصفوف
- **قفل على مستوى الصف**: قفل صفوف محددة
- **قفل على مستوى الجدول**: قفل الجدول بأكمله
### الجمود
- التبعية الدائرية حيث تنتظر المعاملات بعضها البعض
- الوقاية: ترتيب القفل المتسق، والمهلات، واكتشاف حالة الجمود
- الحل: إحباط معاملة واحدة
## النسخ والقياس
### أنواع النسخ
- **السيد والعبد**: نسخ متماثلة أساسية متعددة القراءة
- **ماجستير-ماجستير**: الانتخابات التمهيدية المتعددة، النسخ المتماثل ثنائي الاتجاه
- **متعدد التخصصات**: الانتخابات التمهيدية N، يلزم حل الصراع
- **النسخ المتماثل للسلسلة**: النسخ المتماثل المتسلسل عبر العقد
### نهج التوسع
- **القياس الرأسي**: زيادة موارد الخادم (وحدة المعالجة المركزية، ذاكرة الوصول العشوائي، التخزين)
- **القياس الأفقي**: إضافة المزيد من الخوادم (التقسيم والتقسيم)
- **قراءة النسخ المتماثلة**: إلغاء تحميل حركة مرور القراءة
- **التقسيم**: تقسيم البيانات عبر الخوادم حسب المفتاح/النطاق/التجزئة
- **الاتحاد**: مقسم حسب الوظيفة/الخدمة
### نماذج الاتساق
- **اتساق قوي**: ترى جميع العقد نفس البيانات في نفس الوقت
- **الاتساق النهائي**: تتقارب العقد بمرور الوقت
- **الاتساق السببي**: الحفاظ على العلاقات بين السبب والنتيجة
- **اقرأ ما تكتبه**: يرى المستخدم التحديثات الخاصة به على الفور
## النسخ الاحتياطي والاسترداد
### استراتيجيات النسخ الاحتياطي
- **النسخ الاحتياطي الكامل**: نسخة كاملة من قاعدة البيانات
- **النسخ الاحتياطي التزايدي**: التغييرات منذ آخر نسخة احتياطية
- **النسخ الاحتياطي التفاضلي**: التغييرات منذ آخر نسخة احتياطية كاملة
- **الاسترداد في نقطة زمنية**: استعادة إلى لحظة معينة
- ** النسخ الاحتياطي المستمر **: النسخ المتماثل للنسخ الاحتياطي في الوقت الحقيقي
### إجراءات الاسترداد
- **RTO (هدف وقت الاسترداد)**: الحد الأقصى لوقت التوقف المقبول
- **RPO (هدف نقطة الاسترداد)**: الحد الأقصى المقبول لفقدان البيانات
- **خطة التعافي من الكوارث**: إجراءات موثقة للفشل
- **الاختبار**: تدريبات التعافي المنتظمة
## حماية
### التحكم في الوصول
- **المصادقة**: التحقق من هوية المستخدم
- **التفويض**: منح الأذونات (منح، إلغاء)
- **الأدوار**: أذونات المجموعة لتسهيل الإدارة
- **مبدأ الامتياز الأقل**: الحد الأدنى من الوصول الضروري
### حماية البيانات
- **التشفير أثناء الراحة**: تشفير البيانات المخزنة
- **التشفير أثناء النقل**: TLS/SSL للاتصالات
- **الإخفاء**: إخفاء البيانات الحساسة في غير الإنتاج
- **الترميز**: استبدال البيانات الحساسة بالرموز المميزة
### نقاط الضعف الشائعة
- **حقن SQL**: SQL ضار في إدخال المستخدم
- **تصعيد الامتياز**: الحصول على وصول غير مصرح به
- **تسجيل التدقيق**: تتبع جميع أنشطة قاعدة البيانات
- **الامتثال**: متطلبات القانون العام لحماية البيانات (GDPR)، وقانون HIPAA، وPCI-DSS
## تقنيات قواعد البيانات الحديثة
### قواعد البيانات السحابية
- **AWS**: RDS، Aurora، DynamoDB، Redshift
- **Google Cloud**: Cloud SQL، وSpanner، وBigtable، وFirestore
- **Azure**: قاعدة بيانات SQL، وCosmos DB، وSynapse
- **الفوائد**: الخدمة المُدارة، والقياس التلقائي، والنسخ الاحتياطية متضمنة
### قواعد بيانات NewSQL
- الجمع بين تناسق SQL وقابلية التوسع NoSQL
- **أمثلة**: CockroachDB، وTiDB، وYugabyteDB، وGoogle Spanner
- **الميزات**: معاملات ACID الموزعة والقياس الأفقي
### قواعد بيانات السلاسل الزمنية
- الأمثل للبيانات ذات الطابع الزمني
- **أمثلة**: InfluxDB، TimescaleDB، Prometheus
- **حالات الاستخدام**: إنترنت الأشياء، والمراقبة، والبيانات المالية
### قواعد بيانات المتجهات
- تخزين ناقلات التضمين والاستعلام عنها
- **أمثلة**: Pinecone، Milvus، Weaviate، Qdrant
- **حالات الاستخدام**: البحث الدلالي، وأنظمة التوصية، وتطبيقات الذكاء الاصطناعي
### قواعد بيانات متعددة النماذج
- دعم نماذج بيانات متعددة في نظام واحد
- **أمثلة**: ArangoDB، وOrientDB، وAzure Cosmos DB
- **الفائدة**: المرونة بدون قواعد بيانات متعددة
