# موبائل ڈویلپمنٹ
موبائل ڈویلپمنٹ اسمارٹ فونز اور ٹیبلٹس کے لیے ایپلی کیشنز بنانے کا عمل ہے — بنیادی طور پر iOS (Apple) اور Android (Google) کے لیے۔ اس میں چھوٹی اسکرینوں کے لیے UI ڈیزائن سے لے کر بیٹری کی زندگی کو منظم کرنے، نیٹ ورک کے عدم استحکام سے نمٹنے، اور اسٹورز کے ذریعے ایپس کی تقسیم تک ہر چیز شامل ہے۔ میدان نمایاں طور پر پختہ ہو چکا ہے، کراس پلیٹ فارم فریم ورک اب زیادہ تر استعمال کے معاملات میں مقامی ترقی کے ساتھ مقابلہ کر رہے ہیں۔
---

## کراس پلیٹ فارم فریم ورک
ایک بار بنائیں، iOS اور Android دونوں پر تعینات کریں۔
| فریم ورک | زبان | رینڈرنگ | کارکردگی | کے لیے بہترین |
|------------|---------|------------|-------------|---------|
| ** پھڑپھڑاہٹ** | ڈارٹ | حسب ضرورت انجن (Skia/Impeller) | قریبی مقامی | بھرپور کسٹم UIs؛ پلیٹ فارمز میں مسلسل نظر |
| **آبائی ردعمل کا اظہار کریں** | JavaScript/TypeScript | پل کے ذریعے مقامی اجزاء | اچھا (نیا فن تعمیر اس کو بہتر بناتا ہے) | ویب/جے ایس تجربہ کے ساتھ ٹیمیں |
| **کوٹلن ملٹی پلیٹ فارم** | کوٹلن | مقامی UI فی پلیٹ فارم | مقامی | کاروباری منطق کا اشتراک؛ مقامی UI |
| **MAUI** (.NET) | C# | مقامی کنٹرولز | اچھا | .NET ٹیمیں؛ انٹرپرائز ایپس |
| **Ionic/ Capacitor** | HTML/CSS/JS | ویب ویو | زیریں | سادہ ایپس؛ ویب ٹیمیں |
### پھڑپھڑاہٹ بمقابلہ رد عمل مقامی
| پہلو | پھڑپھڑانا | مقامی رد عمل کا اظہار کریں |
|---------|---------|------------|
| **زبان** | ڈارٹ | JavaScript/TypeScript |
| **UI رینڈرنگ** | ہر چیز کو خود کھینچتا ہے (پلیٹ فارمز میں مستقل) | مقامی اجزاء کا استعمال کرتا ہے (پلیٹ فارم کی مخصوص شکل) |
| ** گرم دوبارہ لوڈ ** | بہترین | اچھا |
| **ماحولیاتی نظام** | تیزی سے بڑھتی ہوئی؛ ویجیٹ پر مبنی | بڑا npm ماحولیاتی نظام |
| **سیکھنے کا وکر** | ڈارٹ سیکھنے کی ضرورت ہے | ویب ڈویلپرز کے لیے آسان |
| **پلیٹ فارم انضمام** | مقامی کوڈ کے لیے پلیٹ فارم چینلز | پل کے ذریعے مقامی ماڈیول |
| **کارکردگی** | بہترین؛ قریبی مقامی | اچھا پل اوور ہیڈ (نئے فن تعمیر کے ساتھ کم کیا گیا) |

## موبائل آرکیٹیکچر پیٹرن
| پیٹرن | تفصیل | کب استعمال کریں |
|---------|------------|------------|
| **MVC** | ماڈل-ویو-کنٹرولر | سادہ ایپس؛ ویب ڈویلپرز سے واقف |

| **MVI** | ماڈل-دیکھنے کا ارادہ؛ یک سمتی ڈیٹا کا بہاؤ | پیچیدہ ریاستی انتظام؛ لہرانا (BLoC/Riverpod کے ساتھ) |
| **صاف فن تعمیر** | انحصار الٹ کے ساتھ پرتیں | بڑی ٹیمیں؛ پیچیدہ کاروباری منطق |

## موبائل کے اہم خدشات
### آف لائن-پہلا ڈیزائن
موبائل ایپس کو قابل اعتماد انٹرنیٹ کے بغیر کام کرنا چاہیے۔
| حکمت عملی | تفصیل |
|------------|---------------|
| **مقامی ڈیٹا بیس** | ڈیوائس پر ڈیٹا اسٹور کریں (SQLite, Room, CoreData, Realm) |
| **ہم آہنگی کی حکمت عملی** | آن لائن ہونے پر سرور کے ساتھ مطابقت پذیری کریں؛ تنازعات کو حل کریں |
| **پرامید UI** | UI کو فوری طور پر اپ ڈیٹ کریں؛ جب سرور جواب دیتا ہے تو صلح کریں |
| **کیشے** | کیشے API کے جوابات؛ آف لائن ہونے پر کیشے سے سرو کریں |
### کارکردگی
| تشویش | حل |
|---------|------------|
| **ایپ شروع ہونے کا وقت** | سست لوڈنگ؛ ابتدائی کام کو کم سے کم کریں |
| **میموری کا استعمال** | تصویر کمپریشن؛ میموری لیک سے بچیں؛ پروفائلنگ ٹولز کا استعمال کریں |
| **بیٹری ڈرین** | پس منظر کے کام کو کم کریں؛ بیچ نیٹ ورک کی درخواستیں؛ موثر مقام کی خدمات کا استعمال کریں |
| **نیٹ ورک کی کارکردگی** | پے لوڈز کو کمپریس کریں؛ صفحہ بندی کا استعمال کریں؛ جارحانہ طور پر کیشے |
| **فہرست سکرولنگ** | ری سائیکل مناظر؛ تصاویر کے لیے سست لوڈنگ کا استعمال کریں |
### سیکیورٹی
| تشویش | حل |
|---------|------------|
| **ڈیٹا باقی ** | حساس ڈیٹا کو خفیہ کریں (iOS پر Keychain، Android پر EncryptedSharedPreferences) |
| **نیٹ ورک** | ہمیشہ HTTPS؛ حساس ایپس کے لیے سرٹیفکیٹ پننگ |
| **توثیق** | بایومیٹرکس (چہرے کی شناخت، فنگر پرنٹ)؛ OAuth؛ ٹوکن اسٹوریج |
| **کوڈ کی الجھن** | ProGuard/R8 برائے Android؛ بٹ کوڈ برائے iOS |
| **جیل بریک/جڑ کا پتہ لگانا** | سمجھوتہ شدہ آلات کا پتہ لگائیں؛ فعالیت کو محدود کریں |

| **معطل** | OS نے وسائل کو بچانے کے لیے ایپ کو منجمد کر دیا ہے۔ کچھ نہیں؛ ایپ منجمد ہے |
| **ختم کر دیا گیا** | OS نے میموری کو آزاد کرنے کے لیے ایپ کو ختم کر دیا | اگلے لانچ پر حالت کو بحال کریں |

## خلاصہ
موبائل ڈویلپمنٹ مقامی (بہترین کارکردگی، پلیٹ فارم کے لیے مخصوص) اور کراس پلیٹ فارم (مشترکہ کوڈ بیس، تیز تر تکرار) کے درمیان انتخاب پیش کرتا ہے۔ پھڑپھڑانا اور رد عمل مقامی اس مقام پر پختہ ہو چکے ہیں جہاں زیادہ تر ایپلی کیشنز کے لیے کراس پلیٹ فارم صحیح انتخاب ہے۔ بنیادی چیلنجز فریم ورک سے قطع نظر ایک جیسے ہی رہتے ہیں: آف لائن فرسٹ ڈیزائن، محدود ہارڈ ویئر پر کارکردگی، بیٹری کی کارکردگی، غیر بھروسہ مند آلات پر سیکیورٹی، اور ایپ اسٹور کے جائزے کے عمل کو نیویگیٹ کرنا۔ فیلڈ ان ڈویلپرز کو انعام دیتا ہے جو پہلے صارف کے تجربے کے بارے میں سوچتے ہیں — تیز آغاز، ہموار سکرولنگ، اور ناقص کنیکٹیویٹی کا خوبصورت ہینڈلنگ۔
