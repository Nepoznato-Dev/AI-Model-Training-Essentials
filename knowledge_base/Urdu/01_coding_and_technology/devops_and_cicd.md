# DevOps اور CI/CD
DevOps ثقافتی فلسفے، طریقوں، اور ٹولز کا مجموعہ ہے جو ٹیموں کو سافٹ ویئر کو تیز اور زیادہ قابل اعتماد طریقے سے ڈیلیور کرنے کے قابل بناتا ہے۔ یہ ڈویلپرز (جو تبدیلیاں بھیجنا چاہتے ہیں) اور آپریشنز (جو استحکام چاہتے ہیں) کے درمیان دیوار کو توڑ دیتا ہے۔ CI/CD — مسلسل انضمام اور مسلسل ترسیل — آٹومیشن ریڑھ کی ہڈی ہے جو اسے ممکن بناتی ہے۔
---

## CI/CD پائپ لائنز
### CI/CD کا اصل مطلب کیا ہے۔
| مدت | یہ کیا کرتا ہے |
|------|---------------|
| **مسلسل انضمام (CI)** | ڈویلپرز کوڈ کو کثرت سے ضم کرتے ہیں۔ ہر انضمام خودکار تعمیرات اور ٹیسٹ کو متحرک کرتا ہے |
| **مسلسل ڈیلیوری (CD)** | کوڈ ہمیشہ قابل تعینات حالت میں ہوتا ہے۔ پیداوار کو جاری کرنا ایک دستی فیصلہ ہے |
| **مسلسل تعیناتی** | ہر تبدیلی جو ٹیسٹ پاس کرتی ہے خود بخود پروڈکشن میں جاتی ہے — کوئی دستی گیٹ نہیں |
### پائپ لائن کے عام مراحل
| اسٹیج | کیا ہوتا ہے | اوزار |
|---------|---------------|------|
| **ماخذ** | ڈویلپر کوڈ کو Git پر دھکیلتا ہے | گٹ ہب، گٹ لیب، بٹ بکٹ |
| **تعمیر** | کوڈ مرتب کریں، انحصار انسٹال کریں | Maven, Gradle, npm, pip |
| **ٹیسٹ** | یونٹ چلائیں، انضمام، لنٹ چیکس | جیسٹ، پائٹسٹ، JUnit |
| **پیکیج** | ڈوکر امیج یا آرٹفیکٹ بنائیں | Docker, Buildpacks |
| **تعینات (اسٹیجنگ)** | سٹیجنگ ماحول میں تعینات کریں | Kubernetes, ECS, VM |
| **ٹیسٹ (اسٹیجنگ)** | انٹیگریشن ٹیسٹ، دھواں ٹیسٹ | سیلینیم، ڈاکیا |
| **تعینات (پیداوار)** | پیداوار کے لیے ریلیز | نیلا سبز، کینری، رولنگ |
| **مانیٹر** | صحت، غلطیاں، کارکردگی کا مشاہدہ کریں | Prometheus, Grafana, Datadog |
### مقابلے میں CI/CD ٹولز
| ٹول | قسم | طاقت |
|------|------|---------|
| **گٹ ہب ایکشنز** | کلاؤڈ CI/CD | گٹ ہب کے ساتھ گہرائی سے مربوط؛ YAML ورک فلو |
| **گٹ لیب سی آئی** | بلٹ ان CI/CD | ریپو + پائپ لائن کے لیے سنگل پلیٹ فارم |
| **جینکنز** | خود میزبان CI/CD | انتہائی قابل ترتیب؛ بڑے پیمانے پر پلگ ان ماحولیاتی نظام |
| **CircleCI** | کلاؤڈ CI/CD | تیز؛ کنٹینرائزڈ ورک فلو کے لیے اچھا |
| **ArgoCD** | GitOps for Kubernetes | اعلانیہ، گٹ سے چلنے والی تعیناتیاں |

## ڈوکر اور کنٹینرز
### کنٹینرز کیوں؟
کنٹینرز سے پہلے، کلاسک مسئلہ تھا "یہ میری مشین پر کام کرتا ہے۔" کنٹینرز کسی ایپلیکیشن کو اس کے تمام انحصار کے ساتھ پیک کر کے حل کرتے ہیں — لائبریریز، رن ٹائم، تشکیل — ایک واحد، پورٹیبل یونٹ میں جو کہیں بھی یکساں طور پر چلتا ہے۔
### ڈوکر لوازم
| تصور | تفصیل |
|---------|---------------|
| **تصویر** | ایپ + انحصار کے ساتھ صرف پڑھنے کے لیے ٹیمپلیٹ |
| **کنٹینر** | ایک تصویر کی چل رہی مثال |
| **ڈاکر فائل** | تصویر بنانے کا نسخہ |
| **رجسٹری** | تصاویر کے لیے ذخیرہ (Docker Hub, ECR, GCR) |
| **حجم** | کنٹینر دوبارہ شروع ہونے سے بچ جانے والا مستقل ذخیرہ |
| **نیٹ ورک** | کنٹینرز کے لیے الگ تھلگ نیٹ ورکنگ پرت |
### ڈاکر فائل کے بہترین طریقے
```dockerfile
# Use specific base image tags, not 'latest'
FROM python:3.12-slim

# Set working directory
WORKDIR /app

# Copy dependency file first (leverage Docker layer caching)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code
COPY . .

# Run as non-root user
USER appuser

# Expose port and define entrypoint
EXPOSE 8000
CMD ["python", "main.py"]
```

کلیدی مشقیں: سلم/الپائن بیس امیجز کا استعمال کریں، نان روٹ کے طور پر چلائیں، لیوریج لیئر کیچنگ،`.dockerignore`استعمال کریں، کمزوریوں کے لیے امیجز اسکین کریں (`trivy`، `docker scan`)، اور وسائل کی حدیں سیٹ کریں۔
### ڈوکر کمپوز
متعدد کنٹینرز کو ایک ساتھ چلانے کے لیے (ایپ + ڈیٹا بیس + کیشے):
```yaml
services:
  app:
    build: .
    ports: ["8000:8000"]
    depends_on: [db, redis]
    environment:
      DATABASE_URL: postgresql://user:pass@db:5432/mydb
  db:
    image: postgres:16
    volumes: [pgdata:/var/lib/postgresql/data]
  redis:
    image: redis:7-alpine
volumes:
  pgdata:
```

## Kubernetes (K8s)
Kubernetes صنعت کے معیاری کنٹینر آرکیسٹریٹر ہے۔ یہ کنٹینرائزڈ ایپلی کیشنز کی تعیناتی، اسکیلنگ اور آپریشن کا انتظام کرتا ہے۔
### بنیادی فن تعمیر
| جزو | کردار |
|------------|------|
| **کنٹرول طیارہ** | کلسٹر کا انتظام کرتا ہے (API سرور، شیڈولر، وغیرہ، کنٹرولر مینیجر) |
| **نوڈ** | ورکر مشین (VM یا فزیکل) جو کنٹینرز چلاتی ہے۔
| **پوڈ** | سب سے چھوٹی تعیناتی یونٹ؛ ایک یا زیادہ کنٹینرز جو نیٹ ورکنگ کا اشتراک کرتے ہیں |
| **سروس** | مستحکم نیٹ ورک اینڈ پوائنٹ جو ٹریفک کو پوڈز تک روٹ کرتا ہے |
| **تعینات** | مطلوبہ پوڈ اسٹیٹ کی اعلانیہ تعریف (نقل، تصویر، وغیرہ) |
| **داخلہ** | بیرونی ٹریفک کے لیے HTTP روٹنگ کے اصول |
| **ConfigMap/Secret** | کنفیگریشن اور حساس ڈیٹا کو پوڈز میں داخل کیا جاتا ہے۔
### ضروری کیوبیکٹل کمانڈز
```bash
kubectl get pods                    # List pods
kubectl get services                # List services
kubectl describe pod <name>         # Detailed pod info
kubectl logs <pod-name>             # View pod logs
kubectl exec -it <pod> -- /bin/sh   # Shell into a pod
kubectl apply -f deployment.yaml    # Apply a manifest
kubectl rollout status deploy/myapp # Check rollout progress
kubectl scale deploy/myapp --replicas=5  # Scale to 5 replicas
```

### ہیلم
ہیلم Kubernetes کے لیے پیکیج مینیجر ہے۔ ایک **چارٹ** پہلے سے ترتیب شدہ Kubernetes وسائل کا ایک بنڈل ہے۔ K8s کے لیے اسے`apt`یا`brew`سمجھیں۔
```bash
helm install my-release bitnami/postgresql   # Install a chart
helm upgrade my-release bitnami/postgresql   # Upgrade
helm rollback my-release 1                   # Rollback to revision 1
helm list                                    # List releases
```

## بنیادی ڈھانچہ بطور کوڈ (IaC)
IaC انفراسٹرکچر کنفیگریشن کے ساتھ اسی طرح برتاؤ کرتا ہے جس طرح آپ ایپلیکیشن کوڈ کے ساتھ سلوک کرتے ہیں: ورژن کے زیر کنٹرول، ٹیسٹ شدہ، اور پائپ لائنز کے ذریعے تعینات۔
### ٹیرافارم بمقابلہ جوابدہ
| ٹول | قسم | نقطہ نظر | کے لیے بہترین |
|------|------|---------|---------|
| **ٹیرافارم** | فراہمی | اعلانیہ (HCL)؛ ریاست کی بنیاد پر | کلاؤڈ وسائل کی تخلیق (VPCs، VMs، ڈیٹا بیس) |
| **جواب ** | ترتیب | اعلانیہ (YAML)؛ ایجنٹ کے بغیر | سرورز کو ترتیب دینا، سافٹ ویئر انسٹال کرنا |
| **پلومی** | فراہمی | لازمی (Python, Go, TS) | وہ ٹیمیں جو حقیقی پروگرامنگ زبانوں کو ترجیح دیتی ہیں۔
| **کلاؤڈ فارمیشن** | فراہمی | اعلانیہ (YAML/JSON)؛ AWS-آبائی | AWS صرف انفراسٹرکچر |
### ٹیرافارم کی مثال
```hcl
provider "aws" {
  region = "us-east-1"
}

resource "aws_instance" "web" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.micro"

  tags = {
    Name = "web-server"
  }
}
```

بہترین طریقہ کار: دوبارہ استعمال کے لیے ماڈیولز کا استعمال کریں، اسٹیٹ کو دور سے اسٹور کریں (S3 + DynamoDB لاک کرنے کے لیے)، کبھی بھی ہارڈ کوڈ راز نہ رکھیں، اور ہر چیز کو ورژن کنٹرول کریں۔

## نگرانی اور مشاہدہ
### تین ستون
| ستون | یہ آپ کو کیا بتاتا ہے | اوزار |
|---------|------|------|
| **میٹرکس** | وقت کے ساتھ عددی پیمائش (CPU، درخواست کی شرح، غلطی کی شرح) | Prometheus, CloudWatch, Datadog |
| **لاگز** | سیاق و سباق کے ساتھ مجرد واقعات (غلطیاں، درخواستیں، ریاستی تبدیلیاں) | ELK Stack, Loki, CloudWatch لاگز |
| **ٹریسز** | تمام خدمات میں اختتام سے آخر تک درخواست کا سفر | جیگر، ایکس رے، زپکن |
### پرومیتھیس + گرافانا اسٹیک
معیاری اوپن سورس مانیٹرنگ اسٹیک:
| جزو | کردار |
|------------|------|
| **پرومیتھیس** | ٹائم سیریز ڈیٹا بیس؛ خدمات سے میٹرکس کھینچتا ہے |
| **گرافانا** | ویژولائزیشن اور ڈیش بورڈز |
| ** الرٹ مینیجر** | سلیک، پیجر ڈیوٹی، ای میل کے راستے الرٹس |
| **نوڈ ایکسپورٹر** | سسٹم لیول میٹرکس (CPU, RAM, disk) کو ظاہر کرتا ہے |
| **بلیک باکس ایکسپورٹر** | پروبس اینڈ پوائنٹس (HTTP, TCP, ICMP) |
### ٹریک کرنے کے لیے کلیدی میٹرکس
| زمرہ | میٹرکس |
|------------|---------|
| **بنیادی ڈھانچہ** | CPU، RAM، ڈسک کا استعمال، نیٹ ورک I/O |
| **درخواست** | درخواست کی شرح، تاخیر (p50, p95, p99), غلطی کی شرح |
| **ڈیٹا بیس** | سوالات کی گنتی، سست سوالات، کنکشن پول کا استعمال |
| **کاروبار** | سائن اپس، تبادلوں، آمدنی |

## تعیناتی کی حکمت عملی
| حکمت عملی | یہ کیسے کام کرتا ہے | خطرہ | رول بیک |
|------------|------------|------|----------|
| **رولنگ اپ ڈیٹ** | پرانی مثالوں کو آہستہ آہستہ نئے سے بدلیں | کچھ صارفین پرانے پر، کچھ نئے ورژن پر | پچھلی تصویر پر واپس جائیں |
| **نیلے سبز** | دو ایک جیسے ماحول چلائیں؛ ٹریفک کو تبدیل کریں | منتقلی کے دوران بنیادی ڈھانچے کی لاگت دوگنا | فوری واپس سوئچ |
| **کینری** | ٹریفک کا چھوٹا % نئے ورژن کی طرف روٹ کریں۔ بتدریج اضافہ | پیچیدہ ٹریفک مینجمنٹ | ٹریفک کو واپس مستحکم کرنے کے لیے روٹ |
| **خصوصیت کے جھنڈے** | کوڈ تعینات کریں لیکن خصوصیات کو ٹوگلز کے پیچھے چھپائیں | مشروط منطق سے کوڈ کی پیچیدگی | ٹوگل آف |

## GitOps
GitOps IaC کو اس کے منطقی انجام تک لے جاتا ہے: Git repository آپ کے بنیادی ڈھانچے اور ایپلی کیشنز کی مطلوبہ حالت کے لیے سچائی کا واحد ذریعہ ہے۔
| اصول | تفصیل |
|------------|-------------|
| **اعلانیہ** | کوڈ کے طور پر بیان کردہ ہر چیز (YAML, HCL) |
| **ورژن شدہ** | گٹ سچائی کا ذریعہ ہے |
| **خودکار** | ٹولز مطلوبہ حالت کو حقیقی حالت کے ساتھ مستقل طور پر ہم آہنگ کرتے ہیں۔
| ** قابل سماعت** | ہر تبدیلی ایک گٹ کمٹ ہے |
**ArgoCD** اور **Flux** Kubernetes کے لیے سرکردہ GitOps ٹولز ہیں۔ آپ اپنے گٹ ریپو میں تبدیلی کو آگے بڑھاتے ہیں، اور ٹول خود بخود اسے کلسٹر میں تعینات کر دیتا ہے۔

## واقعہ کا جواب
جب صبح 3 بجے کچھ ٹوٹ جاتا ہے:
1. **تسلیم کریں** الرٹ۔
2. **اسکوپ کا اندازہ کریں**: کون سی خدمات، صارفین اور ڈیٹا متاثر ہوئے ہیں؟
3. **بنیادی وجہ کی شناخت** کریں — لاگز، میٹرکس، حالیہ تعیناتیوں کو چیک کریں۔
4. **اگر ممکن ہو تو** پر مشتمل ہو — سرکٹ بریکر، فیچر فلیگ، ٹریفک شفٹنگ۔
5. **فکس** — رول بیک یا پیچ فارورڈ۔
6. **مواصلات** — اسٹیک ہولڈرز اور صارفین کو اپ ڈیٹ کریں (اسٹیٹس پیج)۔
7. **پوسٹ مارٹم** — 24-48 گھنٹوں کے اندر، دستاویز کی بنیادی وجہ اور کارروائی کی اشیاء۔
مقصد نہ صرف واقعہ کو حل کرنا ہے بلکہ اس بات کو یقینی بنانا ہے کہ ایک ہی واقعہ دوبارہ نہ ہو۔
