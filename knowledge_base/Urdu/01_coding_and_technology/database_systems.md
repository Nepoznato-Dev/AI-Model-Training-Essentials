# ڈیٹا بیس سسٹم
## ڈیٹا بیس کے بنیادی اصول
### ڈیٹا بیس کیا ہے؟
ڈیٹابیس الیکٹرانک طور پر ذخیرہ شدہ ساختی معلومات کا ایک منظم مجموعہ ہے، جو ڈیٹا کی موثر بازیافت، اندراج، اپ ڈیٹ کرنے اور حذف کرنے کے لیے ڈیزائن کیا گیا ہے۔
### ڈیٹا بیس مینجمنٹ سسٹمز (DBMS)
وہ سافٹ ویئر جو ڈیٹا کو حاصل کرنے اور تجزیہ کرنے کے لیے آخری صارفین، ایپلیکیشنز اور خود ڈیٹا بیس کے ساتھ تعامل کرتا ہے۔ مثالیں: MySQL، PostgreSQL، Oracle، MongoDB۔
### کلیدی تصورات
- **سکیمہ**: ڈیٹا بیس کی ساخت/تنظیم (ٹیبلز، فیلڈز، تعلقات)
- **مثال**: ایک خاص لمحے میں ذخیرہ شدہ اصل ڈیٹا
- **ACID خصوصیات**: جوہری، مستقل مزاجی، تنہائی، استحکام
- **CAP تھیوریم**: مستقل مزاجی، دستیابی، تقسیم رواداری (2 کا انتخاب کریں)
- **نارملائزیشن**: فالتو پن کو کم کرنے کے لیے ڈیٹا کو منظم کرنا
- **غیر معمولی بنانا**: پڑھنے کی کارکردگی کو بہتر بنانے کے لیے فالتو پن کو شامل کرنا
## رشتہ دار ڈیٹا بیس (SQL)
### بنیادی تصورات
- **میزیں**: قطاریں (ریکارڈز) اور کالم (فیلڈز)
- **بنیادی کلید**: ہر قطار کے لیے منفرد شناخت کنندہ
- **غیر ملکی کلید**: دوسرے جدول میں بنیادی کلید کا حوالہ
- **انڈیکس**: ڈیٹا سٹرکچرز استفسار کی رفتار کو بہتر بناتے ہیں۔
- **منظر**: استفسار کے نتائج پر مبنی مجازی میزیں۔
- **ذخیرہ شدہ طریقہ کار**: پہلے سے مرتب کردہ ایس کیو ایل کوڈ بلاکس
- **ٹرگرز**: ڈیٹا کی تبدیلیوں پر خودکار کارروائیاں
### SQL آپریشنز (CRUD)```sql
-- Create
INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com');

-- Read
SELECT * FROM users WHERE id = 1;
SELECT name, email FROM users ORDER BY name LIMIT 10;

-- Update
UPDATE users SET email = 'new@example.com' WHERE id = 1;

-- Delete
DELETE FROM users WHERE id = 1;
```

### شامل ہوتا ہے۔
- **اندرونی شمولیت**: دونوں جدولوں سے مماثل قطاریں لوٹاتا ہے۔
- **بائیں شمولیت**: بائیں میز سے تمام قطاریں، دائیں سے ملتی ہیں۔
- **دائیں شمولیت**: دائیں میز سے تمام قطاریں، بائیں سے مماثل ہیں۔
- **مکمل بیرونی شمولیت**: دونوں میزوں سے تمام قطاریں۔
- **کراس جوائن**: دونوں جدولوں کا کارٹیشین پروڈکٹ
- **خود شمولیت**: ٹیبل اپنے ساتھ شامل ہوگیا۔
### نارملائزیشن فارمز
- **1NF**: جوہری اقدار، کوئی دہرانے والے گروپ نہیں۔
- **2NF**: 1NF + کوئی جزوی انحصار نہیں (تمام غیر کلیدی خصوصیات پوری بنیادی کلید پر منحصر ہیں)
- **3NF**: 2NF + کوئی عبوری انحصار نہیں ہے (غیر کلیدی خصوصیات دیگر غیر کلیدی خصوصیات پر منحصر نہیں ہیں)
- **BCNF**: مضبوط 3NF، ہر تعین کنندہ امیدوار کی کلید ہے۔
- **4NF**: کوئی کثیر قیمتی انحصار نہیں ہے۔
- **5NF**: شامل ہونے کا کوئی انحصار نہیں۔
### مقبول RDBMS
- **PostgreSQL**: اعلی درجے کی خصوصیات، قابل توسیع، ACID کے مطابق
- **MySQL**: وسیع پیمانے پر استعمال ہونے والی، تیز پڑھنے والی، ویب ایپلیکیشنز
- **اوریکل**: انٹرپرائز کی خصوصیات، اسکیل ایبلٹی، مہنگی۔
- **SQL سرور**: مائیکروسافٹ ایکو سسٹم، مربوط ٹولز
- **SQLite**: ایمبیڈڈ، سرور لیس، ہلکا پھلکا
- **MariaDB**: MySQL فورک، اوپن سورس
## NoSQL ڈیٹا بیس
### NoSQL ڈیٹا بیس کی اقسام
#### دستاویزات کی دکانیں۔
- **ساخت**: JSON جیسی دستاویزات (BSON)
- **کیسز استعمال کریں**: مواد کا انتظام، کیٹلاگ، صارف پروفائلز
- **مثالیں**: MongoDB، CouchDB، DocumentDB
- **استفسار کی مثال** (MongoDB):```javascript
db.users.find({ age: { $gt: 25 } }).sort({ name: 1 });
```

#### کلیدی قیمت والے اسٹورز
- **ساخت**: کلیدی قدر کے سادہ جوڑے
- **کیسز استعمال کریں**: کیشنگ، سیشنز، شاپنگ کارٹس
- **مثالیں**: Redis، DynamoDB، Riak
- **خصوصیات**: تیز، سادہ، محدود استفسار
#### کالم-فیملی اسٹورز
- **ساخت**: کالموں کو خاندانوں میں گروپ کیا گیا ہے۔
- **کیسز استعمال کریں**: بڑا ڈیٹا، تجزیات، ٹائم سیریز
- **مثالیں**: Cassandra, HBase, ScyllaDB
- **خصوصیات**: تحریری طور پر بہتر، تقسیم شدہ، توسیع پذیر
#### گراف ڈیٹا بیس
- ** ساخت**: نوڈس، کنارے، خصوصیات
- **کیسز استعمال کریں**: سوشل نیٹ ورکس، فراڈ کا پتہ لگانا، سفارشات
- **مثالیں**: Neo4j، Amazon Neptune، ArangoDB
- **استفسار کی زبان**: سائفر (Neo4j)، Gremlin
### NoSQL کب استعمال کریں۔
- لچکدار/بڑھتی ہوئی اسکیما
- افقی پیمانے کی ضروریات
- ہائی رائٹ تھرو پٹ
- درجہ بندی/نیسٹڈ ڈیٹا
- تقسیم شدہ نظام
- ریئل ٹائم ایپلی کیشنز
## ڈیٹا بیس ڈیزائن
### ہستی-رشتہ ماڈلنگ
- **ہستی**: اشیاء/تصورات (کسٹمر، پروڈکٹ، آرڈر)
- **اوصاف**: اداروں کی خصوصیات (نام، قیمت، تاریخ)
- **تعلقات**: اداروں کے درمیان روابط (ایک سے ایک، ایک سے کئی، کئی سے کئی)
- **کارڈینیلٹی**: رشتے میں مثالوں کی تعداد
### اسکیما ڈیزائن پیٹرنز
- **سنگل ٹیبل وراثت**: تمام اقسام ایک ٹیبل میں ٹائپ ڈسکریمینیٹر کے ساتھ
- **کلاس ٹیبل وراثت**: بیس اور ذیلی طبقات کے لیے الگ الگ میزیں۔
- **کنکریٹ ٹیبل وراثت**: ہر کنکریٹ کلاس کے لیے علیحدہ میز
- **جنکشن ٹیبلز**: کئی سے کئی رشتوں کو حل کریں۔
- **آڈٹ ٹیبلز**: تبدیلیوں کو ٹریک کریں (created_at, update_at, deleted_at)
### اشاریہ سازی کی حکمت عملی
- **B-Tree**: ڈیفالٹ، رینج کے سوالات، چھانٹنا
- **ہیش**: عین مطابق مماثلت کی تلاش
- **بٹ میپ**: کم کارڈنلٹی کالم (صنف، حیثیت)
- **مکمل متن**: متن تلاش کرنے کی صلاحیتیں۔
- **مقامی**: جغرافیائی ڈیٹا (GIS)
- **جامع**: متعدد کالموں کو ملا کر
- **کورنگ**: استفسار کے لیے درکار تمام کالموں پر مشتمل ہے۔
## استفسار کی اصلاح
### عملدرآمد کے منصوبے
- یہ سمجھنا کہ ڈیٹا بیس سوالات کو کیسے انجام دیتا ہے۔
- رکاوٹوں کی نشاندہی کرنا (مکمل ٹیبل اسکین، گمشدہ اشاریہ جات)
- ٹولز: وضاحت کریں، تجزیہ کی وضاحت کریں۔
### اصلاح کی تکنیک
- **انڈیکس کا استعمال**: یقینی بنائیں کہ سوالات مناسب اشاریہ جات کا استعمال کرتے ہیں۔
- **سوال دوبارہ لکھنا**: پیچیدہ سوالات کو آسان بنائیں
- **جوائن آپٹیمائزیشن**: جوائن کی صحیح اقسام اور آرڈر کا انتخاب کریں۔
- **تقسیم**: بڑی میزیں تقسیم کریں (حد، ہیش، فہرست)
- **مٹیریلائزڈ ویوز**: پہلے سے شمار شدہ استفسار کے نتائج
- **سوال کیشنگ**: اکثر استفسار کے نتائج کو اسٹور کریں۔
### عام کارکردگی کے مسائل
- **N+1 سوال کا مسئلہ**: متعلقہ ڈیٹا کو غیر موثر طریقے سے بازیافت کرنا
- **لاپتہ اشاریہ جات**: بڑی میزوں پر مکمل ٹیبل اسکین
- **زیادہ اشاریہ سازی**: بہت زیادہ اشاریہ جات کی وجہ سے آہستہ لکھتا ہے۔
- **لاک کنٹینشن**: لین دین تالے کا انتظار کر رہے ہیں۔
- **غیر موثر سوالات**: منتخب کریں *، غیر ضروری شمولیت
## لین دین اور ہم آہنگی۔
### ٹرانزیکشن آئسولیشن لیولز
- **غیر پابند پڑھیں**: سب سے کم تنہائی، گندا پڑھنا ممکن ہے۔
- **کمیٹڈ پڑھیں**: صرف کمٹڈ ڈیٹا نظر آتا ہے (زیادہ تر DBs میں ڈیفالٹ)
- **بار بار پڑھا جا سکتا ہے**: ایک ہی سوال لین دین میں وہی نتائج دیتا ہے۔
- **سیریلائزیبل**: سب سے زیادہ تنہائی، لین دین ترتیب وار انجام پاتا ہے
### کنکرنسی کنٹرول
- **ناامیدی سے متعلق تالا لگانا**: رسائی سے پہلے وسائل کو مقفل کریں۔
- **پرامید لاکنگ**: کمٹ کرنے سے پہلے ورژن چیک کریں۔
- **MVCC (ملٹی ورژن کنکرنسی کنٹرول)**: قطاروں کے متعدد ورژن کو برقرار رکھیں
- **رو لیول لاکنگ**: مخصوص قطاروں کو لاک کریں۔
- **ٹیبل لیول لاکنگ**: پوری ٹیبل کو لاک کریں۔
### تعطل
- سرکلر انحصار جہاں لین دین ایک دوسرے کا انتظار کرتے ہیں۔
- روک تھام: مستقل لاک آرڈرنگ، ٹائم آؤٹ، تعطل کا پتہ لگانا
- قرارداد: ایک لین دین کو ختم کریں۔
## نقل اور اسکیلنگ
### نقل کی اقسام
- **Master-Slave**: ایک بنیادی، متعدد پڑھی ہوئی نقلیں
- **ماسٹر-ماسٹر**: متعدد پرائمریز، دو طرفہ نقل
- **ملٹی ماسٹر**: این پرائمریز، تنازعات کے حل کی ضرورت ہے۔
- **چین کی نقل**: نوڈس کے ذریعے ترتیب وار نقل
### پیمانے کے نقطہ نظر
- **عمودی اسکیلنگ**: سرور کے وسائل میں اضافہ کریں (CPU، RAM، اسٹوریج)
- **افقی اسکیلنگ**: مزید سرورز شامل کریں (شارڈنگ، پارٹیشننگ)
- **ریپلیکاس پڑھیں**: آف لوڈ ریڈ ٹریفک
- **شارڈنگ**: کلید/رینج/ہیش کے ذریعے ڈیٹا کو سرورز پر تقسیم کریں۔
- **فیڈریشن**: فنکشن/سروس کے لحاظ سے تقسیم
### مستقل مزاجی کے ماڈل
- **مضبوط مستقل مزاجی**: تمام نوڈس ایک ہی وقت میں ایک ہی ڈیٹا دیکھتے ہیں۔
- **واقعی مستقل مزاجی**: نوڈس وقت کے ساتھ مل جاتے ہیں۔
- **وجہ کی مستقل مزاجی**: کاز ایفیکٹ تعلقات محفوظ ہیں۔
- **آپ کی تحریریں پڑھیں**: صارف فوری طور پر اپنی اپ ڈیٹس دیکھتا ہے۔
## بیک اپ اور ریکوری
### بیک اپ کی حکمت عملی
- **مکمل بیک اپ**: ڈیٹا بیس کی مکمل کاپی
- **بڑھتی ہوئی بیک اپ**: آخری بیک اپ کے بعد تبدیلیاں
- **فرق بیک اپ**: آخری مکمل بیک اپ کے بعد تبدیلیاں
- **پوائنٹ ان ٹائم ریکوری**: مخصوص لمحے پر بحال کریں۔
- **مسلسل بیک اپ**: بیک اپ کے لیے حقیقی وقت کی نقل
### بازیابی کے طریقہ کار
- **RTO (ریکوری ٹائم مقصد)**: زیادہ سے زیادہ قابل قبول ڈاؤن ٹائم
- **RPO (ریکوری پوائنٹ کا مقصد)**: زیادہ سے زیادہ قابل قبول ڈیٹا کا نقصان
- **ڈیزاسٹر ریکوری پلان**: ناکامیوں کے لیے دستاویزی طریقہ کار
- **ٹیسٹنگ**: بحالی کی باقاعدہ مشقیں۔
## سیکیورٹی
### رسائی کنٹرول
- **توثیق**: صارف کی شناخت کی تصدیق کریں۔
- **مجازت**: اجازت دیں (گرانٹ، منسوخ)
- **کردار**: آسان انتظام کے لیے گروپ کی اجازت
- **کم سے کم استحقاق کا اصول**: کم از کم ضروری رسائی
### ڈیٹا پروٹیکشن
- **انکرپشن آرام پر**: ذخیرہ شدہ ڈیٹا کو انکرپٹ کریں۔
- **ٹرانزٹ میں خفیہ کاری**: کنکشنز کے لیے TLS/SSL
- **ماسکنگ**: حساس ڈیٹا کو غیر پروڈکشن میں چھپائیں۔
- **ٹوکنائزیشن**: حساس ڈیٹا کو ٹوکنز سے تبدیل کریں۔
### عام کمزوریاں
- **SQL انجیکشن**: صارف کے ان پٹ میں نقصان دہ SQL
- **استحقاق میں اضافہ**: غیر مجاز رسائی حاصل کرنا
- **آڈٹ لاگنگ**: ڈیٹا بیس کی تمام سرگرمیوں کو ٹریک کریں۔
- **تعمیل**: GDPR، HIPAA، PCI-DSS کی ضروریات
## جدید ڈیٹا بیس ٹیکنالوجیز
### کلاؤڈ ڈیٹا بیس
- **AWS**: RDS، Aurora، DynamoDB، Redshift
- **گوگل کلاؤڈ**: کلاؤڈ ایس کیو ایل، اسپنر، بگ ٹیبل، فائر اسٹور
- **Azure**: SQL ڈیٹا بیس، Cosmos DB، Synapse
- **فوائد**: منظم سروس، آٹو اسکیلنگ، بیک اپ شامل ہیں۔
### نیو ایس کیو ایل ڈیٹا بیس
- NoSQL اسکیل ایبلٹی کے ساتھ SQL مستقل مزاجی کو یکجا کریں۔
- **مثالیں**: کاکروچ ڈی بی، ٹی آئی ڈی بی، یوگا بائٹ ڈی بی، گوگل اسپنر
- **خصوصیات**: تقسیم شدہ، ACID ٹرانزیکشنز، افقی اسکیلنگ
### ٹائم سیریز ڈیٹا بیس
- ٹائم اسٹیمپڈ ڈیٹا کے لئے آپٹمائزڈ
- **مثالیں**: InfluxDB، TimescaleDB، Prometheus
- **معاملات استعمال کریں**: IoT، نگرانی، مالیاتی ڈیٹا
### ویکٹر ڈیٹا بیس
- ایمبیڈنگ ویکٹرز کو اسٹور اور استفسار کریں۔
- **مثالیں**: Pinecone، Milvus، Weaviate، Qdrant
- **کیسز استعمال کریں**: سیمنٹک تلاش، سفارشی نظام، AI ایپلیکیشنز
### ملٹی ماڈل ڈیٹا بیس
- سنگل سسٹم میں متعدد ڈیٹا ماڈلز کی حمایت کریں۔
- **مثالیں**: ArangoDB، OrientDB، Azure Cosmos DB
- **فائدہ**: متعدد ڈیٹا بیس کے بغیر لچک
## ORMs اور ڈیٹا تک رسائی
### آبجیکٹ-ریلیشنل میپنگ
- **مقصد**: ڈیٹا بیس ٹیبلز کو پروگرامنگ آبجیکٹ کے لیے نقشہ بنائیں
- **مقبول ORMs**:
  - ازگر: SQLAlchemy، Django ORM، Peewee
  - JavaScript: Sequelize، Prisma، TypeORM
  - جاوا: ہائبرنیٹ، جے پی اے
  - روبی: ایکٹو ریکارڈ
  - .NET: ہستی کا فریم ورک
### فوائد
- SQL سے خلاصہ
- قسم کی حفاظت
- ہجرت کا انتظام
- استفسار بلڈنگ APIs
### خرابیاں
- کارکردگی اوور ہیڈ
- پیچیدہ سوالات لکھنا مشکل ہے۔
- N+1 استفسار کے مسائل
- سیکھنے کا وکر
## ڈیٹا بیس ایڈمنسٹریشن
### DBA کی ذمہ داریاں
- تنصیب اور ترتیب
- کارکردگی ٹیوننگ
- بیک اپ اور ریکوری
- سیکیورٹی کا انتظام
- صلاحیت کی منصوبہ بندی
- نگرانی اور انتباہ
- پیچ کا انتظام
### مانیٹرنگ میٹرکس
- سوال کے جواب کا وقت
- تھرو پٹ (فی سیکنڈ لین دین)
- کنکشن کی گنتی
- کیشے ہٹ کا تناسب
- ڈسک I/O
- انتظار کا وقت مقفل کریں۔
--.نقل کا وقفہ n
### دیکھ بھال کے کام
- **ویکیوم/تجزیہ**: اعدادوشمار کو اپ ڈیٹ کریں، جگہ کا دوبارہ دعوی کریں۔
- **انڈیکس ری بلڈنگ**: ڈیفراگمنٹ انڈیکس
- **اعداد و شمار کی تازہ کارییں**: استفسار کے اصلاح کار کو مطلع رکھیں
- **لاگ روٹیشن**: لاگ فائل کے سائز کا نظم کریں۔
- **صلاحیت کی منصوبہ بندی**: ترقی کی پیشن گوئی کریں، اپ گریڈ کی منصوبہ بندی کریں۔
