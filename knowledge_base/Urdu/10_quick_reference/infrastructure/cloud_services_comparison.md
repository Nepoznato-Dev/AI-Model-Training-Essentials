# کلاؤڈ سروسز کا موازنہ
کمپیوٹ، اسٹوریج، ڈیٹا بیس، AI/ML، نیٹ ورکنگ، مانیٹرنگ، اور انفراسٹرکچر کے بطور کوڈ میں تین بڑے کلاؤڈ فراہم کنندگان — AWS، Azure، اور Google Cloud — کا ایک دوسرے کے ساتھ موازنہ۔ یہ فیصلہ کرنے والے معماروں کے لیے مفید ہے کہ کون سا پلیٹ فارم استعمال کرنا ہے، یا ایک کلاؤڈ سے دوسرے میں خدمات کی نقشہ سازی کرنا ہے۔
---

## فراہم کنندہ کا جائزہ
| | AWS | Azure | گوگل کلاؤڈ (GCP) |
|---|------|---------|----------------------|
| **مارکیٹ شیئر** | ~31% (سب سے بڑا) | ~25% (دوسرا) | ~11% (تیسرا، سب سے تیزی سے بڑھتا ہوا) |
| **طاقتیں** | خدمات کی وسعت؛ پختگی ماحولیاتی نظام | انٹرپرائز انضمام؛ ہائبرڈ بادل؛ مائیکروسافٹ اسٹیک | ڈیٹا/AI؛ کبرنیٹس؛ عالمی نیٹ ورک |
| ** کے لیے بہترین ** | کاروباری اداروں کے لئے آغاز؛ وسیع ترین سروس کیٹلاگ | مائیکروسافٹ/ایکٹو ڈائریکٹری کے ساتھ انٹرپرائزز؛ ہائبرڈ | ڈیٹا پر مبنی کام کا بوجھ؛ Kubernetes-آبائی؛ AI/ML |
| **علاقے** | 33 علاقے، 105 AZs | 60+ علاقے | 40+ علاقے، 100+ زون |
| **مفت درجے** | 12 ماہ مفت درجے + ہمیشہ مفت | 12 ماہ مفت + $200 کریڈٹ | 90 دنوں کے لیے $300 کریڈٹ + ہمیشہ مفت |

|------|------|---------|------|

| **آٹو اسکیلنگ** | آٹو اسکیلنگ گروپس | ورچوئل مشین اسکیل سیٹ | مثال کے گروپس |
| **سرور لیس فنکشنز** | لیمبڈا | Azure افعال | کلاؤڈ فنکشنز |
| **کنٹینر رجسٹری** | ECR (لچکدار کنٹینر رجسٹری) | Azure کنٹینر رجسٹری | آرٹفیکٹ رجسٹری |
| **کنٹینر آرکیسٹریشن** | ECS / EKS | ACS / AKS | جی کے ای / کلاؤڈ رن |
| **سرور لیس کنٹینرز** | فارگیٹ | کنٹینر ایپس | کلاؤڈ رن |

| **بیچ پروسیسنگ** | AWS بیچ | Azure بیچ | کلاؤڈ بیچ |

## کون سا کب استعمال کریں۔
| منظر نامہ | تجویز کردہ | کیوں |
|------------|---------------|------|
| **سروس کا وسیع انتخاب؛ بالغ ماحولیاتی نظام** | AWS | سب سے بڑا کیٹلاگ؛ سب سے زیادہ تیسری پارٹی کے انضمام |
| **مائیکروسافٹ انٹرپرائز؛ ایکٹو ڈائریکٹری؛ ہائبرڈ** | Azure | مقامی AD انضمام؛ مضبوط ہائبرڈ ٹولنگ |
| **ڈیٹا گودام؛ BigQuery; analytics- بھاری** | جی سی پی | BigQuery کلاس میں بہترین ہے؛ ہموار ڈیٹا انضمام |
| **Kubernetes-مقامی ترقی** | جی سی پی | GKE سب سے زیادہ پالش منظم Kubernetes ہے |
| **جنریٹیو AI/LLM ایپلی کیشنز** | Azure یا GCP | GPT ماڈلز کے لیے Azure OpenAI؛ Vertex AI برائے Gemini |
| **عالمی پیمانے پر، کم تاخیر والی ایپلی کیشنز** | جی سی پی | گوگل کا عالمی نیٹ ورک ایک حقیقی فائدہ ہے |
| **حکومت / تعمیل کے لیے کام کا بھاری بوجھ** | AWS یا Azure | زیادہ تر تعمیل کے سرٹیفیکیشن؛ GovCloud علاقوں |
| **لاگت کے لحاظ سے حساس آغاز** | GCP یا AWS | GCP کا مفت درجہ فراخ ہے۔ AWS کے پاس اسٹارٹ اپ کریڈٹ ہے |
| **موجودہ Microsoft / .NET اسٹیک** | Azure | بصری اسٹوڈیو، .NET، آفس 365 کے ساتھ سخت انضمام
| **ملٹی کلاؤڈ حکمت عملی** | Terraform + تینوں | بادلوں میں وسائل کا انتظام کرنے کے لیے Terraform کا استعمال کریں |

## خلاصہ
تینوں بادل قابل، قابل اعتماد اور مسلسل پھیلتے ہیں۔ انتخاب عام طور پر اس بات پر آتا ہے: آپ کی ٹیم پہلے سے کیا جانتی ہے، آپ کے موجودہ معاہدے کیسا نظر آتا ہے، اور آپ کے کام کے بوجھ کے لیے کون سی مخصوص خدمات اہم ہیں۔ ملٹی کلاؤڈ تیزی سے عام ہوتا جا رہا ہے — انفراسٹرکچر پرت پر وینڈر لاک ان سے بچنے کے لیے ٹیرافارم یا پلومی کا استعمال کریں، اور ہر کلاؤڈ کو اس کے لیے منتخب کریں جو یہ بہترین کرتا ہے۔
