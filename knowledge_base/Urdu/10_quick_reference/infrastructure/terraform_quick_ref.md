# کوڈ کے طور پر ٹیرافارم اور انفراسٹرکچر
Terraform کوڈ (IaC) ٹول کے طور پر سب سے زیادہ استعمال ہونے والا انفراسٹرکچر ہے — یہ آپ کو کلاؤڈ انفراسٹرکچر (سرور، ڈیٹا بیس، نیٹ ورکس، اجازت) کی وضاحتی کنفیگریشن فائلوں میں وضاحت کرنے دیتا ہے جن کا ورژن، جائزہ، تجربہ، اور خودکار کیا جا سکتا ہے۔ کلاؤڈ کنسول کے ذریعے کلک کرنے کے بجائے، آپ کوڈ لکھتے ہیں جو آپ کے بنیادی ڈھانچے کی مطلوبہ حالت کو بیان کرتا ہے، اور Terraform یہ بتاتا ہے کہ کیا تبدیلیاں کرنی ہیں۔
---

## بنیادی تصورات
| تصور | تفصیل |
|---------|---------------|
| **فراہم کنندہ** | پلگ ان جو ایک مخصوص کلاؤڈ پلیٹ فارم کا انتظام کرتا ہے (AWS، Azure، GCP، وغیرہ) |
| **وسائل** | ایک بنیادی ڈھانچہ آبجیکٹ (سرور، ڈیٹا بیس، نیٹ ورک) |
| **ریاست** | ٹیرافارم کا ریکارڈ جو کہ بنیادی ڈھانچہ موجود ہے۔ ریاستی فائل میں محفوظ |
| **منصوبہ** | Terraform کیا تبدیلیاں کرے گا اس کا پیش نظارہ |
| ** اپلائی کریں** | منصوبے پر عمل کریں؛ بنیادی ڈھانچہ بنائیں/اپ ڈیٹ کریں/تباہ کریں |
| **ماڈیول** | وسائل کا دوبارہ قابل استعمال مجموعہ |
| **متغیر** | کنفیگریشنز کے لیے ان پٹ پیرامیٹر |
| **آؤٹ پٹ** | ماڈیول یا کنفیگریشن سے برآمد کردہ قدر |
| **ڈیٹا سورس** | موجودہ انفراسٹرکچر سے معلومات پڑھیں |
---

## بنیادی ورک فلو
| مرحلہ | کمانڈ | تفصیل |
|------|---------|------------|
| **1۔ ترتیب لکھیں** |`.tf`فائلیں بنائیں | فراہم کنندگان، وسائل، متغیرات کی وضاحت کریں۔
| **2۔ شروع کریں** | `terraform init`| فراہم کنندگان ڈاؤن لوڈ کریں؛ بیک اینڈ سیٹ اپ |
| **3۔ فارمیٹ** | `terraform fmt`| فارمیٹنگ کو معیاری بنائیں |
| **4۔ توثیق کریں** | `terraform validate`| نحو اور ترتیب چیک کریں |
| **5۔ منصوبہ** | `terraform plan`| تبدیلیوں کا پیش نظارہ (ڈرائی رن) |
| **6۔ اپلائی کریں** | `terraform apply`| انفراسٹرکچر بنائیں یا اپ ڈیٹ کریں |
| **7۔ تباہ کر دیں** | `terraform destroy`| تمام زیر انتظام انفراسٹرکچر کو ختم کر دیں |
---

## کامن کمانڈز
| کمانڈ | تفصیل |
|---------|---------------|
| `terraform init`| ورکنگ ڈائرکٹری شروع کریں؛ فراہم کنندگان اور ماڈیولز ڈاؤن لوڈ کریں |
| `terraform plan`| دکھائیں کہ کیا تبدیلیاں کی جائیں گی |
| `terraform apply`| تبدیلیاں لاگو کریں؛ تصدیق کو چھوڑنے کے لیے`-auto-approve`شامل کریں۔
| `terraform destroy`| تمام منظم وسائل کو تباہ کر دیں |
| `terraform fmt`| کنفیگریشن فائلوں کو معیاری انداز میں فارمیٹ کریں |
| `terraform validate`| کنفیگریشن نحو کی توثیق کریں |
| `terraform output`| آؤٹ پٹ اقدار دکھائیں |
| `terraform state list`| ریاست میں تمام وسائل کی فہرست بنائیں |
| `terraform state show <resource>`| ایک مخصوص وسائل کی تفصیلات دکھائیں |
| `terraform import <resource> <id>`| ریاست میں موجودہ بنیادی ڈھانچے کو درآمد کریں |
| `terraform taint <resource>`| اگلی درخواست پر تفریح ​​کے لیے وسائل کو نشان زد کریں |
| `terraform refresh`| حقیقی انفراسٹرکچر سے مماثل حالت کو اپ ڈیٹ کریں |
| `terraform graph`| ایک بصری انحصار گراف (DOT فارمیٹ) بنائیں |
| `terraform console`| تاثرات کی جانچ کے لیے انٹرایکٹو کنسول |

## ریاستی انتظام
| بہترین عمل | تفصیل |
|---------------|---------------|
| **دور کی حالت** | S3، GCS، Azure Blob، یا Terraform Cloud میں سٹور اسٹیٹ - کبھی بھی مقامی طور پر |
| **اسٹیٹ لاکنگ** | ہم آہنگی ترمیم کو روکنے کے لیے DynamoDB (S3 بیک اینڈ) یا مقامی لاکنگ کا استعمال کریں |
| **ریاستی خفیہ کاری** | ریاستی فائلوں کے لیے آرام سے انکرپشن کو فعال کریں (ان میں حساس ڈیٹا ہوتا ہے) |
| **ریاست کی علیحدگی** | مختلف ماحول یا ٹیموں کے لیے علیحدہ اسٹیٹ فائلیں استعمال کریں۔
| **ریاستی بیک اپ** | ریموٹ بیک اینڈ خود بخود ورژن کی حالت؛ اسے فعال رکھیں |
| **دستی طور پر حالت میں کبھی ترمیم نہ کریں** | اس کی بجائے`terraform state mv`,`rm`,`import`استعمال کریں |

## ماڈیول کا ڈھانچہ
```
module/
├── main.tf          # Primary resources
├── variables.tf     # Input variables
├── outputs.tf       # Output values
├── versions.tf      # Provider and Terraform version constraints
├── README.md        # Documentation
└── examples/        # Example usage
    └── basic/
        └── main.tf
```

## متغیر کی اقسام
| قسم | مثال | کیس استعمال کریں |
|------|---------|---------|
| **سٹرنگ** | `variable "region" { type = string }`| سنگل ٹیکسٹ ویلیو |
| **نمبر** | `variable "count" { type = number }`| عددی قدر |
| **بول** | `variable "enable" { type = bool }`| سچا/جھوٹا جھنڈا |
| **فہرست** | `variable "zones" { type = list(string) }`| آرڈر شدہ مجموعہ |
| **نقشہ** | `variable "tags" { type = map(string) }`| کلیدی قدر کے جوڑے |
| **آبجیکٹ** | `variable "config" { type = object({...}) }`| سٹرکچرڈ کنفیگریشن |

## مشترکہ پیٹرن
| پیٹرن | تفصیل |
|---------|---------------|
| **گنتی** | `count = 3`وسائل کی متعدد مثالیں تخلیق کرتا ہے |
| **ہر ایک کے لیے** | `for_each = var.items`نقشے یا سیٹ پر دہراتا ہے |
| **متحرک بلاکس** | بار بار نیسٹڈ بلاکس بنائیں (مثلاً داخل ہونے کے اصول) |
| **مقامی اقدار** | `locals { ... }`حسابی اقدار اور تکرار کو کم کرنے کے لیے |
| **ڈیٹا ذرائع** | موجودہ انفراسٹرکچر پڑھیں (مثال کے طور پر، ایک موجودہ VPC تلاش کریں) |
| **فراہم کرنے والے** | تخلیق کے بعد وسائل پر سکرپٹ چلائیں (تھوڑے سے استعمال کریں) |
| **ورک اسپیس** | ایک ہی ترتیب میں مختلف ماحول کے لیے الگ ریاست |
---

## خرابی کا سراغ لگانا
| مسئلہ | حل |
|---------|------------|
| **ریاست کا بہاؤ** | فرق دیکھنے کے لیے`terraform plan`چلائیں؛ `terraform apply`مصالحت کے لیے |
| **مقفل حالت** | چیک کریں کہ تالا کس کے پاس ہے؛ اگر محفوظ ہو تو`terraform force-unlock`استعمال کریں۔
| **فراہم کرنے والے کی غلطیاں** | اسناد چیک کریں؛ اپ ڈیٹ فراہم کنندہ ورژن؛ API حدود کو چیک کریں |
| **درآمد تنازعات** | وسائل پہلے سے ہی ریاست میں ہیں؛ پہلے`terraform state rm`استعمال کریں۔
| **سرکلر انحصار** | وسائل کی تنظیم نو؛`depends_on`احتیاط سے استعمال کریں۔
| **بڑی ریاست** | ماڈیولز میں تقسیم؛ جزوی کارروائیوں کے لیے`-target`استعمال کریں۔
---

## خلاصہ
Terraform اعلانیہ کنفیگریشن فائلوں کے ذریعے انفراسٹرکچر کا انتظام کرتا ہے۔ ورک فلو یہ ہے: کنفیگریشن لکھیں → init → پلان → اپلائی کریں۔ ریاست ان چیزوں کو ٹریک کرتی ہے جو موجود ہے اور اسے لاکنگ کے ساتھ دور سے ذخیرہ کیا جانا چاہیے۔ ماڈیول دوبارہ استعمال کے قابل بناتے ہیں۔ متغیرات پیرامیٹرائز کنفیگریشنز۔ کلیدی اصول ہیں: بنیادی ڈھانچے کو کوڈ کے طور پر دیکھیں (ورژن کنٹرول؛ جائزہ؛ ٹیسٹ)؛ دستی طور پر ریاست میں کبھی ترمیم نہیں کریں؛ درخواست دینے سے پہلے منصوبہ بنائیں؛ تالا لگا کے ساتھ دور دراز حالت کا استعمال کریں؛ اور برقرار رکھنے کے لیے ماڈیولز کے ساتھ ساخت کی ترتیب۔
