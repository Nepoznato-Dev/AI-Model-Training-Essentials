# مقامی AI فن تعمیر
بڑے لینگویج ماڈلز کو مکمل طور پر ڈیوائس پر چلانے کے لیے ایک عملی گائیڈ — ہارڈ ویئر کے تحفظات، انفرنس انجن، میموری کی اصلاح، اور کنارے کی تعیناتی کے لیے سسٹم ڈیزائن۔
---

## AI مقامی طور پر کیوں چلائیں؟
- **رازداری**: کوئی ڈیٹا ڈیوائس سے نہیں نکلتا۔
- **لاگت**: فی ٹوکن کوئی API فیس نہیں۔
- **لیٹنسی**: قابل قیاس، نیٹ ورک سے پاک اندازہ۔
- **آف لائن دستیابی**: انٹرنیٹ کے بغیر کام کرتا ہے۔
- **کنٹرول**: ماڈل ورژن، کسٹمائزیشن، اور فائن ٹیوننگ پر مکمل کنٹرول۔
---

## ہارڈ ویئر کی ضروریات
### GPU میموری (VRAM)
سب سے اہم وسیلہ۔ میموری میں ماڈل کا سائز ≈ **پیرامیٹر × بائٹس فی پیرامیٹر**۔
| صحت سے متعلق | بائٹس فی پیرامیٹر | 3.8B ماڈل | 7B ماڈل | 13B ماڈل | 70B ماڈل |
|------------|---------|------------|------------|------------|
| FP32 | 4 | ~15 جی بی | ~28 جی بی | ~52 جی بی | ~280 جی بی |
| FP16 | 2 | ~7.6 جی بی | ~14 جی بی | ~26 جی بی | ~140 جی بی |
| INT8 (8 بٹ) | 1 | ~3.8 جی بی | ~7 جی بی | ~13 جی بی | ~70 جی بی |
| INT4 (4-bit) | 0.5 | ~1.9 جی بی | ~3.5 جی بی | ~6.5 جی بی | ~35 جی بی |
**عملی رہنما خطوط:**
- 8GB VRAM → 4-bit پر 7B ماڈلز تک۔
- 12GB VRAM → 4-bit پر 13B ماڈلز تک۔
- 24GB VRAM → 4-bit پر 70B ماڈلز (یا 8-bit پر 13B)۔
- Apple Silicon (یونیفائیڈ میموری) 64GB+ سسٹمز پر 70B ماڈل چلا سکتا ہے۔
### ریم (سسٹم میموری)
- CPU کا اندازہ لگانے کے لیے، آپ کو ماڈل لوڈ کرنے کے لیے کافی سسٹم RAM کی ضرورت ہے (VRAM نمبروں کی طرح)۔
- GPU تخمینہ کے لیے، VRAM پر آف لوڈ کرنے سے پہلے ماڈل کو میموری میں لوڈ کرنے کے لیے سسٹم RAM اہم ہے۔
### اسٹوریج
- مقداری ماڈل کے وزن میں چند جی بی لگتے ہیں (جیسے، 4 بٹ 7B ≈ 4 GB ڈسک پر)۔ متعدد ماڈلز کے لیے کم از کم 20-50 GB مفت کو یقینی بنائیں۔
### سی پی یو
- فوری پروسیسنگ (پری فل) اور سی پی یو آف لوڈنگ کے لیے، ایک جدید ملٹی کور سی پی یو مدد کرتا ہے۔
- ایپل ایم سیریز کی چپس LLMs کے لیے متحد میموری اور نیورل انجن کی وجہ سے بہترین کارکردگی رکھتی ہیں۔
---

## مقدار
مقدار کا تعین وزن کی عددی درستگی کو کم کرتا ہے، ڈرامائی طور پر میموری کو کم کرتا ہے اور تھوڑی درستگی کی قیمت پر رفتار میں اضافہ کرتا ہے۔
### مقبول فارمیٹس
| فارمیٹ | بٹس | تفصیل | عام استعمال |
|---------|------|---------------|-------------|
| **GGUF** | 4–8 | llama.cpp فارمیٹ، CPU/GPU ہائبرڈ کے لیے آپٹمائزڈ | مقامی اندازہ کے لیے بہترین |
| **GPTQ** | 4–8 | صرف GPU، CUDA پر موثر | NVIDIA GPUs کے لیے بہترین |
| **AWQ** | 4 | ایکٹیویشن سے آگاہ، صرف GPU | GPUs پر بیچ کے اندازہ کے لیے اچھا |
| **ONNX** | متغیر | معیاری، کراس پلیٹ فارم | پروڈکشن سرونگ |
### کوانٹائزیشن لیول کا انتخاب
- **Q8_0** (8 بٹ): معیار کا کم سے کم نقصان، سب سے بڑا سائز۔
- **Q6_K** (6 بٹ): اچھی کوالٹی، مہذب کمپریشن۔
- **Q5_K_M** (5-bit): عام میٹھی جگہ۔
- **Q4_K_M** (4-bit): سب سے چھوٹا، زیادہ تر کاموں کے لیے قابل قبول معیار۔
- **IQ4_XS** / **IQ3_XS**: 4/3 بٹس پر بہتر الجھن کے ساتھ بہتر کوانٹائزیشن۔
**انگوٹھے کا اصول:** معیار اور سائز کے اچھے توازن کے لیے Q4_K_M استعمال کریں۔ اگر آپ کے پاس اضافی VRAM ہے تو Q5 یا Q6 استعمال کریں۔

## انفرنس انجن (مقامی)
### llama.cpp
- C++ میں لکھا گیا۔
- GGUF فارمیٹ کو سپورٹ کرتا ہے۔
- CPU اور GPU (CUDA، Metal، OpenCL کے ذریعے) کے لیے آپٹمائزڈ۔
- بہت تیز، خاص طور پر CPU پر۔
- کمانڈ لائن، سرور موڈ، اور ازگر کی پابندیاں۔
**مثال کا حکم:**```bash
./llama-cli -m model.Q4_K_M.gguf -p "Tell me a joke" -n 100 -ngl 32
# -ngl 32 offloads 32 layers to GPU
```

### علامہ
- llama.cpp کو ایک سادہ CLI اور REST API کے ساتھ لپیٹتا ہے۔
- ماڈلز کو آٹو ڈاؤن لوڈ کرتا ہے، ان کا انتظام کرتا ہے۔
- پروٹو ٹائپنگ اور ڈیسک ٹاپ ایپس کے لیے بہترین۔
- سسٹم کے اشارے کے لئے اپنی مرضی کے مطابق ماڈل فائلوں کی حمایت کرتا ہے۔
```bash
ollama run phi3:3.8b
ollama run llama3:8b
```

### ایل ایم اسٹوڈیو
- ونڈوز، میک او ایس، لینکس کے لیے گرافیکل ڈیسک ٹاپ ایپ۔
- ایک کلک ڈاؤن لوڈ اور چیٹ انٹرفیس۔
- اوپن اے آئی کے موافق API کے ساتھ بلٹ ان لوکل سرور۔
- غیر تکنیکی صارفین اور فوری جانچ کے لیے اچھا ہے۔
### ہگنگ فیس ٹرانسفارمرز + بٹ سینڈ بائٹس
- HF ماڈلز کے لیے معیاری Python لائبریری۔
- 4 بٹ کوانٹائزیشن (`load_in_4bit=True`) کے لیے`bitsandbytes`استعمال کریں۔
- فائن ٹیوننگ کے لیے زیادہ لچکدار لیکن اندازہ کے لیے llama.cpp سے سست۔
### ExLlamaV2
- GPTQ اور AWQ کے لیے بہت تیز GPU تخمینہ۔
- NVIDIA GPUs پر بہترین کارکردگی۔
- بیچڈ نسل کی حمایت کرتا ہے۔
### ایم ایل ایکس (ایپل)
- ایم سیریز چپس کے لیے ایپل کا فریم ورک۔
- ایپل سلیکن کے لیے انتہائی موزوں۔
- Python API۔

## میموری کا انتظام
### سیاق و سباق کی ونڈو اور کے وی کیشے
کے وی کیشے سیاق و سباق میں ہر پرت اور ہر ٹوکن کے لیے کلیدی قدر کے جوڑے محفوظ کرتا ہے۔ یہ سیاق و سباق کی لمبائی کے ساتھ لکیری طور پر بڑھتا ہے۔
میموری لاگت ≈ 2 × تہوں × (KV ہیڈز × ہیڈ ڈیم) × ٹوکن × بائٹس فی قدر
8 KV ہیڈز اور 128 ہیڈ ڈیم والے 32 پرت والے ماڈل کے لیے، ہر ٹوکن کی قیمت ~32 × 8 × 128 × 2 بائٹس = 65 KB فی ٹوکن ہے۔ 128k ٹوکنز کے لیے، یہ صرف کیشے کے لیے ~8 GB ہے۔
### آف لوڈنگ کی حکمت عملی
- **پرت آف لوڈنگ**: کچھ پرتیں GPU پر رکھیں، دوسری CPU پر۔ خالص CPU سے تیز، VRAM کی کم ضرورت۔
- **ٹوکن اسٹریمنگ**: ٹوکنز پر ایک ساتھ عمل کرنے کی بجائے بتدریج عمل کریں۔
### فوری کیشنگ
پری فل فیز کی دوبارہ گنتی سے بچنے کے لیے اسی طرح کے اشارے پر KV کیچز کو دوبارہ استعمال کریں۔ کچھ فریم ورک اس کی حمایت کرتے ہیں (مثال کے طور پر، vLLM، llama.cpp`--prompt-cache`کے ساتھ)۔
### میموری میپڈ فائلیں۔
ماڈل کے وزن کو مکمل طور پر RAM میں لوڈ کیے بغیر براہ راست ڈسک سے لوڈ کریں (میموری لمیٹڈ سسٹمز پر بڑے ماڈلز کے لیے مفید)۔ llama.cpp بطور ڈیفالٹ میموری میپنگ کا استعمال کرتا ہے۔

## تعیناتی آرکیٹیکچرز
### سنگل ڈیوائس موڈ
ایک ماڈل ایک مشین (لیپ ٹاپ، اسمارٹ فون، ایج ڈیوائس) پر چلتا ہے۔ ذاتی معاونین، نوٹ لینے والی ایپس، کوڈ کی تکمیل کے لیے استعمال کیا جاتا ہے۔
### ہائبرڈ ایج کلاؤڈ
مقامی ماڈل عام سوالات کو ہینڈل کرتا ہے۔ پیچیدہ سوالات کے لیے کلاؤڈ ماڈل پر واپس جائیں۔ یہ دونوں جہانوں میں بہترین دیتا ہے — زیادہ تر کے لیے رفتار/نجی، ایج کیسز کے لیے صلاحیت۔
### تقسیم شدہ تخمینہ (ملٹی جی پی یو)
بڑے ماڈلز کے لیے، ایک سے زیادہ GPUs پر پرتوں کو تقسیم کریں (ٹینسر متوازی) یا آلات پر سیاق و سباق کو تقسیم کریں (پائپ لائن متوازی)۔`-ngl`کے ساتھ llama.cpp یا`--num-gpu-layers`کے ساتھ ExLlamaV2 استعمال کریں۔
### موبائل کی تعیناتی۔
- **Android**: JNI بائنڈنگز یا ML Kit کے ذریعے llama.cpp استعمال کریں۔
- **iOS**: Swift بائنڈنگز یا mlx کے ذریعے llama.cpp استعمال کریں۔
- **ویب**: WebLLM (OnNX رن ٹائم کے ذریعے WebGPU پر چلتا ہے) یا transformers.js استعمال کریں۔

## کارکردگی کی اصلاح
### فلیش توجہ
توجہ کی گنتی کو تیز کرتا ہے اور میموری کے استعمال کو کم کرتا ہے۔ llama.cpp، ExLlamaV2، اور جدید ٹرانسفارمرز لائبریریوں میں دستیاب ہے۔
### بیچ کا اندازہ
ایک ہی فارورڈ پاس میں متعدد اشارے پر کارروائی کریں۔ تھرو پٹ کو ڈرامائی طور پر بڑھاتا ہے۔`llama-batch`یا vLLM استعمال کریں۔
### جلد روکنا / ٹوکن بجٹنگ
غیر محدود پیداوار کو روکنے کے لیے زیادہ سے زیادہ ٹوکن بجٹ مقرر کریں۔
### قیاس آرائی پر مبنی ضابطہ کشائی
ٹوکن کی پیشن گوئی کرنے کے لیے ایک چھوٹا تیز ماڈل (ڈرافٹ) استعمال کریں، پھر متوازی طور پر بڑے ماڈل سے تصدیق کریں۔ 2–3× سپیڈ اپ حاصل کر سکتا ہے۔

## عملی سیٹ اپ گائیڈ
### 1. Ollama انسٹال کریں۔
```bash
curl -fsSL https://ollama.com/install.sh | sh
```

### 2. ایک ماڈل کھینچیں۔
```bash
ollama pull phi3:3.8b-q4_K_M
```

### 3. API کے ساتھ چلائیں۔
```bash
ollama serve
```

پھر`http://localhost:11434/api/generate`کو درخواستیں بھیجیں۔
### 4. ازگر کا انٹیگریشن
```python
import requests

response = requests.post(
    "http://localhost:11434/api/generate",
    json={"model": "phi3:3.8b", "prompt": "Hello", "stream": False}
)
print(response.json()["response"])
```

### 5. (متبادل) llama.cpp براہ راست استعمال کریں۔
```bash
# Download GGUF from Hugging Face
wget https://huggingface.co/microsoft/Phi-3-mini-4k-instruct-gguf/resolve/main/Phi-3-mini-4k-instruct-q4_K_M.gguf

# Run server
./llama-server -m Phi-3-mini-4k-instruct-q4_K_M.gguf --host 0.0.0.0 --port 8080
```

## نگرانی اور مشاہدہ
- GPU کے استعمال کو ٹریک کریں (Linux پر `nvidia-smi`، macOS پر ایکٹیویٹی مانیٹر)۔
- میموری کے استعمال کو ٹریک کریں (RAM اور VRAM)۔
- ٹریک ٹوکن فی سیکنڈ (تھرو پٹ)۔
- پہلے ٹوکن (لیٹنسی) کے لیے وقت کا پتہ لگائیں۔
- llama.cpp یا Ollama سے بلٹ ان لاگنگ استعمال کریں۔

## حدود اور تجارت
- **کوالٹی گیپ**: چھوٹے مقامی ماڈلز (3.8B–7B) عام طور پر بڑے کلاؤڈ ماڈلز (GPT-4، Claude 3.5) پیچیدہ استدلال پر کم کارکردگی کا مظاہرہ کرتے ہیں۔
- **نالج کٹ آف**: ٹریننگ کے وقت ماڈل کا علم منجمد ہوجاتا ہے۔ موجودہ معلومات کو انجیکشن لگانے کے لیے RAG کا استعمال کریں۔
- **کثیر لسانی**: چھوٹے ماڈلز میں کم کثیر لسانی صلاحیت ہو سکتی ہے۔
- **آل کا استعمال**: ایجنٹ ورک فلوز (فنکشن کالنگ) چھوٹے ماڈلز پر کم قابل اعتماد ہوسکتے ہیں۔
روزمرہ کے بہت سے کاموں (خلاصہ، سوال و جواب، کوڈ کی تکمیل، درجہ بندی) کے لیے مقامی ماڈل پہلے ہی کافی ہیں اور تیزی سے بہتر ہو رہے ہیں۔
