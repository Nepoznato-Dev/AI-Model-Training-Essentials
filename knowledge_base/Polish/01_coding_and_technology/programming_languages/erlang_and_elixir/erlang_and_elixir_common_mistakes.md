# Erlang i Elixir — częste błędy i anty-wzorce
Dokument ten kataloguje najczęstsze błędy, pułapki i anty-wzorce w Erlangu i Elixirze wraz z poprawkami.
---

## 1. Pojedyncze zadanie (Erlang)
```erlang
% ❌ WRONG — expecting reassignment
X = 1.
X = 2.  % exception! X is already bound to 1

% ✅ CORRECT — use different variables or shadow
X1 = 1,
X2 = X1 + 1,

% Or in a new scope (function clause)
f(X) ->
    X = compute(),  % new X in this scope
    use(X).
```

---

## 2. Brak łączenia/monitorowania procesów (Erlang)
```erlang
% ❌ WRONG — fire-and-forget process
spawn(fun() -> risky_operation() end).
% If it crashes, nobody knows

% ✅ CORRECT — link or monitor
Pid = spawn_link(fun() -> risky_operation() end),
% If it crashes, this process gets an exit signal

% ✅ CORRECT — monitor for non-linked observation
Ref = monitor(process, Pid),
receive
    {'DOWN', Ref, process, Pid, Reason} ->
        handle_crash(Reason)
end
```

## 3. Wywołanie GenServer bez limitu czasu (eliksir)
```elixir
# ❌ WRONG — default 5s timeout
GenServer.call(server, :slow_operation)
# crashes with :timeout if operation takes > 5s

# ✅ CORRECT — explicit timeout
GenServer.call(server, :slow_operation, :infinity)
# or appropriate timeout
GenServer.call(server, :operation, 30_000)
```

---

## 4. Dopasowanie wzorca w`receive`bez przekroczenia limitu czasu (Erlang)
```erlang
% ❌ WRONG — blocks forever
receive
    {ok, Data} -> process(Data)
end.

% ✅ CORRECT — always use timeout
receive
    {ok, Data} -> process(Data)
after 5000 ->
    handle_timeout()
end.
```

## 5. Nieużywanie`with`do dopasowywania wzorców zagnieżdżonych (eliksir)
```elixir
# ❌ WRONG — deeply nested case
case authenticate(user) do
  {:ok, token} ->
    case authorize(token) do
      {:ok, perms} ->
        case fetch_data(perms) do
          {:ok, data} -> {:ok, data}
          {:error, e} -> {:error, e}
        end
      {:error, e} -> {:error, e}
    end
  {:error, e} -> {:error, e}
end

# ✅ CORRECT — use with
with {:ok, token} <- authenticate(user),
     {:ok, perms} <- authorize(token),
     {:ok, data} <- fetch_data(perms) do
  {:ok, data}
end
```

## 6. Anty-wzorzec: długotrwałe wywołania zwrotne serwera GenServer
```elixir
# ❌ WRONG — blocking GenServer
def handle_call(:slow_op, _from, state) do
  result = :timer.sleep(10_000)  # blocks the server!
  {:reply, result, state}
end

# ✅ CORRECT — async work
def handle_call(:slow_op, from, state) do
  Task.start(fn ->
    result = compute()
    GenServer.reply(from, result)
  end)
  {:noreply, state}
end
```

## Streszczenie
Pułapki Erlang/Elixir: zmienne są przypisywane pojedynczo, procesy wymagają łączy/monitorów, wywołania GenServer wymagają jawnych limitów czasu,`receive`blokuje na zawsze bez limitu czasu, a wywołania zwrotne GenServer nie powinny blokować. Sposób BEAM jest następujący: pozwolić mu się zawiesić (z nadzorem), użyć`with`do czystego dopasowywania wzorców, zapewnić szybkie wywołania zwrotne GenServer i zawsze obsługiwać awarie procesów.
