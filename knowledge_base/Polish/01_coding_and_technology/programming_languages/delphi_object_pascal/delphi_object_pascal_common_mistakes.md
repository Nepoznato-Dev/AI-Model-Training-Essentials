# Delphi / Object Pascal — częste błędy i anty-wzorce
Dokument ten kataloguje najczęstsze błędy, pułapki i antywzorce w Delphi/Object Pascal wraz z poprawkami.
---

## 1. Nieuwalnianie obiektów (wycieki pamięci)
```pascal
// ❌ WRONG — object never freed
procedure Process;
var
  List: TStringList;
begin
  List := TStringList.Create;
  List.Add('data');
  // List is never freed!
end;

// ✅ CORRECT — try/finally
procedure Process;
var
  List: TStringList;
begin
  List := TStringList.Create;
  try
    List.Add('data');
  finally
    List.Free;
  end;
end;
```

---

## 2.`=`kontra `:=`
```pascal
// ❌ WRONG — confusing assignment and comparison
if x = 5 then  // comparison, not assignment!
  x := 10;     // this is assignment
```

---

## 3. Indeksowanie ciągów (na podstawie 1)
```pascal
// ❌ WRONG — 0-based indexing
var s: string;
s := 'Hello';
s[0]  // Error or unexpected!

// ✅ CORRECT — Delphi strings are 1-indexed
s[1]  // 'H'
```

---

## 4. Nieużywanie`inherited`w konstruktorach
```pascal
// ❌ WRONG — skipping parent constructor
constructor TMyClass.Create(AName: string);
begin
  FName := AName;  // parent's Create never called!
end;

// ✅ CORRECT — call inherited
constructor TMyClass.Create(AName: string);
begin
  inherited Create;  // or inherited Create(AName)
  FName := AName;
end;
```

---

## 5. Anty-wzorzec: Logika biznesowa w formularzach
```pascal
// ❌ WRONG — all logic in form events
procedure TForm1.btnSaveClick(Sender: TObject);
begin
  // database access, validation, email sending, all here
end;

// ✅ CORRECT — separate business logic
procedure TForm1.btnSaveClick(Sender: TObject);
begin
  UserService.Save(edtName.Text, edtEmail.Text);
end;
```

---

## Streszczenie
Pułapki Delphi: zawsze uwalniaj obiekty za pomocą try/finally, odróżniaj`=`(porównanie) od`:=`(przypisanie), ciągi znaków są indeksowane o 1, wywołują`inherited`w konstruktorach i oddzielają logikę biznesową od interfejsu użytkownika. Struktura Delphi VCL/FMX nagradza czyste oddzielanie problemów.
