# Scratch — typowe błędy i anty-wzorce
Dokument ten kataloguje najczęstsze błędy i pułapki w Scratchu wraz z poprawkami.
---

## 1. Nieużywanie przycisku „Stop” do kończenia skryptów
```
❌ WRONG — script keeps running after game over
when green flag clicked
forever
    if <touching [edge v]?> then
        say [Game Over]
        // script continues!
    end
end

✅ CORRECT — use stop block
when green flag clicked
forever
    if <touching [edge v]?> then
        say [Game Over]
        stop [all v]
    end
end
```

---

## 2. Zamieszanie z klonami
```
❌ WRONG — modifying original sprite thinking it's a clone
when I start as a clone
change [score v] by (1)  // modifies global variable
// but "when green flag clicked" also runs on clones!

✅ CORRECT — separate clone logic from original
when green flag clicked
// setup code only

when I start as a clone
// clone-specific behavior only
```

---

## 3. Czas transmisji
```
❌ WRONG — expecting immediate response
broadcast [jump v]
// code continues immediately, doesn't wait!

✅ CORRECT — use broadcast and wait
broadcast [jump v] and wait
// now waits for all recipients to finish
```

---

## 4. Zmienny zakres
```
❌ WRONG — using global variable when local needed
// All sprites share the variable "my variable"
// Sprite A changes it, Sprite B sees the change

✅ CORRECT — use "For this sprite only"
// Create variable as "For this sprite only"
// Each sprite has its own copy
```

---

## 5. Nieskończone pętle bez wydajności
```
❌ WRONG — freezes the program
when green flag clicked
forever
    // no wait or visual change
    // locks up the interface
end

✅ CORRECT — add a small wait
when green flag clicked
forever
    // do work
    wait (0.1) seconds
end
```

---

## Streszczenie
Pułapki Scratch: zawsze używaj „stop”, aby zakończyć grę, oddzielaj logikę klonowania od oryginalnej logiki sprite’ów, używaj „rozgłaszania i czekania” do synchronicznej komunikacji, w razie potrzeby używaj zmiennych specyficznych dla duszka i dodawaj oczekiwania w pętlach wiecznych, aby zapobiec zawieszaniu się. Scratch uczy podstawowych pojęć — szanuj model sterowany zdarzeniami.
