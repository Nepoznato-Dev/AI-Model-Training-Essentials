# নিরাপত্তার সর্বোত্তম অভ্যাস
অ্যাপ্লিকেশন, অবকাঠামো এবং ডেটা সুরক্ষিত করার জন্য একটি ব্যবহারিক নির্দেশিকা — উন্নয়ন থেকে উৎপাদন পর্যন্ত।
---

## OWASP শীর্ষ 10 (2021) — ওভারভিউ
1. **ব্রোকেন এক্সেস কন্ট্রোল**: ব্যবহারকারীরা এমন রিসোর্স অ্যাক্সেস করতে পারে যা তাদের উচিত নয়।
2. **ক্রিপ্টোগ্রাফিক ব্যর্থতা**: দুর্বল বা অনুপস্থিত এনক্রিপশন।
3. **ইঞ্জেকশন**: SQL, NoSQL, OS কমান্ড, বা LDAP ইনজেকশন।
4. **অনিরাপদ নকশা**: স্থাপত্যের ত্রুটি।
5. **নিরাপত্তা ভুল কনফিগারেশন**: ডিফল্ট পাসওয়ার্ড, ওপেন পোর্ট, ভার্বোস ত্রুটি।
6. **সুরক্ষিত এবং পুরানো উপাদান**: নির্ভরশীলতায় পরিচিত CVE.
7. **শনাক্তকরণ এবং প্রমাণীকরণ ব্যর্থতা**: দুর্বল পাসওয়ার্ড, সেশন অব্যবস্থাপনা।
8. **সফ্টওয়্যার এবং ডেটা ইন্টিগ্রিটি ব্যর্থতা**: সাপ্লাই চেইন আক্রমণ, স্বাক্ষরবিহীন আপডেট।
9. **নিরাপত্তা লগিং এবং মনিটরিং ব্যর্থতা**: লঙ্ঘনের কোন সনাক্তকরণ নেই।
10. **সার্ভার-সাইড অনুরোধ জালিয়াতি (SSRF): অভ্যন্তরীণ সিস্টেমে অনুরোধ করার জন্য সার্ভারের অপব্যবহার।

## ইনপুট যাচাইকরণ এবং আউটপুট এনকোডিং
### বৈধকরণের নিয়ম
- **হোয়াইটলিস্ট > ব্ল্যাকলিস্ট**: পরিচিত খারাপ প্যাটার্ন ব্লক করার পরিবর্তে অনুমোদিত প্যাটার্ন (যেমন, ইমেলের জন্য regex) সংজ্ঞায়িত করুন।
- **দৈর্ঘ্য সীমা**: বাফার ওভারফ্লো এবং DoS প্রতিরোধ করতে সর্বাধিক দৈর্ঘ্য প্রয়োগ করুন।
- **টাইপ চেকিং**: নিশ্চিত করুন যে পূর্ণসংখ্যাগুলি পূর্ণসংখ্যা, বুলিয়ানগুলি বুলিয়ান।
- **সু-পরীক্ষিত লাইব্রেরি ব্যবহার করুন**: ইমেল, URL, এবং তারিখ যাচাইয়ের জন্য, স্ট্যান্ডার্ড লাইব্রেরি ব্যবহার করুন (যেমন, পাইথনে `email-validator`, নোডে `validator.js`)।
### আউটপুট এনকোডিং
- **HTML এনকোডিং**:`<`,`>`,`&`,`"`,`'`XSS প্রতিরোধ করতে এনকোড করুন৷
- **SQL প্যারামিটারাইজেশন**: কখনোই এসকিউএল কোয়েরিতে ব্যবহারকারীর ইনপুট সংযুক্ত করবেন না। প্যারামিটারাইজড প্রশ্ন (প্রস্তুত বিবৃতি) বা একটি ORM ব্যবহার করুন।
- **শেল এস্কেপিং**: ব্যবহারকারীর ইনপুট থেকে শেল কমান্ড তৈরি করা এড়িয়ে চলুন; যদি অনিবার্য হয়,`shlex.quote()`বা অনুরূপ ব্যবহার করুন।

## প্রমাণীকরণ এবং অনুমোদন
### পাসওয়ার্ড ব্যবস্থাপনা
- **হ্যাশিং**: একটি শক্তিশালী, ধীর হ্যাশিং অ্যালগরিদম সহ পাসওয়ার্ড সংরক্ষণ করুন: **Argon2id** (পছন্দের), **bcrypt**, **স্ক্রিপ্ট**, বা **PBKDF2**।
- **সল্টিং**: প্রতি ব্যবহারকারীর জন্য একটি অনন্য লবণ যোগ করুন।
- **ন্যূনতম দৈর্ঘ্য**: কমপক্ষে 12-16 অক্ষর প্রয়োগ করুন।
- **MFA (মাল্টি-ফ্যাক্টর প্রমাণীকরণ)**: সংবেদনশীল ক্রিয়াকলাপের জন্য একটি দ্বিতীয় ফ্যাক্টর (TOTP, SMS, হার্ডওয়্যার কী) প্রয়োজন৷
- **রেট সীমিত**: লগইন এন্ডপয়েন্টে ব্রুট-ফোর্স প্রচেষ্টা প্রতিরোধ করুন (যেমন, প্রতি আইপি/ব্যবহারকারী প্রতি 5 মিনিটে 5টি প্রচেষ্টা)।
### সেশন ম্যানেজমেন্ট
- সেশন টোকেনগুলির জন্য নিরাপদ, শুধুমাত্র-এইচটিটিপি, একইসাইট কুকিজ ব্যবহার করুন।
- উপযুক্ত মেয়াদ শেষ হওয়ার সময় সেট করুন।
- লগআউট এবং পাসওয়ার্ড পরিবর্তনের সময় সেশনগুলি বাতিল করুন৷
- URL-এ সেশন আইডি প্রকাশ করা এড়িয়ে চলুন।
### OAuth2 / OIDC
- সু-প্রতিষ্ঠিত লাইব্রেরি ব্যবহার করুন (যেমন, Authlib, PyJWT, Passport.js, স্প্রিং সিকিউরিটি)।
- আইডি টোকেনগুলি পুঙ্খানুপুঙ্খভাবে যাচাই করুন (স্বাক্ষর, ইস্যুকারী, দর্শক, মেয়াদ)।
- CSRF প্রতিরোধ করতে রাষ্ট্রীয় পরামিতি ব্যবহার করুন।
- গ্রাহকের গোপনীয়তা গোপন রাখুন।
### JWT (JSON ওয়েব টোকেন)
- **সাইন**: ভালো নিরাপত্তার জন্য RS256 বা ES256 (অসমমিত) ব্যবহার করুন; HS256 (সিমেট্রিক) গ্রহণযোগ্য যদি ভাগ করা গোপনীয়তাগুলি ভালভাবে পরিচালিত হয়।
- **প্রমাণিত করুন**: সর্বদা স্বাক্ষর, ইস্যুকারী (`iss`), দর্শক (`aud`), এবং মেয়াদ (`exp`) যাচাই করুন৷
- **সম্পূর্ণ মেয়াদ সংক্ষিপ্ত রাখুন**: অ্যাক্সেস টোকেনের জন্য 15-60 মিনিট; দীর্ঘ সেশনের জন্য রিফ্রেশ টোকেন ব্যবহার করুন।
- **নিরাপদভাবে সঞ্চয় করুন**: JWTs কখনই লোকাল স্টোরেজে সংরক্ষণ করবেন না (XSS-এর জন্য ঝুঁকিপূর্ণ); পরিবর্তে HTTP-শুধু কুকি ব্যবহার করুন।

## API নিরাপত্তা
### প্রমাণীকরণ
- সর্বদা API কল প্রমাণীকরণ করুন (পাবলিক এন্ডপয়েন্ট ব্যতীত)।
- মৌলিক প্রমাণীকরণের চেয়ে API কী বা OAuth2 টোকেন পছন্দ করুন (যা প্রতিটি অনুরোধে শংসাপত্র পাঠায়)।
### রেট লিমিটিং এবং থ্রটলিং
- অপব্যবহার এবং DoS প্রতিরোধ করতে প্রতি-ব্যবহারকারী এবং প্রতি-আইপি হারের সীমা প্রয়োগ করুন।
- একটি`Retry-After`হেডার সহ`429 Too Many Requests`ফেরত দিন।
### CORS (ক্রস-অরিজিন রিসোর্স শেয়ারিং)
- শুধুমাত্র নির্দিষ্ট উত্সের অনুমতি দিন (কখনও`*`উত্পাদনে নয়)।
- সার্ভার সাইডে`Origin`হেডার যাচাই করুন।
### ইনপুট যাচাইকরণ
- হেডার এবং বডি সহ সমস্ত অনুরোধের পরামিতি যাচাই করুন।
- অপ্রত্যাশিত ক্ষেত্রগুলি প্রত্যাখ্যান করুন ( JSON স্কিমাতে`"strict": true`বা `additionalProperties: false`)।
### HTTPS/TLS
- উৎপাদনে HTTPS প্রয়োগ করুন।
- ব্রাউজারগুলিকে HTTPS ব্যবহার করতে বাধ্য করতে HSTS (HTTP স্ট্রিক্ট ট্রান্সপোর্ট সিকিউরিটি) ব্যবহার করুন৷
- TLS 1.2 বা 1.3 ব্যবহার করুন (TLS 1.0/1.1 নিষ্ক্রিয় করুন)।

## গোপন ব্যবস্থাপনা
### কখনই হার্ডকোড সিক্রেটস করবেন না
- উৎস নিয়ন্ত্রণে গোপনীয়তা (এপিআই কী, পাসওয়ার্ড, ডাটাবেস ইউআরএল) প্রতিশ্রুতিবদ্ধ করবেন না।
- পরিবেশের ভেরিয়েবল বা গোপন ব্যবস্থাপনার সরঞ্জাম ব্যবহার করুন।
### টুলস
| টুল | বর্ণনা |
|------|---------------|
| **হাশিকর্প ভল্ট** | এন্টারপ্রাইজ-গ্রেড, গতিশীল গোপনীয়তা |
| **AWS সিক্রেটস ম্যানেজার / Azure Key Vault / GCP সিক্রেট ম্যানেজার** | মেঘ-দেশী |
| **এসওপিএস** | ফাইলগুলিতে গোপনীয়তাগুলি এনক্রিপ্ট করুন এবং তাদের প্রতিশ্রুতিবদ্ধ করুন (KMS বা GPG সহ) |
| **ডকার গোপনীয়তা** | ঝাঁক মোডের জন্য; কুবারনেটেস সিক্রেটস (বাহ্যিক সিক্রেটস স্টোর সিএসআই ড্রাইভার বিবেচনা করুন) |
### ঘূর্ণন
- নিয়মিত গোপনীয়তা এবং পরিষেবা অ্যাকাউন্টগুলি ঘোরান৷
- যেখানে সম্ভব স্বয়ংক্রিয় ঘূর্ণন।

## নির্ভরতা ব্যবস্থাপনা
### দুর্বলতা স্ক্যানিং
| ভাষা/প্ল্যাটফর্ম | টুলস |
|------|---------|
| **পাইথন** | `safety`,`pip-audit`,`bandit`|
| **নোড** | `npm audit`,`yarn audit`,`snyk`|
| **মরিচা** | `cargo audit`|
| **যাও** | `govulncheck`|
| **সাধারণ** | `Dependabot`(GitHub),`Renovate`,`Trivy`|
### প্যাচিং
- প্যাচ করা সংস্করণে নির্ভরতা আপডেট রাখুন।
- ছোট/প্যাচ আপডেটের জন্য স্বয়ংক্রিয় পুল অনুরোধ সেট আপ করুন।
- পরিবর্তন পরিবর্তনের জন্য চেঞ্জলগ পর্যালোচনা করুন।
### সাপ্লাই চেইন ইন্টিগ্রিটি
- পুনরুত্পাদনযোগ্য বিল্ডগুলি নিশ্চিত করতে প্যাকেজ লকফাইলগুলি (`package-lock.json`,`Cargo.lock`,`go.sum`) ব্যবহার করুন৷
- ডাউনলোড করা নির্ভরতার চেকসাম যাচাই করুন।
- অফিসিয়াল রেজিস্ট্রি পছন্দ করুন এবং শুধুমাত্র যাচাইকৃত প্রকাশকদের বিশ্বাস করুন।

## অবকাঠামোগত নিরাপত্তা
### ফায়ারওয়াল
- স্পষ্টভাবে প্রয়োজনীয় (যেমন, 80, 443) ছাড়া সমস্ত অন্তর্মুখী পোর্ট ব্লক করুন।
- নির্দিষ্ট আইপি রেঞ্জে SSH অ্যাক্সেস সীমিত করুন (অথবা একটি VPN/বেসশন হোস্ট ব্যবহার করুন)।
- সূক্ষ্ম নিয়ন্ত্রণের জন্য নিরাপত্তা গোষ্ঠী (AWS) বা NSGs (Azure) ব্যবহার করুন।
### ওএস হার্ডেনিং
- নিয়মিত নিরাপত্তা আপডেট প্রয়োগ করুন (`sudo apt upgrade`, `yum update`)।
- অপ্রয়োজনীয় পরিষেবা এবং ডিফল্ট অ্যাকাউন্টগুলি অক্ষম করুন।
- SSH-এ ব্রুট-ফোর্স প্রচেষ্টা ব্লক করতে fail2ban ব্যবহার করুন।
- কঠোর SSH: রুট লগইন অক্ষম করুন, কী-ভিত্তিক প্রমাণীকরণ ব্যবহার করুন, ডিফল্ট পোর্ট পরিবর্তন করুন (ঐচ্ছিক)।
### নেটওয়ার্ক সেগমেন্টেশন
- ইন্টারনেট অ্যাক্সেস ছাড়াই ব্যক্তিগত সাবনেটে ডেটাবেস এবং ক্যাশে রাখুন।
- জনসাধারণের মুখোমুখি পরিষেবাগুলির জন্য একটি DMZ ব্যবহার করুন৷
- নেটওয়ার্ক অ্যাক্সেসে ন্যূনতম বিশেষাধিকারের নীতিটি প্রয়োগ করুন।
### অবকাঠামোর গোপনীয়তা
- এনক্রিপ্ট না করা পর্যন্ত সিআই/সিডি এনভায়রনমেন্ট ভেরিয়েবলে গোপনীয়তা সংরক্ষণ করবেন না।
- দীর্ঘস্থায়ী কীগুলির পরিবর্তে EC2/VM দৃষ্টান্তগুলির জন্য ক্লাউড প্রদানকারীর IAM ভূমিকাগুলি ব্যবহার করুন৷

## লগিং এবং মনিটরিং
### কি লগ করবেন
- প্রমাণীকরণ ঘটনা (সফল/ব্যর্থতা)।
- অ্যাক্সেস নিয়ন্ত্রণ সিদ্ধান্ত (অনুমোদন ব্যর্থতা)।
- অ্যাডমিন অ্যাকশন (ব্যবহারকারী তৈরি, মুছে ফেলা, অনুমতি পরিবর্তন)।
- ডাটাবেস স্কিমা পরিবর্তন.
- সিস্টেম ত্রুটি এবং ব্যতিক্রম.
- API অনুরোধ এবং প্রতিক্রিয়া (সংবেদনশীল ডেটা রিডাক্ট করুন)।
### কি লগ না
- পাসওয়ার্ড, গোপনীয়তা, টোকেন, PII (ব্যক্তিগত শনাক্তযোগ্য তথ্য) যদি না হ্যাশ/সংশোধন করা হয়।
- সম্পূর্ণ ক্রেডিট কার্ড নম্বর।
### সতর্কতা
- এর জন্য সতর্কতা সেট আপ করুন:
  - একাধিক ব্যর্থ লগইন (সম্ভাব্য ব্রুট ফোর্স)।
  - অস্বাভাবিক অ্যাক্সেস প্যাটার্ন (যেমন, নতুন অবস্থান থেকে, বিজোড় সময়ে)।
  - নতুন অ্যাডমিন অ্যাকাউন্ট তৈরি করা হয়েছে।
  - উচ্চ ত্রুটির হার বা লেটেন্সি স্পাইক।
- উন্নত পারস্পরিক সম্পর্কের জন্য একটি SIEM (নিরাপত্তা তথ্য এবং ইভেন্ট ম্যানেজমেন্ট) ব্যবহার করুন।
### লগ ধরে রাখা
- নিয়ন্ত্রক প্রয়োজনীয়তার উপর নির্ভর করে কমপক্ষে 30-90 দিনের জন্য লগ ধরে রাখুন।
- একটি কেন্দ্রীভূত, টেম্পার-প্রকাশ্য সিস্টেমে লগ সংরক্ষণ করুন (যেমন, ELK স্ট্যাক, স্প্লঙ্ক, ডেটাডগ)।

## নিরাপদ উন্নয়ন জীবনচক্র (SDL)
1. **প্রশিক্ষণ**: নিশ্চিত করুন যে বিকাশকারীরা সাধারণ দুর্বলতাগুলি বোঝেন৷
2. **হুমকি মডেলিং**: নকশার প্রথম দিকে সম্ভাব্য হুমকি চিহ্নিত করুন।
3. **নিরাপদ কোডিং মান**: লিন্টার এবং কোড পর্যালোচনা চেকলিস্টের মাধ্যমে প্রয়োগ করুন।
4. **SAST** (স্ট্যাটিক অ্যাপ্লিকেশন সিকিউরিটি টেস্টিং): দুর্বলতার জন্য সোর্স কোড স্ক্যান করুন (সোনারকিউব, কোডকিউএল)।
5. **DAST** (ডাইনামিক অ্যাপ্লিকেশন সিকিউরিটি টেস্টিং): চলমান অ্যাপ্লিকেশন স্ক্যান করুন (OWASP ZAP, Burp Suite)।
6. **SCA** (সফ্টওয়্যার রচনা বিশ্লেষণ): স্ক্যান নির্ভরতা।
7. **পেনিট্রেশন টেস্টিং**: নিয়মিত নৈতিক হ্যাকিং ব্যায়াম।
8. **বাগ বাউন্টি**: বহিরাগত গবেষকদের দায়িত্বশীলতার সাথে দুর্বলতা খুঁজে পেতে উত্সাহিত করুন৷
9. **ঘটনার প্রতিক্রিয়া পরিকল্পনা**: যখন একটি লঙ্ঘন সনাক্ত করা হয় তার জন্য একটি পরিষ্কার পরিকল্পনা রাখুন।

## জরুরী চেকলিস্ট (যখন লঙ্ঘনের সন্দেহ হয়)
1. **আতঙ্কিত হবেন না** — তবে দ্রুত কাজ করুন।
2. প্রভাবিত সিস্টেমগুলিকে **বিচ্ছিন্ন করুন (প্রয়োজন হলে নেটওয়ার্ক থেকে সংযোগ বিচ্ছিন্ন করুন)।
3. **প্রমাণ সংরক্ষণ করুন**: ক্যাপচার লগ, মেমরি ডাম্প, এবং ডিস্ক ছবি.
4. **শনাক্ত করুন** সুযোগ: কোন সিস্টেম, কোন ডেটা।
5. **ঘোরান** সমস্ত আপসকৃত শংসাপত্র এবং গোপনীয়তা।
6. **প্যাচ** দুর্বলতা।
7. **অবহিত করুন** প্রভাবিত ব্যবহারকারী এবং নিয়ন্ত্রক সংস্থা যদি প্রয়োজন হয় (আইনি সময়সীমার মধ্যে)।
8. মূল কারণ বুঝতে এবং প্রক্রিয়াগুলিকে উন্নত করতে **একটি পোস্টমর্টেম পরিচালনা করুন।
