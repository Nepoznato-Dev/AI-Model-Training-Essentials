# নেটওয়ার্কিং বেসিক
বিকাশকারী এবং সিসাডমিনদের জন্য একটি ব্যবহারিক রেফারেন্স — মূল ধারণা, প্রোটোকল, কমান্ড এবং সমস্যা সমাধান।

## OSI মডেল (7 স্তর)
নেটওয়ার্ক যোগাযোগ বোঝার জন্য একটি ধারণাগত কাঠামো।
| স্তর | নাম | ফাংশন | উদাহরণ প্রোটোকল |
|---------|------|------------|------|
| 7 | আবেদন | শেষ ব্যবহারকারী পরিষেবা | HTTP, HTTPS, FTP, SMTP, DNS, SSH |
| 6 | উপস্থাপনা | ডেটা ফরম্যাটিং, এনক্রিপশন, কম্প্রেশন | TLS, JPEG, ASCII |
| 5 | অধিবেশন | সংযোগ ব্যবস্থাপনা | NetBIOS, RPC |
| 4 | পরিবহন | এন্ড-টু-এন্ড ডেলিভারি, ত্রুটি সংশোধন, প্রবাহ নিয়ন্ত্রণ | TCP, UDP |
| 3 | নেটওয়ার্ক | রাউটিং, ঠিকানা | IP, ICMP, OSPF, BGP |
| 2 | ডেটা লিঙ্ক | ফ্রেমিং, ত্রুটি সনাক্তকরণ, MAC ঠিকানা | ইথারনেট, ওয়াই-ফাই, পিপিপি |
| 1 | শারীরিক | কাঁচা বিট ট্রান্সমিশন | ইথারনেট কেবল, ফাইবার অপটিক্স, রেডিও তরঙ্গ |
অনুশীলনে, **TCP/IP মডেল** (4 স্তর: লিঙ্ক, ইন্টারনেট, পরিবহন, অ্যাপ্লিকেশন) ইন্টারনেটের জন্য বেশি ব্যবহৃত হয়।

## আইপি অ্যাড্রেসিং
### IPv4
- 32-বিট ঠিকানা, চারটি অক্টেট হিসাবে লেখা:`192.168.1.1`
- মোট: ~4.3 বিলিয়ন ঠিকানা (কিন্তু অনুশীলনে ক্লান্ত)।
### IPv6
- 128-বিট ঠিকানা, হেক্সে লেখা:`2001:0db8:85a3:0000:0000:8a2e:0370:7334`
- মোট: 2¹²⁸ ঠিকানা (ব্যবহারিকভাবে অসীম)।
### ব্যক্তিগত আইপি রেঞ্জ (RFC 1918)
এগুলি ইন্টারনেটে রাউটেবল নয়; স্থানীয় নেটওয়ার্কের ভিতরে ব্যবহৃত:
-`10.0.0.0/8`(10.0.0.0 – 10.255.255.255)
-`172.16.0.0/12`(172.16.0.0 – 172.31.255.255)
-`192.168.0.0/16`(192.168.0.0 - 192.168.255.255)
### CIDR স্বরলিপি
`192.168.1.0/24`মানে প্রথম 24 বিট হল নেটওয়ার্ক উপসর্গ; শেষ 8 বিট হোস্ট. এতে`192.168.1.0`থেকে`192.168.1.255`ঠিকানা অন্তর্ভুক্ত রয়েছে।

## DNS (ডোমেন নেম সিস্টেম)
আইপি ঠিকানায় ডোমেন নাম (যেমন,`example.com`) ম্যাপ করে।
### রেকর্ডের ধরন
| প্রকার | উদ্দেশ্য |
|------|---------|
| **A** | IPv4 ঠিকানায় ম্যাপ ডোমেন |
| **এএএএ** | IPv6 ঠিকানায় ম্যাপ ডোমেন |
| **CNAME** | অন্য ডোমেইন নামের উপনাম |
| **MX** | মেইল এক্সচেঞ্জ সার্ভার |
| **TXT** | নির্বিচারে পাঠ্য (SPF, DKIM, যাচাইকরণ) |
| **NS** | ডোমেনের জন্য নেমসার্ভার |
| **SRV** | পরিষেবা রেকর্ড (যেমন, এসআইপির জন্য) |
### সাধারণ সরঞ্জাম```bash
dig example.com            # DNS lookup (detailed)
nslookup example.com       # DNS lookup (simpler)
host example.com           # Quick lookup
dig -x 8.8.8.8             # Reverse lookup (IP to name)
```

## HTTP এবং HTTPS
### HTTP পদ্ধতি
| পদ্ধতি | বর্ণনা |
|---------|-------------|
| **পান** | একটি সম্পদ পুনরুদ্ধার করুন (অদম্য, নিরাপদ) |
| **পোস্ট** | তথ্য জমা দিন (অদম্য নয়) |
| **পুট** | একটি সংস্থান আপডেট/প্রতিস্থাপন করুন (আদমশক্তিহীন) |
| **প্যাচ** | আংশিক আপডেট |
| **মুছুন** | একটি সম্পদ সরান (অদম্য) |
### স্ট্যাটাস কোড
| কোড | অর্থ |
|------|---------|
| **1xx** | তথ্যমূলক (100 চালিয়ে যান) |
| **2xx** | সাফল্য (200 ঠিক আছে, 201 তৈরি, 204 কোন বিষয়বস্তু নেই) |
| **3xx** | পুনঃনির্দেশ (301 স্থায়ীভাবে সরানো হয়েছে, 302 পাওয়া গেছে, 304 সংশোধন করা হয়নি) |
| **4xx** | ক্লায়েন্ট ত্রুটি (400 খারাপ অনুরোধ, 401 অননুমোদিত, 403 নিষিদ্ধ, 404 পাওয়া যায়নি, 429 অনেক অনুরোধ) |
| **5xx** | সার্ভার ত্রুটি (500 অভ্যন্তরীণ সার্ভার ত্রুটি, 502 খারাপ গেটওয়ে, 503 পরিষেবা অনুপলব্ধ) |
### শিরোনাম
| হেডার | উদ্দেশ্য |
|---------|---------|
| `Content-Type`| মিডিয়া প্রকার (`application/json`,`text/html`) |
| `Authorization`| শংসাপত্র (যেমন,`Bearer <token>`) |
| `Cache-Control`| ক্যাশিং নীতি |
| CORS হেডার |  `Access-Control-Allow-Origin`, ইত্যাদি |

## TLS/SSL
HTTP ট্রাফিক এনক্রিপ্ট করে (HTTPS = HTTP ওভার TLS)।
- সার্টিফিকেট অথরিটি (CAs) থেকে সার্টিফিকেট সার্ভারকে প্রমাণীকরণ করে।
- ক্লায়েন্ট সাইডে সার্টিফিকেট চেইন এবং হোস্টনাম যাচাই করুন।

## ফায়ারওয়াল এবং NAT
### ফায়ারওয়াল
- নিয়মের উপর ভিত্তি করে ট্র্যাফিক ফিল্টার করে (সোর্স আইপি, ডেস্ট আইপি, পোর্ট, প্রোটোকল)।
- স্টেটফুল ফায়ারওয়াল ট্র্যাক কানেকশন স্টেট।
### NAT (নেটওয়ার্ক ঠিকানা অনুবাদ)
- ইন্টারনেট অ্যাক্সেসের জন্য ব্যক্তিগত আইপিগুলিকে একটি পাবলিক আইপিতে অনুবাদ করে৷
- পোর্ট ফরওয়ার্ডিং: একটি অভ্যন্তরীণ হোস্ট/পোর্টে একটি পাবলিক পোর্ট ম্যাপ করে।

## সাধারণ নেটওয়ার্কিং কমান্ড
### সংযোগ পরীক্ষা
```bash
ping google.com            # ICMP echo request
ping -c 4 8.8.8.8          # ping 4 times
traceroute google.com      # Trace the route (Linux)
tracert google.com         # Windows version
```

### রাউটিং
```bash
ip route show              # Linux: routing table
route -n                   # Older Linux
netstat -r                 # Windows/Mac
```

### নেটওয়ার্ক ইন্টারফেস
```bash
ip addr show               # List interfaces and IPs
ifconfig                   # Older command
```

### DNS
```bash
dig example.com
nslookup example.com
host example.com
```

### একটি বন্দরের সাথে সংযোগ
```bash
nc -zv google.com 443      # Netcat: check if port 443 is open
telnet google.com 443      # Telnet to port
curl -v https://google.com # Verbose output
```

### ফায়ারওয়াল (লিনাক্স iptables/nftables)
```bash
sudo ufw status            # Ubuntu: simple firewall
sudo iptables -L -n        # List rules
```

### নেটওয়ার্ক পরিসংখ্যান
```bash
ss -tulpn                  # Show listening sockets (Linux)
netstat -an                # All sockets (all OS)
```

## লোড ব্যালেন্সিং এবং রিভার্স প্রক্সি
### বিপরীত প্রক্সি হিসাবে Nginx
```nginx
server {
    listen 80;
    server_name example.com;
    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## সমস্যা সমাধানের চেকলিস্ট
1. শারীরিক লিঙ্ক আপ? (তারের, Wi-Fi সংযোগ পরীক্ষা করুন)।
2. আপনি গেটওয়ে পিং করতে পারেন? (যেমন, `ping 192.168.1.1`)।
3. আপনি একটি বহিরাগত আইপি পিং করতে পারেন? (যেমন, `8.8.8.8`)।
4. আপনি একটি ডোমেইন সমাধান করতে পারেন? (`dig google.com`)।
5. অ্যাপ্লিকেশন কি প্রত্যাশিত পোর্টে শুনছে? (`ss -tulpn | grep 8080`)।
6. ফায়ারওয়াল কি পোর্ট ব্লক করছে? (`iptables` /`ufw`বা ক্লাউড নিরাপত্তা গ্রুপ চেক করুন)।
7. অ্যাপ্লিকেশন লগগুলিতে কোন ত্রুটি আছে?
8. TLS শংসাপত্র কি বৈধ এবং বিশ্বস্ত? (`openssl s_client -connect example.com:443`)।
