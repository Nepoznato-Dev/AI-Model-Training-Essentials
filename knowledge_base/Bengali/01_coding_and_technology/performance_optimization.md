# কর্মক্ষমতা অপ্টিমাইজেশান
পারফরম্যান্স অপ্টিমাইজেশান হল সফ্টওয়্যারকে দ্রুততর করার অভ্যাস — প্রতিক্রিয়ার সময় হ্রাস করা, থ্রুপুট বৃদ্ধি করা, মেমরির ব্যবহার কমানো এবং বাধাগুলি দূর করা। এটি একজন বিকাশকারীর সবচেয়ে প্রভাবশালী দক্ষতাগুলির মধ্যে একটি, কারণ ধীর সফ্টওয়্যার ব্যবহারকারীদের হারায়, সম্পদ নষ্ট করে এবং সবাইকে হতাশ করে। তবে এটি সবচেয়ে সাধারণভাবে করা ভুলগুলির মধ্যে একটি, বিকাশকারীরা প্রমাণের পরিবর্তে অন্তর্দৃষ্টির উপর ভিত্তি করে ভুল জিনিসগুলিকে অপ্টিমাইজ করে।
---

## সুবর্ণ নিয়ম
> **প্রথমে পরিমাপ করুন, দ্বিতীয়টি অপ্টিমাইজ করুন।** কখনই অনুমানের উপর ভিত্তি করে অপ্টিমাইজ করবেন না। কোডটি প্রোফাইল করুন, প্রকৃত বাধা খুঁজে বের করুন এবং এটি ঠিক করুন।
| বিরোধী প্যাটার্ন | কেন এটা খারাপ |
|---------------|-------------|
| **অকাল অপ্টিমাইজেশন** | ধীরগতির নয় এমন কোডের গতি বাড়াতে সময় ব্যয় করা
| **পরিমাপ ছাড়াই অপ্টিমাইজিং** | ভুল বটলনেক ঠিক করা; উন্নতি যাচাই করার কোন উপায় নেই |
| **গতির জন্য পঠনযোগ্যতা ত্যাগ** | অপঠনযোগ্য কোড কর্মক্ষমতা লাভের চেয়ে বেশি খরচ করে |
| **সবকিছু ক্যাশে** | বাসি তথ্য, মেমরি ফোলা, জটিলতা |

## প্রোফাইলিং
আপনি দ্রুত কিছু করার আগে, আপনাকে জানতে হবে *কোথায়* সময় ব্যয় করা হচ্ছে।
| টুল টাইপ | এটা কি পরিমাপ করে | উদাহরণ |
|------------|------|------------|
| **CPU প্রোফাইলার** | কোন ফাংশন সবচেয়ে বেশি CPU সময় খরচ করে | cProfile (Python), perf (Linux), Chrome DevTools (JS) |
| **মেমরি প্রোফাইলার** | মেমরি বরাদ্দ এবং ফাঁস | tracemalloc (Python), Valgrind, heaptrack |
| **I/O প্রোফাইলার** | ডিস্ক এবং নেটওয়ার্ক I/O বাধা | iotop, strace, Wireshark |
| **এপিএম (অ্যাপ্লিকেশন পারফরম্যান্স মনিটরিং)** | এন্ড-টু-এন্ড অনুরোধের সময় | নিউ রিলিক, ডাটাডগ, জাইগার |
| **ব্রাউজার DevTools** | ফ্রন্টএন্ড রেন্ডারিং, জাভাস্ক্রিপ্ট এক্সিকিউশন, নেটওয়ার্ক | Chrome DevTools, Firefox প্রোফাইলার |
### প্রোফাইলিং ওয়ার্কফ্লো
| ধাপ | বর্ণনা |
|------|---------------|
| 1. ধীর অপারেশন সনাক্ত করুন | ব্যবহারকারীরা ধীর পৃষ্ঠা লোড রিপোর্ট; পর্যবেক্ষণ উচ্চ বিলম্ব দেখায় |
| 2. সম্পূর্ণ পথ প্রোফাইল | কোন উপাদানটি সবচেয়ে বেশি সময় নেয় তা খুঁজুন |
| 3. ড্রিল ডাউন | হট ফাংশন খুঁজে পেতে যে নির্দিষ্ট উপাদান প্রোফাইল |
| 4. বাধা ঠিক করুন | উপযুক্ত অপ্টিমাইজেশান প্রয়োগ করুন |
| 5. আবার পরিমাপ করুন | উন্নতি যাচাই করুন; রিগ্রেশনের জন্য চেক করুন |

## অ্যালগরিদমিক অপ্টিমাইজেশান
সবচেয়ে বড় পারফরম্যান্স লাভ হয় আরও ভালো অ্যালগরিদম বেছে নেওয়া থেকে, মাইক্রো-অপ্টিমাইজেশন থেকে নয়।
| পরিবর্তন | উন্নতি |
|---------|------------|
| লিনিয়ার সার্চ O(n) → হ্যাশ টেবিল লুকআপ O(1) | 100x+ বড় ডেটাসেটের জন্য |
| নেস্টেড লুপ O(n²) → সাজান + বাইনারি অনুসন্ধান O(n log n) | বড় n এর জন্য মাত্রার আদেশ |
| পুনরাবৃত্ত গণনা → স্মৃতিচারণ / ক্যাশিং | অপ্রয়োজনীয় কাজ দূর করে |
| একটি লুপে স্ট্রিং সংযুক্তি → বিল্ডার / যোগদান | দ্বিঘাত স্ট্রিং কপি করা এড়িয়ে যায় |
| সাজানো না হওয়া ডেটা → বাইনারি অনুসন্ধানের সাথে সাজানো ডেটা | প্রতি লুকআপে O(n) এর পরিবর্তে O(log n) |

## ক্যাশিং কৌশল
ক্যাশিং কম্পিউটেড ফলাফল সঞ্চয় করে তাই তাদের পুনরায় গণনা করার প্রয়োজন নেই।
| ক্যাশের ধরন | অবস্থান | গতি | আজীবন |
|------------|----------|-------|----------|
| **CPU ক্যাশে** | L1/L2/L3 | ~1 এনএস | স্বয়ংক্রিয় |
| **মেমোরি** | অ্যাপ্লিকেশন RAM (ডিক্ট, হ্যাশম্যাপ) | ~100 এনএস | সাফ বা উচ্ছেদ না হওয়া পর্যন্ত |
| **ডিস্ট্রিবিউটেড ক্যাশে** | Redis, Memcached | ~1 ms | কনফিগারযোগ্য TTL |
| **CDN** | বিশ্বব্যাপী এজ সার্ভার | ~10-50 ms | কনফিগারযোগ্য TTL |
| **ব্রাউজার ক্যাশে** | ব্যবহারকারীর ব্রাউজার | ~1 ms | HTTP ক্যাশে হেডার |
| **ডাটাবেস কোয়েরি ক্যাশে** | ডাটাবেস বা ORM স্তর | ~1-10 ms | ডেটা পরিবর্তন না হওয়া পর্যন্ত |
### ক্যাশিং প্যাটার্ন
| প্যাটার্ন | বর্ণনা | কখন ব্যবহার করবেন |
|---------|---------------|------------|
| **ক্যাশে-একপাশে** | অ্যাপ্লিকেশন চেক ক্যাশে; মিস উপর DB থেকে লোড; ক্যাশে দোকান | সবচেয়ে সাধারণ; সহজ |
| **লিখুন** | ক্যাশে এবং ডিবিতে একই সাথে লিখুন | যখন পড়ে >> লেখে; ধারাবাহিকতা গুরুত্বপূর্ণ |
| **লেখুন** | ক্যাশে লিখুন; অ্যাসিঙ্ক্রোনাসলি ডিবিতে লিখুন | উচ্চ লিখন থ্রুপুট; কিছু তথ্য হারানোর ঝুঁকি |
| **TTL (টাইম টু লাইভ)** | ক্যাশে এন্ট্রি একটি নির্দিষ্ট সময়ের পরে মেয়াদ শেষ হয় | যখন ডেটা পর্যায়ক্রমে পরিবর্তিত হয় |
| **অবৈধতা** | স্পষ্টভাবে পুরানো ক্যাশে এন্ট্রিগুলি সরান | যখন আপনি জানেন ঠিক কখন ডেটা পরিবর্তন হয় |
### ক্যাশে অবৈধকরণ
কম্পিউটার বিজ্ঞানের দুটি কঠিন সমস্যা: ক্যাশে অকার্যকরকরণ, জিনিসের নামকরণ এবং একের পর এক ত্রুটি।
| কৌশল | বর্ণনা |
|------------|-------------|
| **TTL-ভিত্তিক** | এন্ট্রি N সেকেন্ড পরে মেয়াদ শেষ হয়; সহজ কিন্তু বাসি তথ্য পরিবেশন করতে পারে |
| **ইভেন্ট-চালিত** | তথ্য পরিবর্তন হলে অবৈধ; আরো জটিল কিন্তু সঠিক |
| **সংস্করণ-ভিত্তিক** | একটি সংস্করণ নম্বর অন্তর্ভুক্ত করুন; পরিবর্তনের উপর বৃদ্ধি |
| **ট্যাগ-ভিত্তিক** | ট্যাগ সম্পর্কিত ক্যাশে এন্ট্রি; ট্যাগ দিয়ে সব এন্ট্রি বাতিল করুন |

## ডাটাবেস অপ্টিমাইজেশান
ডেটাবেসগুলি প্রায়শই ওয়েব অ্যাপ্লিকেশনগুলির মধ্যে সবচেয়ে বড় বাধা।
| টেকনিক | বর্ণনা | প্রভাব |
|------------|---------------|---------|
| **সূচীকরণ** | WHERE, JOIN, ORDER BY | এ ব্যবহৃত কলামগুলিতে সূচী যোগ করুন 10-1000x দ্রুত প্রশ্ন |
| **কোয়েরি অপ্টিমাইজেশন** | নির্বাচন এড়িয়ে চলুন *; প্রশ্ন বিশ্লেষণ করতে EXPLAIN ব্যবহার করুন | I/O হ্রাস করুন |
| **সংযোগ পুলিং** | নতুন তৈরি করার পরিবর্তে ডাটাবেস সংযোগগুলি পুনরায় ব্যবহার করুন | ওভারহেড সংযোগ মুছে ফেলুন |
| **প্রতিলিপি পড়ুন** | প্রতিলিপি ডাটাবেসে রুট পড়ার প্রশ্নগুলি | পঠিত লোড বিতরণ |
| **বিভাজন** | বড় টেবিলকে ছোট পার্টিশনে বিভক্ত করুন | বড় ডেটাসেটগুলিতে দ্রুত প্রশ্ন |
| **সাধারণকরণ** | যোগদান এড়াতে অপ্রয়োজনীয় ডেটা যোগ করুন | দ্রুত পড়া; আস্তে লেখে |
| **বস্তুগত দৃষ্টিভঙ্গি** | প্রাক-গণনা করা প্রশ্নের ফলাফল | তাত্ক্ষণিক জটিল প্রশ্ন |
| **N+1 প্রতিরোধ** | যোগদান, আগ্রহী লোডিং, বা ব্যাচ প্রশ্ন ব্যবহার করুন | হাজারো প্রশ্ন বাদ দিন |

## সামঞ্জস্য এবং সমান্তরালতা
| ধারণা | বর্ণনা | কখন ব্যবহার করবেন |
|---------|---------------|------------|
| **থ্রেডিং** | একটি একক প্রক্রিয়ার মধ্যে একাধিক থ্রেড | I/O- আবদ্ধ কাজ (নেটওয়ার্ক, ডিস্ক) |
| **মাল্টিপ্রসেসিং** | একাধিক প্রক্রিয়া (পাইথনে জিআইএলকে বাইপাস করে) | CPU- আবদ্ধ কাজ |
| **অসিঙ্ক/অপেক্ষা** | সমবায় মাল্টিটাস্কিং; একক সুতো | উচ্চ-সঙ্গতি I/O (ওয়েব সার্ভার) |
| **GPU কম্পিউটিং** | হাজার হাজার সমান্তরাল কোর | ম্যাট্রিক্স অপারেশন; ছবি প্রক্রিয়াকরণ; এমএল |
### অ্যাসিঙ্ক বনাম থ্রেডিং
| দৃষ্টিভঙ্গি | Async/অপেক্ষা করুন | থ্রেডিং |
|---------|------------|------------|
| **মডেল** | সমবায় (কাজের ফলন নিয়ন্ত্রণ) | অগ্রিম (OS সুইচ থ্রেড) |
| **ওভারহেড** | খুব কম (কোন প্রসঙ্গ স্যুইচিং নেই) | উচ্চতর (থ্রেড তৈরি, প্রসঙ্গ স্যুইচিং) |
| **জটিলতা** | সরল যুক্তি (একক থ্রেড) | রেসের অবস্থা, অচলাবস্থা, তালা |
| **এর জন্য সেরা** | অনেক সমসাময়িক I/O অপারেশন | অ্যাসিঙ্ক করা যাবে না এমন অপারেশন ব্লক করা

## সারাংশ
পারফরম্যান্স অপ্টিমাইজেশান একটি পদ্ধতিগত প্রক্রিয়া: পরিমাপ করুন, বাধা চিহ্নিত করুন, এটি ঠিক করুন, আবার পরিমাপ করুন। সবচেয়ে বড় জয় আসে অ্যালগরিদমিক উন্নতি এবং অপ্রয়োজনীয় কাজ বাদ দিয়ে — মাইক্রো-অপ্টিমাইজেশন থেকে নয়। ক্যাশিং, ডাটাবেস ইনডেক্সিং এবং কনকারেন্সি হল সবচেয়ে শক্তিশালী টুল। ফ্রন্টএন্ড কর্মক্ষমতা পেলোড আকার এবং রাউন্ড ট্রিপ কমানোর উপর নির্ভর করে। এবং সবচেয়ে গুরুত্বপূর্ণ নিয়ম সবসময় একই: অনুমান করবেন না — প্রোফাইল।
