# ক্লাউড আর্কিটেকচার
ক্লাউড কম্পিউটিং সংস্থাগুলি কীভাবে সফ্টওয়্যার তৈরি, স্থাপন এবং স্কেল করে তা মৌলিকভাবে পরিবর্তন করেছে। প্রকৃত সার্ভার কেনা এবং রক্ষণাবেক্ষণ করার পরিবর্তে, আপনি চাহিদা অনুযায়ী কম্পিউটিং সংস্থান সরবরাহ করতে পারেন, আপনি যা ব্যবহার করেন তার জন্য অর্থ প্রদান করতে পারেন এবং মিনিটের মধ্যে বিশ্বব্যাপী স্কেল করতে পারেন। এই ফাইলটি মূল ধারণা, স্থাপত্য নিদর্শন, পরিষেবা এবং আপনার জানা প্রয়োজন সর্বোত্তম অনুশীলনগুলি কভার করে৷
---

## ক্লাউড কম্পিউটিং মৌলিক বিষয়
### ক্লাউড কম্পিউটিং কি?
কম্পিউটিং রিসোর্স - সার্ভার, স্টোরেজ, ডাটাবেস, নেটওয়ার্কিং, সফ্টওয়্যার - ইন্টারনেটের মাধ্যমে চাহিদা অনুযায়ী ডেলিভারি, যেমন-ই-ই-ই-গো মূল্য দিয়ে।
### NIST এর প্রয়োজনীয় বৈশিষ্ট্য
| চারিত্রিক | অর্থ |
|---------------|---------|
| **অন-ডিমান্ড স্ব-পরিষেবা** | মানুষের মিথস্ক্রিয়া ছাড়া সংস্থান সম্পদ |
| **বিস্তৃত নেটওয়ার্ক অ্যাক্সেস** | স্ট্যান্ডার্ড মেকানিজমের মাধ্যমে নেটওয়ার্কে উপলব্ধ |
| **রিসোর্স পুলিং** | মাল্টি ভাড়াটে মডেল; সম্পদ গতিশীলভাবে বরাদ্দ |
| **দ্রুত স্থিতিস্থাপকতা** | দ্রুত বাহ্যিক এবং অভ্যন্তরীণ স্কেল করুন |
| **পরিমাপিত পরিষেবা** | ব্যবহার নিরীক্ষণ এবং বিল করা হয় |
### স্থাপনার মডেল
| মডেল | বর্ণনা | কখন ব্যবহার করবেন |
|---------|---------------|------------|
| **পাবলিক ক্লাউড** | প্রদানকারীদের মালিকানাধীন; ভাগ করা অবকাঠামো (AWS, Azure, GCP) | বেশিরভাগ কাজের চাপ; সাশ্রয়ী |
| **ব্যক্তিগত মেঘ** | একটি একক সংস্থার জন্য উত্সর্গীকৃত | নিয়ন্ত্রক প্রয়োজনীয়তা, সংবেদনশীল তথ্য |
| **হাইব্রিড ক্লাউড** | পাবলিক এবং প্রাইভেট এর সমন্বয় | নমনীয়তা + সম্মতি |
| **মাল্টি-ক্লাউড** | একাধিক পাবলিক ক্লাউড প্রদানকারী ব্যবহার করে | বিক্রেতা লক-ইন এড়িয়ে চলুন, সর্বোত্তম জাত |
### সার্ভিস মডেল
| মডেল | প্রদান করে | উদাহরণ | কেস ব্যবহার করুন |
|-------|----------|----------|------------|
| **আইএএএস** | VM, স্টোরেজ, নেটওয়ার্ক, OS | AWS EC2, Azure VMs, GCP কম্পিউট ইঞ্জিন | লিফট-এন্ড-শিফ্ট মাইগ্রেশন, সম্পূর্ণ নিয়ন্ত্রণ |
| **পাস** | ডেভেলপমেন্ট প্ল্যাটফর্ম, ডাটাবেস, মিডলওয়্যার | Heroku, Google App Engine, AWS ইলাস্টিক বিনস্টক | অ্যাপ ডেভেলপমেন্ট, API স্থাপনা |
| **সাস** | ইন্টারনেটের মাধ্যমে সম্পূর্ণ অ্যাপ্লিকেশন | Salesforce, Google Workspace, Microsoft 365 | ইমেল, CRM, সহযোগিতা |
| **FaaS / সার্ভারহীন** | ইভেন্ট-চালিত ফাংশন এক্সিকিউশন | AWS Lambda, Azure ফাংশন, GCP ক্লাউড ফাংশন | APIs, ইভেন্ট প্রক্রিয়াকরণ, নির্ধারিত কাজ |

| **ডিজিটাল মহাসাগর** | কুলুঙ্গি | বিকাশকারী-বান্ধব, সরলীকৃত অফার |

## স্থাপত্য নিদর্শন
### ভাল-আর্কিটেক্টেড ফ্রেমওয়ার্ক
তিনটি প্রধান প্রদানকারীই পাঁচটি স্তম্ভের চারপাশে নির্মিত সু-স্থাপত্য কাঠামো প্রকাশ করে:
| স্তম্ভ | মূল নীতি |
|---------|---------------|
| **অপারেশনাল এক্সিলেন্স** | স্বয়ংক্রিয় অপারেশন; ঘন ঘন, বিপরীত পরিবর্তন করা; ব্যর্থতা প্রত্যাশিত |
| **নিরাপত্তা** | শক্তিশালী পরিচয় ভিত্তি; প্রতিটি স্তরে নিরাপত্তা প্রয়োগ করুন; ট্রানজিট এবং বিশ্রামে ডেটা রক্ষা করুন |
| **বিশ্বস্ততা** | পরীক্ষা পুনরুদ্ধারের পদ্ধতি; ব্যর্থতা থেকে স্বয়ংক্রিয় পুনরুদ্ধার; অনুভূমিকভাবে স্কেল |
| **কর্মক্ষমতা দক্ষতা** | সার্ভারহীন ব্যবহার করুন; মিনিটের মধ্যে বিশ্বব্যাপী যান; পরীক্ষা প্রায়ই |
| **কস্ট অপ্টিমাইজেশান** | খরচ মডেল গ্রহণ; পরিচালিত পরিষেবা ব্যবহার করুন; অপ্রত্যাশিত কাজে ব্যয় করা বন্ধ করুন |
### সাধারণ নিদর্শন
| প্যাটার্ন | বর্ণনা | সুবিধা | চ্যালেঞ্জ |
|---------|---------------|---------|------------|
| **মাইক্রোসার্ভিসেস** | অ্যাপটিকে ছোট, স্বাধীন পরিষেবাগুলিতে পচে | পরিমাপযোগ্যতা, ত্রুটি বিচ্ছিন্নতা, স্বাধীন স্থাপনা | বিতরণ করা জটিলতা, ডেটা সামঞ্জস্য |
| **ইভেন্ট-চালিত** | উপাদান ঘটনা মাধ্যমে যোগাযোগ | লুজ কাপলিং, রিয়েল-টাইম প্রসেসিং | ডিবাগিং জটিলতা, চূড়ান্ত ধারাবাহিকতা |
| **সার্ভারহীন** | কোন সার্ভার ব্যবস্থাপনা; প্রতি মৃত্যুদন্ড প্রদান | খরচ দক্ষতা, দ্রুত স্থাপনা | কোল্ড স্টার্ট, ভেন্ডর লক-ইন, এক্সিকিউশন লিমিট |
| **স্তরযুক্ত (N-স্তর)** | উপস্থাপনা → ব্যবসায়িক যুক্তি → ডেটা অ্যাক্সেস → ডেটাবেস | উদ্বেগের বিচ্ছেদ, রক্ষণাবেক্ষণযোগ্যতা | একচেটিয়া হয়ে উঠতে পারে |
| **মহাকাশ-ভিত্তিক** | ভার্চুয়ালাইজড মেমরি নোড জুড়ে বিতরণ করা ডেটা | উচ্চ সংগতি, কম লেটেন্সি পরিচালনা করে | ডিজাইন এবং পরিচালনার জন্য জটিল |

## নেটওয়ার্কিং
### ভার্চুয়াল নেটওয়ার্ক
প্রতিটি ক্লাউড স্থাপনা একটি ভার্চুয়াল প্রাইভেট ক্লাউড (VPC/VNet)-এর মধ্যে থাকে — একটি বিচ্ছিন্ন নেটওয়ার্ক যা আপনি CIDR ব্লক, সাবনেট (সর্বজনীন বা ব্যক্তিগত), রুট টেবিল এবং গেটওয়ে দিয়ে সংজ্ঞায়িত করেন।
### লোড ব্যালেন্সিং এবং সিডিএন
| সেবা | উদ্দেশ্য |
|---------|---------|
| **লোড ব্যালেন্সার** | দৃষ্টান্ত জুড়ে ট্রাফিক বিতরণ (L4 নেটওয়ার্ক, L7 অ্যাপ্লিকেশন) |
| **CDN** | নিম্ন লেটেন্সি (ক্লাউডফ্রন্ট, ক্লাউড CDN, Azure CDN) এর জন্য প্রান্তের অবস্থানে ক্যাশে সামগ্রী |
| **DNS** | ডোমেন নিবন্ধন, রাউটিং নীতি, স্বাস্থ্য পরীক্ষা (রুট 53, ক্লাউড DNS, Azure DNS) |
### সংযোগের বিকল্প
| বিকল্প | বর্ণনা |
|---------|-------------|
| **ইন্টারনেট গেটওয়ে** | ভিপিসির জন্য সর্বজনীন ইন্টারনেট অ্যাক্সেস |
| **NAT গেটওয়ে** | ব্যক্তিগত সাবনেট আউটবাউন্ড অ্যাক্সেস |
| **ভিপিএন** | অন-প্রাঙ্গনে এনক্রিপ্ট করা টানেল |
| **ডাইরেক্ট কানেক্ট / এক্সপ্রেস রুট** | নিবেদিত ব্যক্তিগত সংযোগ |
| **ভিপিসি পিয়ারিং** | অ্যাকাউন্টের মধ্যে বা মধ্যে ভিপিসি সংযুক্ত করুন |

## খরচ ব্যবস্থাপনা
### দামের মডেল
| মডেল | বর্ণনা | জন্য সেরা |

### অপ্টিমাইজেশান কৌশল
কাজের চাপ মেলে ডান-আকারের উদাহরণ। চাহিদা স্পাইক পরিচালনা করতে অটো-স্কেলিং ব্যবহার করুন। অনুমানযোগ্য লোডের জন্য রিজার্ভ ক্ষমতা। ব্যাচ কাজের জন্য স্পট উদাহরণ ব্যবহার করুন. সস্তা স্টোরেজ স্তরে কদাচিৎ অ্যাক্সেস করা ডেটা সরান। অব্যবহৃত সম্পদ মুছুন (অনাথ স্ন্যাপশট, নিষ্ক্রিয় লোড ব্যালেন্সার, সংযুক্ত না করা আইপি)।

## উচ্চ প্রাপ্যতা এবং দুর্যোগ পুনরুদ্ধার
### প্রাপ্যতা ধারণা
| ধারণা | বর্ণনা |
|---------|---------------|
| **উপলভ্যতা অঞ্চল (AZ)** | একটি অঞ্চলের মধ্যে শারীরিকভাবে পৃথক ডেটা সেন্টার |
| **অঞ্চল** | একাধিক AZ সহ ভৌগলিক এলাকা |
| **প্রান্তের অবস্থান** | বিষয়বস্তু বিতরণের জন্য CDN ক্যাশে অবস্থান |
### দুর্যোগ পুনরুদ্ধারের কৌশল
| কৌশল | খরচ | আরটিও | আরপিও | বর্ণনা |
|----------|------|------|------|-------------|
| **ব্যাকআপ এবং পুনরুদ্ধার** | সর্বনিম্ন | ঘন্টা | ঘন্টা-দিন | পর্যায়ক্রমিক ব্যাকআপ, প্রয়োজন হলে পুনরুদ্ধার করুন |
| **পাইলট লাইট** | কম | মিনিট-ঘন্টা | মিনিট | মূল উপাদান সর্বদা চলমান, দুর্যোগের উপর স্কেল আপ |
| **উষ্ণ স্ট্যান্ডবাই** | মাঝারি | মিনিট | সেকেন্ড-মিনিট | স্কেল-ডাউন সংস্করণ সর্বদা চলমান |
| **মাল্টি-সাইট সক্রিয়/সক্রিয়** | সর্বোচ্চ | কাছাকাছি-শূন্য | শূন্য | একাধিক অঞ্চলে পূর্ণ উৎপাদন |
**RTO** (পুনরুদ্ধারের সময় উদ্দেশ্য) = সর্বাধিক গ্রহণযোগ্য ডাউনটাইম। **RPO** (রিকভারি পয়েন্ট অবজেক্টিভ) = সর্বাধিক গ্রহণযোগ্য ডেটা ক্ষতি।
