# DevOps এবং CI/CD
DevOps হল সাংস্কৃতিক দর্শন, অনুশীলন এবং সরঞ্জামগুলির সমন্বয় যা দলগুলিকে দ্রুত এবং আরও নির্ভরযোগ্যভাবে সফ্টওয়্যার সরবরাহ করতে সক্ষম করে। এটি ডেভেলপারদের (যারা পরিবর্তন করতে চায়) এবং অপারেশন (যারা স্থিতিশীলতা চায়) এর মধ্যে দেয়াল ভেঙে দেয়। CI/CD — ক্রমাগত ইন্টিগ্রেশন এবং ক্রমাগত ডেলিভারি — হল অটোমেশন ব্যাকবোন যা এটিকে সম্ভব করে তোলে।

## CI/CD পাইপলাইন
### আসলে CI/CD মানে কি
| মেয়াদ | এটা কি করে |
|------|---------------|
| **কন্টিনিউয়াস ইন্টিগ্রেশন (CI)** | বিকাশকারীরা ঘন ঘন কোড মার্জ করে; প্রতিটি মার্জ স্বয়ংক্রিয় বিল্ড এবং পরীক্ষা শুরু করে |
| **কন্টিনিউয়াস ডেলিভারি (সিডি)** | কোড সর্বদা একটি স্থাপনযোগ্য অবস্থায় থাকে; উৎপাদনে মুক্তি দেওয়া একটি ম্যানুয়াল সিদ্ধান্ত |
| **নিরবিচ্ছিন্ন স্থাপনা** | পরীক্ষায় উত্তীর্ণ প্রতিটি পরিবর্তন স্বয়ংক্রিয়ভাবে উৎপাদনে যায় — কোনো ম্যানুয়াল গেট নেই |
### সাধারণ পাইপলাইন পর্যায়
| মঞ্চ | কি হয় | টুলস |
|---------|---------------|-------|
| **সূত্র** | বিকাশকারী গিটে কোড পুশ করে | GitHub, GitLab, Bitbucket |
| **বিল্ড** | কোড কম্পাইল করুন, নির্ভরতা ইনস্টল করুন | Maven, Gradle, npm, pip |
| **পরীক্ষা** | ইউনিট, ইন্টিগ্রেশন, লিন্ট চেক চালান | Jest, pytest, JUnit |
| **প্যাকেজ** | ডকার ইমেজ বা আর্টিফ্যাক্ট তৈরি করুন | ডকার, বিল্ডপ্যাকস |
| **নিয়োগ (মঞ্চায়ন)** | পরিবেশন মঞ্চে স্থাপন করুন | Kubernetes, ECS, VM |
| **পরীক্ষা (মঞ্চায়ন)** | ইন্টিগ্রেশন পরীক্ষা, ধোঁয়া পরীক্ষা | সেলেনিয়াম, পোস্টম্যান |
| **মোতায়েন (উৎপাদন)** | উৎপাদনে মুক্তি | নীল-সবুজ, ক্যানারি, ঘূর্ণায়মান |
| **মনিটর** | স্বাস্থ্য, ত্রুটি, কর্মক্ষমতা পর্যবেক্ষণ করুন | প্রমিথিউস, গ্রাফানা, ডাটাডগ |
### CI/CD টুলের তুলনা
| টুল | প্রকার | শক্তি |
|------|------|----------|
| **গিটহাব অ্যাকশন** | ক্লাউড CI/CD | গিটহাবের সাথে গভীরভাবে সংহত; YAML কর্মপ্রবাহ |
| **গিটল্যাব সিআই** | অন্তর্নির্মিত CI/CD | রেপো + পাইপলাইনের জন্য একক প্ল্যাটফর্ম |
| **জেনকিন্স** | স্ব-হোস্টেড CI/CD | অত্যন্ত কনফিগারযোগ্য; বিশাল প্লাগইন ইকোসিস্টেম |
| **CircleCI** | ক্লাউড CI/CD | দ্রুত; কন্টেইনারাইজড ওয়ার্কফ্লো জন্য ভাল |
| **ArgoCD** | Kubernetes জন্য GitOps | ঘোষণামূলক, গিট-চালিত স্থাপনা |

## ডকার এবং কন্টেইনার
### কেন পাত্রে?
পাত্রে আগে, ক্লাসিক সমস্যা ছিল "এটি আমার মেশিনে কাজ করে।" কনটেইনারগুলি একটি অ্যাপ্লিকেশনকে এর সমস্ত নির্ভরতা - লাইব্রেরি, রানটাইম, কনফিগারেশন - একটি একক, পোর্টেবল ইউনিটে প্যাকেজ করে এটি সমাধান করে যা একইভাবে যে কোনও জায়গায় চলে।
### ডকার অপরিহার্য
| ধারণা | বর্ণনা |
|---------|---------------|
| **ছবি** | অ্যাপ + নির্ভরতা সহ শুধুমাত্র পঠনযোগ্য টেমপ্লেট
| **ধারক** | একটি চিত্রের চলমান উদাহরণ |
| **ডকারফাইল** | একটি ছবি নির্মাণের রেসিপি |
| **রেজিস্ট্রি** | ছবির জন্য সঞ্চয়স্থান (ডকার হাব, ইসিআর, জিসিআর) |
| **ভলিউম** | স্থায়ী সঞ্চয়স্থান যা কন্টেইনার পুনঃসূচনা থেকে বেঁচে থাকে |
| **নেটওয়ার্ক** | পাত্রে জন্য বিচ্ছিন্ন নেটওয়ার্কিং স্তর |
### ডকারফাইলের সর্বোত্তম অনুশীলন
```dockerfile
# Use specific base image tags, not 'latest'
FROM python:3.12-slim

# Set working directory
WORKDIR /app

# Copy dependency file first (leverage Docker layer caching)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code
COPY . .

# Run as non-root user
USER appuser

# Expose port and define entrypoint
EXPOSE 8000
CMD ["python", "main.py"]
```

মূল অভ্যাস: স্লিম/আলপাইন বেস ইমেজ ব্যবহার করুন, নন-রুট হিসাবে চালান, লেয়ার ক্যাশিং লিভারেজ ব্যবহার করুন,`.dockerignore`ব্যবহার করুন, দুর্বলতার জন্য ছবি স্ক্যান করুন (`trivy`,`docker scan`), এবং সংস্থান সীমা সেট করুন।
### ডকার কম্পোজ
একসাথে একাধিক পাত্র চালানোর জন্য (অ্যাপ + ডাটাবেস + ক্যাশে):
```yaml
services:
  app:
    build: .
    ports: ["8000:8000"]
    depends_on: [db, redis]
    environment:
      DATABASE_URL: postgresql://user:pass@db:5432/mydb
  db:
    image: postgres:16
    volumes: [pgdata:/var/lib/postgresql/data]
  redis:
    image: redis:7-alpine
volumes:
  pgdata:
```

## কুবারনেটস (K8s)
Kubernetes হল শিল্প-মানের ধারক অর্কেস্ট্রেটর। এটি কন্টেইনারাইজড অ্যাপ্লিকেশনগুলির স্থাপনা, স্কেলিং এবং অপারেশন পরিচালনা করে।
### মূল আর্কিটেকচার
| উপাদান | ভূমিকা |
|------------|------|
| **কন্ট্রোল প্লেন** | ক্লাস্টার পরিচালনা করে (API সার্ভার, শিডিউলার, etcd, কন্ট্রোলার ম্যানেজার) |
| **নোড** | ওয়ার্কার মেশিন (ভিএম বা ফিজিক্যাল) যা কন্টেইনার চালায় |
| **পড** | সবচেয়ে ছোট স্থাপনযোগ্য ইউনিট; নেটওয়ার্কিং শেয়ার করে এক বা একাধিক পাত্রে |
| **পরিষেবা** | স্থিতিশীল নেটওয়ার্ক এন্ডপয়েন্ট যা ট্র্যাফিককে পড পর্যন্ত রুট করে |
| **নিয়োগ** | পছন্দসই পড অবস্থার ঘোষণামূলক সংজ্ঞা (প্রতিলিপি, চিত্র, ইত্যাদি) |
| **অনুপ্রবেশ** | বাহ্যিক ট্রাফিকের জন্য HTTP রাউটিং নিয়ম |
| **কনফিগম্যাপ/সিক্রেট** | কনফিগারেশন এবং সংবেদনশীল ডেটা পডগুলিতে ইনজেক্ট করা হয় |
### প্রয়োজনীয় kubectl কমান্ড
```bash
kubectl get pods                    # List pods
kubectl get services                # List services
kubectl describe pod <name>         # Detailed pod info
kubectl logs <pod-name>             # View pod logs
kubectl exec -it <pod> -- /bin/sh   # Shell into a pod
kubectl apply -f deployment.yaml    # Apply a manifest
kubectl rollout status deploy/myapp # Check rollout progress
kubectl scale deploy/myapp --replicas=5  # Scale to 5 replicas
```

### হেলম
হেলম হলেন কুবারনেটসের প্যাকেজ ম্যানেজার। একটি **চার্ট** হল পূর্ব-কনফিগার করা Kubernetes সম্পদের একটি বান্ডিল। K8 এর জন্য এটিকে`apt`বা`brew`হিসাবে ভাবুন৷
```bash
helm install my-release bitnami/postgresql   # Install a chart
helm upgrade my-release bitnami/postgresql   # Upgrade
helm rollback my-release 1                   # Rollback to revision 1
helm list                                    # List releases
```

## কোড হিসাবে পরিকাঠামো (IaC)
IaC অবকাঠামো কনফিগারেশনকে একইভাবে ব্যবহার করে যেভাবে আপনি অ্যাপ্লিকেশন কোড ব্যবহার করেন: সংস্করণ-নিয়ন্ত্রিত, পরীক্ষা করা এবং পাইপলাইনের মাধ্যমে স্থাপন করা।
### টেরাফর্ম বনাম উত্তরযোগ্য
| টুল | প্রকার | দৃষ্টিভঙ্গি | জন্য সেরা |
|------|------|------------|---------|
| **টেরাফর্ম** | বিধান | ঘোষণামূলক (HCL); রাষ্ট্র ভিত্তিক | ক্লাউড রিসোর্স তৈরি করা (ভিপিসি, ভিএম, ডেটাবেস) |
| **উত্তর** | কনফিগারেশন | ঘোষণামূলক (YAML); এজেন্টহীন | সার্ভার কনফিগার করা, সফ্টওয়্যার ইনস্টল করা |
| **পুলুমি** | বিধান | আবশ্যিক (পাইথন, গো, টিএস) | যে দলগুলি বাস্তব প্রোগ্রামিং ভাষা পছন্দ করে |
| **ক্লাউড ফরমেশন** | বিধান | ঘোষণামূলক (YAML/JSON); AWS-নেটিভ | AWS-শুধু অবকাঠামো |
### টেরাফর্ম উদাহরণ
```hcl
provider "aws" {
  region = "us-east-1"
}

resource "aws_instance" "web" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.micro"

  tags = {
    Name = "web-server"
  }
}
```

সর্বোত্তম অনুশীলন: পুনঃব্যবহারযোগ্যতার জন্য মডিউলগুলি ব্যবহার করুন, দূরবর্তী অবস্থানে সংরক্ষণ করুন (লক করার জন্য S3 + DynamoDB), কখনও হার্ডকোড গোপনীয়তা করবেন না এবং সংস্করণ-নিয়ন্ত্রণ সবকিছু।

## পর্যবেক্ষণ এবং পর্যবেক্ষণযোগ্যতা
### তিনটি স্তম্ভ
| স্তম্ভ | এটি আপনাকে কী বলে | টুলস |
|---------|------------------|---------|
| **মেট্রিক্স** | সময়ের সাথে সংখ্যাসূচক পরিমাপ (CPU, অনুরোধের হার, ত্রুটির হার) | প্রমিথিউস, ক্লাউডওয়াচ, ডেটাডগ |
| **লগ** | প্রসঙ্গ সহ বিচ্ছিন্ন ঘটনা (ত্রুটি, অনুরোধ, রাষ্ট্র পরিবর্তন) | ELK স্ট্যাক, লোকি, ক্লাউডওয়াচ লগ |
| **চিহ্ন** | পরিষেবা জুড়ে এন্ড-টু-এন্ড অনুরোধ যাত্রা | জেগার, এক্স-রে, জিপকিন |
### প্রমিথিউস + গ্রাফানা স্ট্যাক
স্ট্যান্ডার্ড ওপেন সোর্স মনিটরিং স্ট্যাক:
| উপাদান | ভূমিকা |
|------------|------|
| **প্রমিথিউস** | টাইম-সিরিজ ডাটাবেস; পরিষেবাগুলি থেকে মেট্রিক্স টানে |
| **গ্রাফনা** | ভিজ্যুয়ালাইজেশন এবং ড্যাশবোর্ড |
| **সতর্ক ব্যবস্থাপক** | স্ল্যাক, পেজারডিউটি, ইমেলের রুট সতর্কতা |
| **নোড রপ্তানিকারক** | সিস্টেম-স্তরের মেট্রিক্স (CPU, RAM, disk) প্রকাশ করে |
| **ব্ল্যাকবক্স রপ্তানিকারক** | প্রোব এন্ডপয়েন্ট (HTTP, TCP, ICMP) |
### ট্র্যাক করার জন্য মূল মেট্রিক্স
| বিভাগ | মেট্রিক্স |
|----------|---------|

## গিটঅপস
GitOps IaC কে তার যৌক্তিক উপসংহারে নিয়ে যায়: গিট রিপোজিটরি আপনার অবকাঠামো এবং অ্যাপ্লিকেশনগুলির পছন্দসই অবস্থার জন্য সত্যের একক উত্স।
| নীতি | বর্ণনা |
|------------|-------------|
| **ঘোষণামূলক** | কোড হিসাবে বর্ণিত সবকিছু (YAML, HCL) |
| **সংস্করণ** | গিট সত্যের উৎস |
| **স্বয়ংক্রিয়** | টুলস ক্রমাগত প্রকৃত অবস্থার সাথে কাঙ্ক্ষিত অবস্থার মিলন ঘটায় |
| **নিরীক্ষাযোগ্য** | প্রতিটি পরিবর্তন একটি গিট কমিট |
**ArgoCD** এবং **Flux** হল Kubernetes-এর জন্য নেতৃস্থানীয় GitOps টুল। আপনি আপনার গিট রেপোতে একটি পরিবর্তন করেন এবং সরঞ্জামটি স্বয়ংক্রিয়ভাবে এটি ক্লাস্টারে স্থাপন করে।
