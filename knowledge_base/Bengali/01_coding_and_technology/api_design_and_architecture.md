# API ডিজাইন এবং আর্কিটেকচার
একটি API (অ্যাপ্লিকেশন প্রোগ্রামিং ইন্টারফেস) হল সফ্টওয়্যার উপাদানগুলি কীভাবে একে অপরের সাথে কথা বলে। একটি ভাল-পরিকল্পিত API স্বজ্ঞাত, সামঞ্জস্যপূর্ণ, এবং এর সাথে কাজ করা আনন্দদায়ক। একটি খারাপভাবে ডিজাইন করা বিভ্রান্তি, বাগ এবং হতাশার কারণ। এই ফাইলটি API তৈরির নীতি, নিদর্শন এবং অনুশীলনগুলিকে কভার করে যা বিকাশকারীরা আসলে ব্যবহার করতে চায়৷
---

## REST API নীতিগুলি
REST (রিপ্রেজেন্টেশনাল স্টেট ট্রান্সফার) হল ওয়েব API-এর জন্য প্রভাবশালী স্থাপত্য শৈলী। এটি ডেটাকে ইউআরএল দ্বারা চিহ্নিত **সম্পদ** হিসাবে বিবেচনা করে এবং সেগুলি পরিচালনা করতে HTTP পদ্ধতি ব্যবহার করে।
### মূল নীতি
| নীতি | বর্ণনা |
|------------|-------------|
| **সম্পদ** | সবকিছুই একটি ইউআরআই সহ একটি সম্পদ (`/users/123`,`/orders/456`) |
| **HTTP পদ্ধতি** | পান (পড়ুন), পোস্ট করুন (তৈরি করুন), রাখুন (প্রতিস্থাপন করুন), প্যাচ (আংশিক আপডেট করুন), মুছুন (সরান) |
| **রাষ্ট্রহীনতা** | প্রতিটি অনুরোধে প্রয়োজনীয় সমস্ত তথ্য রয়েছে; সার্ভার-সাইড সেশন স্টেট নেই |
| **ইউনিফর্ম ইন্টারফেস** | সামঞ্জস্যপূর্ণ সম্পদের নামকরণ, আদর্শ পদ্ধতি, স্ট্যান্ডার্ড স্ট্যাটাস কোড |
| **প্রতিনিধিত্ব** | সম্পদগুলিকে একাধিক ফর্ম্যাটে (JSON, XML) |
### সম্পদের নামকরণের নিয়মাবলী
| করবেন | করবেন না |
|----|-------|
| `/users`(বহুবচন বিশেষ্য) | `/user`(একবচন) |
| `/users/123/orders`(নেস্টেড) | `/getOrdersForUser?id=123`|
| `/products?category=electronics`(ফিল্টারিংয়ের জন্য প্রশ্ন প্যারাম) | `/productsByCategory/electronics`|
| হাইফেন ব্যবহার করুন:`/user-profiles`| আন্ডারস্কোর ব্যবহার করুন:`/user_profiles`|
### HTTP পদ্ধতি এবং অদম্যতা
| পদ্ধতি | উদ্দেশ্য | অদম্য? | নিরাপদ? |
|---------|---------|---------------|-------|
| **পান** | একটি সম্পদ পড়ুন | ✅ হ্যাঁ | ✅ হ্যাঁ |
| **পোস্ট** | একটি সম্পদ তৈরি করুন | ❌ না | ❌ না |
| **পুট** | একটি সম্পদ সম্পূর্ণভাবে প্রতিস্থাপন করুন | ✅ হ্যাঁ | ❌ না |
| **প্যাচ** | আংশিকভাবে একটি সংস্থান আপডেট করুন | ❌ না* | ❌ না |
| **মুছুন** | একটি সম্পদ সরান | ✅ হ্যাঁ | ❌ না |
*প্যাচ সাবধানে নকশা সঙ্গে অদম্য করা যেতে পারে.
### HTTP স্ট্যাটাস কোড
| কোড | অর্থ | কখন ব্যবহার করবেন |
|------|---------|---------------|
| **200** | ঠিক আছে | সফলভাবে GET, PUT, PATCH, DELETE |
| **201** | তৈরি | সফল পোস্ট (সম্পদ তৈরি) |
| **204** | কোন বিষয়বস্তু নেই | সফলভাবে DELETE (ফেরত করার কিছু নেই) |
| **400** | খারাপ অনুরোধ | অবৈধ ইনপুট বা বিকৃত অনুরোধ |
| **401** | অননুমোদিত | অনুপস্থিত বা অবৈধ প্রমাণীকরণ |
| **403** | নিষিদ্ধ | প্রমাণিত কিন্তু অনুমোদিত নয় |
| **404** | পাওয়া যায়নি | সম্পদ বিদ্যমান নেই |
| **409** | দ্বন্দ্ব | সদৃশ সম্পদ বা রাষ্ট্রের দ্বন্দ্ব |
| **422** | অপ্রসেসযোগ্য সত্তা | বৈধ JSON কিন্তু শব্দার্থগত ত্রুটি |
| **429** | অনেক অনুরোধ | হার সীমা অতিক্রম করেছে |
| **500** | অভ্যন্তরীণ সার্ভার ত্রুটি | অপ্রত্যাশিত সার্ভার ত্রুটি |
| **502** | খারাপ গেটওয়ে | আপস্ট্রিম পরিষেবা ব্যর্থতা |
| **503** | পরিষেবা অনুপলব্ধ | অস্থায়ী ওভারলোড বা রক্ষণাবেক্ষণ |

## API সংস্করণ
এপিআই বিকশিত হয়। আপনি যখন ব্রেকিং পরিবর্তন করতে চান, তখন ভার্সনিং বিদ্যমান ক্লায়েন্টদের কাজ চালিয়ে যেতে দেয়।
| কৌশল | উদাহরণ | পেশাদার | কনস |
|----------|---------|------|------|
| **URL পাথ** | `/v1/users`,`/v2/users`| সহজ, স্পষ্ট | সংস্করণ প্রতি URL পরিবর্তন |
| **কোয়েরি প্যারামিটার** | `/users?version=2`| নমনীয় | ভুলে যাওয়া সহজ |
| **হেডার** | `Accept: application/vnd.myapi.v2+json`| URL গুলি পরিষ্কার করুন | কম আবিষ্কারযোগ্য |
| **কোন সংস্করণ নেই** | স্কিমা বিবর্তন শুধুমাত্র | সহজতম | ব্রেকিং পরিবর্তন সবাইকে প্রভাবিত করে |
**সর্বোত্তম অনুশীলন**: স্বচ্ছতার জন্য URL পাথ সংস্করণ ব্যবহার করুন (`/v1/`)। অন্তত একটি পূর্ববর্তী সংস্করণ সমর্থন. পরিষ্কার টাইমলাইন সহ পুরানো সংস্করণগুলি বাতিল করুন।

## প্রমাণীকরণ পদ্ধতি
| পদ্ধতি | এটা কিভাবে কাজ করে | জন্য সেরা |
|---------|-------------|------------|
| **API কী** | হেডারে গোপন কী (`X-API-Key: abc123`) | সার্ভার থেকে সার্ভার, সহজ ইন্টিগ্রেশন |
| **OAuth2** | স্কোপ সহ টোকেন-ভিত্তিক প্রতিনিধি দল | তৃতীয় পক্ষের অ্যাক্সেস, ব্যবহারকারী-অনুমোদিত অ্যাপস |
| **JWT** | দাবি সহ স্বয়ংসম্পূর্ণ টোকেন | পরিষেবা জুড়ে রাষ্ট্রহীন প্রমাণীকরণ |
| **মৌলিক প্রমাণ** | Base64-এনকোডেড ব্যবহারকারীর নাম:পাসওয়ার্ড | শুধুমাত্র উন্নয়ন — TLS ছাড়া কখনোই উৎপাদন |
| **সেশন কুকিজ** | শুধুমাত্র HTTP কুকিতে সার্ভার-সাইড সেশন আইডি | ঐতিহ্যগত ওয়েব অ্যাপ্লিকেশন |
### OAuth2 ফ্লো (সরলীকৃত)
1. ক্লায়েন্ট ব্যবহারকারীকে অনুমোদন সার্ভারে পুনঃনির্দেশ করে।
2. ব্যবহারকারী লগ ইন করে এবং অনুমতি দেয়।
3. অনুমোদন সার্ভার একটি অনুমোদন কোড প্রদান করে।
4. অ্যাক্সেস টোকেনের জন্য ক্লায়েন্ট এক্সচেঞ্জ কোড (এবং ঐচ্ছিকভাবে টোকেন রিফ্রেশ)।
5. ক্লায়েন্ট API কল করার জন্য অ্যাক্সেস টোকেন ব্যবহার করে।
6. অ্যাক্সেস টোকেনের মেয়াদ শেষ হয়ে গেলে, একটি নতুন পেতে রিফ্রেশ টোকেন ব্যবহার করুন।

## API শৈলী: REST বনাম GraphQL বনাম gRPC
| বৈশিষ্ট্য | বিশ্রাম | গ্রাফকিউএল | gRPC |
|---------|------|---------|------|
| **ডেটা ফরম্যাট** | JSON (সাধারণত) | JSON | প্রোটোবুফ (বাইনারী) |
| **শেষ পয়েন্ট** | একাধিক (প্রতি সম্পদে একটি) | একক শেষ বিন্দু | .proto ফাইল দ্বারা সংজ্ঞায়িত |
| **ওভার-ফেচিং** | সাধারণ (প্রয়োজনের চেয়ে বেশি পান) | কোনটিই নয় (ক্লায়েন্ট ক্ষেত্র নির্দিষ্ট করে) | কোনোটিই নয় (স্কিমা-সংজ্ঞায়িত) |
| **আন্ডার-ফেচিং** | একাধিক কল প্রয়োজন | কোনটিই নয় (ঠিক যা প্রয়োজন তা পান) | কোনটিই না |
| **রিয়েল-টাইম** | ওয়েবসকেট প্রয়োজন | অন্তর্নির্মিত সদস্যতা | অন্তর্নির্মিত স্ট্রিমিং |
| **ক্যাশিং** | HTTP ক্যাশিং স্বাভাবিকভাবে কাজ করে | ক্যাশে করা কঠিন | লিমিটেড |
| **লার্নিং কার্ভ** | কম | মাঝারি | মাঝারি-উচ্চ |
| **এর জন্য সেরা** | সর্বজনীন API, CRUD অ্যাপস | জটিল UIs, মোবাইল অ্যাপস | অভ্যন্তরীণ মাইক্রোসার্ভিস, উচ্চ-কর্মক্ষমতা |

## পেজিনেশন, ফিল্টারিং এবং বাছাই করা
এন্ডপয়েন্টের জন্য যা তালিকা ফেরত দেয়:
| টেকনিক | উদাহরণ | কখন ব্যবহার করবেন |
|------------|---------|---------------|
| **অফসেট/সীমা** | `?offset=20&limit=10`| সরল; ছোট ডেটাসেটের জন্য কাজ করে |
| **কারসার-ভিত্তিক** | `?cursor=abc123&limit=10`| বড় ডেটাসেট; ধারাবাহিক ফলাফল |
| **কীসেট** | `?created_after=2024-01-01&limit=10`| অত্যন্ত দক্ষ; অনন্য কী প্রয়োজন |
```json
// Cursor-based response
{
  "data": [...],
  "pagination": {
    "next_cursor": "abc123",
    "has_more": true
  }
}
```

## হার সীমাবদ্ধতা
অপব্যবহার থেকে আপনার API রক্ষা করুন এবং ন্যায্য ব্যবহার নিশ্চিত করুন।
| কৌশল | এটা কিভাবে কাজ করে |
|------------|-------------|
| **স্থির জানালা** | টাইম উইন্ডো প্রতি N অনুরোধ (যেমন, 100/ঘন্টা) |
| ** স্লাইডিং উইন্ডো** | আরো দানাদার; রোলিং উইন্ডোতে অনুরোধ গণনা করে |
| **টোকেন বালতি** | নির্দিষ্ট হারে টোকেন যোগ করা হয়েছে; প্রতিটি অনুরোধ একটি টোকেন গ্রহণ করে |
হেডার সহ`429 Too Many Requests`ফেরত দিন:```
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1625097600
Retry-After: 60
```

## ত্রুটি হ্যান্ডলিং
ধারাবাহিক ত্রুটির প্রতিক্রিয়াগুলি এপিআইগুলির সাথে কাজ করা আরও সহজ করে তোলে:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid input data",
    "details": [
      {
        "field": "email",
        "issue": "Invalid email format"
      }
    ]
  }
}
```

**নীতি**: সামঞ্জস্যপূর্ণ ত্রুটি কাঠামো ব্যবহার করুন, অ্যাকশনযোগ্য বার্তা অন্তর্ভুক্ত করুন, স্ট্যান্ডার্ড HTTP স্ট্যাটাস কোড ব্যবহার করুন, পারস্পরিক সম্পর্ক আইডি সহ সার্ভার-সাইডে ত্রুটিগুলি লগ করুন এবং স্ট্যাক ট্রেস বা অভ্যন্তরীণ বিবরণ প্রকাশ করবেন না।

## API ডকুমেন্টেশন
| টুল | বর্ণনা |
|------|---------------|
| **OpenAPI (Swagger)** | REST API ডকুমেন্টেশনের জন্য ইন্ডাস্ট্রি স্ট্যান্ডার্ড |
| **Swagger UI** | OpenAPI স্পেক থেকে ইন্টারেক্টিভ API ডকুমেন্টেশন |
| **পোস্টম্যান** | API পরীক্ষা, ডকুমেন্টেশন, এবং সংগ্রহ ভাগাভাগি |
| **রিডক** | OpenAPI স্পেক থেকে সুন্দর API রেফারেন্স ডক্স |
| **গ্রাফকিউএল খেলার মাঠ / গ্রাফিকিউএল** | ইন্টারেক্টিভ গ্রাফকিউএল এক্সপ্লোরেশন |
**সর্বোত্তম অনুশীলন**: প্রথমে OpenAPI স্পেক লিখুন (স্পেক-চালিত বিকাশ), তারপর এটি থেকে ডকুমেন্টেশন এবং ক্লায়েন্ট SDK তৈরি করুন।

## API গেটওয়ে প্যাটার্নস
একটি API গেটওয়ে ক্লায়েন্ট এবং ব্যাকএন্ড পরিষেবার মধ্যে বসে, একটি একক এন্ট্রি পয়েন্ট প্রদান করে।
| দায়িত্ব | বর্ণনা |
|---------------|---------------|
| **রাউটিং** | উপযুক্ত ব্যাকএন্ড পরিষেবার জন্য সরাসরি অনুরোধ |
| **প্রমাণিকরণ** | গেটওয়ে স্তরে টোকেন যাচাই করুন |
| **হার সীমাবদ্ধতা** | বিশ্বব্যাপী বা প্রতি-ক্লায়েন্ট সীমা প্রয়োগ করুন |
| **পরিবর্তন** | প্রোটোকলের মধ্যে রূপান্তর করুন (REST ↔ gRPC) |
| **ক্যাশিং** | ক্যাশে সাধারণ প্রতিক্রিয়া |
| **মনিটরিং** | কেন্দ্রীভূত লগিং এবং মেট্রিক্স |
| **লোড ব্যালেন্সিং** | পরিষেবা দৃষ্টান্ত জুড়ে ট্রাফিক বিতরণ |
| টুল | প্রকার |
|------|------|
| **কং** | ওপেন সোর্স API গেটওয়ে (Nginx-ভিত্তিক) |
| **AWS API গেটওয়ে** | সম্পূর্ণরূপে পরিচালিত, AWS এর সাথে সংহত |
| ** Azure API ব্যবস্থাপনা** | বিকাশকারী পোর্টালের সাথে পরিচালিত গেটওয়ে |
| **দূত/ইসটিও** | API গেটওয়ে ক্ষমতা সহ পরিষেবা জাল |
| **ট্রাফিক** | স্বতঃ-আবিষ্কার, আসুন একীকরণ এনক্রিপ্ট করি |

## ওয়েবহুক
ওয়েবহুকগুলি পরিবর্তনের জন্য ক্লায়েন্টদের পোল করার পরিবর্তে আপনার এপিআই ইভেন্টগুলিকে রিয়েল-টাইমে ক্লায়েন্টদের কাছে পুশ করতে দেয়।
| দৃষ্টিভঙ্গি | সর্বোত্তম অনুশীলন |
|---------|---------------|
| **ডেলিভারি** | ক্লায়েন্টের URL-এ JSON পেলোড সহ অনুরোধ পোস্ট করুন |
| **নিরাপত্তা** | HMAC এর সাথে পেলোড সাইন ইন করুন; ক্লায়েন্ট স্বাক্ষর যাচাই করে |
| **বিশ্বস্ততা** | সূচকীয় ব্যাকঅফের সাথে ব্যর্থ ডেলিভারির পুনরায় চেষ্টা করুন |
| **আদমশক্তি** | অনন্য ইভেন্ট আইডি অন্তর্ভুক্ত করুন; ক্লায়েন্ট ডুপ্লিকেট পরিচালনা করে |
| **সংস্করণ** | ওয়েবহুক পেলোডে API সংস্করণ অন্তর্ভুক্ত করুন |
