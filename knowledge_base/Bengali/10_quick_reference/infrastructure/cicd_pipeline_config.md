# CI/CD পাইপলাইন কনফিগারেশন
কন্টিনিউয়াস ইন্টিগ্রেশন (সিআই) এবং কন্টিনিউয়াস ডিপ্লয়মেন্ট (সিডি) পাইপলাইনগুলি সফ্টওয়্যার তৈরি, পরীক্ষা এবং স্থাপনের প্রক্রিয়াটিকে স্বয়ংক্রিয় করে। এই রেফারেন্সটি সর্বাধিক জনপ্রিয় CI/CD প্ল্যাটফর্মগুলির কনফিগারেশন প্যাটার্নগুলিকে কভার করে: GitHub অ্যাকশন, GitLab CI, এবং সাধারণ পাইপলাইন ডিজাইনের নীতিগুলি৷
---

## গিটহাব অ্যাকশন
### ওয়ার্কফ্লো স্ট্রাকচার
```yaml
name: CI Pipeline
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up language
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - name: Install dependencies
        run: pip install -r requirements.txt
      - name: Run tests
        run: pytest
      - name: Build
        run: python setup.py build
```

### সাধারণ ট্রিগার
| ট্রিগার | বর্ণনা |
|---------|---------------|
| `on: push`| প্রতি ধাক্কায় |
| `on: pull_request`| পিআর খুলুন, আপডেট করুন, পুনরায় খুলুন |
| `on: schedule`| ক্রন-ভিত্তিক সময়সূচী |
| `on: workflow_dispatch`| ম্যানুয়াল ট্রিগার |
| `on: release`| রিলিজ সৃষ্টিতে |
| `on: workflow_call`| অন্য ওয়ার্কফ্লো দ্বারা কল করা হয়েছে (পুনরায় ব্যবহারযোগ্য) |
### মূল বৈশিষ্ট্য
| বৈশিষ্ট্য | বর্ণনা |
|---------|---------------|
| **ম্যাট্রিক্স কৌশল** | বিভিন্ন কনফিগারেশনের সাথে একই কাজ চালান |
| **গোপন** | এনক্রিপ্ট করা পরিবেশ ভেরিয়েবল (`${{ secrets.MY_SECRET }}`) |
| **পরিবেশ** | সুরক্ষা নিয়ম সহ স্থাপনার লক্ষ্য |
| **ক্যাশিং** | রানের মধ্যে ক্যাশে নির্ভরতা |
| **নিদর্শন** | চাকরি থেকে ফাইল আপলোড করুন (পরীক্ষা প্রতিবেদন, বিল্ড) |
| **পুনঃব্যবহারযোগ্য কর্মপ্রবাহ** | ভান্ডার জুড়ে ওয়ার্কফ্লো যুক্তি শেয়ার করুন |
| **যৌগিক ক্রিয়া** | একটি কর্মে একাধিক ধাপ একত্রিত করুন |
### ম্যাট্রিক্স কৌশল
```yaml
jobs:
  test:
    strategy:
      matrix:
        python-version: ['3.10', '3.11', '3.12']
        os: [ubuntu-latest, macos-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
```

## গিটল্যাব সিআই
### পাইপলাইন গঠন
```yaml
stages:
  - build
  - test
  - deploy

build:
  stage: build
  script:
    - docker build -t myapp:$CI_COMMIT_SHA .
    - docker push myapp:$CI_COMMIT_SHA

test:
  stage: test
  script:
    - docker run myapp:$CI_COMMIT_SHA pytest

deploy:
  stage: deploy
  script:
    - deploy.sh $CI_COMMIT_SHA
  only:
    - main
  when: manual
```

### মূল কীওয়ার্ড
| কীওয়ার্ড | বর্ণনা |
|---------|---------------|
| `stages`| পাইপলাইন পর্যায় এবং তাদের ক্রম সংজ্ঞায়িত করুন |
| `stage`| একটি পর্যায়ে একটি কাজ বরাদ্দ করুন |
| `script`| কার্যকর করার আদেশ |
| `before_script`| প্রধান স্ক্রিপ্টের আগে কমান্ড চালানো হয় |
| `after_script`| কমান্ডগুলি প্রধান স্ক্রিপ্টের পরে চলে (এমনকি ব্যর্থ হলেও) |
| `only / except`| যখন কাজ চালানো হয় নিয়ন্ত্রণ (শাখা, ট্যাগ) |
| `rules`| শুধুমাত্র/ব্যতীত | এর আরও নমনীয় সংস্করণ
| `variables`| CI/CD ভেরিয়েবল সংজ্ঞায়িত করুন |
| `cache`| পাইপলাইন রানের মধ্যে ক্যাশে ফাইল |
| `artifacts`| কাজের মধ্যে পাস করার জন্য ফাইল |
| `environment`| স্থাপনার পরিবেশ |
| `when`| কাজ সম্পাদন নিয়ন্ত্রণ করুন (সফলতা, অন_ব্যর্থতা, ম্যানুয়াল, সর্বদা) |
| `needs`| কাজের নির্ভরতা নির্দিষ্ট করুন (DAG মোড) |
| `extends`| অন্য চাকরি থেকে কনফিগারেশন ইনহেরিট করুন |
| `include`| বাহ্যিক YAML ফাইল আমদানি করুন |
### পূর্বনির্ধারিত ভেরিয়েবল
| পরিবর্তনশীল | বর্ণনা |
|------------|-------------|
| `$CI_COMMIT_SHA`| বর্তমান কমিট হ্যাশ |
| `$CI_COMMIT_REF_NAME`| শাখা বা ট্যাগের নাম |
| `$CI_PIPELINE_ID`| পাইপলাইন আইডি |
| `$CI_JOB_ID`| চাকরির আইডি |
| `$CI_PROJECT_DIR`| প্রকল্পের সম্পূর্ণ পথ |
| `$CI_REGISTRY`| কন্টেইনার রেজিস্ট্রি URL |
| `$CI_DEFAULT_BRANCH`| ডিফল্ট শাখার নাম |

## পাইপলাইন ডিজাইন প্যাটার্ন
### সাধারণ নিদর্শন
| প্যাটার্ন | বর্ণনা |
|---------|---------------|
| **একবার তৈরি করুন, অনেকগুলি স্থাপন করুন** | একবার আর্টিফ্যাক্ট তৈরি করুন; প্রতিটি পরিবেশে একই আর্টিফ্যাক্ট স্থাপন করুন |
| **গেট চেক** | উত্পাদন স্থাপনার আগে ম্যানুয়াল অনুমোদন |
| **ফিচার পতাকা** | উত্পাদনে স্থাপন করুন কিন্তু বৈশিষ্ট্য পতাকার পিছনে লুকান |
| **ক্যানারি স্থাপনা** | ছোট শতাংশে স্থাপন; নিরীক্ষণ রোল আউট |
| **নীল-সবুজ স্থাপনা** | দুটি অভিন্ন পরিবেশ; ট্রাফিক পরিবর্তন করুন |
| **সমান্তরাল পরীক্ষা** | পাইপলাইনের সময় কমাতে সমান্তরালভাবে টেস্ট স্যুট চালান |
| **লিন্ট ফার্স্ট** | ব্যয়বহুল পরীক্ষার আগে লিন্টার চালান; দ্রুত ব্যর্থ |
| **ক্যাশে নির্ভরতা** | ক্যাশে নোড_মডিউল, পিপ, মাভেন তৈরির গতি বাড়াতে |
### পাইপলাইন পর্যায় (সাধারণ)
| মঞ্চ | উদ্দেশ্য |
|-------|---------|
| **লিন্ট** | কোড শৈলী এবং স্ট্যাটিক বিশ্লেষণ |
| **বিল্ড** | সংকলন; বান্ডিল শিল্পকর্ম তৈরি করুন |
| **ইউনিট পরীক্ষা** | দ্রুত পরীক্ষা; কোনো বাহ্যিক নির্ভরতা নেই |
| **একীকরণ পরীক্ষা** | ডাটাবেস সহ পরীক্ষা; এপিআই; বাহ্যিক সেবা |
| **নিরাপত্তা স্ক্যান** | নির্ভরতা দুর্বলতা; গোপন স্ক্যানিং; SAST |
| **প্যাকেজ** | ডকার ইমেজ তৈরি করুন; রিলিজ আর্টিফ্যাক্ট নির্মাণ |
| **মঞ্চায়ন স্থাপন করুন** | পরিবেশন মঞ্চে স্থাপন করুন |
| **E2E পরীক্ষা** | স্টেজিং বিরুদ্ধে সম্পূর্ণ সিস্টেম পরীক্ষা |
| **উৎপাদন স্থাপন করুন** | উৎপাদনে স্থাপন (ম্যানুয়াল বা স্বয়ংক্রিয়) |
| **ধূমপান পরীক্ষা** | স্থাপনা স্বাস্থ্যকর যাচাই করুন |

## সারাংশ
CI/CD পাইপলাইনগুলি স্বয়ংক্রিয়ভাবে বিল্ডিং, টেস্টিং এবং সফ্টওয়্যার স্থাপন করে। GitHub অ্যাকশনগুলি সংগ্রহস্থলের ইভেন্টগুলির দ্বারা ট্রিগার করা YAML ওয়ার্কফ্লো ব্যবহার করে; GitLab CI নমনীয় নিয়ম সহ পর্যায় এবং কাজ ব্যবহার করে। মূল নিদর্শন অন্তর্ভুক্ত: একবার বিল্ড অনেক স্থাপন; উত্পাদনের আগে গেট চেক; দ্রুত প্রতিক্রিয়ার জন্য প্রথমে লিন্ট; নির্মাণের গতি বাড়ানোর জন্য ক্যাশে নির্ভরতা; এবং সমান্তরাল পরীক্ষা। পাইপলাইনের ধাপগুলি সাধারণত লিন্ট → বিল্ড → টেস্ট → সিকিউরিটি → প্যাকেজ → ডিপ্লয় → স্মোক টেস্ট থেকে অগ্রসর হয়। ক্যাশিং কৌশল ভাষা অনুসারে পরিবর্তিত হয় কিন্তু একই নীতি অনুসরণ করে: লক ফাইল হ্যাশ দ্বারা চাবি করা ক্যাশে নির্ভরতা ডিরেক্টরি। লক্ষ্য হল প্রতিটি পরিবর্তনের উপর দ্রুত, নির্ভরযোগ্য প্রতিক্রিয়া এবং উৎপাদনে নিরাপদ, পুনরাবৃত্তিযোগ্য স্থাপনা।
