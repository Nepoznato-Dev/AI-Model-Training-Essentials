# কোড হিসাবে টেরাফর্ম এবং অবকাঠামো
Terraform হল কোড (IaC) টুল হিসাবে সর্বাধিক ব্যবহৃত পরিকাঠামো — এটি আপনাকে ঘোষণামূলক কনফিগারেশন ফাইলগুলিতে ক্লাউড অবকাঠামো (সার্ভার, ডাটাবেস, নেটওয়ার্ক, অনুমতি) সংজ্ঞায়িত করতে দেয় যা সংস্করণ, পর্যালোচনা, পরীক্ষিত এবং স্বয়ংক্রিয় হতে পারে। একটি ক্লাউড কনসোলের মাধ্যমে ক্লিক করার পরিবর্তে, আপনি কোড লিখুন যা আপনার অবকাঠামোর পছন্দসই অবস্থা বর্ণনা করে এবং Terraform কী পরিবর্তন করতে হবে তা নির্ধারণ করে।

## মূল ধারণা
| ধারণা | বর্ণনা |
|---------|---------------|
| **প্রদানকারী** | প্লাগইন যা একটি নির্দিষ্ট ক্লাউড প্ল্যাটফর্ম পরিচালনা করে (AWS, Azure, GCP, ইত্যাদি) |
| **সম্পদ** | একটি অবকাঠামো বস্তু (সার্ভার, ডাটাবেস, নেটওয়ার্ক) |
| **রাজ্য** | কি পরিকাঠামো বিদ্যমান তার Terraform এর রেকর্ড; একটি স্টেট ফাইলে সংরক্ষিত |
| **পরিকল্পনা** | Terraform কি পরিবর্তন আনবে তার পূর্বরূপ |
| **আবেদন** | পরিকল্পনা বাস্তবায়ন; অবকাঠামো তৈরি/আপডেট/ধ্বংস করুন |
| **মডিউল** | সম্পদের পুনঃব্যবহারযোগ্য সংগ্রহ |
| **পরিবর্তনশীল** | কনফিগারেশনের জন্য ইনপুট প্যারামিটার |
| **আউটপুট** | একটি মডিউল বা কনফিগারেশন থেকে রপ্তানি করা মান |
| **ডেটা সোর্স** | বিদ্যমান পরিকাঠামো থেকে তথ্য পড়ুন |

## মৌলিক কর্মপ্রবাহ
| ধাপ | আদেশ | বর্ণনা |
|------|---------|---------------|
| **1। কনফিগারেশন লিখুন** |`.tf`ফাইল তৈরি করুন | প্রদানকারী, সম্পদ, ভেরিয়েবল সংজ্ঞায়িত করুন |
| **2। শুরু করুন** | `terraform init`| ডাউনলোড প্রদানকারী; ব্যাকএন্ড সেট আপ করুন |
| **3। বিন্যাস** | `terraform fmt`| স্ট্যান্ডার্ডাইজ ফরম্যাটিং |
| **4. যাচাই করুন** | `terraform validate`| সিনট্যাক্স এবং কনফিগারেশন পরীক্ষা করুন |
| **5। পরিকল্পনা** | `terraform plan`| পূর্বরূপ পরিবর্তন (ড্রাই রান) |
| **6. আবেদন করুন** | `terraform apply`| অবকাঠামো তৈরি বা আপডেট করুন |
| **7. ধ্বংস ** | `terraform destroy`| সমস্ত পরিচালিত পরিকাঠামো ভেঙে ফেলুন |

## কমন কমান্ড
| আদেশ | বর্ণনা |
|---------|---------------|
| `terraform init`| ওয়ার্কিং ডিরেক্টরি শুরু করুন; ডাউনলোড প্রদানকারী এবং মডিউল |
| `terraform plan`| দেখান কি পরিবর্তন করা হবে |
| `terraform apply`| পরিবর্তনগুলি প্রয়োগ করুন; নিশ্চিতকরণ এড়িয়ে যেতে`-auto-approve`যোগ করুন |
| `terraform destroy`| সমস্ত পরিচালিত সম্পদ ধ্বংস করুন |
| `terraform fmt`| কনফিগারেশন ফাইলগুলিকে স্ট্যান্ডার্ড স্টাইলে ফর্ম্যাট করুন |
| `terraform validate`| কনফিগারেশন সিনট্যাক্স যাচাই করুন |
| `terraform output`| আউটপুট মান দেখান |
| `terraform state list`| রাজ্যের সমস্ত সংস্থান তালিকাভুক্ত করুন |
| `terraform state show <resource>`| একটি নির্দিষ্ট সম্পদের বিবরণ দেখান |
| `terraform import <resource> <id>`| রাজ্যে বিদ্যমান পরিকাঠামো আমদানি করুন |
| `terraform taint <resource>`| পরবর্তী আবেদনে বিনোদনের জন্য একটি সম্পদ চিহ্নিত করুন |
| `terraform refresh`| বাস্তব পরিকাঠামোর সাথে মেলে অবস্থা আপডেট করুন |
| `terraform graph`| একটি ভিজ্যুয়াল নির্ভরতা গ্রাফ তৈরি করুন (DOT বিন্যাস) |
| `terraform console`| এক্সপ্রেশন পরীক্ষার জন্য ইন্টারেক্টিভ কনসোল |

## রাজ্য ব্যবস্থাপনা
| সর্বোত্তম অনুশীলন | বর্ণনা |
|---------------|-------------|
| **দূরবর্তী অবস্থা** | S3, GCS, Azure Blob, বা Terraform ক্লাউডে স্টোর স্টেট — স্থানীয়ভাবে কখনই নয় |
| **স্টেট লকিং** | সমসাময়িক পরিবর্তন রোধ করতে DynamoDB (S3 ব্যাকএন্ড) বা নেটিভ লকিং ব্যবহার করুন |
| **রাষ্ট্রীয় এনক্রিপশন** | রাষ্ট্রীয় ফাইলগুলির জন্য বিশ্রামে এনক্রিপশন সক্ষম করুন (এগুলিতে সংবেদনশীল ডেটা রয়েছে) |
| **রাষ্ট্র বিচ্ছেদ** | বিভিন্ন পরিবেশ বা দলের জন্য পৃথক স্টেট ফাইল ব্যবহার করুন |
| **রাষ্ট্রীয় ব্যাকআপ** | দূরবর্তী ব্যাকএন্ড স্বয়ংক্রিয়ভাবে সংস্করণ অবস্থা; এটি সক্রিয় রাখুন |
| **কখনও ম্যানুয়ালি স্টেট এডিট করবেন না** | পরিবর্তে`terraform state mv`,`rm`,`import`ব্যবহার করুন |

## সারাংশ
Terraform ঘোষণামূলক কনফিগারেশন ফাইলের মাধ্যমে পরিকাঠামো পরিচালনা করে। কর্মপ্রবাহ হল: কনফিগারেশন লিখুন → init → পরিকল্পনা → প্রয়োগ করুন। রাজ্য যা আছে তা ট্র্যাক করে এবং লকিংয়ের মাধ্যমে দূরবর্তীভাবে সংরক্ষণ করা আবশ্যক। মডিউল পুনঃব্যবহার সক্ষম করে। ভেরিয়েবল প্যারামিটারাইজ কনফিগারেশন। মূল নীতিগুলি হল: অবকাঠামোকে কোড হিসাবে বিবেচনা করুন (সংস্করণ নিয়ন্ত্রণ; পর্যালোচনা; পরীক্ষা); ম্যানুয়ালি রাষ্ট্র সম্পাদনা করবেন না; আবেদন করার আগে পরিকল্পনা করুন; লকিং সহ দূরবর্তী অবস্থা ব্যবহার করুন; এবং বজায় রাখার জন্য মডিউল সহ কাঠামো কনফিগারেশন।
