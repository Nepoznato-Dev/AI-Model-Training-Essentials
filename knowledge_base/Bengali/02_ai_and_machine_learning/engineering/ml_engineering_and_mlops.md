# ML ইঞ্জিনিয়ারিং এবং MLOps
একটি মেশিন লার্নিং মডেল তৈরি করা মাত্র অর্ধেক যুদ্ধ। এটিকে উৎপাদনে নিয়ে আসা, এটিকে নির্ভরযোগ্যভাবে চলমান রাখা, ড্রিফটের জন্য পর্যবেক্ষণ করা এবং এটির উপর পুনরাবৃত্তি করা — এখানেই ML ইঞ্জিনিয়ারিং এবং MLOps আসে৷ এই ফাইলটি পরীক্ষা থেকে উৎপাদন ব্যবস্থা পর্যন্ত সম্পূর্ণ জীবনচক্রকে কভার করে৷
---

## এমএল লাইফসাইকেল
| পর্যায় | বর্ণনা | মূল কার্যক্রম |
|---------|-------------|---------------|
| **1। সমস্যার সংজ্ঞা** | ব্যবসায়িক সমস্যাটিকে একটি ML টাস্ক হিসাবে ফ্রেম করুন | মেট্রিক্স, সীমাবদ্ধতা, সাফল্যের মানদণ্ড সংজ্ঞায়িত করুন |
| **2। তথ্য সংগ্রহ** | প্রশিক্ষণ তথ্য সংগ্রহ এবং লেবেল | ETL, লেবেলিং, পরিবর্ধন |
| **3. পরীক্ষা** | ট্রেন এবং মডেল মূল্যায়ন | ফিচার ইঞ্জিনিয়ারিং, হাইপারপ্যারামিটার টিউনিং |
| **4. মডেল নির্বাচন** | সেরা মডেল নির্বাচন করুন | মেট্রিক্স তুলনা করুন, ট্রেড-অফ মূল্যায়ন করুন |
| **5। স্থাপনা** | উৎপাদনে মডেল পাঠান | পরিকাঠামো পরিবেশন করা, API, ব্যাচ |
| **6. মনিটরিং** | প্রবাহ এবং অধঃপতনের জন্য দেখুন | ডেটা প্রবাহ, ধারণা প্রবাহ, কর্মক্ষমতা |
| **7. পুনরায় প্রশিক্ষণ** | নতুন ডেটা সহ মডেল আপডেট করুন | নির্ধারিত বা ট্রিগার পুনঃপ্রশিক্ষণ |
বেশিরভাগ মান (এবং অসুবিধা) পর্যায়ক্রমে 5-7। জুপিটার নোটবুকে বসা একটি মডেল ব্যবসায়িক মূল্য তৈরি করে না।

## মডেল রেজিস্ট্রি
একটি মডেল রেজিস্ট্রি হল ML মডেলগুলি পরিচালনা করার জন্য একটি কেন্দ্রীভূত স্টোর — তাদের সংস্করণ, মেটাডেটা, মেট্রিক্স এবং স্থাপনার স্থিতি।
| সামর্থ্য | বর্ণনা |
|------------|-------------|
| **সংস্করণ** | অনন্য আইডি সহ প্রতিটি মডেল সংস্করণ ট্র্যাক করুন |
| **মেটাডেটা** | প্রশিক্ষণের ডেটা, হাইপারপ্যারামিটার, মেট্রিক্স, লেখক |
| **পর্যায় পরিবর্তন** | পর্যায়গুলির মধ্য দিয়ে মডেলগুলি সরান: মঞ্চায়ন → উৎপাদন → সংরক্ষণাগারভুক্ত |
| **বংশ** | কোন ডেটা এবং কোড প্রতিটি মডেল উত্পাদিত ট্রেস |
| টুল | বর্ণনা |
|------|---------------|
| **MLflow** | উন্মুক্ত উৎস; মডেল রেজিস্ট্রি + পরীক্ষা ট্র্যাকিং |
| **ওজন ও পক্ষপাত (W&B)** | বাণিজ্যিক; পরীক্ষা ট্র্যাকিং + মডেল রেজিস্ট্রি |
| **DVC** | Git এর সাথে ডেটা এবং মডেল সংস্করণ |
| ** Azure ML / SageMaker** | ক্লাউড-নেটিভ মডেল ব্যবস্থাপনা |

## এক্সপেরিমেন্ট ট্র্যাকিং
প্রতিটি ML পরীক্ষা ট্র্যাক করা উচিত: কোন ডেটা ব্যবহার করা হয়েছিল, কোন হাইপারপ্যারামিটার, কোন মেট্রিক্সের ফলাফল।
| টুল | মূল বৈশিষ্ট্য |
|------|---------------|
| **MLflow** | ওপেন-সোর্স, স্ব-হোস্টেড, প্যারাম/মেট্রিক্স/আর্টিফ্যাক্ট ট্র্যাক করে
| **W&B** | সমৃদ্ধ UI, sweeps, artifact versioning, reports |
| **নেপচুন** | MLOps এর জন্য মেটাডেটা স্টোর |
| **টেনসরবোর্ড** | TensorFlow মধ্যে নির্মিত; প্রশিক্ষণ বক্ররেখা কল্পনা করুন |
### কী ট্র্যাক করবেন
| বিভাগ | উদাহরণ |
|----------|---------|
| **প্যারামিটার** | শেখার হার, ব্যাচের আকার, মডেল আর্কিটেকচার, যুগের সংখ্যা |
| **মেট্রিক্স** | নির্ভুলতা, ক্ষতি, F1, AUC-ROC (প্রতি যুগ এবং চূড়ান্ত) |
| **নিদর্শন** | মডেল ওজন, বিভ্রান্তি ম্যাট্রিক্স, ভবিষ্যদ্বাণী নমুনা |
| **ডেটা** | ডেটাসেট সংস্করণ, বিভক্ত অনুপাত, প্রিপ্রসেসিং পদক্ষেপ |
| **পরিবেশ** | পাইথন সংস্করণ, লাইব্রেরি সংস্করণ, হার্ডওয়্যার |

## এমএল সিস্টেম মনিটরিং
এমএল সিস্টেমগুলিকে প্রথাগত সফ্টওয়্যারের চেয়ে বেশি পর্যবেক্ষণের প্রয়োজন কারণ ডেটা নিজেই পরিবর্তন করতে পারে।
### প্রবাহের প্রকার
| ড্রিফ্ট টাইপ | কি পরিবর্তন | উদাহরণ |
|------------|---------------|---------|
| **ডেটা ড্রিফ্ট** | ইনপুট বিতরণ পরিবর্তন | একটি বিপণন প্রচারের পরে গ্রাহক জনসংখ্যার পরিবর্তন |
| **কনসেপ্ট ড্রিফ্ট** | ইনপুট এবং আউটপুট পরিবর্তনের মধ্যে সম্পর্ক | মন্দার সময় ভোক্তাদের আচরণ পরিবর্তিত হয় |
| **লেবেল ড্রিফ্ট** | লক্ষ্য বন্টন পরিবর্তন | জালিয়াতির হার 1% থেকে 5% পর্যন্ত বৃদ্ধি পায় |
### কি মনিটর করবেন
| বিভাগ | মেট্রিক্স |
|----------|---------|
| **মডেল পারফরম্যান্স** | নির্ভুলতা, নির্ভুলতা, প্রত্যাহার, F1, AUC (বেসলাইনের তুলনায়) |
| **ডেটা কোয়ালিটি** | অনুপস্থিত মান, বৈশিষ্ট্য বিতরণ, আউটলায়ার |
| **ড্রিফট সনাক্তকরণ** | পরিসংখ্যানগত পরীক্ষা (KS পরীক্ষা, PSI, KL ডাইভারজেন্স) |
| **অবকাঠামো** | লেটেন্সি, থ্রুপুট, জিপিইউ ব্যবহার, মেমরি |
| **বিজনেস মেট্রিক্স** | রূপান্তর হার, রাজস্ব প্রভাব, ব্যবহারকারীর সন্তুষ্টি |
### মনিটরিং টুল
| টুল | প্রকার |
|------|------|
| **স্পষ্টতই AI** | ওপেন সোর্স ডেটা ড্রিফ্ট এবং মডেল পারফরম্যান্স পর্যবেক্ষণ |
| **গ্রাফনা** | ড্যাশবোর্ড ভিজ্যুয়ালাইজেশন (প্রমিথিউসের সাথে কাজ করে) |
| **কেন ল্যাবস** | ডেটা পর্যবেক্ষণ প্ল্যাটফর্ম |
| **আরাইজ** | ML পর্যবেক্ষণযোগ্যতা এবং মূল কারণ বিশ্লেষণ |
| **প্রমিথিউস + গ্রাফানা** | অবকাঠামো এবং অ্যাপ্লিকেশন মেট্রিক্স |

## প্রজননযোগ্য প্রশিক্ষণ
প্রজননযোগ্যতা মানে আপনি একটি পরীক্ষা পুনরায় চালাতে পারেন এবং একই ফলাফল পেতে পারেন। এটি ডিবাগিং, অডিটিং এবং সম্মতির জন্য অপরিহার্য।
### প্রয়োজনীয়তা
| প্রয়োজনীয়তা | কিভাবে এটা অর্জন করতে হবে |
|---------------|-------------------|
| **ডেটা সংস্করণ** | DVC, ডেল্টা লেক, বা হ্যাশ সহ ডেটাসেট স্ন্যাপশট |
| **কোড সংস্করণ** | সমস্ত প্রশিক্ষণ কোডের জন্য গিট |
| **পরিবেশ পিনিং** | `requirements.txt`,`conda env`, সঠিক সংস্করণ সহ ডকার ছবি |
| **বীজ সেটিং** | নম্পি, টর্চ, টেনসরফ্লো এর জন্য এলোমেলো বীজ ঠিক করুন |
| **কনফিগ ব্যবস্থাপনা** | Hydra, OmegaConf, বা YAML কনফিগার সব হাইপারপ্যারামিটারের জন্য |
| **আর্টিফ্যাক্ট ট্র্যাকিং** | প্রতিটি পরীক্ষা লগ করার জন্য MLflow বা W&B |

|------------|-------------|
| **ব্যাচিং** | একক ফরোয়ার্ড পাসে একাধিক অনুরোধ গ্রুপ করুন |
| **পরিমাণ** | দ্রুত অনুমানের জন্য মডেলের নির্ভুলতা হ্রাস করুন (FP32 → INT8 বা INT4) |
| **মডেল পাতন** | একটি বড় মডেলকে অনুকরণ করতে একটি ছোট মডেলকে প্রশিক্ষণ দিন |
| **ছাঁটাই** | গুরুত্বহীন ওজন বা নিউরন সরান |
| **ক্যাশিং** | পুনঃগণনা এড়াতে ঘন ঘন ভবিষ্যদ্বাণী ক্যাশে |
| **GPU অপ্টিমাইজেশন** | TensorRT, ONNX রানটাইম, ফ্ল্যাশ মনোযোগ |
| **অনুভূমিক স্কেলিং** | একটি লোড ব্যালেন্সারের পিছনে একাধিক মডেলের প্রতিলিপি চালান |

## ML এর জন্য ফিচার ফ্ল্যাগ
ফিচার ফ্ল্যাগগুলি আপনাকে নিয়ন্ত্রণ করতে দেয় কোন মডেল সংস্করণ কোন ব্যবহারকারীদের পরিষেবা দেয়, পুনঃনিয়োগ না করে।
| কেস ব্যবহার করুন | বর্ণনা |
|------------|-------------|
| **ক্রমিক রোলআউট** | 5% ব্যবহারকারীদের নতুন মডেল পরিবেশন করুন, তারপর বৃদ্ধি করুন |
| **কিল সুইচ** | সমস্যা সনাক্ত হলে তাৎক্ষণিকভাবে পূর্ববর্তী মডেলে ফিরে যান |
| **সেগমেন্ট-ভিত্তিক** | বিভিন্ন ব্যবহারকারী বিভাগের জন্য বিভিন্ন মডেল |
| **পরীক্ষা** | ব্যবসায়িক মেট্রিক্স সহ A/B পরীক্ষার মডেল ভেরিয়েন্ট |
টুলস: লঞ্চ ডার্কলি, আনলিশ, ফ্ল্যাগস্মিথ, বা সাধারণ ডাটাবেস-সমর্থিত বৈশিষ্ট্য পতাকা।

## MLOps পরিপক্কতা বক্ররেখা
| স্তর | বৈশিষ্ট্য |
|---------|----------------|
| **লেভেল 0 — ম্যানুয়াল** | ম্যানুয়াল প্রশিক্ষণ, ম্যানুয়াল স্থাপনা, কোন পর্যবেক্ষণ নেই |
| **লেভেল 1 — পরীক্ষা** | এক্সপেরিমেন্ট ট্র্যাকিং, মডেল রেজিস্ট্রি, বেসিক সিআই |
| **লেভেল 2 — অটোমেশন** | স্বয়ংক্রিয় পুনরায় প্রশিক্ষণ, মডেলের জন্য CI/CD, স্বয়ংক্রিয় পরীক্ষা |
| **লেভেল 3 — সম্পূর্ণ পাইপলাইন** | এন্ড-টু-এন্ড স্বয়ংক্রিয় পাইপলাইন পর্যবেক্ষণ, ড্রিফট সনাক্তকরণ এবং স্বয়ংক্রিয়-পুনঃপ্রশিক্ষণ সহ |
বেশিরভাগ প্রতিষ্ঠানই লেভেল 0 এবং লেভেল 1 এর মধ্যে রয়েছে। লক্ষ্য হল লেভেল 2-3, যেখানে ML জীবনচক্র স্বয়ংক্রিয় এবং স্ব-নিরাময়।
