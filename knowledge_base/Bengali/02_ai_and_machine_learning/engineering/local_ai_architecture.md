# স্থানীয় এআই আর্কিটেকচার
বৃহৎ ভাষার মডেলগুলি সম্পূর্ণরূপে অন-ডিভাইস চালানোর জন্য একটি ব্যবহারিক নির্দেশিকা — হার্ডওয়্যার বিবেচনা, অনুমান ইঞ্জিন, মেমরি অপ্টিমাইজেশন, এবং প্রান্ত স্থাপনের জন্য সিস্টেম ডিজাইন।
---

## কেন স্থানীয়ভাবে এআই চালাবেন?
- **গোপনীয়তা**: কোনো ডেটা ডিভাইস ছেড়ে যায় না।
- **খরচ**: টোকেন প্রতি কোন API ফি নেই।
- **লেটেন্সি**: অনুমানযোগ্য, নেটওয়ার্ক-মুক্ত অনুমান।
- **অফলাইন উপলব্ধতা**: ইন্টারনেট ছাড়াই কাজ করে।
- **নিয়ন্ত্রণ**: মডেল সংস্করণ, কাস্টমাইজেশন এবং ফাইন-টিউনিংয়ের উপর সম্পূর্ণ নিয়ন্ত্রণ।

## হার্ডওয়্যারের প্রয়োজনীয়তা
### GPU মেমরি (VRAM)
সবচেয়ে গুরুত্বপূর্ণ সম্পদ। মেমরিতে মডেলের আকার ≈ **প্যারামিটার × বাইট প্রতি প্যারামিটার**।
| নির্ভুলতা | প্যারামিটার প্রতি বাইট | 3.8B মডেল | 7B মডেল | 13B মডেল | 70B মডেল |
|------------|----------|------------|------------|------------|------------|
| FP32 | 4 | ~15 জিবি | ~28 জিবি | ~52 জিবি | ~280 জিবি |
| FP16 | 2 | ~7.6 জিবি | ~14 জিবি | ~26 জিবি | ~140 জিবি |
| INT8 (8-বিট) | 1 | ~3.8 জিবি | ~7 জিবি | ~13 জিবি | ~70 জিবি |
| INT4 (4-বিট) | 0.5 | ~1.9 জিবি | ~3.5 জিবি | ~6.5 জিবি | ~35 জিবি |
**ব্যবহারিক নির্দেশিকা:**
- 8GB VRAM → 4-বিটে 7B মডেল পর্যন্ত।
- 12GB VRAM → 4-বিটে 13B মডেল পর্যন্ত।
- 24GB VRAM → 4-বিটে 70B মডেল পর্যন্ত (বা 8-বিটে 13B)।
- অ্যাপল সিলিকন (ইউনিফায়েড মেমরি) 64GB+ সিস্টেমে 70B মডেল চালাতে পারে।
### RAM (সিস্টেম মেমরি)
- CPU অনুমানের জন্য, মডেলটি লোড করার জন্য আপনার যথেষ্ট সিস্টেম RAM প্রয়োজন (VRAM সংখ্যার মতো)।
- GPU অনুমানের জন্য, VRAM এ অফলোড করার আগে মডেলটিকে মেমরিতে লোড করার জন্য সিস্টেম RAM গুরুত্বপূর্ণ।
### স্টোরেজ
- কোয়ান্টাইজড মডেলের ওজন কয়েক জিবি নেয় (যেমন, ডিস্কে 4-বিট 7B ≈ 4 GB)। একাধিক মডেলের জন্য কমপক্ষে 20-50 GB বিনামূল্যে নিশ্চিত করুন৷
### সিপিইউ
- প্রম্পট প্রসেসিং (প্রিফিল) এবং CPU-অফলোডিংয়ের জন্য, একটি আধুনিক মাল্টি-কোর CPU সাহায্য করে।
- ইউনিফাইড মেমরি এবং নিউরাল ইঞ্জিনের কারণে অ্যাপল এম-সিরিজ চিপগুলির LLM-এর জন্য দুর্দান্ত পারফরম্যান্স রয়েছে।

## ইনফারেন্স ইঞ্জিন (স্থানীয়)
### llama.cpp
- C++ এ লেখা।
- GGUF ফর্ম্যাট সমর্থন করে।
- CPU এবং GPU এর জন্য অপ্টিমাইজ করা হয়েছে (CUDA, Metal, OpenCL এর মাধ্যমে)।
- খুব দ্রুত, বিশেষ করে CPU তে।
- কমান্ড-লাইন, সার্ভার মোড এবং পাইথন বাইন্ডিং।
**উদাহরণ কমান্ড:**```bash
./llama-cli -m model.Q4_K_M.gguf -p "Tell me a joke" -n 100 -ngl 32
# -ngl 32 offloads 32 layers to GPU
```

### ওল্লামা
- একটি সাধারণ CLI এবং REST API দিয়ে llama.cpp মোড়ানো।
- মডেল অটো-ডাউনলোড করে, সেগুলি পরিচালনা করে।
- প্রোটোটাইপিং এবং ডেস্কটপ অ্যাপ্লিকেশনের জন্য দুর্দান্ত।
- সিস্টেম প্রম্পটের জন্য কাস্টম মডেল ফাইল সমর্থন করে।
```bash
ollama run phi3:3.8b
ollama run llama3:8b
```

### এলএম স্টুডিও
- Windows, macOS, Linux-এর জন্য গ্রাফিক্যাল ডেস্কটপ অ্যাপ।
- এক-ক্লিক ডাউনলোড এবং চ্যাট ইন্টারফেস।
- OpenAI- সামঞ্জস্যপূর্ণ API সহ অন্তর্নির্মিত স্থানীয় সার্ভার।
- অ-প্রযুক্তিগত ব্যবহারকারী এবং দ্রুত পরীক্ষার জন্য ভাল।
### হাগিং ফেস ট্রান্সফরমার + বিটস্যান্ডবাইট
- HF মডেলের জন্য আদর্শ পাইথন লাইব্রেরি।
- 4-বিট কোয়ান্টাইজেশনের জন্য`bitsandbytes`ব্যবহার করুন ( `load_in_4bit=True`)।
- ফাইন-টিউনিংয়ের জন্য আরও নমনীয় কিন্তু অনুমানের জন্য llama.cpp থেকে ধীর।
### ExLlamaV2
- GPTQ এবং AWQ এর জন্য খুব দ্রুত GPU অনুমান।
- NVIDIA GPU-তে সেরা পারফরম্যান্স।
- ব্যাচড প্রজন্মকে সমর্থন করে।
### mlx (অ্যাপল)
- এম-সিরিজ চিপসের জন্য অ্যাপলের ফ্রেমওয়ার্ক।
- অ্যাপল সিলিকনের জন্য অত্যন্ত অপ্টিমাইজ করা।
- পাইথন API।

## মেমরি ম্যানেজমেন্ট
### প্রসঙ্গ উইন্ডো এবং কেভি ক্যাশে
কেভি ক্যাশে প্রতিটি স্তর এবং প্রসঙ্গের প্রতিটি টোকেনের জন্য কী-মান জোড়া সংরক্ষণ করে। এটি প্রসঙ্গ দৈর্ঘ্যের সাথে রৈখিকভাবে বৃদ্ধি পায়।
মেমরি খরচ ≈ 2 × স্তর × (কেভি হেড × হেড ডিম) × টোকেন × বাইট প্রতি মান
8 KV হেড এবং 128 হেড ডিম সহ একটি 32-লেয়ার মডেলের জন্য, প্রতিটি টোকেনের দাম ~32 × 8 × 128 × 2 বাইট = 65 KB প্রতি টোকেন। 128k টোকেনের জন্য, এটি ক্যাশের জন্য ~8 GB।
### অফলোডিং কৌশল
- **লেয়ার অফলোডিং**: কিছু লেয়ার GPU-তে রাখুন, অন্যগুলি CPU-তে রাখুন। বিশুদ্ধ CPU এর চেয়ে দ্রুত, কম VRAM প্রয়োজন।
- **টোকেন স্ট্রিমিং**: টোকেনগুলি একবারে না করে ক্রমবর্ধমানভাবে প্রক্রিয়া করুন৷
### প্রম্পট ক্যাশিং
প্রিফিল ফেজ পুনরায় গণনা এড়াতে অনুরূপ প্রম্পট জুড়ে KV ক্যাশে পুনরায় ব্যবহার করুন। কিছু ফ্রেমওয়ার্ক এটিকে সমর্থন করে (যেমন, vLLM, llama.cpp`--prompt-cache`এর সাথে)।
### মেমরি-ম্যাপ করা ফাইল
সম্পূর্ণরূপে RAM এ লোড না করে সরাসরি ডিস্ক থেকে মডেলের ওজন লোড করুন (মেমরি-সীমিত সিস্টেমে বিশাল মডেলের জন্য দরকারী)। llama.cpp ডিফল্টরূপে মেমরি-ম্যাপিং ব্যবহার করে।

## স্থাপনার আর্কিটেকচার
### একক-ডিভাইস মোড
একটি মডেল একটি মেশিনে চলে (ল্যাপটপ, স্মার্টফোন, প্রান্ত ডিভাইস)। ব্যক্তিগত সহকারী, নোট নেওয়ার অ্যাপ, কোড সমাপ্তির জন্য ব্যবহৃত হয়।
### হাইব্রিড এজ-ক্লাউড
স্থানীয় মডেল সাধারণ প্রশ্নগুলি পরিচালনা করে; জটিল প্রশ্নের জন্য একটি ক্লাউড মডেলে পতন। এটি উভয় জগতের সেরা দেয় — গতি/বেশিরভাগের জন্য ব্যক্তিগত, প্রান্ত ক্ষেত্রের জন্য ক্ষমতা।
### বিতরণকৃত অনুমান (মাল্টি-জিপিইউ)
বৃহত্তর মডেলগুলির জন্য, একাধিক GPU জুড়ে স্তরগুলিকে বিভক্ত করুন (টেনসর সমান্তরালতা) বা ডিভাইসগুলি জুড়ে বিভক্ত প্রসঙ্গ (পাইপলাইন সমান্তরালতা)।`-ngl`এর সাথে llama.cpp বা`--num-gpu-layers`এর সাথে ExLlamaV2 ব্যবহার করুন৷
### মোবাইল স্থাপনা
- **Android**: JNI বাইন্ডিং বা ML Kit এর মাধ্যমে llama.cpp ব্যবহার করুন।
- **iOS**: Swift bindings বা mlx এর মাধ্যমে llama.cpp ব্যবহার করুন।
- **ওয়েব**: WebLLM (ONNX রানটাইমের মাধ্যমে WebGPU তে চলে) বা transformers.js ব্যবহার করুন।

## কর্মক্ষমতা অপ্টিমাইজেশান
### ফ্ল্যাশ মনোযোগ
মনোযোগ গণনার গতি বাড়ায় এবং মেমরির ব্যবহার হ্রাস করে। llama.cpp, ExLlamaV2 এবং আধুনিক ট্রান্সফরমার লাইব্রেরিতে পাওয়া যায়।
### ব্যাচ ইনফারেন্স
একটি একক ফরওয়ার্ড পাসে একাধিক প্রম্পট প্রক্রিয়া করুন। নাটকীয়ভাবে থ্রুপুট বৃদ্ধি করে।`llama-batch`বা vLLM ব্যবহার করুন।
### প্রারম্ভিক স্টপিং / টোকেন বাজেটিং

### অনুমানমূলক ডিকোডিং
টোকেনগুলির পূর্বাভাস দিতে একটি ছোট দ্রুত মডেল (খসড়া) ব্যবহার করুন, তারপর সমান্তরালে বড় মডেলের সাথে যাচাই করুন৷ 2-3× স্পীডআপ দিতে পারে।

## ব্যবহারিক সেটআপ গাইড
### 1. ওল্লামা ইনস্টল করুন
```bash
curl -fsSL https://ollama.com/install.sh | sh
```

### 2. একটি মডেল টানুন
```bash
ollama pull phi3:3.8b-q4_K_M
```

### 3. API দিয়ে চালান
```bash
ollama serve
```

তারপর`http://localhost:11434/api/generate`এ অনুরোধ পাঠান।
### 4. পাইথন ইন্টিগ্রেশন
```python
import requests

response = requests.post(
    "http://localhost:11434/api/generate",
    json={"model": "phi3:3.8b", "prompt": "Hello", "stream": False}
)
print(response.json()["response"])
```

### 5. (বিকল্প) সরাসরি llama.cpp ব্যবহার করুন
```bash
# Download GGUF from Hugging Face
wget https://huggingface.co/microsoft/Phi-3-mini-4k-instruct-gguf/resolve/main/Phi-3-mini-4k-instruct-q4_K_M.gguf

# Run server
./llama-server -m Phi-3-mini-4k-instruct-q4_K_M.gguf --host 0.0.0.0 --port 8080
```

- llama.cpp বা ওল্লামা থেকে বিল্ট-ইন লগিং ব্যবহার করুন।

## সীমাবদ্ধতা এবং ট্রেডঅফ
- **গুণগত ব্যবধান**: ছোট স্থানীয় মডেলগুলি (3.8B–7B) সাধারণত জটিল যুক্তিতে বড় ক্লাউড মডেলগুলি (GPT-4, Claude 3.5) কম করে।
- **নলেজ কাটঅফ**: প্রশিক্ষণের সময় মডেল জ্ঞান হিমায়িত হয়; বর্তমান তথ্য ইনজেক্ট করতে RAG ব্যবহার করুন।
- **বহুভাষিক**: ছোট মডেলের কম বহুভাষিক ক্ষমতা থাকতে পারে।
- **টুল ব্যবহার**: এজেন্টিক ওয়ার্কফ্লো (ফাংশন কলিং) ছোট মডেলগুলিতে কম নির্ভরযোগ্য হতে পারে।
অনেক দৈনন্দিন কাজের জন্য (সারসংক্ষেপ, প্রশ্নোত্তর, কোড সমাপ্তি, শ্রেণীবিভাগ), স্থানীয় মডেল ইতিমধ্যেই যথেষ্ট এবং দ্রুত উন্নতি করছে।
