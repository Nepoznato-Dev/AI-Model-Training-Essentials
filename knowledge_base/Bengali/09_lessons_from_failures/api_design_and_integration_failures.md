# API ডিজাইন এবং ইন্টিগ্রেশন ব্যর্থতা
APIs (অ্যাপ্লিকেশন প্রোগ্রামিং ইন্টারফেস) হল আধুনিক সফ্টওয়্যারের সংযোগকারী টিস্যু — তারা পরিষেবাগুলিকে যোগাযোগ করতে দেয়, তৃতীয় পক্ষকে একীভূত করতে দেয় এবং দলগুলিকে স্বাধীনভাবে কাজ করতে দেয়। যখন এপিআই ডিজাইন ভুল হয়ে যায়, তখন এর উপর নির্ভরশীল প্রতিটি সিস্টেম জুড়ে এর পরিণতি ছড়িয়ে পড়ে: ভাঙা ইন্টিগ্রেশন, নিরাপত্তা দুর্বলতা, বিকাশকারীর হতাশা এবং ব্যয়বহুল পুনর্লিখন। ইন্টিগ্রেশন ব্যর্থতা - যেখানে সিস্টেমগুলি নির্ভরযোগ্যভাবে যোগাযোগ করতে পারে না - উত্পাদন ঘটনার সবচেয়ে সাধারণ উত্সগুলির মধ্যে একটি।

## সাধারণ API ডিজাইন ব্যর্থতা
### ডিজাইনের ভুল
| ভুল | বর্ণনা | পরিণতি |
|---------|---------------|------------|
| **অসঙ্গত নামকরণ** | `/getUsers`বনাম`/list_users`বনাম`/fetch-users`| বিভ্রান্তি; ত্রুটি; ধীর বিকাশ |
| **ওভারলোডেড এন্ডপয়েন্ট** | একটি শেষ পয়েন্ট যা পরামিতিগুলির উপর ভিত্তি করে 10টি ভিন্ন জিনিস করে | বোঝা কঠিন; পরীক্ষা করা কঠিন; পরিবর্তন করা কঠিন |
| **আন্ডার-ফেচিং** | সম্পর্কিত ডেটা পেতে ক্লায়েন্টকে 5টি API কল করতে হবে | ধীর; অপচয়কারী জটিল ক্লায়েন্ট কোড |
| **ওভার-ফেচিং** | ক্লায়েন্টের শুধুমাত্র 2 | প্রয়োজন হলে API সমস্ত ক্ষেত্র ফেরত দেয় নষ্ট ব্যান্ডউইথ; মোবাইলে ধীরগতি; নিরাপত্তা ঝুঁকি (অপ্রয়োজনীয় তথ্য প্রকাশ) |
| **কোন সংস্করণ নেই** | ব্রেকিং পরিবর্তনগুলি সতর্কতা ছাড়াই স্থাপন করা হয়েছে | ক্লায়েন্ট বিরতি; ক্রুদ্ধ ডেভেলপাররা |
| **অস্পষ্ট ত্রুটি বার্তা** | "ত্রুটি 500: অভ্যন্তরীণ সার্ভার ত্রুটি" বিশদ বিবরণ ছাড়াই | ডিবাগ করা অসম্ভব; ধীর রেজোলিউশন |
| **পেজিনেশন অনুপস্থিত** | এন্ডপয়েন্ট সমস্ত রেকর্ড ফেরত দেয় ( লক্ষ লক্ষ হতে পারে) | সময়সীমা; স্মৃতি ক্লান্তি; ক্র্যাশড ক্লায়েন্ট |
| **অসঙ্গত স্ট্যাটাস কোড** | 200 ত্রুটির জন্য ঠিক আছে; ক্লায়েন্ট ভুলের জন্য 500 | ক্লায়েন্টরা ব্যর্থতা থেকে সাফল্যের পার্থক্য করতে পারে না |
### REST API অ্যান্টি-প্যাটার্নস
| বিরোধী প্যাটার্ন | বর্ণনা | উন্নত পদ্ধতি |
|---------------|---------------|-------------------|
| **মিউটেশনের জন্য GET ব্যবহার করা** | `GET /delete-user?id=5`| DELETE পদ্ধতি ব্যবহার করুন |
| **সবকিছুর জন্য পোস্ট ব্যবহার করা** | `POST /get-users`; `POST /update-user`| উপযুক্ত HTTP পদ্ধতি ব্যবহার করুন (GET, POST, PUT, PATCH, DELETE) |
| **এপিআই থেকে এইচটিএমএল রিটার্নিং** | এপিআই এইচটিএমএল টুকরা প্রদান করে | JSON রিটার্ন; ক্লায়েন্ট রেন্ডার করতে দিন |
| **ইউআরএলগুলিতে ব্যবসায়িক যুক্তি** | `/users/active/premium/from-2023`| ক্যোয়ারী প্যারামিটার ব্যবহার করুন বা জটিল ফিল্টারের জন্য বডি অনুরোধ করুন |
| **ডাটাবেস স্কিমা প্রকাশ করা** | `/api/table_name/column`| রিসোর্স এবং ডোমেন ধারণার চারপাশে ডিজাইন API, টেবিল নয় |
| **কোন HATEOAS / লিঙ্ক নেই** | ক্লায়েন্ট হার্ডকোড সব URLs | প্রতিক্রিয়াগুলিতে সম্পর্কিত সংস্থানগুলির লিঙ্কগুলি অন্তর্ভুক্ত করুন |

## নিরাপত্তা ব্যর্থতা
### সাধারণ API দুর্বলতা
| দুর্বলতা | বর্ণনা | উদাহরণ |
|---------------|---------------|---------|
| **ভাঙা প্রমাণীকরণ** | API সঠিকভাবে পরিচয় যাচাই করে না | অনুপস্থিত টোকেন বৈধতা; মেয়াদ উত্তীর্ণ টোকেন গৃহীত |
| **অতিরিক্ত ডেটা এক্সপোজার** | API ক্লায়েন্টের চাহিদার চেয়ে বেশি ডেটা ফেরত দেয় | ব্যবহারকারীর এন্ডপয়েন্ট পাসওয়ার্ড হ্যাশ এবং অভ্যন্তরীণ আইডি ফেরত দেয় |
| **মাস অ্যাসাইনমেন্ট** | ক্লায়েন্ট ক্ষেত্র সেট করতে পারে তাদের উচিত নয় | `PATCH /user``role: "admin"` | সেট করার অনুমতি দেয়
| **ইনজেকশন** | ব্যবহারকারীর ইনপুট কোড হিসাবে ব্যাখ্যা করা হয়েছে | এসকিউএল ইনজেকশন; NoSQL ইনজেকশন; কমান্ড ইনজেকশন |
| **IDOR** (অনিরাপদ প্রত্যক্ষ অবজেক্ট রেফারেন্স) | ইউআরএলে আইডি পরিবর্তন করে সম্পদ অ্যাক্সেস করা | `/api/users/5`→ অন্য কারো ডেটা দেখতে`/api/users/6`এ পরিবর্তন করুন |
| ** হার সীমিত অনুপস্থিত** | API কলের কোন সীমা নেই | পাশবিক শক্তি; সেবা অস্বীকার; স্ক্র্যাপিং |
| **CORS ভুল কনফিগারেশন** | অতিমাত্রায় অনুমোদিত ক্রস-অরিজিন অ্যাক্সেস | `Access-Control-Allow-Origin: *`প্রমাণীকৃত শেষ পয়েন্টে |
### প্রমাণীকরণ এবং অনুমোদনের ব্যর্থতা
| ব্যর্থতা | বর্ণনা | প্রভাব |
|---------|---------------|---------|
| **হার্ডকোডেড শংসাপত্র** | সোর্স কোডে API কী বা পাসওয়ার্ড | সংস্করণ নিয়ন্ত্রণ মাধ্যমে ফাঁস; সকল ডেভেলপারদের কাছে অ্যাক্সেসযোগ্য |
| **কোন টোকেনের মেয়াদ নেই** | টোকেন কখনই মেয়াদ শেষ হয় না | চুরি করা টোকেন স্থায়ী অ্যাক্সেস দেয় |
| **দুর্বল গোপন কী** | সংক্ষিপ্ত বা অনুমানযোগ্য সাইনিং কী | টোকেন জাল করা যাবে |
| **কোন সুযোগ / অনুমতি নেই** | সমস্ত টোকেন সম্পূর্ণ অ্যাক্সেস আছে | আপস করা টোকেন = সম্পূর্ণ সিস্টেম অ্যাক্সেস |
| **লগিং সংবেদনশীল ডেটা** | লগে টোকেন বা পাসওয়ার্ড | লগ অ্যাক্সেস সহ যে কেউ অ্যাক্সেসযোগ্য |
| **অসংলগ্ন অনুমোদন** | কিছু এন্ডপয়েন্ট অনুমতি চেক করে; অন্যরা না | অরক্ষিত শেষ পয়েন্টের মাধ্যমে অননুমোদিত অ্যাক্সেস |

## ইন্টিগ্রেশন ব্যর্থতা
### ডিস্ট্রিবিউটেড সিস্টেম ইন্টিগ্রেশন সমস্যা
| ব্যর্থতা | বর্ণনা | উদাহরণ |
|---------|---------------|---------|
| **টাইট কাপলিং** | পরিষেবাগুলি একে অপরের অভ্যন্তরীণ বাস্তবায়ন বিবরণের উপর নির্ভর করে | একটি পরিষেবার ডাটাবেস পরিবর্তন করা অন্য তিনটি ব্রেক করে |
| **সিঙ্ক্রোনাস চেইন** | পরিষেবা A কল B কল করে C কল করে D; লেটেন্সি জমে | 200ms + 300ms + 500ms = 1 সেকেন্ড প্রতিক্রিয়া সময় |
| **কোন সার্কিট ব্রেকার নেই** | ব্যর্থ পরিষেবা ক্যাসকেডিং ব্যর্থতার কারণ | পরিষেবা D ধীর; সমস্ত আপস্ট্রিম পরিষেবা তাদের থ্রেড অপেক্ষা করছে |
| **কোন পুনঃপ্রচেষ্টা যুক্তি** | ক্ষণস্থায়ী ব্যর্থতা স্থায়ী হয় | নেটওয়ার্ক ব্লিপ = ব্যর্থ লেনদেন; ব্যবহারকারীকে ম্যানুয়ালি পুনরায় চেষ্টা করতে হবে |
| **অতিরিক্ত পুনরায় চেষ্টা** | ব্যাকঅফ ছাড়াই পুনরুদ্ধার পরিষেবাগুলিকে অভিভূত করে | বজ্রপাতের সমস্যা |
| **কোন অদম্যতা** | একটি অ-অদম্য অপারেশন পুনরায় চেষ্টা করা সদৃশ তৈরি করে | পেমেন্ট দুইবার চার্জ করা হয়; অর্ডার দুইবার তৈরি |
| **আন্তরিক ধারাবাহিকতা বিস্ময়** | ক্লায়েন্ট একটি লেখার পরে বাসি ডেটা পড়ে | ব্যবহারকারীর প্রোফাইল আপডেট; পৃষ্ঠা রিফ্রেশ করে; পুরানো তথ্য এখনও দেখানো হয়েছে |
### থার্ড-পার্টি ইন্টিগ্রেশন ব্যর্থতা
| ব্যর্থতা | বর্ণনা | প্রশমন |
|---------|-------------|------------|
| **বিক্রেতা API পরিবর্তন** | থার্ড-পার্টি তাদের এপিআই পরিবর্তন করে নোটিশ ছাড়াই | সংস্করণ পিনিং; বিমূর্ততা স্তর; বিক্রেতা চেঞ্জলগ পর্যবেক্ষণ |
| **দর সীমিত** | থার্ড-পার্টি আপনার অনুরোধ থ্রোটল করে | ক্যাশিং; অনুরোধ সারিবদ্ধ; উচ্চ সীমা আলোচনা |
| **বিক্রেতা ডাউনটাইম** | তৃতীয় পক্ষের পরিষেবা অনুপলব্ধ | সার্কিট ব্রেকার; ফলব্যাক আচরণ; বহু-বিক্রেতা কৌশল |
| **ডেটা ফরম্যাট পরিবর্তন** | তৃতীয় পক্ষের প্রতিক্রিয়া বিন্যাস পরিবর্তন | স্কিমা বৈধতা; রূপান্তর স্তর; বিন্যাস পরিবর্তন সম্পর্কে সতর্কতা |
| **অভিবাসন পথ ছাড়া অবচয়** | বিক্রেতা কোন সমতুল্য ছাড়া শেষপয়েন্ট অবচয় | অবগত থাকুন; বিমূর্ততা বজায় রাখা; দ্রুত স্থানান্তরের পরিকল্পনা করুন |

## সারাংশ
API ডিজাইন ব্যর্থতা প্রসাধনী (অসংগত নামকরণ) থেকে বিপর্যয়কর (নিরাপত্তা দুর্বলতা, ক্যাসকেডিং ব্যর্থতা) পর্যন্ত। ডিজাইনের সবচেয়ে সাধারণ ভুলগুলি — ওভারলোডেড এন্ডপয়েন্ট, ওভার-ফেচিং, পেজিনেশন অনুপস্থিত, অস্পষ্ট ত্রুটি — API-গুলি ব্যবহার এবং বজায় রাখা কঠিন করে তোলে। নিরাপত্তা ব্যর্থতা — ভাঙা প্রমাণীকরণ, IDOR, ভর অ্যাসাইনমেন্ট, অত্যধিক ডেটা এক্সপোজার — আক্রমণের জন্য সিস্টেমগুলি প্রকাশ করে৷ ইন্টিগ্রেশন ব্যর্থতা — টাইট কাপলিং, সিঙ্ক্রোনাস চেইন, অনুপস্থিত সার্কিট ব্রেকার, কোনো অদম্যতা নেই — এমন ভঙ্গুর সিস্টেম তৈরি করে যেখানে একটি ব্যর্থতা পরিষেবা জুড়ে ক্যাসকেড হয়। থার্ড-পার্টি ইন্টিগ্রেশন বাহ্যিক ঝুঁকি যোগ করে: API পরিবর্তন, হার সীমিত করা, এবং বিক্রেতা ডাউনটাইম। প্রতিরোধের কৌশলগুলি সুপ্রতিষ্ঠিত: সুস্পষ্ট প্রতিক্রিয়া মডেল ব্যবহার করুন; প্রথম দিন থেকে সংস্করণ; সার্কিট ব্রেকার এবং টাইমআউট বাস্তবায়ন; বুদ্ধিমত্তার জন্য নকশা; সমস্ত ইনপুট যাচাই এবং স্যানিটাইজ করুন; সবকিছু নিরীক্ষণ; এবং API চুক্তিগুলিকে বাধ্যতামূলক চুক্তি হিসাবে বিবেচনা করুন যার পরিবর্তনের জন্য সমন্বয় প্রয়োজন। সেরা APIগুলি বিরক্তিকর — অনুমানযোগ্য, সামঞ্জস্যপূর্ণ, ভাল-নথিভুক্ত, এবং ব্যর্থতার জন্য স্থিতিস্থাপক৷
