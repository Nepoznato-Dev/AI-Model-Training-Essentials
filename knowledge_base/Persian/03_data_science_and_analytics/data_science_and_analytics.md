# علم داده و تجزیه و تحلیل
علم داده رشته تبدیل داده های خام به بینش عملی است. این در تقاطع آمار، علوم کامپیوتر و تخصص حوزه قرار دارد - و در هر بخش از مالی تا مراقبت های بهداشتی ضروری شده است. این فایل در میان مفاهیم اصلی، ابزارها و گردش کار که هر پزشک باید بداند، می پردازد.
---

## فرآیند علم داده
اکثر پروژه ها از برخی تغییرات **CRISP-DM** پیروی می کنند، چرخه عمر استاندارد صنعت:
| فاز | چه اتفاقی می افتد | زمان معمولی |
|-------|------------|--------------|
| **تفاهم تجاری** | تعریف اهداف، معیارهای موفقیت و محدودیت ها | 10-15٪ |
| **درک داده** | جمع آوری، کاوش، و نمایه داده ها | 10-15٪ |
| **تهیه داده** | ویژگی های تمیز، تبدیل، مهندسی | ~50-60٪ |
| **مدلینگ** | انتخاب و آموزش مدل ها | 10-15٪ |
| **ارزیابی** | ارزیابی عملکرد در برابر اهداف تجاری | 5-10٪ |
| **استقرار** | ارسال مدل به تولید | 5-10٪ |
تخمین زده می‌شود که آماده‌سازی داده‌ها، به‌ویژه پاکسازی داده‌ها، حدود 80 درصد از زمان یک دانشمند داده را مصرف می‌کند.

## انواع داده در یک نگاه
| نوع | توضیحات | مثال |
|------|-------------|---------|
| **ساختار یافته** | سازماندهی شده در ردیف و ستون | جداول SQL، صفحات گسترده |
| **بدون ساختار** | بدون قالب از پیش تعریف شده | متن، تصویر، صوتی، تصویری |
| **نیمه ساختار** | برخی سازمان اما انعطاف پذیر | JSON، XML، HTML |
| **سری زمانی** | داده های متوالی نمایه شده بر اساس زمان | قیمت سهام، خوانش سنسور |
| **فضایی** | جغرافیایی یا مبتنی بر مکان | مختصات GPS، داده های نقشه |
| **نمودار** | گره ها و لبه های نشان دهنده روابط | شبکه های اجتماعی، نمودار دانش |

## مبانی آمار
### آمار توصیفی در مقابل آمار استنباطی
آمار توصیفی آنچه را که *دارید* خلاصه می کند. آمار استنباطی به شما امکان می دهد در مورد آنچه *نداشته اید (جمعیت گسترده تر) نتیجه گیری کنید.
| مفهوم | ایده های کلیدی |
|---------|-----------|
| **گرایش مرکزی** | میانگین (حساس به نقاط پرت)، میانه (قوی)، حالت (متداول ترین) |
| **پراکندگی** | محدوده، واریانس، انحراف معیار، محدوده بین چارکی |
| **شکل توزیع** | چولگی (عدم تقارن)، کشیدگی (سنگینی دم) |
| **آزمایش فرضیه** | فرضیه صفر در مقابل فرضیه جایگزین، مقادیر p، سطح معناداری (α) |
| **فاصله های اطمینان** | محدوده احتمالاً حاوی پارامتر جمعیت واقعی |
| **خطاهای نوع I / نوع II** | مثبت کاذب (رد یک تهی واقعی) / منفی کاذب (از دست دادن یک اثر واقعی) |
### آزمون های آماری رایج
| تست | زمان استفاده |
|------|-------------|
| **t-test** | مقایسه میانگین بین دو گروه |
| **ANOVA** | مقایسه میانگین ها در سه یا چند گروه |
| **چی مربع** | آزمون استقلال متغیرهای طبقه بندی |
| **Mann-Whitney U** | جایگزین ناپارامتریک آزمون t (بدون فرض نرمال بودن) |
| **همبستگی پیرسون** | رابطه خطی بین دو متغیر پیوسته |
| **همبستگی اسپیرمن** | رابطه یکنواخت (مبتنی بر رتبه، قوی تر) |
### توزیع های احتمالی که ارزش دانستن دارد
| توزیع | مورد استفاده |
|-------------|----------|
| **عادی** | پدیده های طبیعی، خطاهای اندازه گیری - منحنی زنگ کلاسیک |
| **دوجمله ای** | شمارش موفقیت/شکست (چرخش سکه، نرخ تبدیل) |
| **پواسون** | تعداد رویدادها در یک بازه زمانی ثابت (تماس در ساعت، نقص در هر دسته) |
| **نمای** | زمان بین رویدادها (زمان انتظار، فواصل شکست) |
| **t-Distribution** | نمونه های کوچک یا واریانس جمعیت ناشناخته |
| **چی مربع** | تجزیه و تحلیل داده های طبقه بندی شده، آزمون های برازش |

## جمع آوری و ذخیره سازی داده ها
### داده ها از کجا می آیند
داده‌های دنیای واقعی از منابع زیادی به دست می‌آیند: پایگاه‌های اطلاعاتی رابطه‌ای، API (REST، GraphQL)، فایل‌های مسطح (CSV، JSON، پارکت)، پلتفرم‌های جریان (کافکا، کینزیس)، نظرسنجی‌ها، و مخازن عمومی (Kaggle، پورتال‌های دولتی). فرمتی که دریافت می‌کنید بیشتر استراتژی پیش‌پردازش شما را تعیین می‌کند.
### مفاهیم ذخیره سازی داده ها
| مفهوم | توضیحات |
|---------|-------------|
| **ETL** | استخراج → تبدیل → بار - رویکرد سنتی خط لوله |
| **ELT** | Extract → Load → Transform — رویکرد ابری مدرن (بارگیری خام، تبدیل در انبار) |
| **دریاچه دیتا** | داده های خام ذخیره شده در قالب بومی (طرحواره-در-خواندن) |
| ** انبار داده** | داده های ساختاریافته و پردازش شده بهینه سازی شده برای تجزیه و تحلیل (شما در نوشتن) |
| **دیتا مارت** | زیرمجموعه ای از یک انبار که در یک بخش یا دامنه |
| **طرحواره ستاره** | جدول اطلاعات مرکزی احاطه شده توسط جداول ابعاد |
| **طرحواره دانه های برف** | جداول ابعاد نرمال شده ( افزونگی کمتر، پیوستن بیشتر) |
### انواع پایگاه داده
| نوع | مثال ها | بهترین برای |
|------|----------|----------|
| **رابطه ای (SQL)** | PostgreSQL، MySQL، Oracle | داده های ساخت یافته، تراکنش های ACID |
| **سند** | MongoDB، CouchDB | طرحواره های انعطاف پذیر، داده های JSON مانند |
| **کلید-مقدار** | Redis، DynamoDB | ذخیره سازی، جلسات، جستجوهای ساده |
| **ستون-خانواده** | کاساندرا، اچ بیس | حجم کاری سنگین، سری زمانی |
| **نمودار** | Neo4j، آمازون نپتون | روابط، شبکه های اجتماعی |
| **سریال زمانی** | InfluxDB، TimescaleDB | معیارهای IoT، نظارت |
| **وکتور** | کاج، Milvus | جاسازی فضای ذخیره سازی برای جستجوی ML/AI |

## پیش پردازش داده ها و مهندسی ویژگی
### چک لیست تمیز کردن
هر مجموعه داده واقعی مشکلاتی دارد. در اینجا پاکسازی استاندارد آمده است:
| شماره | رویکرد |
|-------|----------|
| **مقادیر گم شده** | انتساب (میانگین، میانه، پیش بینی)، یا حذف در صورت پراکندگی |
| **فراتبه** | تشخیص از طریق IQR یا Z-score. درمان با درپوش یا تبدیل |
| **تکراری** | شناسایی و حذف |
| **ناهماهنگی** | استاندارد کردن فرمت ها، رفع اشتباهات تایپی، عادی سازی واحدها |
### تکنیک های تبدیل
| تکنیک | چه کاری انجام می دهد |
|-----------|-------------|
| ** عادی سازی ** | مقياس مقادير به محدوده 0-1 |
| **استانداردسازی** | امتیاز Z: میانگین = 0، std = 1 |
| **رمزگذاری تک داغ** | دسته ها را به ستون های باینری تبدیل می کند |
| **رمزگذاری برچسب** | برچسب های عدد صحیح را به دسته ها اختصاص می دهد |
| **تحول لاگ** | انحراف راست در داده ها را کاهش می دهد |
| ** بنینگ** | مقادیر پیوسته را در سطل های مجزا گروه بندی می کند |
### مهندسی ویژگی
مهندسی ویژگی اغلب تفاوت بین یک مدل متوسط ​​و یک مدل عالی است. تکنیک های کلیدی عبارتند از:
- **ایجاد ویژگی**: استخراج ستون های جدید از ستون های موجود (به عنوان مثال،`age_group`از `age`).
- **انتخاب ویژگی**: روش های فیلتر (همبستگی)، روش های بسته بندی (حذف بازگشتی)، روش های تعبیه شده (LASSO، اهمیت درخت).
- **کاهش ابعاد **: PCA برای خطی، t-SNE یا UMAP برای تجسم.
- **شرایط تعامل**: ترکیب ویژگی ها به صورت ضربی برای گرفتن اثرات مشترک.

### انتخاب نمودار مناسب

|-----------|----------|
| **هیستوگرام** | توزیع یک متغیر |
| **قطعه جعبه** | خلاصه پنج عددی، تشخیص پرت |
| **طرح پراکندگی** | رابطه بین دو متغیر پیوسته |
| **هیت مپ** | ماتریس های همبستگی، تجسم چگالی |
| **نمودار میله ای** | مقایسه دسته ها |
| **نمودار خطی** | روند در طول زمان |
| **طرح ویولن** | چگالی توزیع + خلاصه نمودار جعبه |

### پشته پایتون EDA

## هوش تجاری و تجزیه و تحلیل
### ابزارهای BI مقایسه شد
| ابزار | نوع | قدرت |
|------|------|----------|
| **تابلو** | تجاری | تجزیه و تحلیل بصری غنی، کشیدن و رها کردن |

### اصول طراحی داشبورد
داشبوردهای موثر از اصول تعیین شده پیروی می کنند: مخاطب را شناسایی کنید، تجسم مناسب را برای هر معیار انتخاب کنید، از رنگ به صورت استراتژیک (نه تزئینی) استفاده کنید، مقیاس های ثابت را حفظ کنید، و تعامل (فیلترها، تمرین ها) را فعال کنید. عملکرد نیز مهم است - داشبوردهایی با زمان بارگذاری آهسته پذیرش کاربر را کاهش می دهند.
### دسته بندی های رایج KPI
| دسته بندی | مثال ها |
|----------|---------|
| **مالی** | درآمد، حاشیه سود، ROI، ارزش طول عمر مشتری |
| **مشتری** | هزینه اکتساب (CAC)، نرخ ریزش، NPS، امتیاز رضایت |
| **عملیاتی** | نرخ بهره وری، زمان چرخه، نرخ نقص |
| **بازاریابی** | نرخ تبدیل، نرخ کلیک، ROAS، انتساب |
| **محصول** | کاربران فعال روزانه، تعامل، حفظ، پذیرش ویژگی |

### تعصب و انصاف
سوگیری می‌تواند در هر مرحله وارد شود: سوگیری نمونه‌برداری (داده‌های غیرنماینده)، سوگیری اندازه‌گیری (ابزار معیوب)، یا سوگیری الگوریتمی (پیش‌بینی‌های تبعیض‌آمیز). راهبردهای کاهش شامل پیش پردازش (تثبیت داده ها)، در پردازش (محدود کردن مدل)، و پس پردازش (تنظیم خروجی ها) است. معیارهای انصاف مانند برابری جمعیتی و فرصت برابر به کمیت کردن مشکل کمک می کند.

## روندهای نوظهور
- **AutoML**: ایجاد خودکار خط لوله و انتخاب مدل.
- **MLOps**: شیوه های DevOps برای مدیریت چرخه حیات ML اعمال می شود.
- **فروشگاه های ویژه **: مدیریت ویژگی متمرکز برای استفاده مجدد در تیم ها.
- **Data Mesh**: معماری داده غیرمتمرکز و متعلق به دامنه.
- **LLM ها و هوش مصنوعی مولد **: مدل های زبان بزرگ که گردش کار متن، کد و تصویر را تغییر می دهد.
- **Edge Analytics**: پردازش داده ها در دستگاه به جای ابر.
- **استنتاج علی**: حرکت فراتر از همبستگی برای درک علت و معلول واقعی.
- **آموزش فدرال**: آموزش مدل های داده های غیرمتمرکز بدون جابجایی آن ها.
- **هوش مصنوعی مسئول **: اخلاق، توضیح پذیری و شفافیت به الزامات استاندارد تبدیل می شوند.
