# ساختارها و الگوریتم های داده
ساختار داده روشی است که ما داده ها را در حافظه سازماندهی می کنیم تا عملیات روی آن کارآمد باشد. الگوریتم ها روش های گام به گام برای حل مسائل هستند. آنها با هم پایه و اساس علم کامپیوتر را تشکیل می دهند - هر برنامه ای که تا به حال استفاده کرده اید به آنها متکی است. انتخاب ساختار داده مناسب می تواند یک برنامه غیرممکن کند را به یک برنامه سریع تبدیل کند و دانستن الگوریتم مناسب می تواند یک مشکل غیر قابل حل را به یک مشکل پیش پاافتاده تبدیل کند.
---

## ساختارهای داده بنیادی
### سازه های خطی
| ساختار | دسترسی | جستجو | درج | حذف | مورد استفاده |
|-----------|--------|--------|--------|-------|----------|
| **آرایه** | O(1) با شاخص | O(n) | O(n) | O(n) | مجموعه های با اندازه ثابت؛ دسترسی تصادفی |
| **فهرست پیوند شده** | O(n) | O(n) | O(1) در سر | O(1) در سر | اندازه پویا؛ درج/حذف |
| **پشته** | O(n) | O(n) | O(1) push/pop | O(1) پاپ | فراخوانی تابع؛ لغو تجزیه |
| **صف ** | O(n) | O(n) | O(1) صف | O(1) dequeue | برنامه ریزی وظایف؛ BFS; صف های پیام |
| **دکه** | O(1) در هر دو انتها | O(n) | O(1) در هر دو انتها | O(1) در هر دو انتها | پنجره کشویی؛ کار دزدی |
### ساختارهای مبتنی بر هش
| ساختار | جستجو | درج | حذف | مورد استفاده |
|-----------|--------|--------|-------|----------|
| **جدول هش** | O(1) میانگین | O(1) میانگین | O(1) میانگین | جستجوهای کلید-مقدار؛ حافظه های پنهان؛ مجموعه |
| **هش ست** | O(1) | O(1) | O(1) | تست عضویت؛ کپی برداری |
**تصادف هش**: وقتی دو کلید در یک اسلات هش می کنند، در یک لیست پیوندی (زنجیره ای) یا شکاف موجود بعدی (آدرس دهی باز) ذخیره می شوند. توابع هش خوب برخوردها را به حداقل می رساند.
### ساختارهای درختی
| ساختار | جستجو | درج | حذف | مورد استفاده |
|-----------|--------|--------|-------|----------|
| **درخت جستجوی دودویی** | O(log n) میانگین | O(log n) | O(log n) | داده های مرتب شده؛ پرس و جوهای محدوده |
| **AVL / درخت قرمز-سیاه** | O(log n) تضمین شده | O(log n) | O(log n) | خود تعادلی؛ مورد استفاده در نقشه ها/مجموعه ها |
| **B-Tree / B+ Tree** | O(log n) | O(log n) | O(log n) | نمایه های پایگاه داده؛ سیستم های فایل |
| **تلاش** | O(k) که در آن k = طول کلید | O(k) | O(k) | تکمیل خودکار؛ تطبیق پیشوند |
| **هپ (دودویی)** | O(n) | O(log n) | O(log n) | صف های اولویت دار؛ زمان بندی |
### نمایش نمودار
| نمایندگی | فضا | جستجوی لبه | افزودن لبه | همسایه های تکراری |
|---------------|-------|------------|---------|-------------------|
| **ماتریس مجاورت** | O(V²) | O(1) | O(1) | O(V) |
| **لیست مجاورت** | O(V + E) | O(درجه) | O(1) | O(درجه) |
| **لیست لبه** | O(E) | O(E) | O(1) | O(E) |

## پیچیدگی الگوریتم (Big-O)
نماد Big-O توضیح می دهد که چگونه با افزایش اندازه ورودی، زمان یا مکان مورد نیاز الگوریتم افزایش می یابد.
| پیچیدگی | نام | مثال |
|-----------|------|---------|
| **O(1)** | ثابت | جستجوی جدول هش. دسترسی به آرایه بر اساس شاخص |
| **O(log n)** | لگاریتمی | جستجوی باینری؛ عملیات درخت متعادل |
| **O(n)** | خطی | جستجوی خطی؛ تکرار یک آرایه |
| **O(n log n)** | ریاضی خطی | ادغام مرتب سازی؛ مرتب سازی پشته؛ کارآمدترین انواع همه منظوره |
| **O(n²)** | درجه دوم | مرتب سازی حبابی؛ حلقه های تو در تو روی داده های مشابه |
| **O(2^n)** | نمایی | تولید زیر مجموعه نیروی Brute-Force. فیبوناچی بازگشتی ساده لوح |
| **O(n!)** | فاکتوریل | فروشنده دوره گرد (بی رحمانه); جایگشت |
### باورهای غلط رایج
| تصور غلط | واقعیت |
|--------------|---------|
| "O(n) همیشه سریعتر از O(n²) است" | برای n کوچک، ضریب ثابت اهمیت بیشتری دارد |
| "Ower Big-O همیشه بهتر است" | مبادلات فضا-زمان وجود دارد. جستجوی O(1) از حافظه O(n) |
| "Big-O سرعت دقیق را به شما می گوید" | این نرخ رشد را توصیف می کند، نه زمان مطلق |

## الگوریتم های مرتب سازی
| الگوریتم | بهترین | میانگین | بدترین | فضا | پایدار | در محل |
|-----------|------|---------|-------|------|--------|---------|
| **مرتب سازی حبابی** | O(n) | O(n²) | O(n²) | O(1) | بله | بله |
| ** مرتب سازی درج ** | O(n) | O(n²) | O(n²) | O(1) | بله | بله |
| **مرتب سازی انتخاب** | O(n²) | O(n²) | O(n²) | O(1) | نه | بله |
| **ادغام مرتب سازی** | O(n log n) | O(n log n) | O(n log n) | O(n) | بله | نه |
| **مرتب سازی سریع** | O(n log n) | O(n log n) | O(n²) | O(log n) | نه | بله |
| **مرتب سازی پشته** | O(n log n) | O(n log n) | O(n log n) | O(1) | نه | بله |
| **Tim Sort** | O(n) | O(n log n) | O(n log n) | O(n) | بله | نه |
**توصیه عملی**: از مرتب سازی داخلی زبان خود استفاده کنید (`sorted()` پایتون،`Array.sort()`جاوا اسکریپت). آنها از الگوریتم های بسیار بهینه شده (Tim Sort، Introsort) استفاده می کنند که تمام موارد لبه را مدیریت می کند.

## الگوریتم های جستجو
| الگوریتم | ساختار داده | پیچیدگی | مورد نیاز |
|-----------|---------------|-----------|------------|
| **جستجوی خطی** | هر | O(n) | هیچکدام |
| **جستجوی باینری** | آرایه مرتب شده | O(log n) | داده ها باید مرتب شوند |
| **جستجوی جدول هش** | جدول هش | O(1) میانگین | عملکرد هش خوب |
| **BFS** (جستجوی عرض-اول) | نمودار / درخت | O(V + E) | کوتاه ترین مسیر بدون وزن |
| **DFS** (جستجوی عمقی-اول) | نمودار / درخت | O(V + E) | مسیریابی؛ تشخیص چرخه |
| **Dijkstra's** | نمودار وزنی | O((V + E) log V) | وزن های غیر منفی؛ کوتاه ترین مسیر |
| **الف* جستجو** | نمودار وزنی | O((V + E) log V) | هدایت اکتشافی؛ بهینه با اکتشافی قابل قبول |

## الگوهای الگوریتم کلیدی
| الگو | توضیحات | نمونه مشکلات |
|---------|------------|----------------|
| **تفرقه بینداز و غلبه کن** | تقسیم مسئله به مسائل فرعی؛ حل بازگشتی؛ ترکیب | ادغام مرتب سازی؛ مرتب سازی سریع؛ جستجوی باینری |
| **برنامه نویسی پویا** | شکستن به مشکلات فرعی همپوشانی؛ نتایج کش | فیبوناچی؛ کوله پشتی; طولانی ترین دنباله متداول |
| **طمع** | انتخاب بهینه محلی در هر مرحله | Dijkstra's; کدنویسی هافمن؛ انتخاب فعالیت |
| **بازگشت ** | احتمالات را امتحان کنید؛ لغو انتخاب های بد؛ جایگزین ها را امتحان کنید | حل کننده سودوکو؛ N-ملکه ها; جایگشت |
| **پنجره کشویی** | پنجره ای از عناصر را حفظ کنید. آن را روی داده ها بکشید | حداکثر مجموع زیر مجموعه به اندازه K; طولانی ترین زیر رشته بدون تکرار |
| **دو اشاره گر** | از دو نشانگر در حال حرکت به سمت یکدیگر یا در یک جهت استفاده کنید مجموع جفت در آرایه مرتب شده. حذف تکراری |
| **جستجوی باینری در پاسخ** | جستجوی باینری فضای پاسخ | اختصاص حداقل صفحات؛ گاوهای مهاجم |

## چه زمانی از What استفاده کنیم
| مشکل | ساختار داده | الگوریتم |
|---------|--------------|-----------|
| جستجوی سریع کلید-مقدار | جدول هش / فرهنگ لغت | هش کردن |
| حفظ نظم مرتب شده | BST متعادل (TreeMap، std::set) | عملیات درختی |
| پردازش مبتنی بر اولویت | هیپ / صف اولویت | عملیات هپ |
| کوتاه ترین مسیر (بدون وزن) | نمودار (لیست مجاورت) | BFS |
| کوتاه ترین مسیر (وزن دار) | نمودار (لیست مجاورت) | Dijkstra's / A* |
| تست عضویت | هش ست / فیلتر بلوم | هش کردن |
| تطبیق پیشوند | سعی کنید | پیمایش سعی کنید |
| پرس و جوهای محدوده | درخت قطعه / درخت فنویک | عملیات درختی |
| کش LRU | نقشه هش + لیست پیوندی دوگانه | عملیات ترکیبی |
| اجزای متصل | Disjoint Set Union (Union-Find) | اتحاد و پیدا کردن |

## خلاصه
ساختارهای داده و الگوریتم‌ها فقط موضوعات مصاحبه نیستند - آنها بلوک‌های سازنده نرم‌افزار کارآمد هستند. آرایه ها و جداول هش اکثر نیازهای روزمره را برطرف می کنند. درختان و نمودارها داده های سلسله مراتبی و رابطه ای را مدیریت می کنند. مرتب سازی و جستجو مشکلات حل شده در کتابخانه های استاندارد است. الگوهای الگوریتمی - تفرقه کن و غلبه کن، برنامه نویسی پویا، حریص، عقب نشینی - استراتژی های قابل استفاده مجدد برای مقابله با مشکلات جدید هستند. مهارت کلیدی حفظ الگوریتم ها نیست. تشخیص اینکه کدام الگو با یک مشکل معین مطابقت دارد و انتخاب ساختار داده مناسب برای کار است.
