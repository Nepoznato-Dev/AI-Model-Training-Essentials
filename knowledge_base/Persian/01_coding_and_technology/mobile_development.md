# توسعه موبایل
توسعه موبایل، تمرین ساخت برنامه های کاربردی برای گوشی های هوشمند و تبلت ها است – در درجه اول برای iOS (اپل) و اندروید (گوگل). این شامل همه چیز است، از طراحی UI برای نمایشگرهای کوچک گرفته تا مدیریت عمر باتری، مدیریت ناپایداری شبکه، و توزیع برنامه‌ها در فروشگاه‌ها. این زمینه به طور قابل توجهی به بلوغ رسیده است، به طوری که چارچوب های چند پلتفرمی در حال حاضر با توسعه بومی برای بیشتر موارد استفاده رقابت می کنند.

## چارچوب های چند پلتفرمی
یک بار بسازید، هم در iOS و هم برای اندروید استقرار دهید.
| چارچوب | زبان | رندر | عملکرد | بهترین برای |
|-----------|----------|----------|------------|----------|
| **فلاتر** | دارت | موتور سفارشی (اسکیا/ پروانه) | نزدیک بومی | UI های سفارشی غنی؛ نگاه ثابت در سراسر پلتفرم ها |
| **React Native** | جاوا اسکریپت/تایپ اسکریپت | اجزای بومی از طریق پل | خوب (معماری جدید این را بهبود می بخشد) | تیم هایی با تجربه وب/JS |
| **مولتی پلتفرم کاتلین** | کاتلین | رابط کاربری بومی در هر پلتفرم | بومی | به اشتراک گذاری منطق تجاری؛ رابط کاربری بومی |
| **MAUI** (.NET) | سی شارپ | کنترل های بومی | خوب | تیم های دات نت; برنامه های سازمانی |
| **یونی / خازن** | HTML/CSS/JS | نمایش وب | پایین | برنامه های ساده؛ تیم های وب |
### Flutter در مقابل React Native
| جنبه | فلاتر | React Native |
|--------|--------|-------------|
| **زبان** | دارت | جاوا اسکریپت/تایپ اسکریپت |
| ** رندر رابط کاربری ** | همه چیز را به خودی خود ترسیم می کند (در همه پلتفرم ها سازگار است) | از مؤلفه های بومی (نگاه ویژه پلتفرم) |
| **بارگذاری مجدد داغ** | عالی | خوب |
| **اکوسیستم** | رشد سریع؛ مبتنی بر ویجت | بزرگ؛ اکوسیستم npm |
| **منحنی یادگیری** | نیاز به یادگیری دارت | آسان تر برای توسعه دهندگان وب |
| **ادغام پلتفرم** | کانال های بستر برای کد بومی | ماژول های بومی از طریق پل |
| **عملکرد** | عالی؛ نزدیک به بومی | خوب؛ بالای پل (کاهش با معماری جدید) |

## الگوهای معماری موبایل
| الگو | توضیحات | زمان استفاده |
|---------|------------|-------------|
| **MVC** | Model-View-Controller | برنامه های ساده؛ آشنا برای توسعه دهندگان وب |
| **MVVM** | Model-View-ViewModel; داده های الزام آور | مدرن ترین اپلیکیشن های موبایل |
| **MVI** | Model-View-Intent; جریان داده های یک طرفه | مدیریت پیچیده دولتی؛ فلاتر (با BLoC/Riverpod) |
| **معماری پاک** | لایه ها با وارونگی وابستگی | تیم های بزرگ؛ منطق پیچیده کسب و کار |

## نگرانی های کلیدی موبایل
### طراحی آفلاین-اول
برنامه های موبایل باید بدون اینترنت قابل اعتماد کار کنند.
| استراتژی | توضیحات |
|----------|-------------|
| **پایگاه داده محلی** | ذخیره اطلاعات روی دستگاه (SQLite، Room، CoreData، Realm) |
| **استراتژی همگام سازی** | همگام سازی با سرور هنگام آنلاین. حل تعارض |
| **رابط کاربری خوش بینانه** | فورا UI را به روز کنید. آشتی وقتی سرور پاسخ می دهد |
| **کش** | پاسخ های Cache API. هنگام آفلاین بودن از حافظه پنهان |
### عملکرد
| نگرانی | راه حل |
|---------|----------|
| **زمان راه اندازی اپلیکیشن** | بارگذاری تنبل؛ به حداقل رساندن کار مقداردهی اولیه |
| **استفاده از حافظه** | فشرده سازی تصویر؛ جلوگیری از نشت حافظه؛ استفاده از ابزارهای پروفایل |
| **تخلیه باتری** | کاهش کار پس زمینه؛ درخواست های شبکه دسته ای؛ استفاده از خدمات مکان یابی کارآمد |
| **کارایی شبکه** | فشرده سازی محموله ها؛ استفاده از صفحه بندی؛ کش به صورت تهاجمی |
| **پیمایش لیست** | نماهای بازیافت استفاده از بارگذاری تنبل برای تصاویر |
### امنیت
| نگرانی | راه حل |
|---------|----------|
| **داده در حالت استراحت** | رمزگذاری داده های حساس (Keychain در iOS، EncryptedSharedPreferences در اندروید) |
| **شبکه** | همیشه HTTPS؛ پین کردن گواهی برای برنامه های حساس |
| ** احراز هویت ** | بیومتریک (Face ID، اثر انگشت)؛ OAuth; ذخیره توکن |
| **ابهام سازی کد** | ProGuard/R8 برای اندروید؛ بیت کد برای iOS |
| **جیل بریک/تشخیص ریشه** | شناسایی دستگاه های در معرض خطر؛ محدود کردن عملکرد |

## چرخه عمر برنامه
| ایالت | توضیحات | چه باید کرد |
|-------|------------|------------|
| **پیش زمینه (فعال)** | کاربر در حال تعامل با برنامه است | عملکرد عادی |
| **پس زمینه** | برنامه قابل مشاهده نیست اما همچنان در حافظه است | مکث انیمیشن ها؛ ذخیره حالت |
| **تعلیق ** | سیستم عامل برای صرفه جویی در منابع، برنامه را مسدود کرده است | هیچ چیز؛ برنامه منجمد شده است |
| **فسخ شد** | سیستم عامل برنامه را برای آزادسازی حافظه نابود کرد | بازیابی وضعیت در راه اندازی بعدی |

## خلاصه
توسعه موبایل امکان انتخاب بین بومی (بهترین عملکرد، مخصوص پلتفرم) و چند پلتفرمی (پایه کد مشترک، تکرار سریعتر) را ارائه می دهد. Flutter و React Native به حدی رسیده اند که کراس پلتفرم برای اکثر برنامه ها انتخاب مناسبی است. چالش‌های اصلی بدون در نظر گرفتن چارچوب یکسان باقی می‌مانند: طراحی آفلاین، عملکرد در سخت‌افزار محدود، کارایی باتری، امنیت در دستگاه‌های غیرقابل اعتماد، و مرور فرآیندهای بررسی فروشگاه برنامه. این زمینه به توسعه‌دهندگانی که ابتدا به تجربه کاربری فکر می‌کنند پاداش می‌دهد - راه‌اندازی سریع، پیمایش روان، و مدیریت برازنده اتصال ضعیف.
