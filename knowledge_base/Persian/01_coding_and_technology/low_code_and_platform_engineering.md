# مهندسی کم کد و پلت فرم
پلتفرم‌های کم‌کد به افراد اجازه می‌دهند برنامه‌هایی را با حداقل کد دست‌نویس بسازند – معمولاً از طریق رابط‌های کشیدن و رها کردن، گردش‌های کاری بصری و اتصال‌های از پیش ساخته شده. مهندسی پلتفرم رشته ساختن پلتفرم‌های توسعه‌دهنده داخلی (IDP) است که به تیم‌های محصول امکان خودسرویس زیرساخت‌ها، CI/CD و ابزارهای عملیاتی را آسان می‌کند. هر دو روند پاسخی به یک مشکل هستند: شکاف بین تقاضا برای نرم افزار و عرضه توسعه دهندگانی که می توانند آن را بسازند.
---

## پلتفرم های کم کد
### در واقع Low-Code به چه معناست
| جنبه | توضیحات |
|--------|------------|
| **توسعه بصری** | سازندگان UI را بکشید و رها کنید. ویرایشگرهای گردش کار بصری؛ طراحان فرم |
| **قطعات از پیش ساخته شده** | ویجت های آماده، رابط ها، قالب ها و ادغام ها |
| **منطق اعلامی** | پیکربندی رفتار از طریق قوانین و شرایط به جای نوشتن کد |
| **توسعه پذیری** | قابلیت افزودن کد سفارشی زمانی که قابلیت های داخلی پلتفرم کافی نیست |
| **زیرساخت های مدیریت شده** | پلتفرم مدیریت میزبانی، مقیاس بندی، وصله های امنیتی |
### پلتفرم های محبوب کم کد
| پلت فرم | قدرت | مورد استفاده معمولی |
|----------|----------|-----------------|
| **پلتفرم مایکروسافت پاور** | ادغام Deep Microsoft 365 / Azure. Power Apps، Power Automate، Power BI | گردش کار سازمانی؛ ابزار داخلی |
| **پلتفرم نیروی فروش** | CRM بومی؛ Apex برای برنامه های افزودنی؛ جریان ساز | برنامه های رو به مشتری؛ گردش کار فروش |
| **ServiceNow** | مدیریت خدمات فناوری اطلاعات؛ اتوماسیون گردش کار | عملیات فناوری اطلاعات؛ منابع انسانی امکانات |
| **اپیان** | استخراج فرآیندی؛ مدیریت پرونده | فرآیندهای تجاری پیچیده؛ انطباق |
| **OutSystems** | وب و موبایل تمام پشته؛ درجه سازمانی | پورتال های مشتریان؛ برنامه های موبایل |
| **تجهیز مجدد** | ابزار ساز داخلی; به پایگاه داده ها و API ها متصل می شود | پنل های مدیریت؛ داشبوردها؛ ابزارهای عملیاتی |
| **ایرتابل** | ترکیبی صفحه گسترده-پایگاه داده. اتوماسیون | پیگیری پروژه؛ CRM سبک |
### وقتی Low-Code خوب کار می کند
| سناریو | چرا کم کد مناسب است |
|----------|-------------------|
| **ابزارهای داخلی** | ساخت سریع؛ کاربران داخلی هستند، بنابراین انعطاف پذیری UI اهمیت کمتری دارد |
| **فرم ها و مصوبات** | سازندگان گردش کار بصری در این |
| **برنامه های CRUD** | اکثر پلتفرم‌های کم‌کد برای الگوهای ایجاد، خواندن، به‌روزرسانی، حذف بهینه‌سازی شده‌اند
| **نمونه سازی** | اعتبار یک ایده را در ساعت به جای هفته |
| **توسعه شهروندی** | تحلیلگران کسب و کار می توانند راه حل های خود را با حاکمیت IT ایجاد کنند |
### وقتی کد پایین کوتاه می‌شود
| محدودیت | تاثیر |
|------------|--------|
| **قفل فروشنده** | برنامه ها را نمی توان به راحتی از پلتفرم خارج کرد |
| **سقف های عملکرد** | مناسب برای برنامه های پر توان یا حساس به تأخیر نیست |
| **محدودیت های رابط کاربری** | طراحی های سفارشی دشوار است. شما محدود به آنچه پلتفرم پشتیبانی می کند |
| **پیچیدگی ادغام** | اتصال به APIهای غیرمعمول یا سیستم‌های قدیمی ممکن است به کد سفارشی نیاز داشته باشد |
| **هزینه در مقیاس** | با افزایش استفاده، قیمت گذاری برای هر کاربر یا هر برنامه می تواند گران شود |
| **مشکل اشکال زدایی** | انتزاعات بصری تشخیص مسائل پیچیده را دشوار می کند |

## مهندسی پلت فرم
### مشکل مهندسی پلتفرم حل می شود
| بدون مهندسی پلتفرم | با مهندسی پلتفرم |
|---------------------------------------------------------|
| هر تیم زیرساخت خود را مدیریت می کند | زیرساخت چکیده پلت فرم سلف سرویس |
| ابزار ناسازگار در بین تیم ها | زنجیره ابزار استاندارد؛ مسیرهای طلایی |
| توسعه دهندگان منتظر عملیاتی برای تهیه منابع هستند | توسعه دهندگان منابع را بر اساس تقاضا تهیه می کنند |
| سیلوهای دانش؛ دانش قبیله ای | مستند؛ خودکار؛ قابل کشف |
| ورود آهسته برای مهندسین جدید | مهندسان جدید می توانند در روز اول مستقر شوند |
### اجزای اصلی یک پلتفرم توسعه دهنده داخلی
| جزء | هدف | ابزارهای مثال |
|-----------|---------|---------------|
| **کاتالوگ خدمات** | ثبت مرکزی کلیه خدمات و صاحبان آنها | پشت صحنه؛ بندر; قشر |
| **داربست شابلون** | ایجاد سرویس های جدید از قالب های تایید شده | قالب های نرم افزار Backstage; شیرینی پزی |
| **زیرساخت سلف سرویس** | توسعه دهندگان منابع ابری را بدون پر کردن بلیط تهیه می کنند | ماژول های Terraform; پولومی; هواپیمای متقابل |
| **خطوط لوله CI/CD** | استاندارد ساخت، آزمایش، استقرار خطوط لوله | GitHub Actions; GitLab CI; سی دی آرگو |
| **مدیریت محیط زیست** | محیط‌های برنامه‌نویس/مرحله‌سازی زودگذر بنا به تقاضا | Vcluster; فضای نام؛ گیت پاد |
| **قابل مشاهده** | ورود به سیستم، معیارها، ردیابی تعبیه شده در هر سرویس | پرومتئوس گرافانا; OpenTelemetry; Datadog |
| **مدیریت مخفی** | ذخیره سازی امن و چرخش اعتبارنامه ها | طاق; مدیر اسرار AWS؛ SOPS |
| **هویت و دسترسی** | SSO; دسترسی مبتنی بر نقش؛ سرویس به سرویس auth | اوکتا شنل کلید؛ اسپیف |
### مسیرهای طلایی
یک مسیر طلایی، راهی است که برای انجام کاری مورد حمایت و عقیده قرار می گیرد. این مسیر کمترین مقاومت است - اگر آن را دنبال کنید، همه چیز کار می کند. شما می توانید از مسیر خارج شوید، اما خودتان هستید.
| مسیر طلایی | آنچه ارائه می دهد |
|-------------|-----------------|
| **سرویس جدید** | مخزن قالب؛ CI/CD; نظارت؛ قطع درختان؛ پیکربندی استقرار |
| **پایگاه داده جدید** | نمونه تدارک دیده شده؛ رشته های اتصال در اسرار؛ پشتیبان پیکربندی شد |
| **فرانت اند جدید** | ساخت خط لوله؛ CDN; محیط های پیش نمایش؛ فانوس دریایی چک |
| **خط لوله داده** | ارکستراسیون؛ اعتبار سنجی طرحواره؛ نظارت؛ هشدار دهنده |
### تصمیمات ساخت در مقابل خرید
| فاکتور | ساخت سفارشی | استفاده از ابزار موجود |
|--------|------------|------------------|
| **شایستگی اصلی** | منحصر به فرد برای کسب و کار شما؛ مزیت رقابتی | کالا؛ هر شرکتی به آن نیاز دارد |
| **بار نگهداری** | شما ظرفیت نگهداری آن را دارید | ابزار توسط فروشنده/جامعه به خوبی نگهداری می شود
| **نیازهای یکپارچه سازی** | ادغام عمیق با سیستم های داخلی مورد نیاز | APIهای استاندارد و کانکتورها کافی است |
| **هزینه** | ساخت ارزان تر از مجوز | مجوز ارزان تر از ساخت |

## رابطه بین مهندسی کم کد و پلت فرم
| ابعاد | کم کد | مهندسی پلت فرم |
|-----------|----------|--------------------|
| **کاربر مورد نظر** | کاربران تجاری؛ شهروند توسعه دهندگان | مهندسین نرم افزار حرفه ای |
| **هدف** | کاهش کد؛ افزایش سرعت | کاهش بار شناختی؛ افزایش استقلال |
| **سطح انتزاع** | بسیار بالا؛ بصری | متوسط؛ مبتنی بر کد اما ساده شده |
| **انعطاف پذیری** | محدود شده توسط قابلیت های پلت فرم | انعطاف پذیری کامل؛ می توانید هر کدی بنویسید |
| **حکمرانی** | پلتفرم قوانین را اجرا می کند | پلتفرم مسیرهای طلایی را فراهم می کند |
آنها مکمل هم هستند: مهندسی پلتفرم توسعه دهندگان حرفه ای را سریعتر می کند، در حالی که کد پایین به غیر توسعه دهندگان امکان می دهد برنامه های کاربردی ساده بسازند. آنها با هم، شکاف تحویل نرم افزار را از زوایای مختلف برطرف می کنند.

## خلاصه
پلتفرم‌های کم‌کد و پلت‌فرم‌های توسعه‌دهنده داخلی، هر دو هدفشان افزایش تعداد افرادی است که می‌توانند نرم‌افزار ارائه دهند. Low-code این کار را با انتزاع کردن کد به طور کامل انجام می دهد - سازنده های بصری، اتصال دهنده های از پیش ساخته شده، منطق اعلامی. مهندسی پلتفرم این کار را برای توسعه دهندگان حرفه ای با ارائه زیرساخت های سلف سرویس، مسیرهای طلایی و ابزار استاندارد انجام می دهد تا زمان کمتری را برای کارهای عملیاتی و زمان بیشتری را برای ویژگی های محصول صرف کنند. هیچ کدام یک گلوله نقره ای نیست: کد پایین دارای محدودیت های قفل فروشنده و عملکرد است، و مهندسی پلت فرم نیاز به سرمایه گذاری مداوم برای نگهداری دارد. اما هنگامی که برای مشکلات مناسب - ابزارهای داخلی، برنامه های CRUD، ارائه خدمات استاندارد شده - اعمال شود، هر دو می توانند زمان ایده تا تولید را به طور چشمگیری کاهش دهند.
