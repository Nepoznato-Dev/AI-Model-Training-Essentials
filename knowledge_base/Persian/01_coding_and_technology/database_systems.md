# سیستم های پایگاه داده
## مبانی پایگاه داده
### پایگاه داده چیست؟
پایگاه داده مجموعه ای سازمان یافته از اطلاعات ساختاریافته است که به صورت الکترونیکی ذخیره شده و برای بازیابی کارآمد، درج، به روز رسانی و حذف داده ها طراحی شده است.
### سیستم های مدیریت پایگاه داده (DBMS)
نرم افزاری که با کاربران نهایی، برنامه ها و خود پایگاه داده برای جمع آوری و تجزیه و تحلیل داده ها تعامل دارد. مثال: MySQL، PostgreSQL، Oracle، MongoDB.
### مفاهیم کلیدی
- **طرحواره**: ساختار/سازماندهی پایگاه داده (جدول، فیلدها، روابط)
- **نمونه**: داده های واقعی ذخیره شده در یک لحظه خاص
- **خواص اسید**: اتمی، سازگاری، جداسازی، دوام
- ** قضیه CAP **: سازگاری، در دسترس بودن، تحمل پارتیشن (2 را انتخاب کنید)
- ** عادی سازی **: سازماندهی داده ها برای کاهش افزونگی
- **Denormalization**: اضافه کردن افزونگی برای بهبود عملکرد خواندن
## پایگاه های داده رابطه ای (SQL)
### مفاهیم اصلی
- **جدول**: ردیف ها (سوابق) و ستون ها (فیلدها)
- ** کلید اصلی **: شناسه منحصر به فرد برای هر ردیف
- **کلید خارجی**: ارجاع به کلید اصلی در جدولی دیگر
- **شاخص ها**: ساختارهای داده سرعت پرس و جو را بهبود می بخشد
- **نمایش**: جداول مجازی بر اساس نتایج پرس و جو
- **روش های ذخیره شده**: بلوک های کد SQL از پیش کامپایل شده
- **محرک**: اقدامات خودکار روی تغییرات داده ها
### عملیات SQL (CRUD)```sql
-- Create
INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com');

-- Read
SELECT * FROM users WHERE id = 1;
SELECT name, email FROM users ORDER BY name LIMIT 10;

-- Update
UPDATE users SET email = 'new@example.com' WHERE id = 1;

-- Delete
DELETE FROM users WHERE id = 1;
```

### ملحق می شود
- **پیوستن داخلی **: ردیف های منطبق از هر دو جدول را برمی گرداند
- ** LEFT JOIN **: همه ردیف ها از جدول سمت چپ، منطبق از سمت راست
- ** RIGHT JOIN **: همه ردیف ها از جدول سمت راست، منطبق از سمت چپ
- ** FULL OUTER JOIN **: همه ردیف ها از هر دو جدول
- **CROSS JOIN**: محصول دکارتی هر دو جدول
- **SELF JOIN**: جدول با خودش پیوست
### فرم های عادی سازی
- **1NF**: مقادیر اتمی، بدون گروه های تکرار شونده
- **2NF**: 1NF + بدون وابستگی جزئی (همه ویژگی های غیر کلیدی به کل کلید اصلی بستگی دارند)
- **3NF**: 2NF + بدون وابستگی گذرا (ویژگی های غیر کلیدی به سایر ویژگی های غیر کلیدی بستگی ندارند)
- **BCNF**: 3NF قوی تر، هر تعیین کننده یک کلید کاندید است
- **4NF**: بدون وابستگی چند ارزشی
- **5NF**: بدون وابستگی به پیوستن
### RDBMS محبوب
- ** PostgreSQL **: ویژگی های پیشرفته، قابل توسعه، سازگار با ACID
- **MySQL**: به طور گسترده مورد استفاده، خواندن سریع، برنامه های کاربردی وب
- **Oracle**: ویژگی های سازمانی، مقیاس پذیری، گران قیمت
- **SQL Server**: اکوسیستم مایکروسافت، ابزارهای یکپارچه
- **SQLite**: تعبیه شده، بدون سرور، سبک وزن
- **MariaDB**: فورک MySQL، منبع باز
## پایگاه های داده NoSQL
### انواع پایگاه های داده NoSQL
#### فروشگاه های اسناد
- **ساختار**: اسناد JSON مانند (BSON)
- ** موارد استفاده **: مدیریت محتوا، کاتالوگ ها، پروفایل های کاربر
- **مثال**: MongoDB، CouchDB، DocumentDB
- **مثال پرس و جو** (MongoDB):```javascript
db.users.find({ age: { $gt: 25 } }).sort({ name: 1 });
```

#### فروشگاه های کلیدی ارزش
- **ساختار**: جفت های کلید-مقدار ساده
- ** موارد استفاده **: ذخیره سازی، جلسات، سبد خرید
- **نمونه**: Redis، DynamoDB، Riak
- **ویژگی ها**: پرس و جو سریع، ساده، محدود
#### ستون-فروشگاه های خانوادگی
- **ساختار**: ستون ها به خانواده ها گروه بندی شده اند
- ** موارد استفاده **: داده های بزرگ، تجزیه و تحلیل، سری زمانی
- **مثال**: Cassandra، HBase، ScyllaDB
- **ویژگی ها**: نوشتن بهینه، توزیع شده، مقیاس پذیر
#### پایگاه‌های داده گراف
- **ساختار**: گره ها، لبه ها، خواص
- ** موارد استفاده **: شبکه های اجتماعی، کشف تقلب، توصیه ها
- **مثال**: Neo4j، Amazon Neptune، ArangoDB
- **زبان پرس و جو**: Cypher (Neo4j)، Gremlin
### چه زمانی از NoSQL استفاده کنیم
- طرح واره انعطاف پذیر/در حال تحول
- الزامات مقیاس بندی افقی
- توان نوشتن بالا
- داده های سلسله مراتبی/تودرتو
- سیستم های توزیع شده
- برنامه های بلادرنگ
## طراحی پایگاه داده
### مدلسازی نهاد-رابطه
- **موجودات**: اشیاء/مفاهیم (مشتری، محصول، سفارش)
- **ویژگی ها**: ویژگی های موجودیت ها (نام، قیمت، تاریخ)
- **روابط**: ارتباطات بین موجودیت ها (یک به یک، یک به چند، چند به چند)
- **Cardinality **: تعداد موارد در رابطه
### الگوهای طراحی طرحواره
- ** وراثت جدول تکی **: همه انواع در یک جدول با تفکیک کننده نوع
- ** کلاس جدول وراثت **: جداول جدا برای پایه و زیر کلاس
- ** وراثت جدول بتنی **: جدول مجزا برای هر کلاس بتن
- ** جداول متقابل **: روابط چند به چند را حل کنید
- **جدول حسابرسی**: ردیابی تغییرات (created_at، updated_at، deleted_at)
### استراتژی های نمایه سازی
- **B-Tree**: پیش فرض، پرس و جوهای محدوده، مرتب سازی
- **هش**: جستجوهای دقیق مطابقت
- **Bitmap**: ستون های کم کاردینالیته (جنسیت، وضعیت)
- **Full-Text**: قابلیت جستجوی متن
- **مکانی**: داده های جغرافیایی (GIS)
- **کامپوزیت**: ترکیب چند ستون
- **پوشش**: شامل تمام ستون های مورد نیاز برای پرس و جو می باشد
## بهینه سازی پرس و جو
### برنامه های اجرایی
- درک نحوه اجرای پرس و جو توسط پایگاه داده
- شناسایی تنگناها (اسکن جدول کامل، نمایه های گم شده)
- ابزار: EXPLAIN، EXPLAIN ANALYZE
### تکنیک های بهینه سازی
- **استفاده از فهرست**: اطمینان حاصل کنید که پرس و جوها از نمایه های مناسب استفاده می کنند
- **بازنویسی پرس و جو**: پرس و جوهای پیچیده را ساده می کند
- **بهینه سازی پیوستن**: انواع اتصال و ترتیب صحیح را انتخاب کنید
- **پارتیشن بندی**: جداسازی جداول بزرگ (محدوده، هش، فهرست)
- **نماهای مادی**: نتایج پرس و جو از پیش محاسبه شده
- **Query Caching**: ذخیره نتایج جستجوی مکرر
### مشکلات رایج عملکرد
- **مشکل پرس و جو N+1**: واکشی ناکارآمد داده های مرتبط
- **شاخص های گمشده**: جدول کامل اسکن روی جداول بزرگ
- **بیش از حد نمایه سازی**: به دلیل نمایه های زیاد، کند می نویسد
- **مشاهده قفل **: معاملات در انتظار قفل
- **پرسش های ناکارآمد**: SELECT *، پیوستن های غیر ضروری
## معاملات و همزمانی
### سطوح جداسازی تراکنش
- **READ UNCOMMITTED**: کمترین انزوا، خواندن کثیف ممکن است
- **READ COMMITTED**: فقط داده های متعهد قابل مشاهده است (پیش فرض در اکثر DB ها)
- **Repeatable Read **: همان پرس و جو نتایج یکسانی را در تراکنش برمی گرداند
- **SRIALIZABLE **: بالاترین انزوا، تراکنش ها به صورت متوالی اجرا می شوند
### کنترل همزمان
- ** قفل بدبینانه **: قفل کردن منابع قبل از دسترسی
- **قفل خوش بینانه**: نسخه را قبل از انجام بررسی کنید
- **MVCC (Multi-Version Concurrency Control)**: حفظ چندین نسخه از ردیف ها
- **قفل در سطح ردیف**: سطرهای خاص را قفل کنید
- **قفل کردن سطح جدول**: کل جدول را قفل کنید
### بن بست
- وابستگی دایره ای که در آن تراکنش ها منتظر یکدیگر هستند
- پیشگیری: ترتیب قفل مداوم، وقفه های زمانی، تشخیص بن بست
- قطعنامه: یک تراکنش را لغو کنید
## تکرار و مقیاس‌بندی
### انواع تکرار
- **Master-Slave**: یک نسخه اولیه، چند نسخه خوانده شده
- **Master-Master**: مقدماتی چندگانه، تکرار دوطرفه
- **Multi-Master**: N مرحله مقدماتی، حل تعارض مورد نیاز است
- **تکثیر زنجیره ای**: تکرار متوالی از طریق گره ها
### رویکردهای مقیاس بندی
- ** مقیاس عمودی **: افزایش منابع سرور (CPU، RAM، حافظه)
- **مقیاس بندی افقی**: سرورهای بیشتری را اضافه کنید (شاردینگ، پارتیشن بندی)
- **Read Replicas**: بارگیری ترافیک خوانده شده
- **Sharding**: تقسیم داده ها در سرورها بر اساس کلید/محدوده/هش
- **فدراسیون**: تقسیم بر اساس عملکرد/سرویس
### مدل های سازگاری
- ** ثبات قوی **: همه گره ها داده های یکسانی را در یک زمان مشاهده می کنند
- **ثبات نهایی **: گره ها در طول زمان همگرا می شوند
- **ثبات علّی**: روابط علت و معلولی حفظ شده است
- ** Read-Your-Writes **: کاربر فوراً به روز رسانی های خود را می بیند
## پشتیبان گیری و بازیابی
### استراتژی های پشتیبان گیری
- **پشتیبان گیری کامل**: کپی کامل پایگاه داده
- ** پشتیبان گیری افزایشی **: تغییرات از آخرین نسخه پشتیبان
- **Differential Backup**: تغییرات از آخرین نسخه پشتیبان کامل
- **بازیابی نقطه در زمان**: بازیابی به لحظه خاص
- **پشتیبان گیری مستمر **: تکرار در زمان واقعی به پشتیبان
### مراحل بازیابی
- **RTO (Recovery Time Objective) **: حداکثر زمان خرابی قابل قبول
- **RPO (Recovery Point Objective) **: حداکثر از دست دادن داده قابل قبول
- **طرح بازیابی بلایا**: رویه های مستند برای خرابی ها
- **تست **: تمرینات بازیابی منظم
## امنیت
### کنترل دسترسی
- **Authentication**: تایید هویت کاربر
- **مجوز**: اعطای مجوزها (GRANT، ReEVOKE)
- **نقش**: مجوزهای گروهی برای مدیریت آسانتر
- **اصل حداقل امتیاز**: حداقل دسترسی لازم
### حفاظت از داده ها
- **رمزگذاری در حالت استراحت**: داده های ذخیره شده را رمزگذاری کنید
- **رمزگذاری در حمل و نقل**: TLS/SSL برای اتصالات
- **Masking**: مخفی کردن داده های حساس در غیر تولید
- **Tokenization**: جایگزینی داده های حساس با توکن ها
### آسیب پذیری های رایج
- **SQL Injection**: SQL مخرب در ورودی کاربر
- ** افزایش امتیاز **: به دست آوردن دسترسی غیرمجاز
- ** ثبت حسابرسی **: تمام فعالیت های پایگاه داده را ردیابی کنید
- **تناسب **: الزامات GDPR، HIPAA، PCI-DSS
## فن آوری های مدرن پایگاه داده
### پایگاه های داده ابری
- **AWS**: RDS، Aurora، DynamoDB، Redshift
- **Google Cloud**: Cloud SQL، Spanner، Bigtable، Firestore
- **Azure**: پایگاه داده SQL، Cosmos DB، Synapse
- ** مزایا **: خدمات مدیریت شده، مقیاس بندی خودکار، پشتیبان گیری گنجانده شده است
### پایگاه های داده NewSQL
- سازگاری SQL را با مقیاس پذیری NoSQL ترکیب کنید
- **مثال**: CockroachDB، TiDB، YugabyteDB، Google Spanner
- **ویژگی ها**: توزیع شده، تراکنش های ACID، مقیاس بندی افقی
### پایگاه های داده سری زمانی
- برای داده های مهر زمانی بهینه شده است
- **مثال**: InfluxDB، TimescaleDB، Prometheus
- ** موارد استفاده **: اینترنت اشیا، نظارت، داده های مالی
### پایگاه های داده برداری
- بردارهای جاسازی را ذخیره و پرس و جو کنید
- **مثال**: Pinecone، Milvus، Weaviate، Qdrant
- ** موارد استفاده **: جستجوی معنایی، سیستم های توصیه، برنامه های کاربردی هوش مصنوعی
### پایگاه های داده چند مدلی
- پشتیبانی از مدل های داده های متعدد در سیستم واحد
- **مثال**: ArangoDB، OrientDB، Azure Cosmos DB
- ** مزیت **: انعطاف پذیری بدون پایگاه داده های متعدد
