# مهندسی ML و MLOps
ساخت یک مدل یادگیری ماشین تنها نیمی از نبرد است. وارد کردن آن به تولید، اجرای مطمئن آن، نظارت بر دریفت، و تکرار بر روی آن - اینجاست که مهندسی ML و MLO ها وارد می شوند. این فایل تمام چرخه حیات از آزمایش تا سیستم تولید را پوشش می دهد.
---

## چرخه حیات ML
| فاز | توضیحات | فعالیت های کلیدی |
|-------|------------|---------------|
| **1. تعریف مسئله** | مشکل کسب و کار را به عنوان یک وظیفه ML قاب بندی کنید | تعریف معیارها، محدودیت ها، معیارهای موفقیت |
| **2. گردآوری داده** | جمع آوری و برچسب گذاری داده های آموزشی | ETL، برچسب زدن، تقویت |
| **3. آزمایش** | آموزش و ارزیابی مدل ها | مهندسی ویژگی، تنظیم هایپرپارامتر |
| **4. انتخاب مدل** | بهترین مدل را انتخاب کنید | مقایسه معیارها، ارزیابی مبادلات |
| **5. استقرار ** | ارسال مدل به تولید | خدمات زیرساخت، API، دسته |
| **6. نظارت ** | مراقب رانش و تخریب باشید | رانش داده، رانش مفهومی، عملکرد |
| **7. بازآموزی** | به روز رسانی مدل با داده های جدید | بازآموزی برنامه ریزی شده یا فعال |
بیشتر ارزش (و سختی) در مراحل 5-7 است. مدلی که در دفترچه یادداشت Jupyter نشسته ارزش تجاری ایجاد نمی کند.

## ثبت مدل
رجیستری مدل یک فروشگاه متمرکز برای مدیریت مدل‌های ML است - نسخه‌ها، ابرداده‌ها، معیارها و وضعیت استقرار آنها.
| قابلیت | توضیحات |
|-----------|-------------|
| **نسخه** | ردیابی هر نسخه مدل با شناسه منحصر به فرد |
| **فراداده** | داده های آموزشی، هایپرپارامترها، متریک ها، نویسنده |
| **انتقالات مرحله** | جابجایی مدل ها از طریق مراحل: مرحله بندی → تولید → بایگانی شده |
| **نسب ** | ردیابی کدام داده و کد تولید هر مدل |
| ابزار | توضیحات |
|------|-------------|
| **MLflow** | منبع باز؛ رجیستری مدل + ردیابی آزمایش |
| **وزن ها و سوگیری ها (W&B)** | تجاری؛ ردیابی آزمایش + رجیستری مدل |
| **DVC** | داده ها و نسخه سازی مدل با Git |
| **Azure ML / SageMaker** | مدیریت مدل بومی ابری |

## ردیابی آزمایش
هر آزمایش ML باید ردیابی شود: چه داده هایی استفاده شده است، چه فراپارامترهایی، چه معیارهایی به دست آمده است.
| ابزار | ویژگی های کلیدی |
|------|-------------|
| **MLflow** | منبع باز، خود میزبانی، پارامترها / معیارها / مصنوعات را ردیابی می کند |
| **W&B** | رابط کاربری غنی، جاروها، نسخه‌سازی مصنوعات، گزارش‌ها |
| **نپتون** | فروشگاه ابرداده برای MLOps |
| **TensorBoard** | ساخته شده در TensorFlow. تجسم منحنی های آموزشی |
### چه چیزی را ردیابی کنیم
| دسته بندی | مثال ها |
|----------|---------|
| **پارامترها** | نرخ یادگیری، اندازه دسته ای، معماری مدل، تعداد دوره ها |
| **متریک** | دقت، از دست دادن، F1، AUC-ROC (در هر دوره و نهایی) |
| **مصنوعات** | وزن مدل، ماتریس های سردرگمی، نمونه های پیش بینی |
| **داده** | نسخه مجموعه داده، نسبت تقسیم، مراحل پیش پردازش |
| **محیط زیست** | نسخه پایتون، نسخه های کتابخانه، سخت افزار |

## استراتژی های استقرار مدل
| استراتژی | چگونه کار می کند | ریسک |
|----------|-------------|------|
| **استقرار سایه** | مدل جدید در کنار قدیمی اجرا می شود. پیش بینی ها مقایسه شدند اما ارائه نشد | ریسک صفر؛ قبل از پخش زنده اعتبار سنجی می کند |
| **رهاسازی قناری** | مسیریابی درصد کمی از ترافیک به مدل جدید. افزایش تدریجی | کم خطر؛ برگشت سریع |
| **تست A/B** | تقسیم کاربران بین قدیمی و جدید؛ مقایسه معیارهای کسب و کار | اندازه گیری تاثیر واقعی |
| **آبی-سبز** | دو محیط یکسان؛ همه ترافیک را به یکباره تغییر دهید | بازگشت فوری؛ هزینه مضاعف در طول انتقال |
| **پرچم های ویژگی** | روشن/خاموش کردن مدل در هر بخش کاربر | کنترل ریزدانه |

## نظارت بر سیستم های ML
سیستم های ML نسبت به نرم افزارهای سنتی به نظارت بیشتری نیاز دارند زیرا خود داده ها می توانند تغییر کنند.
### انواع دریفت
| نوع دریفت | چه تغییراتی | مثال |
|-----------|-------------|---------|
| **Data Drift** | تغییرات توزیع ورودی | تغییر جمعیت شناسی مشتری پس از یک کمپین بازاریابی |
| **مفهوم دریفت** | رابطه بین تغییرات ورودی و خروجی | تغییر رفتار مصرف کننده در دوران رکود |
| **برچسب دریفت** | تغییرات توزیع هدف | نرخ تقلب از 1% به 5% افزایش می یابد |
### چه چیزی را مانیتور کنیم
| دسته بندی | متریک |
|----------|---------|
| **عملکرد مدل** | دقت، دقت، فراخوان، F1، AUC (در مقایسه با خط پایه) |
| **کیفیت داده** | مقادیر از دست رفته، توزیع ویژگی، نقاط پرت |
| **تشخیص دریفت** | آزمون های آماری (تست KS، PSI، واگرایی KL) |
| **زیرساخت** | تأخیر، توان عملیاتی، استفاده از GPU، حافظه |
| ** معیارهای کسب و کار ** | نرخ تبدیل، تاثیر درآمد، رضایت کاربر |
### ابزارهای نظارت
| ابزار | نوع |
|------|------|
| **ظاهراً هوش مصنوعی** | رانش داده منبع باز و نظارت بر عملکرد مدل |
| **گرافانا** | تجسم داشبورد (با پرومتئوس کار می کند) |
| **WhyLabs** | پلت فرم مشاهده پذیری داده ها |
| **آریزه** | قابلیت مشاهده ML و تجزیه و تحلیل علت ریشه ای |
| **پرومته + گرافانا** | معیارهای زیرساخت و کاربرد |

## آموزش تکراری
تکرارپذیری به این معنی است که می توانید یک آزمایش را دوباره اجرا کنید و همان نتیجه را بگیرید. برای اشکال زدایی، ممیزی و انطباق ضروری است.
### الزامات
| مورد نیاز | چگونه به آن دست یابیم |
|-------------|-------------------|
| **نسخه سازی داده** | عکس‌های فوری DVC، Delta Lake یا مجموعه داده با هش |
| **نسخه سازی کد** | کد آموزشی Git for all |
| **پین زدن محیط** | `requirements.txt`,`conda env`, تصاویر داکر با نسخه های دقیق |
| **تنظیم بذر** | دانه های تصادفی را برای numpy، torch، tensorflow |
| **مدیریت پیکربندی** | پیکربندی های Hydra، OmegaConf یا YAML برای همه هایپرپارامترها |
| **ردیابی مصنوعات** | MLflow یا W&B برای ثبت هر آزمایش |

## استنتاج مقیاس بندی
هنگامی که یک مدل نیاز به ارائه میلیون ها درخواست در روز دارد، عملکرد اهمیت دارد.
| تکنیک | توضیحات |
|-----------|-------------|
| **بچینگ** | چندین درخواست را در یک پاس به جلو |
| **کوانتیزاسیون** | کاهش دقت مدل (FP32 → INT8 یا INT4) برای استنتاج سریعتر |
| **مدل تقطیر** | یک مدل کوچکتر را برای تقلید از مدل بزرگتر آموزش دهید |
| **هرس** | حذف وزنه ها یا نورون های بی اهمیت |
| **در حافظه پنهان** | برای جلوگیری از محاسبه مجدد، پیش بینی های مکرر را در حافظه پنهان ذخیره کنید |
| **بهینه سازی GPU** | TensorRT، ONNX Runtime، Flash Attention |
| **مقیاس بندی افقی** | چند مدل ماکت را پشت یک بار متعادل کننده اجرا کنید |

## پرچم های ویژگی برای ML
پرچم‌های ویژگی به شما این امکان را می‌دهند که بدون استفاده مجدد، کنترل کنید که کدام نسخه مدل به کدام کاربر خدمات می‌دهد.
| مورد استفاده | توضیحات |
|----------|-------------|
| **عرضه تدریجی** | مدل جدید را به 5% از کاربران ارائه دهید، سپس افزایش دهید |
| **سوئیچ کش** | در صورت شناسایی مشکلات، فوراً به مدل قبلی برگردید |
| **بر اساس بخش** | مدل های مختلف برای بخش های مختلف کاربران |
| **آزمایش** | انواع مدل تست A/B با معیارهای تجاری |
ابزارها: LaunchDarkly، Unleash، Flagsmith، یا پرچم های ویژگی ساده با پشتیبانی پایگاه داده.
