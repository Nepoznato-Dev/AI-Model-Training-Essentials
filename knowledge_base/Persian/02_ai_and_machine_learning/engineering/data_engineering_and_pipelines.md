# مهندسی داده و خطوط لوله
مهندسی داده رشته ساختن سیستم هایی است که داده ها را در مقیاس جابجا، تبدیل و ذخیره می کند. بدون خطوط انتقال داده های قابل اعتماد، مدل های یادگیری ماشین را نمی توان آموزش داد، داشبوردها اعداد قدیمی را نشان می دهند و تصمیمات تجاری بر اساس حدس و گمان است. این فایل معماری، ابزارها و شیوه‌های ساخت زیرساخت داده را پوشش می‌دهد که کار می‌کند.
---

## ETL در مقابل ELT
| رویکرد | چگونه کار می کند | بهترین برای | ابزار |
|----------|------------|---------|-------|
| **ETL** (Extract → Transform → Load) | تبدیل داده ها *قبل از* بارگیری در انبار | انبارهای سنتی با محاسبات محدود | Informatica، Talend، Apache NiFi |
| **ELT** (Extract → Load → Transform) | ابتدا داده های خام را بارگیری کنید. تبدیل *داخل* انبار | انبارهای ابری مدرن با محاسبات الاستیک | dbt، Fivetran، Airbyte + BigQuery/Snowflake |
تغییر از ETL به ELT توسط انبارهای داده ابری (BigQuery، Snowflake، Redshift) انجام شده است که می توانند محاسبه را مستقل از فضای ذخیره سازی مقیاس کنند. دیگر نیازی به پیش پردازش همه چیز قبل از بارگیری نیست.
---

## دریاچه های داده در مقابل انبارهای داده
| ویژگی | دریاچه داده | انبار داده |
|---------|-----------|---------------|
| **فرمت داده** | فرمت خام، بومی (طرحواره روی خواندن) | ساختاریافته، پردازش شده (شما روی نوشتن) |
| **طرحواره** | تعریف شده در زمان پرس و جو | تعریف شده قبل از بارگذاری |
| **انواع داده** | ساختاریافته،نیمه ساختاریافته،بدون ساختار | ساختار اولیه |
| **کاربران** | دانشمندان داده، مهندسان | تحلیلگران کسب و کار، ابزارهای BI |
| **هزینه** | ذخیره سازی ارزان تر (ذخیره سازی اشیاء) | گران تر (بهینه شده برای پرس و جو) |
| **نمونه** | AWS S3، Azure Data Lake، GCS | Snowflake، BigQuery، Redshift |
رویکرد مدرن **دریاچه** است: ذخیره سازی ارزان و انعطاف پذیر یک دریاچه را با ویژگی های مدیریت و عملکرد یک انبار ترکیب کنید. دریاچه دلتا، کوه یخ آپاچی و آپاچی هودی فناوری‌های کلیدی در اینجا هستند.

## معماری خطوط لوله
### دسته در مقابل جریان
| حالت | توضیحات | تأخیر | مورد استفاده |
|------|-------------|---------|----------|
| **دسته** | پردازش داده ها در قطعات بزرگ در فواصل زمان بندی شده | دقیقه تا ساعت | گزارش های روزانه، مشاغل ETL، غنی سازی داده ها |
| **استریم** | پردازش داده ها به صورت پیوسته به محض رسیدن | میلی ثانیه به ثانیه | داشبوردهای بلادرنگ، تشخیص تقلب، هشدارها |
| **میکرو دسته** | دسته های کوچک در فواصل زمانی بسیار کوتاه | ثانیه | تقریباً در زمان واقعی با سادگی دسته ای |
### اجزای خط لوله
یک خط لوله داده معمولی دارای این مراحل است:
| مرحله | توضیحات | ابزار |
|-------|-------------|-------|
| **بلع ** | جمع آوری داده ها از منابع | Kafka، Airbyte، Fivetran، Debezium |
| **تحول** | تمیز کردن، غنی سازی، کل | dbt، اسپارک، پانداها |
| **ذخیره** | تداوم داده های پردازش شده | BigQuery، Snowflake، S3، Delta Lake |
| **سرویس** | داده ها را در دسترس مصرف کنندگان قرار دهید | API ها، داشبوردها، فروشگاه های ویژگی ML |
| **ارکستراسیون** | برنامه ریزی و مدیریت وابستگی ها | جریان هوا، بخشدار، داگستر |
| **نظارت** | ردیابی سلامت خط لوله و کیفیت داده | انتظارات بزرگ، مونت کارلو، هشدارهای سفارشی |

## ابزار ارکستراسیون
| ابزار | رویکرد | قدرت |
|------|----------|----------|
| **Apache Airflow** | DAG های مبتنی بر پایتون؛ استاندارد صنعت | اکوسیستم بزرگ، بالغ، انعطاف پذیر |
| **بخشدار** | Python-native; API تمیزتر از Airflow | طراحی مدرن، رسیدگی به خطاهای بزرگ |
| **داگستر** | دارایی محوری؛ رویکرد مهندسی نرم افزار | سیستم نوع، تست، مشاهده پذیری |
| **لوئیجی** | ابزار اصلی خط لوله اسپاتیفای | ساده، اما کمتر توسعه یافته |
### مثال جریان هوا
```python
from airflow import DAG
from airflow.operators.python import PythonOperator
from datetime import datetime

def extract():
    # Pull data from source
    pass

def transform():
    # Clean and process
    pass

def load():
    # Write to warehouse
    pass

with DAG("etl_pipeline", start_date=datetime(2024, 1, 1),
         schedule="@daily", catchup=False) as dag:
    e = PythonOperator(task_id="extract", python_callable=extract)
    t = PythonOperator(task_id="transform", python_callable=transform)
```

## آپاچی کافکا
کافکا ستون فقرات بسیاری از سیستم های داده بلادرنگ است. این یک گزارش رویداد توزیع‌شده است که پیام‌هایی با توان عملیاتی بالا و با تحمل خطا ارائه می‌دهد.
### مفاهیم اصلی
| مفهوم | توضیحات |
|---------|-------------|
| **موضوع** | دسته ای از پیام ها (به عنوان مثال، `orders`، `user-events`) |
| **پارتیشن** | موضوعات برای موازی سازی به پارتیشن تقسیم می شوند |
| **تهیه کننده** | برنامه ای که برای موضوعات پیام می نویسد |
| **مصرف کننده** | برنامه ای که پیام ها را از موضوعات می خواند |
| **گروه مصرف کنندگان** | گروهی از مصرف کنندگان که بار خواندن یک موضوع را به اشتراک می گذارند |
| **افست** | موقعیت یک مصرف کننده در یک پارتیشن |
| **کارگزار** | یک گره سرور کافکا |
### چه زمانی از کافکا استفاده کنیم
- ** جریان رویداد **: پردازش رویداد در زمان واقعی در مقیاس.
- **خدمات جداسازی**: تولیدکنندگان و مصرف کنندگان نیازی به دانستن یکدیگر ندارند.
- **بازپخش**: پیام ها حفظ می شوند. مصرف کنندگان می توانند از هر افست دوباره بخوانند.
- ** فشار معکوس **: کافکا به طور طبیعی تفاوت های سرعت بین تولید کنندگان و مصرف کنندگان را کنترل می کند.

## مدل سازی داده
### طرحواره ستاره در مقابل طرح واره دانه برف
| طرحواره | ساختار | جوانب مثبت | معایب |
|--------|----------|------|------|
| **ستاره** | جدول واقعیت مرکزی احاطه شده توسط جداول ابعاد غیرعادی شده | سوالات ساده، خواندن سریع | افزونگی داده |
| **دانه برف** | جداول ابعاد نرمال می شوند (به جداول فرعی تقسیم می شوند) | افزونگی کمتر | پیوستن های بیشتر، درخواست های کندتر |
### جداول واقعیت و ابعاد
| نوع جدول | حاوی | مثال |
|-----------|----------|---------|
| **واقعیت** | رویدادهای قابل اندازه گیری (متریک) | `orders`(شناسه_سفارش، شناسه_ محصول، شناسه_مشتری، مبلغ، تاریخ) |
| **بعد ** | ویژگی های توصیفی | `products`(شناسه_محصول، نام، دسته، قیمت)،`customers`(شناسه_مشتری، نام، شهر) |

## فروشگاه های ویژه
فروشگاه ویژگی یک مخزن متمرکز از ویژگی‌های ML است - مقادیر مشتق شده به عنوان ورودی مدل‌ها (مثلاً "متوسط ​​مقدار سفارش کاربر در 30 روز گذشته").
| قابلیت | توضیحات |
|-----------|-------------|
| **رجیستری ویژگی** | کاتالوگ ویژگی های موجود با ابرداده |
| **فروشگاه آفلاین** | ویژگی های تاریخی برای آموزش مدل (بچ) |
| **فروشگاه اینترنتی** | ویژگی با تأخیر کم برای استنتاج بلادرنگ |
| **نظارت بر ویژگی** | تشخیص رانش، مقادیر از دست رفته، تغییرات توزیع |
| ابزار | توضیحات |
|------|-------------|
| **عید** | منبع باز؛ با هر چارچوب ML کار می کند |
| **تکتون** | تجاری؛ پلت فرم ویژگی بلادرنگ |
| **Hopsworks** | منبع باز؛ پلتفرم کامل ML با فروشگاه ویژگی |
| **فروشگاه ویژگی Databricks** | یکپارچه شده با Databricks/Spark |

## کیفیت داده
کیفیت داده ها قاتل خاموش پروژه های ML است. زباله داخل، زباله بیرون.
### ابعاد کیفیت
| ابعاد | سوال |
|-----------|----------|
| **دقت** | آیا داده ها واقعیت را منعکس می کنند؟ |
| **کامل بودن** | آیا فیلدهای الزامی پر شده است؟ |
| **ثبات ** | آیا ارزش ها در منابع مختلف با هم همخوانی دارند؟ |
| **به موقع** | آیا داده جاری است؟ |
| **اعتبار** | آیا مقادیر با قوانین تعریف شده مطابقت دارند؟ |
| **بی نظیری** | آیا سوابق تکراری وجود دارد؟ |
### ابزارهای کیفیت داده
| ابزار | رویکرد |
|------|----------|
| **انتظارات بزرگ** | مبتنی بر پایتون؛ تعریف "انتظارات" در مورد داده |
| **مونته کارلو** | پلت فرم مشاهده‌پذیری داده‌های مبتنی بر ML |
| **تست های dbt** | تست های داخلی برای داده های انبار (محصول، not_null، روابط) |
| **نوشابه** | اسکن کیفیت داده منبع باز |

## حاکمیت داده
حاکمیت داده تضمین می کند که داده ها به طور مسئولانه در سراسر سازمان مدیریت می شوند.
| منطقه | توضیحات |
|------|-------------|
| **کاتالوگ داده** | موجودی قابل جستجو مجموعه داده با ابرداده (Amundsen, DataHub, Atlan) |
| **Data Lineage** | ردیابی کنید که داده ها از کجا می آیند و چگونه تبدیل می شوند |
| **کنترل دسترسی** | مجوزهای مبتنی بر نقش؛ چه کسی می تواند چه بخواند/بنویسد |
| **تناسب ** | پایبندی GDPR، CCPA، HIPAA |
| **مالکیت داده** | مالکیت روشن برای هر مجموعه داده (مدیریت) |
| **سیاست های حفظ ** | مشخص کنید که چه مدت داده ها نگهداری می شوند و چه زمانی حذف می شوند |

## پشته داده های مدرن
"پشته داده های مدرن" به ترکیب معمولی از ابزارهایی اشاره دارد که امروزه توسط تیم های داده استفاده می شود:
| لایه | ابزارهای معمولی |
|-------|-------------|
| **بلع ** | Fivetran، Airbyte |
| **انبار** | Snowflake، BigQuery، Redshift |
| **تحول** | dbt |
| **ارکستراسیون** | جریان هوا، بخشدار، داگستر |
| **BI / تجسم ** | Looker, Metabase, Tableau |
| ** ETL معکوس ** | سرشماری، Hightouch (همگام سازی داده های انبار به ابزارها) |
| **کیفیت داده** | انتظارات بزرگ، مونت کارلو |
گرایش به سمت ابزارهای مدولار و بهترین است که با استانداردهای باز (SQL، مدل‌های dbt، DAGs جریان هوا) به جای پلتفرم‌های یکپارچه متصل می‌شوند.
