# پرومتئوس و گرافانا
Prometheus یک جعبه ابزار نظارت و هشدار منبع باز است که برای قابلیت اطمینان و مقیاس پذیری طراحی شده است. Grafana پلت فرم منبع باز پیشرو برای تجسم داده های سری زمانی است. آنها با هم، محبوب ترین پشته نظارت را برای زیرساخت ها و برنامه های کاربردی مدرن تشکیل می دهند. پرومتئوس معیارها را جمع آوری و ذخیره می کند. Grafana آنها را در داشبورد نمایش می دهد.
---

## معماری پرومتئوس
| جزء | توضیحات |
|-----------|-------------|
| **سرور پرومتئوس** | معیارها را از اهداف خراش می دهد. داده های سری زمانی را ذخیره می کند. قوانین هشدار را ارزیابی می کند |
| **صادر کننده** | معیارهای یک سیستم (Node Exporter، cAdvisor و غیره) را نشان می دهد |
| **Pushgateway** | معیارهایی را از مشاغل کوتاه مدت (کارهای دسته ای، CI) دریافت می کند |
| **Alertmanager** | هشدارها را کنترل می کند: گروه بندی، خاموش کردن، مسیریابی، مهار |
| **کشف سرویس** | به طور خودکار اهداف (Kubernetes، Consul، EC2، و غیره) را کشف می کند |
---

## مفاهیم کلیدی
| مفهوم | توضیحات |
|---------|-------------|
| **متریک** | اندازه گیری با نام با برچسب های اختیاری و مقدار |
| **سری زمانی** | جریانی از نقاط داده برای یک متریک خاص + ترکیب برچسب |
| **شغل** | مجموعه ای از اهداف با همین هدف |
| **نمونه** | یک هدف برای خراش دادن (معمولاً یک فرآیند) |
| **خراش** | پرومتئوس معیارها را از یک هدف در فواصل زمانی منظم می کشد |
| **برچسب** | یک جفت کلید-مقدار که یک متریک را ابعاد می دهد (به عنوان مثال،`method="GET"`) |
| **نمونه** | یک مقدار در یک نقطه از زمان: (مهر زمانی، مقدار) |

## انواع متریک
| نوع | توضیحات | مورد استفاده |
|------|-------------|----------|
| **پیشخوان** | مقدار افزایش یکنواخت (فقط بالا می رود) | تعداد درخواست ها؛ خطاها؛ وظایف تکمیل شده |

| **هیستوگرام** | مشاهدات با مقدار | درخواست تأخیر؛ اندازه پاسخ |
| **خلاصه** | مشابه هیستوگرام؛ محاسبه چندک سمت مشتری | صدک تاخیر |

## PromQL (زبان پرس و جو)
### پرس و جوهای اساسی
| پرس و جو | توضیحات |
|-------|------------|
| `http_requests_total`| سری زمانی خام |
| `http_requests_total{method="GET"}`| فیلتر بر اساس برچسب |
| `http_requests_total{method="GET", status="200"}`| فیلترهای چندگانه برچسب |
| `rate(http_requests_total[5m])`| نرخ در ثانیه بیش از 5 دقیقه |
| `increase(http_requests_total[1h])`| افزایش کل بیش از 1 ساعت |
| `sum(rate(http_requests_total[5m])) by (status)`| نرخ کل بر اساس وضعیت |
| `histogram_quantile(0.95, rate(http_duration_bucket[5m]))`| تأخیر صدک 95 |
| `avg(node_cpu_seconds_total{mode="idle"})`| متوسط ​​CPU بیکار |
| `1 - avg(rate(node_cpu_seconds_total{mode="idle"}[5m]))`| استفاده از CPU |
### توابع رایج
| تابع | توضیحات | مثال |
|----------|-------------|---------|
| `rate()`| میانگین نرخ افزایش در هر ثانیه | `rate(requests_total[5m])`|
| `irate()`| نرخ بر ثانیه بر اساس دو نقطه داده آخر | `irate(requests_total[1m])`|
| `increase()`| افزایش کل در بازه زمانی | `increase(errors_total[1h])`|
| `sum()`| مجموع بین سری | `sum(rate(requests_total[5m])) by (service)`|
| `avg()`| میانگین در بین سری | `avg(node_memory_usage)`|
| `histogram_quantile()`| محاسبه چندک از هیستوگرام | `histogram_quantile(0.99, rate(duration_bucket[5m]))`|
| `topk()`| سری K برتر بر اساس مقدار | `topk(5, rate(requests_total[5m]))`|
| `predict_linear()`| پیش بینی خطی | `predict_linear(disk_usage[1h], 4*3600)`|
| `absent()`| بررسی کنید که آیا متریک موجود نیست | `absent(up{job="myapp"})`|

## گرافانا
### مفاهیم کلیدی
| مفهوم | توضیحات |
|---------|-------------|
| **منبع داده** | اتصال به Prometheus (یا سایر باطن ها) |
| **داشبورد** | مجموعه پانل های چیدمان شده در یک طرح |
| **پنل** | تجسم تک (گراف، گیج، جدول، نقشه حرارتی) |
| **متغیر** | فیلتر پویا برای داشبورد (به عنوان مثال، انتخاب نمونه) |
| ** حاشیه نویسی ** | علامت گذاری رویدادها بر روی نمودارها (استقرار، حوادث) |
| **قانون هشدار** | هشدار مبتنی بر آستانه در Grafana |
| **قالب سازی** | الگوهای داشبورد قابل استفاده مجدد با متغیرها |
### الگوهای مفید داشبورد
| الگو | توضیحات |
|---------|-------------|
| ** ردیف نمای کلی ** | معیارهای کلیدی در یک نگاه: نرخ خطا، تاخیر، توان عملیاتی |
| **تحلیل** | با استفاده از متغیرهای | از خلاصه به نمای تفصیلی کلیک کنید
| **روش قرمز** | نرخ، خطا، مدت - سه معیار کلیدی خدمات |
| **روش استفاده** | استفاده، اشباع، خطاها — برای زیرساخت |
| **سیگنال های طلایی** | تأخیر، ترافیک، خطاها، اشباع (کتاب SRE گوگل) |

## هشدار
### ساختار قانون هشدار
```yaml
groups:
  - name: example
    rules:
      - alert: HighErrorRate
        expr: rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m]) > 0.05
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "High error rate on {{ $labels.instance }}"
          description: "Error rate is {{ $value | humanizePercentage }}"
```

### مسیریابی Alertmanager
| مفهوم | توضیحات |
|---------|-------------|
| **گروه** | ترکیب هشدارهای مشابه در یک اعلان |
| **مسیر** | درخت همسان که تعیین می کند هشدارها کجا می روند |
| **گیرنده** | کجا برای ارسال هشدار (ایمیل، Slack، PagerDuty، webhook) |
| **مهار** | وقتی هشدار دیگری در حال پخش است، هشدارها را سرکوب کنید |
| **سکوت** | بی‌صدا کردن موقت هشدارها توسط تطبیق‌کننده برچسب |

## عیب یابی
| مشکل | راه حل |
|---------|----------|
| **هدف به پایین** | بررسی کنید که آیا صادرکننده در حال اجرا است. شبکه/فایروال را بررسی کنید. تایید پیکربندی scrape |
| **بدون داده** | بررسی املای نام متریک؛ فیلترهای برچسب را بررسی کنید. بررسی محدوده زمانی |
| **کاردینالیته بالا** | تعداد زیادی ترکیب برچسب؛ کاهش مقادیر برچسب؛ استفاده از قوانین ضبط |
| **پرس و جوهای کند** | از قوانین ضبط برای پرس و جوهای پیچیده استفاده کنید. افزایش فاصله خراشیدن |
| **خستگی هوشیار** | آستانه تنظیم؛ اضافه کردن مدت زمان `for`. هشدارهای مرتبط با گروه |
| **معیارهای پس از راه اندازی مجدد وجود ندارد** | Prometheus داده ها را به صورت محلی ذخیره می کند. تنظیمات حفظ را بررسی کنید |

## خلاصه
Prometheus سیستم ها را با خراش دادن معیارها از صادرکنندگان در فواصل منظم نظارت می کند. متریک ها در چهار نوع هستند: شمارنده (فقط بالا می رود)، سنج (بالا و پایین)، هیستوگرام (مشاهدات سطلی)، و خلاصه (چندک). PromQL زبان پرس و جو است — `rate()`، `increase()`، `histogram_quantile()`، و توابع تجمع (`sum`، `avg`) رایج ترین عملیات هستند. Grafana داده‌های Prometheus را در داشبورد با پانل‌ها، متغیرها و حاشیه‌نویسی تجسم می‌کند. Alerting از Alertmanager برای گروه بندی، مسیریابی، خاموش کردن و مهار هشدارها استفاده می کند. الگوهای نظارتی کلیدی سیگنال‌های طلایی Google (تأخیر، ترافیک، خطاها، اشباع) و روش RED (نرخ، خطاها، مدت زمان) برای خدمات و روش USE (استفاده، اشباع، خطاها) برای زیرساخت هستند.
