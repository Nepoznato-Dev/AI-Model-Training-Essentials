# Terraform و Infrastructure به عنوان کد
Terraform پرکاربردترین ابزار زیرساخت به‌عنوان کد (IaC) است - به شما امکان می‌دهد زیرساخت ابری (سرورها، پایگاه‌های داده، شبکه‌ها، مجوزها) را در فایل‌های پیکربندی اعلامی تعریف کنید که می‌توانند نسخه‌سازی، بررسی، آزمایش و خودکار شوند. به جای کلیک کردن روی یک کنسول ابری، کدی می نویسید که وضعیت مطلوب زیرساخت شما را توصیف می کند و Terraform متوجه می شود که چه تغییراتی باید ایجاد کند.
---

## مفاهیم اصلی
| مفهوم | توضیحات |
|---------|-------------|
| **ارائه دهنده** | افزونه ای که یک پلتفرم ابری خاص (AWS، Azure، GCP و غیره) را مدیریت می کند |
| **منبع** | یک شی زیرساخت (سرور، پایگاه داده، شبکه) |
| **دولت** | سابقه Terraform از زیرساخت های موجود. ذخیره شده در یک فایل وضعیت |
| **برنامه** | پیش نمایش تغییرات Terraform |
| **اعمال** | اجرای طرح؛ ایجاد/به روز رسانی/تخریب زیرساخت |
| **ماژول** | مجموعه منابع قابل استفاده مجدد |
| **متغیر** | پارامتر ورودی برای تنظیمات |
| **خروجی** | مقدار صادر شده از یک ماژول یا پیکربندی |
| **منبع داده** | خواندن اطلاعات از زیرساخت های موجود |
---

## گردش کار پایه
| مرحله | فرمان | توضیحات |
|------|---------|-------------|
| **1. نوشتن پیکربندی** | ایجاد فایل`.tf`| تعریف ارائه دهندگان، منابع، متغیرها |
| **2. راه اندازی ** |  `terraform init` | ارائه دهندگان دانلود؛ راه اندازی باطن |
| **3. قالب** | `terraform fmt`| استاندارد کردن قالب بندی |
| **4. اعتبارسنجی ** |  `terraform validate` | بررسی نحو و پیکربندی |
| **5. طرح** | `terraform plan`| پیش نمایش تغییرات (اجرای خشک) |
| **6. درخواست ** | `terraform apply`| ایجاد یا به روز رسانی زیرساخت |
| **7. نابود کردن** |  `terraform destroy` | تمام زیرساخت های مدیریت شده را خراب کنید |
---

## دستورات رایج
| فرمان | توضیحات |
|---------|-------------|
| `terraform init`| راه اندازی دایرکتوری کار. ارائه دهندگان و ماژول های دانلود |
|  `terraform plan` | نمایش چه تغییراتی اعمال خواهد شد |
| `terraform apply`| اعمال تغییرات؛ برای رد شدن از تایید |`-auto-approve` را اضافه کنید
| `terraform destroy`| نابود کردن تمام منابع مدیریت شده |
| `terraform fmt`| فرمت فایل های پیکربندی به سبک استاندارد |
|  `terraform validate` | اعتبارسنجی نحو پیکربندی |
| `terraform output`| نمایش مقادیر خروجی |
| `terraform state list`| فهرست تمام منابع در ایالت |
|  `terraform state show <resource>` | نمایش جزئیات یک منبع خاص |
| `terraform import <resource> <id>`| واردات زیرساخت های موجود به ایالت |
| `terraform taint <resource>`| علامت گذاری یک منبع برای تفریح ​​در درخواست بعدی |
| `terraform refresh`| به روز رسانی وضعیت برای مطابقت با زیرساخت واقعی |
| `terraform graph`| ایجاد نمودار وابستگی بصری (فرمت DOT) |
| `terraform console`| کنسول تعاملی برای تست عبارات |

## مدیریت دولتی
| بهترین تمرین | توضیحات |
|--------------|-------------|
| **دولت از راه دور** | وضعیت را در S3، GCS، Azure Blob یا Terraform Cloud ذخیره کنید — هرگز به صورت محلی |
| **قفل دولتی** | از DynamoDB (باطن S3) یا قفل بومی برای جلوگیری از تغییرات همزمان استفاده کنید |
| **رمزگذاری حالت** | فعال کردن رمزگذاری در حالت استراحت برای فایل های حالت (حاوی داده های حساس) |
| **تفکیک دولت** | استفاده از فایل های حالت جداگانه برای محیط ها یا تیم های مختلف |
| **پشتیبان گیری دولتی** | باطن از راه دور به طور خودکار وضعیت نسخه. این را فعال نگه دارید |
| **هرگز حالت را به صورت دستی ویرایش نکنید** | به جای آن از `terraform state mv`، `rm`،`import`استفاده کنید |

## الگوهای رایج
| الگو | توضیحات |
|---------|-------------|
| **شمارش** | `count = 3`چندین نمونه از یک منبع را ایجاد می کند |
| **برای هر** | `for_each = var.items`روی نقشه یا مجموعه | تکرار می شود
| **بلوک های پویا** | ایجاد بلوک های تودرتوی مکرر (به عنوان مثال، قوانین ورود) |
| **مقادیر محلی** | `locals { ... }`برای مقادیر محاسبه شده و کاهش تکرار |
| **منابع داده** | خواندن زیرساخت های موجود (به عنوان مثال، یک VPC موجود را پیدا کنید) |
| **تامین کنندگان** | اجرای اسکریپت ها بر روی منابع پس از ایجاد (استفاده کم) |
| **فضای کاری** | حالت مجزا برای محیط های مختلف در یک پیکربندی |

## عیب یابی
| مشکل | راه حل |
|---------|----------|
| ** رانش ایالتی** |`terraform plan`را اجرا کنید تا تفاوت ها را ببینید. `terraform apply`برای آشتی دادن |
| **حالت قفل** | بررسی کنید که چه کسی قفل را دارد. در صورت امن بودن از`terraform force-unlock`استفاده کنید |
| **خطاهای ارائه دهنده** | بررسی اعتبار؛ نسخه ارائه دهنده به روز رسانی؛ بررسی محدودیت های API |
| **تضادهای واردات** | منبع در حال حاضر در حالت است. ابتدا از`terraform state rm`استفاده کنید |
| **وابستگی های دایره ای** | تجدید ساختار منابع؛ از`depends_on`با دقت استفاده کنید |
| **ایالت بزرگ** | تقسیم به ماژول. استفاده از`-target`برای عملیات جزئی |

## خلاصه
Terraform زیرساخت را از طریق فایل های پیکربندی اعلامی مدیریت می کند. گردش کار عبارت است از: نوشتن پیکربندی → init → plan → اعمال. State آنچه را که وجود دارد و باید از راه دور با قفل ذخیره شود، ردیابی می کند. ماژول ها استفاده مجدد را فعال می کنند. تنظیمات پارامترهای متغیرها اصول کلیدی عبارتند از: زیرساخت را به عنوان کد (کنترل نسخه، بررسی، تست) در نظر بگیرید. هرگز حالت را به صورت دستی ویرایش نکنید. قبل از درخواست برنامه ریزی کنید. استفاده از حالت از راه دور با قفل. و پیکربندی ساختار با ماژول ها برای نگهداری.
