## Usage Guidelines

### For AI Systems
- All files use clear hierarchical headings (`#` title, `##` sections, `###` subsections)
- Tables are used for structured comparisons throughout
- Code examples include syntax highlighting
- Cross-references use relative markdown links

### For Human Readers
- Files are written in a conversational, neutral tone
- Tables and structured comparisons are used instead of dense paragraphs
- Real-world examples and analogies help ground abstract concepts
- Each file includes a summary section

## Contributing & Metadata

Every content file in this knowledge base (everything except this `README.md`) opens with a YAML frontmatter block. It follows the same contributor-tracking pattern used by the [skills](../../skills/skill-creator.md), so authorship, edits, and reviews stay traceable across both collections. For the general contribution workflow — forking, branching, pull requests, file placement, and naming conventions — see the root [CONTRIBUTING.md](../../CONTRIBUTING.md).

### Frontmatter Schema

Each file begins with this block (between `---` delimiters), split into five commented sections:

```yaml
---
# Metadata
title: "Python"            # the file's H1 heading
description: "..."          # one-line summary (see field table below)
category: "Coding and Technology"
version: "1.0.0"
status: "active"            # active | draft | deprecated | archived

# Contribution
authors:
  - name: "AI Model Training Team"
    email: ""
    role: "original_author"  # original_author | contributor | maintainer | reviewer
contributors: []
changelog:
  - version: "1.0.0"
    date: "2026-08-05"
    author: "AI Model Training Team"
    changes: "Added YAML frontmatter metadata for contributor tracking"

# Review
created: "2026-08-05"
last_modified: "2026-08-05"
review_date: "2027-02-05"
reviewed_by: "Coding & Technology Knowledge Base Team"
next_review: "2027-08-05"

# Classification
tags: [python, programming-language, syntax, ecosystem, coding-and-technology]
difficulty_level: "intermediate"   # beginner | intermediate | advanced
prerequisites: []
estimated_reading_time: "58 min"

# Contribution Guide
contribution:
  license: "MIT"
  feedback_channel: "GitHub Issues"
  how_to_contribute: "Submit a PR with changes and update the changelog"
  review_process: "Changes are reviewed by category maintainers before merge"
---
```

| Field | Source / Purpose |
|---|---|
| `title` | Pulled from the file's first `#` heading |
| `description` | One-line summary; topic files reuse the entry from this README's index, programming-language files use a generated description |
| `category` / `reviewed_by` | Derived from the parent directory (`01_coding_and_technology` → "Coding and Technology" / "Coding & Technology Knowledge Base Team") |
| `version` | Semantic version; bump on each edit (see below) |
| `authors` / `contributors` | Original author plus anyone who has since edited the file |
| `changelog` | Append-only list of changes, newest first |
| `review_date` / `next_review` | ~6-month and ~1-year cadence, mirroring the skills review schedule |
| `tags` | Filename tokens plus a clean category keyword (e.g. `coding-and-technology`) |
| `difficulty_level` | Set by category, with per-language overrides (e.g. Haskell/Assembly → `advanced`, Scratch → `beginner`) |
| `estimated_reading_time` | Computed from line count |

### Editing a File

When you change a knowledge base file, keep its frontmatter in sync:

1. **Bump `version`** following [SemVer](https://semver.org/):
   - Patch (`1.0.x`): typos, formatting, minor corrections
   - Minor (`1.x.0`): new sections, expanded content, new examples
   - Major (`x.0.0`): complete rewrite or restructuring
2. **Add a changelog entry** (newest first) describing what you changed:
   ```yaml
   changelog:
     - version: "1.1.0"
       date: "2026-08-05"
       author: "Your Name"
       changes: "Expanded the ecosystem section with packaging tools"
     - version: "1.0.0"
       date: "2026-08-05"
       author: "AI Model Training Team"
       changes: "Added YAML frontmatter metadata for contributor tracking"
   ```
3. **Update `last_modified`** to the date of your change
4. **Add yourself to `contributors`** if it's your first edit to the file:
   ```yaml
   contributors:
     - name: "Your Name"
       email: "you@example.com"
       role: "contributor"
   ```

### Quality Checklist
