# 데이터 시각화
잘 디자인된 차트는 숫자표가 숨기고 있는 패턴을 드러낼 수 있습니다. 제대로 설계되지 않은 제품은 오해를 불러일으키거나 혼란을 주거나 지루할 수 있습니다. 데이터 시각화는 데이터를 결정을 알리는 시각적 스토리로 바꾸는 기술입니다. 이 파일에는 차트 선택, 디자인 원칙, 일반적인 실수 및 이를 가능하게 하는 도구가 포함되어 있습니다.
---

## 올바른 차트 선택
시각화에서 가장 중요한 결정은 데이터와 메시지에 적합한 차트 유형을 선택하는 것입니다.
### 차트 선택 가이드
| 당신의 목표 | 최고의 차트 유형 |
|------------|----|
| **카테고리 비교** | 막대 차트, 그룹화된 막대 차트 |
| **시간에 따른 변화 표시** | 꺾은선형 차트, 영역형 차트 |
| **배포 표시** | 히스토그램, 박스 플롯, 바이올린 플롯 |
| **관계 표시** | 산점도, 버블 차트 |
| **구성 표시** | 누적 막대, 원형 차트(제한된 조각), 트리맵 |
| **상관관계 표시** | 산점도, 히트맵, 쌍 도표 |
| **순위 표시** | 수평 막대 차트 |
| **지리적 패턴 표시** | 등치도, 도트 맵 |
| **시간 경과에 따른 부분에서 전체 표시** | 누적 영역형 차트 |
### 각 차트를 사용하는 경우
| 차트 | 강점 | 피해야 할 때 |
|-------|------------|------------|
| **바** | 카테고리 전반에 걸친 명확한 비교 | 카테고리가 너무 많습니다(>15) |
| **라인** | 시간 경과에 따른 추세 연속 데이터 | 데이터가 순차적이지 않습니다 |
| **분산** | 두 변수 사이의 관계 | 겹치는 점이 너무 많습니다 |
| **히스토그램** | 하나의 변수의 분포 형태 | 작은 샘플 크기(<20) |
| **Box plot** | Summary statistics + outliers; compare distributions | Audience unfamiliar with them |
| **Heatmap** | Correlation matrices; patterns in 2D data | Too many variables |
| **Pie chart** | Simple composition (2–5 slices) | More than 5 slices; precise comparisons needed |
| **Violin plot** | Distribution density + quartiles | Small audiences unfamiliar with them |
| **Pair plot** | Quick overview of all variable relationships | Many variables (>8) |

## 디자인 원칙
### Tufte의 핵심 아이디어
Edward Tufte의 원칙은 데이터 시각화의 표준으로 남아 있습니다.
| 원리 | 설명 |
|------------|-------------|
| **데이터-잉크 비율 극대화** | 모든 잉크 방울은 데이터를 전달해야 합니다. 다른 모든 것을 제거하십시오. |
| **차트 정크 제거** | 3D 효과, 불필요한 그라데이션 또는 장식 요소가 없습니다. |
| **데이터 표시** | 왜곡하거나 숨기거나 선별하지 마세요. 데이터가 말하게 하세요. |
| **작은 배수** | 카테고리 간 비교를 위해 반복되는 작은 차트를 사용하세요. |
| **스파크라인** | 인라인 추세 데이터를 위한 작은 단어 크기의 차트입니다. |
### 실용적인 설계 규칙
| 규칙 | 왜 |
|------|-----|
| **Y축을 0에서 시작**(막대형 차트의 경우) | 그렇지 않으면 차이점을 과장합니다 |
| **직접 라벨링** | 가능하다면 범례를 사용하는 대신 선/막대에 라벨을 붙이세요 |
| **의도적으로 색상을 사용하세요** | 중요한 것을 강조하세요. 컨텍스트에 회색을 사용 |
| **간단하게 유지하세요** | 차트당 하나의 메시지; 과부하하지 마십시오 |
| **일관적인 척도 사용** | 차트를 비교할 때 축을 동일하게 유지 |
| **의미있게 주문하세요** | 자연 순서가 아닌 한 값을 기준으로 막대 정렬(알파벳순 아님) |
| **컨텍스트 제공** | 벤치마크, 목표 또는 과거 평균 추가 |
### 색상 지침
| 사용 사례 | 접근 |
|------------|----------|
| **범주형** | 뚜렷한 색상(파란색, 주황색, 녹색, 빨간색) — 최대 7~8개 카테고리 |
| **순차** | 한 색상의 연한 색부터 어두운 색까지(하늘색 → 진한 파란색) |
| **다양함** | 의미 있는 중간점을 갖는 데이터에 대한 2색 그라데이션(빨간색 ← 흰색 → 파란색) |
| **접근성** | 색맹 시뮬레이터로 테스트하세요. 색상에만 의존하지 마세요(레이블이나 패턴 추가) |

## 데이터로 스토리텔링하기
설명이 없는 차트는 그림일 뿐이다. 스토리텔링은 데이터를 통찰력으로 바꿔줍니다.
### 스토리텔링 프레임워크
1. **컨텍스트**: 상황은 어떻습니까? 청중은 이미 무엇을 알고 있는가?
2. **갈등**: 데이터의 문제점, 놀라움 또는 긴장감은 무엇입니까?
3. **해결 방법**: 청중은 이 통찰력을 바탕으로 무엇을 해야 합니까?
### 실용적인 팁
| 팁 | 설명 |
|------|-------------|
| **통찰력을 바탕으로 이끌어라** | 데이터가 아닌 시사점으로 차트 제목을 지정하십시오("분기별 수익"이 아닌 "수익 30% 증가") |
| **주요 사항에 주석 달기** | 중요한 이벤트나 전환점에 대한 텍스트 설명선 추가 |
| **점진적 공개 사용** | 한 번에 하나의 차트를 표시합니다. 단계별로 스토리 구축 |
| **중요한 점 강조** | 색상이나 크기를 사용하여 핵심 데이터 포인트에 주의를 집중시키세요 |
| **"그래서 뭐?"를 제공하세요** | 모든 차트는 질문에 답하거나 조치를 취해야 합니다 |

## 흔히 저지르는 실수
| 실수 | 왜 나쁜가요 | 수정 |
|---------|-------------|------|
| **잘린 y축** | 작은 차이를 과장함 | 막대 차트의 경우 0부터 시작 |
| **체리따기 시간대** | 트렌드에 대한 오해 | 전체 사용 가능한 범위 보기 |
| **색상이 너무 많습니다** | 보는 사람을 압도한다 | 5~7개로 제한됩니다. 컨텍스트에 회색을 사용 |
| **이중 y축** | 존재하지 않을 수 있는 상관관계를 암시합니다 | 두 개의 별도 차트 사용 |
| **3D 차트** | 비율을 왜곡 | 항상 2D 사용 |
| **10개 이상의 조각이 포함된 원형 차트** | 비교불가 | 대신 막대 차트를 사용하세요 |
| **라벨 누락** | 뷰어가 차트를 이해할 수 없음 | 항상 축, 제목 및 단위에 레이블을 지정합니다. |
| **오해의 소지가 있는 영역 차트** | 누적된 영역으로 인해 개별 계열에 대한 인식이 왜곡됨 | 꺾은선형 차트 또는 작은 배수 사용 |

## 대시보드 디자인
대시보드는 프로세스, 시스템 또는 비즈니스에 대한 완전한 스토리를 함께 전달하는 시각화 모음입니다.
### 대시보드 유형
| 유형 | 관객 | 목적 |
|------|----------|---------|
| **전략적** | 임원 | 높은 수준의 KPI 장기 동향 |
| **작동** | 관리자 | 실시간 모니터링; 일일 운영 |
| **분석** | 분석가 | 깊은 탐구; 필터링, 드릴다운 |
### 디자인 체크리스트
- **청중을 파악하세요**: 그들이 이 대시보드에서 어떤 결정을 내릴까요?
- **5초 규칙**: 주요 내용을 5초 안에 파악할 수 있나요?
- **레이아웃**: 가장 중요한 측정항목은 왼쪽 상단(눈이 먼저 가는 곳)입니다.
- **차트 유형 제한**: 일관성을 위해 대시보드당 최대 3~4개 유형입니다.
- **기본적으로 대화형**: 필터, 날짜 범위 선택기, 드릴다운.
- **성능**: 로드하는 데 5초 이상 걸리는 대시보드는 사용되지 않습니다.
- **모바일**: 사용자가 이동 중에 필요한 경우 반응형 디자인을 고려하세요.

## 요약
좋은 데이터 시각화는 명확성, 정직성, 영향력에 관한 것입니다. 데이터에 적합한 차트를 선택하세요. 메시지를 제공하지 않는 모든 것을 제거하십시오. 색상과 주석을 사용하여 시청자를 안내하세요. 그리고 항상 데이터가 이야기를 전달하도록 하십시오. 그 반대가 아닙니다.
