# 글쓰기와 의사소통의 기초
글쓰기와 의사소통은 이메일, 보고서, 문서, 프레젠테이션, 대화 등을 통해 아이디어를 명확하고 효과적으로 전달하는 기술입니다. 대부분의 지식 작업은 기본적으로 커뮤니케이션 작업입니다. 자신의 생각을 설명하고, 다른 사람을 설득하고, 결정을 문서화하고, 사양을 작성하고, 결과를 제시하고, 팀 간 협업을 수행해야 합니다. 당신이 의미하는 것과 누군가가 이해하는 것 사이의 격차는 대부분의 문제가 발생하는 곳에서 발생하며, 더 나은 의사소통은 그 격차를 줄여줍니다.
---

## 명확한 글쓰기의 원칙
### 핵심 원칙
| 원리 | 설명 | 예 |
|------------|-------------|---------|
| **명확성** | 무슨 뜻인지 정확히 말해보세요. 모호함을 피하다 | "시스템이 곧 다시 시작됩니다."가 아니라 "시스템이 오후 3시 UTC에 다시 시작됩니다." |
| **간결함** | 필요한 최소한의 단어를 사용하십시오 | "우리는 해야 합니다" → 필요한 것이 무엇인지만 명시 |
| **구체성** | 모호한 언어가 아닌 구체적인 세부사항을 사용하세요 | "수익이 크게 증가했다"가 아닌 "3분기 매출 15% 증가" |
| **능동태** | 주체가 작업을 수행합니다 | "기능이 배송되었습니다"가 아니라 "팀이 기능을 배송했습니다" |
| **문장당 하나의 아이디어** | 문장을 너무 많이 쓰지 마세요 | 길고 복잡한 문장을 짧은 문장으로 나누기 |
| **병렬 구조** | 목록의 항목에 대해 동일한 문법 형식 사용 | '달리기, 수영, 자전거 타기'가 아닌 '달리기, 수영, 자전거 타기' |
| **청중 인지도** | 자신이 아닌 독자를 위해 글을 쓰세요 | 엔지니어를 위한 기술 문서 경영진을 위한 요약 |
### 일반적인 글쓰기 문제
| 문제 | 설명 | 수정 |
|---------|-------------|------|
| **명칭화** | 동사를 명사로 바꾸기(산문을 무디게 함) | "우리가 결정했다"가 아닌 "우리가 결정했다" |
| **헤징** | 불필요하게 메시지를 약화시키는 것 | "이것이 암시한다" → "이것이 보인다" (증거가 있는 경우) |
| **전문 용어 과부하** | 기술에 익숙하지 않은 독자에게 기술 용어 사용하기 | 용어를 설명하십시오. 비유를 사용 |
| **족제비 단어** | 의미를 훼손하는 모호한 한정자 | "매우", "매우", "다소", "아마도" 제거 |
| **매장된 납** | 요점 숨기기 | 가장 중요한 정보를 먼저 입력하세요 |
| **정원길 문장** | 독자를 잘못된 해석으로 이끄는 문장 | 명확성을 위한 재구성 |

## 전문적인 글쓰기 유형
### 기술 문서
| 유형 | 목적 | 관객 | 주요 기능 |
|------|---------|----------|-------------|
| **읽어보기** | 프로젝트 개요 | 신규 사용자 기여자 | 빠른 시작; 그것이 무엇을 하는가; 설치 방법 |
| **API 문서** | API를 사용하는 방법 | 개발자 | 엔드포인트; 매개변수; 예; 오류 코드 |
| **아키텍처 결정 기록(ADR)** | 결정이 내려진 이유를 문서화하기 | 미래의 개발자; 이해관계자 | 문맥; 결정; 결과 |
| **런북/플레이북** | 단계별 운영절차 | 운영팀 | 정확한 명령; 예상 출력; 롤백 단계 |
| **RFC(의견 요청)** | 변경을 제안합니다. 피드백 요청 | 팀; 이해관계자 | 문제; 제안; 대안; 절충안 |
| **사후부검** | 해결 후 사건 분석 | 팀; 관리 | 타임라인; 근본 원인; 조치 항목 |
### 비즈니스 글쓰기
| 유형 | 목적 | 주요 기능 |
|------|---------|-------------|
| **이메일** | 동료, 고객과 소통 | 제목을 명확하게 하세요. 이메일당 하나의 요청; 행동 촉구 |
| **신고** | 연구 결과 또는 분석 발표 | 요약; 구조화된 섹션; 데이터 시각화 |
| **제안** | 누군가를 설득하여 무언가를 승인하거나 자금을 지원하도록 | 문제; 해결책; 이익; 비용; 타임라인 |
| **회의록** | 결정사항 및 조치사항 기록 | 결정이 내려졌습니다. 누가 무엇을 하는가? 언제까지 |
| **상태 업데이트** | 진행상황 전달 | 무슨 일이 일어났는가? 다음은 무엇입니까? 차단제 |

## 구조화 정보
### 피라미드 원리(바바라 민토)
| 레벨 | 설명 |
|-------|-------------|
| **결론/권고** | 답변부터 시작 |
| **주요 주장** | 결론을 뒷받침하는 3~4가지 이유 |
| **증거 입증** | 각 주장에 대한 데이터, 예시, 분석 |
**작동 이유**: 바쁜 독자들은 먼저 답을 원하고 그 다음 추론을 원합니다. 첫 번째 문단만 읽으면 요점을 알 수 있습니다.
### 역피라미드(저널리즘)
| 레벨 | 설명 |
|-------|-------------|
| **리드** | 가장 중요한 정보(누가, 무엇을, 언제, 어디서, 왜) |
| **몸** | 중요한 세부정보 문맥; 따옴표 |
| **꼬리** | 배경; 덜 중요한 정보 |
### SCQA 프레임워크
| 요소 | 설명 | 예 |
|---------|-------------|---------|
| **상황** | 현재 상태 | "우리 애플리케이션은 초당 10,000개의 요청을 처리합니다." |
| **복잡성** | 문제 또는 변화 | "트래픽이 매달 30%씩 증가하고 있습니다" |
| **질문** | 우리는 무엇을 해야 합니까? | "10배의 트래픽을 어떻게 처리하나요?" |
| **답변** | 추천 | "자동 확장을 통해 마이크로서비스 아키텍처로 마이그레이션" |

## 프레젠테이션
### 프리젠테이션 구조
| 섹션 | 목적 | 시간배분 |
|---------|---------|----|
| **훅** | 관심을 끌기; 문제를 진술 | 10% |
| **컨텍스트** | 이것이 왜 중요한가? 배경 | 15% |
| **주요 내용** | 증거가 있는 3가지 핵심 사항 | 60% |
| **결론** | 요약; 행동 촉구 | 10% |
| **Q&A** | 주소 질문 | 5% |
### 슬라이드 디자인 원칙
| 원리 | 설명 |
|------------|-------------|
| **슬라이드당 하나의 아이디어** | 각 슬라이드는 단일 지점을 전달합니다 |
| **최소 텍스트** | 슬라이드는 스피커를 지원합니다. 프레젠테이션이 아니야 |
| **말보다는 시각적** | 가능하면 글머리 기호 대신 다이어그램, 차트, 이미지를 사용하십시오 |
| **일관된 디자인** | 전체적으로 동일한 글꼴, 색상, 레이아웃 |
| **읽을 수 있음** | 텍스트가 충분히 큽니다. 충분한 대비 |
| **데이터 시각화** | 단순한 데이터가 아닌 통찰력을 보여주세요 |
### 질문 처리
| 상황 | 전략 |
|------------|----------|
| **당신은 답을 알고 있습니다** | 간결하게 대답하세요. 증거 제공 |
| **당신은 모른다** | "좋은 질문이네요. 정확한 데이터는 없지만 후속 조치를 취하겠습니다." |
| **적대적인 질문** | 우려 사항을 인정합니다. 물질을 다루십시오. 방어적인 자세를 취하지 마세요 |
| **불명확한 질문** | "이해했는지 확인하겠습니다. X 또는 Y에 대해 묻는 겁니까?" |
| **주제에서 벗어난 질문** | "그것은 중요하지만 이 논의의 범위를 벗어납니다. 오프라인으로 가져가겠습니다." |

## 설득과 영향력
### 아리스토텔레스의 수사학적 호소
| 항소 | 설명 | 사용방법 |
|---------|-------------|----------|
| **로고**(논리) | 이유와 증거 | 데이터; 논리적인 주장; 사례 연구 |
| **파토스**(감정) | 정서적 연결 | 이야기; 생생한 예; 공유가치 |
| **에토스**(신뢰성) | 신뢰와 권위 | 전문적 지식; 실적; 참고자료; 정직 |
### 치알디니의 설득원칙
| 원리 | 설명 | 신청 |
|------------|-------------|-------------|
| **상호주의** | 사람들은 호의를 보답합니다 | 유용한 정보를 먼저 공유하세요 |
| **헌신과 일관성** | 사람들은 약속을 존중합니다 | 작은 계약부터 먼저 맺으세요 |
| **사회적 증명** | 사람들은 다른 사람들을 팔로우합니다 | 동료들이 이미 하고 있음을 보여주기 |
| **권한** | 사람들은 전문가를 따른다 | 자격 증명을 인용하십시오. 참고 연구 |
| **좋아요** | 사람들은 자신이 좋아하는 사람에게 '예'라고 말합니다 | 공통점을 찾으세요. 진실하다 |
| **희소성** | 사람들은 희귀한 것을 소중히 여깁니다 | 고유한 이점을 강조합니다. 시간 제한 |

## 다문화 커뮤니케이션
| 차원 | 설명 | 커뮤니케이션에 미치는 영향 |
|------------|-------------|-----------|
| **고맥락 vs 저맥락** | 높음: 의미가 함축되어 있습니다. 낮음: 의미가 명시적임 | 고맥락 문화(일본, 아랍)는 독자가 추론하기를 기대합니다. 저맥락(미국, 독일)은 명시된 모든 것을 예상합니다 |
| **직접 vs 간접** | 의견 불일치나 나쁜 소식이 어떻게 직접적으로 전달되는지 | 직접(네덜란드, 이스라엘) vs 간접(일본, 태국) |
| **형식** | 의사소통의 격식 수준 | 공식(독일, 일본) vs 비공식(호주, 미국) |
| **시간 방향** | 단시간성(시간 엄수) vs 다시성(유연함) | 기대치 충족 및 마감일에 영향을 미침 |
| **전력 거리** | 계층 구조가 통신에 미치는 영향 | 높은 권력 거리: 후배들은 선배들에게 공개적으로 도전하지 않는다 |

## 요약
명확한 글쓰기와 의사소통은 영리해지는 것이 아니라 이해받는 것입니다. 주요 요점(피라미드 원리)부터 시작하세요. 능동태, 구체적인 언어, 짧은 문장을 사용하세요. 독자가 필요한 것을 찾을 수 있도록 정보를 구조화하세요. 기술 문서는 스캔 가능하고 예제 중심이어야 합니다. 비즈니스 글쓰기는 추천으로 이어져야 합니다. 프레젠테이션은 슬라이드당 하나의 아이디어로 스토리를 전달해야 합니다. 설득은 논리(로고스), 감정(파토스), 신뢰성(에토스)을 결합합니다. 문화 간 인식은 글로벌 팀의 오해를 방지합니다. 근본적인 기술은 청중 인식입니다. 즉, 누구를 위해 글을 쓰고 있는지, 그들이 무엇을 알아야 하는지, 어떤 형식이 청중이 그것을 이해하는 데 도움이 될지 아는 것입니다. 보다 명확한 의사소통에 투자하는 매분마다 혼란이 줄어들고, 오해가 줄어들고, 의사결정이 빨라지는 등 시간이 여러 배로 절약됩니다.
