# 관리 및 프로젝트 방법론
사람과 프로젝트를 관리하는 것은 모든 조직에서 가장 까다로운 책임 중 하나입니다. 기술적인 능력은 진입을 제공하지만 팀을 이끌고, 결정을 내리고, 효과적으로 의사소통하고, 결과를 전달하는 능력은 목표 달성 여부를 결정합니다. 이 파일은 효과적인 관리자와 프로젝트 리더가 적용하는 프레임워크, 방법론 및 실무 기술을 다룹니다.

## 리더십 스타일
리드하는 데 단 하나의 "올바른" 방법은 없습니다. 최고의 스타일은 팀, 작업, 상황에 따라 다릅니다.
| 스타일 | 설명 | 가장 좋은 때는 | 위험 |
|-------|-------------|----------|------|
| **독재** | 리더는 최소한의 입력으로 결정을 내립니다 | 위기; 경험이 부족한 팀; 시간 압박 | 낮은 사기; 리더에 대한 의존성 |
| **민주적** | 리더는 의견을 요청합니다. 팀은 실질적인 영향력을 갖고 있습니다 | 숙련된 팀; 동의가 필요한 복잡한 결정 | 더 느린 결정; 밋밋함을 느낄 수 있다 |
| **자유방임** | 리더는 방향을 제시합니다. 팀이 자체 관리 | 고도로 숙련되고 자발적인 전문가 | 조정 부족; 불분명한 책임 |
| **변혁적** | 리더는 비전과 개인적 성장을 고취합니다 | 변화 이니셔티브 고성과 문화 구축 | 실행에 근거하지 않으면 소진될 수 있음 |
| **서번트 리더십** | 리더는 팀의 요구와 개발을 우선시합니다 | 지식 근로자; 신뢰와 충성도 구축 | 계층적 문화에서는 약하다고 인식될 수 있음 |
| **상황에 따른** | 리더는 팀 성숙도와 업무에 맞춰 스타일을 조정합니다 | 대부분의 실제 상황 | 높은 감성지능이 필요함 |
### 훌륭한 관리자가 실제로 하는 일
연구(특히 Google의 Project Oxygen)에서는 효과적인 관리자의 주요 행동을 확인했습니다.
1. **훌륭한 코치입니다** — 질문을 하고, 사람들의 생각을 돕습니다. 단지 답변만 제공하는 것이 아닙니다.
2. **팀 역량 강화** — 의미 있는 위임; 세세하게 관리하지 않음
3. **포용적인 환경 조성** — 심리적 안전; 누구나 기여할 수 있다
4. **생산적이고 결과 지향적입니다** — 팀이 중요한 일에 집중할 수 있도록 해줍니다.
5. **좋은 의사소통 능력** — 경청하고, 상황을 공유하고, 명확한 방향을 제시합니다.
6. **경력 개발 지원** - 업무뿐만 아니라 성장에 대해서도 이야기합니다.
7. **명확한 비전과 전략이 있습니다** - 팀이 어디로 가고 있는지, 왜 가는지 알고 있습니다.
8. **핵심 기술 보유** - 작업을 조언하고 이해할 수 있습니다(작업을 수행하지 않더라도).

## 프로젝트 관리 방법론
### 전통(폭포)
| 단계 | 활동 |
|-------|------------|
| **요구사항** | 구축해야 할 사항을 수집하고 문서화 |
| **디자인** | 아키텍처, 사양, 계획 |
| **구현** | 물건 만들기 |
| **테스트** | 지정된 대로 작동하는지 확인 |
| **배포** | 프로덕션/사용자에게 릴리스 |
| **유지보수** | 문제를 해결하세요. 지속적인 지원 |
**최적의 용도**: 요구 사항이 고정되어 있고 변경 비용이 많이 드는 건설, 제조, 규제 산업.
### 애자일
애자일은 방법론이 아니라 사고방식입니다. [Agile Manifesto](https://agilemanifesto.org/)(2001)에서 가져온 것입니다.
> 프로세스 및 도구에 대한 *개인 및 상호 작용*
> 포괄적인 문서에 대한 *작업 소프트웨어*
> *계약 협상을 통한 고객 협업*
> *계획을 따르는 것보다 변화에 대응*
| 민첩한 원칙 | 실제로 의미하는 것 |
|---|-------------|
| 작동하는 소프트웨어를 자주 제공 | 단기 반복(1~4주) |
| 변화하는 요구 사항을 환영합니다 | 개발이 늦어도 |
| 비즈니스와 개발자가 함께 작업 | 시작과 끝뿐만 아니라 일상적인 협업 |
| 동기 부여된 개인을 중심으로 프로젝트 구축 | 그들에게 필요한 환경과 신뢰를 제공하세요 |
| 대면대화 | 정보를 전달하는 가장 효율적인 방법 |
| 작동하는 소프트웨어는 발전의 주요 척도입니다 | 문서도 아니고 계획도 아니고 |
| 지속 가능한 속도 | 무기한; 죽음의 행진은 없다 |
| 기술적 우수성에 대한 지속적인 관심 | 좋은 디자인과 깔끔한 ​​코드 |
| 단순성 | 완료되지 않은 작업을 최대화 |
| 자체 조직 팀 | 최고의 아키텍처와 디자인이 그로부터 탄생합니다 |
| 정기적인 반영 및 조정 | 회고전; 지속적인 개선 |
### 스크럼
스크럼은 가장 널리 사용되는 Agile 프레임워크입니다.
| 요소 | 설명 |
|---------|-------------|
| **스프린트** | 고정 길이 반복(보통 2주) |
| **제품 소유자** | 백로그를 정의하고 우선순위를 지정합니다. 이해관계자를 대표합니다 |
| **스크럼 마스터** | 프로세스를 촉진합니다. 장애물을 제거합니다. 팀을 보호합니다 |
| **개발팀** | 다기능, 자기 조직화(5~9명이 이상적) |
| **제품 백로그** | 필요할 수 있는 모든 항목의 우선순위 목록 |
| **스프린트 백로그** | 현재 스프린트에 선택된 항목 + 전달 계획 |
| **데일리 스탠드업** | 15분 동기화: 내가 무슨 짓을 한 걸까? 나는 무엇을 할 것인가? 차단제가 있나요? |
| **스프린트 리뷰** | 이해관계자에게 작동하는 소프트웨어를 시연합니다. 피드백 수집 |
| **스프린트 회고** | 팀은 프로세스 개선 방법을 반영합니다 |
### 칸반
Kanban은 작업을 시각화하고 진행 중인 작업을 제한하는 데 초점을 맞춘 흐름 기반 방법입니다.
| 연습 | 설명 |
|----------|-------------|
| **워크플로 시각화** | 컬럼이 있는 게시판(할 일 → 진행 중 → 검토 → 완료) |
| **WIP 한도** | 각 열의 최대 항목 수 설정 |
| **흐름 관리** | 사이클 시간을 측정합니다. 병목 현상 식별 및 제거 |
| **정책을 명시적으로 작성** | 각 열의 "완료"가 의미하는 바에 대해 모두가 동의합니다 |
| **공동으로 개선** | 데이터와 피드백을 사용하여 프로세스 발전 |
**스크럼 대 칸반**:
| | 스크럼 | 칸반 |
|---|-------|---------|
| **케이던스** | 고정 스프린트(2주) | 지속적인 흐름 |
| **역할** | PO, 스크럼 마스터, 팀 | 정해진 역할 없음 |
| **변경** | 스프린트 중간에는 변경 사항이 없습니다 | 언제든지 변경 |
| **측정항목** | 속도(스프린트당 스토리 포인트) | 사이클 타임, 처리량 |
| **최고의 대상** | 정기 출시를 통한 제품 개발 | 지원팀 지속적인 전달 |

## OKR 및 KPI
### OKR(목표 및 주요 결과)
OKR은 Google, Intel, Spotify 등이 사용하는 목표 설정 프레임워크입니다.
| 구성요소 | 설명 | 예 |
|------------|-------------|---------|
| **목표** | 질적, 야심적, 영감을 주는 | "중소기업 회계를 위한 최고의 플랫폼이 되자" |
| **주요 결과 1** | 측정 가능; 목표가 달성되고 있음을 증명합니다 | 월간 활성 사용자를 10,000명에서 50,000명으로 늘리기 |
| **주요 결과 2** | 측정 가능 | NPS 점수 60점 이상 달성 |
| **주요 결과 3** | 측정 가능 | 온보딩 시간을 30분에서 5분으로 단축 |
**OKR 모범 사례**:
- 분기당 목표를 3~5개 설정
- 각 목표에는 2~5개의 핵심 결과가 있습니다.
- 70% 달성을 목표로 하세요. (100%는 목표가 너무 쉬웠음을 의미합니다.)
- OKR은 성과평가와 별개입니다.
- 투명성: 모든 사람이 다른 사람의 OKR을 볼 수 있습니다.
### KPI(핵심성과지표)
| 카테고리 | KPI 예시 |
|----------|-------------|
| **재무** | 매출, 총마진, 순이익, EBITDA |
| **고객** | NPS, CSAT, 이탈률, CLV |
| **제품** | DAU/MAU, 기능 채택, 가치 실현 시간 |
| **엔지니어링** | 배포 빈도, 리드 타임, MTTR, 변경 실패율 |
| **마케팅** | CAC, ROAS, 전환율, 유기 트래픽 |
| **사람** | 직원 NPS, 유지율, 채용 시간 |

## 통신 프레임워크
| 프레임워크 | 구조 | 사용 시기 |
|------------|------------|-------------|
| **준비** | 요점 → 이유 → 예 → 요점 | 설득력 있는 의사소통; 회의 |
| **스타** | 상황 → 임무 → 행동 → 결과 | 인터뷰; 성과 리뷰 |
| **블루프** | 하단 라인 업 프론트 | 임원에게 이메일을 보냅니다. 상태 업데이트 |
| **SBAR** | 상황 → 배경 → 평가 → 권고사항 | 핸드오프; 사건통신 |
| **7C** | 명확함, 간결함, 구체적, 정확함, 일관됨, 완전함, 정중함 | 일반 서면 커뮤니케이션 |
### 피드백 제공
| 접근 | 설명 |
|----------|-------------|
| **SBI**(상황-행동-영향) | "어제 회의(상황)에서 당신이 클라이언트(행동)를 방해했고, 이로 인해 클라이언트가 종료되었습니다(영향)." |
| **피드포워드** | 과거의 실수가 아닌 미래의 행동에 초점을 맞추세요. "다음번에는..." |
| **급진적 솔직함** (킴 스콧) | 개인적으로 배려+직접 도전하세요. 너무 친절하지도 않고(파멸적인 공감), 너무 가혹하지도 않습니다(불쾌한 공격성). |

## 의사결정 모델
| 모델 | 설명 | 최고의 대상 |
|-------|-------------|----------|
| **빠른** | 추천, 동의, 수행, 입력, 결정 — 누가 무엇을 하는지 명확하게 합니다 | 많은 이해관계자의 복잡한 의사결정 |
| **레이시** | 책임 있음, 책임 있음, 상담 가능, 정보 제공 — 역할 명확성 | 프로젝트 작업 및 결과물 |
| **아이젠하워 매트릭스** | 긴급/중요 그리드 - 작업 우선 순위 지정 | 개인 생산성; 작업 분류 |
| **결정 매트릭스** | 가중치 기준에 따른 점수 옵션 | 대안 중에서 선택하기 |
| **OODA 루프** | 관찰 → 지향 → 결정 → 행동 — 신속한 결정 주기 | 경쟁 상황 사고대응 |
| **여섯 가지 생각 모자** | 6가지 관점(사실, 감정, 위험, 이점, 창의성, 프로세스)에서 의사결정 보기 | 그룹 결정; 집단사고 피하기 |
### 아이젠하워 매트릭스
| | 긴급 | 긴급하지 않음 |
|---|---------|------------|
| **중요** | **먼저 수행** — 위기, 기한, 중대한 문제 | **일정** — 전략 계획, 관계 구축, 학습 |
| **중요하지 않음** | **위임자** — 일부 이메일, 회의, 방해 | **제거** — 시간 낭비, 바쁜 업무, 과도한 탐색 |

## 위험 관리
| 단계 | 설명 |
|------|-------------|
| **1. 위험 식별** | 무엇이 잘못될 수 있는지 브레인스토밍(기술, 일정, 자원, 외부) |
| **2. 확률 및 영향 평가** | 각 위험 평가: 높음/보통/낮음 |
| **3. 우선순위** | 확률이 높고 영향력이 큰 위험에 집중 |
| **4. 대응 계획** | 각 위험을 방지, 완화, 이전 또는 수용 |

## 제품 관리 기초
제품 관리는 무엇을, 누구를 위해, 왜 구축할지 결정하고 그것이 가치를 제공하는지 확인하는 규율입니다.
| 책임 | 설명 |
|---------------|-------------|
| **발견** | 사용자 조사, 시장 분석, 경쟁 인텔리전스 |
| **전략** | 제품 비전, 로드맵, 우선순위 프레임워크 |
| **실행** | 사양/사용자 스토리 작성 엔지니어링 및 디자인 작업 |
| **출시** | 시장 진출 계획; 포지셔닝; 영업 활성화 |
| **반복** | 측정항목을 분석합니다. 피드백을 수집하고; 다음 개선 사항의 우선 순위 지정 |
### 우선순위 지정 프레임워크
| 프레임워크 | 작동 원리 |
|------------|-------------|
| **모스크바** | 있어야 한다 / 있어야 한다 / 가질 수 있었다 / 갖지 않을 것이다 |
| **쌀** | 도달범위 × 영향력 × 자신감 ¼ 노력 |
| **카노 모델** | 기능을 기본, 성능 또는 즐거움으로 분류 |
| **가치 vs 노력 매트릭스** | 2×2 그리드에 플롯합니다. 가치가 높고 노력이 적은 항목의 우선 순위 지정 |
| **기회 점수 부여** | 중요성에서 만족도를 뺀 것입니다. 소외된 요구사항 찾기 |

## 요약
경영은 다른 사람을 통해 목표를 달성하는 관행입니다. 효과적인 관리자는 명확한 사고(프레임워크, 방법론, 측정 기준)와 대인 관계 기술(경청, 공감, 신뢰)을 결합합니다. 좋은 판단을 대체하는 방법론은 없지만 건전한 프레임워크를 통해 좋은 판단이 향상됩니다. 이는 엄격한 교리보다는 실제적인 지침으로 적용되어야 합니다.
