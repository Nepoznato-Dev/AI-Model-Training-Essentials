# 데이터 구조 및 알고리즘
데이터 구조는 데이터를 효율적으로 작업할 수 있도록 메모리에 데이터를 구성하는 방식입니다. 알고리즘은 문제를 해결하기 위한 단계별 절차입니다. 이 둘은 함께 컴퓨터 과학의 기초를 형성합니다. 여러분이 사용해 본 모든 프로그램은 여기에 의존합니다. 올바른 데이터 구조를 선택하면 엄청나게 느린 프로그램을 빠른 프로그램으로 바꿀 수 있고, 올바른 알고리즘을 알면 해결 불가능한 문제를 사소한 문제로 바꿀 수 있습니다.
---

## 기본 데이터 구조
### 선형 구조
| 구조 | 액세스 | 검색 | 삽입 | 삭제 | 사용 사례 |
|------------|---------|---------|---------|---------|------------|
| **배열** | O(1) 인덱스별 | 오(n) | 오(n) | 오(n) | 고정 크기 컬렉션; 랜덤 액세스 |
| **연결된 목록** | 오(n) | 오(n) | O(1) 머리 | O(1) 머리 | 동적 크기; 삽입/삭제 |
| **스택** | 오(n) | 오(n) | O(1) 푸시/팝 | O(1) 팝 | 함수 호출; 끄르다; 파싱 ​​|
| **큐** | 오(n) | 오(n) | O(1) 대기열에 넣기 | O(1) 큐에서 제거 | 작업 스케줄링; BFS; 메시지 대기열 |
| **데크** | O(1) 양쪽 끝 | 오(n) | O(1) 양쪽 끝 | O(1) 양쪽 끝 | 슬라이딩 윈도우; 일을 훔치는 |
### 해시 기반 구조
| 구조 | 검색 | 삽입 | 삭제 | 사용 사례 |
|------------|---------|---------|---------|----------|
| **해시 테이블** | O(1) 평균 | O(1) 평균 | O(1) 평균 | 키-값 조회 캐시; 세트 |
| **해시 세트** | 오(1) | 오(1) | 오(1) | 회원 테스트; 중복 제거 |
**해시 충돌**: 두 개의 키가 동일한 슬롯에 해시되면 연결된 목록(체인) 또는 다음 사용 가능한 슬롯(공개 주소 지정)에 저장됩니다. 좋은 해시 함수는 충돌을 최소화합니다.
### 트리 구조
| 구조 | 검색 | 삽입 | 삭제 | 사용 사례 |
|------------|---------|---------|---------|----------|
| **이진 검색 트리** | O(log n) 평균 | O(로그 n) | O(로그 n) | 정렬된 데이터 범위 쿼리 |
| **AVL / 레드-블랙 트리** | O(log n) 보장 | O(로그 n) | O(로그 n) | 자체 균형 조정; 지도/세트에 사용됨 |
| **B-트리 / B+ 트리** | O(로그 n) | O(로그 n) | O(로그 n) | 데이터베이스 인덱스 파일 시스템 |
| **트리** | O(k) 여기서 k = 키 길이 | 오(k) | 오(k) | 자동완성; 접두사 일치 |
| **힙(바이너리)** | 오(n) | O(로그 n) | O(로그 n) | 우선순위 대기열; 일정 |
### 그래프 표현
| 대표 | 공간 | 가장자리 조회 | 가장자리 추가 | 이웃 반복 |
|---------------|-------|-------------|----------|------|
| **인접 행렬** | O(V²) | 오(1) | 오(1) | 오(V) |
| **인접 목록** | O(V + E) | O(학위) | 오(1) | O(학위) |
| **가장자리 목록** | O(E) | O(E) | 오(1) | O(E) |

## 알고리즘 복잡성(Big-O)
Big-O 표기법은 입력 크기가 증가함에 따라 알고리즘의 시간 또는 공간 요구 사항이 어떻게 증가하는지 설명합니다.
| 복잡성 | 이름 | 예 |
|------------|------|---------|
| **O(1)** | 상수 | 해시 테이블 조회; 인덱스로 배열 액세스 |
| **O(log n)** | 로그 | 바이너리 검색; 균형 트리 작업 |
| **O(n)** | 선형 | 선형 검색; 배열 반복 |
| **O(n log n)** | 선형 | 병합 정렬; 힙 정렬; 가장 효율적인 범용 정렬 |
| **O(n²)** | 이차 | 버블 정렬; 동일한 데이터에 대한 중첩 루프 |
| **O(2^n)** | 지수 | 무차별 하위 집합 생성 순진한 재귀 피보나치 |
| **오(안!)** | 팩토리얼 | 여행하는 세일즈맨(무차별 대입); 순열 |
### 일반적인 오해
| 오해 | 현실 |
|---------------|---------|
| "O(n)은 항상 O(n²)보다 빠릅니다." | 작은 n의 경우 상수 인자가 더 중요합니다 |
| "낮은 Big-O는 항상 더 좋습니다" | 시공간 상충관계가 존재합니다. O(1) 조회는 O(n) 메모리를 사용합니다 |
| "Big-O가 정확한 속도를 알려드립니다" | 절대 시간이 아닌 성장률을 설명합니다 |

## 정렬 알고리즘
| 알고리즘 | 최고 | 평균 | 최악의 | 공간 | 안정 | 현재 위치 |
|------------|------|---------|-------|-------|---------|----------|
| **버블정렬** | 오(n) | 오(n²) | 오(n²) | 오(1) | 예 | 예 |
| **삽입 정렬** | 오(n) | 오(n²) | 오(n²) | 오(1) | 예 | 예 |
| **선택 정렬** | 오(n²) | 오(n²) | 오(n²) | 오(1) | 아니요 | 예 |
| **병합 정렬** | O(n 로그 n) | O(n 로그 n) | O(n 로그 n) | 오(n) | 예 | 아니요 |
| **빠른 정렬** | O(n 로그 n) | O(n 로그 n) | 오(n²) | O(로그 n) | 아니요 | 예 |
| **힙 정렬** | O(n 로그 n) | O(n 로그 n) | O(n 로그 n) | 오(1) | 아니요 | 예 |
| **팀 소트** | 오(n) | O(n 로그 n) | O(n 로그 n) | 오(n) | 예 | 아니요 |
**실용적인 조언**: 언어에 내장된 정렬(Python의 `sorted()`, JavaScript의 `Array.sort()`)을 사용하세요. 그들은 모든 극단적인 경우를 처리하는 고도로 최적화된 알고리즘(Tim Sort, Introsort)을 사용합니다.

## 알고리즘 검색
| 알고리즘 | 데이터 구조 | 복잡성 | 요구사항 |
|------------|---------------|------------|------------|
| **선형 검색** | 모두 | 오(n) | 없음 |
| **이진 검색** | 정렬된 배열 | O(로그 n) | 데이터를 정렬해야 합니다 |
| **해시 테이블 조회** | 해시 테이블 | O(1) 평균 | 좋은 해시 함수 |
| **BFS**(너비 우선 검색) | 그래프/트리 | O(V + E) | 비가중 최단 경로 |
| **DFS**(깊이 우선 검색) | 그래프/트리 | O(V + E) | 경로 찾기; 사이클 감지 |
| **다익스트라** | 가중 그래프 | O((V + E) 로그 V) | 음수가 아닌 가중치; 최단 경로 |
| **아* ​​검색** | 가중 그래프 | O((V + E) 로그 V) | 경험적 안내; 허용 가능한 경험적 방법으로 최적 |

## 주요 알고리즘 패턴
| 패턴 | 설명 | 예제 문제 |
|---------|-------------|----|
| **분열과 정복** | 문제를 하위 문제로 분할합니다. 재귀적으로 해결합니다. 결합 | 병합 정렬; 퀵소트; 이진 검색 |
| **동적 프로그래밍** | 겹치는 하위 문제를 분석하세요. 캐시 결과 | 피보나치; 배낭; 가장 긴 공통 부분 수열 |
| **욕심** | 각 단계에서 지역적으로 최적의 선택 | 다익스트라; 허프만 코딩; 활동 선택 |
| **역추적** | 가능성을 시도해 보세요. 나쁜 선택을 취소하십시오. 대안을 시도해 보세요 | 스도쿠 해결사; N-여왕; 순열 |
| **슬라이딩 윈도우** | 요소 창을 유지합니다. 데이터 위로 슬라이드 | 크기 K의 최대 합계 하위 배열. 반복이 없는 가장 긴 부분 문자열 |
| **두 가지 지침** | 서로를 향해 또는 같은 방향으로 움직이는 두 개의 포인터 사용 | 정렬된 배열의 쌍 합계; 중복 제거 |
| **답변에 대한 이진 검색** | 답변 공간을 이진 검색 | 최소 페이지를 할당합니다. 공격적인 소 |

## 언제 무엇을 사용하는가
| 문제 | 데이터 구조 | 알고리즘 |
|---------|---------------|----------|
| 빠른 키-값 조회 | 해시 테이블/사전 | 해싱 |
| 정렬된 순서 유지 | 균형 잡힌 BST(TreeMap, std::set) | 트리 작업 |
| 우선순위 기반 처리 | 힙/우선순위 큐 | 힙 작업 |
| 최단 경로(가중치 없음) | 그래프(인접 목록) | BFS |
| 최단 경로(가중치) | 그래프(인접 목록) | 다익스트라의 / A* |
| 회원 테스트 | 해시 세트 / 블룸 필터 | 해싱 |
| 접두사 일치 | 트라이 | 트라이 순회 |
| 범위 쿼리 | 세그먼트 트리/펜윅 트리 | 트리 작업 |
| LRU 캐시 | 해시 맵 + 이중 연결 리스트 | 결합된 운영 |
| 연결된 구성요소 | 서로소 집합 합집합(Union-Find) | 결합 및 찾기 |

## 요약
데이터 구조와 알고리즘은 단순한 인터뷰 주제가 아니라 효율적인 소프트웨어의 구성 요소입니다. 배열과 해시 테이블은 대부분의 일상적인 요구를 처리합니다. 트리와 그래프는 계층적 및 관계형 데이터를 처리합니다. 정렬 및 검색은 표준 라이브러리의 문제를 해결합니다. 분할 정복, 동적 프로그래밍, 탐욕, 역추적 등의 알고리즘 패턴은 새로운 문제를 해결하기 위한 재사용 가능한 전략입니다. 핵심 기술은 알고리즘을 암기하는 것이 아닙니다. 주어진 문제에 맞는 패턴을 인식하고 작업에 적합한 데이터 구조를 선택하는 것입니다.
