# 클라우드 아키텍처
클라우드 컴퓨팅은 조직이 소프트웨어를 구축, 배포 및 확장하는 방식을 근본적으로 변화시켰습니다. 물리적 서버를 구입하고 유지 관리하는 대신 필요에 따라 컴퓨팅 리소스를 프로비저닝하고, 사용한 만큼만 비용을 지불하고, 몇 분 만에 전 세계적으로 확장할 수 있습니다. 이 파일은 알아야 할 핵심 개념, 아키텍처 패턴, 서비스 및 모범 사례를 다룹니다.
---

## 클라우드 컴퓨팅 기초
### 클라우드 컴퓨팅이란 무엇입니까?
종량제 가격으로 인터넷을 통해 컴퓨팅 리소스(서버, 스토리지, 데이터베이스, 네트워킹, 소프트웨어)를 주문형으로 제공합니다.
### NIST 필수 특성
| 특징 | 의미 |
|---------------|---------|
| **온디맨드 셀프 서비스** | 사람의 개입 없이 리소스 프로비저닝 |
| **광범위한 네트워크 액세스** | 표준 메커니즘을 통해 네트워크를 통해 사용 가능 |
| **리소스 풀링** | 다중 테넌트 모델 동적으로 할당된 자원 |
| **빠른 탄력성** | 외부 및 내부로 빠르게 확장 |
| **측정된 서비스** | 사용량이 모니터링되고 요금이 청구됩니다 |
### 배포 모델
| 모델 | 설명 | 사용 시기 |
|-------|-------------|------------|
| **퍼블릭 클라우드** | 공급자가 소유합니다. 공유 인프라(AWS, Azure, GCP) | 대부분의 워크로드 비용 효율적인 |
| **프라이빗 클라우드** | 단일 조직 전용 | 규제 요구 사항, 민감한 데이터 |
| **하이브리드 클라우드** | 공공과 민간의 결합 | 유연성 + 규정 준수 |
| **멀티 클라우드** | 여러 퍼블릭 클라우드 제공업체 사용 | 업계 최고의 공급업체 종속 방지 |
### 서비스 모델
| 모델 | 제공 | 예 | 사용 사례 |
|-------|----------|----------|-----------|
| **IaaS** | VM, 스토리지, 네트워크, OS | AWS EC2, Azure VM, GCP 컴퓨팅 엔진 | 리프트 앤 시프트 마이그레이션, 전체 제어 |
| **PaaS** | 개발 플랫폼, 데이터베이스, 미들웨어 | Heroku, Google App Engine, AWS Elastic Beanstalk | 앱 개발, API 배포 |
| **SaaS** | 인터넷을 통해 신청서 작성 | 세일즈포스, 구글 워크스페이스, 마이크로소프트 365 | 이메일, CRM, 협업 |
| **FaaS/서버리스** | 이벤트 기반 기능 실행 | AWS Lambda, Azure 함수, GCP 클라우드 함수 | API, 이벤트 처리, 예약된 작업 |

## 아키텍처 패턴
### Well-Architected 프레임워크
세 가지 주요 제공업체 모두 다음과 같은 5가지 원칙을 중심으로 구축된 잘 설계된 프레임워크를 게시합니다.
| 기둥 | 주요 원칙 |
|---------|---------------|
| **운영 우수성** | 운영 자동화 빈번하고 되돌릴 수 있는 변경을 수행합니다. 실패를 예상하다 |
| **보안** | 강력한 정체성 기반; 모든 계층에 보안을 적용합니다. 전송 중인 데이터와 저장 중인 데이터를 보호 |
| **신뢰성** | 테스트 복구 절차 실패로부터 자동 복구; 수평으로 확장 |
| **성능 효율성** | 서버리스를 사용하세요. 몇 분 만에 세계로 진출하세요. 자주 실험해 보세요 |
| **비용 최적화** | 소비 모델을 채택하십시오. 관리형 서비스 사용 획일적인 업무에 대한 지출을 중단하세요 |
### 일반적인 패턴
| 패턴 | 설명 | 혜택 | 도전과제 |
|---------|-------------|----------|------------|
| **마이크로서비스** | 앱을 작고 독립적인 서비스로 분해 | 확장성, 장애 격리, 독립적 배포 | 분산된 복잡성, 데이터 일관성 |
| **이벤트 중심** | 구성요소는 이벤트를 통해 통신합니다 | 느슨한 결합, 실시간 처리 | 디버깅 복잡성, 최종 일관성 |
| **서버리스** | 서버 관리가 없습니다. 실행당 지불 | 비용 효율성, 신속한 배포 | 콜드 스타트, 벤더 종속, 실행 제한 |
| **계층형(N계층)** | 프리젠테이션 → 비즈니스 로직 → 데이터 액세스 → 데이터베이스 | 우려사항 분리, 유지보수성 | 모놀리식으로 될 수 있음 |
| **우주 기반** | 가상화된 메모리 노드 전체에 데이터 분산 | 높은 동시성, 낮은 대기 시간 처리 | 설계 및 관리가 복잡함 |

## 핵심 서비스
### 컴퓨팅
| 서비스 유형 | 세부정보 |
|---------------|---------|
| **가상 머신** | 범용, 컴퓨팅 최적화, 메모리 최적화, GPU. 가격: 주문형, 예약, 현장. |
| **컨테이너** | 도커 런타임; Kubernetes(EKS, AKS, GKE)를 통한 오케스트레이션. 레지스트리: ECR, GCR, ACR. |
| **서버리스 기능** | 이벤트에 의해 트리거되고 상태가 없습니다. 실행 시간, 메모리, 동시성에 대한 제한. |
### 저장
| 유형 | 특징 | 예 | 최고의 대상 |
|------|---|----------|----------|
| **개체** | 평면 구조, HTTP 액세스, 풍부한 메타데이터 | S3, 클라우드 스토리지, Azure Blob | 정적 자산, 백업, 데이터 레이크 |
| **차단** | VM에 연결된 원시 볼륨 | EBS, 영구 디스크, Azure 디스크 | 데이터베이스, 부팅 볼륨 |
| **파일** | 공유 파일 시스템(NFS/SMB) | EFS, 파일 저장소, Azure 파일 | 콘텐츠 관리, 공유 구성 |
| **아카이브** | 최저 비용, 검색 지연 | S3 Glacier, Azure 아카이브 | 규정 준수, 장기 백업 |
### 데이터베이스
| 카테고리 | 서비스 | 사용 사례 |
|------------|------------|---------|
| **관리형 관계형** | RDS, 클라우드 SQL, Azure SQL | 기존 앱, ACID 거래 |
| **NoSQL — 문서** | DocumentDB, Firestore, 코스모스 DB | 유연한 스키마, JSON 데이터 |
| **NoSQL — 키-값** | DynamoDB, Redis 캐시 | 캐싱, 세션, 단순 조회 |
| **NoSQL — 넓은 열** | 빅테이블, 카산드라 | 쓰기가 많은 시계열 |
| **NoSQL — 그래프** | 넵튠, 코스모스 DB (그래프 API) | 관계, 소셜 네트워크 |
| **데이터 웨어하우징** | 눈송이, Redshift, BigQuery, 시냅스 | 분석, BI |
| **캐싱** | ElastiCache, 클라우드 메모리스토어 | 세션 저장, 쿼리 캐싱 |

## 네트워킹
### 가상 네트워크
모든 클라우드 배포는 CIDR 블록, 서브넷(퍼블릭 또는 프라이빗), 경로 테이블 및 게이트웨이로 정의하는 격리된 네트워크인 Virtual Private Cloud(VPC/VNet) 내에 있습니다.
### 로드 밸런싱 및 CDN
| 서비스 | 목적 |
|---------|---------|
| **로드 밸런서** | 인스턴스 간 트래픽 분산(L4 네트워크, L7 애플리케이션) |
| **CDN** | 지연 시간을 줄이기 위해 엣지 위치에 콘텐츠 캐시(CloudFront, Cloud CDN, Azure CDN) |
| **DNS** | 도메인 등록, 라우팅 정책, 상태 확인(Route 53, Cloud DNS, Azure DNS) |
### 연결 옵션
| 옵션 | 설명 |
|---------|-------------|
| **인터넷 게이트웨이** | VPC용 공용 인터넷 액세스 |
| **NAT 게이트웨이** | 프라이빗 서브넷 아웃바운드 액세스 |
| **VPN** | 온프레미스에 대한 암호화된 터널 |
| **직접 연결/ExpressRoute** | 전용 개인 연결 |
| **VPC 피어링** | 계정 내 또는 계정 간 VPC 연결 |

## 보안
### 공유 책임 모델
| 레이어 | 공급자 | 고객 |
|-------|----------|----------|
| **인프라**(하드웨어, 시설) | ✅ | |
| **컴퓨팅, 스토리지, 네트워킹** | ✅ (관리됨) | ✅ (자체 관리) |
| **데이터, 애플리케이션, ID** | | ✅ |
서비스를 더 많이 관리할수록 공급자가 더 많은 것을 처리합니다. IaaS를 사용하면 거의 모든 것을 관리할 수 있습니다. SaaS를 사용하면 공급자가 거의 모든 것을 처리합니다.
### ID 및 액세스 관리(IAM)
| 개념 | 설명 |
|---------|-------------|
| **사용자** | 개인의 정체성 |
| **그룹** | 사용자 컬렉션 |
| **역할** | 서비스 또는 사용자에 대한 임시 자격 증명 |
| **정책** | 권한을 정의하는 문서 |
| **원칙** | 최소 권한, 업무 분리 |
### 데이터 보호
- **미사용 암호화**: KMS, 고객 관리 키, HSM.
- **전송 중 암호화**: TLS/SSL, HTTPS.
- **비밀 관리**: Secrets Manager, Key Vault — 비밀을 하드코딩하지 않습니다.

## 비용 관리
### 가격 모델
| 모델 | 설명 | 최고의 대상 |
|-------|-------------|----------|
| **온디맨드** | 사용한 만큼만 초/시간 단위로 지불 | 가변적인 단기 작업량 |
| **예약 인스턴스** | 1~3년 약정, 상당한 할인 | 정상 상태 워크로드 |
| **스팟 인스턴스** | 미사용 용량에 대한 입찰 중단될 수 있습니다 | 내결함성, 유연한 작업 |
| **저축 계획** | 유연한 약정 가격 | 혼합된 사용 패턴 |
| **무료 등급** | 신규 계정의 무료 사용량 제한 | 학습, 프로토타이핑 |
### 최적화 전략
워크로드에 맞게 인스턴스 크기를 조정하세요. 수요 급증을 처리하려면 자동 크기 조정을 사용하세요. 예측 가능한 부하를 위한 용량을 예약하세요. 일괄 작업에는 스팟 인스턴스를 사용합니다. 자주 액세스하지 않는 데이터를 더 저렴한 스토리지 계층으로 이동하세요. 사용하지 않는 리소스(분리된 스냅샷, 유휴 로드 밸런서, 연결되지 않은 IP)를 삭제합니다.

## 고가용성 및 재해 복구
### 가용성 개념
| 개념 | 설명 |
|---------|-------------|
| **가용성 영역(AZ)** | 지역 내에서 물리적으로 분리된 데이터 센터 |
| **지역** | 여러 AZ가 있는 지리적 영역 |
| **엣지 위치** | 콘텐츠 전달을 위한 CDN 캐시 위치 |
### 재해 복구 전략
| 전략 | 비용 | RTO | RPO | 설명 |
|----------|------|------|------|-------------|
| **백업 및 복원** | 최저 | 영업시간 | 시간–일 | 정기적인 백업, 필요할 때 복원 |
| **파일럿 라이트** | 낮음 | 분~시간 | 분 | 핵심 요소는 항상 실행 중이며 재해 발생 시 확장 가능 |
| **따뜻한 대기** | 중간 | 분 | 초~분 | 축소 버전이 항상 실행 중 |
| **다중 사이트 활성/활성** | 최고 | 거의 0에 가까운 | 제로 | 여러 지역에서 전체 생산 |
**RTO**(복구 시간 목표) = 허용 가능한 최대 가동 중지 시간. **RPO**(복구 지점 목표) = 허용 가능한 최대 데이터 손실.
