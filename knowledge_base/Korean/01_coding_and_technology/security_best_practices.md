# 보안 모범 사례
개발부터 생산까지 애플리케이션, 인프라, 데이터 보안에 대한 실무 가이드입니다.
---

## OWASP 상위 10대(2021) — 개요
1. **깨진 액세스 제어**: 사용자가 액세스해서는 안 되는 리소스에 액세스할 수 있습니다.
2. **암호화 오류**: 암호화가 약하거나 누락되었습니다.
3. **삽입**: SQL, NoSQL, OS 명령 또는 LDAP 주입.
4. **안전하지 않은 디자인**: 구조적 결함.
5. **보안 구성 오류**: 기본 비밀번호, 열린 포트, 자세한 오류.
6. **취약하고 오래된 구성 요소**: 종속성으로 알려진 CVE.
7. **식별 및 인증 실패**: 취약한 비밀번호, 잘못된 세션 관리.
8. **소프트웨어 및 데이터 무결성 오류**: 공급망 공격, 서명되지 않은 업데이트.
9. **보안 로깅 및 모니터링 실패**: 침해가 감지되지 않습니다.
10. **서버측 요청 위조(SSRF)**: 서버를 악용하여 내부 시스템에 요청합니다.

## 입력 검증 및 출력 인코딩
### 유효성 검사 규칙
- **화이트리스트 > 블랙리스트**: 알려진 잘못된 패턴을 차단하는 대신 허용되는 패턴(예: 이메일 정규식)을 정의합니다.
- **길이 제한**: 버퍼 오버플로 및 DoS를 방지하기 위해 최대 길이를 적용합니다.
- **유형 확인**: 정수가 정수인지, 부울이 부울인지 확인하세요.
- **잘 테스트된 라이브러리 사용**: 이메일, URL 및 날짜 유효성 검사의 경우 표준 라이브러리(예: Python의 `email-validator`, Node의 `validator.js`)를 사용합니다.
### 출력 인코딩
- **HTML 인코딩**: XSS를 방지하려면`<`,`>`,`&`,`"`,`'`를 인코딩합니다.
- **SQL 매개변수화**: 사용자 입력을 SQL 쿼리에 연결하지 마세요. 매개변수화된 쿼리(준비된 문) 또는 ORM을 사용합니다.
- **셸 이스케이프**: 사용자 입력으로 셸 명령을 작성하지 마세요. 불가피한 경우`shlex.quote()`또는 이와 유사한 것을 사용하십시오.

## 인증 및 승인
### 비밀번호 관리
- **해싱**: 강력하고 느린 해싱 알고리즘(**Argon2id**(선호), **bcrypt**, **scrypt** 또는 **PBKDF2**)을 사용하여 비밀번호를 저장합니다.
- **솔팅**: 사용자별 고유한 솔트를 추가합니다.
- **최소 길이**: 최소 12~16자를 적용하세요.
- **MFA(Multi-Factor Authentication)**: 민감한 작업에는 두 번째 요소(TOTP, SMS, 하드웨어 키)가 필요합니다.
- **속도 제한**: 로그인 엔드포인트에 대한 무차별 대입 시도를 방지합니다(예: IP/사용자당 5분당 5회 시도).
### 세션 관리
- 세션 토큰에 안전한 HTTP 전용 SameSite 쿠키를 사용합니다.
- 적절한 만료 시간을 설정합니다.
- 로그아웃 및 비밀번호 변경 시 세션이 무효화됩니다.
- URL에 세션 ID가 노출되지 않도록 하세요.
### OAuth2 / OIDC
- 잘 확립된 라이브러리(예: Authlib, PyJWT, Passport.js, Spring Security)를 사용합니다.
- ID 토큰을 철저하게 검증합니다(서명, 발급자, 대상, 만료).
- CSRF를 방지하려면 상태 매개변수를 사용하세요.
- 고객의 비밀을 기밀로 유지하십시오.
### JWT(JSON 웹 토큰)
- **서명**: 보안 강화를 위해 RS256 또는 ES256(비대칭)을 사용합니다. 공유 비밀이 잘 관리된다면 HS256(대칭)이 허용됩니다.
- **검증**: 서명, 발급자(`iss`), 대상(`aud`) 및 만료(`exp`)를 항상 확인합니다.
- **짧은 만료 유지**: 액세스 토큰의 경우 15~60분; 더 긴 세션에는 새로 고침 토큰을 사용하세요.
- **안전하게 저장**: JWT를 localStorage에 저장하지 마세요(XSS에 취약함). 대신 HTTP 전용 쿠키를 사용하세요.

## API 보안
### 인증
- 항상 API 호출을 인증합니다(퍼블릭 엔드포인트 제외).
- 기본 인증(요청할 때마다 자격 증명 전송)보다 API 키나 OAuth2 토큰을 선호합니다.
### 속도 제한 및 조절
- 남용 및 DoS를 방지하기 위해 사용자별 및 IP별 속도 제한을 적용합니다.
-`Retry-After`헤더와 함께 `429 Too Many Requests`을 반환합니다.
### CORS(교차 출처 리소스 공유)
- 특정 출처만 허용합니다(프로덕션에서는 절대 `*`하지 않음).
- 서버 측에서`Origin`헤더의 유효성을 검사합니다.
### 입력 유효성 검사
- 헤더와 본문을 포함한 모든 요청 매개변수의 유효성을 검사합니다.
- 예상치 못한 필드(JSON 스키마의`"strict": true`또는 `additionalProperties: false`)를 거부합니다.
### HTTPS / TLS
- 프로덕션에 HTTPS를 적용합니다.
- HSTS(HTTP Strict Transport Security)를 사용하여 브라우저가 HTTPS를 사용하도록 합니다.
- TLS 1.2 또는 1.3을 사용합니다(TLS 1.0/1.1 비활성화).

## 비밀 관리
### 비밀을 하드코딩하지 마세요
- 소스 제어에 비밀(API 키, 비밀번호, 데이터베이스 URL)을 커밋하지 마세요.
- 환경 변수나 비밀 관리 도구를 사용하세요.
### 도구
| 도구 | 설명 |
|------|-------------|
| **HashiCorp 금고** | 엔터프라이즈급 동적 비밀 |
| **AWS Secrets Manager / Azure Key Vault / GCP Secret Manager** | 클라우드 네이티브 |
| **죄송합니다** | 파일의 비밀을 암호화하고 커밋(KMS 또는 GPG 사용) |
| **Docker 비밀** | Swarm 모드의 경우; Kubernetes 비밀(외부 Secret Store CSI 드라이버 고려) |
### 회전
- 보안 비밀과 서비스 계정을 정기적으로 교체합니다.
- 가능한 경우 회전을 자동화합니다.
---

## 종속성 관리
### 취약점 검색
| 언어/플랫폼 | 도구 |
|------|-------|
| **파이썬** | `safety`,`pip-audit`,`bandit`|
| **노드** | `npm audit`,`yarn audit`,`snyk`|
| **러스트** |  __보호_6__ |
| **가기** |  __보호_7__ |
| **일반** |  `Dependabot`(GitHub),`Renovate`,`Trivy`|
### 패치 중
- 패치 버전으로 종속성을 업데이트하세요.
- 마이너/패치 업데이트에 대한 자동 풀 요청을 설정합니다.
- 주요 변경 사항에 대한 변경 로그를 검토하세요.
### 공급망 무결성
- 재현 가능한 빌드를 보장하려면 패키지 잠금 파일(`package-lock.json`,`Cargo.lock`,`go.sum`)을 사용하세요.
- 다운로드된 종속성의 체크섬을 확인합니다.
- 공식 레지스트리를 선호하고 검증된 게시자만 신뢰하세요.

## 인프라 보안
### 방화벽
- 명시적으로 필요한 포트(예: 80, 443)를 제외한 모든 인바운드 포트를 차단합니다.
- SSH 액세스를 특정 IP 범위로 제한합니다(또는 VPN/배스천 호스트 사용).
- 세분화된 제어를 위해 보안 그룹(AWS) 또는 NSG(Azure)를 사용합니다.
### OS 강화
- 정기적으로 보안 업데이트를 적용합니다(`sudo apt upgrade`,`yum update`).
- 불필요한 서비스와 기본 계정을 비활성화합니다.
- SSH에 대한 무차별 대입 공격을 차단하려면 fall2ban을 사용하세요.
- SSH 강화: 루트 로그인 비활성화, 키 기반 인증 사용, 기본 포트 변경(선택 사항).
### 네트워크 세분화
- 인터넷 접속이 불가능한 프라이빗 서브넷에 데이터베이스와 캐시를 배치합니다.
- 공공 서비스에는 DMZ를 사용하세요.
- 네트워크 접속에 최소 권한 원칙을 적용합니다.
### 인프라의 비밀
- 암호화되지 않은 경우 CI/CD 환경 변수에 비밀을 저장하지 마십시오.
- 수명이 긴 키 대신 EC2/VM 인스턴스에 대한 클라우드 공급자의 IAM 역할을 사용합니다.

## 로깅 및 모니터링
### 기록할 내용
- 인증 이벤트(성공/실패).
- 액세스 제어 결정(인증 실패).
- 관리자 작업(사용자 생성, 삭제, 권한 변경).
- 데이터베이스 스키마 변경.
- 시스템 오류 및 예외.
- API 요청 및 응답(민감한 데이터 수정)
### 기록하지 말아야 할 사항
- 해시/수정되지 않은 비밀번호, 비밀, 토큰, PII(개인 식별 정보).
- 전체 신용카드 번호.
### 알림
- 다음에 대한 알림 설정:
  - 여러 번의 로그인 실패(잠재적 무차별 공격).
  - 비정상적인 접근 패턴(예: 새로운 위치에서, 이상한 시간에)
  - 새로운 관리자 계정이 생성되었습니다.
  - 오류율이 높거나 대기 시간이 급증합니다.
- 고급 상관관계 분석을 위해 SIEM(Security Information and Event Management)을 사용합니다.
### 로그 보관
- 규제 요구 사항에 따라 최소 30~90일 동안 로그를 보관합니다.
- 중앙 집중식 변조 방지 시스템(예: ELK Stack, Splunk, Datadog)에 로그를 저장합니다.

## 보안 개발 수명주기(SDL)
1. **교육**: 개발자가 일반적인 취약점을 이해하도록 합니다.
2. **위협 모델링**: 설계 초기에 잠재적인 위협을 식별합니다.
3. **보안 코딩 표준**: 린터 및 코드 검토 체크리스트를 통해 시행합니다.
4. **SAST**(정적 애플리케이션 보안 테스트): 소스 코드에서 취약점을 스캔합니다(SonarQube, CodeQL).
5. **DAST**(동적 애플리케이션 보안 테스트): 실행 중인 애플리케이션(OWASP ZAP, Burp Suite)을 검사합니다.
6. **SCA**(소프트웨어 구성 분석): 종속성을 검색합니다.
7. **침투 테스트**: 정기적인 윤리적 해킹 훈련.
8. **버그 현상금**: 외부 연구원이 책임감 있게 취약점을 찾도록 권장합니다.
9. **사고 대응 계획**: 위반이 감지되는 시기에 대한 명확한 계획을 마련합니다.
---

## 긴급 체크리스트(위반이 의심되는 경우)
1. **당황하지 말고** — 신속하게 행동하십시오.
2. 영향을 받은 시스템을 **격리**합니다(필요한 경우 네트워크 연결을 끊습니다).
3. **증거 보존**: 로그, 메모리 덤프, 디스크 이미지를 캡처합니다.
4. **식별** 범위: 어떤 시스템, 어떤 데이터.
5. 손상된 모든 자격 증명과 비밀을 **순환**합니다.
6. 취약점을 **패치**합니다.
7. 필요한 경우 (법적 기간 내에) 영향을 받는 사용자 및 규제 기관에 **알립니다**.
8. **사후 분석을 실시**하여 근본 원인을 파악하고 프로세스를 개선합니다.
