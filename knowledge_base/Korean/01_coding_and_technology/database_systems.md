# 데이터베이스 시스템
## 데이터베이스 기초
### 데이터베이스란 무엇입니까?
데이터베이스는 데이터의 효율적인 검색, 삽입, 업데이트 및 삭제를 위해 설계된 전자적으로 저장된 구조화된 정보의 조직화된 모음입니다.
### 데이터베이스 관리 시스템(DBMS)
최종 사용자, 애플리케이션 및 데이터베이스 자체와 상호 작용하여 데이터를 캡처하고 분석하는 소프트웨어입니다. 예: MySQL, PostgreSQL, Oracle, MongoDB.
### 주요 개념
- **스키마**: 데이터베이스의 구조/구성(테이블, 필드, 관계)
- **인스턴스**: 특정 순간에 저장된 실제 데이터
- **ACID 속성**: 원자성, 일관성, 격리성, 내구성
- **CAP 정리**: 일관성, 가용성, 파티션 허용오차(2개 선택)
- **정규화**: 중복성을 줄이기 위해 데이터를 정리합니다.
- **비정규화**: 읽기 성능 향상을 위해 중복성 추가
## 관계형 데이터베이스(SQL)
### 핵심 개념
- **테이블**: 행(레코드) 및 열(필드)
- **기본 키**: 각 행의 고유 식별자
- **외래 키**: 다른 테이블의 기본 키를 참조합니다.
- **인덱스**: 쿼리 속도를 향상시키는 데이터 구조
- **뷰**: 쿼리 결과를 기반으로 하는 가상 테이블
- **저장 프로시저**: 미리 컴파일된 SQL 코드 블록
- **트리거**: 데이터 변경에 대한 자동 조치
### SQL 작업(CRUD)```sql
-- Create
INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com');

-- Read
SELECT * FROM users WHERE id = 1;
SELECT name, email FROM users ORDER BY name LIMIT 10;

-- Update
UPDATE users SET email = 'new@example.com' WHERE id = 1;

-- Delete
DELETE FROM users WHERE id = 1;
```

### 조인
- **INNER JOIN**: 두 테이블 모두에서 일치하는 행을 반환합니다.
- **LEFT JOIN**: 왼쪽 테이블의 모든 행, 오른쪽부터 일치
- **RIGHT JOIN**: 오른쪽 테이블의 모든 행, 왼쪽에서 일치
- **FULL OUTER JOIN**: 두 테이블의 모든 행
- **CROSS JOIN**: 두 테이블의 데카르트 곱
- **SELF JOIN**: 테이블 자체가 조인되었습니다.
### 정규화 형식
- **1NF**: 원자 값, 반복 그룹 없음
- **2NF**: 1NF + 부분 종속성 없음(키가 아닌 모든 속성은 전체 기본 키에 종속됨)
- **3NF**: 2NF + 전이적 종속성 없음(키가 아닌 속성은 다른 키가 아닌 속성에 종속되지 않음)
- **BCNF**: 더 강력한 3NF, 모든 행렬식은 후보 키입니다.
- **4NF**: 다중 값 종속성 없음
- **5NF**: 조인 종속성이 없습니다.
### 인기 있는 RDBMS
- **PostgreSQL**: 고급 기능, 확장 가능, ACID 규격
- **MySQL**: 널리 사용되며 빠른 읽기, 웹 애플리케이션
- **Oracle**: 엔터프라이즈 기능, 확장성, 고가
- **SQL Server**: Microsoft 생태계, 통합 도구
- **SQLite**: 임베디드, 서버리스, 경량
- **MariaDB**: MySQL 포크, 오픈 소스
## NoSQL 데이터베이스
### NoSQL 데이터베이스 유형
#### 문서 저장소
- **구조**: JSON과 유사한 문서(BSON)
- **사용 사례**: 콘텐츠 관리, 카탈로그, 사용자 프로필
- **예**: MongoDB, CouchDB, DocumentDB
- **쿼리 예**(MongoDB):```javascript
db.users.find({ age: { $gt: 25 } }).sort({ name: 1 });
```

#### 키-값 저장소
- **구조**: 간단한 키-값 쌍
- **사용 사례**: 캐싱, 세션, 장바구니
- **예**: Redis, DynamoDB, Riak
- **특성**: 빠르고 간단하며 제한된 쿼리
#### 기둥형 상점
- **구조**: 계열로 그룹화된 열
- **사용 사례**: 빅데이터, 분석, 시계열
- **예**: Cassandra, HBase, ScyllaDB
- **특성**: 쓰기 최적화, 분산, 확장 가능
#### 그래프 데이터베이스
- **구조**: 노드, 모서리, 속성
- **사용 사례**: 소셜 네트워크, 사기 감지, 추천
- **예**: Neo4j, Amazon Neptune, ArangoDB
- **쿼리 언어**: Cypher(Neo4j), Gremlin
### NoSQL을 사용해야 하는 경우
- 유연하고 진화하는 스키마
- 수평적 확장 요구 사항
- 높은 쓰기 처리량
- 계층적/중첩 데이터
- 분산 시스템
- 실시간 애플리케이션
## 데이터베이스 디자인
### 엔터티-관계 모델링
- **엔터티**: 개체/개념(고객, 제품, 주문)
- **속성**: 엔터티의 속성(이름, 가격, 날짜)
- **관계**: 엔터티 간의 연결(일대일, 일대다, 다대다)
- **카디널리티**: 관계에 있는 인스턴스 수
### 스키마 디자인 패턴
- **단일 테이블 상속**: 유형 구분자가 있는 하나의 테이블에 모든 유형이 있습니다.
- **클래스 테이블 상속**: 기본 클래스와 하위 클래스에 대한 별도의 테이블
- **구체적 테이블 상속**: 각 구체적 클래스에 대한 별도의 테이블
- **접합 테이블**: 다대다 관계 해결
- **감사 테이블**: 변경 사항 추적(created_at, update_at, delete_at)
### 색인 전략
- **B-Tree**: 기본값, 범위 쿼리, 정렬
- **해시**: 정확히 일치하는 조회
- **비트맵**: 낮은 카디널리티 열(성별, 상태)
- **전체 텍스트**: 텍스트 검색 기능
- **공간**: 지리 데이터(GIS)
- **복합**: 여러 열이 결합됨
- **Covering**: 쿼리에 필요한 모든 컬럼을 포함합니다.
## 쿼리 최적화
### 실행 계획
- 데이터베이스가 쿼리를 실행하는 방법 이해
- 병목 현상 식별(전체 테이블 스캔, 누락된 인덱스)
- 도구: 설명, 설명, 분석
### 최적화 기술
- **인덱스 사용**: 쿼리가 적절한 인덱스를 사용하는지 확인
- **쿼리 재작성**: 복잡한 쿼리 단순화
- **조인 최적화**: 올바른 조인 유형 및 순서 선택
- **파티셔닝**: 대규모 테이블 분할(범위, 해시, 목록)
- **구체화된 뷰**: 미리 계산된 쿼리 결과
- **쿼리 캐싱**: 자주 쿼리한 결과를 저장합니다.
### 일반적인 성능 문제
- **N+1 쿼리 문제**: 관련 데이터를 비효율적으로 가져오는 문제
- **누락된 인덱스**: 대규모 테이블에서 전체 테이블 스캔
- **과도한 색인 생성**: 색인이 너무 많아 쓰기 속도가 느립니다.
- **Lock Contention**: 잠금을 기다리는 트랜잭션
- **비효율적인 쿼리**: SELECT *, 불필요한 조인
## 트랜잭션 및 동시성
### 트랜잭션 격리 수준
- **커밋되지 않은 읽기**: 가장 낮은 격리, 더티 읽기 가능
- **READ COMMITTED**: 커밋된 데이터만 표시됨(대부분의 DB에서 기본값)
- **REPEATABLE READ**: 동일한 쿼리가 트랜잭션 내에서 동일한 결과를 반환합니다.
- **SERIALIZABLE**: 가장 높은 격리성, 트랜잭션이 순차적으로 실행됨
### 동시성 제어
- **비관적 잠금**: 액세스하기 전에 리소스를 잠급니다.
- **낙관적 잠금**: 커밋하기 전에 버전을 확인하세요.
- **MVCC(Multi-Version Concurrency Control)**: 행의 여러 버전 유지
- **행 수준 잠금**: 특정 행을 잠급니다.
- **테이블 수준 잠금**: 전체 테이블 잠금
### 교착상태
- 트랜잭션이 서로를 기다리는 순환 종속성
- 예방: 일관된 잠금 순서, 시간 초과, 교착 상태 감지
- 해결 방법: 하나의 거래를 중단합니다.
## 복제 및 확장
### 복제 유형
- **마스터-슬레이브**: 하나의 기본, 여러 읽기 복제본
- **마스터-마스터**: 다중 기본, 양방향 복제
- **다중 마스터**: N개의 기본, 충돌 해결 필요
- **체인 복제**: 노드를 통한 순차적 복제
### 확장 접근 방식
- **수직적 확장**: 서버 리소스(CPU, RAM, 스토리지) 증가
- **수평적 확장**: 서버 추가(샤딩, 파티셔닝)
- **읽기 복제본**: 읽기 트래픽 오프로드
- **샤딩**: 키/범위/해시를 기준으로 서버 전체에 데이터를 분할합니다.
- **연합**: 기능별/서비스별 분할
### 일관성 모델
- **강력한 일관성**: 모든 노드가 동시에 동일한 데이터를 확인합니다.
- **최종 일관성**: 시간이 지남에 따라 노드가 수렴됩니다.
- **인과적 일관성**: 인과관계가 보존됩니다.
- **쓰기 읽기**: 사용자는 자신의 업데이트를 즉시 확인합니다.
## 백업 및 복구
### 백업 전략
- **전체 백업**: 전체 데이터베이스 복사본
- **증분 백업**: 마지막 백업 이후 변경 사항
- **차등 백업**: 마지막 전체 백업 이후 변경 사항
- **Point-in-Time Recovery**: 특정 순간으로 복원
- **연속 백업**: 백업에 실시간 복제
### 복구 절차
- **RTO(복구 시간 목표)**: 허용 가능한 최대 가동 중지 시간
- **RPO(복구 지점 목표)**: 허용 가능한 최대 데이터 손실
- **재해 복구 계획**: 실패에 대한 문서화된 절차
- **테스트**: 정기 복구 훈련
## 보안
### 접근 제어
- **인증**: 사용자 본인 여부를 확인합니다.
- **권한**: 권한 부여(GRANT, REVOKE)
- **역할**: 보다 쉬운 관리를 위한 그룹 권한
- **최소 권한의 원칙**: 필요한 최소한의 접근 권한
### 데이터 보호
- **미사용 암호화**: 저장된 데이터를 암호화합니다.
- **전송 중 암호화**: 연결용 TLS/SSL
- **마스킹**: 비프로덕션에서 민감한 데이터를 숨깁니다.
- **토큰화**: 민감한 데이터를 토큰으로 대체
### 일반적인 취약점
- **SQL 인젝션**: 사용자 입력에 악성 SQL 삽입
- **권한 상승**: 무단 접근권 획득
- **감사 로깅**: 모든 데이터베이스 활동 추적
- **규정 준수**: GDPR, HIPAA, PCI-DSS 요구 사항
## 최신 데이터베이스 기술
### 클라우드 데이터베이스
- **AWS**: RDS, Aurora, DynamoDB, Redshift
- **Google Cloud**: Cloud SQL, Spanner, Bigtable, Firestore
- **Azure**: SQL 데이터베이스, Cosmos DB, Synapse
- **혜택**: 관리형 서비스, 자동 확장, 백업 포함
### NewSQL 데이터베이스
- SQL 일관성과 NoSQL 확장성을 결합합니다.
- **예**: CockroachDB, TiDB, YugabyteDB, Google Spanner
- **기능**: 분산, ACID 트랜잭션, 수평 확장
### 시계열 데이터베이스
- 타임스탬프가 있는 데이터에 최적화됨
- **예**: InfluxDB, TimescaleDB, Prometheus
- **사용 사례**: IoT, 모니터링, 금융 데이터
### 벡터 데이터베이스
- 임베딩 벡터 저장 및 쿼리
- **예**: Pinecone, Milvus, Weaviate, Qdrant
- **사용 사례**: 의미 검색, 추천 시스템, AI 애플리케이션
### 다중 모델 데이터베이스
- 단일 시스템에서 다양한 데이터 모델 지원
- **예**: ArangoDB, OrientDB, Azure Cosmos DB
- **이점**: 여러 데이터베이스가 필요 없는 유연성
## ORM 및 데이터 액세스

- **인기 ORM**:
  - 파이썬: SQLAlchemy, Django ORM, Peewee
  - 자바스크립트: Sequelize, Prisma, TypeORM
  - 자바: 하이버네이트, JPA
  - 루비: 액티브레코드
  - .NET: 엔터티 프레임워크
### 혜택
- SQL에서 추상화
- 유형 안전
- 마이그레이션 관리
- 쿼리 작성 API
### 단점
- 성능 오버헤드
- 작성하기 어려운 복잡한 쿼리
- N+1 쿼리 문제
- 학습 곡선
## 데이터베이스 관리
### DBA 책임
- 설치 및 구성
- 성능 튜닝
- 백업 및 복구
- 보안관리
- 용량 계획
- 모니터링 및 경고

### 유지 관리 작업

- **인덱스 재구축**: 인덱스 조각 모음

- **로그 회전**: 로그 파일 크기 관리
- **용량 계획**: 성장 예측, 업그레이드 계획
