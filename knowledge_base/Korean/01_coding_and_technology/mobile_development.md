# 모바일 개발
모바일 개발은 주로 iOS(Apple) 및 Android(Google)용 스마트폰 및 태블릿용 애플리케이션을 구축하는 관행입니다. 작은 화면을 위한 UI 디자인부터 배터리 수명 관리, 네트워크 불안정 처리, 스토어를 통한 앱 배포까지 모든 것을 포괄합니다. 이 분야는 이제 대부분의 사용 사례에서 기본 개발과 경쟁하는 크로스 플랫폼 프레임워크로 인해 상당히 성숙해졌습니다.
---

## 모바일 환경
| 플랫폼 | 개발자 | 언어 | 매장 | 시장점유율(글로벌) |
|----------|------------|-------------|-------|---------|
| **안드로이드** | 구글 | 코틀린, 자바 | 구글 플레이 | ~72% |
| **iOS** | 애플 | 스위프트, 오브젝티브-C | 앱스토어 | ~27% |

### iOS
| 측면 | 세부정보 |
|---------|---------|

## 크로스 플랫폼 프레임워크
한 번 빌드하면 iOS와 Android 모두에 배포됩니다.
| 프레임워크 | 언어 | 렌더링 | 성과 | 최고의 대상 |
|------------|----------|------------|------------|----------|
| **플러터** | 다트 | 커스텀 엔진(스키아/임펠러) | 가까운 원주민 | 풍부한 사용자 정의 UI; 플랫폼 전반에 걸쳐 일관된 모습 |
| **리액트 네이티브** | 자바스크립트/타입스크립트 | 브리지를 통한 기본 구성 요소 | 좋음(새로운 아키텍처가 이를 개선함) | 웹/JS 경험이 있는 팀 |
| **Kotlin 멀티플랫폼** | 코틀린 | 플랫폼별 기본 UI | 네이티브 | 비즈니스 로직 공유 네이티브 UI |
| **마우이**(.NET) | C# | 기본 컨트롤 | 좋음 | .NET 팀; 기업용 앱 |
| **이온성/축전기** | HTML/CSS/JS | 웹뷰 | 낮은 | 간단한 앱; 웹 팀 |
### Flutter와 React Native 비교
| 측면 | 설레다 | 리액트 네이티브 |
|---------|---------|------------|
| **언어** | 다트 | 자바스크립트/타입스크립트 |
| **UI 렌더링** | 모든 것을 그 자체로 그립니다(플랫폼 전반에 걸쳐 일관됨) | 기본 구성 요소 사용(플랫폼별 모양) |
| **핫 리로드** | 우수 | 좋음 |
| **생태계** | 빠르게 성장하고 있습니다. 위젯 기반 | 크기가 큰; npm 생태계 |
| **학습 곡선** | 다트를 배워야 한다 | 웹 개발자를 위한 더 쉬운 |
| **플랫폼 통합** | 네이티브 코드용 플랫폼 채널 | 브리지를 통한 기본 모듈 |
| **성능** | 훌륭한; 거의 네이티브 | 좋은; 교량 오버헤드(새 아키텍처로 감소) |

## 모바일 아키텍처 패턴
| 패턴 | 설명 | 사용 시기 |
|---------|-------------|-------------|
| **MVC** | 모델-뷰-컨트롤러 | 간단한 앱; 웹 개발자에게 친숙한 |
| **MVVM** | 모델-뷰-뷰모델; 데이터 바인딩 | 가장 현대적인 모바일 앱 |
| **MVI** | 모델-뷰-의도; 단방향 데이터 흐름 | 복잡한 상태 관리; Flutter(BLoC/Riverpod 포함) |
| **클린 아키텍처** | 종속성 반전이 포함된 레이어 | 대규모 팀; 복잡한 비즈니스 로직 |

## 주요 모바일 문제
### 오프라인 우선 디자인
모바일 앱은 안정적인 인터넷 없이도 작동해야 합니다.
| 전략 | 설명 |
|----------|-------------|
| **로컬 데이터베이스** | 장치에 데이터 저장(SQLite, Room, CoreData, Realm) |
| **동기화 전략** | 온라인일 때 서버와 동기화합니다. 갈등 해결 |
| **낙관적인 UI** | UI를 즉시 업데이트하세요. 서버가 응답하면 조정 |
| **캐시** | 캐시 API 응답; 오프라인일 때 캐시에서 제공 |
### 성능
| 우려사항 | 솔루션 |
|---------|----------|
| **앱 시작 시간** | 지연 로딩; 초기화 작업 최소화 |
| **메모리 사용량** | 이미지 압축; 메모리 누수를 방지하세요. 프로파일링 도구 사용 |
| **배터리 소모** | 백그라운드 작업을 줄입니다. 일괄 네트워크 요청; 효율적인 위치 서비스 이용 |
| **네트워크 효율성** | 페이로드를 압축합니다. 페이지 매김을 사용하십시오. 적극적으로 캐시 |
| **목록 스크롤** | 뷰를 재활용합니다. 이미지에 지연 로딩 사용 |
### 보안
| 우려사항 | 솔루션 |
|---------|----------|
| **미사용 데이터** | 민감한 데이터 암호화(iOS의 키체인, Android의 EncryptedSharedPreferences) |
| **네트워크** | 항상 HTTPS입니다. 민감한 앱에 대한 인증서 고정 |
| **인증** | 생체 인식(얼굴 ID, 지문) OAuth; 토큰 저장 |
| **코드 난독화** | 안드로이드용 ProGuard/R8; iOS용 비트코드 |
| **탈옥/루트 감지** | 손상된 장치를 감지합니다. 기능 제한 |

## 앱 수명주기
| 상태 | 설명 | 해야 할 일 |
|-------|-------------|------------|
| **전경(활성)** | 사용자가 앱과 상호작용하고 있습니다 | 정상작동 |
| **배경** | 앱이 표시되지 않지만 여전히 메모리에 있습니다 | 애니메이션을 일시 중지합니다. 상태 저장 |
| **정지됨** | OS가 리소스를 절약하기 위해 앱을 정지했습니다 | 아무것도 아님; 앱이 정지되었습니다 |
| **해지됨** | OS가 메모리를 확보하기 위해 앱을 종료했습니다 | 다음 실행 시 상태 복원 |

## 푸시 알림
| 플랫폼 | 서비스 | 프로토콜 |
|------------|---------|----------|

| **안드로이드** | FCM(Firebase 클라우드 메시징) | HTTP/v1 |
| 알림 유형 | 설명 |
|------|-------------|
| **데이터 알림** | 조용한; 앱이 페이로드를 처리합니다 | 배경 업데이트 |
| **알림 표시** | 알림 트레이에 표시 | 사용자 경고 |
| **리치 알림** | 이미지, 작업 또는 사용자 정의 UI 포함 | 향상된 사용자 참여 |

## 요약
모바일 개발에서는 네이티브(최고 성능, 플랫폼별)와 크로스 플랫폼(공유 코드베이스, 더 빠른 반복) 중에서 선택할 수 있습니다. Flutter와 React Native는 크로스 플랫폼이 대부분의 애플리케이션에 적합한 선택이 될 정도로 성숙해졌습니다. 오프라인 우선 설계, 제한된 하드웨어에서의 성능, 배터리 효율성, 신뢰할 수 없는 장치에서의 보안, 앱 스토어 검토 프로세스 탐색 등 프레임워크에 관계없이 핵심 과제는 동일하게 유지됩니다. 이 분야는 빠른 시작, 부드러운 스크롤, 연결 불량에 대한 우아한 처리 등 사용자 경험을 먼저 생각하는 개발자에게 보상을 제공합니다.
