# 로우코드 및 플랫폼 엔지니어링
로우 코드 플랫폼을 사용하면 사람들은 일반적으로 드래그 앤 드롭 인터페이스, 시각적 워크플로 및 사전 구축된 커넥터를 통해 최소한의 손으로 작성한 코드로 애플리케이션을 구축할 수 있습니다. 플랫폼 엔지니어링은 제품 팀이 인프라, CI/CD 및 운영 도구를 쉽게 셀프 서비스할 수 있도록 하는 내부 개발자 플랫폼(IDP)을 구축하는 분야입니다. 두 추세 모두 동일한 문제, 즉 소프트웨어에 대한 수요와 이를 구축할 수 있는 개발자 공급 간의 격차에 대한 대응입니다.
---

## 로우 코드 플랫폼
### 로우코드의 실제 의미
| 측면 | 설명 |
|---------|-------------|
| **시각적 발달** | 드래그 앤 드롭 UI 빌더; 시각적 작업 흐름 편집기; 양식 디자이너 |
| **사전 구축된 구성요소** | 기성품 위젯, 커넥터, 템플릿 및 통합 |
| **선언적 논리** | 코드를 작성하는 대신 규칙과 조건을 통해 동작 구성 |
| **확장성** | 플랫폼의 내장 기능이 충분하지 않을 때 사용자 정의 코드를 추가하는 기능 |
| **관리형 인프라** | 플랫폼이 호스팅, 확장, 보안 패치를 처리합니다 |
### 인기 있는 로우 코드 플랫폼
| 플랫폼 | 힘 | 일반적인 사용 사례 |
|----------|----------|----|
| **Microsoft Power 플랫폼** | 심층적인 Microsoft 365/Azure 통합; Power Apps, Power Automate, Power BI | 기업 워크플로우 내부 도구 |
| **Salesforce 플랫폼** | CRM 기반; 확장을 위한 Apex; 흐름 빌더 | 고객 대면 앱 판매 워크플로 |
| **서비스나우** | IT 서비스 관리; 워크플로 자동화 | IT 운영; 인사; 시설 |
| **아피안** | 프로세스 마이닝; 사례 관리 | 복잡한 비즈니스 프로세스 준수 |
| **아웃시스템** | 풀스택 웹 및 모바일; 엔터프라이즈급 | 고객 포털 모바일 앱 |
| **재조정** | 내부 도구 빌더 데이터베이스 및 API에 연결 | 관리 패널 대시보드; 운영 도구 |
| **공기 테이블** | 스프레드시트-데이터베이스 하이브리드; 자동화 | 프로젝트 추적; 경량 CRM |
### 로우코드가 잘 작동하는 경우
| 시나리오 | 로우코드가 적합한 이유 |
|------------|------|
| **내부 도구** | 구축 속도가 빠릅니다. 사용자는 내부이므로 UI ​​유연성은 덜 중요합니다 |
| **양식 및 승인** | 시각적 워크플로 빌더는 이 점에 탁월합니다. |
| **CRUD 애플리케이션** | 대부분의 로우 코드 플랫폼은 생성-읽기-업데이트-삭제 패턴에 최적화되어 있습니다 |
| **프로토타이핑** | 몇 주가 아닌 몇 시간 만에 아이디어 검증 |
| **시민개발** | 비즈니스 분석가는 IT 거버넌스를 통해 자체 솔루션을 구축할 수 있습니다 |
### 로우 코드가 부족할 때
| 제한사항 | 영향 |
|------------|---------|
| **공급업체 종속** | 애플리케이션을 플랫폼에서 쉽게 마이그레이션할 수 없음 |
| **성능 한도** | 처리량이 많거나 대기 시간에 민감한 애플리케이션에는 적합하지 않음 |
| **UI 제약** | 맞춤형 디자인은 어렵습니다. 플랫폼이 지원하는 것으로 제한됩니다 |
| **통합 복잡성** | 어쨌든 특이한 API 또는 레거시 시스템에 연결하려면 사용자 정의 코드가 필요할 수 있습니다 |
| **규모에 따른 비용** | 사용량이 증가함에 따라 사용자별 또는 앱별 가격이 높아질 수 있음 |
| **디버깅 난이도** | 시각적 추상화로 인해 복잡한 문제를 진단하기가 어려워짐 |

## 플랫폼 엔지니어링
### 플랫폼 엔지니어링이 해결하는 문제
| 플랫폼 엔지니어링 없이 | 플랫폼 엔지니어링 |
|------------------|---------------|
| 각 팀은 자체 인프라를 관리합니다 | 인프라를 추상화하는 셀프 서비스 플랫폼 |
| 팀 전체에 걸쳐 일관되지 않은 도구 사용 | 표준화된 툴체인 황금 길 |
| 개발자는 Ops가 리소스를 프로비저닝할 때까지 기다립니다 | 개발자는 필요에 따라 리소스를 프로비저닝 |
| 지식 사일로; 부족 지식 | 문서화됨; 자동화; 검색 가능 |
| 새로운 엔지니어의 느린 온보딩 | 새로운 엔지니어가 첫날부터 배포 가능 |
### 내부 개발자 플랫폼의 핵심 구성요소
| 구성요소 | 목적 | 예제 도구 |
|------------|---------|---------------|
| **서비스 카탈로그** | 모든 서비스 및 소유자의 중앙 등록 | 무대 뒤에서; 포트; 피질 |
| **템플릿 비계** | 승인된 템플릿에서 새 서비스 생성 | 백스테이지 소프트웨어 템플릿; 쿠키커터 |
| **셀프서비스 인프라** | 개발자는 티켓을 제출하지 않고 클라우드 리소스를 프로비저닝 | Terraform 모듈; 풀루미; 크로스플레인 |
| **CI/CD 파이프라인** | 표준화된 빌드, 테스트, 배포 파이프라인 | GitHub 작업; GitLab CI; 아르고 CD |
| **환경경영** | 주문형 임시 개발/스테이징 환경 | 클러스터; 네임스페이스; Gitpod |
| **관측성** | 모든 서비스에 내장된 로깅, 메트릭, 추적 | 프로메테우스; 그라파나; 오픈텔레메트리; 데이터독 |
| **비밀관리** | 자격 증명의 안전한 저장 및 순환 | 둥근 천장; AWS 비밀 관리자; SOPS |
| **신원 및 액세스** | SSO; 역할 기반 액세스; 서비스 간 인증 | 옥타; 열쇠망토; SPIFFE |
### 골든 패스
골든 패스(Golden Path)는 어떤 일을 하기 위해 지지받고 독선적인 방법입니다. 이는 저항이 가장 적은 경로입니다. 이를 따르면 모든 것이 작동합니다. 당신은 길을 벗어날 수 있지만 당신은 혼자입니다.
| 골든패스 | 그것이 제공하는 것 |
|---------------|----|
| **새로운 서비스** | 템플릿 저장소; CI/CD; 모니터링; 벌채 반출; 배포 구성 |
| **새 데이터베이스** | 프로비저닝된 인스턴스 비밀의 연결 문자열; 백업 구성됨 |
| **새로운 프런트엔드** | 파이프라인 구축 CDN; 미리보기 환경; 등대 점검 |
| **데이터 파이프라인** | 관현악법; 스키마 검증; 모니터링; 경고 |
### 구축 및 구매 결정
| 요인 | 맞춤형 구축 | 기존 도구 사용 |
|---------|-------------|------|
| **핵심역량** | 귀하의 비즈니스에 고유한 것입니다. 경쟁 우위 | 상품; 모든 회사에 필요합니다 |
| **유지보수 부담** | 당신은 그것을 유지할 수 있는 능력이 있습니다 | 도구는 공급업체/커뮤니티에서 잘 관리됩니다 |
| **통합 요구** | 내부 시스템과의 긴밀한 통합 필요 | 표준 API 및 커넥터로 충분 |
| **비용** | 라이센스보다 구축 비용이 저렴함 | 빌드보다 라이센스 비용이 저렴함 |

## 로우 코드와 플랫폼 엔지니어링의 관계
| 차원 | 로우 코드 | 플랫폼 엔지니어링 |
|------------|----------|---------|
| **대상 사용자** | 비즈니스 사용자 시민 개발자 | 전문 소프트웨어 엔지니어 |
| **목표** | 코드를 줄입니다. 속도 증가 | 인지 부하를 줄입니다. 자율성 증대 |
| **추상화 수준** | 매우 높음; 시각적 | 중간; 코드 기반이지만 단순화됨 |
| **유연성** | 플랫폼 기능에 따라 제한됨 | 완전한 유연성; 어떤 코드라도 작성할 수 있습니다 |
| **거버넌스** | 플랫폼은 규칙을 시행합니다 | 플랫폼은 골든 경로를 제공합니다 |
이들은 상호 보완적입니다. 플랫폼 엔지니어링을 통해 전문 개발자는 더 빠르게 작업할 수 있고, 로우 코드를 사용하면 개발자가 아닌 사람도 간단한 애플리케이션을 구축할 수 있습니다. 이들은 함께 다양한 각도에서 소프트웨어 제공 격차를 해결합니다.
---

## 요약
로우코드 플랫폼과 내부 개발자 플랫폼 모두 소프트웨어를 제공할 수 있는 사람의 수를 늘리는 것을 목표로 합니다. 로우 코드는 시각적 빌더, 사전 구축된 커넥터, 선언적 논리 등 코드를 완전히 추상화하여 이를 수행합니다. 플랫폼 엔지니어링은 셀프 서비스 인프라, 최적의 경로, 표준화된 도구를 제공하여 전문 개발자가 운영 작업에 소요되는 시간을 줄이고 제품 기능에 더 많은 시간을 할애할 수 있도록 하여 이를 수행합니다. 만병통치약도 아닙니다. 로우 코드에는 공급업체 종속 및 성능 제한이 있으며 플랫폼 엔지니어링을 유지하려면 지속적인 투자가 필요합니다. 그러나 내부 도구, CRUD 앱, 표준화된 서비스 제공 등 올바른 문제에 적용하면 둘 다 아이디어에서 생산까지의 시간을 크게 단축할 수 있습니다.
