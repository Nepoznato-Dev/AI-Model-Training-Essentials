# 임베디드 시스템과 IoT
임베디드 시스템은 자동차의 엔진 제어 장치, 세탁기 컨트롤러, 스마트 온도 조절 장치의 마이크로컨트롤러 등 다른 장치 내부에 숨겨진 컴퓨터입니다. 범용 컴퓨터와 달리 특정 작업을 위해 설계되었으며 전력, 메모리 및 처리 속도에 대한 엄격한 제약이 있는 경우가 많습니다. 사물 인터넷(IoT)은 임베디드 시스템을 네트워크에 연결하여 원격 모니터링, 제어 및 데이터 수집을 가능하게 함으로써 임베디드 시스템을 확장합니다. 이들은 함께 물리적 세계와 상호 작용하는 수십억 개의 컴퓨팅 장치를 나타냅니다.
---

## 임베디드 시스템 기초
### 임베디드의 차별점
| 측면 | 범용 컴퓨터 | 임베디드 시스템 |
|---------|------------|----|
| **목적** | 소프트웨어 실행 | 특정 작업 수행 |
| **자원** | 풍부한 CPU, RAM, 스토리지 | 제한됨(KB~MB RAM, MHz~낮은 GHz) |
| **전력** | 전원이 연결되어 있거나 대용량 배터리 | 종종 배터리 구동 또는 에너지 수확 |
| **OS** | 전체 OS(Windows, Linux, macOS) | RTOS, 베어메탈 또는 임베디드 Linux |
| **사용자 인터페이스** | 리치(화면, 키보드, 마우스) | 최소(LED, 버튼, 센서) 또는 없음 |
| **실시간** | 최선의 노력 | 종종 실시간 마감일이 빡빡함 |
| **평생** | 3~7세 | 10~25세 이상 |
### 마이크로컨트롤러와 마이크로프로세서
| 기능 | 마이크로컨트롤러(MCU) | 마이크로프로세서(MPU) |
|---------|---------|-------|
| **통합** | 하나의 칩에 CPU + RAM + 플래시 + 주변 장치 | CPU 전용; 외부 RAM 및 스토리지 |
| **성능** | 낮음~보통(MHz 범위) | 높음(GHz 범위) |
| **전력** | 매우 낮음(μA ~ mA) | 더 높음(수백 mA ~ 암페어) |
| **비용** | $0.10 - $10 | $5 - $100+ |
| **예** | STM32, ESP32, 아두이노(ATmega), nRF52 | 라즈베리 파이(BCM2835), i.MX, Allwinner |
| **사용 사례** | 센서, 액추에이터, 단순 제어 | 디스플레이, 복합처리, Linux |

## 일반적인 임베디드 플랫폼
| 플랫폼 | MCU/MPU | 주요 기능 | 최고의 대상 |
|------------|---------|-------------|----------|
| **아두이노** | ATmega328P(및 기타) | 단순한; 거대한 커뮤니티 | 학습; 프로토타이핑 |
| **ESP32** | Espressif 듀얼 코어 | Wi-Fi + 블루투스; 저렴한 비용 | IoT 프로젝트; 연결된 장치 |
| **라즈베리 파이 피코** | RP2040(듀얼 코어 ARM) | 입수 가능한; MicroPython 지원 | 교육; 취미 프로젝트 |
| **STM32** | ARM Cortex-M 시리즈 | 산업 등급; 넓은 범위 | 전문 내장; 산업 |
| **nRF52/nRF53** | 노르딕 반도체 | 블루투스 저에너지 전문가 | 웨어러블; 비콘 |
| **라즈베리 파이** | 브로드컴 BCM(ARM) | 전체 리눅스; GPIO 핀 | 프로토타이핑; 미디어 센터; 라이트 엣지 컴퓨팅 |
| **비글본** | TI 시타라(ARM) | 실시간 PRU 코어 | 산업; 실시간 애플리케이션 |
| **ESP32-S3** | 에스프레소 | AI 가속; USB | 엣지 AI; 비전 애플리케이션 |

## 실시간 운영 체제(RTOS)
RTOS는 정의된 시간 내에 중요한 작업이 완료되도록 보장합니다.
| RTOS | 라이센스 | 최고의 대상 |
|------|---------|----------|
| **FreeRTOS** | MIT | 가장 일반적입니다. 광범위한 MCU 지원 |
| **제퍼** | 아파치 2.0 | 현대의; 리눅스 재단; 성장하는 생태계 |
| **ThreadX(Azure RTOS)** | MIT | 안전 인증; IoT |
| **embOS** | 상업용 | 산업; 인증 |
| **RT-스레드** | 아파치 2.0 | 중국생태계; 전 세계적으로 성장 |
### RTOS와 베어메탈 비교
| 측면 | 베어메탈 | RTOS |
|---------|------------|------|
| **복잡성** | 간단한 작업을 위한 단순 | 복잡한 동시 작업에 필요 |
| **스케줄링** | 수동(메인 루프 + 인터럽트) | 우선순위에 따른 선제적 스케줄링 |
| **확장성** | 기능을 추가하기 어려움 | 작업 추가가 용이함 |
| **기억** | 최소한의 오버헤드 | 작은 오버헤드(몇 KB) |

## 통신 프로토콜
### 유선 프로토콜
| 프로토콜 | 속도 | 거리 | 사용 사례 |
|----------|---------|----------|----------|
| **UART** | 최대 1Mbps | 쇼트(온보드) | 디버그 콘솔; GPS 모듈 |
| **SPI** | 최대 100MHz | 쇼트(온보드) | 고속 주변기기(디스플레이, 플래시) |
| **I²C** | 최대 3.4MHz | 쇼트(온보드) | 센서; 핀 수가 적은 통신 |
| **할 수 있습니다** | 최대 1Mbps | 최대 1km | 자동차; 산업 |
| **이더넷** | 10Mbps~100Gbps | 최대 100m | 네트워킹; 산업용(확장 포함) |
| **USB** | 최대 40Gbps(USB4) | 최대 5m | 주변기기; 충전 중 |
### 무선 프로토콜
| 프로토콜 | 범위 | 힘 | 속도 | 사용 사례 |
|----------|---------|-------|-------|----------|
| **와이파이** | ~100m | 높음 | 최대 Wi-Fi 7(46Gbps 이론) | 고대역폭 IoT; 스트리밍 |
| **블루투스 클래식** | ~100m | 중간 | 1~3Mbps | 오디오; 파일 전송 |
| **BLE**(블루투스 저에너지) | ~100m | 매우 낮음 | 1-2Mbps | 웨어러블; 비콘; 센서 |
| **지그비** | ~100m(메쉬) | 낮음 | 250kbps | 홈 오토메이션; 산업용 센서 |
| **Z-웨이브** | ~100m(메쉬) | 낮음 | 100kbps | 홈 오토메이션 |
| **LoRa / LoRaWAN** | 최대 15km | 매우 낮음 | 0.3~50kbps | 농업; 유용; 도시 전체 센서 |
| **NB-IoT** | 셀룰러 범위 | 낮음 | 250kbps | 계량; 자산 추적 |
| **스레드 / 물질** | ~100m(메시) | 낮음 | 보통 | 스마트 홈(애플, 구글, 아마존) |
| **셀룰러(4G/5G)** | 글로벌 | 높음 | 높음 | 연결된 차량; 원격 모니터링 |

## IoT 아키텍처
### IoT 스택
| 레이어 | 기능 | 예 |
|-------|----------|---------|
| **기기** | 센서, 액추에이터, 마이크로컨트롤러 | ESP32, STM32, 라즈베리 파이 |
| **연결성** | 네트워크 프로토콜 | MQTT, HTTP, CoAP, LoRaWAN |
| **엣지 컴퓨팅** | 장치 근처에서 처리 | AWS 그린그래스, Azure IoT Edge |
| **클라우드 플랫폼** | 데이터 수집, 저장, 처리 | AWS IoT, Azure IoT Hub, Google Cloud IoT |
| **신청** | 대시보드, 분석, 경고 | Grafana, 맞춤형 웹 앱 |
### IoT 통신 프로토콜
| 프로토콜 | 패턴 | 최고의 대상 |
|------------|---------|----------|
| **MQTT** | 게시/구독 경량 | 대부분의 IoT 애플리케이션; 낮은 대역폭 |
| **HTTP/레스트** | 요청/응답 | 단순성이 중요한 경우; 웹 통합 |
| **CoAP** | 요청/응답 UDP 기반 | 제한된 장치; 저전력 |
| **AMQP** | 메시지 대기열 | 엔터프라이즈 IoT; 안정적인 배송 |
| **웹소켓** | 양방향; 지속적인 연결 | 실시간 대시보드 실시간 데이터 |
### MQTT 세부정보
| 개념 | 설명 |
|---------|-------------|
| **브로커** | 메시지를 라우팅하는 중앙 서버(Mosquitto, EMQX, HiveMQ) |
| **주제** | 계층적 주소(예:`home/living-room/temperature`) |
| **QoS** | 0(최대 한 번), 1(적어도 한 번), 2(정확히 한 번) |
| **보존된 메시지** | 주제에 대한 마지막 메시지입니다. 신규 가입자에게 전달 |
| **마지막 유언** | 클라이언트 연결이 예기치 않게 끊어지면 메시지가 게시됩니다. |

## 엣지 컴퓨팅
모든 것을 클라우드로 보내는 대신 소스 근처에서 데이터를 처리합니다.
| 혜택 | 설명 |
|---------|-------------|
| **지연시간 단축** | 클라우드로의 왕복이 없습니다. 즉각적인 결정 |
| **대역폭 절약** | 요약이나 예외사항만 보내기 |
| **개인정보보호** | 민감한 데이터가 온프레미스에 유지됨 |
| **신뢰성** | 인터넷이 다운되었을 때 작동 |
| 플랫폼 | 설명 |
|----------|-------------|
| **AWS 그린그래스** | 엣지 디바이스에서 Lambda 함수 실행 |
| **Azure IoT Edge** | 에지 장치에서 컨테이너 실행 |
| **엔비디아 젯슨** | GPU 가속 엣지 AI(오린, 나노) |
| **라즈베리 파이** | 경량 엣지 컴퓨팅 |

## 펌웨어 업데이트(OTA)
무선 업데이트를 통해 버그를 수정하고 배포된 장치에 기능을 추가할 수 있습니다.
| 우려사항 | 솔루션 |
|---------|----------|
| **신뢰성** | 듀얼 뱅크 플래시; 실패 시 롤백 |
| **보안** | 서명된 이미지 암호화된 전송 |
| **사이즈** | 델타 업데이트(변경된 부분만) |
| **연결성** | 장치가 온라인 상태가 될 때의 대기열 업데이트 |

## 요약
임베디드 시스템과 IoT는 소프트웨어와 물리적 세계의 교차점을 나타냅니다. 모터를 제어하는 ​​마이크로컨트롤러부터 클라우드에 연결된 센서 네트워크에 이르기까지 웹이나 앱 개발과는 다른 사고방식(제한된 리소스, 실시간 요구 사항, 긴 수명, 버그로 인한 실제 세계의 결과)이 필요합니다. 생태계는 엄청나게 성숙했습니다. ESP-IDF 및 Zephyr와 같은 프레임워크를 통해 전문적인 개발이 가능해지고 AWS IoT 및 Azure IoT Hub와 같은 플랫폼이 클라우드 측면을 처리합니다. 핵심 기술은 하드웨어 인터페이스, 통신 프로토콜, 전원 관리 및 개입 없이 수년 동안 안정적으로 실행되어야 하는 소프트웨어를 작성하는 규율을 이해하는 것입니다.
