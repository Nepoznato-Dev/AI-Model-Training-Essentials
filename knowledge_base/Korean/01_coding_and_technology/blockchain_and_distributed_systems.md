# 블록체인 및 분산 시스템
블록체인은 레코드(블록)가 암호화 해시로 연결되는 분산형 추가 전용 원장인 특정 유형의 분산 시스템입니다. 분산 시스템은 여러 컴퓨터가 하나로 함께 작동하도록 만드는 더 넓은 분야입니다. 두 개념 모두 암호화폐부터 분산 데이터베이스, 글로벌 서비스를 지원하는 합의 알고리즘에 이르기까지 현대 인프라를 이해하는 데 중요합니다.
---

## 분산 시스템 기초
### 왜 분산 시스템인가?
| 동기부여 | 설명 |
|------------|-------------|
| **확장성** | 더 많은 로드를 처리하려면 더 많은 시스템을 추가하세요 |
| **내결함성** | 일부 기계에 장애가 발생하더라도 시스템은 계속 작동합니다 |
| **지리적 분포** | 인근 데이터 센터의 사용자에게 서비스 제공 |
| **전문성** | 다양한 기계가 다양한 작업을 처리합니다 |
### 주요 개념
| 개념 | 설명 | 도전 |
|---------|-------------|------------|
| **합의** | 모든 노드가 값에 동의하도록 하기 | 네트워크 파티션; 비잔틴 단층 |
| **복제** | 여러 노드에 걸쳐 데이터 복사 | 일관성과 가용성 |
| **파티셔닝(샤딩)** | 노드 간 데이터 분할 | 핫스팟; 교차 샤드 쿼리 |
| **일관성 모델** | 다양한 독자가 보는 내용 보장 | 강력한 일관성은 느립니다. 최종 일관성은 사용자를 놀라게 할 수 있습니다 |
| **CAP 정리** | 일관성, 가용성, 파티션 허용 중 2개만 가질 수 있습니다. 실제로는 분할 허용이 필요합니다. C 또는 A를 선택하세요 |
### CAP 정리
| 선택 | 당신이 얻는 것 | 당신이 포기한 것 | 예 |
|---------|-------------|----|---------|
| **CP** | 일관성 + 파티션 허용 | 파티션 중에 일부 노드를 사용하지 못할 수 있음 | HBase, 몽고DB, 레디스 |
| **AP** | 사용 가능 + 파티션 허용 | 읽기 시 오래된 데이터가 반환될 수 있음 | 카산드라, DynamoDB, CouchDB |
| **캘리포니아** | 일관성 + 사용 가능 | 네트워크 파티션을 허용할 수 없음 | 단일 노드 데이터베이스(실제로 분산되지 않음) |

## 합의 알고리즘
분산 노드는 시스템 상태에 어떻게 동의합니까?
| 알고리즘 | 유형 | 내결함성 | 사용됨 |
|------------|------|---|---------|
| **팍소스** | 충돌 내결함성 | 2f+1개 노드에서 최대 f개의 오류 발생 | 구글 처비; 기초이론 |
| **뗏목** | 충돌 내결함성 | 2f+1개 노드에서 최대 f개의 오류 발생 | etcd, 영사, TiKV |
| **PBFT** | 비잔틴 내결함성 | 3f+1개 노드에서 최대 f개의 오류 발생 | 하이퍼레저 패브릭 |
| **작업 증명** | 비잔틴 내결함성 | 해시 파워에 따라 다름 | 비트코인 |
| **지분 증명** | 비잔틴 내결함성 | 지분에 따라 다름 | 이더리움 2.0, 카르다노 |
### 뗏목(간체)
| 역할 | 책임 |
|------|---------------|
| **리더** | 모든 클라이언트 요청을 처리합니다. 팔로어에게 로그 항목을 보냅니다 |
| **팔로워** | 리더의 요청에 응답합니다. 선거 투표 |
| **후보** | 리더가 되기 위한 투표 요청 |
1. 모든 노드는 추종자로 시작합니다.
2. 팔로어가 선출 시간 초과에 대한 리더의 연락을 받지 못한 경우 후보가 됩니다.
3. 후보자가 투표를 요청합니다. 가장 많은 표를 얻은 사람이 리더가 됩니다.
4. 리더는 로그 항목을 팔로어에게 복제합니다.
5. 과반수가 확인하면 참가가 확정됩니다.

## 블록체인
### 블록체인 작동 방식
| 구성요소 | 설명 |
|------------|-------------|
| **차단** | 일괄 트랜잭션 + 메타데이터 + 이전 블록의 해시 |
| **해시** | 블록 내용의 암호화 지문 |
| **체인** | 각 블록은 이전 블록의 해시를 참조하여 변경할 수 없는 체인을 생성합니다 |
| **합의** | 네트워크 참가자는 추가할 블록에 동의합니다 |
| **머클 트리** | 블록의 모든 거래를 요약하는 해시 트리 |
### 블록체인이 변조하기 어려운 이유
1. 각 블록에는 이전 블록의 해시가 포함됩니다.
2. 거래를 변경하면 블록의 해시가 변경됩니다.
3. 변경된 해시가 체인을 끊습니다. 이후의 모든 블록은 무효화됩니다.
4. 공격자는 모든 후속 블록을 다시 채굴하고 네트워크의 50% 이상을 제어해야 합니다.
### 블록체인의 종류
| 유형 | 액세스 | 검증인 | 예 |
|------|---------|------------|---------|
| **공개(무허가)** | 누구나 읽고 쓸 수 있습니다 | 공개 합의(PoW, PoS) | 비트코인, 이더리움 |
| **비공개(허가됨)** | 제한된 액세스 | 알려진 검증인 | 하이퍼레저, 코르다 |
| **컨소시엄** | 조직 그룹의 관리 | 선택된 검증인 | 은행용 R3 Corda |
### 스마트 계약
미리 결정된 조건이 충족되면 실행되는 블록체인에 저장된 자체 실행 코드입니다.
| 플랫폼 | 언어 | 주목할만한 기능 |
|----------|----------|----|
| **이더리움** | 솔리디티, 바이퍼 | 최대 규모의 스마트 계약 생태계 |
| **솔라나** | 러스트, C | 높은 처리량; 낮은 수수료 |
| **카르다노** | 하스켈(플루투스) | 동료 검토; 정식 검증 |
| **하이퍼레저** | 바둑, 자바, 자바스크립트 | 기업; 허가된 |

## 분산 데이터베이스
| 데이터베이스 | 건축 | 일관성 | 최고의 대상 |
|----------|-------------|-------------|----------|
| **카산드라** | 와이드 컬럼; 피어 투 피어 | 조정 가능(최종 쿼럼까지) | 높은 쓰기 처리량; 시계열 |
| **몽고DB** | 문서; 복제 세트 | 최종(인과적 일관성 옵션 포함) | 유연한 스키마; 급속한 발전 |
| **바퀴벌레DB** | 분산 SQL; 뗏목 합의 | 강한 | 분산 SQL; 글로벌 배포 |
| **TiDB** | 분산 SQL; 뗏목(TiKV를 통해) | 강한 | MySQL 호환; 수평 확장 |
| **DynamoDB** | 키-값; 관리 | 최종(또는 일관된 읽기로 강력함) | 서버리스; AWS 통합 |
| **스패너** | 분산 SQL; 팍소스 | 강한 | 구글 클라우드; 글로벌 일관성 |

## 분산 시스템 패턴
| 패턴 | 설명 | 사용 사례 |
|---------|-------------|----------|
| **리더 선출** | 조정할 노드 하나 선택 | 뗏목 리더; 동물원지기 |
| **복제** | 중복성 및 읽기 확장을 위해 데이터 복사 | 데이터베이스 복제본 CDN |
| **샤딩** | 키 범위 또는 해시로 데이터 파티션 | 대규모 데이터베이스 |
| **맵리듀스** | 노드 전체에 걸쳐 계산을 분할합니다. 집계 결과 | 대용량 데이터 처리 |
| **가십 프로토콜** | 노드는 주기적으로 임의의 피어와 상태를 공유합니다 | 클러스터 멤버십; 실패 감지 |
| **2단계 커밋** | 여러 노드에서 트랜잭션 조정 | 분산 데이터베이스 |
| **사가 패턴** | 보상 조치가 포함된 일련의 현지 거래 | 마이크로서비스 트랜잭션 |
| **회로 차단기** | 실패한 서비스 호출을 중지하세요. 빨리 실패 | 회복력; 계단식 오류 방지 |

## 분산 시스템의 과제
| 도전 | 설명 | 완화 |
|------------|-------------|------------|
| **네트워크 파티션** | 노드가 통신할 수 없습니다 | CAP 트레이드오프; 백오프로 재시도 |
| **시계 왜곡** | 노드마다 시계가 다릅니다 | 논리적 시계를 사용하세요. NTP; 벽시계 시간에 의존하지 마세요 |
| **비잔틴 단층** | 거짓말을 하거나 임의로 행동하는 노드 | BFT 합의; 블록체인 |
| **분할 두뇌** | 두 노드 모두 자신이 리더라고 생각합니다 | 펜싱; 정족수 기반 결정 |
| **계단식 오류** | 하나의 실패가 다른 실패를 촉발합니다 | 회로 차단기; 격벽; 우아한 저하 |
| **데이터 일관성** | 복제본을 동기화 상태로 유지 | 일관성 모델 갈등 해결 |
---

## 요약
분산 시스템은 최신 소프트웨어가 확장되고, 장애를 극복하며, 전 세계적으로 사용자에게 서비스를 제공하는 방법입니다. 합의 알고리즘(Raft, Paxos)은 노드의 동의를 보장합니다. 블록체인은 암호화 검증 및 분산화를 추가하여 무신뢰 원장을 생성합니다. 분산 데이터베이스(Cassandra, CockroachDB, DynamoDB)는 대규모로 데이터를 처리합니다. CAP 정리에 의해 포착된 근본적인 균형은 네트워크가 신뢰할 수 없을 때 일관성과 가용성 사이에 있습니다. 이러한 개념을 이해하는 것은 인터넷 규모에서 작동하는 시스템을 구축하는 데 필수적입니다.
