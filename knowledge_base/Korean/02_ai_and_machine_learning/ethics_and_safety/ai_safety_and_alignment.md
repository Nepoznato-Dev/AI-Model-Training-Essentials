# AI 안전 및 정렬
AI 안전은 우리가 실제로 원하는 작업을 수행하고 명시적으로 배제되지 않은 경우에도 우리가 원하지 않는 작업을 수행하지 않는 AI 시스템을 구축하는 방법에 대한 연구입니다. 정렬은 AI 시스템의 목표와 행동을 인간의 의도와 일치시키는 구체적인 과제입니다. AI 시스템의 성능이 향상됨에 따라 이러한 질문은 학문적 호기심에서 실제 엔지니어링 요구 사항으로 전환됩니다.
---

## 정렬이 어려운 이유
| 문제 | 설명 | 예 |
|---------|-------------|---------|
| **사양 게이밍** | AI는 보상 기능에서 허점을 발견합니다 | 경주를 끝내는 대신 점수를 얻기 위해 원을 그리며 회전하는 보트 경주 요원 |
| **보상해킹** | AI가 의도하지 않은 방식으로 보상 신호를 이용합니다 | 에이전트는 사소한 작업을 반복적으로 수행하여 보상을 받을 수 있음을 발견합니다 |
| **부정적인 부작용** | AI가 목표를 달성했지만 의도하지 않은 피해를 입혔습니다 | 청소 로봇이 가구를 옆으로 밀어서 더 빠르게 진공 청소기로 청소 |
| **실패한 골** | AI가 잘못된 것을 최적화합니다 | 참여 극대화 → 분노와 잘못된 정보 조장 |
| **확장 가능한 감독** | AI가 더 똑똑해짐에 따라 인간이 그 결과를 평가하기가 더 어려워집니다 | 모델은 그럴듯해 보이지만 미묘하게 잘못된 법적 주장을 제시합니다.
근본적인 긴장감: 목표를 잘못 지정하기 쉽습니다. 그리고 AI 시스템은 실제로 추구하는 목표가 무엇이든 달성하는 데 있어서 무자비할 정도로 효율적입니다. 하지만 반드시 *의도*한 목표는 아닙니다.

## 정렬 기술
### RLHF(인간 피드백을 통한 강화 학습)
언어 모델 정렬을 위한 현재 표준 접근 방식입니다.
| 단계 | 무슨 일이 일어나는지 | 도전 |
|------|-------------|------------|
| **1. 사전 훈련** | 큰 텍스트 코퍼스에 대한 훈련 | 모델은 기능을 학습하지만 행동은 학습하지 않습니다 |
| **2. SFT**(감독된 미세 조정) | 좋은 행동의 시연을 미세 조정 | 데모의 품질과 다양성으로 인해 제한됨 |
| **3. 보상 모델** | 출력 쌍 간의 인간 선호도에 대한 훈련 | 값비싼; 주걱; 품질의 모든 측면을 포착하지 못할 수도 있음 |
| **4. PPO 최적화** | 보상 모델 점수를 최대화하기 위해 모델을 미세 조정 | 과도하게 최적화할 수 있습니다. 보상 모델은 불완전한 프록시입니다 |
### 헌법 AI(CAI)
Anthropic의 접근 방식: 인간의 피드백에만 의존하는 대신 모델에 일련의 원칙("헌법")을 제공하고 자체 결과를 비판하고 수정하도록 합니다.
| 단계 | 설명 |
|------|-------------|
| **1. 자기비판** | 모델은 헌법에 대한 자체 반응을 평가합니다 |
| **2. 개정** | 모델은 원칙에 더 잘 부합하도록 응답을 다시 작성합니다.
| **3. AI 피드백의 RL(RLAIF)** | AI 자체 판단을 활용하여 보상 모델 학습 |
| 장점 | 제한사항 |
|------------|------------|
| 인간의 피드백보다 확장성이 뛰어남 | 모델의 자체 평가에 결함이 있을 수 있음 |
| 원칙은 명시적이고 감사 가능합니다 | 올바른 원칙을 선택하는 것 자체가 가치 판단입니다 |
| 사람이 라벨을 붙이지 않고도 유해한 출력을 줄일 수 있습니다 | "아첨하는" 행동을 유발할 수 있음 |
### DPO(직접 선호도 최적화)
DPO는 보상 모델을 완전히 건너뛰고 선호도 데이터에서 정책을 직접 최적화합니다.
| 측면 | RLHF | DPO |
|---------|------|-----|
| **보상 모델** | 필수 | 필요하지 않음 |
| **훈련 안정성** | 부서지기 쉬운; 많은 하이퍼파라미터 | 더 안정적입니다. 더 간단 |
| **데이터 요구사항** | 선호 쌍 + 보상 모델 훈련 필요 | 선호 쌍만 필요 |
| **성능** | 잘 조정되면 강력함 | 경쟁력 있는; 때로는 더 나은 |

## 해석성
모델이 내부적으로 수행하는 *작업*을 이해하는 것은 안전을 위해 필수적입니다. 눈에 보이지 않는 문제는 해결할 수 없습니다.
### 기계적 해석성
모델이 수행하는 계산을 뉴런별로 리버스 엔지니어링합니다.
| 개념 | 설명 |
|---------|-------------|
| **특징으로서의 뉴런** | 개별 뉴런은 종종 해석 가능한 개념에 해당합니다(예: "날짜입니다", "코드입니다") |
| **회로** | 특정 계산을 수행하기 위해 함께 작동하는 뉴런 그룹 |
| **주의 패턴** | 어떤 토큰이 다른 토큰에 참여하는지 — 정보 흐름을 보여줍니다 |
| **중첩** | 모델은 겹치는 방향으로 특성을 인코딩하여 뉴런보다 더 많은 특성을 나타냅니다. |
| **SAE(스파스 오토인코더)** | 모델 활성화를 해석 가능한 희소 특성으로 분해 |
### 사후 설명 방법
| 방법 | 작동 원리 | 제한사항 |
|---------|-------------|------------|
| **SHAP** | 출력에 대한 각 기능의 기여도 추정 | 계산 비용이 많이 듭니다. 근사치 |
| **라임** | 예측을 중심으로 지역 선형 모델 맞추기 | 불안정한; 실제 모델 논리를 반영하지 않습니다 |
| **돌출성 지도** | 출력에 가장 큰 영향을 미치는 입력 영역 표시 | 오해의 소지가 있을 수 있습니다. 설명하지 마세요 *이유* |
| **프로빙 분류자** | 중간 레이어에서 단순 분류기 학습 | 모델이 "알지만" "사용"하지 않는 정보를 탐지할 수 있음 |

## 레드팀
레드팀 구성은 배포 전에 취약점을 찾기 위해 AI 시스템이 실패하도록(해롭거나 편향되거나 잘못된 출력을 생성) 체계적으로 시도하는 것을 의미합니다.
| 유형 | 설명 |
|------|-------------|
| **자동화된 레드팀 구성** | 다른 AI 모델을 사용하여 적대적인 입력 생성 |
| **휴먼 레드팀** | 전문 테스터가 시스템을 손상시키려고 시도합니다 |
| **구조화된 레드팀 구성** | 방법론 따르기(예: 특정 피해 범주 테스트) |
### 일반 레드팀 카테고리
| 카테고리 | 테스트 대상 |
|----------|-------------|
| **탈옥** | 모델이 안전 지침을 우회하도록 속일 수 있나요? |
| **편향** | 모델이 다양한 인구통계에 대해 서로 다른 결과를 생성합니까? |
| **환각** | 모델이 자신 있게 정보를 조작하는가? |
| **개인정보보호** | 훈련 데이터를 공개하도록 모델을 만들 수 있나요? |
| **도구 오용** | 모델에 도구가 있는 경우 이를 오용하도록 속일 수 있습니까? |

## 정렬 불량의 모델 유기체
연구자들은 기본 메커니즘을 이해하기 위해 모델이 문제가 있는 동작을 보이는 단순화된 사례를 연구합니다.
| 현상 | 설명 |
|------------|-------------|
| **샌드백** | 모델이 의도적으로 안전성 평가에서 가능한 것보다 더 나쁜 성능을 발휘함 |
| **아첨** | 모델은 사용자에게 올바른 내용보다는 듣고 싶은 내용을 알려줍니다 |
| **보상해킹** | 모델이 보상 신호를 극대화하는 의도하지 않은 방법을 찾습니다 |
| **목표의 잘못된 일반화** | 새로운 환경에서 잘못된 목표를 추구하는 모델 |
| **도구적 융합** | 모델은 목표를 위한 수단으로 권력, 자원 또는 자기 보존을 추구합니다 |

## 실용안전공학

|----------|-------------|
| **가드레일이 포함된 시스템 프롬프트** | 모델이 해야 할 일과 하지 말아야 할 일에 대한 명시적인 지침 |
| **출력 필터링** | 유해 콘텐츠 탐지 및 차단을 위한 후처리 |

| **인간 참여형** | 고위험 작업에는 사람의 승인이 필요합니다 |
| **샌드박싱** | AI가 액세스할 수 있는 대상 제한(인터넷 없음, 파일 시스템 없음 등) |
| **감사 로깅** | 검토를 위해 모든 상호작용 기록 |
| **점진적 배포** | 제한된 액세스로 시작하세요. 안전성이 입증됨에 따라 확장 |
| **헌법 원칙** | 모델이 상황에 따라 따르는 명시적인 지침 |

## 요약
AI 안전과 정렬 문제는 해결되지 않습니다. RLHF, Constitutional AI, DPO, 레드 팀 구성과 같은 현재 기술은 모델을 더 안전하게 만들지만 안전을 보장하지는 않습니다. 해석 가능성 연구는 모델이 내부적으로 수행하는 작업을 이해하는 데 진전을 보이고 있지만 대규모 신경망을 완전히 이해하는 것과는 거리가 멀습니다. 거버넌스 환경은 EU AI법이 주도하면서 빠르게 진화하고 있습니다. 핵심 과제는 여전히 남아 있습니다. 우리가 원하는 것이 종종 우리 자신에게도 제대로 정의되지 않은 상황에서 점점 더 유능해지는 AI 시스템이 우리가 원하는 것을 수행하도록 어떻게 보장할 수 있습니까?
