# 머신러닝 평가 및 워크플로
문제 프레이밍부터 프로덕션 모니터링까지, 측정항목, 검증, 디버깅에 초점을 맞춘 ML 수명주기에 대한 실용적인 가이드입니다.
---

## ML 워크플로(CRISP-ML)
1. **비즈니스 이해**: 목표와 성공 기준을 정의합니다.
2. **데이터 이해**: 사용 가능한 데이터를 탐색하고 품질 문제를 식별합니다.
3. **데이터 준비**: 데이터를 정리, 변환 및 분할합니다.
4. **모델링**: 모델을 훈련하고 초매개변수를 조정합니다.
5. **평가**: 지표를 기준으로 성과를 평가합니다.
6. **배포**: 프로덕션 환경에 모델을 제공합니다.
7. **모니터링**: 드리프트, 성능 및 이상 현상을 추적합니다.
이는 반복 루프입니다. 평가 결과에 따라 이전 단계를 다시 방문하게 됩니다.
---

## 데이터 분할
### 학습/검증/테스트 분할
- **훈련 세트**(~70%): 모델 매개변수를 맞추는 데 사용됩니다.
- **검증 세트**(~15%): 하이퍼파라미터를 조정하고 모델 변형을 선택하는 데 사용됩니다.
- **테스트 세트**(~15%): 일반화 성능을 추정하기 위해 마지막에 한 번만 사용됩니다.
**중요:** 데이터 유출을 방지하려면 최종 평가까지 테스트 세트를 완전히 그대로 유지해야 합니다.
### 교차 검증(k-겹)
작은 데이터 세트의 경우 k-겹 교차 검증을 사용합니다. 즉, 데이터를 k 폴드로 분할하고, k-1에 대해 훈련하고, 나머지에 대해 검증하고, k번 반복합니다. 성능을 평균화하십시오. k=5 또는 k=10이 일반적입니다.
### 층화 분할
클래스가 불균형한 분류의 경우 계층화된 분할을 사용하여 각 하위 집합의 클래스 비율을 유지합니다.
### 시간 기반 분할
시계열 데이터의 경우 무작위가 아닌 시간순으로 분할합니다(과거 학습, 미래 테스트).

## 평가 지표
### 분류 측정항목
| 미터법 | 측정 대상 | 가장 적합한 용도 |
|---------|------|---------------|
| **정확성** | (TP + TN) / (TP + TN + FP + FN) | 균형 잡힌 데이터세트 |
| **정밀도** | TP / (TP + FP) | 거짓 긍정으로 인해 비용이 많이 드는 경우(예: 스팸 감지) |
| **리콜** | TP / (TP + FN) | 위음성(false negatives)에 비용이 많이 드는 경우(예: 암 검진) |
| **F1 점수** | 정밀도와 재현율의 조화 평균 | 불균형 데이터세트, 단일 숫자 측정항목 |
| **AUC-ROC** | ROC 곡선 아래 영역 TPR과 FPR 사이의 절충 | 임계값과 무관한 일반 분류기 성능 |
| **AUC-PR** | 정밀도-재현율 곡선 아래 영역 | 불균형이 심한 데이터 세트 |
**정의:**
- TP = 참양성
- TN = 참음성
- FP = 거짓 긍정(유형 I 오류)
- FN = 거짓 음성(유형 II 오류)
### 회귀 측정항목
| 미터법 | 측정 대상 | 이상치에 대한 민감도 |
|---------|------|-------------|
| **MSE**(평균 제곱 오차) | 평균 제곱 차이 | 높음 |
| **RMSE**(제곱평균제곱근 오류) | MSE의 제곱근(목표와 동일한 단위) | 높음 |
| **MAE**(평균 절대 오류) | 평균 절대 차이 | 낮음 |
| **R²** (결정계수) | 분산 비율 설명 | 직접적으로는 없지만 간접적으로 이상값에 민감함 |
### 순위 및 검색 지표
- **Precision@k**: Top-k 추천 중 관련 항목의 비율입니다.
- **Recall@k**: top-k에 나타나는 모든 관련 항목의 비율입니다.
- **NDCG**(정규화된 할인 누적 이익): 포지션 관련성을 설명합니다.
- **적중률**: 해당 항목이 top-k에 나타나는지 여부입니다.
### 생성/LLM 측정항목
- **당황**: 텍스트를 길게 눌러 모델이 얼마나 "놀랐는지"(낮을수록 좋음)
- **BLEU**: n-gram이 참조 번역과 겹칩니다(정밀도 중심).
- **ROUGE**: 요약을 위한 회상 중심 중복입니다.
- **BERTScore**: 상황별 임베딩을 사용한 의미론적 유사성(BLEU보다 강력함)
- **METEOR**: WordNet 동의어 및 어간에 정렬됩니다.

## 평가의 함정
### 데이터 유출
테스트 세트의 정보가 실수로 훈련에 영향을 미칠 때 발생합니다.
- **예방:** 기능 엔지니어링, 정규화 또는 초매개변수 조정을 위해 테스트 데이터를 사용하지 마세요.
- **탐지:** 모델 점수가 의심스러울 정도로 높으면 누출을 의심해 보세요.
### 과적합
모델은 훈련 데이터에서는 잘 작동하지만 검증/테스트에서는 성능이 좋지 않습니다.
- **완화:** 정규화, 조기 중지, 아키텍처 단순화를 사용하거나 더 많은 데이터를 수집합니다.
### 과소적합
모델은 훈련과 검증 모두에서 성능이 좋지 않습니다.
- **완화:** 더 복잡한 모델을 사용하거나 기능을 추가하거나 정규화를 줄입니다.
### 불균형 데이터
- **완화:** 클래스 가중치, 오버샘플링(SMOTE), 언더샘플링을 사용하거나 정확성보다는 적절한 측정항목(F1, AUC-PR)을 사용하세요.
### 시간적 드리프트(개념 드리프트)
기능과 대상 간의 관계는 시간이 지남에 따라 변경됩니다.
- **완화:** 주기적으로 재교육하고 성능을 모니터링하며 드리프트 감지 알고리즘을 사용합니다.

## 하이퍼파라미터 튜닝
- **그리드 검색**: 사전 정의된 하이퍼파라미터 세트의 모든 조합을 철저하게 시도합니다. 간단하지만 계산 비용이 많이 듭니다.
- **임의 검색**: 분포에서 무작위 조합을 샘플링합니다. 고차원 공간에 대한 그리드 검색보다 더 효율적입니다.
- **베이지안 최적화**: 목적 함수의 확률 모델을 구축하고 하이퍼파라미터를 지능적으로 선택합니다. 라이브러리: Optuna, Hyperopt, scikit-optimise.
- **자동 조정**: 분산 조정을 위해 Optuna, Ray Tune 또는 Weights & Biases Sweeps와 같은 도구를 사용합니다.
**공통 하이퍼파라미터에 대한 권장 검색 범위:**
| 매개변수 | 제안된 범위(로그 규모) |
|------------|----------------|
| 학습률 | 1e-5에서 1e-1로 |
| 배치 크기 | 16, 32, 64, 128, 256 |
| 레이어 수(NN) | 2~6 |
| 뉴런 수(NN) | 32~1024 |
| 정규화(L2) | 1e-6에서 1e-2로 |
| 트리 깊이(XGBoost) | 3~12 |
---

## 모델 선택 및 검증
1. **기준 모델**: 하한을 설정하기 위해 간단한 경험적 모델이나 단순 모델(예: 로지스틱 회귀, 평균 예측 변수)로 시작합니다.
2. **후보 모델**: 여러 모델 계열(예: Random Forest, XGBoost, 신경망)을 훈련합니다.
3. 검증 세트의 각 후보를 **교차 검증**합니다.
4. **측정항목을 비교**(신뢰 구간 포함)하고 가장 적합한 후보를 선택합니다.
5. 유지된 테스트 세트에 대한 **최종 평가**.
6. **오류 분석**: 모델이 잘못된 예를 살펴보세요. 패턴(예: 희귀 클래스, 모호한 입력)을 식별하고 데이터 준비 또는 기능 엔지니어링에 통찰력을 다시 제공합니다.

## 배포 및 모니터링
### 제공 패턴
- **일괄 추론**: 대량의 데이터를 오프라인으로 처리합니다(예: 야간 추천).
- **온라인 추론**: API를 통한 실시간 예측(예: 신용 점수, 사기 감지)
- **스트리밍 추론**: 지연 시간이 짧은 이벤트 기반 실시간(예: IoT 센서 알림).
### 모델 모니터링
- **성능 모니터링**: 실시간 데이터에서 시간 경과에 따른 정확도/F1을 추적합니다(실측이 가능한 경우).
- **데이터 드리프트**: 입력 특성 분포의 변화를 모니터링합니다(예: PSI – 인구 안정성 지수 사용).
- **개념 드리프트**: 입력과 출력 간의 관계 변화를 모니터링합니다.
- **예측 드리프트**: 예측된 결과의 분포를 추적합니다.
- **대기 시간 및 처리량**: SLA(서비스 수준 계약)가 충족되는지 확인하세요.
### 로깅 및 경고
- 모든 예측 요청 및 응답을 기록합니다(익명화 포함).
- 다음에 대한 알림 설정:
  - 성능이 크게 저하되었습니다.
  - 누락되거나 잘못된 입력의 비율이 높습니다.
  - 모델 출력이 예상 범위를 벗어났습니다.
### 모델 버전 관리 및 레지스트리
- 모델 레지스트리(예: MLflow, Weights & Biases, Sagemaker 모델 레지스트리)를 사용하여 모델, 메타데이터 및 평가 결과를 저장하고 버전을 지정합니다.
- 훈련 코드와 데이터 버전을 모델과 함께 (DVC 또는 Git LFS를 통해) 저장합니다.

## 실용적인 작업 흐름 체크리스트
- [ ] 문제 프레임 및 성공 지표가 정의되었습니다.
- [ ] 데이터 탐색이 수행되었습니다(결측값, 이상치, 분포).
- [ ] 훈련/검증/테스트 분할이 생성되었습니다(필요한 경우 계층화됨).
- [ ] 기본 모델이 확립되었습니다.
- [ ] 훈련되고 검증된 후보 모델.
- [ ] 하이퍼파라미터가 조정되었습니다.
- [ ] 교차 검증을 통해 가장 좋은 모델이 선택되었습니다.
- [ ] 테스트 세트에 대한 최종 평가입니다.
- [ ] 오류 분석이 수행되었습니다.
- [ ] 배포 계획이 준비되었습니다(서비스 인프라).
- [ ] 모니터링 대시보드 설정.
- [ ] 문서화(데이터 카드, 모델 카드)가 완료되었습니다.
