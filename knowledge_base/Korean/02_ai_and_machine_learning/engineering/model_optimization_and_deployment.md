# 모델 최적화 및 배포
대규모 AI 모델을 교육하는 것은 중요한 성과이지만 이를 효율적으로 배포하는 데에는 대부분의 엔지니어링 노력이 필요합니다. 응답하는 데 10초가 걸리거나 8개의 A100 GPU가 필요한 모델은 대부분의 실제 애플리케이션에 비실용적입니다. 모델 최적화는 허용 가능한 품질을 유지하면서 모델을 더 작고, 빠르고, 비용 효율적으로 만드는 프로세스입니다. 이 파일은 양자화, 가지치기, 증류 및 프로덕션에 모델을 배포하기 위한 실용적인 도구를 다룹니다.
---

## 왜 최적화해야 하나요?
| 우려사항 | 영향 |
|---------|---------|
| **지연 시간** | 사용자는 1초 이내에 응답을 기대합니다. 100ms가 추가될 때마다 참여가 사라집니다 |
| **비용** | GPU 추론은 비용이 많이 듭니다. 700억 모델의 비용은 클라우드 하드웨어에서 100만 개 토큰당 ~$0.05-0.15 |
| **메모리** | FP32의 7B 모델에는 28GB의 VRAM이 필요합니다. 대부분의 소비자 GPU는 8~24GB |
| **에너지** | 대형 모델을 실행하면 상당한 전력이 소비됩니다. 모바일과 엣지에 대한 문제 |
| **규모** | 수백만 명의 사용자에게 서비스를 제공하려면 사용 가능한 하드웨어에 맞는 모델이 필요합니다 |
---

## 양자화
양자화는 모델 가중치의 정밀도를 32비트 부동 소수점(FP32)에서 INT8, INT4 또는 그보다 낮은 형식으로 줄입니다.
### 정밀 형식
| 형식 | 무게당 비트 | 7B 모델용 메모리 | 품질 |
|---------|---|---------|---------|
| **FP32** | 32 | 28GB | 기준선(완전 정밀도) |
| **FP16 / BF16** | 16 | 14GB | FP32와 거의 동일 |
| **INT8** | 8 | 7GB | 매우 작은 품질 손실 |
| **INT4** | 4 | 3.5GB | 보통 수준의 품질 손실; 아직 사용 가능 |
| **INT3 / INT2** | 3-2 | 2.6~1.75GB | 상당한 품질 손실; 연구 단계 |
### 양자화 방법
| 방법 | 그런 일이 발생하면 | 작동 원리 | 품질 |
|---------|---|---------------|---------|
| **훈련 후 양자화(PTQ)** | 훈련이 완료된 후 | 작은 데이터 세트에서 모델을 보정합니다. 최적의 척도 찾기 | INT8에 좋습니다. INT4에서 성능 저하 |
| **GPTQ** | 훈련 후 | 대략적인 2차 정보를 사용한 GPU 친화적인 INT4 양자화 | INT4의 좋은 품질 |
| **AWQ**(활성화 인식 중량 양자화) | 훈련 후 | 활성화 크기를 기반으로 두드러진 가중치 보호 | INT4의 GPTQ보다 우수함 |
| **GGUF**(llama.cpp 형식) | 훈련 후 | CPU 친화적인 양자화; 레이어당 혼합 정밀도 | CPU 추론에 최적화됨 |
| **양자화 인식 훈련(QAT)** | 훈련 중 | 모델이 대처 방법을 학습할 수 있도록 훈련 중 양자화 시뮬레이션 | 최고의 품질; 재교육이 필요합니다 |
### 실질적인 영향
| 모델 | FP16 크기 | INT4 크기 | 속도 향상 | 품질 손실 |
|-------|------------|------------|---------|-------------|
| **라마 7B** | 14GB | 3.5GB | 2-4배 | 벤치마크에서 ~1-2% |
| **라마 70B** | 140GB | 35GB | 2~3배 | 벤치마크에서 ~2-3% |

## 가지치기
가지치기는 훈련된 모델에서 불필요한 가중치나 뉴런을 제거합니다.
| 유형 | 설명 | 장점 | 도전 |
|------|-------------|------------|------------|
| **구조화되지 않음** | 개별 가중치 제거(0으로 설정) | 최고의 압축률 | 희박한 하드웨어 지원 필요 |
| **구조적** | 전체 뉴런, 주의 헤드 또는 레이어 제거 | 모델 크기를 직접적으로 줄임 | 품질이 더 떨어질 수 있음 |
| **크기 기반** | 절대값이 가장 작은 가중치 제거 | 단순한; 잘 작동합니다 | 중요한 작은 가중치를 놓칠 수 있음 |
| **중요도 기반** | 출력에 대한 기여도를 기준으로 가중치 제거 | 더 나은 품질 보존 | 계산 비용이 더 많이 듭니다 |
### 가지치기 파이프라인
| 단계 | 설명 |
|------|-------------|
| 1. 기차 | 전체 모델을 정상적으로 훈련 |
| 2. 점수 | 각 가중치/뉴런에 대한 중요도 점수 계산 |
| 3. 가지치기 | 가장 덜 중요한 요소 제거 |
| 4. 미세 조정 | 손실된 정확도를 복구하기 위해 재훈련 |
| 5. 반복 | 더 높은 압축률을 위해 가지치기 및 미세 조정 반복 |

## 지식 증류
큰 "교사" 모델을 모방하기 위해 작은 "학생" 모델을 훈련합니다.
| 구성요소 | 역할 |
|------------|------|
| **선생님** | 대형 고품질 모델 |
| **학생** | 선생님으로부터 배우는 작은 모델 |
| **증류손실** | 학생은 교사의 출력 분포(소프트 라벨)를 일치시키려고 시도합니다 |
### 증류의 종류
| 유형 | 설명 | 예 |
|------|-------------|---------|
| **로짓 기반** | 학생이 교사의 출력 확률과 일치함 | 힌튼의 오리지널 증류 |
| **기능 기반** | 학생은 교사의 중간 표현과 일치합니다 | 핏넷 |
| **관계 기반** | 학생이 샘플 간의 관계를 일치시킵니다 | RKD(관계형 지식 증류) |
| **데이터 프리** | 원본 훈련 데이터가 필요하지 않습니다. 선생님 세대를 이용하세요 | DAFL, 딥인버전 ​​|
### 주목할만한 증류 사례
| 선생님 | 학생 | 결과 |
|---------|---------|---------|
| **GPT-4** | GPT-3.5 터보(소문 있음) | GPT-4의 품질을 최대한 활용한 소형 모델 |
| **BERT-대형** | 디스틸버트 | 40% 더 작고, 60% 더 빠르며, BERT 성능의 97% |
| **라마 70B** | LLaMA 7B(증류를 통해) | 대형 모델 품질에 접근하는 오픈 소스 소형 모델 |

## LLM 관련 최적화
### KV-캐시 최적화
대규모 언어 모델은 재계산을 피하기 위해 이전 토큰의 키-값 쌍을 캐시합니다.
| 기술 | 설명 | 영향 |
|------------|-------------|---------|
| **다중 쿼리 어텐션(MQA)** | 모든 관심 헤드는 하나의 KV 쌍을 공유합니다 | 메모리를 줄입니다. 약간의 품질 손실 |
| **그룹형 쿼리 어텐션(GQA)** | 헤드 그룹은 KV 쌍을 공유합니다 | MQA와 표준 주의 사이의 균형 |
| **슬라이딩 윈도우 주의** | 마지막 W 토큰에만 참여 | 긴 컨텍스트에 대한 KV 캐시 크기 감소 |
### 추측적 디코딩
| 단계 | 설명 |
|------|-------------|
| 1 | 작은 "초안" 모델은 K 토큰을 빠르게 생성합니다 |
| 2 | 대형 모델은 한 번의 전달 패스로 모든 K 토큰을 확인합니다 |
| 3 | 승인된 토큰은 보관됩니다. 거부된 항목이 재생성됩니다 |
결과: 품질 손실 없이 생성 속도가 2~3배 향상되었습니다(최종 결정권은 항상 대형 모델에 있습니다).
### 플래시 주의
| 기능 | 설명 |
|---------|-------------|
| **문제** | 표준 주의에는 주의 매트릭스 |에 O(n²) 메모리가 필요합니다.
| **솔루션** | 블록 단위로 주의를 계산합니다. 메모리에서 전체 행렬을 구체화하지 마십시오 |
| **결과** | 2~4배 더 빠릅니다. 훨씬 더 긴 컨텍스트 창을 지원합니다 |
| **변형** | Flash Attention 2(더 빠름), FlashDecoding(추론에 최적화됨) |

| **일괄 추론** | 일정에 따라 데이터를 대량으로 처리 | 실시간이 필요하지 않은 경우 |

## 실용적인 팁
- **양자화부터 시작하세요.** INT4 양자화(AWQ 또는 GPTQ)는 크기 대비 품질이 가장 좋은 균형을 제공합니다. 대부분의 7B 모델은 INT4의 단일 소비자 GPU에서 편안하게 실행됩니다.
- **LLM 제공을 위해 vLLM을 사용합니다.** 처리량이 높은 LLM 추론을 위한 가장 빠른 오픈 소스 옵션입니다.
- **최적화하기 전에 프로필을 작성하세요.** 실제로 시간이 소요되는 부분을 측정하세요. 병목 현상이 발생하는 원인은 컴퓨팅이 아닌 메모리 대역폭인 경우가 많습니다.
- **작업에 모델을 연결하세요.** 7B 모델은 대부분의 작업에 적합합니다. 7B로 충분할 때 70B를 사용하지 마십시오.
- **증류를 고려하세요.** 생산을 위해 작고 빠른 모델이 필요한 경우 처음부터 훈련하는 대신 더 큰 모델에서 추출하세요.
- **지속적으로 모니터링합니다.** 데이터 분포가 바뀌면서 시간이 지나면서 모델 성능이 저하될 수 있습니다. 대기 시간, 처리량 및 품질 지표를 추적합니다.
---

## 요약
모델 최적화는 연구와 생산 사이의 가교입니다. 양자화는 품질 손실을 최소화하면서 모델을 4~8배 축소합니다. 가지치기는 사중을 제거합니다. 증류는 지식을 큰 모델에서 작은 모델로 전달합니다. Flash Attention 및 KV 캐시 트릭을 사용하면 추론 속도가 빨라집니다. 이러한 기술을 함께 사용하면 데이터 센터가 필요한 모델이 노트북이나 휴대폰에서 실행되는 모델로 전환됩니다. 이 분야는 빠르게 움직이고 있습니다. 작년에 8개의 A100이 필요했던 것이 오늘날 소비자 GPU에서 실행됩니다.
