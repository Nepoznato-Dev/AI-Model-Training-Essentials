# ML 엔지니어링 및 MLOps
기계 학습 모델을 구축하는 것은 전투의 절반에 불과합니다. 프로덕션에 투입하고 안정적인 실행을 유지하며 드리프트를 모니터링하고 반복하는 것이 ML 엔지니어링과 MLOps가 필요한 부분입니다. 이 파일은 실험부터 프로덕션 시스템까지 전체 수명주기를 다룹니다.
---

## ML 수명 주기
| 단계 | 설명 | 주요 활동 |
|-------|-------------|---------------|
| **1. 문제 정의** | 비즈니스 문제를 ML 작업으로 구성 | 측정항목, 제약조건, 성공 기준 정의 |
| **2. 데이터 수집** | 훈련 데이터 수집 및 라벨링 | ETL, 라벨링, 확대 |
| **3. 실험** | 모델 훈련 및 평가 | 기능 엔지니어링, 하이퍼파라미터 튜닝 |
| **4. 모델선정** | 최고의 모델을 선택하세요 | 지표 비교, 장단점 평가 |
| **5. 배포** | 모델을 프로덕션으로 배송 | 인프라, API, 배치 제공 |
| **6. 모니터링** | 드리프트 및 성능 저하 감시 | 데이터 드리프트, 개념 드리프트, 성능 |
| **7. 재교육** | 새 데이터로 모델 업데이트 | 예정된 또는 트리거된 재교육 |
대부분의 가치(및 난이도)는 5~7단계에 있습니다. Jupyter 노트북에 있는 모델은 비즈니스 가치를 창출하지 않습니다.

| **스트리밍 추론** | 데이터 스트림에 대한 프로세스 예측 | 초 | 이상 징후 감지, 이벤트 처리 |

## 모델 레지스트리
모델 레지스트리는 ML 모델(버전, 메타데이터, 지표, 배포 상태)을 관리하기 위한 중앙 집중식 저장소입니다.
| 능력 | 설명 |
|------------|-------------|
| **버전 관리** | 고유 ID로 모든 모델 버전 추적 |
| **메타데이터** | 훈련 데이터, 하이퍼파라미터, 메트릭, 작성자 |
| **단계 전환** | 단계를 통해 모델 이동: 준비 → 생산 → 보관 |
| **리니지** | 각 모델을 생성한 데이터와 코드 추적 |
| 도구 | 설명 |
|------|-------------|
| **MLflow** | 오픈 소스; 모델 등록 + 실험 추적 |
| **가중치 및 편향(W&B)** | 광고; 실험 추적 + 모델 등록 |
| **DVC** | Git을 사용한 데이터 및 모델 버전 관리 |
| **Azure ML/SageMaker** | 클라우드 네이티브 모델 관리 |
---

## 실험 추적
모든 ML 실험은 사용된 데이터, 하이퍼파라미터, 결과 지표 등을 추적해야 합니다.
| 도구 | 주요 기능 |
|------|-------------|
| **MLflow** | 오픈 소스, 자체 호스팅, 매개변수/메트릭/아티팩트 추적 |
| **W&B** | 리치 UI, 스윕, 아티팩트 버전 관리, 보고서 |
| **해왕성** | MLOps용 메타데이터 저장소 |
| **텐서보드** | TensorFlow에 내장되어 있습니다. 훈련 곡선 시각화 |
### 추적 대상
| 카테고리 | 예 |
|------------|---------|
| **매개변수** | 학습률, 배치 크기, 모델 아키텍처, 시대 수 |
| **측정항목** | 정확도, 손실, F1, AUC-ROC(에포크별 및 최종별) |
| **아티팩트** | 모델 가중치, 혼동 행렬, 예측 샘플 |
| **데이터** | 데이터 세트 버전, 분할 비율, 전처리 단계 |
| **환경** | Python 버전, 라이브러리 버전, 하드웨어 |

## 모델 배포 전략
| 전략 | 작동 원리 | 위험 |
|----------|-------------|------|
| **섀도 배포** | 새로운 모델은 기존 모델과 함께 실행됩니다. 비교되었으나 제공되지 않은 예측 | 위험 제로; 라이브로 전환하기 전에 유효성을 검사합니다 |
| **카나리아 출시** | 작은 비율의 트래픽을 새 모델로 라우팅합니다. 점진적으로 증가 | 낮은 위험; 빠른 롤백 |
| **A/B 테스트** | 사용자를 기존 사용자와 신규 사용자로 분할합니다. 비즈니스 지표 비교 | 실제 영향 측정 |
| **청록색** | 두 개의 동일한 환경; 모든 트래픽을 한 번에 전환 | 즉시 롤백; 전환 중 이중 비용 |
| **기능 플래그** | 사용자 세그먼트별로 모델 켜기/끄기 전환 | 세밀한 제어 |

## ML 시스템 모니터링
ML 시스템은 데이터 자체가 변경될 수 있으므로 기존 소프트웨어보다 더 많은 모니터링이 필요합니다.
### 드리프트 유형
| 드리프트 유형 | 변경되는 사항 | 예 |
|------------|-------------|---------|
| **데이터 드리프트** | 입력 분포 변경 | 마케팅 캠페인 이후 고객 인구통계 변화 |
| **개념 드리프트** | 입력과 출력 변화의 관계 | 불경기 동안 소비자 행동 변화 |
| **라벨 드리프트** | 목표 분포 변경 | 사기율이 1%에서 5%로 증가 |
### 모니터링 대상
| 카테고리 | 측정항목 |
|------------|---------|
| **모델 성능** | 정확도, 정밀도, 재현율, F1, AUC(기준 대비) |
| **데이터 품질** | 누락된 값, 특성 분포, 이상값 |
| **드리프트 감지** | 통계적 테스트(KS 테스트, PSI, KL 발산) |
| **인프라** | 지연 시간, 처리량, GPU 활용도, 메모리 |
| **비즈니스 지표** | 전환율, 수익 영향, 사용자 만족도 |
### 모니터링 도구
| 도구 | 유형 |
|------|------|
| **분명히 AI** | 오픈 소스 데이터 드리프트 및 모델 성능 모니터링 |
| **그라파나** | 대시보드 시각화(Prometheus와 함께 작동) |
| **와이랩스** | 데이터 관측 플랫폼 |
| **아리즈** | ML 관측 가능성 및 근본 원인 분석 |
| **프로메테우스 + 그라파나** | 인프라 및 애플리케이션 지표 |
---

## 재현 가능한 훈련
재현성은 실험을 다시 실행하여 동일한 결과를 얻을 수 있음을 의미합니다. 디버깅, 감사 및 규정 준수에 필수적입니다.
### 요구 사항
| 요구사항 | 그것을 달성하는 방법 |
|-------------|------|
| **데이터 버전 관리** | 해시가 포함된 DVC, Delta Lake 또는 데이터 세트 스냅샷 |
| **코드 버전 관리** | 모든 훈련 코드에 대한 Git |
| **환경 고정** | `requirements.txt`,`conda env`, 정확한 버전의 Docker 이미지 |
| **시드 설정** | numpy, torch, tensorflow의 무작위 시드 수정 |
| **구성 관리** | 모든 하이퍼파라미터에 대한 Hydra, OmegaConf 또는 YAML 구성 |
| **아티팩트 추적** | 모든 실험을 기록하는 MLflow 또는 W&B |
---

## 스케일링 추론
모델이 하루에 수백만 건의 요청을 처리해야 하는 경우 성능이 중요합니다.
| 기술 | 설명 |
|------------|-------------|
| **일괄 처리** | 여러 요청을 단일 정방향 전달로 그룹화 |
| **양자화** | 더 빠른 추론을 위해 모델 정밀도 감소(FP32 → INT8 또는 INT4) |
| **모델 증류** | 더 큰 모델을 모방하도록 더 작은 모델 훈련 |
| **가지치기** | 중요하지 않은 가중치나 뉴런 제거 |
| **캐싱** | 재계산을 피하기 위해 자주 예측을 캐시하기 |
| **GPU 최적화** | TensorRT, ONNX 런타임, 플래시 주의 |
| **수평적 확장** | 로드 밸런서 뒤에서 여러 모델 복제본 실행 |

## ML용 기능 플래그
기능 플래그를 사용하면 재배포하지 않고도 어떤 모델 버전이 어떤 사용자에게 서비스를 제공하는지 제어할 수 있습니다.
| 사용 사례 | 설명 |
|----------|-------------|
| **점진적 출시** | 5%의 사용자에게 새 모델을 제공한 후 |
| **킬 스위치** | 문제가 감지되면 즉시 이전 모델로 되돌리기 |
| **세그먼트 기반** | 다양한 사용자 세그먼트를 위한 다양한 모델 |
| **실험** | 비즈니스 측정항목을 사용한 A/B 테스트 모델 변형 |
도구: LaunchDarkly, Unleash, Flagsmith 또는 간단한 데이터베이스 지원 기능 플래그.

## MLOps 성숙도 곡선
| 레벨 | 특징 |
|-------|---|
| **레벨 0 - 수동** | 수동 교육, 수동 배포, 모니터링 없음 |
| **레벨 1 - 실험** | 실험 추적, 모델 등록, 기본 CI |
| **레벨 2 - 자동화** | 자동화된 재교육, 모델용 CI/CD, 자동화된 테스트 |
| **레벨 3 - 전체 파이프라인** | 모니터링, 드리프트 감지 및 자동 재훈련 기능을 갖춘 엔드투엔드 자동화 파이프라인 |
대부분의 조직은 레벨 0과 레벨 1 사이에 있습니다. 목표는 ML 수명 주기가 자동화되고 자가 치유되는 레벨 2~3입니다.
