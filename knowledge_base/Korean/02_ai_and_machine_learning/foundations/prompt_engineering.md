# 프롬프트엔지니어링
프롬프트 엔지니어링은 언어 모델에서 가능한 최상의 출력을 얻기 위해 입력 프롬프트를 설계, 개선 및 최적화하는 방법입니다. 이는 예술이자 과학이며, 미세 조정 없이 LLM 동작을 제어하기 위한 기본 인터페이스입니다.
---

## 핵심 원칙
### 명확성과 특이성
명확한 프롬프트는 모호함의 여지를 남기지 않습니다. 형식, 길이, 관점 등 원하는 것을 정확하게 지정하세요.
**모호함:**
> "파이썬에 대해 알려주세요."
**구체적:**
> "Python의 GIL(Global Interpreter Lock)에 대해 설명하세요. 멀티스레딩에 미치는 영향을 설명하고 해결 방법을 제시하고 답변을 200단어 이내로 유지하세요."
### 컨텍스트 제공
모델은 역할, 청중, 목표를 알 때 더 나은 성과를 냅니다.
**맥락 없음:**
> "목록을 정렬하는 함수를 작성하세요."
**컨텍스트 포함:**
> "당신은 Python 수석 개발자입니다. 주어진 키를 기준으로 사전 목록을 정렬하는 함수를 작성하세요. 유형 힌트를 사용하고 극단적인 경우를 처리하세요. 대상은 주니어 개발자입니다."
### 긍정적인 지침을 사용하세요
모델에게 무엇을 피해야 하는지가 아니라 무엇을 해야 하는지 알려주세요. "전문 용어를 포함하지 마세요"는 "10살 어린이가 접근할 수 있는 간단한 언어를 사용하세요"보다 약합니다.

## 프롬프트 구조
### 시스템/사용자/보조 역할
대부분의 LLM API는 다중 회전 구조를 지원합니다.
- **시스템 메시지**: 모델의 행동, 페르소나 및 제약 조건을 설정합니다(전체 세션 동안 지속됨).
- **사용자 메시지**: 현재 쿼리 또는 지침입니다.
- **어시스턴트 메시지**: 모델의 이전 응답(연속성을 위해 사용됨)
**예(OpenAI API 스타일):**
시스템: 당신은 유용한 코딩 도우미입니다. 간결한 코드 예제와 간단한 설명으로 답변해 주세요. 안전하지 않은 코드를 제공하지 마십시오.
사용자: URL에서 파일을 다운로드하는 Python 함수를 작성합니다.
### 몇 번의 메시지 표시
모델에게 작업 수행을 요청하기 전에 원하는 입출력 형식의 예를 2~3개 제공하세요. 이것은 패턴을 가르칩니다.
**예:**
사용자: 다음 문장을 수동태로 변환하세요.
입력: 고양이가 쥐를 쫓았습니다.
결과: 쥐가 고양이에게 쫓겼습니다.
입력: 요리사가 식사를 요리했습니다.
결과: 식사는 요리사가 요리했습니다.
입력: 폭풍으로 인해 집이 파괴되었습니다.
출력: (모델 완료)
### 생각의 사슬(CoT)
모델이 추론을 단계별로 보여주도록 격려하세요. 이를 통해 산술, 논리 및 다단계 작업의 정확성이 향상됩니다.
**CoT 미포함:**
> "24×37이 뭔가요?"
**CoT 포함:**
> "24 × 37을 계산하세요. 단계별로 추론을 보여주세요."
모델은 중간 단계를 생성하여 산술 오류를 줄입니다.
### 구조화된 출력
안정적인 구문 분석을 위해 JSON, YAML 또는 마크다운 테이블과 같은 특정 형식을 요청하세요.
사용자: 마이크로서비스의 세 가지 장점과 세 가지 단점을 나열하세요. 각각 문자열 배열인 "pros" 및 "cons" 키가 있는 유효한 JSON 객체만 반환합니다.

## 고급 기술
### 자체 일관성
동일한 프롬프트(온도 > 0)에 대해 여러 응답을 생성하고 최종 답변에 대해 과반수 투표를 합니다. 이는 추론 작업에 특히 효과적입니다.
### 생각의 나무
여러 추론 경로를 병렬로 탐색하고 각각을 평가한 후 가장 적합한 경로를 선택합니다. 이는 연구 수준의 기술이지만 모델에 "대체 솔루션 탐색"을 요청하여 대략적으로 접근할 수 있습니다.
### ReAct(추론+연기)
모델이 추론과 도구 호출을 인터리브하게 하세요. 생각하고 행동한 다음(예: 웹 검색, 코드 실행) 결과에 따라 다시 생각할 수 있습니다.
**프롬프트 구조:**
계산기와 검색 엔진에 액세스할 수 있습니다. 각 단계에 대해 다음을 출력합니다.
생각: (당신의 추론)
조치: (도구 이름, 입력)
관찰: (도구 출력)
... 최종 답을 얻을 때까지 계속하세요.
### 페르소나 할당
특정 인물을 할당하여 응답을 구성하세요.
**예:**
- "당신은 신입생에게 메모리 관리를 설명하는 Linux 커널 개발자입니다."
- "당신은 고객에게 일반적인 조언을 해주는 친절한 영양사입니다."
- "당신은 새로운 장치를 검토하는 냉소적인 기술 평론가입니다."
---

## 매개변수 튜닝
- **온도** (0.0 – 1.0+): 무작위성을 제어합니다. 낮을수록 더 결정적이며, 높을수록 더 창의적입니다. 사실적인 답변에는 0.0~0.3을 사용하세요. 창의적인 글쓰기의 경우 0.7~1.0입니다.
- **Top-p**(핵 샘플링): 특정 누적 임계값에서 확률 질량을 차단합니다. 0.9는 가능성 있는 토큰의 상위 90%에서 모델 샘플링을 의미합니다. 일반적으로 온도나 top-p 중 하나만 조정하고 둘 다 조정하지는 않습니다.
- **최대 토큰**: 최대 출력 길이를 설정합니다. 컨텍스트 창 내에서 응답을 위한 공간을 예약하는 것을 잊지 마세요.
- **빈도 페널티**: 동일한 토큰의 반복을 줄입니다.
- **존재 패널티**: 모델이 새로운 주제를 소개하도록 장려합니다.

## 일반적인 문제 및 수정 사항
| 문제 | 가능한 원인 | 수정 |
|---------|--------------|------|
| 모델이 프롬프트의 일부를 무시합니다 | 프롬프트가 너무 길거나 과부하됨 | 줄이다; 가장 중요한 지시사항을 맨 끝에 넣으세요 |
| 출력이 너무 장황합니다. | 길이 제한 없음 | "3개 문장으로 제한"을 추가하거나 max_tokens |
| 출력이 너무 간결합니다. | 지나치게 제한적 | "자세히 설명해주세요" 추가 또는 온도 낮추기 |
| 사실적인 환각 | 맥락이 부족하거나 질문이 모호함 | "잘 모르겠으면 '모르겠다'라고 말하세요."를 추가하고 RAG 컨텍스트를 제공하세요 |
| 일관되지 않은 형식 | 명시적인 형식 지침 없음 | JSON, 마크다운 테이블 또는 글머리 기호 목록 요청 |
| 잘못된 언어로 모델 답변 | 언어 교육 없음 | "영어로 응답"(또는 대상 언어)을 명시적으로 명시 |

## 일반 작업을 위한 프롬프트 템플릿
### 요약
다음 텍스트를 3개의 글머리 기호로 요약하세요. 주요 주장에 초점을 맞추고 세부 사항은 피하십시오.
텍스트: [텍스트 삽입]

### 코드 생성
[X를 수행하는] [언어] 함수를 작성하세요.
요구사항:
유형 힌트를 사용하세요.
독스트링을 포함하세요.
극단적인 경우 처리: [목록].
지정하지 않는 한 외부 라이브러리를 사용하지 마십시오.

### 설명
[비전문가/대학생/어린이]에게 [개념]을 설명해보세요. 적절한 경우 비유를 사용하십시오.
### 브레인스토밍
[주제]에 대한 아이디어 10개를 생성하세요. 각 아이디어에 대해 한 문장으로 설명하고 잠재적인 과제를 하나씩 제시하세요.
텍스트
### 분류
다음 고객 피드백을 [긍정적, 중립적, 부정적]으로 분류하세요.
신뢰도 점수(0~100)와 간단한 이유를 제공하세요.
피드백: [텍스트 삽입]
### 스타일을 사용한 번역
다음 영어 텍스트를 스페인어로 번역하세요. 소셜 미디어 게시물에 적합한 비공식적인 어조를 사용하세요.
텍스트: [텍스트 삽입]

## 프롬프트 평가
프롬프트를 코드로 처리합니다. 버전을 지정하고, 테스트하고, 반복합니다.
- 보류된 쿼리 세트에 대해 다양한 프롬프트 변형을 **A/B 테스트**합니다.
- 사람의 평가 또는 자동화된 지표(예: 정확한 일치, BLEU, 맞춤 채점)를 통해 **성공을 측정**합니다.
- 프롬프트, 버전 및 관찰된 성능이 포함된 **프롬프트 레지스트리**(간단한 텍스트 파일 또는 스프레드시트)를 유지합니다.
