# 클라우드 아키텍처

## 클라우드 컴퓨팅 기초

### 클라우드 컴퓨팅이란 무엇인가?
클라우드 컴퓨팅은 서버, 스토리지, 데이터베이스, 네트워킹, 소프트웨어 같은 컴퓨팅 리소스를 인터넷을 통해 필요할 때 즉시 제공하고, 사용한 만큼 비용을 지불하는 방식입니다.

### 기본 특성 (NIST 정의)
- **온디맨드 셀프서비스**: 사람의 개입 없이 필요한 리소스를 직접 프로비저닝할 수 있습니다.
- **광범위한 네트워크 액세스**: 표준 메커니즘을 통해 네트워크 어디서나 접근할 수 있습니다.
- **리소스 풀링**: 멀티테넌트 모델을 기반으로 리소스를 공유하고 동적으로 할당합니다.
- **신속한 탄력성**: 수요 변화에 따라 빠르게 확장하거나 축소할 수 있습니다.
- **측정된 서비스**: 리소스 사용량을 모니터링하고 그에 따라 과금합니다.

### 클라우드 배포 모델
- **퍼블릭 클라우드**: 공급자가 소유한 공유 인프라를 사용하는 방식입니다 (AWS, Azure, GCP).
- **프라이빗 클라우드**: 단일 조직 전용으로 운영되는 클라우드입니다 (온프레미스 또는 호스팅).
- **하이브리드 클라우드**: 퍼블릭 클라우드와 프라이빗 클라우드를 함께 사용하는 방식입니다.
- **멀티클라우드**: 여러 퍼블릭 클라우드 공급자를 동시에 활용하는 전략입니다.
- **커뮤니티 클라우드**: 공통 관심사나 요구사항을 가진 조직들이 함께 사용하는 클라우드입니다.

### 서비스 모델

#### Infrastructure as a Service (IaaS)
- **제공 내용**: 가상 머신, 스토리지, 네트워크, 운영 체제
- **예시**: AWS EC2, Google Compute Engine, Azure VMs
- **사용 사례**: 리프트 앤드 시프트 마이그레이션, 개발 환경, 높은 수준의 제어가 필요한 경우

#### Platform as a Service (PaaS)
- **제공 내용**: 개발 플랫폼, 데이터베이스, 미들웨어
- **예시**: Heroku, Google App Engine, AWS Elastic Beanstalk
- **사용 사례**: 애플리케이션 개발, API 배포, 마이크로서비스 운영

#### Software as a Service (SaaS)
- **제공 내용**: 완성된 애플리케이션을 인터넷을 통해 제공합니다.
- **예시**: Salesforce, Google Workspace, Microsoft 365, Slack
- **사용 사례**: 이메일, CRM, 협업, 다양한 비즈니스 애플리케이션

#### Function as a Service (FaaS) / 서버리스
- **제공 내용**: 이벤트 기반으로 함수를 실행합니다.
- **예시**: AWS Lambda, Azure Functions, Google Cloud Functions
- **사용 사례**: 이벤트 처리, API 구현, 예약 작업, 실시간 처리

## 주요 클라우드 제공자

### Amazon Web Services (AWS)
- **시장 점유율**: 약 32%로 가장 큰 공급자입니다.
- **주요 서비스**:
  - 컴퓨트: EC2, Lambda, ECS, EKS
  - 스토리지: S3, EBS, Glacier
  - 데이터베이스: RDS, DynamoDB, Aurora
  - 네트워킹: VPC, Route 53, CloudFront
  - AI/ML: SageMaker, Rekognition, Comprehend

### Microsoft Azure
- **시장 점유율**: 약 23%
- **강점**: 엔터프라이즈 통합, 하이브리드 클라우드, Microsoft 생태계와의 연계
- **주요 서비스**:
  - 컴퓨트: Virtual Machines, Azure Functions, AKS
  - 스토리지: Blob Storage, Disk Storage
  - 데이터베이스: SQL Database, Cosmos DB
  - 네트워킹: Virtual Network, Traffic Manager
  - AI/ML: Azure ML, Cognitive Services

### Google Cloud Platform (GCP)
- **시장 점유율**: 약 10%
- **강점**: 데이터 분석, AI/ML, Kubernetes
- **주요 서비스**:
  - 컴퓨트: Compute Engine, Cloud Functions, GKE
  - 스토리지: Cloud Storage, Persistent Disk
  - 데이터베이스: Cloud SQL, Firestore, Bigtable
  - 분석: BigQuery, Dataflow, Pub/Sub
  - AI/ML: Vertex AI, AutoML

### 기타 제공자
- **IBM Cloud**: 엔터프라이즈 중심 서비스와 Watson AI에 강점이 있습니다.
- **Oracle Cloud**: 데이터베이스 워크로드와 엔터프라이즈 애플리케이션에 적합합니다.
- **Alibaba Cloud**: 아시아 태평양 지역에서 강한 영향력을 가지고 있습니다.
- **DigitalOcean**: 개발자 친화적이고 제품 구성이 단순합니다.

## 클라우드 아키텍처 패턴

### Well-Architected Framework 원칙

#### 운영 우수성
- 운영을 자동화합니다.
- 변경은 자주, 그리고 되돌릴 수 있게 수행합니다.
- 절차를 지속적으로 개선합니다.
- 장애를 미리 예측하고 대비합니다.

#### 보안
- 강력한 ID 기반 제어를 구현합니다.
- 추적 가능성을 확보합니다.
- 모든 계층에 보안을 적용합니다.
- 보안 모범 사례를 자동화합니다.
- 전송 중인 데이터와 저장된 데이터를 모두 보호합니다.

#### 신뢰성
- 복구 절차를 정기적으로 테스트합니다.
- 장애 발생 시 자동으로 복구합니다.
- 가용성 확보를 위해 수평 확장을 활용합니다.
- 추측에 의존한 용량 계획을 지양합니다.
- 자동화를 통해 변경을 관리합니다.

#### 성능 효율성
- 최신 기술을 폭넓게 활용할 수 있도록 합니다.
- 몇 분 안에 전 세계로 확장할 수 있도록 설계합니다.
- 서버리스 아키텍처를 적극 활용합니다.
- 더 자주 실험하고 개선합니다.
- 하드웨어 특성과 워크로드의 상성을 고려합니다.

#### 비용 최적화
- 사용량 기반의 소비 모델을 채택합니다.
- 전체 효율성을 측정합니다.
- 차별화되지 않는 반복 작업에는 과도한 비용을 쓰지 않습니다.
- 지출을 분석하고 적절히 귀속합니다.
- 가능하면 관리형 서비스를 사용합니다.

### 일반적인 아키텍처 패턴

#### 마이크로서비스 아키텍처
- 애플리케이션을 작고 독립적인 서비스들로 분해합니다.
- 각 서비스는 자신만의 데이터와 로직을 소유합니다.
- API(REST, gRPC, 메시징)를 통해 서로 통신합니다.
- 서비스별로 독립 배포가 가능합니다.
- **장점**: 확장성, 장애 격리, 기술 선택의 유연성
- **과제**: 분산 시스템의 복잡성, 데이터 일관성, 모니터링 부담

#### 이벤트 기반 아키텍처
- 구성 요소가 이벤트를 통해 통신합니다.
- 프로듀서는 이벤트를 발행하고, 컨슈머는 이에 반응합니다.
- **패턴**: 이벤트 소싱, CQRS, pub/sub
- **기술**: Kafka, SNS/SQS, EventBridge, Pub/Sub
- **장점**: 느슨한 결합, 높은 확장성, 실시간 처리에 유리

#### 서버리스 아키텍처
- 서버를 직접 관리할 필요가 없습니다.
- 실제 실행된 만큼만 비용을 지불합니다.
- 자동으로 확장됩니다.
- **구성 요소**: 함수, API Gateway, 관리형 서비스
- **장점**: 비용 효율성, 운영 부담 감소, 빠른 배포
- **고려 사항**: 콜드 스타트, 벤더 종속성, 실행 시간 제한

#### 레이어드 아키텍처 (N-Tier)
- 프레젠테이션 계층 (UI)
- 애플리케이션/비즈니스 로직 계층
- 데이터 액세스 계층
- 데이터베이스 계층
- **장점**: 관심사 분리, 높은 유지보수성
- **일반적 사용 예**: 3티어 웹 애플리케이션

#### 스페이스 기반 아키텍처
- 높은 동시성과 분산 데이터 처리를 목표로 합니다.
- 서버 간에 가상화된 메모리 공간을 활용합니다.
- 처리 노드를 독립적으로 확장할 수 있습니다.
- **사용 사례**: 대규모 저지연 애플리케이션

## 컴퓨트 서비스

### 가상 머신
- **유형**: 범용, 컴퓨트 최적화, 메모리 최적화, GPU
- **가격 책정**: 온디맨드, 리저브드 인스턴스, 스팟 인스턴스
- **관리 방식**: 오토스케일링 그룹, 로드 밸런서
- **모범 사례**: 적절한 사이징, 태깅, 모니터링, 패치 적용

### 컨테이너
- **Docker**: 사실상의 컨테이너 런타임 표준입니다.
- **오케스트레이션**: Kubernetes(EKS, AKS, GKE), ECS, Fargate
- **장점**: 이식성, 효율성, 일관성
- **레지스트리**: ECR, GCR, ACR, Docker Hub

### 서버리스 함수
- **실행 모델**: 이벤트로 트리거되며 기본적으로 상태가 없습니다.
- **제한 사항**: 실행 시간, 메모리, 동시 실행 수
- **사용 사례**: API, 파일 처리, 예약 작업, IoT 백엔드
- **모니터링 항목**: 호출 수, 오류율, 실행 시간, 콜드 스타트

## 스토리지 솔루션

### 객체 스토리지
- **특징**: 평면 구조, 메타데이터 지원, HTTP 액세스
- **예시**: AWS S3, Google Cloud Storage, Azure Blob
- **사용 사례**: 정적 자산, 백업, 데이터 레이크, 아카이브
- **스토리지 클래스**: 핫, 쿨, 콜드, 아카이브로 나뉘며 비용과 접근 속도가 다릅니다.

### 블록 스토리지
- **특징**: RAW 볼륨 형태이며 VM에 연결해 사용합니다.
- **예시**: AWS EBS, Google Persistent Disk, Azure Disks
- **사용 사례**: 데이터베이스, 부트 볼륨, 고성능이 필요한 워크로드
- **유형**: SSD, HDD, 프로비저닝 IOPS

### 파일 스토리지
- **특징**: 공유 파일 시스템이며 NFS/SMB 프로토콜을 사용합니다.
- **예시**: AWS EFS, Google Filestore, Azure Files
- **사용 사례**: 콘텐츠 관리, 공유 구성, 리프트 앤드 시프트

### 아카이브 스토리지
- **특징**: 비용은 가장 낮지만 조회 지연이 큽니다.
- **예시**: S3 Glacier, Azure Archive Storage
- **사용 사례**: 규정 준수, 장기 백업, 과거 데이터 보관

## 데이터베이스 서비스

### 관리형 관계형 데이터베이스
- **서비스**: AWS RDS/Aurora, Google Cloud SQL, Azure SQL Database
- **기능**: 자동 백업, 패치 적용, 확장, 복제
- **엔진**: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server

### NoSQL 데이터베이스
- **문서형**: DocumentDB, Firestore, Cosmos DB
- **키-값형**: DynamoDB, Redis Cache
- **와이드 컬럼형**: Bigtable, Cassandra(관리형)
- **그래프형**: Neptune, Cosmos DB(그래프 API)

### 데이터 웨어하우징
- **서비스**: Snowflake, Redshift, BigQuery, Synapse
- **특징**: 컬럼형 스토리지, MPP 아키텍처
- **사용 사례**: 분석, BI, 대규모 데이터 분석

### 캐싱 서비스
- **인메모리 캐시**: ElastiCache(Redis/Memcached), Cloud Memorystore
- **CDN 캐싱**: CloudFront, Cloud CDN, Azure CDN
- **사용 사례**: 세션 스토리지, 쿼리 캐싱, 콘텐츠 전송

## 네트워킹

### 가상 네트워크
- **VPC/VNet**: 격리된 네트워크 환경을 제공합니다.
- **서브넷**: 퍼블릭(인터넷 연결)과 프라이빗(내부 전용)으로 나뉩니다.
- **IP 주소 지정**: CIDR 블록, IPv4/IPv6
- **라우트 테이블**: 트래픽 흐름을 제어합니다.

### 로드 밸런싱
- **유형**: 애플리케이션 (L7), 네트워크 (L4), 게이트웨이
- **기능**: 헬스 체크, SSL 종료, 스티키 세션
- **서비스**: ELB/ALB/NLB, Cloud Load Balancing, Azure Load Balancer

### 콘텐츠 전송 네트워크 (CDN)
- **목적**: 엣지 로케이션에서 콘텐츠를 캐싱합니다.
- **장점**: 지연 시간 감소, 오리진 부하 감소, 전 세계 배포 가속
- **서비스**: CloudFront, Cloud CDN, Azure CDN, Akamai

### DNS 서비스
- **기능**: 도메인 등록, 라우팅, 헬스 체크
- **서비스**: Route 53, Cloud DNS, Azure DNS
- **라우팅 정책**: 심플, 가중치, 지연 시간 기반, 지리적 위치 기반, 페일오버

### 연결 옵션
- **인터넷 게이트웨이**: 퍼블릭 인터넷 액세스를 제공합니다.
- **NAT 게이트웨이**: 프라이빗 서브넷의 아웃바운드 인터넷 접근을 지원합니다.
- **VPN**: 온프레미스와 연결하는 암호화 터널입니다.
- **Direct Connect/ExpressRoute**: 전용 프라이빗 연결입니다.
- **VPC 피어링**: 동일 계정 또는 다른 계정의 VPC를 연결합니다.

## 클라우드 보안

### 공유 책임 모델
- **제공자 책임**: 클라우드 인프라 자체의 보안
- **고객 책임**: 클라우드 안에서 사용하는 데이터, 애플리케이션, 접근 제어의 보안
- **서비스별 차이**: 관리 범위가 넓은 서비스일수록 제공자의 책임이 더 커집니다.

### ID 및 액세스 관리 (IAM)
- **사용자**: 개별 ID입니다.
- **그룹**: 사용자들의 묶음입니다.
- **롤**: 서비스나 사용자가 일시적으로 사용하는 자격 증명입니다.
- **정책**: 권한을 정의하는 JSON 문서입니다.
- **원칙**: 최소 권한과 직무 분리를 지켜야 합니다.

### 네트워크 보안
- **보안 그룹**: 인스턴스 단위의 상태 저장 방화벽입니다.
- **네트워크 ACL**: 서브넷 단위의 비상태 저장 방화벽입니다.
- **웹 애플리케이션 방화벽 (WAF)**: 웹 공격으로부터 애플리케이션을 보호합니다.
- **DDoS 보호**: Shield, Cloud Armor, DDoS Protection

### 데이터 보호

## 비용 관리

### 가격 모델
- **종량제**: 사용한 만큼 비용을 지불합니다.
- **리저브드 인스턴스**: 1-3년 약정을 통해 큰 할인을 받습니다.
- **스팟 인스턴스**: 남는 용량을 저렴하게 사용하지만 중단될 수 있습니다.
- **세이빙스 플랜**: 보다 유연한 약정형 가격 모델입니다.
- **무료 티어**: 신규 계정에 제한적으로 무료 사용량을 제공합니다.

### 비용 최적화 전략
- **적절한 사이징**: 인스턴스 유형을 워크로드 요구사항에 맞춥니다.
- **오토스케일링**: 수요에 따라 자동으로 확장하거나 축소합니다.
- **리저브드 용량**: 안정적인 워크로드에는 약정을 활용합니다.
- **스팟 사용**: 내결함성이 있고 유연한 워크로드에 적합합니다.
- **스토리지 티어링**: 자주 쓰지 않는 데이터를 더 저렴한 티어로 이동합니다.
- **정리**: 미사용 리소스, 스냅샷, AMI를 주기적으로 삭제합니다.

### 비용 관리 도구
- **AWS**: Cost Explorer, Budgets, Trusted Advisor
- **Azure**: Cost Management, Advisor
- **GCP**: Billing 보고서, Recommender
- **서드파티**: CloudHealth, CloudCheckr, Datadog

## 고가용성 및 재해 복구

### 가용성 개념
- **가용 영역**: 리전 안에서 물리적으로 분리된 데이터 센터입니다.
- **리전**: 여러 AZ로 구성된 지리적 영역입니다.
- **엣지 로케이션**: 전 세계에 분산된 CDN 캐시 위치입니다.

### HA 전략
- **멀티 AZ**: 여러 가용 영역에 걸쳐 배포합니다.
- **자동 복구**: 장애가 난 인스턴스를 자동으로 교체합니다.
- **로드 밸런싱**: 트래픽을 정상 인스턴스들에 분산합니다.
- **데이터베이스 복제**: 멀티 AZ 배포와 읽기 복제본을 활용합니다.

### 재해 복구 전략
- **백업 및 복원**: 정기적으로 백업하고 필요할 때 복원합니다 (가장 저렴한 방식).
- **파일럿 라이트**: 핵심 구성 요소만 최소한으로 항상 실행해 두고, 재해 시 전체로 확장합니다.
- **웜 스탠바이**: 축소된 운영 환경을 상시 실행해 두는 방식입니다.
- **멀티사이트 액티브/액티브**: 여러 리전에서 전체 서비스를 동시에 운영하는 방식으로 비용이 가장 높습니다.

### RTO 및 RPO
- **목표 복구 시간 (RTO)**: 허용 가능한 최대 다운타임
- **목표 복구 시점 (RPO)**: 허용 가능한 최대 데이터 손실
- **전략 선택**: 비즈니스 요구사항과 예산을 기준으로 선택합니다.
