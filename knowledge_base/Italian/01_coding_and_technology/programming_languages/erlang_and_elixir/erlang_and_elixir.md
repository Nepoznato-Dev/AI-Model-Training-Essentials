# Erlang ed elisir
Erlang è stato costruito da Ericsson nel 1986 per alimentare gli interruttori telefonici, il che spiega perché gestisce la concorrenza, la tolleranza agli errori e i sistemi distribuiti meglio di quasi qualsiasi altra cosa. I processi Erlang sono leggeri, isolati e comunicano solo tramite lo scambio di messaggi. Quando un processo si blocca, un supervisore lo riavvia. Questa filosofia "lascia che si blocchi" produce sistemi che funzionano per anni senza tempi di inattività.
Elixir è un linguaggio moderno costruito sulla VM di Erlang (BEAM) da Jose Valim nel 2012. Mantiene tutto ciò che Erlang offre - concorrenza, tolleranza agli errori, distribuzione - ma aggiunge una sintassi amichevole, metaprogrammazione e strumenti eccellenti (gestore di pacchetti Mix, registro di pacchetti Hex). Elixir è ampiamente utilizzato per applicazioni web (tramite il framework Phoenix), sistemi in tempo reale e dispositivi embedded (tramite Nerves).
---

## Perché Erlang/Elixir è importante
- **Modello di concorrenza**: processi leggeri con passaggio di messaggi: nessuno stato condiviso, nessun blocco, nessun deadlock.
- **Tolleranza agli errori**: gli alberi del supervisore riavviano automaticamente i processi bloccati. I sistemi si riprendono dagli errori con garbo.
- **Distribuito in base alla progettazione**: i nodi Erlang comunicano in modo trasparente tra le macchine. Costruito per i cluster.
- **Ricaricamento del codice a caldo**: aggiorna i sistemi in esecuzione senza tempi di inattività. Fondamentale per le app di telecomunicazioni e in tempo reale.
- **Tempo di attività nove nove**: i sistemi Erlang hanno raggiunto un'affidabilità di produzione del 99,9999999%.
- **Phoenix framework (Elixir)**: uno dei framework web più produttivi, con canali in tempo reale integrati.
- **LiveView (Elixir)**: crea interfacce utente web ricche e in tempo reale su connessioni WebSocket senza scrivere JavaScript.
## I compromessi
| Limitazione | Dettagli | Soluzione tipica |
|-----------|---------|-------------|
| **Solo funzionale** | Nessuno stato mutabile, nessuna OOP: curva di apprendimento ripida | Abbraccia l'immutabilità; la corrispondenza del modello sostituisce i condizionali |
| **Sintassi Erlang** | La sintassi simile a Prolog è insolita e dettagliata | Usa invece Elixir per la sintassi moderna |
| **Mercato del lavoro più piccolo** | Nicchia rispetto a Python, Java, JavaScript | Forte domanda in settori specifici (telecomunicazioni, fintech, giochi) |
| **Dimensione dell'ecosistema** | Meno biblioteche rispetto agli ecosistemi tradizionali | Sfruttare l'OTP di Erlang; Hex in costante crescita |
| **Non per l'interfaccia utente** | Nessun framework GUI nativo | Utilizzare per i backend; accoppiarsi con i framework frontend |
| **Gestione delle stringhe** | Le stringhe Erlang sono scomode (elenchi di caratteri o binari) | Elixir ha un eccellente supporto delle corde |

## Sintassi dell'elisir
```elixir
# Variables (immutable — rebinding creates a new binding)
name = "Alice"
age = 30
name = "Bob"  # Rebinding is allowed, but original value is unchanged

# Atoms (named constants — like symbols in Ruby)
status = :ok
error = :error

# Pattern matching (the core mechanism)
{status, message} = {:ok, "Success"}
# status => :ok, message => "Success"

# Functions
defmodule Math do
  def add(a, b), do: a + b

  def factorial(0), do: 1
  def factorial(n) when n > 0, do: n * factorial(n - 1)

  # Pattern matching in function heads
  def describe(:ok, result), do: "Success: #{result}"
  def describe(:error, reason), do: "Error: #{reason}"
end

Math.add(2, 3)        # 5
Math.factorial(5)     # 120

# Pipe operator (chain transformations)
"  Hello, World!  "
|> String.trim()
|> String.downcase()
|> String.replace("world", "elixir")
# "hello, elixir!"

# Collections
list = [1, 2, 3, 4, 5]
Enum.map(list, &(&1 * 2))          # [2, 4, 6, 8, 10]
Enum.filter(list, &(rem(&1, 2) == 0))  # [2, 4]
Enum.reduce(list, 0, &+/2)         # 15

# Maps
user = %{name: "Alice", age: 30, email: "alice@example.com"}
user.name                          # "Alice"
%{user | age: 31}                  # Update (creates new map)

# Process spawning (lightweight — you can spawn millions)
spawn(fn ->
  IO.puts("Hello from process #{self()}")
end)

# Message passing
defmodule Counter do
  def loop(count) do
    receive do
      {:increment} -> loop(count + 1)
      {:get, sender} -> send(sender, count); loop(count)
    end
  end
end

pid = spawn(Counter, :loop, [0])
send(pid, {:increment})
send(pid, {:get, self()})
receive do count -> IO.puts("Count: #{count}") end  # Count: 1

# Error handling with try/rescue
try do
  raise "Something went wrong"
rescue
  e in RuntimeError -> IO.puts("Caught: #{e.message}")
end

# With statement (clean error handling)
with {:ok, data} <- fetch_data(),
     {:ok, parsed} <- parse(data),
     {:ok, result} <- process(parsed) do
  {:ok, result}
else
  {:error, reason} -> {:error, reason}
end
```

## Sintassi Erlang (per riferimento)
```erlang
-module(hello).
-export([greet/1, factorial/1]).

% Function definition
greet(Name) ->
    io:format("Hello, ~s!~n", [Name]).

% Pattern matching and recursion
factorial(0) -> 1;
factorial(N) when N > 0 ->
    N * factorial(N - 1).

% Process spawning
start() ->
    Pid = spawn(fun loop/0),
    Pid ! {self(), hello},
    receive
        Response -> io:format("Got: ~p~n", [Response])
    end.

loop() ->
    receive
        {From, Msg} -> From ! {ack, Msg}, loop()
    end.
```

## Sintassi e modelli avanzati
### Metaprogrammazione con le Macro (Elixir)
Le macro Elixir operano in fase di compilazione, trasformando l'AST prima dell'esecuzione.
```elixir
defmodule MyMacros do
  # Simple macro: unless (opposite of if)
  defmacro unless(condition, do: block) do
    quote do
      if !unquote(condition), do: unquote(block)
    end
  end

  # Macro with multiple arguments
  defmacro assert_equal(left, right) do
    quote do
      left_val = unquote(left)
      right_val = unquote(right)
      if left_val != right_val do
        raise "Assertion failed: #{inspect(left_val)} != #{inspect(right_val)}"
      end
    end
  end

  # DSL-building macro
  defmacro route(method, path, do: block) do
    quote do
      def handle(unquote(method), unquote(path), conn) do
        _ = conn
        unquote(block)
      end
    end
  end
end

# Usage
require MyMacros

MyMacros.unless 1 == 2 do
  IO.puts("This runs because 1 != 2")
end

# DSL example
defmodule Router do
  require MyMacros
  MyMacros.route :get, "/users" do
    {:ok, list_users()}
  end
  MyMacros.route :post, "/users" do
    {:ok, create_user(conn)}
  end
end
```

### Protocolli (classi di tipi di elisir)
```elixir
# Define a protocol
defprotocol Serializable do
  @doc "Convert a data structure to a serializable format"
  def serialize(data)
end

# Implement for multiple types
defimpl Serializable, for: Map do
  def serialize(map), do: Jason.encode!(map)
end

defimpl Serializable, for: List do
  def serialize(list), do: Jason.encode!(list)
end

defimpl Serializable, for: Atom do
  def serialize(nil), do: "null"
  def serialize(true), do: "true"
  def serialize(false), do: "false"
  def serialize(atom), do: Atom.to_string(atom)
end

# Usage
Serializable.serialize(%{name: "Alice"})  # JSON string
Serializable.serialize([1, 2, 3])         # JSON array
Serializable.serialize(:ok)               # "ok"

# Derive implementation for structs
defmodule User do
  @derive [Serializable]
  defstruct [:name, :age, :email]
end
```

### Comportamenti (interfacce Erlang/Elixir)
```elixir
# Define a behaviour (contract)
defmodule CacheBehaviour do
  @callback init(opts :: keyword()) :: {:ok, state :: term()} | {:error, term()}
  @callback get(key :: term(), state :: term()) :: {:ok, term()} | :miss
  @callback put(key :: term(), value :: term(), state :: term()) :: {:ok, term()}
  @callback delete(key :: term(), state :: term()) :: :ok
end

# Implement the behaviour
defmodule MemoryCache do
  @behaviour CacheBehaviour

  @impl true
  def init(_opts), do: {:ok, %{}}

  @impl true
  def get(key, state) do
    case Map.get(state, key) do
      nil -> :miss
      value -> {:ok, value}
    end
  end

  @impl true
  def put(key, value, state), do: {:ok, Map.put(state, key, value)}

  @impl true
  def delete(key, state), do: :ok
end
```

## Concorrenza e parallelismo
### Processi BEAM VM
BEAM VM (la macchina virtuale di Erlang) esegue milioni di processi leggeri, ciascuno con il proprio heap.
```elixir
# Spawning processes
pid = spawn(fn ->
  receive do
    {:hello, name} -> IO.puts("Hello, #{name}!")
    :stop -> IO.puts("Stopping...")
  end
end)

send(pid, {:hello, "World"})  # "Hello, World!"
send(pid, :stop)              # "Stopping..."

# GenServer — the standard process pattern
defmodule KeyValueStore do
  use GenServer

  # Client API
  def start_link(initial \\ %{}) do
    GenServer.start_link(__MODULE__, initial, name: __MODULE__)
  end

  def get(key), do: GenServer.call(__MODULE__, {:get, key})
  def put(key, value), do: GenServer.cast(__MODULE__, {:put, key, value})
  def delete(key), do: GenServer.call(__MODULE__, {:delete, key})

  # Server callbacks
  @impl true
  def init(state), do: {:ok, state}

  @impl true
  def handle_call({:get, key}, _from, state) do
    {:reply, Map.get(state, key), state}
  end

  @impl true
  def handle_cast({:put, key, value}, state) do
    {:noreply, Map.put(state, key, value)}
  end

  @impl true
  def handle_call({:delete, key}, _from, state) do
    {:reply, :ok, Map.delete(state, key)}
  end
end

# Usage
KeyValueStore.start_link()
KeyValueStore.put(:name, "Alice")
KeyValueStore.get(:name)  # "Alice"
```

### Alberi supervisori OTP
```elixir
defmodule AppSupervisor do
  use Supervisor

  def start_link(init_arg) do
    Supervisor.start_link(__MODULE__, init_arg, name: __MODULE__)
  end

  @impl true
  def init(_init_arg) do
    children = [
      # Worker that restarts on any crash
      {KeyValueStore, %{}},

      # Worker with custom restart strategy
      {DatabasePool, [size: 10, timeout: 5000]},

      # Supervisor for a subtree of processes
      {TaskSupervisor, name: MyApp.TaskSupervisor},

      # Temporary worker (never restarted)
      {OneTimeJob, [run_immediately: true]}
    ]

    # Strategy: :one_for_one restarts only the crashed child
    # :one_for_all restarts all children when one crashes
    # :rest_for_one restarts the crashed child and all children started after it
    Supervisor.init(children, strategy: :one_for_one,
      max_restarts: 5, max_seconds: 60)
  end
end
```

# Distributed GenServer
# Register a process globally across the cluster
defmodule DistributedCounter do
  use GenServer

  def start_link do
    GenServer.start_link(__MODULE__, 0, name: {:global, __MODULE__})
  end

  def increment do
    :global.trans({__MODULE__, fn ->
      GenServer.call({:global, __MODULE__}, :inc)
    end}, [node()])
  end

  def handle_call(:inc, _from, count) do
    {:reply, count + 1, count + 1}
  end
end

defmodule TrafficLight do

  @transitions %{red: :green, green: :yellow, yellow: :red}
  @durations %{red: 30_000, green: 25_000, yellow: 5_000}

  def start_link(_opts), do: GenServer.start_link(__MODULE__, :red)
  def current_state(pid), do: GenServer.call(pid, :current)

  @impl true
  def init(state) do
    Process.send_after(self(), :transition, @durations[state])
    {:ok, state}
  end

  @impl true
  def handle_info(:transition, current) do
    next = @transitions[current]
    Process.send_after(self(), :transition, @durations[next])
    {:noreply, next}
  end

  @impl true
  def handle_call(:current, _from, state), do: {:reply, state, state}
end
```

### Modello di pipeline con tipo di risultato

defmodule OrderPipeline do
  def place_order(params) do
    {:ok, params}
    |> validate_items()
    |> validate_address()
    |> calculate_total()
    |> charge_payment()
    |> create_order_record()
  end

  defp validate_items({:ok, %{items: []}}), do: {:error, :validate, "No items"}
  defp validate_items({:ok, params}), do: {:ok, params}
  defp validate_items(err), do: err

  defp calculate_total({:ok, params}) do
    total = Enum.reduce(params.items, 0, fn item, acc ->
      acc + item.price * item.quantity
    end)
    {:ok, Map.put(params, :total, total)}
  end
  defp calculate_total(err), do: err

  defp charge_payment({:ok, %{total: total} = params}) do
    case Payment.charge(params.payment_method, total) do
      {:ok, tx_id} -> {:ok, Map.put(params, :transaction_id, tx_id)}
      {:error, reason} -> {:error, :payment, reason}
    end
  end
  defp charge_payment(err), do: err

  defp create_order_record({:ok, params}), do: {:ok, Orders.create(params)}
  defp create_order_record(err), do: err
end

## Domande e risposte sintetiche
### D1: Come funziona la filosofia "let it crash" di Erlang?
**R:** Invece di una programmazione difensiva, Erlang lascia che i processi si blocchino e li riavvii tramite supervisori:
```erlang
% Supervisor restarts crashed workers
{ok, Pid} = supervisor:start_link(my_sup, []),
% If a worker crashes, the supervisor restarts it automatically
% This is MORE reliable than trying to handle every error
```

### D2: Come funzionano le pipeline Elixir?
**R:** L'operatore`|>`passa il risultato di una funzione come primo argomento a quella successiva:
```elixir
"hello world"
|> String.split()
|> Enum.map(&String.capitalize/1)
|> Enum.join(" ")
# "Hello World"
```

### D3: Qual è la differenza tra Erlang ed Elixir?
**R:** Elixir funziona su Erlang VM (BEAM) con la sintassi moderna:
- Elixir: operatore pipe, macro, protocolli, interpolazione di stringhe
- Erlang: sintassi più semplice, OTP integrato, più testato in battaglia
- Entrambi condividono lo stesso modello di concorrenza, VM ed ecosistema
### D4: Come funzionano i GenServer in Elixir?
**R:** GenServer è l'astrazione standard per i processi con stato:
```elixir
defmodule Counter do
  use GenServer
  def start_link(init), do: GenServer.start_link(__MODULE__, init, name: __MODULE__)
  def increment, do: GenServer.cast(__MODULE__, :inc)
  def value, do: GenServer.call(__MODULE__, :get)
  def init(val), do: {:ok, val}
  def handle_cast(:inc, n), do: {:noreply, n + 1}
  def handle_call(:get, _, n), do: {:reply, n, n}
end
```

### D5: Come gestisco gli errori in Elixir?
**R:** Utilizzare`try/rescue`per le eccezioni,`{:ok, result} | {:error, reason}`per gli errori previsti:
```elixir
case File.read("data.txt") do
  {:ok, content} -> process(content)
  {:error, :enoent} -> Logger.warning("File not found")
  {:error, reason} -> Logger.error("Failed: #{reason}")
end
```

## Risoluzione dei problemi basati sulla catena di pensiero
### Problema 1: creazione di un archivio di valori-chiave con tolleranza agli errori
**Passaggio 1: comprendere il problema**
Creare un archivio di valori-chiave che sopravviva agli arresti anomali del processo.
**Passaggio 2: identificare l'approccio**
Utilizza un GenServer con supervisore.
**Passaggio 3: implementazione**```elixir
defmodule KVStore do
  use GenServer
  def start_link, do: GenServer.start_link(__MODULE__, %{}, name: __MODULE__)
  def put(key, val), do: GenServer.cast(__MODULE__, {:put, key, val})
  def get(key), do: GenServer.call(__MODULE__, {:get, key})
  def init(state), do: {:ok, state}
  def handle_cast({:put, k, v}, state), do: {:noreply, Map.put(state, k, v)}
  def handle_call({:get, k}, _, state), do: {:reply, Map.get(state, k), state}
end

# Supervisor
children = [{KVStore, []}]
Supervisor.start_link(children, strategy: :one_for_one)
```

**Passaggio 4: verifica**
Uccidi il processo e verifica che si riavvii con un nuovo stato.
### Problema 2: Web Scraper simultaneo
**Passaggio 1: comprendere il problema**
Recupera più URL contemporaneamente e raccogli risultati.
**Passaggio 2: identificare l'approccio**
Utilizza le attività Elixir per l'esecuzione simultanea.
**Passaggio 3: implementazione**```elixir
urls = ["https://example.com", "https://example.org", "https://example.net"]

tasks = Enum.map(urls, fn url ->
  Task.async(fn ->
    case HTTPoison.get(url) do
      {:ok, %HTTPoison.Response{status_code: 200, body: body}} ->
        {url, :ok, String.length(body)}
      {:ok, %HTTPoison.Response{status_code: code}} ->
        {url, :error, code}
      {:error, %HTTPoison.Error{reason: reason}} ->
        {url, :error, reason}
    end
  end)
end)

results = Task.await_many(tasks, 10_000)
```

**Passaggio 4: ottimizza**
Aggiungi limitazioni di velocità, nuovi tentativi e streaming per elenchi di URL di grandi dimensioni.

## Riepilogo
Erlang ha risolto un problema con cui la maggior parte delle lingue continua a lottare: costruire sistemi che non crollano mai. Il suo modello di concorrenza – processi leggeri, scambio di messaggi, supervisione “let it crash” – è decenni avanti rispetto a ciò che i linguaggi tradizionali stanno scoprendo solo ora. Elixir prende i superpoteri di Erlang e li racchiude in una sintassi moderna con un'eccellente esperienza di sviluppo. Se stai costruendo sistemi in tempo reale, distribuiti o tolleranti ai guasti, Erlang/Elixir vale l'investimento. La curva di apprendimento è reale (programmazione funzionale, corrispondenza di modelli, pensiero processuale), ma il profitto è un software che rimane aggiornato e si adatta in modo prevedibile.
