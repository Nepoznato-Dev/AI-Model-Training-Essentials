# DevOps और CI/CD
DevOps सांस्कृतिक दर्शन, प्रथाओं और उपकरणों का संयोजन है जो टीमों को तेज़ी से और अधिक विश्वसनीय रूप से सॉफ़्टवेयर वितरित करने में सक्षम बनाता है। यह डेवलपर्स (जो परिवर्तन भेजना चाहते हैं) और संचालन (जो स्थिरता चाहते हैं) के बीच की दीवार को तोड़ देता है। सीआई/सीडी - सतत एकीकरण और सतत वितरण - स्वचालन रीढ़ है जो इसे संभव बनाता है।

## सीआई/सीडी पाइपलाइन
### सीआई/सीडी का वास्तव में क्या मतलब है
| अवधि | यह क्या करता है |
|------|----||
| **निरंतर एकीकरण (सीआई)** | डेवलपर्स बार-बार कोड मर्ज करते हैं; प्रत्येक मर्ज स्वचालित निर्माण और परीक्षण को ट्रिगर करता है |
| **निरंतर वितरण (सीडी)** | कोड हमेशा परिनियोजन योग्य स्थिति में होता है; उत्पादन के लिए जारी करना एक मैन्युअल निर्णय है |
| **निरंतर तैनाती** | परीक्षण में उत्तीर्ण होने वाला प्रत्येक परिवर्तन स्वचालित रूप से उत्पादन में चला जाता है - कोई मैन्युअल गेट नहीं |
### विशिष्ट पाइपलाइन चरण
| स्टेज | क्या होता है | उपकरण |
|-------|---|-------|
| **स्रोत** | डेवलपर कोड को Git में धकेलता है | गिटहब, गिटलैब, बिटबकेट |
| **निर्माण** | कोड संकलित करें, निर्भरताएँ स्थापित करें | मावेन, ग्रैडल, एनपीएम, पिप |
| **टेस्ट** | इकाई चलाएँ, एकीकरण, लिंट जाँचें | जेस्ट, पाइटेस्ट, जुनिट |
| **पैकेज** | डॉकर छवि या आर्टिफैक्ट बनाएं | डॉकर, बिल्डपैक |
| **तैनाती (मंचन)** | मंचन वातावरण में तैनात करें | कुबेरनेट्स, ईसीएस, वीएम |
| **परीक्षण (मंचन)** | एकीकरण परीक्षण, धुआं परीक्षण | सेलेनियम, डाकिया |
| **तैनाती (उत्पादन)** | उत्पादन के लिए रिलीज | नीला-हरा, कैनरी, रोलिंग |
| **मॉनीटर** | स्वास्थ्य, त्रुटियों, प्रदर्शन का निरीक्षण करें | प्रोमेथियस, ग्राफाना, डेटाडॉग |
### सीआई/सीडी उपकरण की तुलना
| उपकरण | प्रकार | ताकत |
|------|------|----------|
| **गिटहब क्रियाएँ** | क्लाउड सीआई/सीडी | GitHub के साथ गहराई से एकीकृत; YAML वर्कफ़्लोज़ |
| **गिटलैब सीआई** | अंतर्निर्मित सीआई/सीडी | रेपो + पाइपलाइन के लिए एकल मंच |
| **जेनकींस** | स्व-होस्टेड सीआई/सीडी | अत्यधिक विन्यास योग्य; विशाल प्लगइन पारिस्थितिकी तंत्र |
| **सर्किलसीआई** | क्लाउड सीआई/सीडी | तेज़; कंटेनरीकृत वर्कफ़्लो के लिए अच्छा है |
| **आर्गोसीडी** | कुबेरनेट्स के लिए GitOps | घोषणात्मक, गिट-संचालित तैनाती |

## डॉकर और कंटेनर
### कंटेनर क्यों?
कंटेनरों से पहले, क्लासिक समस्या थी "यह मेरी मशीन पर काम करता है।" कंटेनर किसी एप्लिकेशन को उसकी सभी निर्भरताओं - लाइब्रेरी, रनटाइम, कॉन्फ़िगरेशन - के साथ एक एकल, पोर्टेबल इकाई में पैक करके हल करते हैं जो कहीं भी समान रूप से चलती है।
### डॉकर अनिवार्यताएँ
| संकल्पना | विवरण |
|---------|-----------------|
| **छवि** | ऐप + निर्भरता के साथ केवल पढ़ने योग्य टेम्पलेट |
| **कंटेनर** | एक छवि का चल रहा उदाहरण |
| **डॉकरफ़ाइल** | छवि निर्माण की विधि |
| **रजिस्ट्री** | छवियों के लिए भंडारण (डॉकर हब, ईसीआर, जीसीआर) |
| **वॉल्यूम** | लगातार भंडारण जो कंटेनर के पुनरारंभ होने से बचा रहता है |
| **नेटवर्क** | कंटेनरों के लिए पृथक नेटवर्किंग परत |
### डॉकरफ़ाइल सर्वोत्तम अभ्यास
```dockerfile
# Use specific base image tags, not 'latest'
FROM python:3.12-slim

# Set working directory
WORKDIR /app

# Copy dependency file first (leverage Docker layer caching)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code
COPY . .

# Run as non-root user
USER appuser

# Expose port and define entrypoint
EXPOSE 8000
CMD ["python", "main.py"]
```

मुख्य अभ्यास: स्लिम/अल्पाइन बेस छवियों का उपयोग करें, गैर-रूट के रूप में चलाएं, लेयर कैशिंग का लाभ उठाएं,`.dockerignore`का उपयोग करें, कमजोरियों के लिए छवियों को स्कैन करें (`trivy`, `docker scan`), और संसाधन सीमाएं निर्धारित करें।
### डॉकर कम्पोज़
एकाधिक कंटेनरों को एक साथ चलाने के लिए (ऐप + डेटाबेस + कैश):
```yaml
services:
  app:
    build: .
    ports: ["8000:8000"]
    depends_on: [db, redis]
    environment:
      DATABASE_URL: postgresql://user:pass@db:5432/mydb
  db:
    image: postgres:16
    volumes: [pgdata:/var/lib/postgresql/data]
  redis:
    image: redis:7-alpine
volumes:
  pgdata:
```

## कुबेरनेट्स (K8s)
कुबेरनेट्स उद्योग-मानक कंटेनर ऑर्केस्ट्रेटर है। यह कंटेनरीकृत अनुप्रयोगों की तैनाती, स्केलिंग और संचालन का प्रबंधन करता है।
### कोर आर्किटेक्चर
| घटक | भूमिका |
|--------|------|
| **नियंत्रण विमान** | क्लस्टर का प्रबंधन करता है (एपीआई सर्वर, शेड्यूलर, आदि, नियंत्रक प्रबंधक) |
| **नोड** | वर्कर मशीन (वीएम या फिजिकल) जो कंटेनर चलाती है |
| **पॉड** | सबसे छोटी तैनाती योग्य इकाई; एक या अधिक कंटेनर जो नेटवर्किंग साझा करते हैं |
| **सेवा** | स्थिर नेटवर्क एंडपॉइंट जो ट्रैफ़िक को पॉड्स तक रूट करता है |
| **तैनाती** | वांछित पॉड स्थिति की घोषणात्मक परिभाषा (प्रतिकृतियां, छवि, आदि) |
| **प्रवेश** | बाहरी ट्रैफ़िक के लिए HTTP रूटिंग नियम |
| **कॉन्फिगमैप/गुप्त** | कॉन्फ़िगरेशन और संवेदनशील डेटा को पॉड्स में इंजेक्ट किया गया |
### आवश्यक कुबेक्टल कमांड
```bash
kubectl get pods                    # List pods
kubectl get services                # List services
kubectl describe pod <name>         # Detailed pod info
kubectl logs <pod-name>             # View pod logs
kubectl exec -it <pod> -- /bin/sh   # Shell into a pod
kubectl apply -f deployment.yaml    # Apply a manifest
kubectl rollout status deploy/myapp # Check rollout progress
kubectl scale deploy/myapp --replicas=5  # Scale to 5 replicas
```

### हेल्म
हेल्म कुबेरनेट्स के लिए पैकेज मैनेजर है। एक **चार्ट** पूर्व-कॉन्फ़िगर कुबेरनेट्स संसाधनों का एक बंडल है। इसे K8s के लिए`apt`या`brew`के रूप में सोचें।
```bash
helm install my-release bitnami/postgresql   # Install a chart
helm upgrade my-release bitnami/postgresql   # Upgrade
helm rollback my-release 1                   # Rollback to revision 1
helm list                                    # List releases
```

## कोड के रूप में इन्फ्रास्ट्रक्चर (IaC)
IaC बुनियादी ढांचे के कॉन्फ़िगरेशन को उसी तरह से मानता है जैसे आप एप्लिकेशन कोड को मानते हैं: संस्करण-नियंत्रित, परीक्षण किया गया और पाइपलाइनों के माध्यम से तैनात किया गया।
### टेराफॉर्म बनाम अन्सिबल
| उपकरण | प्रकार | दृष्टिकोण | के लिए सर्वश्रेष्ठ |
|------|------|----------|----------|
| **टेराफॉर्म** | प्रावधान | घोषणात्मक (एचसीएल); राज्य आधारित | क्लाउड संसाधन बनाना (VPCs, VMs, डेटाबेस) |
| **उत्तरदायी** | विन्यास | घोषणात्मक (YAML); एजेंट रहित | सर्वर कॉन्फ़िगर करना, सॉफ़्टवेयर स्थापित करना |
| **पुलुमी** | प्रावधान | अनिवार्य (पायथन, गो, टीएस) | टीमें जो वास्तविक प्रोग्रामिंग भाषाएं पसंद करती हैं |
| **बादलों का निर्माण** | प्रावधान | घोषणात्मक (YAML/JSON); AWS-मूल | AWS-केवल बुनियादी ढाँचा |
### टेराफॉर्म उदाहरण
```hcl
provider "aws" {
  region = "us-east-1"
}

resource "aws_instance" "web" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.micro"

  tags = {
    Name = "web-server"
  }
}
```

सर्वोत्तम अभ्यास: पुन: प्रयोज्यता के लिए मॉड्यूल का उपयोग करें, स्थिति को दूरस्थ रूप से संग्रहीत करें (लॉकिंग के लिए S3 + DynamoDB), कभी भी हार्डकोड रहस्य नहीं, और संस्करण-नियंत्रण सब कुछ।

## निगरानी और अवलोकन
### तीन स्तंभ
| स्तंभ | यह आपको क्या बताता है | उपकरण |
|--------|------------------|-------|
| **मेट्रिक्स** | समय के साथ संख्यात्मक माप (सीपीयू, अनुरोध दर, त्रुटि दर) | प्रोमेथियस, क्लाउडवॉच, डेटाडॉग |
| **लॉग्स** | संदर्भ के साथ अलग-अलग घटनाएँ (त्रुटियाँ, अनुरोध, स्थिति परिवर्तन) | ईएलके स्टैक, लोकी, क्लाउडवॉच लॉग्स |
| **निशान** | सेवाओं में शुरू से अंत तक अनुरोध यात्रा | जेगर, एक्स-रे, ज़िपकिन |
### प्रोमेथियस + ग्राफाना स्टैक

| घटक | भूमिका |
|--------|------|
| **प्रोमेथियस** | समय-श्रृंखला डेटाबेस; सेवाओं से मेट्रिक्स खींचता है |
| **ग्राफाना** | विज़ुअलाइज़ेशन और डैशबोर्ड |
| **अलर्टमैनेजर** | स्लैक, पेजरड्यूटी, ईमेल पर अलर्ट रूट करता है |
| **नोड निर्यातक** | सिस्टम-स्तरीय मेट्रिक्स (सीपीयू, रैम, डिस्क) को उजागर करता है |
| **ब्लैकबॉक्स निर्यातक** | जांच समापन बिंदु (HTTP, TCP, ICMP) |
### ट्रैक करने के लिए मुख्य मेट्रिक्स
| श्रेणी | मेट्रिक्स |
|---|----|

| **डेटाबेस** | क्वेरी संख्या, धीमी क्वेरी, कनेक्शन पूल उपयोग |
| **व्यापार** | साइनअप, रूपांतरण, राजस्व |

## गिटऑप्स
GitOps IaC को उसके तार्किक निष्कर्ष पर ले जाता है: Git रिपॉजिटरी आपके बुनियादी ढांचे और अनुप्रयोगों की वांछित स्थिति के लिए सत्य का एकमात्र स्रोत है।
| सिद्धांत | विवरण |
|----|----|
| **घोषणात्मक** | सब कुछ कोड (YAML, HCL) | के रूप में वर्णित है
| **संस्करणित** | Git सत्य का स्रोत है |
| **स्वचालित** | उपकरण लगातार वांछित स्थिति का वास्तविक स्थिति से मिलान करते रहते हैं |
| **श्रवणयोग्य** | प्रत्येक परिवर्तन एक Git प्रतिबद्धता है |
**ArgoCD** और **Flux** Kubernetes के लिए प्रमुख GitOps उपकरण हैं। आप अपने Git रेपो में एक बदलाव लाते हैं, और टूल स्वचालित रूप से इसे क्लस्टर में तैनात कर देता है।
