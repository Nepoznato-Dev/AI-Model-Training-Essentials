# कोड के रूप में टेराफॉर्म और इन्फ्रास्ट्रक्चर
टेराफ़ॉर्म सबसे व्यापक रूप से उपयोग किया जाने वाला इन्फ्रास्ट्रक्चर ऐज़ कोड (IaC) टूल है - यह आपको घोषणात्मक कॉन्फ़िगरेशन फ़ाइलों में क्लाउड इन्फ्रास्ट्रक्चर (सर्वर, डेटाबेस, नेटवर्क, अनुमतियाँ) को परिभाषित करने देता है जिसे संस्करणित, समीक्षा, परीक्षण और स्वचालित किया जा सकता है। क्लाउड कंसोल पर क्लिक करने के बजाय, आप कोड लिखते हैं जो आपके बुनियादी ढांचे की वांछित स्थिति का वर्णन करता है, और टेराफॉर्म यह पता लगाता है कि क्या बदलाव करने हैं।
---

## मूल अवधारणाएँ
| संकल्पना | विवरण |
|---------|-----------------|
| **प्रदाता** | प्लगइन जो एक विशिष्ट क्लाउड प्लेटफ़ॉर्म (AWS, Azure, GCP, आदि) का प्रबंधन करता है |
| **संसाधन** | एक इंफ्रास्ट्रक्चर ऑब्जेक्ट (सर्वर, डेटाबेस, नेटवर्क) |
| **राज्य** | कौन सा बुनियादी ढांचा मौजूद है, इसका टेराफॉर्म का रिकॉर्ड; एक राज्य फ़ाइल में संग्रहीत |
| **योजना** | टेराफॉर्म क्या बदलाव करेगा इसका पूर्वावलोकन |
| **लागू करें** | योजना निष्पादित करें; बुनियादी ढाँचा बनाएँ/अद्यतन/नष्ट करें |
| **मॉड्यूल** | संसाधनों का पुन: प्रयोज्य संग्रह |
| **परिवर्तनीय** | कॉन्फ़िगरेशन के लिए इनपुट पैरामीटर |
| **आउटपुट** | किसी मॉड्यूल या कॉन्फ़िगरेशन से निर्यात किया गया मान |
| **डेटा स्रोत** | मौजूदा बुनियादी ढांचे से जानकारी पढ़ें |
---

## बुनियादी कार्यप्रवाह
| कदम | आदेश | विवरण |
|------|---------|----------------|
| **1. कॉन्फ़िगरेशन लिखें** |`.tf`फ़ाइलें बनाएं | प्रदाताओं, संसाधनों, चरों को परिभाषित करें |
| **2. प्रारंभ करें** | `terraform init`| डाउनलोड प्रदाता; बैकएंड सेट करें |
| **3. प्रारूप** | `terraform fmt`| स्वरूपण को मानकीकृत करें |
| **4. मान्य करें** | `terraform validate`| सिंटैक्स और कॉन्फ़िगरेशन की जाँच करें |
| **5. योजना** | `terraform plan`| पूर्वावलोकन परिवर्तन (ड्राई रन) |
| **6. आवेदन करें** | `terraform apply`| बुनियादी ढांचा बनाएं या अपडेट करें |
| **7. नष्ट** | `terraform destroy`| सभी प्रबंधित बुनियादी ढांचे को नष्ट कर दें |
---

## सामान्य आदेश
| आदेश | विवरण |
|---------|-----------------|
| `terraform init`| कार्यशील निर्देशिका प्रारंभ करें; डाउनलोड प्रदाता और मॉड्यूल |
| `terraform plan`| दिखाएँ कि क्या परिवर्तन किए जाएंगे |
| `terraform apply`| परिवर्तनों को लागू करें; पुष्टिकरण छोड़ने के लिए`-auto-approve`जोड़ें |
| `terraform destroy`| सभी प्रबंधित संसाधनों को नष्ट करें |
| `terraform fmt`| कॉन्फ़िगरेशन फ़ाइलों को मानक शैली में प्रारूपित करें |
| `terraform validate`| कॉन्फ़िगरेशन सिंटैक्स मान्य करें |
| `terraform output`| आउटपुट मान दिखाएँ |
| `terraform state list`| राज्य में सभी संसाधनों की सूची बनाएं |
| `terraform state show <resource>`| किसी विशिष्ट संसाधन का विवरण दिखाएँ |
| `terraform import <resource> <id>`| राज्य में मौजूदा बुनियादी ढांचे को आयात करें |
| `terraform taint <resource>`| अगले आवेदन पर मनोरंजन के लिए एक संसाधन चिह्नित करें |
| `terraform refresh`| वास्तविक बुनियादी ढांचे से मेल खाने के लिए राज्य को अद्यतन करें |
| `terraform graph`| एक दृश्य निर्भरता ग्राफ (डीओटी प्रारूप) उत्पन्न करें |
| `terraform console`| अभिव्यक्ति के परीक्षण के लिए इंटरैक्टिव कंसोल |
---

## राज्य प्रबंधन
| सर्वोत्तम अभ्यास | विवरण |
|----|---|
| **दूरस्थ राज्य** | S3, GCS, Azure Blob, या टेराफ़ॉर्म क्लाउड में स्टोर स्थिति - कभी भी स्थानीय रूप से नहीं |
| **स्टेट लॉकिंग** | समवर्ती संशोधनों को रोकने के लिए DynamoDB (S3 बैकएंड) या नेटिव लॉकिंग का उपयोग करें |
| **राज्य एन्क्रिप्शन** | राज्य फ़ाइलों के लिए बाकी एन्क्रिप्शन सक्षम करें (उनमें संवेदनशील डेटा होता है) |
| **राज्य पृथक्करण** | विभिन्न परिवेशों या टीमों के लिए अलग-अलग राज्य फ़ाइलों का उपयोग करें |
| **स्टेट बैकअप** | रिमोट स्वचालित रूप से संस्करण स्थिति का बैकएंड करता है; इसे सक्षम रखें |
| **कभी भी स्थिति को मैन्युअल रूप से संपादित न करें** | इसके बजाय`terraform state mv`,`rm`,`import`का उपयोग करें |

## परिवर्तनशील प्रकार
| प्रकार | उदाहरण | केस का प्रयोग करें |
|------|---------|----------|
| **स्ट्रिंग** | `variable "region" { type = string }`| एकल पाठ मान |
| **संख्या** | `variable "count" { type = number }`| संख्यात्मक मान |
| **बूल** | `variable "enable" { type = bool }`| सच्चा/झूठा झंडा |
| **सूची** | `variable "zones" { type = list(string) }`| आदेशित संग्रह |
| **नक्शा** | `variable "tags" { type = map(string) }`| कुंजी-मूल्य जोड़े |
| **वस्तु** | `variable "config" { type = object({...}) }`| संरचित विन्यास |

## सामान्य पैटर्न
| पैटर्न | विवरण |
|---------|-----------------|
| **गणना** | `count = 3`एक संसाधन के अनेक उदाहरण बनाता है |
| **प्रत्येक के लिए** | `for_each = var.items`किसी मानचित्र या सेट पर पुनरावृत्त होता है |
| **गतिशील ब्लॉक** | बार-बार नेस्टेड ब्लॉक उत्पन्न करें (उदाहरण के लिए, प्रवेश नियम) |
| **स्थानीय मूल्य** |  परिकलित मानों और पुनरावृत्ति को कम करने के लिए`locals { ... }`|
| **डेटा स्रोत** | मौजूदा बुनियादी ढांचे को पढ़ें (उदाहरण के लिए, मौजूदा वीपीसी ढूंढें) |
| **प्रावधानकर्ता** | निर्माण के बाद संसाधनों पर स्क्रिप्ट चलाएँ (संयम से उपयोग करें) |
| **कार्यस्थान** | एक ही कॉन्फ़िगरेशन के भीतर विभिन्न वातावरणों के लिए अलग-अलग स्थिति |
---

## समस्या निवारण
| समस्या | समाधान |
|---------|----------|
| **राज्य बहाव** | अंतर देखने के लिए`terraform plan`चलाएँ; `terraform apply`सामंजस्य बिठाने के लिए |
| **लॉक स्थिति** | जांचें कि ताला किसके पास है; यदि सुरक्षित हो तो`terraform force-unlock`का उपयोग करें |
| **प्रदाता त्रुटियाँ** | साख की जाँच करें; अद्यतन प्रदाता संस्करण; एपीआई सीमाएं जांचें |
| **आयात विवाद** | राज्य में पहले से ही संसाधन; पहले`terraform state rm`का उपयोग करें |
| **परिपत्र निर्भरताएँ** | संसाधनों का पुनर्गठन;`depends_on`का सावधानी से उपयोग करें |
| **बड़ा राज्य** | मॉड्यूल में विभाजित; आंशिक संचालन के लिए`-target`का उपयोग करें |
---

## सारांश
टेराफ़ॉर्म घोषणात्मक कॉन्फ़िगरेशन फ़ाइलों के माध्यम से बुनियादी ढांचे का प्रबंधन करता है। वर्कफ़्लो है: कॉन्फ़िगरेशन लिखें → init → योजना → लागू करें। राज्य ट्रैक करता है कि क्या मौजूद है और उसे लॉकिंग के साथ दूरस्थ रूप से संग्रहीत किया जाना चाहिए। मॉड्यूल पुन: उपयोग को सक्षम करते हैं। वेरिएबल कॉन्फ़िगरेशन को पैरामीटराइज़ करते हैं। मुख्य सिद्धांत हैं: बुनियादी ढांचे को कोड के रूप में मानें (संस्करण नियंत्रण; समीक्षा; परीक्षण); राज्य को कभी भी मैन्युअल रूप से संपादित न करें; आवेदन करने से पहले योजना बनाएं; लॉकिंग के साथ दूरस्थ स्थिति का उपयोग करें; और रखरखाव के लिए मॉड्यूल के साथ संरचना विन्यास।
