# ML Engineering และ MLOps
การสร้างโมเดลแมชชีนเลิร์นนิงมีชัยไปกว่าครึ่งเท่านั้น การนำมันเข้าสู่การผลิต ทำให้มันทำงานได้อย่างน่าเชื่อถือ การตรวจสอบการดริฟท์ และวนซ้ำ - นั่นคือที่มาของวิศวกรรม ML และ MLOps ไฟล์นี้ครอบคลุมวงจรการใช้งานทั้งหมดตั้งแต่การทดลองไปจนถึงระบบที่ใช้งานจริง
---

## วงจรชีวิตของ ML
| เฟส | คำอธิบาย | กิจกรรมสำคัญ |
|-------|-------------|---------------|
| **1. คำจำกัดความของปัญหา** | วางกรอบปัญหาทางธุรกิจเป็นงาน ML | กำหนดตัวชี้วัด ข้อจำกัด เกณฑ์ความสำเร็จ |
| **2. การรวบรวมข้อมูล** | รวบรวมและติดป้ายกำกับข้อมูลการฝึกอบรม | ETL การติดฉลาก การเสริม |
| **3. การทดลอง** | ฝึกอบรมและประเมินโมเดล | วิศวกรรมคุณลักษณะ, การปรับแต่งไฮเปอร์พารามิเตอร์ |
| **4. การเลือกรุ่น** | เลือกรุ่นที่ดีที่สุด | เปรียบเทียบตัวชี้วัด ประเมินข้อเสีย |
| **5. การปรับใช้** | จัดส่งโมเดลเพื่อการผลิต | ให้บริการโครงสร้างพื้นฐาน API แบทช์ |
| **6. การตรวจสอบ** | เฝ้าระวังการดริฟท์และความเสื่อมโทรม | การดริฟท์ข้อมูล การดริฟท์แนวคิด ประสิทธิภาพ |
| **7. การฝึกอบรมขึ้นใหม่** | อัปเดตโมเดลด้วยข้อมูลใหม่ | การฝึกอบรมขึ้นใหม่ตามกำหนดเวลาหรือทริกเกอร์ |
ค่าส่วนใหญ่ (และความยาก) อยู่ในระยะที่ 5–7 โมเดลที่อยู่ในสมุดบันทึก Jupyter ไม่ได้สร้างมูลค่าทางธุรกิจ

## รูปแบบการให้บริการแบบจำลอง
| รูปแบบ | คำอธิบาย | เวลาแฝง | ใช้กรณี |
|---------|-------------|---------|----------|
| **การอนุมานเป็นกลุ่ม** | รันโมเดลบนแบตช์ข้อมูลตามกำหนดเวลา | ชั่วโมง | คำแนะนำรายวันคะแนนการโกง |
| **การอนุมานออนไลน์** | การคาดการณ์แบบเรียลไทม์ต่อคำขอ | มิลลิวินาที | อันดับการค้นหา การจัดหมวดหมู่แบบเรียลไทม์ |
| **การอนุมานแบบสตรีมมิ่ง** | ประมวลผลการคาดการณ์ในสตรีมข้อมูล | วินาที | การตรวจจับความผิดปกติ การประมวลผลเหตุการณ์ |
### ให้บริการโครงสร้างพื้นฐาน
| เครื่องมือ | พิมพ์ | ดีที่สุดสำหรับ |
|------|-|---------|
| **การให้บริการ TensorFlow** | เซิร์ฟเวอร์รุ่น | โมเดล TensorFlow |
| **TorchServe** | เซิร์ฟเวอร์รุ่น | รุ่น PyTorch |
| **เซิร์ฟเวอร์การอนุมาน Triton** | หลายเฟรมเวิร์ก | การอนุมาน GPU หลายเฟรมเวิร์ก |
| **vLLM** | ให้บริการ LLM | การอนุมาน LLM ความเร็วสูง |
| **เบนโตะเอ็มแอล** | การให้บริการแบบรวม | การปรับใช้แบบไม่เชื่อเรื่องกรอบงาน |
| **เซลดอน** | K8s-พื้นเมือง | การปรับใช้โมเดล Kubernetes |
| **เรย์เสิร์ฟ** ​​| การให้บริการที่ปรับขนาดได้ | โมเดลขนาดใหญ่ การอนุมานแบบกระจาย |

## การลงทะเบียนรุ่น
การลงทะเบียนโมเดลคือที่จัดเก็บส่วนกลางสำหรับการจัดการโมเดล ML เช่น เวอร์ชัน ข้อมูลเมตา ตัววัด และสถานะการใช้งาน
| ความสามารถ | คำอธิบาย |
|-----------|-------------|
| **เวอร์ชัน** | ติดตามทุกรุ่นด้วย ID ที่ไม่ซ้ำกัน |
| **ข้อมูลเมตา** | ข้อมูลการฝึกอบรม ไฮเปอร์พารามิเตอร์ ตัวชี้วัด ผู้แต่ง |
| **การเปลี่ยนฉาก** | ย้ายโมเดลไปตามขั้นตอนต่างๆ: การจัดเตรียม → การผลิต → เก็บถาวร |
| **เชื้อสาย** | ติดตามข้อมูลและโค้ดที่สร้างแต่ละรุ่น |
| เครื่องมือ | คำอธิบาย |
|-|-------------|
| **MLflow** | โอเพ่นซอร์ส; การลงทะเบียนโมเดล + การติดตามการทดสอบ |
| **น้ำหนักและอคติ (W&B)** | ทางการค้า; การติดตามการทดสอบ + การลงทะเบียนโมเดล |
| **ดีวีซี** | การกำหนดเวอร์ชันข้อมูลและโมเดลด้วย Git |
| **Azure ML / SageMaker** | การจัดการโมเดลแบบคลาวด์เนทีฟ |

## การติดตามการทดลอง
ควรติดตามการทดสอบ ML ทุกครั้ง เช่น ข้อมูลใดที่ใช้ ไฮเปอร์พารามิเตอร์ใด ผลลัพธ์เป็นหน่วยเมตริกใด
| เครื่องมือ | คุณสมบัติที่สำคัญ |
|-|-------------|
| **MLflow** | โอเพ่นซอร์ส โฮสต์เอง ติดตามพารามิเตอร์/เมตริก/อาร์ติแฟกต์ |
| **ดับเบิลยูแอนด์บี** | Rich UI, การเรตติ้ง, การกำหนดเวอร์ชันสิ่งประดิษฐ์, รายงาน |
| **ดาวเนปจูน** | ที่เก็บข้อมูลเมตาสำหรับ MLOps |
| **เทนเซอร์บอร์ด** | สร้างขึ้นใน TensorFlow; เห็นภาพเส้นโค้งการฝึก |
### สิ่งที่ต้องติดตาม
| หมวดหมู่ | ตัวอย่าง |
|----------|---------|
| **พารามิเตอร์** | อัตราการเรียนรู้ ขนาดแบทช์ สถาปัตยกรรมแบบจำลอง จำนวนยุค |
| **ตัวชี้วัด** | ความแม่นยำ การสูญเสีย F1 AUC-ROC (ต่อยุคและสุดท้าย) |
| **สิ่งประดิษฐ์** | ตุ้มน้ำหนักแบบจำลอง เมทริกซ์ความสับสน ตัวอย่างการทำนาย |
| **ข้อมูล** | เวอร์ชันชุดข้อมูล อัตราส่วนการแยก ขั้นตอนการประมวลผลล่วงหน้า |
| **สิ่งแวดล้อม** | เวอร์ชัน Python, เวอร์ชันไลบรารี, ฮาร์ดแวร์ |

## กลยุทธ์การปรับใช้แบบจำลอง
| กลยุทธ์ | มันทำงานอย่างไร | ความเสี่ยง |
|----------|-------------|------|
| **การปรับใช้เงา** | รุ่นใหม่วิ่งเคียงข้างรุ่นเก่า การเปรียบเทียบการคาดการณ์แต่ไม่ได้ให้บริการ | ความเสี่ยงเป็นศูนย์ ตรวจสอบก่อนที่จะถ่ายทอดสด |
| **นกขมิ้นปล่อย** | กำหนดเส้นทาง % เล็กน้อยของการรับส่งข้อมูลไปยังโมเดลใหม่ เพิ่มขึ้นเรื่อยๆ | ความเสี่ยงต่ำ ย้อนกลับอย่างรวดเร็ว |
| **การทดสอบ A/B** | แยกผู้ใช้ระหว่างเก่าและใหม่ เปรียบเทียบตัวชี้วัดทางธุรกิจ | วัดผลกระทบที่เกิดขึ้นจริง |
| **ฟ้า-เขียว** | สองสภาพแวดล้อมที่เหมือนกัน สลับการรับส่งข้อมูลทั้งหมดในครั้งเดียว | ย้อนกลับทันที; ค่าใช้จ่ายสองเท่าระหว่างการเปลี่ยนแปลง |
| **คุณสมบัติเด่น** | สลับเปิด/ปิดโมเดลตามกลุ่มผู้ใช้ | การควบคุมที่ละเอียด |

## การตรวจสอบระบบ ML
ระบบ ML ต้องการการตรวจสอบมากกว่าซอฟต์แวร์แบบดั้งเดิม เนื่องจากข้อมูลสามารถเปลี่ยนแปลงได้
### ประเภทดริฟท์
| ประเภทดริฟท์ | การเปลี่ยนแปลงอะไร | ตัวอย่าง |
|----------|-------------|---------|
| **ดริฟท์ข้อมูล** | การเปลี่ยนแปลงการกระจายอินพุต | ข้อมูลประชากรของลูกค้าเปลี่ยนไปหลังแคมเปญการตลาด |
| **แนวคิดดริฟท์** | ความสัมพันธ์ระหว่างการเปลี่ยนแปลงอินพุตและเอาต์พุต | พฤติกรรมผู้บริโภคเปลี่ยนแปลงไปในช่วงเศรษฐกิจถดถอย |
| **ฉลากดริฟท์** | การเปลี่ยนแปลงการกระจายเป้าหมาย | อัตราการฉ้อโกงเพิ่มขึ้นจาก 1% เป็น 5% |
### สิ่งที่ต้องตรวจสอบ
| หมวดหมู่ | ตัวชี้วัด |
|----------|---------|
| **ประสิทธิภาพของโมเดล** | ความแม่นยำ ความแม่นยำ การเรียกคืน F1, AUC (เทียบกับค่าพื้นฐาน) |
| **คุณภาพข้อมูล** | ค่าที่หายไป การแจกแจงคุณลักษณะ ค่าผิดปกติ |
| **การตรวจจับการดริฟท์** | การทดสอบทางสถิติ (การทดสอบ KS, PSI, ความแตกต่างของ KL) |
| **โครงสร้างพื้นฐาน** | เวลาแฝง, ปริมาณงาน, การใช้งาน GPU, หน่วยความจำ |
| **ตัวชี้วัดทางธุรกิจ** | อัตราการแปลง ผลกระทบต่อรายได้ ความพึงพอใจของผู้ใช้ |
### เครื่องมือตรวจสอบ
| เครื่องมือ | พิมพ์ |
|-|------|
| **เห็นได้ชัดว่า AI** | การดริฟท์ข้อมูลโอเพ่นซอร์สและการตรวจสอบประสิทธิภาพของโมเดล |
| **กราฟาน่า** | การแสดงภาพแดชบอร์ด (ทำงานร่วมกับ Prometheus) |
| **ทำไมแล็บส์** | แพลตฟอร์มการสังเกตข้อมูล |
| **อาไรซ์** | ความสามารถในการสังเกต ML และการวิเคราะห์สาเหตุที่แท้จริง |
| **โพรมีธีอุส + กราฟาน่า** | ตัวชี้วัดโครงสร้างพื้นฐานและแอปพลิเคชัน |

## การฝึกอบรมที่ทำซ้ำได้
ความสามารถในการทำซ้ำหมายความว่าคุณสามารถทำการทดสอบซ้ำและได้รับผลลัพธ์เดียวกัน จำเป็นสำหรับการดีบัก การตรวจสอบ และการปฏิบัติตามข้อกำหนด
### ความต้องการ
| ข้อกำหนด | ทำอย่างไรจึงจะบรรลุผล |
|-----------------|-------------------|
| **การกำหนดเวอร์ชันข้อมูล** | DVC, Delta Lake หรือสแนปช็อตชุดข้อมูลที่มีแฮช |
| **การกำหนดเวอร์ชันโค้ด** | Git สำหรับโค้ดการฝึกอบรมทั้งหมด |
| **ปักหมุดสิ่งแวดล้อม** | `requirements.txt`,`conda env`, อิมเมจ Docker พร้อมเวอร์ชันที่แน่นอน |
| **การตั้งเมล็ด** | แก้ไขเมล็ดสุ่มสำหรับ numpy, torch, tensorflow |
| **การจัดการการกำหนดค่า** | การกำหนดค่า Hydra, OmegaConf หรือ YAML สำหรับไฮเปอร์พารามิเตอร์ทั้งหมด |
| **การติดตามสิ่งประดิษฐ์** | MLflow หรือ W&B เพื่อบันทึกทุกการทดลอง |

## การอนุมานมาตราส่วน
เมื่อโมเดลจำเป็นต้องตอบสนองคำขอนับล้านครั้งต่อวัน ประสิทธิภาพเป็นสิ่งสำคัญ
| เทคนิค | คำอธิบาย |
|-----------|-------------|
| **การแบทช์** | จัดกลุ่มคำขอหลายรายการเป็นการส่งต่อครั้งเดียว |
| **ปริมาณ** | ลดความแม่นยำของโมเดล (FP32 → INT8 หรือ INT4) เพื่อการอนุมานที่เร็วขึ้น |
| **แบบจำลองการกลั่น** | ฝึกโมเดลขนาดเล็กเพื่อเลียนแบบโมเดลที่ใหญ่กว่า |
| **การตัดแต่งกิ่ง** | ลบน้ำหนักหรือเซลล์ประสาทที่ไม่สำคัญ |
| **แคช** | แคชการคาดการณ์บ่อยครั้งเพื่อหลีกเลี่ยงการคำนวณใหม่ |
| **การเพิ่มประสิทธิภาพ GPU** | TensorRT, รันไทม์ ONNX, ความสนใจแบบแฟลช |
| **การปรับสเกลแนวนอน** | เรียกใช้แบบจำลองหลายแบบจำลองเบื้องหลังโหลดบาลานเซอร์ |

## แฟล็กคุณลักษณะสำหรับ ML
แฟล็กคุณลักษณะช่วยให้คุณควบคุมเวอร์ชันของโมเดลที่ให้บริการแก่ผู้ใช้รายใด โดยไม่ต้องปรับใช้ใหม่
| ใช้กรณี | คำอธิบาย |
|----------|-------------|
| **การเปิดตัวแบบค่อยเป็นค่อยไป** | ให้บริการโมเดลใหม่แก่ผู้ใช้ 5% จากนั้นเพิ่ม |
| **สวิตช์ฆ่า** | เปลี่ยนกลับเป็นรุ่นก่อนหน้าทันทีหากตรวจพบปัญหา |
| **ตามกลุ่ม** | รุ่นที่แตกต่างกันสำหรับกลุ่มผู้ใช้ที่แตกต่างกัน |
| **การทดลอง** | รูปแบบการทดสอบ A/B พร้อมเมตริกธุรกิจ |
เครื่องมือ: LaunchDarkly, Unleash, Flagsmith หรือแฟล็กฟีเจอร์ที่สนับสนุนฐานข้อมูลแบบธรรมดา

## เส้นโค้งการเจริญเติบโตของ MLOps
| ระดับ | ลักษณะ |
|----------------------|----------------|
| **ระดับ 0 — แมนนวล** | การฝึกอบรมด้วยตนเอง การปรับใช้ด้วยตนเอง ไม่มีการตรวจสอบ |
| **ระดับ 1 — การทดลอง** | การติดตามการทดลอง การลงทะเบียนโมเดล CI พื้นฐาน |
| **ระดับ 2 — ระบบอัตโนมัติ** | การฝึกอบรมขึ้นใหม่อัตโนมัติ, CI/CD สำหรับโมเดล, การทดสอบอัตโนมัติ |
| **ระดับ 3 — ไปป์ไลน์แบบเต็ม** | ไปป์ไลน์อัตโนมัติแบบครบวงจรพร้อมการตรวจสอบ การตรวจจับการดริฟท์ และการฝึกอบรมใหม่อัตโนมัติ |
องค์กรส่วนใหญ่อยู่ระหว่างระดับ 0 ถึงระดับ 1 เป้าหมายคือระดับ 2-3 โดยที่วงจรชีวิตของ ML เป็นแบบอัตโนมัติและรักษาตัวเองได้
