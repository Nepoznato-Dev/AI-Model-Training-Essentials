| `review_date`/`next_review`| จังหวะ ~6 เดือนและ ~1 ปี สะท้อนตารางทบทวนทักษะ |
| `tags`| โทเค็นชื่อไฟล์บวกกับคีย์เวิร์ดหมวดหมู่ที่ชัดเจน (เช่น`coding-and-technology`) |
| `difficulty_level`| กำหนดตามหมวดหมู่ พร้อมการแทนที่ต่อภาษา (เช่น Haskell/Assembly →`advanced`, Scratch →`beginner`) |
| `estimated_reading_time`| คำนวณจากจำนวนบรรทัด |
### การแก้ไขไฟล์
เมื่อคุณเปลี่ยนไฟล์ฐานความรู้ ให้ซิงค์ส่วนหน้าของไฟล์ไว้:
1. **ชน`version`** กำลังติดตาม[SemVer](https://semver.org/):
   - แพทช์ (`1.0.x`): การพิมพ์ผิด การจัดรูปแบบ การแก้ไขเล็กน้อย
   - รอง (`1.x.0`): ส่วนใหม่ เนื้อหาเพิ่มเติม ตัวอย่างใหม่
   - Major (`x.0.0`): เขียนใหม่หรือปรับโครงสร้างใหม่ทั้งหมด
2. **เพิ่มรายการบันทึกการเปลี่ยนแปลง** (ใหม่ที่สุดก่อน) อธิบายสิ่งที่คุณเปลี่ยนแปลง:   ```yaml
   changelog:
     - version: "1.1.0"
       date: "2026-08-05"
       author: "Your Name"
       changes: "Expanded the ecosystem section with packaging tools"
     - version: "1.0.0"
       date: "2026-08-05"
       author: "AI Model Training Team"
       changes: "Added YAML frontmatter metadata for contributor tracking"
   ```
3. **อัปเดต`last_modified`** เป็นวันที่คุณเปลี่ยนแปลง
4. **เพิ่มตัวคุณเองใน`contributors`** หากเป็นการแก้ไขไฟล์ครั้งแรก:   ```yaml
   contributors:
     - name: "Your Name"
       email: "you@example.com"
       role: "contributor"
   ```

### รายการตรวจสอบคุณภาพ
ก่อนที่จะส่งไฟล์ฐานความรู้ใหม่หรือที่มีการแก้ไข ให้ตรวจสอบ:
- [ ] ส่วนหน้าของ YAML เสร็จสมบูรณ์และถูกต้อง (มีทั้งหมดห้าส่วนอยู่ระหว่างตัวคั่น `---`)
- [ ]`title`,`description`,`category`,`version`,`status`ถูกตั้งค่าแล้ว
- [ ] มีผู้เขียนอย่างน้อยหนึ่งรายอยู่ในรายการ`authors`
- [ ]`changelog`มีรายการบันทึกการเปลี่ยนแปลง (ล่าสุดก่อน)
- [ ]`last_modified`สะท้อนถึงวันที่ของวันนี้
- [ ]`tags`รวมคำหลักที่เกี่ยวข้อง 3-6 คำ บวกกับคำหลักหมวดหมู่ที่สะอาดตา
- [ ]`difficulty_level`ถูกตั้งค่าแล้ว (เริ่มต้น / กลาง / ขั้นสูง)
- [ ]`estimated_reading_time`มีความสมจริงสำหรับความยาวของเนื้อหา
- [ ] เนื้อหาเนื้อหาเป็นไปตาม[Usage Guidelines](#usage-guidelines)ด้านบน
- [ ] ไม่มีการอ้างอิงโยงที่เสียหาย
