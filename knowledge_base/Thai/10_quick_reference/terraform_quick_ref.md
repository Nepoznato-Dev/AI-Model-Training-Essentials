# Terraform และโครงสร้างพื้นฐานเป็นโค้ด
Terraform เป็นเครื่องมือ Infrastructure as Code (IaC) ที่ใช้กันอย่างแพร่หลาย โดยช่วยให้คุณกำหนดโครงสร้างพื้นฐานคลาวด์ (เซิร์ฟเวอร์ ฐานข้อมูล เครือข่าย การอนุญาต) ในไฟล์การกำหนดค่าที่เปิดเผยซึ่งสามารถกำหนดเวอร์ชัน ตรวจสอบ ทดสอบ และทำงานอัตโนมัติได้ แทนที่จะคลิกผ่านคอนโซลคลาวด์ คุณจะเขียนโค้ดที่อธิบายสถานะโครงสร้างพื้นฐานที่คุณต้องการ จากนั้น Terraform จะคำนวณว่าจะต้องเปลี่ยนแปลงอะไรบ้าง
---

## แนวคิดหลัก
| แนวคิด | คำอธิบาย |
|---------|-------------|
| **ผู้ให้บริการ** | ปลั๊กอินที่จัดการแพลตฟอร์มคลาวด์เฉพาะ (AWS, Azure, GCP ฯลฯ ) |
| **แหล่งข้อมูล** | ออบเจ็กต์โครงสร้างพื้นฐาน (เซิร์ฟเวอร์ ฐานข้อมูล เครือข่าย) |
| **รัฐ** | บันทึกของ Terraform เกี่ยวกับโครงสร้างพื้นฐานที่มีอยู่ เก็บไว้ในไฟล์สถานะ |
| **แผน** | ดูตัวอย่างการเปลี่ยนแปลงที่ Terraform จะทำ |
| **สมัคร** | ดำเนินการตามแผน สร้าง/อัพเดต/ทำลายโครงสร้างพื้นฐาน |
| **โมดูล** | การรวบรวมทรัพยากรที่ใช้ซ้ำได้ |
| **ตัวแปร** | พารามิเตอร์อินพุตสำหรับการกำหนดค่า |
| **เอาท์พุท** | ค่าที่ส่งออกจากโมดูลหรือการกำหนดค่า |
| **แหล่งข้อมูล** | อ่านข้อมูลจากโครงสร้างพื้นฐานที่มีอยู่ |
---

## ขั้นตอนการทำงานขั้นพื้นฐาน
| ขั้นตอน | คำสั่ง | คำอธิบาย |
|------|---------|-------------|
| **1. เขียนการกำหนดค่า** | สร้างไฟล์`.tf`| กำหนดผู้ให้บริการ ทรัพยากร ตัวแปร |
| **2. เริ่มต้น** | `terraform init`| ผู้ให้บริการดาวน์โหลด; ตั้งค่าแบ็กเอนด์ |
| **3. รูปแบบ** | `terraform fmt`| จัดรูปแบบมาตรฐาน |
| **4. ตรวจสอบความถูกต้อง** | `terraform validate`| ตรวจสอบไวยากรณ์และการกำหนดค่า |
| **5. แผน** | `terraform plan`| ดูตัวอย่างการเปลี่ยนแปลง (ทดลองรัน) |
| **6. สมัคร** | `terraform apply`| สร้างหรืออัปเดตโครงสร้างพื้นฐาน |
| **7. ทำลาย** | `terraform destroy`| รื้อโครงสร้างพื้นฐานที่ได้รับการจัดการทั้งหมด |
---

## คำสั่งทั่วไป
| คำสั่ง | คำอธิบาย |
|---------|-------------|
| `terraform init`| เริ่มต้นไดเร็กทอรีการทำงาน ผู้ให้บริการดาวน์โหลดและโมดูล |
| `terraform plan`| แสดงสิ่งที่จะทำการเปลี่ยนแปลง |
| `terraform apply`| ใช้การเปลี่ยนแปลง เพิ่ม`-auto-approve`เพื่อข้ามการยืนยัน |
| `terraform destroy`| ทำลายทรัพยากรที่ได้รับการจัดการทั้งหมด |
| `terraform fmt`| จัดรูปแบบไฟล์การกำหนดค่าเป็นรูปแบบมาตรฐาน |
| `terraform validate`| ตรวจสอบไวยากรณ์การกำหนดค่า |
| `terraform output`| แสดงค่าเอาต์พุต |
| `terraform state list`| แสดงรายการทรัพยากรทั้งหมดในสถานะ |
| `terraform state show <resource>`| แสดงรายละเอียดของทรัพยากรเฉพาะ |
| `terraform import <resource> <id>`| นำเข้าโครงสร้างพื้นฐานที่มีอยู่เข้าสู่สถานะ |
| `terraform taint <resource>`| ทำเครื่องหมายแหล่งข้อมูลเพื่อการพักผ่อนหย่อนใจครั้งต่อไป |
| `terraform refresh`| อัปเดตสถานะให้ตรงกับโครงสร้างพื้นฐานจริง |
| `terraform graph`| สร้างกราฟการพึ่งพาภาพ (รูปแบบ DOT) |
| `terraform console`| คอนโซลแบบโต้ตอบสำหรับการทดสอบนิพจน์ |
---

## การจัดการของรัฐ
| แนวปฏิบัติที่ดีที่สุด | คำอธิบาย |
|--------------|-------------|
| **สถานะระยะไกล** | จัดเก็บสถานะใน S3, GCS, Azure Blob หรือ Terraform Cloud — ไม่เคยอยู่ในเครื่อง |
| **สถานะล็อค** | ใช้ DynamoDB (แบ็กเอนด์ S3) หรือการล็อกแบบเนทิฟเพื่อป้องกันการแก้ไขพร้อมกัน |
| **การเข้ารหัสสถานะ** | เปิดใช้งานการเข้ารหัสที่เหลือสำหรับไฟล์สถานะ (มีข้อมูลที่ละเอียดอ่อน) |
| **การแยกรัฐ** | ใช้ไฟล์สถานะแยกกันสำหรับสภาพแวดล้อมหรือทีมที่แตกต่างกัน |
| **สถานะสำรอง** | แบ็กเอนด์ระยะไกลจะระบุเวอร์ชันโดยอัตโนมัติ เปิดใช้งานสิ่งนี้ |
| **ไม่ต้องแก้ไขสถานะด้วยตนเอง** | ใช้`terraform state mv`,`rm`,`import`แทน |
---

## โครงสร้างโมดูล
```
module/
├── main.tf          # Primary resources
├── variables.tf     # Input variables
├── outputs.tf       # Output values
├── versions.tf      # Provider and Terraform version constraints
├── README.md        # Documentation
└── examples/        # Example usage
    └── basic/
        └── main.tf
```

## ประเภทตัวแปร
| พิมพ์ | ตัวอย่าง | ใช้กรณี |
|------|---------|----------|
| **สตริง** | `variable "region" { type = string }`| ค่าข้อความเดียว |
| **หมายเลข** | `variable "count" { type = number }`| ค่าตัวเลข |
| **บูล** | `variable "enable" { type = bool }`| แฟล็กจริง/เท็จ |
| **รายการ** | `variable "zones" { type = list(string) }`| สั่งซื้อคอลเลกชัน |
| **แผนที่** | `variable "tags" { type = map(string) }`| คู่คีย์-ค่า |
| **วัตถุ** | `variable "config" { type = object({...}) }`| การกำหนดค่าแบบมีโครงสร้าง |
---

## รูปแบบทั่วไป
| รูปแบบ | คำอธิบาย |
|---------|-------------|
| **นับ** | `count = 3`สร้างหลายอินสแตนซ์ของทรัพยากร |
| **สำหรับแต่ละ** | `for_each = var.items`วนซ้ำบนแผนที่หรือตั้งค่า |
| **บล็อกไดนามิก** | สร้างบล็อกที่ซ้อนกันซ้ำๆ (เช่น กฎทางเข้า) |
| **ค่านิยมท้องถิ่น** | `locals { ... }`สำหรับค่าที่คำนวณและการลดการซ้ำซ้อน |
| **แหล่งข้อมูล** | อ่านโครงสร้างพื้นฐานที่มีอยู่ (เช่น ค้นหา VPC ที่มีอยู่) |
| **ผู้จัดเตรียม** | เรียกใช้สคริปต์บนทรัพยากรหลังการสร้าง (ใช้เท่าที่จำเป็น) |
| **พื้นที่ทำงาน** | แยกสถานะสำหรับสภาพแวดล้อมที่แตกต่างกันภายใน config | เดียวกัน
---

## การแก้ไขปัญหา
| ปัญหา | โซลูชั่น |
|---------|----------|
| **สภาพดริฟท์** | เรียกใช้`terraform plan`เพื่อดูความแตกต่าง `terraform apply`เพื่อกระทบยอด |
| **สถานะล็อค** | ตรวจสอบว่าใครล็อคอยู่ ใช้`terraform force-unlock`ถ้าปลอดภัย |
| **ข้อผิดพลาดของผู้ให้บริการ** | ตรวจสอบข้อมูลประจำตัว; อัปเดตเวอร์ชันของผู้ให้บริการ ตรวจสอบขีดจำกัด API |
| **ข้อขัดแย้งในการนำเข้า** | ทรัพยากรอยู่ในสถานะแล้ว ใช้`terraform state rm`ก่อน |
| **การอ้างอิงแบบวงกลม** | ปรับโครงสร้างทรัพยากร ใช้`depends_on`อย่างระมัดระวัง |
| **รัฐขนาดใหญ่** | แบ่งออกเป็นโมดูล ใช้`-target`สำหรับการดำเนินการบางส่วน |
---

## สรุป
Terraform จัดการโครงสร้างพื้นฐานผ่านไฟล์การกำหนดค่าที่ประกาศ ขั้นตอนการทำงานคือ: เขียนการกำหนดค่า → init → plan → Apply รัฐติดตามสิ่งที่มีอยู่และต้องจัดเก็บระยะไกลด้วยการล็อค โมดูลช่วยให้สามารถนำกลับมาใช้ใหม่ได้ การกำหนดค่าพารามิเตอร์ตัวแปร หลักการสำคัญคือ: ปฏิบัติต่อโครงสร้างพื้นฐานเสมือนเป็นโค้ด (การควบคุมเวอร์ชัน ทบทวน ทดสอบ); อย่าแก้ไขสถานะด้วยตนเอง วางแผนก่อนสมัคร ใช้สถานะระยะไกลพร้อมล็อค และการกำหนดค่าโครงสร้างด้วยโมดูลเพื่อการบำรุงรักษา
