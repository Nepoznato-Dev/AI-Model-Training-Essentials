#โพรมีธีอุสและกราฟาน่า
Prometheus เป็นชุดเครื่องมือตรวจสอบและแจ้งเตือนแบบโอเพ่นซอร์สที่ออกแบบมาเพื่อความน่าเชื่อถือและความสามารถในการปรับขนาด Grafana เป็นแพลตฟอร์มโอเพ่นซอร์สชั้นนำสำหรับการแสดงภาพข้อมูลอนุกรมเวลา เมื่อรวมกันแล้วจะก่อให้เกิดสแต็กการตรวจสอบที่ได้รับความนิยมสูงสุดสำหรับโครงสร้างพื้นฐานและแอปพลิเคชันสมัยใหม่ Prometheus รวบรวมและจัดเก็บหน่วยวัด Grafana แสดงในแดชบอร์ด
---

## สถาปัตยกรรมโพรมีธีอุส
| ส่วนประกอบ | คำอธิบาย |
|-----------|-------------|
| **เซิร์ฟเวอร์โพรมีธีอุส** | ขูดเมตริกจากเป้าหมาย เก็บข้อมูลอนุกรมเวลา ประเมินกฎการแจ้งเตือน |
| **ผู้ส่งออก** | เปิดเผยตัวชี้วัดจากระบบ (ผู้ส่งออกโหนด, cAdvisor ฯลฯ )
| **ทางเข้าออก** | รับตัวชี้วัดจากงานอายุสั้น (งานแบทช์, CI) |
| **ผู้จัดการการแจ้งเตือน** | จัดการการแจ้งเตือน: การจัดกลุ่ม การปิดเสียง การกำหนดเส้นทาง การยับยั้ง |
| **การค้นพบบริการ** | ค้นหาเป้าหมายโดยอัตโนมัติ (Kubernetes, Consul, EC2 ฯลฯ ) |

## แนวคิดหลัก
| แนวคิด | คำอธิบาย |
|---------|-------------|

| **อนุกรมเวลา** | กระแสข้อมูลจุดสำหรับชุดเมตริก + ป้ายกำกับเฉพาะ |
| **งาน** | รวมเป้าหมายที่มีจุดประสงค์เดียวกัน |
| **ตัวอย่าง** | เป้าหมายเดียวที่จะขูด (โดยปกติจะเป็นกระบวนการ) |
| **ขูด** | โพรดึงการวัดจากเป้าหมายในช่วงเวลาปกติ |
| **ป้ายกำกับ** | คู่คีย์-ค่าที่กำหนดมิติข้อมูลเมตริก (เช่น`method="GET"`) |
| **ตัวอย่าง** | ค่า ณ เวลาใดเวลาหนึ่ง: (การประทับเวลา, ค่า) |

## PromQL (ภาษาแบบสอบถาม)
### แบบสอบถามพื้นฐาน
| แบบสอบถาม | คำอธิบาย |
|-------|-------------|
| `http_requests_total`| อนุกรมเวลาดิบ |
| `http_requests_total{method="GET"}`| กรองตามป้ายกำกับ |
| `http_requests_total{method="GET", status="200"}`| ตัวกรองป้ายกำกับหลายรายการ |
| `rate(http_requests_total[5m])`| อัตราต่อวินาทีในช่วง 5 นาที |
| `increase(http_requests_total[1h])`| รวมเพิ่มขึ้นมากกว่า 1 ชั่วโมง |
| `sum(rate(http_requests_total[5m])) by (status)`| อัตรารวมตามสถานะ |
| `histogram_quantile(0.95, rate(http_duration_bucket[5m]))`| เวลาแฝงเปอร์เซ็นไทล์ที่ 95 |
| `avg(node_cpu_seconds_total{mode="idle"})`| CPU โดยเฉลี่ยไม่ได้ใช้งาน |
| `1 - avg(rate(node_cpu_seconds_total{mode="idle"}[5m]))`| การใช้งาน CPU |
### ฟังก์ชั่นทั่วไป
| ฟังก์ชัน | คำอธิบาย | ตัวอย่าง |
|----------|-------------|---------|
| `rate()`| อัตราการเพิ่มเฉลี่ยต่อวินาที | `rate(requests_total[5m])`|
| `irate()`| อัตราต่อวินาทีอิงตามจุดข้อมูลสองจุดสุดท้าย | `irate(requests_total[1m])`|
| `increase()`| การเพิ่มขึ้นทั้งหมดในช่วงเวลา | `increase(errors_total[1h])`|
| `sum()`| ผลรวมข้ามซีรีส์ | `sum(rate(requests_total[5m])) by (service)`|
| `avg()`| ค่าเฉลี่ยตลอดทั้งซีรีส์ | `avg(node_memory_usage)`|
| `histogram_quantile()`| คำนวณควอนไทล์จากฮิสโตแกรม | `histogram_quantile(0.99, rate(duration_bucket[5m]))`|
| `topk()`| ซีรี่ส์ K ยอดนิยมตามค่า | `topk(5, rate(requests_total[5m]))`|
| `predict_linear()`| การทำนายเชิงเส้น | `predict_linear(disk_usage[1h], 4*3600)`|
| `absent()`| ตรวจสอบว่าเมตริกหายไปหรือไม่ | `absent(up{job="myapp"})`|

## ผู้ส่งออกทั่วไป
| ผู้ส่งออก | มันตรวจสอบอะไร |
|----------|-----------------|
| **ผู้ส่งออกโหนด** | ตัววัดโฮสต์ Linux/Unix (CPU, หน่วยความจำ, ดิสก์, เครือข่าย) |
| **cAdvisor** | เมตริกคอนเทนเนอร์ (CPU, หน่วยความจำ, เครือข่าย, ระบบไฟล์) |
| **ผู้ส่งออก MySQL** | ตัวชี้วัดฐานข้อมูล MySQL |
| **ผู้ส่งออก PostgreSQL** | ตัววัดฐานข้อมูล PostgreSQL |
| **ผู้ส่งออก Redis** | ตัวชี้วัด Redis |
| **ผู้ส่งออกกล่องดำ** | ตรวจสอบจุดสิ้นสุดผ่าน HTTP, HTTPS, DNS, TCP, ICMP |
| **ผู้ส่งออก SNMP** | การวัดอุปกรณ์เครือข่ายผ่าน SNMP |
| **ผู้ส่งออก JSON** | ตัวชี้วัดที่กำหนดเองจาก JSON APIs |

## กราฟาน่า
### แนวคิดหลัก
| แนวคิด | คำอธิบาย |
|---------|-------------|
| **แหล่งข้อมูล** | การเชื่อมต่อกับ Prometheus (หรือแบ็กเอนด์อื่น ๆ ) |
| **แดชบอร์ด** | การรวบรวมแผงที่จัดเรียงในรูปแบบ |
| **แผง** | การสร้างภาพข้อมูลเดี่ยว (กราฟ เกจ ตาราง แผนที่ความร้อน) |
| **ตัวแปร** | ตัวกรองแบบไดนามิกสำหรับแดชบอร์ด (เช่น เลือกอินสแตนซ์) |
| **คำอธิบายประกอบ** | ทำเครื่องหมายเหตุการณ์บนกราฟ (การใช้งาน เหตุการณ์) |
| **กฎการแจ้งเตือน** | การแจ้งเตือนตามเกณฑ์ภายใน Grafana |
| **การสร้างเทมเพลต** | รูปแบบแดชบอร์ดที่ใช้ซ้ำได้พร้อมตัวแปร |
### รูปแบบแดชบอร์ดที่มีประโยชน์
| รูปแบบ | คำอธิบาย |
|---------|-------------|
| **แถวภาพรวม** | สรุปตัวชี้วัดหลัก: อัตราข้อผิดพลาด เวลาแฝง ปริมาณการประมวลผล |
| **เจาะลึก** | คลิกจากสรุปไปยังมุมมองรายละเอียดโดยใช้ตัวแปร |
| **วิธีสีแดง** | อัตรา ข้อผิดพลาด ระยะเวลา — ตัวชี้วัดการบริการหลักสามประการ |
| **ใช้วิธีการ** | การใช้งาน ความอิ่มตัว ข้อผิดพลาด — สำหรับโครงสร้างพื้นฐาน |
| **สัญญาณทอง** | เวลาแฝง การรับส่งข้อมูล ข้อผิดพลาด ความอิ่มตัว (หนังสือ SRE ของ Google) |

## การแจ้งเตือน
### โครงสร้างกฎการแจ้งเตือน
```yaml
groups:
  - name: example
    rules:
      - alert: HighErrorRate
        expr: rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m]) > 0.05
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "High error rate on {{ $labels.instance }}"
          description: "Error rate is {{ $value | humanizePercentage }}"
```

### การกำหนดเส้นทางตัวจัดการการแจ้งเตือน
| แนวคิด | คำอธิบาย |
|---------|-------------|
| **กลุ่ม** | รวมการแจ้งเตือนที่คล้ายกันเป็นการแจ้งเตือนเดียว |
| **เส้นทาง** | แผนผังของผู้จับคู่ที่กำหนดว่าการแจ้งเตือนจะไปที่ใด |
| **ผู้รับ** | จะส่งการแจ้งเตือนได้ที่ไหน (อีเมล, Slack, PagerDuty, webhook) |
| **ยับยั้ง** | ระงับการแจ้งเตือนเมื่อมีการแจ้งเตือนอื่น |
| **ความเงียบ** | ปิดเสียงการแจ้งเตือนชั่วคราวโดยตัวจับคู่ป้ายกำกับ |

## การแก้ไขปัญหา
| ปัญหา | โซลูชั่น |
|---------|----------|
| **กำหนดเป้าหมายลง** | ตรวจสอบว่าผู้ส่งออกกำลังทำงานอยู่หรือไม่ ตรวจสอบเครือข่าย/ไฟร์วอลล์ ตรวจสอบการกำหนดค่าการขูด |
| **ไม่มีข้อมูล** | ตรวจสอบการสะกดชื่อเมตริก ตรวจสอบตัวกรองฉลาก ตรวจสอบช่วงเวลา |
| **จำนวนสมาชิกในเซ็ตสูง** | มีป้ายกำกับผสมกันมากเกินไป ลดค่าฉลาก ใช้กฎการบันทึก |
| **สอบถามช้า** | ใช้กฎการบันทึกสำหรับการสืบค้นที่ซับซ้อน เพิ่มช่วงการขูด |
| **แจ้งเตือนเมื่อยล้า** | ปรับเกณฑ์; เพิ่มระยะเวลา `for`; การแจ้งเตือนที่เกี่ยวข้องกับกลุ่ม |
| **ตัวชี้วัดหายไปหลังจากรีสตาร์ท** | Prometheus จัดเก็บข้อมูลไว้ภายในเครื่อง ตรวจสอบการตั้งค่าการเก็บรักษา |

## สรุป
Prometheus ตรวจสอบระบบโดยดึงข้อมูลตัวชี้วัดจากผู้ส่งออกเป็นระยะๆ หน่วยเมตริกมีสี่ประเภท: ตัวนับ (ขึ้นไปเท่านั้น), เกจ (ขึ้นและลง), ฮิสโตแกรม (การสังเกตแบบถัง) และสรุป (ควอนไทล์) PromQL เป็นภาษาคิวรี —`rate()`,`increase()`,`histogram_quantile()`และฟังก์ชันการรวมกลุ่ม (`sum`,`avg`) เป็นการดำเนินการที่พบบ่อยที่สุด Grafana แสดงภาพข้อมูล Prometheus ในแดชบอร์ดพร้อมแผง ตัวแปร และคำอธิบายประกอบ การแจ้งเตือนใช้ Alertmanager ในการจัดกลุ่ม การกำหนดเส้นทาง ปิดเสียง และยับยั้งการแจ้งเตือน รูปแบบการตรวจสอบที่สำคัญคือสัญญาณทองของ Google (เวลาแฝง การรับส่งข้อมูล ข้อผิดพลาด ความอิ่มตัว) และวิธีการ RED (อัตรา ข้อผิดพลาด ระยะเวลา) สำหรับบริการ และวิธีการ USE (การใช้งาน ความอิ่มตัว ข้อผิดพลาด) สำหรับโครงสร้างพื้นฐาน
