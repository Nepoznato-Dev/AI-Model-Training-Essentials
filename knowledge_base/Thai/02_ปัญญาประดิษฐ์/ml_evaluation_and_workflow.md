# การประเมินการเรียนรู้ของเครื่องและขั้นตอนการทำงาน

คู่มือเชิงปฏิบัติเกี่ยวกับวงจรการใช้งาน ML ตั้งแต่การกำหนดกรอบปัญหาไปจนถึงการตรวจสอบการผลิต โดยเน้นที่ตัววัด การตรวจสอบความถูกต้อง และการดีบัก

---

## เวิร์กโฟลว์ ML (CRISP-ML)

1. **ความเข้าใจทางธุรกิจ**: กำหนดวัตถุประสงค์และเกณฑ์ความสำเร็จ
2. **การทำความเข้าใจข้อมูล**: สำรวจข้อมูลที่มีอยู่ ระบุปัญหาด้านคุณภาพ
3. **การเตรียมข้อมูล**: ทำความสะอาด แปลง และแยกข้อมูล
4. **การสร้างแบบจำลอง**: ฝึกโมเดล ปรับแต่งไฮเปอร์พารามิเตอร์
5. **การประเมิน**: ประเมินประสิทธิภาพเทียบกับหน่วยเมตริก
6. **การปรับใช้**: ให้บริการโมเดลในการผลิต
7. **การตรวจสอบ**: ติดตามการดริฟท์ ประสิทธิภาพ และความผิดปกติ

นี่คือการวนซ้ำ คุณจะกลับมาทบทวนขั้นตอนก่อนหน้านี้ตามผลการประเมิน

---

## การแยกข้อมูล

### ฝึกอบรม / การตรวจสอบ / แยกการทดสอบ
- **ชุดการฝึกอบรม** (~70%): ใช้เพื่อให้พอดีกับพารามิเตอร์โมเดล
- **ชุดการตรวจสอบความถูกต้อง** (~15%): ใช้เพื่อปรับแต่งไฮเปอร์พารามิเตอร์และเลือกตัวแปรโมเดล
- **ชุดทดสอบ** (~15%): ใช้เพียงครั้งเดียวในตอนท้ายสุดเพื่อประเมินประสิทธิภาพการทำงานโดยทั่วไป

**สำคัญ:** ชุดทดสอบจะต้องไม่ถูกแตะต้องโดยสมบูรณ์จนกว่าจะมีการประเมินขั้นสุดท้ายเพื่อหลีกเลี่ยงการรั่วไหลของข้อมูล

### การตรวจสอบข้าม (k-fold)
สำหรับชุดข้อมูลขนาดเล็ก ให้ใช้การตรวจสอบความถูกต้องข้ามแบบ k-fold: แบ่งข้อมูลออกเป็น k พับ ฝึกฝนบน k-1 ตรวจสอบส่วนที่เหลือ และทำซ้ำ k ครั้ง ค่าเฉลี่ยประสิทธิภาพ k=5 หรือ k=10 เป็นเรื่องปกติ

### การแบ่งชั้นแบบแบ่งชั้น
สำหรับการจำแนกประเภทด้วยคลาสที่ไม่สมดุล ให้ใช้การแยกแบบแบ่งชั้นเพื่อรักษาสัดส่วนของคลาสในแต่ละเซ็ตย่อย

### การแยกตามเวลา
สำหรับข้อมูลอนุกรมเวลา ให้แยกตามลำดับเวลา (ฝึกฝนในอดีต ทดสอบในอนาคต) แทนที่จะสุ่ม

## ตัวชี้วัดการประเมินผล

### ตัวชี้วัดการจำแนกประเภท

| เมตริก | มันวัดอะไร | ใช้ดีที่สุดสำหรับ |
|--------|------------------|---------------|
| **ความแม่นยำ** | (TP + TN) / (TP + TN + FP + FN) | ชุดข้อมูลที่สมดุล |
| **ความแม่นยำ** | TP / (TP + FP) | เมื่อผลบวกลวงมีค่าใช้จ่ายสูง (เช่น การตรวจจับสแปม) |
| **จำ** | TP / (TP + FN) | เมื่อผลลบลวงมีค่าใช้จ่ายสูง (เช่น การตรวจคัดกรองมะเร็ง) |
| **คะแนน F1** | ค่าเฉลี่ยฮาร์มอนิกของความแม่นยำและการจดจำ | ชุดข้อมูลไม่สมดุล เมตริกตัวเลขเดียว |
| **AUC-ROC** | พื้นที่ใต้เส้นโค้ง ROC การแลกเปลี่ยนระหว่าง TPR และ FPR | ประสิทธิภาพตัวแยกประเภททั่วไปที่ไม่ขึ้นอยู่กับเกณฑ์ |
| **AUC-PR** | พื้นที่ใต้เส้นโค้งพรีซิชั่น-รีคอล | ชุดข้อมูลที่ไม่สมดุลสูง |

**คำจำกัดความ:**
- TP = บวกจริง
- TN = ลบจริง
- FP = ผลบวกลวง (ข้อผิดพลาดประเภท I)
- FN = เชิงลบที่เป็นเท็จ (ข้อผิดพลาดประเภท II)

### ตัวชี้วัดการถดถอย

| เมตริก | มันวัดอะไร | ความอ่อนไหวต่อค่าผิดปกติ |
|--------|------------------|--------------------------|
| **MSE** (ข้อผิดพลาด Mean Squared) | ผลต่างกำลังสองเฉลี่ย | สูง |
| **RMSE** (ข้อผิดพลาด Root Mean Squared) | รากที่สองของ MSE (หน่วยเดียวกับเป้าหมาย) | สูง |
| **แม่** (หมายถึงข้อผิดพลาดสัมบูรณ์) | ผลต่างสัมบูรณ์เฉลี่ย | ต่ำ |
| **R²** (สัมประสิทธิ์การกำหนด) | อธิบายสัดส่วนของความแปรปรวน | ไม่มีโดยตรง แต่มีความอ่อนไหวต่อค่าผิดปกติทางอ้อม |

### การวัดการจัดอันดับและการดึงข้อมูล
- **Precision@k**: เศษส่วนของรายการที่เกี่ยวข้องจากคำแนะนำยอดนิยม
- **Recall@k**: เศษส่วนของรายการที่เกี่ยวข้องทั้งหมดที่ปรากฏใน top-k
- **NDCG** (กำไรสะสมที่มีส่วนลดตามปกติ): บัญชีสำหรับความเกี่ยวข้องของตำแหน่ง
- **อัตราการเข้าชม**: ไม่ว่ารายการที่เกี่ยวข้องจะปรากฏใน top-k หรือไม่

### เกจวัด / LLM
- **ความฉงนสนเท่ห์**: โมเดลนี้ "ประหลาดใจ" เพียงใดด้วยข้อความที่ยื่นออกมา (ต่ำกว่าจะดีกว่า)
- **BLEU**: การทับซ้อนของ n-gram กับการแปลอ้างอิง (เน้นความแม่นยำ)
- **ROUGE**: การเรียกคืนการทับซ้อนกันเพื่อการสรุป
- **BERTScore**: ความคล้ายคลึงกันเชิงความหมายโดยใช้การฝังตามบริบท (แข็งแกร่งกว่า BLEU)
- **METEOR**: สอดคล้องกับคำพ้องความหมายและต้นกำเนิดของ WordNet

## ข้อผิดพลาดในการประเมิน

### ข้อมูลรั่วไหล
เกิดขึ้นเมื่อข้อมูลจากชุดทดสอบส่งผลต่อการฝึกอบรมโดยไม่ได้ตั้งใจ
- **ป้องกัน:** ห้ามใช้ข้อมูลการทดสอบสำหรับวิศวกรรมฟีเจอร์ การทำให้เป็นมาตรฐาน หรือการปรับแต่งไฮเปอร์พารามิเตอร์
- **ตรวจจับ:** หากโมเดลของคุณได้คะแนนสูงอย่างน่าสงสัย แสดงว่าสงสัยว่ามีการรั่วไหล

### ฟิตเกินไป
โมเดลทำงานได้ดีกับข้อมูลการฝึกอบรม แต่มีประสิทธิภาพไม่ดีในการตรวจสอบ/ทดสอบ
- **บรรเทา:** ใช้การทำให้เป็นมาตรฐาน การหยุดก่อนกำหนด ลดความซับซ้อนของสถาปัตยกรรม หรือรวบรวมข้อมูลเพิ่มเติม

### ช่วงล่าง
โมเดลทำงานได้ไม่ดีทั้งในด้านการฝึกและการตรวจสอบ
- **บรรเทา:** ใช้โมเดลที่ซับซ้อนมากขึ้น เพิ่มฟีเจอร์ หรือลดการทำให้เป็นมาตรฐาน

### ข้อมูลไม่สมดุล
- **บรรเทา:** ใช้น้ำหนักคลาส, ตัวอย่างเกิน (SMOTE), ตัวอย่างต่ำกว่า หรือใช้เมตริกที่เหมาะสม (F1, AUC-PR) แทนที่จะใช้ความแม่นยำ

### ดริฟท์ชั่วคราว (ดริฟท์แนวคิด)
ความสัมพันธ์ระหว่างคุณลักษณะและเป้าหมายเปลี่ยนแปลงตลอดเวลา
- **บรรเทา:** ฝึกซ้ำเป็นระยะ ตรวจสอบประสิทธิภาพ ใช้อัลกอริธึมการตรวจจับการเบี่ยงเบน

## การปรับแต่งไฮเปอร์พารามิเตอร์- **การค้นหาตาราง**: ลองใช้ชุดไฮเปอร์พารามิเตอร์ที่กำหนดไว้ล่วงหน้าทั้งหมดร่วมกันอย่างละเอียดถี่ถ้วน เรียบง่าย แต่มีราคาแพงในการคำนวณ
- **การค้นหาแบบสุ่ม**: ตัวอย่างชุดค่าผสมแบบสุ่มจากการแจกแจง มีประสิทธิภาพมากกว่าการค้นหาตารางสำหรับช่องว่างมิติสูง
- **การเพิ่มประสิทธิภาพแบบเบย์**: สร้างแบบจำลองความน่าจะเป็นของฟังก์ชันวัตถุประสงค์ และเลือกไฮเปอร์พารามิเตอร์อย่างชาญฉลาด ห้องสมุด: Optuna, Hyperopt, scikit-optimise
- **การปรับจูนอัตโนมัติ**: ใช้เครื่องมือเช่น Optuna, Ray Tune หรือ Weights & Biases Sweeps สำหรับการปรับจูนแบบกระจาย

**ช่วงการค้นหาที่แนะนำสำหรับไฮเปอร์พารามิเตอร์ทั่วไป:**

| พารามิเตอร์ | ช่วงที่แนะนำ (log-scale) |
|----------|---------------------------------|
| อัตราการเรียนรู้ | 1e-5 ถึง 1e-1 |
| ขนาดชุด | 16, 32, 64, 128, 256 |
| จำนวนชั้น (NN) | 2 ถึง 6 |
| จำนวนเซลล์ประสาท (NN) | 32 ถึง 1024 |
| การทำให้เป็นมาตรฐาน (L2) | 1e-6 ถึง 1e-2 |
| ความลึกของต้นไม้ (XGBoost) | 3 ถึง 12 |

## การเลือกรุ่นและการตรวจสอบความถูกต้อง

1. **แบบจำลองพื้นฐาน**: เริ่มต้นด้วยแบบจำลองการศึกษาสำนึกอย่างง่ายหรือแบบจำลองอย่างง่าย (เช่น การถดถอยโลจิสติก ตัวทำนายเฉลี่ย) เพื่อสร้างขอบเขตล่าง
2. **โมเดลผู้สมัคร**: ฝึกกลุ่มโมเดลหลายกลุ่ม (เช่น Random Forest, XGBoost, Neural Network)
3. **ตรวจสอบข้าม** ผู้สมัครแต่ละคนในชุดการตรวจสอบ
4. **เปรียบเทียบตัวชี้วัด** (ด้วยช่วงความเชื่อมั่น) และเลือกตัวเลือกที่ดีที่สุด
5. **การประเมินขั้นสุดท้าย** ในชุดทดสอบที่จัดขึ้น
6. **การวิเคราะห์ข้อผิดพลาด**: ดูตัวอย่างที่แบบจำลองผิดพลาด ระบุรูปแบบ (เช่น คลาสที่หายาก อินพุตที่ไม่ชัดเจน) และป้อนข้อมูลเชิงลึกกลับไปในการเตรียมข้อมูลหรือวิศวกรรมฟีเจอร์

## การปรับใช้และการตรวจสอบ

### รูปแบบการให้บริการ
- **การอนุมานเป็นกลุ่ม**: ประมวลผลข้อมูลจำนวนมากแบบออฟไลน์ (เช่น คำแนะนำทุกคืน)
- **การอนุมานออนไลน์**: การคาดการณ์แบบเรียลไทม์ผ่าน API (เช่น การให้คะแนนเครดิต การตรวจจับการฉ้อโกง)
- **การอนุมานแบบสตรีมมิ่ง**: ขับเคลื่อนด้วยเหตุการณ์ แบบเรียลไทม์โดยมีความหน่วงต่ำ (เช่น การแจ้งเตือนเซ็นเซอร์ IoT)

### การตรวจสอบโมเดล
- **การตรวจสอบประสิทธิภาพ**: ติดตามความแม่นยำ/F1 เมื่อเวลาผ่านไปจากข้อมูลสด (เมื่อมีข้อมูลจริง)
- **การเบี่ยงเบนของข้อมูล**: ติดตามการเปลี่ยนแปลงในการแจกแจงคุณลักษณะอินพุต (เช่น การใช้ PSI – ดัชนีความเสถียรของประชากร)
- **การเคลื่อนตัวของแนวคิด**: ติดตามการเปลี่ยนแปลงในความสัมพันธ์ระหว่างอินพุตและเอาต์พุต
- **การทำนายแบบเลื่อนลอย**: ติดตามการกระจายของผลลัพธ์ที่คาดการณ์ไว้
- **เวลาแฝงและปริมาณงาน**: ตรวจสอบให้แน่ใจว่าเป็นไปตาม SLA (ข้อตกลงระดับการให้บริการ)

### การบันทึกและการแจ้งเตือน
- บันทึกคำขอและการตอบกลับการคาดการณ์ทั้งหมด (โดยไม่ระบุชื่อ)
- ตั้งค่าการแจ้งเตือนสำหรับ:
  - ประสิทธิภาพลดลงอย่างมาก
  - เปอร์เซ็นต์อินพุตที่ขาดหายไปหรือไม่ถูกต้องมีสูง
  - โมเดลเอาท์พุตอยู่นอกขอบเขตที่คาดไว้

### การกำหนดเวอร์ชันโมเดลและการลงทะเบียน
- ใช้การลงทะเบียนโมเดล (เช่น MLflow, Weights & Biases, Sagemaker Model Registry) เพื่อจัดเก็บและกำหนดเวอร์ชันโมเดล ข้อมูลเมตา และผลการประเมิน
- จัดเก็บโค้ดการฝึกอบรมและเวอร์ชันข้อมูล (ผ่าน DVC หรือ Git LFS) ไว้ข้างโมเดล
