#การพัฒนาเว็บ
## การพัฒนาส่วนหน้า
### เทคโนโลยีหลัก
#### HTML (ภาษามาร์กอัปไฮเปอร์เท็กซ์)
- **Semantic HTML**: การใช้แท็กที่มีความหมาย (`<header>`,`<nav>`,`<main>`,`<article>`,`<section>`,`<aside>`,`<footer>`)
- **แบบฟอร์ม**: ประเภทอินพุต การตรวจสอบ ป้ายกำกับการเข้าถึง
- **สื่อ**: การฝังรูปภาพ วิดีโอ เสียง
- **เมตาแท็ก**: SEO, วิวพอร์ต, การเข้ารหัสอักขระ
- **คุณสมบัติ HTML5**: Canvas, SVG, ที่จัดเก็บในตัวเครื่อง, ตำแหน่งทางภูมิศาสตร์, ซ็อกเก็ตเว็บ
#### CSS (สไตล์ชีทแบบเรียงซ้อน)
- **โมเดลกล่อง**: เนื้อหา ระยะห่างจากขอบ ขอบ ขอบ
- **ระบบเค้าโครง**:
  - **Flexbox**: เลย์เอาต์แบบมิติเดียว ปรับเนื้อหา จัดแนวรายการ
  - **ตาราง**: เค้าโครงสองมิติ เทมเพลตกริด พื้นที่กริด
  - **การวางตำแหน่ง**: คงที่ สัมพันธ์ สัมบูรณ์ คงที่ เหนียว
- **การออกแบบที่ตอบสนอง**: การสืบค้นสื่อ แนวทางที่เน้นอุปกรณ์เคลื่อนที่เป็นอันดับแรก
- **ตัวแปร CSS**: คุณสมบัติที่กำหนดเองสำหรับธีม
- **ภาพเคลื่อนไหว**: การเปลี่ยนภาพ คีย์เฟรม การแปลง
- **ตัวประมวลผลล่วงหน้า**: Sass, Less (ตัวแปร, มิกซ์อิน, การซ้อน)
#### จาวาสคริปต์
- **การจัดการ DOM**: การเลือก การสร้าง การแก้ไของค์ประกอบ
- **กิจกรรม**: คลิก ส่ง แป้นพิมพ์ กิจกรรมที่กำหนดเอง การมอบหมายกิจกรรม
- **คุณสมบัติ ES6+**: ฟังก์ชั่นลูกศร, การทำลายโครงสร้าง, การแพร่กระจาย/พัก, โมดูล, อะซิงก์/รอ
- **APIs**: ดึงข้อมูล, XMLHttpRequest, localStorage, sessionStorage
- **TypeScript**: การพิมพ์แบบคงที่ อินเทอร์เฟซ ข้อมูลทั่วไป เครื่องมือตกแต่ง
### กรอบการทำงานส่วนหน้าที่ทันสมัย
#### โต้ตอบ
- **ส่วนประกอบ**: ส่วนประกอบการทำงาน ส่วนประกอบของคลาส
- **Hooks**: useState, useEffect, useContext, useReducer, ตะขอแบบกำหนดเอง
- **การจัดการสถานะ**: Context API, Redux, Zustand, Recoil
- **การกำหนดเส้นทาง**: ตอบสนองเราเตอร์ (BrowserRouter, เส้นทาง, เส้นทาง, ลิงก์)
- **ระบบนิเวศ**: Next.js (SSR, SSG), รีมิกซ์, Gatsby
- **Virtual DOM**: การเรนเดอร์ที่มีประสิทธิภาพผ่านอัลกอริทึมที่ต่างกัน
#### Vue.js
- **ตัวเลือก API**: ข้อมูล วิธีการ คำนวณ ดู
- **Composition API**: การตั้งค่า(), การอ้างอิง, ปฏิกิริยา, คำนวณ
- **คำสั่ง**: v-if, v-for, v-bind, v-on, v-model
- **Vuex/Pinia**: การจัดการของรัฐ
- **Vue Router**: การกำหนดเส้นทางฝั่งไคลเอ็นต์
- **Nuxt.js**: เฟรมเวิร์กการเรนเดอร์ฝั่งเซิร์ฟเวอร์
#### เชิงมุม
- **ส่วนประกอบ**: อุปกรณ์ตกแต่ง เทมเพลต ตะขอเกี่ยวกับวงจรชีวิต
- **บริการ**: การพึ่งพาการฉีด รูปแบบซิงเกิลตัน
- **RxJS**: การเขียนโปรแกรมเชิงโต้ตอบ สังเกตได้
- **การกำหนดเส้นทาง**: เราเตอร์โมดูล การ์ด ตัวแก้ไข
- **แบบฟอร์ม**: แบบฟอร์มที่ขับเคลื่อนด้วยเทมเพลตและโต้ตอบ
- **NgRx**: การจัดการสถานะแบบ Redux
### สร้างเครื่องมือและ Bundlers
- **Webpack**: การรวมโมดูล, การแยกโค้ด, ตัวโหลด, ปลั๊กอิน
- **Vite**: เครื่องมือสร้างที่รวดเร็วโดยใช้โมดูล ES ดั้งเดิม
- **พัสดุ**: Bundler ที่ไม่มีการกำหนดค่า
- **ค่าสะสม**: ปรับให้เหมาะสมสำหรับไลบรารี
- **esbuild**: ตัวรวม JavaScript ที่รวดเร็วมาก
- **Babel**: JavaScript transpiler สำหรับความเข้ากันได้แบบย้อนหลัง
- **PostCSS**: การประมวลผล CSS ด้วยปลั๊กอิน
### กรอบงาน CSS และไลบรารี
- **Bootstrap**: ไลบรารีส่วนประกอบ ระบบกริด ยูทิลิตี้
- **Tailwind CSS**: เฟรมเวิร์ก CSS เน้นยูทิลิตี้เป็นหลัก
- **Material UI**: การใช้งานดีไซน์ Material ของ Google
- **Chakra UI**: ไลบรารีส่วนประกอบที่สามารถเข้าถึงได้
- **Ant Design**: ส่วนประกอบ UI ระดับองค์กร
- **ส่วนประกอบที่มีสไตล์**: ไลบรารี CSS-in-JS
- **Emotion**: CSS-in-JS พร้อมซอร์สแมป
## การพัฒนาแบ็กเอนด์
### ภาษาฝั่งเซิร์ฟเวอร์
#### โหนด js
- **รันไทม์**: JavaScript บนเซิร์ฟเวอร์ (เอ็นจิ้น V8)
- **Express.js**: กรอบงานเว็บน้อยที่สุด สถาปัตยกรรมมิดเดิลแวร์
- **NestJS**: สถาปัตยกรรมที่ได้รับแรงบันดาลใจจากเชิงมุม, TypeScript
- **Fastify**: เฟรมเวิร์กประสิทธิภาพสูง
- **Koa**: Modern Express โดยผู้สร้างคนเดียวกัน
- **การจัดการแพ็คเกจ**: npm, เส้นด้าย, pnpm
#### หลาม
- **Django**: เฟรมเวิร์กที่มีคุณสมบัติครบถ้วน, ORM, แผงผู้ดูแลระบบ, รวมแบตเตอรี่
- **Flask**: ไมโครเฟรมเวิร์ก ระบบนิเวศของส่วนขยาย
- **FastAPI**: เอกสาร API อัตโนมัติที่ทันสมัย ไม่พร้อมกัน
- **พีระมิด**: เฟรมเวิร์กที่ยืดหยุ่นและปรับขนาดได้
#### ภาษาแบ็กเอนด์อื่น ๆ
- **Ruby on Rails**: การประชุมผ่านการกำหนดค่า ActiveRecord ORM
- **Java Spring**: เฟรมเวิร์กองค์กร, การแทรกการพึ่งพา
- **PHP Laravel**: ไวยากรณ์ที่สวยงาม, Eloquent ORM, การสร้างเทมเพลต Blade
- **Go Gin**: ประสิทธิภาพสูง เฟรมเวิร์กน้อยที่สุด
- **Rust Actix**: ความปลอดภัยของหน่วยความจำ ประสิทธิภาพ
- **C# ASP.NET Core**: คุณสมบัติข้ามแพลตฟอร์มระดับองค์กร
### บูรณาการฐานข้อมูล
#### ORM (การแมปวัตถุ-เชิงสัมพันธ์)
- **Sequelize**: Node.js ORM สำหรับฐานข้อมูล SQL
- **Prisma**: การเข้าถึงฐานข้อมูลแบบปลอดภัย ไคลเอนต์ที่สร้างขึ้นอัตโนมัติ
- **SQLAlchemy**: ชุดเครื่องมือ Python SQL และ ORM
- **ActiveRecord**: Ruby บน Rails ORM
- **ไฮเบอร์เนต**: Java ORM
- **กรอบงานเอนทิตี**: .NET ORM
#### ไดรเวอร์ฐานข้อมูล
- **pg**: ไคลเอนต์ PostgreSQL สำหรับ Node.js
- **mysql2**: ไคลเอนต์ MySQL พร้อมสัญญา
- **pymongo**: ไดรเวอร์ MongoDB สำหรับ Python
- **redis**: ไคลเอนต์ Redis สำหรับหลายภาษา
### การพัฒนา API
#### REST API
- **วิธี HTTP**: GET, POST, PUT, PATCH, DELETE
- **รหัสสถานะ**: 200, 201, 400, 401, 403, 404, 500
- **การตั้งชื่อทรัพยากร**: คำนาม พหูพจน์ ลำดับชั้น
- **เวอร์ชัน**: เส้นทาง URL, ส่วนหัว, พารามิเตอร์การค้นหา
- **การรับรองความถูกต้อง**: คีย์ JWT, OAuth, API
- **เอกสารประกอบ**: OpenAPI/Swagger, Postman
#### GraphQL
- **คำจำกัดความของสคีมา**: ประเภท การสืบค้น การเปลี่ยนแปลง การสมัครสมาชิก
- **ตัวแก้ไข**: การดึงข้อมูลระดับฟิลด์
- **เซิร์ฟเวอร์ Apollo**: การใช้งานเซิร์ฟเวอร์ GraphQL
- **รีเลย์**: ไคลเอนต์ GraphQL ของ Facebook
- **ข้อดี**: ไม่มีการดึงข้อมูลมากเกินไป มีปลายทางเดียว พิมพ์ได้ดี
#### gRPC
- **บัฟเฟอร์โปรโตคอล**: ภาษาคำจำกัดความของอินเทอร์เฟซ
- **HTTP/2**: การสตรีมแบบสองทิศทาง
- **กรณีการใช้งาน**: การสื่อสารไมโครเซอร์วิส แอปพลิเคชันแบบเรียลไทม์
### การรับรองความถูกต้องและการอนุญาต
- **ตามเซสชัน**: คุกกี้ เซสชันฝั่งเซิร์ฟเวอร์
- **อิงโทเค็น**: JWT (JSON Web Tokens) ไร้สัญชาติ
- **OAuth 2.0**: กรอบงานการอนุญาต การเข้าสู่ระบบของบุคคลที่สาม
- **OpenID Connect**: เลเยอร์ข้อมูลประจำตัวบน OAuth 2.0
- **SAML**: การลงชื่อเพียงครั้งเดียวระดับองค์กร
- **การแฮชรหัสผ่าน**: bcrypt, argon2, scrypt
- **การตรวจสอบสิทธิ์แบบหลายปัจจัย**: TOTP, SMS, รหัสอีเมล
## DevOps และการปรับใช้
### การควบคุมเวอร์ชัน
- **Git**: การควบคุมเวอร์ชันแบบกระจาย
- **GitHub/GitLab/Bitbucket**: การโฮสต์พื้นที่เก็บข้อมูล
- **กลยุทธ์การแยกสาขา**: Git Flow, GitHub Flow, การพัฒนาตาม Trunk
- **CI/CD**: ไปป์ไลน์การทดสอบและการปรับใช้อัตโนมัติ
### การบรรจุคอนเทนเนอร์
- **นักเทียบท่า**: คอนเทนเนอร์รันไทม์, Dockerfile, รูปภาพ
- **Docker Compose**: การเรียบเรียงหลายคอนเทนเนอร์
- **การลงทะเบียนคอนเทนเนอร์**: Docker Hub, AWS ECR, Google GCR
- **แนวทางปฏิบัติที่ดีที่สุด**: การสร้างแบบหลายขั้นตอน อิมเมจพื้นฐานน้อยที่สุด
### การเรียบเรียง
- **Kubernetes**: การจัดเตรียมคอนเทนเนอร์ พ็อด บริการ และการปรับใช้
- **Helm**: ตัวจัดการแพ็คเกจ Kubernetes
- **Service Mesh**: Istio, Linkerd สำหรับเครือข่ายไมโครเซอร์วิส
### แพลตฟอร์มคลาวด์
- **AWS**: EC2, S3, Lambda, RDS, CloudFront, ECS/EKS
- **Google Cloud**: Compute Engine, พื้นที่เก็บข้อมูลบนคลาวด์, ฟังก์ชันคลาวด์, GKE
- **Azure**: เครื่องเสมือน, พื้นที่เก็บข้อมูล Blob, ฟังก์ชัน, AKS
- **Vercel**: การปรับใช้ส่วนหน้า, ฟังก์ชันแบบไร้เซิร์ฟเวอร์
- **Netlify**: การโฮสต์ไซต์แบบคงที่ ฟังก์ชั่นไร้เซิร์ฟเวอร์
- **Heroku**: แพลตฟอร์มเป็นบริการ (PaaS)
- **DigitalOcean**: โครงสร้างพื้นฐานคลาวด์ที่เรียบง่าย
### ไปป์ไลน์ CI/CD
- **การดำเนินการ GitHub**: เวิร์กโฟลว์อัตโนมัติ
- **GitLab CI**: การบูรณาการอย่างต่อเนื่องในตัว
- **Jenkins**: เซิร์ฟเวอร์อัตโนมัติที่ขยายได้
- **CircleCI**: CI/CD บนคลาวด์
- **Travis CI**: บริการบูรณาการอย่างต่อเนื่อง
- **ArgoCD**: การส่งมอบ GitOps อย่างต่อเนื่องสำหรับ Kubernetes
### การตรวจสอบและการบันทึก
- **ประสิทธิภาพของแอปพลิเคชัน**: New Relic, Datadog, AppDynamics
- **การติดตามข้อผิดพลาด**: Sentry, Rollbar, Bugsnag
- **การบันทึก**: ELK Stack (Elasticsearch, Logstash, Kibana), Splunk
- **การตรวจสอบสถานะการออนไลน์**: Pingdom, UptimeRobot
- **การวิเคราะห์**: Google Analytics, มิกซ์พาเนล, แอมพลิจูด
## ประสิทธิภาพเว็บ
### เทคนิคการเพิ่มประสิทธิภาพ
- **การแยกโค้ด**: การโหลดแบบ Lazy Loading การนำเข้าแบบไดนามิก
- **Tree Shaking**: ลบโค้ดที่ไม่ได้ใช้
- **การลดขนาด**: การลดขนาดไฟล์
- **การบีบอัด**: Gzip, Brotli
- **แคช**: แคชของเบราว์เซอร์, CDN, พนักงานบริการ
- **การเพิ่มประสิทธิภาพรูปภาพ**: WebP, AVIF, การโหลดแบบ Lazy Loading, ภาพที่ตอบสนอง
- **CSS ที่สำคัญ**: การแทรกสไตล์ครึ่งหน้าบนไว้ด้านใน
- **การเพิ่มประสิทธิภาพฐานข้อมูล**: การจัดทำดัชนี การเพิ่มประสิทธิภาพการสืบค้น การรวมการเชื่อมต่อ
### Core Web Vitals
- **LCP (Largest Contentful Paint)**: ประสิทธิภาพการโหลด (<2.5 วินาที)
- **FID (ความล่าช้าในการป้อนข้อมูลครั้งแรก)**: การโต้ตอบ (<100ms)
- **CLS (Cumulative Layout Shift)**: ความเสถียรของภาพ (<0.1)
- **INP (การโต้ตอบกับสีถัดไป)**: ตัวชี้วัดการตอบสนอง
### เครือข่ายการจัดส่งเนื้อหา (CDN)
- **Cloudflare**: ความปลอดภัย ประสิทธิภาพ DNS
- **Akamai**: Enterprise CDN
- **Amazon CloudFront**: AWS CDN
- **รวดเร็ว**: แพลตฟอร์ม Edge Cloud
- **StackPath**: บริการ Edge
## ความปลอดภัยทางเว็บ
### ช่องโหว่ทั่วไป (OWASP Top 10)
- **การฉีด**: การฉีด SQL, การฉีดคำสั่ง
- **การตรวจสอบสิทธิ์ที่ใช้งานไม่ได้**: การขโมยเซสชัน การใส่ข้อมูลรับรอง
- **การเปิดเผยข้อมูลที่ละเอียดอ่อน**: ข้อมูลที่ไม่ได้เข้ารหัส การเข้ารหัสที่ไม่รัดกุม
- **XML External Entities (XXE)**: ช่องโหว่ของตัวแยกวิเคราะห์ XML
- **การควบคุมการเข้าถึงที่เสียหาย**: การเพิ่มสิทธิ์, การเข้าถึงที่ไม่ได้รับอนุญาต
- **การกำหนดค่าความปลอดภัยผิดพลาด**: ข้อมูลรับรองเริ่มต้น ข้อผิดพลาดโดยละเอียด
- **การเขียนสคริปต์ข้ามไซต์ (XSS)**: สะท้อน จัดเก็บ อิง DOM
- **การดีซีเรียลไลซ์ที่ไม่ปลอดภัย**: การโจมตีด้วยการแทรกวัตถุ
- **การใช้ส่วนประกอบที่มีช่องโหว่ที่ทราบ**: การพึ่งพาที่ล้าสมัย
- **การบันทึกและการตรวจสอบไม่เพียงพอ**: การละเมิดที่ตรวจไม่พบ
### แนวทางปฏิบัติที่ดีที่สุดด้านความปลอดภัย
- **HTTPS**: การเข้ารหัส TLS/SSL, HSTS
- **นโยบายความปลอดภัยของเนื้อหา (CSP)**: ป้องกันการโจมตี XSS
- **การตรวจสอบอินพุต**: ฆ่าเชื้ออินพุตของผู้ใช้
- **การเข้ารหัสเอาต์พุต**: ป้องกันการโจมตีแบบฉีด
- **การป้องกัน CSRF**: โทเค็นต่อต้าน CSRF, คุกกี้ SameSite
- **การจำกัดอัตรา**: ป้องกันการโจมตีด้วยกำลังดุร้าย
- **ส่วนหัวด้านความปลอดภัย**: X-Frame-Options, X-Content-Type-Options
- **การสแกนการพึ่งพา**: การตรวจสอบ npm, Snyk, Dependabot
## การทดสอบ
### ประเภทการทดสอบ
- **การทดสอบหน่วย**: ส่วนประกอบ/ฟังก์ชันส่วนบุคคล
- **การทดสอบบูรณาการ**: การโต้ตอบของส่วนประกอบ
- **End-to-End (E2E)**: ขั้นตอนการทำงานของผู้ใช้เต็มรูปแบบ
- **การถดถอยของภาพ**: การตรวจจับการเปลี่ยนแปลง UI
- **การทดสอบประสิทธิภาพ**: การทดสอบโหลด ความเครียด ขัดขวาง
- **การทดสอบการเข้าถึง**: การปฏิบัติตาม WCAG
### กรอบการทดสอบ
- **Jest**: กรอบการทดสอบ JavaScript
- **มอคค่า**: นักวิ่งทดสอบที่ยืดหยุ่น
- **pytest**: กรอบการทดสอบ Python
- **RSpec**: เฟรมเวิร์กการทดสอบ Ruby
- **JUnit**: เฟรมเวิร์กการทดสอบ Java
### เครื่องมือทดสอบ E2E
- **ซีลีเนียม**: เบราว์เซอร์อัตโนมัติ
- **Cypress**: การทดสอบ E2E สมัยใหม่
- **นักเขียนบทละคร**: ข้ามเบราว์เซอร์อัตโนมัติ
- **Puppeteer**: การควบคุม Chrome แบบหัวขาด
## การเข้าถึง (a11y)
### แนวทาง WCAG
- **รับรู้ได้**: ตัวเลือกข้อความ คำบรรยาย เนื้อหาที่ปรับเปลี่ยนได้
- **ใช้งานได้**: การนำทางด้วยแป้นพิมพ์ มีเวลาเพียงพอ ไม่กระตุก
- **เข้าใจได้**: สามารถอ่านได้ คาดเดาได้ พร้อมความช่วยเหลือในการป้อนข้อมูล
- **แข็งแกร่ง**: เข้ากันได้กับเทคโนโลยีช่วยเหลือ
### การนำไปปฏิบัติ
- **Semantic HTML**: ลำดับชั้นของส่วนหัวที่เหมาะสม จุดสังเกต
- **แอตทริบิวต์ ARIA**: บทบาท สถานะ คุณสมบัติ
- **การจัดการโฟกัส**: สัญลักษณ์โฟกัสที่มองเห็นได้ ลำดับแท็บแบบลอจิคัล
- **คอนทราสต์ของสี**: อัตราส่วนขั้นต่ำ 4.5:1 สำหรับข้อความ
- **การทดสอบโปรแกรมอ่านหน้าจอ**: NVDA, JAWS, VoiceOver
- **การนำทางด้วยแป้นพิมพ์**: เข้าถึงองค์ประกอบแบบโต้ตอบทั้งหมดได้
## Progressive Web Apps (PWA)
### คุณสมบัติกปภ
- **พนักงานบริการ**: ฟังก์ชันการทำงานออฟไลน์ การซิงค์พื้นหลัง
- **รายการเว็บแอป**: ติดตั้งพรอมต์ ไอคอน สีของธีม
- **App Shell**: โครงกระดูก UI ที่แคชไว้
- **การแจ้งเตือนแบบพุช**: การมีส่วนร่วมของผู้ใช้
- **การออกแบบที่ตอบสนอง**: ใช้งานได้กับทุกอุปกรณ์
- **ต้องใช้ HTTPS**: บริบทที่ปลอดภัย
### เครื่องมือ
- **กล่องงาน**: ไลบรารีของพนักงานบริการ
- **ประภาคาร**: การตรวจสอบการประปาส่วนภูมิภาค
- **PWA Builder**: สร้างรายการและไอคอน
## เทคโนโลยีเกิดใหม่
### WebAssembly (Wasm)
- **วัตถุประสงค์**: เรียกใช้โค้ดที่คอมไพล์แล้วในเบราว์เซอร์ด้วยความเร็วที่ใกล้เคียงกับเนทีฟ
- **ภาษา**: เป้าหมายการคอมไพล์ C++, Rust, Go
- **กรณีการใช้งาน**: เกม การตัดต่อวิดีโอ การเข้ารหัส การอนุมาน ML
### สถาปัตยกรรมแบบไร้เซิร์ฟเวอร์
- **ฟังก์ชันเป็นบริการ**: AWS Lambda, ฟังก์ชัน Azure, ฟังก์ชัน Google Cloud
- **สิทธิประโยชน์**: ไม่มีการจัดการเซิร์ฟเวอร์ ปรับขนาดอัตโนมัติ จ่ายตามการใช้งาน
- **ข้อควรพิจารณา**: Cold Start, การล็อคอินของผู้ขาย, ความซับซ้อนในการแก้ไขจุดบกพร่อง
### สถาปัตยกรรม Jamstack
- **JavaScript**: การโต้ตอบฝั่งไคลเอ็นต์
- **APIs**: ฟังก์ชันแบบไร้เซิร์ฟเวอร์ บริการของบุคคลที่สาม
- **มาร์กอัป**: ไฟล์คงที่ที่สร้างไว้ล่วงหน้า
- **เครื่องมือ**: Next.js, Gatsby, Hugo, Eleventy
- **ข้อดี**: ประสิทธิภาพ ความปลอดภัย ความสามารถในการปรับขนาด ประสบการณ์ของนักพัฒนา
### การสื่อสารแบบเรียลไทม์
- **WebSockets**: การสื่อสารแบบสองทิศทาง
- **เหตุการณ์ที่เซิร์ฟเวอร์ส่ง**: การสตรีมแบบเซิร์ฟเวอร์ถึงไคลเอนต์
- **WebRTC**: วิดีโอ เสียง และข้อมูลแบบเพียร์ทูเพียร์
- **กรณีการใช้งาน**: แชท การทำงานร่วมกัน สตรีมสด เล่นเกม
### ส่วนหน้าแบบไมโคร
- **แนวคิด**: ขยายไมโครเซอร์วิสไปยังส่วนหน้า
- **แนวทาง**: เวลาสร้าง รันไทม์ บูรณาการด้านเอดจ์
- **สิทธิประโยชน์**: การปรับใช้แบบอิสระ ความเป็นอิสระของทีม
- **ความท้าทาย**: ความสม่ำเสมอ ประสิทธิภาพ ความซับซ้อน
