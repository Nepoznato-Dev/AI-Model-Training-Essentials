# พื้นฐานระบบเครือข่าย
ข้อมูลอ้างอิงที่เป็นประโยชน์สำหรับนักพัฒนาและผู้ดูแลระบบ — แนวคิดหลัก โปรโตคอล คำสั่ง และการแก้ไขปัญหา

## โมเดล OSI (7 เลเยอร์)
กรอบแนวคิดสำหรับการทำความเข้าใจการสื่อสารผ่านเครือข่าย
| เลเยอร์ | ชื่อ | ฟังก์ชัน | ตัวอย่างโปรโตคอล |
|----------------------|-|---------|-------------------|
| 7 | ใบสมัคร | บริการสำหรับผู้ใช้ปลายทาง | HTTP, HTTPS, FTP, SMTP, DNS, SSH |
| 6 | การนำเสนอ | การจัดรูปแบบข้อมูล การเข้ารหัส การบีบอัด | TLS, JPEG, ASCII |
| 5 | เซสชั่น | การจัดการการเชื่อมต่อ | NetBIOS, RPC |
| 4 | ขนส่ง | การส่งมอบแบบครบวงจร การแก้ไขข้อผิดพลาด การควบคุมการไหล | TCP, UDP |
| 3 | เครือข่าย | การกำหนดเส้นทางการกำหนดแอดเดรส | IP, ICMP, OSPF, BGP |
| 2 | ลิงค์ข้อมูล | การวางกรอบ การตรวจจับข้อผิดพลาด ที่อยู่ MAC | อีเธอร์เน็ต, Wi-Fi, PPP |
| 1 | กายภาพ | การส่งบิตดิบ | สายอีเธอร์เน็ต ไฟเบอร์ออปติก คลื่นวิทยุ |
ในทางปฏิบัติ **โมเดล TCP/IP** (4 เลเยอร์: ลิงก์ อินเทอร์เน็ต การขนส่ง แอปพลิเคชัน) มักใช้กับอินเทอร์เน็ตมากกว่า

## ที่อยู่ IP
### IPv4
- ที่อยู่แบบ 32 บิต เขียนเป็นสี่ออคเต็ต:`192.168.1.1`
- ทั้งหมด: ~4.3 พันล้านที่อยู่ (แต่ในทางปฏิบัติหมดแล้ว)
### IPv6
- ที่อยู่ 128 บิต เขียนด้วยเลขฐานสิบหก:`2001:0db8:85a3:0000:0000:8a2e:0370:7334`
- ทั้งหมด: ที่อยู่2¹²⁸ (ในทางปฏิบัติไม่มีที่สิ้นสุด)
### ช่วง IP ส่วนตัว (RFC 1918)
สิ่งเหล่านี้ไม่สามารถกำหนดเส้นทางได้บนอินเทอร์เน็ต ใช้ภายในเครือข่ายท้องถิ่น:
-`10.0.0.0/8`(10.0.0.0 – 10.255.255.255)
-`172.16.0.0/12`(172.16.0.0 – 172.31.255.255)
-`192.168.0.0/16`(192.168.0.0 – 192.168.255.255)
### สัญกรณ์ CIDR
`192.168.1.0/24`หมายถึง 24 บิตแรกเป็นคำนำหน้าเครือข่าย 8 บิตสุดท้ายคือโฮสต์ ประกอบด้วยที่อยู่`192.168.1.0`ถึง `192.168.1.255`

## DNS (ระบบชื่อโดเมน)
จับคู่ชื่อโดเมน (เช่น`example.com`) กับที่อยู่ IP
### ประเภทบันทึก
| พิมพ์ | วัตถุประสงค์ |
|------|---------|
| **เอ** | แมปโดเมนกับที่อยู่ IPv4 |
| **AAAA** | แมปโดเมนกับที่อยู่ IPv6 |
| **CNAME** | นามแฝงไปยังชื่อโดเมนอื่น |
| **เอ็มเอ็กซ์** | เซิร์ฟเวอร์แลกเปลี่ยนจดหมาย |
| **TXT** | ข้อความที่กำหนดเอง (SPF, DKIM, การยืนยัน) |
| **นส** | เนมเซิร์ฟเวอร์สำหรับโดเมน |
| **SRV** | บันทึกการบริการ (เช่น สำหรับ SIP) |
### เครื่องมือทั่วไป```bash
dig example.com            # DNS lookup (detailed)
nslookup example.com       # DNS lookup (simpler)
host example.com           # Quick lookup
dig -x 8.8.8.8             # Reverse lookup (IP to name)
```

## TCP กับ UDP
| คุณสมบัติ | TCP | ยูดีพี |
|---------|-----|-----|
| การเชื่อมต่อ | มุ่งเน้นการเชื่อมต่อ (จับมือ) | ไร้การเชื่อมต่อ |
| ความน่าเชื่อถือ | รับประกันการจัดส่งการส่งซ้ำ | พยายามอย่างดีที่สุด (อาจดรอปแพ็กเก็ต) |
| การสั่งซื้อ | รักษาลำดับ | ไม่มีการรับประกันการสั่งซื้อ |
| การควบคุมการไหล | ใช่ (หน้าต่างบานเลื่อน) | ไม่ |
| กรณีการใช้งาน | เว็บ (HTTP), อีเมล, SSH, การถ่ายโอนไฟล์ | DNS, สตรีมมิ่ง, VoIP, เกม, SNMP |
| ขนาดส่วนหัว | 20–60 ไบต์ | 8 ไบต์ |

## HTTP และ HTTPS
### วิธีการ HTTP
| วิธีการ | คำอธิบาย |
|--------|-------------|
| **รับ** | ดึงข้อมูลทรัพยากร (idempotent, safe) |
| **โพสต์** | ส่งข้อมูล (ไม่ใช่ idempotent) |
| **ใส่** | อัปเดต/แทนที่ทรัพยากร (idempotent) |
| **แพทช์** | อัพเดทบางส่วน |
| **ลบ** | ลบทรัพยากร (idempotent) |
### รหัสสถานะ
| รหัส | ความหมาย |
|------|---------|
| **1xxx** | เชิงข้อมูล (100 ต่อ) |
| **2xxx** | สำเร็จ (200 ตกลง, สร้าง 201, 204 ไม่มีเนื้อหา) |
| **3xxx** | การเปลี่ยนเส้นทาง (301 ย้ายอย่างถาวร, 302 พบ, 304 ไม่แก้ไข) |
| **4xxx** | ข้อผิดพลาดของไคลเอนต์ (400 คำขอไม่ถูกต้อง, 401 ไม่ได้รับอนุญาต, 403 ถูกห้าม, 404 ไม่พบ, 429 คำขอมากเกินไป) |
| **5xxx** | ข้อผิดพลาดของเซิร์ฟเวอร์ (ข้อผิดพลาดเซิร์ฟเวอร์ภายใน 500 ข้อ, เกตเวย์ไม่ถูกต้อง 502, บริการ 503 ไม่พร้อมใช้งาน) |
### ส่วนหัว
| ส่วนหัว | วัตถุประสงค์ |
|--------|---------|
| `Content-Type`| ประเภทสื่อ (`application/json`,`text/html`) |
| `Authorization`| ข้อมูลรับรอง (เช่น`Bearer <token>`) |
| `Cache-Control`| นโยบายการแคช |
| ส่วนหัว CORS | `Access-Control-Allow-Origin`ฯลฯ |

## TLS/SSL
เข้ารหัสการรับส่งข้อมูล HTTP (HTTPS = HTTP ผ่าน TLS)
- ใบรับรองจากผู้ออกใบรับรอง (CA) ตรวจสอบความถูกต้องของเซิร์ฟเวอร์
- ตรวจสอบห่วงโซ่ใบรับรองและชื่อโฮสต์บนฝั่งไคลเอ็นต์
---

## ไฟร์วอลล์และ NAT
### ไฟร์วอลล์
- กรองการรับส่งข้อมูลตามกฎ (IP ต้นทาง, IP ปลายทาง, พอร์ต, โปรโตคอล)
- ไฟร์วอลล์ stateful ติดตามสถานะการเชื่อมต่อ
### NAT (การแปลที่อยู่เครือข่าย)
- แปล IP ส่วนตัวเป็น IP สาธารณะสำหรับการเข้าถึงอินเทอร์เน็ต
- การส่งต่อพอร์ต: แมปพอร์ตสาธารณะกับโฮสต์/พอร์ตภายใน
---

## คำสั่งเครือข่ายทั่วไป
### การทดสอบการเชื่อมต่อ
```bash
ping google.com            # ICMP echo request
ping -c 4 8.8.8.8          # ping 4 times
traceroute google.com      # Trace the route (Linux)
tracert google.com         # Windows version
```

### เส้นทาง
```bash
ip route show              # Linux: routing table
route -n                   # Older Linux
netstat -r                 # Windows/Mac
```

### อินเทอร์เฟซเครือข่าย
```bash
ip addr show               # List interfaces and IPs
ifconfig                   # Older command
```

### ดีเอ็นเอส
```bash
dig example.com
nslookup example.com
host example.com
```

### การเชื่อมต่อกับพอร์ต
```bash
nc -zv google.com 443      # Netcat: check if port 443 is open
telnet google.com 443      # Telnet to port
curl -v https://google.com # Verbose output
```

### ไฟร์วอลล์ (Linux iptables/nftables)
```bash
sudo ufw status            # Ubuntu: simple firewall
sudo iptables -L -n        # List rules
```

### สถิติเครือข่าย
```bash
ss -tulpn                  # Show listening sockets (Linux)
netstat -an                # All sockets (all OS)
```

## โหลดบาลานซ์และพร็อกซีย้อนกลับ
### Nginx เป็น Reverse Proxy
```nginx
server {
    listen 80;
    server_name example.com;
    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### อัลกอริธึมการปรับสมดุลโหลด
- **โรบินรอบ**
- **การเชื่อมต่อน้อยที่สุด**
- **แฮช IP** (ความเหนียวของเซสชัน)
- **โรบินถ่วงน้ำหนัก**
### เครื่องมือ
- **Nginx, HAProxy** (ซอฟต์แวร์)
- **AWS ELB, Azure Load Balancer, GCP Cloud Load Balancing** (คลาวด์)

## รายการตรวจสอบการแก้ไขปัญหา
1. ลิงก์ทางกายภาพนั้นใช้งานได้หรือไม่? (ตรวจสอบสายเคเบิล การเชื่อมต่อ Wi-Fi)
2. คุณสามารถ ping เกตเวย์ได้หรือไม่? (เช่น`ping 192.168.1.1`)
3. คุณสามารถ ping IP ภายนอกได้หรือไม่? (เช่น`8.8.8.8`)
4. คุณสามารถแก้ไขโดเมนได้หรือไม่? (`dig google.com`).
5. แอปพลิเคชันกำลังฟังพอร์ตที่ต้องการหรือไม่ (`ss -tulpn | grep 8080`).
6. ไฟร์วอลล์บล็อกพอร์ตหรือไม่? (ตรวจสอบ`iptables`/`ufw`หรือกลุ่มความปลอดภัยของระบบคลาวด์)
7. มีข้อผิดพลาดใดๆ ในบันทึกของแอปพลิเคชันหรือไม่?
8. ใบรับรอง TLS ถูกต้องและเชื่อถือได้หรือไม่? (`openssl s_client -connect example.com:443`).
