# สถาปัตยกรรมคลาวด์
การประมวลผลแบบคลาวด์ได้เปลี่ยนวิธีที่องค์กรสร้าง ปรับใช้ และปรับขนาดซอฟต์แวร์โดยพื้นฐาน แทนที่จะซื้อและบำรุงรักษาเซิร์ฟเวอร์จริง คุณสามารถจัดเตรียมทรัพยากรการประมวลผลตามความต้องการ ชำระค่าบริการที่คุณใช้ และปรับขนาดได้ทั่วโลกภายในไม่กี่นาที ไฟล์นี้ครอบคลุมแนวคิดหลัก รูปแบบสถาปัตยกรรม บริการ และแนวทางปฏิบัติที่ดีที่สุดที่คุณจำเป็นต้องทราบ
---

## พื้นฐานคอมพิวเตอร์คลาวด์
### Cloud Computing คืออะไร?
การส่งมอบทรัพยากรคอมพิวเตอร์ตามความต้องการ — เซิร์ฟเวอร์ พื้นที่เก็บข้อมูล ฐานข้อมูล ระบบเครือข่าย ซอฟต์แวร์ — ผ่านทางอินเทอร์เน็ตในราคาแบบจ่ายตามการใช้งาน
### ลักษณะสำคัญของ NIST
| ลักษณะเฉพาะ | ความหมาย |
|---------------|---------|
| **บริการตนเองตามความต้องการ** | จัดเตรียมทรัพยากรโดยไม่ต้องมีปฏิสัมพันธ์กับมนุษย์ |
| **การเข้าถึงเครือข่ายกว้าง** | พร้อมใช้งานผ่านเครือข่ายผ่านกลไกมาตรฐาน |
| **การรวมทรัพยากร** | รูปแบบผู้เช่าหลายราย ทรัพยากรที่ได้รับมอบหมายแบบไดนามิก |
| **ความยืดหยุ่นอย่างรวดเร็ว** | ปรับขนาดเข้าและออกได้อย่างรวดเร็ว |
| **วัดผลการบริการ** | การใช้งานได้รับการตรวจสอบและเรียกเก็บเงิน |
### โมเดลการใช้งาน
| รุ่น | คำอธิบาย | เมื่อใดควรใช้ |
|-------|-------------|-------------|
| **คลาวด์สาธารณะ** | เป็นเจ้าของโดยผู้ให้บริการ; โครงสร้างพื้นฐานที่ใช้ร่วมกัน (AWS, Azure, GCP) | ปริมาณงานส่วนใหญ่ คุ้มค่า |
| **คลาวด์ส่วนตัว** | ทุ่มเทให้กับองค์กรเดียว | ข้อกำหนดด้านกฎระเบียบ ข้อมูลที่ละเอียดอ่อน |
| **ไฮบริดคลาวด์** | การรวมกันของภาครัฐและเอกชน | ความยืดหยุ่น + การปฏิบัติตามข้อกำหนด |
| **มัลติคลาวด์** | การใช้ผู้ให้บริการคลาวด์สาธารณะหลายราย | หลีกเลี่ยงการล็อคอินของผู้ขาย ซึ่งเป็นสายพันธุ์ที่ดีที่สุด |
### รูปแบบการให้บริการ
| รุ่น | ให้ | ตัวอย่าง | กรณีการใช้งาน |
|-------|----------|----------|-----------|
| **IaaS** | VM, พื้นที่เก็บข้อมูล, เครือข่าย, OS | AWS EC2, Azure VM, GCP Compute Engine | การโยกย้ายแบบยกและเลื่อน ควบคุมเต็มรูปแบบ |
| **PaaS** | แพลตฟอร์มการพัฒนา ฐานข้อมูล มิดเดิลแวร์ | Heroku, Google App Engine, AWS Elastic Beanstalk | การพัฒนาแอพ, การปรับใช้ API |
| **SaaS** | กรอกใบสมัครผ่านอินเตอร์เน็ต | Salesforce, Google Workspace, Microsoft 365 | อีเมล, CRM, การทำงานร่วมกัน |
| **FaaS / ไร้เซิร์ฟเวอร์** | การดำเนินการฟังก์ชันที่ขับเคลื่อนด้วยเหตุการณ์ | AWS Lambda, ฟังก์ชัน Azure, ฟังก์ชันคลาวด์ GCP API, การประมวลผลเหตุการณ์, งานที่กำหนดเวลาไว้ |

## ผู้ให้บริการคลาวด์รายใหญ่
| ผู้ให้บริการ | ส่วนแบ่งการตลาด | จุดแข็ง |
|----------|-------------|-----------|
| **AWS** | ~32% | แค็ตตาล็อกบริการที่กว้างที่สุด ระบบนิเวศที่ใหญ่ที่สุด |
| **สีฟ้า** | ~23% | การบูรณาการระดับองค์กร, ไฮบริดคลาวด์, Microsoft stack |
| **จีซีพี** | ~10% | การวิเคราะห์ข้อมูล, AI/ML, Kubernetes |
| **อาลีบาบาคลาวด์** | ~4% | โดดเด่นในเอเชียแปซิฟิก |
| **ออราเคิลคลาวด์** | ~2% | ปริมาณงานฐานข้อมูล แอประดับองค์กร |
| **ไอบีเอ็ม คลาวด์** | ~2% | โฟกัสองค์กร Watson AI |
| **ดิจิทัลโอเชียน** | นิช | ข้อเสนอที่เป็นมิตรกับนักพัฒนาและเรียบง่าย |
### การเปรียบเทียบบริการ (ผู้ให้บริการ 3 อันดับแรก)
| หมวดหมู่ | AWS | สีฟ้า | จีซีพี |
|----------|-----|-------|-----|
| **คำนวณ** | EC2, แลมบ์ดา, ECS | VM, ฟังก์ชั่น, AKS | Compute Engine, ฟังก์ชันคลาวด์, GKE |
| **การจัดเก็บ** | S3, EBS, กลาเซียร์ | ที่เก็บข้อมูล Blob, ที่เก็บข้อมูลดิสก์ | ที่เก็บข้อมูลบนคลาวด์ ดิสก์ถาวร |
| **ฐานข้อมูล** | RDS, DynamoDB, ออโรร่า | ฐานข้อมูล SQL, คอสมอส DB | Cloud SQL, Firestore, Bigtable |
| **การวิเคราะห์** | เรดชิฟต์, EMR | ไซแนปส์, Databricks | BigQuery, กระแสข้อมูล |
| **AI/ML** | SageMaker, การจดจำ | Azure ML บริการทางปัญญา | จุดยอด AI, AutoML |
| **ระบบเครือข่าย** | VPC, เส้นทาง 53, CloudFront | VNet ผู้จัดการฝ่ายจราจร | VPC, คลาวด์ DNS, คลาวด์ CDN |

## รูปแบบสถาปัตยกรรม
### กรอบงานที่มีการออกแบบอย่างดี
ผู้ให้บริการรายใหญ่ทั้งสามรายเผยแพร่เฟรมเวิร์กที่มีสถาปัตยกรรมอย่างดีซึ่งสร้างขึ้นโดยมีเสาหลัก 5 ประการ:
| เสา | หลักการสำคัญ |
|--------|---------------|
| **ความเป็นเลิศในการปฏิบัติงาน** | ดำเนินการอัตโนมัติ ทำการเปลี่ยนแปลงบ่อยครั้งและย้อนกลับได้ คาดหวังความล้มเหลว |
| **ความปลอดภัย** | รากฐานอัตลักษณ์ที่แข็งแกร่ง รักษาความปลอดภัยทุกชั้น ปกป้องข้อมูลระหว่างทางและที่เหลือ |
| **ความน่าเชื่อถือ** | ทดสอบขั้นตอนการกู้คืน กู้คืนอัตโนมัติจากความล้มเหลว ปรับขนาดในแนวนอน |
| **ประสิทธิภาพการทำงาน** | ใช้แบบไร้เซิร์ฟเวอร์ ก้าวสู่ระดับโลกภายในไม่กี่นาที ทดลองบ่อยๆ |
| **การเพิ่มประสิทธิภาพต้นทุน** | ใช้รูปแบบการบริโภค ใช้บริการที่ได้รับการจัดการ หยุดใช้จ่ายกับการทำงานที่ไม่แตกต่าง |
### รูปแบบทั่วไป
| รูปแบบ | คำอธิบาย | สิทธิประโยชน์ | ความท้าทาย |
|---------|-------------|----------|------------|
| **ไมโครเซอร์วิส** | แยกแอปออกเป็นบริการขนาดเล็กและเป็นอิสระ | ความสามารถในการขยายขนาด การแยกข้อผิดพลาด การปรับใช้แบบอิสระ | ความซับซ้อนแบบกระจาย ความสอดคล้องของข้อมูล
| **ขับเคลื่อนด้วยเหตุการณ์** | ส่วนประกอบสื่อสารผ่านเหตุการณ์ | คลัปหลวม การประมวลผลแบบเรียลไทม์ ความซับซ้อนในการดีบัก ความสอดคล้องในที่สุด
| **ไร้เซิร์ฟเวอร์** | ไม่มีการจัดการเซิร์ฟเวอร์ จ่ายต่อการดำเนินการ | ประสิทธิภาพด้านต้นทุน การใช้งานที่รวดเร็ว | Cold Start, การล็อคอินของผู้ขาย, ขีดจำกัดการดำเนินการ |
| **เลเยอร์ (N-Tier)** | การนำเสนอ → ตรรกะทางธุรกิจ → การเข้าถึงข้อมูล → ฐานข้อมูล | แยกความกังวล การบำรุงรักษา | สามารถกลายเป็นเสาหินได้ |
| **ตามอวกาศ** | ข้อมูลที่กระจายไปทั่วโหนดหน่วยความจำเสมือน | จัดการการทำงานพร้อมกันสูง เวลาแฝงต่ำ | ซับซ้อนในการออกแบบและจัดการ |

## บริการหลัก
### คอมพิวเตอร์
| ประเภทบริการ | รายละเอียด |
|-------------|---------|
| **เครื่องเสมือน** | วัตถุประสงค์ทั่วไป, เพิ่มประสิทธิภาพการประมวลผล, เพิ่มประสิทธิภาพหน่วยความจำ, GPU ราคา: ตามความต้องการ, สงวนไว้, เฉพาะจุด |
| **ตู้คอนเทนเนอร์** | รันไทม์นักเทียบท่า; การเรียบเรียงผ่าน Kubernetes (EKS, AKS, GKE) การลงทะเบียน: ECR, GCR, ACR |
| **ฟังก์ชันไร้เซิร์ฟเวอร์** | เกิดจากเหตุการณ์ ไร้สัญชาติ ข้อจำกัดด้านเวลาดำเนินการ หน่วยความจำ และการทำงานพร้อมกัน |
### พื้นที่จัดเก็บ
| พิมพ์ | ลักษณะ | ตัวอย่าง | ดีที่สุดสำหรับ |
|------|----------------|----------|----------|
| **วัตถุ** | โครงสร้างแบบเรียบ, การเข้าถึง HTTP, | อุดมไปด้วยข้อมูลเมตา S3, ที่เก็บข้อมูลบนคลาวด์, Azure Blob | สินทรัพย์แบบคงที่ การสำรองข้อมูล ที่จัดเก็บข้อมูลดิบ |
| **บล็อก** | วอลุ่มดิบที่แนบกับ VM | EBS, ดิสก์ถาวร, ดิสก์ Azure | ฐานข้อมูล วอลุ่มการบูต |
| **ไฟล์** | ระบบไฟล์ที่ใช้ร่วมกัน (NFS/SMB) | EFS, Filestore, ไฟล์ Azure | การจัดการเนื้อหา การกำหนดค่าที่ใช้ร่วมกัน |
| **เก็บถาวร** | ต้นทุนต่ำสุด ความล่าช้าในการเรียกค้น | S3 Glacier, เอกสารเก่าของ Azure | การปฏิบัติตามข้อกำหนดการสำรองข้อมูลระยะยาว |
### ฐานข้อมูล
| หมวดหมู่ | บริการ | ใช้กรณี |
|----------|----------|----------|
| **จัดการเชิงสัมพันธ์** | RDS, คลาวด์ SQL, Azure SQL | แอพดั้งเดิม ธุรกรรม ACID |
| **NoSQL — เอกสาร** | DocumentDB, Firestore, คอสมอส DB | สคีมาที่ยืดหยุ่น ข้อมูล JSON |
| **NoSQL — คีย์-ค่า** | DynamoDB, แคช Redis | การแคช เซสชัน การค้นหาแบบง่าย |
| **NoSQL — คอลัมน์กว้าง** | บิ๊กเทเบิล, แคสแซนดรา | เขียนหนัก อนุกรมเวลา |
| **NoSQL — กราฟ** | ดาวเนปจูน, คอสมอส DB (กราฟ API) | ความสัมพันธ์, โซเชียลเน็ตเวิร์ก |
| **คลังข้อมูล** | เกล็ดหิมะ, Redshift, BigQuery, ไซแนปส์ | การวิเคราะห์ BI |
| **แคช** | ElastiCache, Cloud Memorystore | ที่เก็บข้อมูลเซสชัน การแคชแบบสอบถาม |

## เครือข่าย
### เครือข่ายเสมือน
การใช้งานคลาวด์ทุกครั้งจะอยู่ภายใน Virtual Private Cloud (VPC / VNet) ซึ่งเป็นเครือข่ายแบบแยกที่คุณกำหนดด้วยบล็อก CIDR ซับเน็ต (สาธารณะหรือส่วนตัว) ตารางเส้นทาง และเกตเวย์
### โหลดบาลานซ์และ CDN
| บริการ | วัตถุประสงค์ |
|---------|---------|
| **โหลดบาลานเซอร์** | กระจายการรับส่งข้อมูลข้ามอินสแตนซ์ (เครือข่าย L4, แอปพลิเคชัน L7) |
| **ซีดีเอ็น** | เนื้อหาแคชที่ตำแหน่ง Edge เพื่อลดเวลาแฝง (CloudFront, Cloud CDN, Azure CDN) |
| **DNS** | การจดทะเบียนโดเมน นโยบายการกำหนดเส้นทาง การตรวจสอบสภาพ (เส้นทาง 53, Cloud DNS, Azure DNS) |
### ตัวเลือกการเชื่อมต่อ
| ตัวเลือก | คำอธิบาย |
|--------|-------------|
| **อินเตอร์เน็ตเกตเวย์** | การเข้าถึงอินเทอร์เน็ตสาธารณะสำหรับ VPC |
| **เกตเวย์ NAT** | การเข้าถึงเครือข่ายย่อยส่วนตัวขาออก |
| **VPN** | อุโมงค์ที่เข้ารหัสไปยังในสถานที่ |
| **เชื่อมต่อโดยตรง / ExpressRoute** | การเชื่อมต่อส่วนตัวโดยเฉพาะ |
| **การเพียร์ VPC** | เชื่อมต่อ VPC ภายในหรือระหว่างบัญชี |

## ความปลอดภัย
### โมเดลความรับผิดชอบร่วมกัน
| เลเยอร์ | ผู้ให้บริการ | ลูกค้า |
|-------|----------|----------|
| **โครงสร้างพื้นฐาน** (ฮาร์ดแวร์ สิ่งอำนวยความสะดวก) | ✅ | |
| **คอมพิวเตอร์ การจัดเก็บ เครือข่าย** | ✅ (จัดการ) | ✅ (จัดการเอง) |
| **ข้อมูล แอปพลิเคชัน ตัวตน** | | ✅ |
ยิ่งมีการจัดการบริการมากเท่าใด ผู้ให้บริการก็จะยิ่งจัดการมากขึ้นเท่านั้น ด้วย IaaS คุณสามารถจัดการได้เกือบทุกอย่าง ด้วย SaaS ผู้ให้บริการจะจัดการเกือบทั้งหมด
### การจัดการข้อมูลประจำตัวและการเข้าถึง (IAM)
| แนวคิด | คำอธิบาย |
|---------|-------------|
| **ผู้ใช้** | ตัวตนส่วนบุคคล |
| **กลุ่ม** | คอลเลกชันของผู้ใช้ |
| **บทบาท** | ข้อมูลรับรองชั่วคราวสำหรับบริการหรือผู้ใช้ |
| **นโยบาย** | เอกสารกำหนดสิทธิ์ |
| **หลักการ** | สิทธิพิเศษน้อยที่สุด, การแบ่งแยกหน้าที่ |
### การปกป้องข้อมูล
- **การเข้ารหัสเมื่อไม่ได้ใช้งาน**: KMS, คีย์ที่จัดการโดยลูกค้า, HSM
- **การเข้ารหัสระหว่างทาง**: TLS/SSL, HTTPS
- **การจัดการความลับ**: ผู้จัดการความลับ, Key Vault — ไม่ต้องฮาร์ดโค้ดความลับ

## การจัดการต้นทุน
### โมเดลการกำหนดราคา
| รุ่น | คำอธิบาย | ดีที่สุดสำหรับ |
|-------|-------------|----------|
| **ตามความต้องการ** | ชำระค่าบริการเป็นวินาที/ชั่วโมง | ปริมาณงานระยะสั้นที่แปรผันได้ |
| **อินสแตนซ์ที่สงวนไว้** | ความมุ่งมั่น 1–3 ปี ส่วนลดจำนวนมาก | ปริมาณงานในสภาวะคงตัว |
| **สปอตอินสแตนซ์** | ประมูลความจุที่ไม่ได้ใช้ สามารถถูกขัดจังหวะได้ | งานที่ทนทานต่อข้อผิดพลาดและยืดหยุ่น |
| **แผนการออมทรัพย์** | การกำหนดราคาข้อผูกมัดที่ยืดหยุ่น | รูปแบบการใช้งานแบบผสม |
| **ฟรีเทียร์** | การใช้งานฟรีแบบจำกัดสำหรับบัญชีใหม่ | การเรียนรู้การสร้างต้นแบบ |
### กลยุทธ์การเพิ่มประสิทธิภาพ
อินสแตนซ์ขนาดที่เหมาะสมเพื่อให้ตรงกับปริมาณงาน ใช้การปรับขนาดอัตโนมัติเพื่อรับมือกับความต้องการที่เพิ่มขึ้นอย่างรวดเร็ว ความจุสำรองสำหรับโหลดที่คาดการณ์ได้ ใช้อินสแตนซ์สปอตสำหรับงานแบทช์ ย้ายข้อมูลที่เข้าถึงไม่บ่อยไปยังระดับพื้นที่จัดเก็บข้อมูลที่ถูกกว่า ลบทรัพยากรที่ไม่ได้ใช้ (สแน็ปช็อตที่ถูกละเลย, ตัวจัดสรรภาระงานที่ไม่ได้ใช้งาน, IP ที่ไม่ได้เชื่อมต่อ)

## ความพร้อมใช้งานสูงและการกู้คืนความเสียหาย
### แนวคิดเรื่องความพร้อมใช้งาน
| แนวคิด | คำอธิบาย |
|---------|-------------|
| **โซนที่มีจำหน่าย (AZ)** | ศูนย์ข้อมูลที่แยกจากกันทางกายภาพภายในภูมิภาค |
| **ภูมิภาค** | พื้นที่ทางภูมิศาสตร์ที่มี AZ หลายรายการ |
| **ตำแหน่งขอบ** | ตำแหน่งแคช CDN สำหรับการจัดส่งเนื้อหา |
### กลยุทธ์การกู้คืนความเสียหาย
| กลยุทธ์ | ราคา | อาร์ทีโอ | อาร์พีโอ | คำอธิบาย |
|----------|-|-----|-----|-------------|
| **สำรองและกู้คืน** | ต่ำสุด | ชั่วโมง | ชั่วโมง–วัน | การสำรองข้อมูลเป็นระยะ กู้คืนเมื่อจำเป็น |
| **ไพล็อตไลท์** | ต่ำ | นาที–ชั่วโมง | นาที | องค์ประกอบหลักทำงานอยู่เสมอ เพิ่มขนาดเมื่อเกิดภัยพิบัติ |
| **สแตนด์บายอย่างอบอุ่น** | ปานกลาง | นาที | วินาที–นาที | เวอร์ชันที่ลดขนาดลงจะทำงานเสมอ |
| **ใช้งานหลายไซต์/ใช้งานอยู่** | สูงสุด | ใกล้ศูนย์ | ศูนย์ | ผลิตเต็มรูปแบบในหลายภูมิภาค |
**RTO** (วัตถุประสงค์ของเวลาการกู้คืน) = เวลาหยุดทำงานสูงสุดที่ยอมรับได้ **RPO** (วัตถุประสงค์ของจุดกู้คืน) = การสูญเสียข้อมูลสูงสุดที่ยอมรับได้

## เทรนด์ที่กำลังมาแรง
| เทรนด์ | เกิดอะไรขึ้น |
|----------------------|-----------------|
| **เอดจ์คอมพิวเตอร์** | การประมวลผลข้อมูลที่ใกล้กับแหล่งที่มามากขึ้น (AWS Outposts, Wavelength, Azure Edge) |
| **มัลติคลาวด์** | หลีกเลี่ยงการล็อคอินของผู้ขาย ใช้ประโยชน์จากผู้ให้บริการที่ดีที่สุดข้ามสายพันธุ์ |
| **บริการ AI/ML** | โมเดลที่ผ่านการฝึกอบรมล่วงหน้า (การมองเห็น คำพูด ภาษา) + การฝึกอบรมแบบกำหนดเอง (SageMaker, Vertex AI) |
| **คอมพิวเตอร์ควอนตัม** | บริการทดลองระยะเริ่มต้น (AWS Braket, Azure Quantum) |
| **คลาวด์ที่ยั่งยืน** | การติดตามรอยเท้าคาร์บอน ความมุ่งมั่นด้านพลังงานทดแทน สถาปัตยกรรมสีเขียว |
