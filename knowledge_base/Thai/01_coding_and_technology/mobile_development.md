# การพัฒนามือถือ
การพัฒนาอุปกรณ์เคลื่อนที่คือแนวทางปฏิบัติในการสร้างแอปพลิเคชันสำหรับสมาร์ทโฟนและแท็บเล็ต — สำหรับ iOS (Apple) และ Android (Google) เป็นหลัก ครอบคลุมทุกอย่างตั้งแต่การออกแบบ UI สำหรับหน้าจอขนาดเล็กไปจนถึงการจัดการอายุการใช้งานแบตเตอรี่ การจัดการความไม่เสถียรของเครือข่าย และการเผยแพร่แอปผ่านร้านค้า ฟิลด์นี้ได้รับการพัฒนาอย่างมาก โดยขณะนี้เฟรมเวิร์กข้ามแพลตฟอร์มกำลังแข่งขันกับการพัฒนาแบบเนทีฟสำหรับกรณีการใช้งานส่วนใหญ่
---

## ภูมิทัศน์มือถือ
| แพลตฟอร์ม | นักพัฒนา | ภาษา | ร้านค้า | ส่วนแบ่งการตลาด (ทั่วโลก) |
|----------|-----------|-------------|-------|----------------------|
| **แอนดรอยด์** | กูเกิล | Kotlin ชวา | Google Play | ~72% |
| **iOS** | แอปเปิ้ล | Swift, Objective-C | แอพสโตร์ | ~27% |
---

## การพัฒนาพื้นเมือง
### แอนดรอยด์
| ด้าน | รายละเอียด |
|--------|---------|
| **ภาษา** | Kotlin (หลัก), Java (ดั้งเดิม) |
| **กรอบ UI** | Jetpack Compose (สมัยใหม่), เค้าโครง XML (ดั้งเดิม) |
| **สร้างระบบ** | เกรเดิล |
| **IDE** | แอนดรอยด์สตูดิโอ |
| **SDK ขั้นต่ำ** | นักพัฒนาเลือก; API เป้าหมายสูงสุด 24+ (Android 7.0, 2016) |
| **การจัดจำหน่าย** | Google Play สโตร์; ร้านค้าทางเลือกในบางตลาด |
### ไอโอเอส
| ด้าน | รายละเอียด |
|--------|---------|
| **ภาษา** | Swift (หลัก), Objective-C (ดั้งเดิม) |
| **กรอบ UI** | SwiftUI (สมัยใหม่), UIKit (ผู้ใหญ่) |
| **สร้างระบบ** | ระบบสร้าง Xcode |
| **IDE** | Xcode (macOS เท่านั้น) |
| **เวอร์ชั่นขั้นต่ำ** | นักพัฒนาเลือก; เป้าหมายสูงสุด iOS 16+ |
| **การจัดจำหน่าย** | Apple App Store (ตัวเลือกเดียวสำหรับแอพส่วนใหญ่) |

## กรอบงานข้ามแพลตฟอร์ม
สร้างครั้งเดียว ปรับใช้กับทั้ง iOS และ Android
| กรอบ | ภาษา | กำลังเรนเดอร์ | ประสิทธิภาพ | ดีที่สุดสำหรับ |
|----------|----------|------|-------------|----------|
| **กระพือ** | โผ | เครื่องยนต์แบบกำหนดเอง (Skia/ใบพัด) | ใกล้พื้นเมือง | UI ที่กำหนดเองที่หลากหลาย ดูสอดคล้องกันในทุกแพลตฟอร์ม |
| **โต้ตอบพื้นเมือง** | จาวาสคริปต์/ไทป์สคริปต์ | ส่วนประกอบดั้งเดิมผ่านบริดจ์ | ดี (สถาปัตยกรรมใหม่ปรับปรุงสิ่งนี้) | ทีมงานที่มีประสบการณ์ด้านเว็บ/JS |
| **Kotlin หลากหลายแพลตฟอร์ม** | คอตลิน | Native UI ต่อแพลตฟอร์ม | พื้นเมือง | แบ่งปันตรรกะทางธุรกิจ UI ดั้งเดิม |
| **MAUI** (.NET) | ซี# | การควบคุมแบบเนทีฟ | ดี | ทีม .NET; แอพระดับองค์กร |
| **อิออน / ตัวเก็บประจุ** | HTML/CSS/JS | เว็บวิว | ล่าง | แอพง่าย ๆ ทีมงานเว็บ |
### Flutter กับ React Native
| ด้าน | กระพือ | ตอบสนองพื้นเมือง |
|--------|---------|-------------|
| **ภาษา** | โผ | จาวาสคริปต์/ไทป์สคริปต์ |
| **การเรนเดอร์ UI** | วาดทุกอย่างด้วยตัวมันเอง (สอดคล้องกันข้ามแพลตฟอร์ม) | ใช้ส่วนประกอบดั้งเดิม (รูปลักษณ์เฉพาะแพลตฟอร์ม) |
| **โหลดใหม่ด่วน** | ดีเยี่ยม | ดี |
| **ระบบนิเวศ** | เติบโตอย่างรวดเร็ว ตามวิดเจ็ต | ใหญ่; ระบบนิเวศ npm |
| **เส้นโค้งการเรียนรู้** | ต้องเรียน Dart | ง่ายกว่าสำหรับนักพัฒนาเว็บ |
| **การบูรณาการแพลตฟอร์ม** | ช่องทางแพลตฟอร์มสำหรับโค้ดเนทีฟ | โมดูลดั้งเดิมผ่านบริดจ์ |
| **ประสิทธิภาพ** | ยอดเยี่ยม; ใกล้พื้นเมือง | ดี; ค่าโสหุ้ยสะพาน (ลดด้วยสถาปัตยกรรมใหม่) |

## รูปแบบสถาปัตยกรรมมือถือ
| รูปแบบ | คำอธิบาย | เมื่อใดควรใช้ |
|---------|-------------|-------------|
| **เอ็มวีซี** | Model-View-Controller | แอพง่าย ๆ คุ้นเคยกับนักพัฒนาเว็บ |
| **MVVM** | โมเดล-ดู-ViewModel; การผูกข้อมูล | แอพมือถือที่ทันสมัยที่สุด |
| **เอ็มวีไอ** | โมเดล-ดู-เจตนา; การไหลของข้อมูลทิศทางเดียว | การจัดการรัฐที่ซับซ้อน กระพือ (พร้อม BLoC/Riverpod) |
| **สถาปัตยกรรมสะอาดตา** | เลเยอร์ที่มีการผกผันการพึ่งพา | ทีมใหญ่; ตรรกะทางธุรกิจที่ซับซ้อน |

## ข้อกังวลสำคัญเกี่ยวกับมือถือ
### การออกแบบออฟไลน์ครั้งแรก
แอพมือถือต้องทำงานโดยไม่มีอินเทอร์เน็ตที่เชื่อถือได้
| กลยุทธ์ | คำอธิบาย |
|----------|-------------|
| **ฐานข้อมูลท้องถิ่น** | จัดเก็บข้อมูลบนอุปกรณ์ (SQLite, Room, CoreData, Realm) |
| **กลยุทธ์การซิงค์** | ซิงค์กับเซิร์ฟเวอร์เมื่อออนไลน์ แก้ไขข้อขัดแย้ง |
| **UI ในแง่ดี** | อัปเดต UI ทันที กระทบยอดเมื่อเซิร์ฟเวอร์ตอบสนอง |
| **แคช** | การตอบสนองของแคช API; ให้บริการจากแคชเมื่อออฟไลน์ |
### ผลงาน
| ความกังวล | โซลูชั่น |
|---------|----------|
| **เวลาเริ่มต้นแอป** | โหลดแบบขี้เกียจ; ลดงานการเริ่มต้นให้เหลือน้อยที่สุด |
| **การใช้หน่วยความจำ** | การบีบอัดภาพ หลีกเลี่ยงการรั่วไหลของหน่วยความจำ ใช้เครื่องมือสร้างโปรไฟล์ |
| **แบตเตอรี่หมด** | ลดการทำงานเบื้องหลัง คำขอเครือข่ายแบบแบตช์ ใช้บริการระบุตำแหน่งที่มีประสิทธิภาพ |
| **ประสิทธิภาพของเครือข่าย** | บีบอัดเพย์โหลด; ใช้การแบ่งหน้า; แคชอย่างจริงจัง |
| **เลื่อนรายการ** | มุมมองรีไซเคิล; ใช้การโหลดแบบ Lazy Loading สำหรับรูปภาพ |
### ความปลอดภัย
| ความกังวล | โซลูชั่น |
|---------|----------|
| **ข้อมูลที่เหลือ** | เข้ารหัสข้อมูลที่ละเอียดอ่อน (Keychain บน iOS, EncryptedSharedPreferences บน Android) |
| **เครือข่าย** | HTTPS เสมอ; การปักหมุดใบรับรองสำหรับแอปที่มีความละเอียดอ่อน |
| **การรับรองความถูกต้อง** | ไบโอเมตริกซ์ (Face ID, ลายนิ้วมือ); OAuth; การจัดเก็บโทเค็น |
| **การทำให้โค้ดสับสน** | ProGuard/R8 สำหรับ Android; บิตโค้ดสำหรับ iOS |
| **การตรวจจับการเจลเบรค/รูท** | ตรวจจับอุปกรณ์ที่ถูกบุกรุก ฟังก์ชั่นจำกัด |

## วงจรชีวิตของแอป
| รัฐ | คำอธิบาย | สิ่งที่ต้องทำ |
|-------|-------------|------------|
| **เบื้องหน้า (ใช้งานอยู่)** | ผู้ใช้กำลังโต้ตอบกับแอป | การทำงานปกติ |
| **ความเป็นมา** | มองไม่เห็นแอปแต่ยังอยู่ในหน่วยความจำ | หยุดภาพเคลื่อนไหวชั่วคราว บันทึกสถานะ |
| **ถูกระงับ** | OS ได้แช่แข็งแอปเพื่อประหยัดทรัพยากร | ไม่มีอะไร; แอพถูกแช่แข็ง |
| **สิ้นสุด** | OS ฆ่าแอปเพื่อเพิ่มหน่วยความจำ | คืนค่าสถานะในการเปิดตัวครั้งถัดไป |

## การแจ้งเตือนแบบพุช
| แพลตฟอร์ม | บริการ | โปรโตคอล |
|----------|---------|----------|
| **iOS** | APN (บริการแจ้งเตือน Apple Push) | HTTP/2 |
| **แอนดรอยด์** | FCM (การส่งข้อความบนคลาวด์ Firebase) | HTTP/v1 |
| ประเภทการแจ้งเตือน | คำอธิบาย |
|-------------------|-------------|
| **การแจ้งเตือนข้อมูล** | เงียบ; แอพประมวลผลเพย์โหลด | การอัปเดตเบื้องหลัง |
| **แสดงการแจ้งเตือน** | แสดงในถาดการแจ้งเตือน | การแจ้งเตือนผู้ใช้ |
| **การแจ้งเตือนที่หลากหลาย** | รวมรูปภาพ การกระทำ หรือ UI ที่กำหนดเอง | เพิ่มการมีส่วนร่วมของผู้ใช้ |

## สรุป
การพัฒนาอุปกรณ์เคลื่อนที่เสนอทางเลือกระหว่างเนทิฟ (ประสิทธิภาพที่ดีที่สุด เฉพาะแพลตฟอร์ม) และข้ามแพลตฟอร์ม (โค้ดเบสที่ใช้ร่วมกัน การวนซ้ำที่เร็วขึ้น) Flutter และ React Native เติบโตถึงจุดที่ข้ามแพลตฟอร์มเป็นตัวเลือกที่เหมาะสมสำหรับแอปพลิเคชันส่วนใหญ่ ความท้าทายหลักยังคงเหมือนเดิมโดยไม่คำนึงถึงกรอบการทำงาน: การออกแบบที่เน้นออฟไลน์เป็นหลัก ประสิทธิภาพบนฮาร์ดแวร์ที่มีจำกัด ประสิทธิภาพแบตเตอรี่ การรักษาความปลอดภัยบนอุปกรณ์ที่ไม่น่าเชื่อถือ และการนำทางกระบวนการตรวจสอบของ App Store ฟิลด์นี้ให้รางวัลแก่นักพัฒนาที่คิดถึงประสบการณ์ผู้ใช้เป็นอันดับแรก — การเริ่มต้นอย่างรวดเร็ว การเลื่อนที่ราบรื่น และการจัดการการเชื่อมต่อที่ไม่ดีอย่างสวยงาม
