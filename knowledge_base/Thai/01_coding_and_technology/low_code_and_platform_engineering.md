# วิศวกรรมโค้ดต่ำและแพลตฟอร์ม
แพลตฟอร์มที่ใช้โค้ดน้อยทำให้ผู้คนสามารถสร้างแอปพลิเคชันด้วยโค้ดที่เขียนด้วยลายมือเพียงเล็กน้อย — โดยทั่วไปผ่านทางอินเทอร์เฟซแบบลากและวาง เวิร์กโฟลว์แบบภาพ และตัวเชื่อมต่อที่สร้างไว้ล่วงหน้า วิศวกรรมแพลตฟอร์มเป็นวินัยในการสร้างแพลตฟอร์มสำหรับนักพัฒนาภายใน (IDP) ซึ่งช่วยให้ทีมผลิตภัณฑ์สามารถให้บริการโครงสร้างพื้นฐานด้วยตนเอง, CI/CD และเครื่องมือในการปฏิบัติงานได้อย่างง่ายดาย แนวโน้มทั้งสองเป็นการตอบสนองต่อปัญหาเดียวกัน นั่นคือช่องว่างระหว่างความต้องการซอฟต์แวร์และอุปทานของนักพัฒนาที่สามารถสร้างซอฟต์แวร์ได้
---

## แพลตฟอร์มโค้ดต่ำ
### จริงๆ แล้ว Low-Code หมายถึงอะไร
| ด้าน | คำอธิบาย |
|--------|-------------|
| **การพัฒนาการมองเห็น** | เครื่องมือสร้าง UI แบบลากและวาง บรรณาธิการเวิร์กโฟลว์ภาพ นักออกแบบแบบฟอร์ม |
| **ส่วนประกอบที่สร้างไว้ล่วงหน้า** | วิดเจ็ต ตัวเชื่อมต่อ เทมเพลต และการรวมระบบสำเร็จรูป |
| **ตรรกะที่ประกาศ** | กำหนดค่าพฤติกรรมผ่านกฎและเงื่อนไขแทนที่จะเขียนโค้ด |
| **ความสามารถในการขยาย** | ความสามารถในการเพิ่มโค้ดที่กำหนดเองเมื่อความสามารถในตัวของแพลตฟอร์มไม่เพียงพอ |
| **โครงสร้างพื้นฐานที่ได้รับการจัดการ** | แพลตฟอร์มรองรับการโฮสต์ การปรับขนาด แพตช์ความปลอดภัย |
### แพลตฟอร์ม Low-Code ยอดนิยม
| แพลตฟอร์ม | ความแข็งแกร่ง | กรณีการใช้งานทั่วไป |
|----------|----------|-----------------|
| **แพลตฟอร์ม Microsoft Power** | บูรณาการ Microsoft 365 / Azure อย่างลึกซึ้ง; Power Apps, Power Automate, Power BI | ขั้นตอนการทำงานระดับองค์กร เครื่องมือภายใน |
| **แพลตฟอร์ม Salesforce** | CRM-เนทิฟ; เอเพ็กซ์สำหรับส่วนขยาย; ตัวสร้างโฟลว์ | แอพที่ติดต่อกับลูกค้า ขั้นตอนการขาย |
| **บริการทันที** | การจัดการบริการไอที เวิร์กโฟลว์อัตโนมัติ | การดำเนินงานด้านไอที ทรัพยากรบุคคล; สิ่งอำนวยความสะดวก |
| **แอปเปียน** | การทำเหมืองแร่แบบกระบวนการ การจัดการกรณี | กระบวนการทางธุรกิจที่ซับซ้อน การปฏิบัติตาม |
| **ระบบภายนอก** | เว็บและมือถือเต็มรูปแบบ ระดับองค์กร | พอร์ทัลลูกค้า แอพมือถือ |
| **ปรับแต่ง** | ตัวสร้างเครื่องมือภายใน เชื่อมต่อกับฐานข้อมูลและ API | แผงผู้ดูแลระบบ แดชบอร์ด; เครื่องมือปฏิบัติการ |
| **โต๊ะบิน** | ลูกผสมฐานข้อมูลสเปรดชีต ระบบอัตโนมัติ | การติดตามโครงการ CRM น้ำหนักเบา |
### เมื่อ Low-Code ทำงานได้ดี
| สถานการณ์ | เหตุใดจึงเหมาะกับ Low-Code |
|----------|-------------------|
| **เครื่องมือภายใน** | รวดเร็วในการสร้าง ผู้ใช้เป็นแบบภายใน ดังนั้นความยืดหยุ่นของ UI จึงมีความสำคัญน้อยลง |
| **แบบฟอร์มและการอนุมัติ** | ตัวสร้างเวิร์กโฟลว์แบบเห็นภาพเก่งในสิ่งนี้ |
| **แอปพลิเคชัน CRUD** | แพลตฟอร์มที่ใช้โค้ดน้อยส่วนใหญ่ได้รับการปรับให้เหมาะสมสำหรับรูปแบบการสร้าง-อ่าน-อัพเดต-ลบ |
| **การสร้างต้นแบบ** | ตรวจสอบความถูกต้องของแนวคิดในหน่วยชั่วโมงแทนที่จะเป็นสัปดาห์ |
| **การพัฒนาพลเมือง** | นักวิเคราะห์ธุรกิจสามารถสร้างโซลูชันของตนเองด้วยการกำกับดูแลด้านไอที |
### เมื่อ Low-Code สั้นลง
| ข้อจำกัด | ผลกระทบ |
|------------|--------|
| **ล็อคอินผู้ขาย** | ไม่สามารถย้ายแอปพลิเคชันออกจากแพลตฟอร์มได้อย่างง่ายดาย |
| **เพดานประสิทธิภาพ** | ไม่เหมาะสำหรับแอปพลิเคชันที่มีปริมาณงานสูงหรือมีความละเอียดอ่อนต่อเวลาแฝง
| **ข้อจำกัด UI** | การออกแบบที่กำหนดเองเป็นเรื่องยาก คุณถูกจำกัดไว้เฉพาะสิ่งที่แพลตฟอร์มรองรับ |
| **ความซับซ้อนในการบูรณาการ** | การเชื่อมต่อกับ API ที่ผิดปกติหรือระบบเดิมอาจต้องใช้โค้ดที่กำหนดเองอยู่แล้ว |
| **ต้นทุนตามขนาด** | การกำหนดราคาต่อผู้ใช้หรือต่อแอปอาจมีราคาแพงเมื่อการใช้งานเพิ่มขึ้น |
| **ความยากในการดีบัก** | ภาพเชิงนามธรรมทำให้ยากต่อการวินิจฉัยปัญหาที่ซับซ้อน |

## วิศวกรรมแพลตฟอร์ม
### วิศวกรรมแพลตฟอร์มปัญหาแก้ไขได้
| ไม่มีวิศวกรรมแพลตฟอร์ม | ด้วยวิศวกรรมแพลตฟอร์ม |
|---------------------------------|---------------------------|
| แต่ละทีมจัดการโครงสร้างพื้นฐานของตนเอง | โครงสร้างพื้นฐานบทคัดย่อแพลตฟอร์มบริการตนเอง |
| การใช้เครื่องมือไม่สอดคล้องกันในทีม | ห่วงโซ่เครื่องมือที่ได้มาตรฐาน เส้นทางทองคำ |
| นักพัฒนาซอฟต์แวร์รอการดำเนินการเพื่อจัดเตรียมทรัพยากร | นักพัฒนาจัดเตรียมทรัพยากรตามความต้องการ |
| ไซโลความรู้ ความรู้เกี่ยวกับชนเผ่า | จัดทำเป็นเอกสาร; อัตโนมัติ; ค้นพบได้ |
| การเริ่มต้นใช้งานวิศวกรใหม่ช้า | วิศวกรใหม่สามารถใช้งานได้ตั้งแต่วันแรก |
### ส่วนประกอบหลักของแพลตฟอร์มนักพัฒนาภายใน
| ส่วนประกอบ | วัตถุประสงค์ | เครื่องมือตัวอย่าง |
|----------|---------|---------------|
| **แคตตาล็อกบริการ** | ทะเบียนกลางของบริการทั้งหมดและเจ้าของ | หลังเวที; ท่าเรือ; เยื่อหุ้มสมอง |
| **แม่แบบนั่งร้าน** | สร้างบริการใหม่จากเทมเพลตที่ได้รับอนุมัติ | เทมเพลตซอฟต์แวร์หลังเวที เครื่องตัดคุกกี้ |
| **โครงสร้างพื้นฐานแบบบริการตนเอง** | นักพัฒนาจัดเตรียมทรัพยากรระบบคลาวด์โดยไม่ต้องยื่นตั๋ว | โมดูลเทอร์ราฟอร์ม; ปูลูมิ; ครอสเพลน |
| **ไปป์ไลน์ CI/CD** | สร้าง ทดสอบ ปรับใช้ไปป์ไลน์ที่ได้มาตรฐาน | การกระทำ GitHub; GitLab ซีไอ; อาร์โก้ซีดี |
| **การจัดการสิ่งแวดล้อม** | สภาพแวดล้อมการพัฒนา/การจัดเตรียมชั่วคราวตามความต้องการ | คลัสเตอร์; เนมสเปซ; กิตพอด |
| **การสังเกต** | การบันทึก ตัวชี้วัด การติดตามที่มีอยู่ในทุกบริการ | โพร; กราฟานา; OpenTelemetry; ดาต้าด็อก |
| **การจัดการความลับ** | การจัดเก็บที่ปลอดภัยและการหมุนเวียนข้อมูลรับรอง | ห้องนิรภัย; ตัวจัดการความลับ AWS; สบส. |
| **ตัวตนและการเข้าถึง** | สปส.; การเข้าถึงตามบทบาท การรับรองความถูกต้องแบบบริการต่อบริการ | ออคตะ; เสื้อคลุมกุญแจ; สปิฟฟ์ |
### เส้นทางทองคำ
เส้นทางทองคือแนวทางที่สนับสนุนและเอาแต่ใจในการทำบางสิ่งบางอย่าง เป็นเส้นทางที่มีการต่อต้านน้อยที่สุด — ถ้าคุณทำตาม ทุกอย่างจะได้ผล คุณสามารถออกนอกเส้นทางได้ แต่คุณอยู่ด้วยตัวเอง
| เส้นทางทองคำ | ให้อะไร |
|-----------------|-----------------|
| **บริการใหม่** | เทมเพลต repo; ซีไอ/ซีดี; การตรวจสอบ; การบันทึก; การกำหนดค่าการปรับใช้ |
| **ฐานข้อมูลใหม่** | อินสแตนซ์ที่จัดเตรียมไว้ สตริงการเชื่อมต่อเป็นความลับ สำรองข้อมูลที่กำหนดค่าไว้ |
| **ส่วนหน้าใหม่** | สร้างไปป์ไลน์ ซีดีเอ็น; สภาพแวดล้อมการแสดงตัวอย่าง การตรวจสอบประภาคาร |
| **ไปป์ไลน์ข้อมูล** | การเรียบเรียง; การตรวจสอบความถูกต้องของสคีมา การตรวจสอบ; การแจ้งเตือน |
### การตัดสินใจสร้างและการซื้อ
| ปัจจัย | สร้างแบบกำหนดเอง | ใช้เครื่องมือที่มีอยู่ |
|--------|-------------|-------------------|
| **ความสามารถหลัก** | มีเอกลักษณ์เฉพาะสำหรับธุรกิจของคุณ ความได้เปรียบในการแข่งขัน | สินค้า; ทุกบริษัทต้องการมัน |
| **ภาระการบำรุงรักษา** | คุณมีความสามารถที่จะรักษามันไว้ | เครื่องมือได้รับการดูแลอย่างดีโดยผู้ขาย/ชุมชน |
| **ความต้องการบูรณาการ** | จำเป็นต้องบูรณาการอย่างลึกซึ้งกับระบบภายใน | API มาตรฐานและตัวเชื่อมต่อก็เพียงพอแล้ว |
| **ราคา** | ถูกกว่าการสร้างใบอนุญาต | ถูกกว่าค่าลิขสิทธิ์มากกว่า build |

## ความสัมพันธ์ระหว่าง Low-Code และวิศวกรรมแพลตฟอร์ม
| มิติข้อมูล | รหัสต่ำ | วิศวกรรมแพลตฟอร์ม |
|----------|----------|---------------------|
| **ผู้ใช้เป้าหมาย** | ผู้ใช้ทางธุรกิจ นักพัฒนาพลเมือง | วิศวกรซอฟต์แวร์มืออาชีพ |
| **เป้าหมาย** | ลดรหัส; เพิ่มความเร็ว | ลดภาระทางปัญญา เพิ่มความเป็นอิสระ |
| **ระดับนามธรรม** | สูงมาก; ภาพ | ปานกลาง; อิงโค้ดแต่เรียบง่าย |
| **ความยืดหยุ่น** | ถูกจำกัดด้วยความสามารถของแพลตฟอร์ม | ความยืดหยุ่นเต็มที่ คุณสามารถเขียนโค้ดใดก็ได้ |
| **การกำกับดูแล** | แพลตฟอร์มบังคับใช้กฎ | แพลตฟอร์มให้เส้นทางทอง |
สิ่งเหล่านี้เป็นส่วนเสริม: วิศวกรรมแพลตฟอร์มทำให้นักพัฒนามืออาชีพเร็วขึ้น ในขณะที่โค้ดต่ำช่วยให้ผู้ที่ไม่ใช่นักพัฒนาสามารถสร้างแอปพลิเคชันที่เรียบง่ายได้ พวกเขาร่วมกันจัดการกับช่องว่างการส่งมอบซอฟต์แวร์จากมุมที่ต่างกัน

## สรุป
แพลตฟอร์มที่ใช้โค้ดน้อยและแพลตฟอร์มสำหรับนักพัฒนาภายในมีเป้าหมายเพื่อเพิ่มจำนวนคนที่สามารถส่งมอบซอฟต์แวร์ได้ Low-code ทำสิ่งนี้โดยการสรุปโค้ดออกไปทั้งหมด — ตัวสร้างภาพ, ตัวเชื่อมต่อที่สร้างไว้ล่วงหน้า, ลอจิกที่ประกาศ วิศวกรรมแพลตฟอร์มทำสิ่งนี้ให้กับนักพัฒนามืออาชีพโดยมอบโครงสร้างพื้นฐานแบบบริการตนเอง เส้นทางทอง และเครื่องมือที่ได้มาตรฐาน เพื่อให้พวกเขาใช้เวลาน้อยลงในการทำงานและมีเวลามากขึ้นกับฟีเจอร์ของผลิตภัณฑ์ ข้อดีอีกอย่างก็คือ low-code มีการล็อคอินจากผู้จำหน่ายและข้อจำกัดด้านประสิทธิภาพ และวิศวกรรมแพลตฟอร์มจำเป็นต้องมีการลงทุนอย่างต่อเนื่องเพื่อรักษา แต่เมื่อนำไปใช้กับปัญหาที่ถูกต้อง เช่น เครื่องมือภายใน แอป CRUD การให้บริการที่ได้มาตรฐาน ทั้งสองอย่างนี้สามารถลดเวลาจากแนวคิดไปสู่การผลิตได้อย่างมาก
