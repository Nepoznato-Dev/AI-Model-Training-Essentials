# ระบบฝังตัวและ IoT
ระบบฝังตัวคือคอมพิวเตอร์ที่ซ่อนอยู่ในอุปกรณ์อื่นๆ เช่น หน่วยควบคุมเครื่องยนต์ของรถ ตัวควบคุมเครื่องซักผ้า ไมโครคอนโทรลเลอร์ในเทอร์โมสตัทอัจฉริยะ ต่างจากคอมพิวเตอร์ทั่วไปตรงที่ได้รับการออกแบบมาสำหรับงานเฉพาะ ซึ่งมักมีข้อจำกัดด้านพลังงาน หน่วยความจำ และความเร็วในการประมวลผลที่เข้มงวด Internet of Things (IoT) ขยายระบบฝังตัวโดยเชื่อมต่อกับเครือข่าย ทำให้สามารถตรวจสอบ การควบคุม และรวบรวมข้อมูลจากระยะไกลได้ เมื่อรวมกันแล้วจะเป็นตัวแทนของอุปกรณ์คอมพิวเตอร์หลายพันล้านเครื่องที่มีการโต้ตอบกับโลกทางกายภาพ
---

## พื้นฐานระบบสมองกลฝังตัว
### อะไรทำให้การฝังตัวแตกต่าง
| ด้าน | คอมพิวเตอร์เอนกประสงค์ | ระบบฝังตัว |
|--------|------------------------|-----------------|
| **วัตถุประสงค์** | เรียกใช้ซอฟต์แวร์ใด ๆ | ปฏิบัติงานเฉพาะ |
| **แหล่งข้อมูล** | CPU, RAM, ที่เก็บข้อมูลมากมาย | จำกัด (KB เป็น MB ของ RAM; MHz ถึง GHz ต่ำ) |
| **พลัง** | เสียบปลั๊กหรือแบตเตอรี่ขนาดใหญ่ | มักจะใช้พลังงานจากแบตเตอรี่หรือเก็บเกี่ยวพลังงาน |
| **ระบบปฏิบัติการ** | ระบบปฏิบัติการเต็ม (Windows, Linux, macOS) | RTOS, Bare-Metal หรือ Linux แบบฝัง |
| **ส่วนติดต่อผู้ใช้** | ริช (จอ, คีย์บอร์ด, เมาส์) | น้อยที่สุด (ไฟ LED, ปุ่ม, เซ็นเซอร์) หรือไม่มีเลย |
| **เรียลไทม์** | พยายามอย่างดีที่สุด | มักจะกำหนดเวลาเรียลไทม์อย่างหนัก |
| **อายุการใช้งาน** | 3-7 ปี | 10-25+ ปี |
### ไมโครคอนโทรลเลอร์กับไมโครโปรเซสเซอร์
| คุณสมบัติ | ไมโครคอนโทรลเลอร์ (MCU) | ไมโครโปรเซสเซอร์ (MPU) |
|---------|----------------------|---------------------|
| **บูรณาการ** | CPU + RAM + Flash + อุปกรณ์ต่อพ่วงในชิปตัวเดียว | ซีพียูเท่านั้น RAM ภายนอกและที่เก็บข้อมูล |
| **ประสิทธิภาพ** | ต่ำถึงปานกลาง (ช่วง MHz) | สูง (ช่วง GHz) |
| **พลัง** | ต่ำมาก (µA ถึง mA) | สูงกว่า (หลายร้อย mA ถึงแอมป์) |
| **ราคา** | $0.10 - $10 | $5 - $100+ |
| **ตัวอย่าง** | STM32, ESP32, Arduino (ATmega), nRF52 | Raspberry Pi (BCM2835), i.MX, Allwinner |
| **กรณีการใช้งาน** | เซ็นเซอร์ แอคทูเอเตอร์ ควบคุมง่าย | จอแสดงผล, การประมวลผลที่ซับซ้อน, Linux |

## แพลตฟอร์มฝังตัวทั่วไป
| แพลตฟอร์ม | MCU/MPU | คุณสมบัติที่สำคัญ | ดีที่สุดสำหรับ |
|----------|---------|-------------|----------|
| **อาร์ดูโน** | ATmega328P (และอื่นๆ) | เรียบง่าย; ชุมชนขนาดใหญ่ | การเรียนรู้; การสร้างต้นแบบ |
| **ESP32** | Espressif แบบดูอัลคอร์ | Wi-Fi + บลูทูธ; ต้นทุนต่ำ | โครงการไอโอที อุปกรณ์ที่เชื่อมต่อ |
| **ราสเบอร์รี่ ไพ พิโก** | RP2040 (ARM ดูอัลคอร์) | ซื้อได้; รองรับ MicroPython | การศึกษา; โครงการงานอดิเรก |
| **STM32** | ซีรีส์ ARM Cortex-M | เกรดอุตสาหกรรม หลากหลาย | มืออาชีพฝังตัว; อุตสาหกรรม |
| **nRF52/nRF53** | นอร์ดิกเซมิคอนดักเตอร์ | ผู้เชี่ยวชาญด้านบลูทูธพลังงานต่ำ | อุปกรณ์สวมใส่; บีคอน |
| **ราสเบอร์รี่พาย** | Broadcom BCM (แขน) | ลินุกซ์เต็ม; หมุด GPIO | การสร้างต้นแบบ; ศูนย์สื่อ การประมวลผลขอบแสง |
| **บีเกิ้ลโบน** | ทีไอ สิตารา (ARM) | แกน PRU แบบเรียลไทม์ | ทางอุตสาหกรรม; แอปพลิเคชั่นแบบเรียลไทม์ |
| **ESP32-S3** | เอสเพรสซิฟ | การเร่งความเร็วของ AI; ยูเอสบี | ขอบ AI; แอพพลิเคชั่นการมองเห็น |

## ระบบปฏิบัติการเรียลไทม์ (RTOS)
RTOS รับประกันว่างานที่สำคัญจะเสร็จสิ้นภายในกรอบเวลาที่กำหนด
| RTOS | ใบอนุญาต | ดีที่สุดสำหรับ |
|------|---------|----------|
| **RTOS ฟรี** | เอ็มไอที | พบมากที่สุด; รองรับ MCU แบบกว้าง |
| **เซเฟอร์** | อาปาเช่ 2.0 | ทันสมัย; มูลนิธิลินุกซ์; ระบบนิเวศที่กำลังเติบโต |
| **ThreadX (Azure RTOS)** | เอ็มไอที | ได้รับการรับรองความปลอดภัย; ไอโอที |
| **embos** | เชิงพาณิชย์ | ทางอุตสาหกรรม; ได้รับการรับรอง |
| **RT-Thread** | อาปาเช่ 2.0 | ระบบนิเวศของจีน เติบโตทั่วโลก |
### RTOS กับ Bare Metal
| ด้าน | โลหะเปลือย | RTOS |
|--------|-----------|-------|
| **ความซับซ้อน** | ง่ายสำหรับงานง่ายๆ | จำเป็นสำหรับงานที่ซับซ้อนและเกิดขึ้นพร้อมกัน |
| **กำหนดการ** | แบบแมนนวล (ลูปหลัก + การขัดจังหวะ) | การกำหนดเวลาล่วงหน้าพร้อมลำดับความสำคัญ |
| **ความสามารถในการปรับขนาด** | เพิ่มฟีเจอร์ยาก | เพิ่มงานง่ายๆ |
| **ความทรงจำ** | ค่าใช้จ่ายน้อยที่สุด | ค่าใช้จ่ายเล็กน้อย (ไม่กี่ KB) |

## โปรโตคอลการสื่อสาร
### โปรโตคอลแบบมีสาย
| โปรโตคอล | ความเร็ว | ระยะทาง | ใช้กรณี |
|---------||-------|----------|----------|
| **UART** | สูงสุด 1 Mbps | สั้น (ออนบอร์ด) | คอนโซลดีบัก โมดูล GPS |
| **เอสพีไอ** | สูงถึง 100 MHz | สั้น (ออนบอร์ด) | อุปกรณ์ต่อพ่วงความเร็วสูง (จอแสดงผล, แฟลช) |
| **ไอทูซี** | สูงสุด 3.4 MHz | สั้น (ออนบอร์ด) | เซ็นเซอร์; การสื่อสารจำนวนพินต่ำ |
| **สามารถ** | สูงสุด 1 Mbps | สูงสุด 1 กม. | ยานยนต์; อุตสาหกรรม |
| **อีเธอร์เน็ต** | 10 Mbps - 100 Gbps | สูงถึง 100 ม. | ระบบเครือข่าย; อุตสาหกรรม (พร้อมส่วนขยาย) |
| **ยูเอสบี** | สูงสุด 40 Gbps (USB4) | สูงถึง 5 ม. | อุปกรณ์ต่อพ่วง; กำลังชาร์จ |
### โปรโตคอลไร้สาย
| โปรโตคอล | พิสัย | พลังงาน | ความเร็ว | ใช้กรณี |
|----------|-------|-------|-------|----------|
| **ไวไฟ** | ~100 ม. | สูง | สูงสุด Wi-Fi 7 (ตามทฤษฎี 46 Gbps) | IoT แบนด์วิธสูง สตรีมมิ่ง |
| **บลูทูธคลาสสิก** | ~100 ม. | ปานกลาง | 1-3 Mbps | เสียง; การถ่ายโอนไฟล์ |
| **BLE** (บลูทูธพลังงานต่ำ) | ~100 ม. | ต่ำมาก | 1-2 Mbps | อุปกรณ์สวมใส่; บีคอน; เซ็นเซอร์ |
| **ซิกบี** | ~100 ม. (ตาข่าย) | ต่ำ | 250 กิโลบิตต่อวินาที | ระบบอัตโนมัติในบ้าน เซ็นเซอร์อุตสาหกรรม |
| **ซี-เวฟ** | ~100 ม. (ตาข่าย) | ต่ำ | 100 กิโลบิตต่อวินาที | ระบบอัตโนมัติในบ้าน |
| **โลรา / โลราวัน** | สูงสุด 15 กม. | ต่ำมาก | 0.3-50 กิโลบิตต่อวินาที | เกษตรกรรม; สาธารณูปโภค; เซ็นเซอร์ทั่วเมือง |
| **NB-IoT** | ความคุ้มครองเซลลูล่าร์ | ต่ำ | 250 กิโลบิตต่อวินาที | การวัดแสง; การติดตามทรัพย์สิน |
| **กระทู้/เรื่อง** | ~100 ม. (ตาข่าย) | ต่ำ | ปานกลาง | บ้านอัจฉริยะ (Apple, Google, Amazon) |
| **เซลลูลาร์ (4G/5G)** | ทั่วโลก | สูง | สูง | ยานพาหนะที่เชื่อมต่อ; การตรวจสอบระยะไกล |

## สถาปัตยกรรม IoT
### กอง IoT
| เลเยอร์ | ฟังก์ชัน | ตัวอย่าง |
|-------|----------|---------|
| **อุปกรณ์** | เซนเซอร์ แอคทูเอเตอร์ ไมโครคอนโทรลเลอร์ | ESP32, STM32, ราสเบอร์รี่ Pi |
| **การเชื่อมต่อ** | โปรโตคอลเครือข่าย | MQTT, HTTP, CoAP, LoRaWAN |
| **การประมวลผลแบบ Edge** | กำลังประมวลผลใกล้กับอุปกรณ์ | AWS Greengrass, Azure IoT Edge |
| **แพลตฟอร์มคลาวด์** | การนำเข้าข้อมูล การจัดเก็บ การประมวลผล | AWS IoT, ฮับ Azure IoT, Google Cloud IoT |
| **ใบสมัคร** | แดชบอร์ด การวิเคราะห์ การแจ้งเตือน | Grafana เว็บแอปแบบกำหนดเอง |
### โปรโตคอลการสื่อสาร IoT
| โปรโตคอล | รูปแบบ | ดีที่สุดสำหรับ |
|----------|---------|----------|
| **MQTT** | เผยแพร่/สมัครสมาชิก; น้ำหนักเบา | แอปพลิเคชัน IoT ส่วนใหญ่ แบนด์วิธต่ำ |
| **HTTP/ส่วนที่เหลือ** | คำขอ/ตอบกลับ | เมื่อความเรียบง่ายมีความสำคัญ บูรณาการเว็บ |
| **สหกรณ์ฯ** | คำขอ/การตอบกลับ; อิง UDP | อุปกรณ์ที่มีข้อจำกัด พลังงานต่ำ |
| **AMQP** | คิวข้อความ | IoT ระดับองค์กร; การจัดส่งที่เชื่อถือได้ |
| **เว็บซ็อกเก็ต** | แบบสองทิศทาง; การเชื่อมต่อแบบถาวร | แดชบอร์ดแบบเรียลไทม์ ข้อมูลสด |
### MQTT โดยละเอียด
| แนวคิด | คำอธิบาย |
|---------|-------------|
| **นายหน้า** | เซิร์ฟเวอร์กลางที่กำหนดเส้นทางข้อความ (Mosquitto, EMQX, HiveMQ) |
| **หัวข้อ** | ที่อยู่แบบลำดับชั้น (เช่น`home/living-room/temperature`) |
| **QoS** | 0 (มากที่สุดหนึ่งครั้ง), 1 (อย่างน้อยหนึ่งครั้ง), 2 (หนึ่งครั้งพอดี) |
| **ข้อความที่เก็บไว้** | ข้อความสุดท้ายในหัวข้อ ส่งมอบให้กับสมาชิกใหม่ |
| **พินัยกรรมสุดท้าย** | ข้อความเผยแพร่เมื่อไคลเอ็นต์ยกเลิกการเชื่อมต่อโดยไม่คาดคิด |

## เอดจ์คอมพิวเตอร์
ประมวลผลข้อมูลใกล้ต้นทางแทนที่จะส่งทุกอย่างไปยังคลาวด์
| ผลประโยชน์ | คำอธิบาย |
|---------|-------------|
| **ลดเวลาแฝง** | ไม่มีการเดินทางไปกลับสู่คลาวด์ การตัดสินใจทันที |
| **ประหยัดแบนด์วิธ** | ส่งเฉพาะข้อมูลสรุปหรือความผิดปกติ |
| **ความเป็นส่วนตัว** | ข้อมูลที่ละเอียดอ่อนจะยังคงอยู่ในองค์กร |
| **ความน่าเชื่อถือ** | ใช้งานได้เมื่ออินเทอร์เน็ตล่ม |
| แพลตฟอร์ม | คำอธิบาย |
|----------|-------------|
| **AWS Greengrass** | เรียกใช้ฟังก์ชัน Lambda บนอุปกรณ์ Edge |
| **Azure IoT Edge** | เรียกใช้คอนเทนเนอร์บนอุปกรณ์ Edge |
| **NVIDIA Jetson** | AI ขอบที่เร่งด้วย GPU (Orin, Nano) |
| **ราสเบอร์รี่พาย** | การประมวลผลแบบ Edge น้ำหนักเบา |

## อัพเดตเฟิร์มแวร์ (OTA)
การอัปเดตแบบ over-the-air ช่วยให้คุณสามารถแก้ไขข้อบกพร่องและเพิ่มคุณสมบัติต่างๆ ให้กับอุปกรณ์ที่ใช้งาน
| ความกังวล | โซลูชั่น |
|---------|----------|
| **ความน่าเชื่อถือ** | แฟลชสองธนาคาร; ย้อนกลับเมื่อล้มเหลว |
| **ความปลอดภัย** | ภาพที่ลงนาม; การถ่ายโอนที่เข้ารหัส |
| **ขนาด** | การอัปเดตเดลต้า (เฉพาะส่วนที่เปลี่ยนแปลง) |
| **การเชื่อมต่อ** | อัปเดตคิวเมื่ออุปกรณ์ออนไลน์ |

## เครื่องมือและการพัฒนา
| เครื่องมือ | วัตถุประสงค์ |
|------|---------|
| **แพลตฟอร์มIO** | การพัฒนาแบบฝังตัวข้ามแพลตฟอร์ม (Arduino, ESP32, STM32) |
| **STM32CubeIDE** | IDE อย่างเป็นทางการของ ST สำหรับ STM32 |
| **Arduino IDE** | การพัฒนาอย่างง่ายสำหรับ Arduino และบอร์ดที่เข้ากันได้ |
| **ESP-IDF** | SDK อย่างเป็นทางการของ Espressif สำหรับ ESP32 |
| **Zephyr SDK** | ระบบสร้างตะวันตกสำหรับ Zephyr RTOS |
| **OpenOCD** | การดีบักบนชิป |
| **ตัววิเคราะห์ลอจิก** | ดีบักโปรโตคอล SPI, I²C, UART |
| **ไวร์ชาร์ค** | การวิเคราะห์โปรโตคอลเครือข่าย |

## สรุป
ระบบสมองกลฝังตัวและ IoT เป็นจุดตัดกันของซอฟต์แวร์และโลกทางกายภาพ ตั้งแต่ไมโครคอนโทรลเลอร์ที่ควบคุมมอเตอร์ไปจนถึงเครือข่ายเซ็นเซอร์ที่เชื่อมต่อกับคลาวด์ พวกเขาต้องการแนวคิดที่แตกต่างจากการพัฒนาเว็บหรือแอป เช่น ทรัพยากรที่มีข้อจำกัด ข้อกำหนดแบบเรียลไทม์ อายุการใช้งานที่ยาวนาน และผลที่ตามมาจากข้อบกพร่องในโลกกายภาพ ระบบนิเวศได้รับการพัฒนาอย่างมหาศาล เฟรมเวิร์กเช่น ESP-IDF และ Zephyr ทำให้สามารถเข้าถึงการพัฒนาระดับมืออาชีพได้ ในขณะที่แพลตฟอร์มอย่าง AWS IoT และ Azure IoT Hub จัดการด้านคลาวด์ ทักษะสำคัญคือการทำความเข้าใจอินเทอร์เฟซฮาร์ดแวร์ โปรโตคอลการสื่อสาร การจัดการพลังงาน และวินัยในการเขียนซอฟต์แวร์ที่ต้องทำงานได้อย่างน่าเชื่อถือเป็นเวลาหลายปีโดยไม่มีการแทรกแซง
