# Структуры данных и алгоритмы
Структуры данных — это способы организации данных в памяти, чтобы операции над ними были эффективными. Алгоритмы — это пошаговые процедуры решения проблем. Вместе они составляют основу информатики — каждая программа, которую вы когда-либо использовали, опирается на них. Выбор правильной структуры данных может превратить невероятно медленную программу в быструю, а знание правильного алгоритма может превратить неразрешимую проблему в тривиальную.

## Фундаментальные структуры данных
### Линейные структуры
| Структура | Доступ | Поиск | Вставить | Удалить | Вариант использования |
|-----------|--------|--------|--------|--------|----------|
| **Массив** | O(1) по индексу | О(п) | О(п) | О(п) | Коллекции фиксированного размера; произвольный доступ |
| **Связанный список** | О(п) | О(п) | O(1) в начале | O(1) в начале | Динамический размер; вставки/удаления |
| **Стек** | О(п) | О(п) | O(1) нажатие/выталкивание | О(1) поп | Вызовы функций; отменить; анализ |
| **Очередь** | О(п) | О(п) | O(1) очередь | O(1) удаление из очереди | Планирование задач; БФС; очереди сообщений |
| **Деке** | O(1) на обоих концах | О(п) | O(1) на обоих концах | O(1) на обоих концах | Раздвижное окно; воровство работы |
### Структуры на основе хеша
| Структура | Поиск | Вставить | Удалить | Вариант использования |
|-----------|--------|--------|--------|----------|
| **Хеш-таблица** | O(1) среднее | O(1) среднее | O(1) среднее | Поиск по ключу-значению; тайники; наборы |
| **Хеш-набор** | О(1) | О(1) | О(1) | Тестирование членства; дедупликация |
**Конфликты хешей**: когда два ключа хешируются в одном и том же слоте, они сохраняются в связанном списке (цепочка) или в следующем доступном слоте (открытая адресация). Хорошие хэш-функции минимизируют коллизии.
### Древовидные структуры
| Структура | Поиск | Вставить | Удалить | Вариант использования |
|-----------|--------|--------|--------|----------|
| **Двоичное дерево поиска** | O(log n) среднее | O(журнал n) | O(журнал n) | Сортированные данные; диапазон запросов |
| **АВЛ / Красно-черное дерево** | O(log n) гарантировано | O(журнал n) | O(журнал n) | Самобалансирующийся; используется в картах/наборах |
| **B-Дерево / B+ Дерево** | O(журнал n) | O(журнал n) | O(журнал n) | Индексы базы данных; файловые системы |
| **Три** | O(k), где k = длина ключа | О(к) | О(к) | Автозаполнение; сопоставление префиксов |
| **Куча (двоичная)** | О(п) | O(журнал n) | O(журнал n) | Приоритетные очереди; планирование |
### Представления графов
| Представительство | Космос | Поиск края | Добавить край | Итерация соседей |
|---------------|-------|-------------|----------|-------------------|
| **Матрица смежности** | О(В²) | О(1) | О(1) | О(В) |
| **Список смежности** | О(В + Е) | О(степень) | О(1) | О(степень) |
| **Список краев** | О(Е) | О(Е) | О(1) | О(Е) |

## Сложность алгоритма (Big-O)
Обозначение Big-O описывает, как требования алгоритма к времени или пространству растут по мере увеличения размера входных данных.
| Сложность | Имя | Пример |
|-----------|------|---------|
| **О(1)** | Константа | Поиск по хэш-таблице; доступ к массиву по индексу |
| **O(log n)** | Логарифмический | Бинарный поиск; сбалансированные древовидные операции |
| **О(н)** | Линейный | Линейный поиск; итерация массива |
| **O(n log n)** | Линеарифмический | Сортировка слиянием; пирамидальная сортировка; наиболее эффективные сорта общего назначения |
| **О(n²)** | Квадратичный | Пузырьковая сортировка; вложенные циклы над одними и теми же данными |
| **О(2^n)** | Экспоненциальный | Генерация подмножества методом грубой силы; наивная рекурсия Фибоначчи |
| **О(н!)** | Факториал | Коммивояжер (грубая сила); перестановки |
### Распространенные заблуждения
| Заблуждение | Реальность |
|--------------|---------|
| «O(n) всегда быстрее, чем O(n²)» | Для малых n постоянный коэффициент имеет большее значение |
| «Нижний Биг-О всегда лучше» | Существуют компромиссы между пространством и временем; Поиск O(1) использует память O(n) |
| «Большой-О скажет вам точную скорость» | Он описывает темпы роста, а не абсолютное время |

## Алгоритмы сортировки
| Алгоритм | Лучшее | Средний | Худшее | Космос | Стабильный | На месте |
|-----------|------|---------|-------|-------|--------|----------|
| **Пузырьковая сортировка** | О(п) | О(n²) | О(n²) | О(1) | Да | Да |
| **Сортировка вставками** | О(п) | О(n²) | О(n²) | О(1) | Да | Да |
| **Сортировка выбором** | О(n²) | О(n²) | О(n²) | О(1) | Нет | Да |
| **Сортировка слиянием** | O(n log n) | O(n log n) | O(n log n) | О(п) | Да | Нет |
| **Быстрая сортировка** | O(n log n) | O(n log n) | О(n²) | O(журнал n) | Нет | Да |
| **Кучная сортировка** | O(n log n) | O(n log n) | O(n log n) | О(1) | Нет | Да |
| **Тим Сорт** | О(п) | O(n log n) | O(n log n) | О(п) | Да | Нет |
**Практический совет**: используйте встроенную в ваш язык сортировку (`sorted()` в Python,`Array.sort()`в JavaScript). Они используют высокооптимизированные алгоритмы (Tim Sort, Introsort), которые обрабатывают все крайние случаи.

## Алгоритмы поиска
| Алгоритм | Структура данных | Сложность | Требование |
|-----------|---------------|-----------|-------------|
| **Линейный поиск** | Любой | О(п) | Нет |
| **Двоичный поиск** | Сортированный массив | O(журнал n) | Данные должны быть отсортированы |
| **Поиск хэш-таблицы** | Хэш-таблица | O(1) среднее | Хорошая хеш-функция |
| **BFS** (поиск в ширину) | Граф/дерево | О(В + Е) | Невзвешенный кратчайший путь |
| **DFS** (поиск в глубину) | Граф/дерево | О(В + Е) | Поиск пути; обнаружение цикла |
| **Дейкстра** | Взвешенный график | O((V + E) log V) | Неотрицательные веса; кратчайший путь |
| **A* Поиск** | Взвешенный график | O((V + E) log V) | Эвристически управляемый; оптимальный с допустимой эвристикой |

## Ключевые шаблоны алгоритмов
| Узор | Описание | Примеры задач |
|---------|-------------|-----------------|
| **Разделяй и властвуй** | Разделить проблему на подзадачи; решить рекурсивно; объединить | Сортировка слиянием; быстрая сортировка; бинарный поиск |
| **Динамическое программирование** | Разбейте перекрывающиеся подзадачи; результаты кэширования | Фибоначчи; рюкзак; самая длинная общая подпоследовательность |
| **Жадный** | Делайте локально оптимальный выбор на каждом шаге | Дейкстры; кодирование Хаффмана; выбор деятельности |
| **Возврат** | Попробуйте возможности; отменить неправильный выбор; попробовать альтернативы | решатель судоку; N-ферзей; перестановки |
| **Раздвижное окно** | Поддерживать окно элементов; проведите им по данным | Подмассив максимальной суммы размера K; самая длинная подстрока без повторов |
| **Два указателя** | Используйте два указателя, движущихся навстречу друг другу или в одном направлении | Парная сумма в отсортированном массиве; удалить дубликаты |
| **Двоичный поиск по ответу** | Бинарный поиск в пространстве ответов | Выделите минимум страниц; агрессивные коровы |

## Когда что использовать
| Проблема | Структура данных | Алгоритм |
|---------|---------------|-----------|
| Быстрый поиск значений ключа | Хэш-таблица/словарь | Хеширование |
| Поддерживать отсортированный порядок | Сбалансированный BST (TreeMap, std::set) | Операции с деревьями |
| Приоритетная обработка | Куча/очередь с приоритетом | Операции с кучей |
| Кратчайший путь (невзвешенный) | Граф (список смежности) | БФС |
| Кратчайший путь (взвешенный) | Граф (список смежности) | Дейкстры / А* |
| Тестирование членства | Хэш-набор/фильтр Блума | Хеширование |
| Соответствие префиксов | Трие | Три обход |
| Диапазон запросов | Дерево отрезков/дерево Фенвика | Операции с деревьями |
| LRU-кэш | Хэш-карта + двусвязный список | Комбинированные операции |
| Подключенные компоненты | Объединение непересекающихся множеств (Union-Find) | Союз и находка |

## Краткое содержание
Структуры данных и алгоритмы — это не просто темы для собеседований — они являются строительными блоками эффективного программного обеспечения. Массивы и хеш-таблицы решают большинство повседневных задач. Деревья и графики обрабатывают иерархические и реляционные данные. Сортировка и поиск — это решенные проблемы в стандартных библиотеках. Алгоритмические шаблоны — «разделяй и властвуй», динамическое программирование, жадный подход, возврат с возвратом — являются стратегиями многократного использования для решения новых проблем. Ключевой навык — не запоминание алгоритмов; это определение того, какой шаблон соответствует данной проблеме, и выбор правильной структуры данных для работы.
