# Системы баз данных
## Основы базы данных
### Что такое база данных?
База данных — это организованный набор структурированной информации, хранящейся в электронном виде и предназначенный для эффективного поиска, вставки, обновления и удаления данных.
### Системы управления базами данных (СУБД)
Программное обеспечение, которое взаимодействует с конечными пользователями, приложениями и самой базой данных для сбора и анализа данных. Примеры: MySQL, PostgreSQL, Oracle, MongoDB.
### Ключевые понятия
- **Схема**: структура/организация базы данных (таблицы, поля, связи).
- **Экземпляр**: фактические данные, сохраненные в определенный момент.
- **Свойства кислоты**: атомарность, консистенция, изоляция, долговечность.
- **Теорема CAP**: согласованность, доступность, устойчивость к разделению (выберите 2)
- **Нормализация**: организация данных для уменьшения избыточности.
- **Денормализация**: добавление избыточности для повышения производительности чтения.
## Реляционные базы данных (SQL)
### Основные понятия
- **Таблицы**: строки (записи) и столбцы (поля).
- **Первичный ключ**: уникальный идентификатор для каждой строки.
- **Внешний ключ**: ссылка на первичный ключ в другой таблице.
- **Индексы**: структуры данных повышают скорость запросов.
- **Представления**: виртуальные таблицы на основе результатов запроса.
- **Хранимые процедуры**: предварительно скомпилированные блоки кода SQL.
- **Триггеры**: автоматические действия при изменении данных.
### SQL-операции (CRUD)```sql
-- Create
INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com');

-- Read
SELECT * FROM users WHERE id = 1;
SELECT name, email FROM users ORDER BY name LIMIT 10;

-- Update
UPDATE users SET email = 'new@example.com' WHERE id = 1;

-- Delete
DELETE FROM users WHERE id = 1;
```

### Присоединяется
- **INNER JOIN**: возвращает совпадающие строки из обеих таблиц.
- **LEFT JOIN**: все строки из левой таблицы, совпадения справа.
- **ПРАВОЕ СОЕДИНЕНИЕ**: все строки из правой таблицы, совпадения слева.
- **FULL OUTER JOIN**: все строки из обеих таблиц.
- **CROSS JOIN**: декартово произведение обеих таблиц.
- **SELF JOIN**: таблица соединена сама с собой.
### Формы нормализации
- **1NF**: атомарные значения, без повторяющихся групп.
- **2NF**: 1NF + нет частичных зависимостей (все неключевые атрибуты зависят от всего первичного ключа)
- **3NF**: 2NF + отсутствие транзитивных зависимостей (неключевые атрибуты не зависят от других неключевых атрибутов)
- **BCNF**: более сильная 3NF, каждый детерминант является потенциальным ключом.
- **4NF**: нет многозначных зависимостей.
- **5NF**: нет зависимостей объединения.
### Популярные СУБД
- **PostgreSQL**: расширенные функции, расширяемость, совместимость с ACID.
- **MySQL**: широко используемые, быстро читаемые веб-приложения.
- **Oracle**: корпоративные функции, масштабируемость, высокая стоимость.
- **SQL Server**: экосистема Microsoft, интегрированные инструменты.
- **SQLite**: встроенный, бессерверный, легкий.
- **MariaDB**: форк MySQL, с открытым исходным кодом.
## Базы данных NoSQL
### Типы баз данных NoSQL
#### Хранилища документов
- **Структура**: документы в формате JSON (BSON).
- **Примеры использования**: управление контентом, каталоги, профили пользователей.
- **Примеры**: MongoDB, CouchDB, DocumentDB.
- **Пример запроса** (MongoDB):```javascript
db.users.find({ age: { $gt: 25 } }).sort({ name: 1 });
```

#### Хранилища ключей-значений
– **Структура**: простые пары «ключ-значение».
- **Примеры использования**: кеширование, сеансы, корзины покупок.
- **Примеры**: Redis, DynamoDB, Riak.
- **Характеристики**: быстрый, простой, ограниченный запрос.
#### Колонно-семейные магазины
– **Структура**: столбцы сгруппированы в семейства.
- **Примеры использования**: большие данные, аналитика, временные ряды.
- **Примеры**: Cassandra, HBase, ScyllaDB.
- **Характеристики**: оптимизированный для записи, распределенный, масштабируемый.
#### Графовые базы данных
- **Структура**: узлы, ребра, свойства.
- **Примеры использования**: социальные сети, обнаружение мошенничества, рекомендации.
- **Примеры**: Neo4j, Amazon Neptune, ArangoDB.
- **Язык запросов**: Cypher (Neo4j), Gremlin
### Когда использовать NoSQL
- Гибкая/развивающаяся схема
- Требования к горизонтальному масштабированию
- Высокая пропускная способность записи
- Иерархические/вложенные данные
- Распределенные системы
- Приложения реального времени
## Проектирование базы данных
### Моделирование сущностей и связей
- **Сущности**: объекты/концепции (Клиент, Продукт, Заказ).
- **Атрибуты**: свойства объектов (название, цена, дата).
- **Отношения**: связи между объектами (один-к-одному, один-ко-многим, многие-ко-многим).
- **Кардинальность**: количество экземпляров, связанных между собой.
### Шаблоны проектирования схем
- **Наследование одной таблицы**: все типы в одной таблице с дискриминатором типов.
- **Наследование таблицы классов**: отдельные таблицы для базовых и подклассов.
- **Наследование конкретной таблицы**: отдельная таблица для каждого конкретного класса.
- **Соединительные таблицы**: разрешение отношений «многие ко многим».
- **Таблицы аудита**: отслеживание изменений (создано_at, обновлено_at, удалено_at).
### Стратегии индексирования
- **B-дерево**: по умолчанию, запросы по диапазону, сортировка.
- **Хеш**: поиск точного совпадения.
- **Растровое изображение**: столбцы с низкой мощностью (пол, статус).
- **Полнотекстовый**: возможности текстового поиска.
- **Пространственные**: географические данные (ГИС).
- **Композитный**: объединение нескольких столбцов.
– **Покрытие**: включает все столбцы, необходимые для запроса.
## Оптимизация запросов
### Планы выполнения
- Понимание того, как база данных выполняет запросы.
- Выявление узких мест (полное сканирование таблицы, отсутствующие индексы)
- Инструменты: ОБЪЯСНИТЬ, ОБЪЯСНИТЬ, АНАЛИЗИРОВАТЬ.
### Методы оптимизации
- **Использование индекса**: убедитесь, что в запросах используются соответствующие индексы.
- **Переписывание запросов**: упрощение сложных запросов.
- **Оптимизация соединений**: выберите правильные типы и порядок соединений.
- **Разделение**: разделение больших таблиц (диапазон, хэш, список).
- **Материализованные представления**: предварительно вычисленные результаты запроса.
- **Кэширование запросов**: сохраняйте результаты частых запросов.
### Распространенные проблемы с производительностью
- **Проблема запроса N+1**: неэффективное получение связанных данных.
- **Отсутствующие индексы**: полное сканирование больших таблиц.
- **Чрезмерная индексация**: медленная запись из-за слишком большого количества индексов.
- **Конфликт за блокировку**: транзакции, ожидающие блокировки.
- **Неэффективные запросы**: SELECT *, ненужные соединения.
## Транзакции и параллелизм
### Уровни изоляции транзакций
- **READ UNCOMMITTED**: самая низкая изоляция, возможно грязное чтение.
- **READ COMMITTED**: видны только зафиксированные данные (по умолчанию в большинстве БД).
- **ПОВТОРИМОЕ ЧТЕНИЕ**: тот же запрос возвращает те же результаты в транзакции.
- **SERIALIZABLE**: высочайшая изоляция, транзакции выполняются последовательно.
### Управление параллелизмом
- **Пессимистическая блокировка**: блокируйте ресурсы перед доступом.
- **Оптимистическая блокировка**: проверьте версию перед фиксацией.
- **MVCC (управление многоверсионным параллелизмом)**: поддержка нескольких версий строк.
- **Блокировка на уровне строк**: блокировка определенных строк.
- **Блокировка на уровне таблицы**: блокировка всей таблицы.
### Тупики
- Циклическая зависимость, при которой транзакции ждут друг друга
- Предотвращение: согласованный порядок блокировок, тайм-ауты, обнаружение взаимоблокировок.
- Решение: прервать одну транзакцию.
## Репликация и масштабирование
### Типы репликации
- **Master-Slave**: одна первичная, несколько реплик чтения.
- **Мастер-Мастер**: несколько первичных серверов, двунаправленная репликация.
- **Мульти-мастер**: N праймериз, необходимо разрешение конфликтов
- **Цепная репликация**: последовательная репликация через узлы.
### Подходы к масштабированию
- **Вертикальное масштабирование**: увеличение ресурсов сервера (ЦП, ОЗУ, хранилище).
- **Горизонтальное масштабирование**: добавление дополнительных серверов (шардинг, секционирование).
- **Реплики чтения**: разгрузка трафика чтения.
- **Шардинг**: разделение данных между серверами по ключу/диапазону/хешу.
- **Федерация**: разделение по функциям/услугам.
### Модели согласованности
- **Сильная согласованность**: все узлы видят одни и те же данные одновременно.
- **Возможная согласованность**: узлы сходятся во времени.
- **Причинно-следственная связь**: причинно-следственные связи сохранены.
- **Читайте свои записи**: пользователь сразу видит свои обновления.
## Резервное копирование и восстановление
### Стратегии резервного копирования
- **Полное резервное копирование**: полная копия базы данных.
- **Инкрементное резервное копирование**: изменения с момента последнего резервного копирования.
- **Дифференциальное резервное копирование**: изменения с момента последнего полного резервного копирования.
- **Восстановление на момент времени**: восстановление до определенного момента.
- **Непрерывное резервное копирование**: репликация в режиме реального времени для резервного копирования.
### Процедуры восстановления
- **RTO (целевое время восстановления)**: максимально допустимое время простоя.
- **RPO (Цель точки восстановления)**: максимально допустимая потеря данных.
- **План аварийного восстановления**: документированные процедуры на случай сбоев.
- **Тестирование**: регулярные тренировки по восстановлению.
## Безопасность
### Контроль доступа
- **Аутентификация**: проверка личности пользователя.
- **Авторизация**: предоставление разрешений (GRANT, REVOKE).
- **Роли**: групповые разрешения для упрощения управления.
- **Принцип наименьших привилегий**: минимально необходимый доступ.
### Защита данных
- **Шифрование при хранении**: шифрование хранящихся данных.
- **Шифрование при передаче**: TLS/SSL для соединений.
- **Маскирование**: скрытие конфиденциальных данных в непроизводственных целях.
- **Токенизация**: замена конфиденциальных данных токенами.
### Распространенные уязвимости
- **SQL-инъекция**: вредоносный SQL-код в пользовательском вводе.
- **Повышение привилегий**: получение несанкционированного доступа.
- **Журнал аудита**: отслеживайте все действия с базой данных.
- **Соответствие**: требованиям GDPR, HIPAA, PCI-DSS.
## Современные технологии баз данных
### Облачные базы данных
- **AWS**: RDS, Аврора, DynamoDB, Redshift.
- **Google Cloud**: Cloud SQL, Spanner, Bigtable, Firestore.
- **Azure**: база данных SQL, Cosmos DB, Synapse.
- **Преимущества**: управляемый сервис, автоматическое масштабирование, включая резервное копирование.
### Базы данных NewSQL
- Сочетание согласованности SQL с масштабируемостью NoSQL.
– **Примеры**: CockroachDB, TiDB, YugabyteDB, Google Spanner.
- **Функции**: Распределение, транзакции ACID, горизонтальное масштабирование.
### Базы данных временных рядов
- Оптимизирован для данных с метками времени.
- **Примеры**: InfluxDB, TimescaleDB, Prometheus.
- **Случаи использования**: Интернет вещей, мониторинг, финансовые данные.
### Векторные базы данных
- Хранение и запрос векторов внедрения.
- **Примеры**: сосновая шишка, мильвус, плетистый, Qdrant.
- **Примеры использования**: семантический поиск, системы рекомендаций, приложения искусственного интеллекта.
### Многомодельные базы данных
- Поддержка нескольких моделей данных в одной системе
- **Примеры**: ArangoDB, OrientDB, Azure Cosmos DB.
- **Преимущество**: гибкость без использования нескольких баз данных.
## ORM и доступ к данным
### Объектно-реляционное сопоставление
- **Цель**: Сопоставить таблицы базы данных с объектами программирования.
- **Популярные ORM**:
  — Python: SQLAlchemy, Django ORM, Peewee.
  - JavaScript: Sequelize, Prisma, TypeORM.
  - Java: спящий режим, JPA
  - Руби: ActiveRecord
  - .NET: Entity Framework
### Преимущества
- Абстракция от SQL
- Типовая безопасность
- Управление миграцией
- API построения запросов
### Недостатки
- Накладные расходы на производительность
- Сложные запросы сложнее писать
- Проблемы с запросами N+1
- Кривая обучения
