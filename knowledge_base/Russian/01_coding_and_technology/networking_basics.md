# Основы работы в сети
Практическое руководство для разработчиков и системных администраторов — основные понятия, протоколы, команды и устранение неполадок.
---

## Модель OSI (7 уровней)
Концептуальная основа для понимания сетевой коммуникации.
| Слой | Имя | Функция | Примеры протоколов |
|-------|------|----------|-------------------|
| 7 | Приложение | Услуги для конечных пользователей | HTTP, HTTPS, FTP, SMTP, DNS, SSH |
| 6 | Презентация | Форматирование данных, шифрование, сжатие | TLS, JPEG, ASCII |
| 5 | Сессия | Управление подключением | NetBIOS, RPC |
| 4 | Транспорт | Комплексная доставка, исправление ошибок, управление потоком | TCP, UDP |
| 3 | Сеть | Маршрутизация, адресация | IP, ICMP, OSPF, BGP |
| 2 | Канал передачи данных | Кадрирование, обнаружение ошибок, MAC-адреса | Ethernet, Wi-Fi, PPP |
| 1 | Физический | Необработанная передача битов | Кабели Ethernet, оптоволокно, радиоволны |
На практике для Интернета чаще используется **модель TCP/IP** (4 уровня: канал, Интернет, транспорт, приложение).

## IP-адресация
### IPv4
- 32-битный адрес, записанный четырьмя октетами:`192.168.1.1`
- Итого: ~4,3 миллиарда адресов (но на практике исчерпано).
### IPv6
- 128-битный адрес, записанный в шестнадцатеричном виде:`2001:0db8:85a3:0000:0000:8a2e:0370:7334`
- Всего: 2¹²⁸ адреса (практически бесконечно).
### Диапазоны частных IP-адресов (RFC 1918)
Их нельзя маршрутизировать в Интернете; используется внутри локальных сетей:
-`10.0.0.0/8`(10.0.0.0 – 10.255.255.255)
-`172.16.0.0/12`(172.16.0.0 – 172.31.255.255)
-`192.168.0.0/16`(192.168.0.0 – 192.168.255.255)
### CIDR-нотация
`192.168.1.0/24`означает, что первые 24 бита представляют собой префикс сети; последние 8 бит — это хосты. Он включает адреса от`192.168.1.0`до `192.168.1.255`.

## DNS (система доменных имен)
Сопоставляет доменные имена (например,`example.com`) с IP-адресами.
### Типы записей
| Тип | Цель |
|------|---------|
| **А** | Сопоставляет домен с адресом IPv4 |
| **АААА** | Сопоставляет домен с адресом IPv6 |
| **CNAME** | Псевдоним другого доменного имени |
| **МХ** | Сервер обмена почтой |
| **ТХТ** | Произвольный текст (SPF, DKIM, проверка) |
| **НС** | Сервер имен для домена |
| **СРВ** | Сервисная запись (например, для SIP) |
### Общие инструменты```bash
dig example.com            # DNS lookup (detailed)
nslookup example.com       # DNS lookup (simpler)
host example.com           # Quick lookup
dig -x 8.8.8.8             # Reverse lookup (IP to name)
```

## TCP против UDP
| Особенность | TCP | UDP |
|---------|-----|-----|
| Подключение | Ориентированное на соединение (рукопожатие) | Без соединения |
| Надежность | Гарантированная доставка, ретрансляция | Лучшее из возможного (пакеты могут отбрасываться) |
| Заказ | Сохраняет порядок | Нет гарантии заказа |
| Управление потоком | Да (скользящее окно) | Нет |
| Варианты использования | Интернет (HTTP), электронная почта, SSH, передача файлов | DNS, потоковая передача, VoIP, игры, SNMP |
| Размер заголовка | 20–60 байт | 8 байт |

## HTTP и HTTPS
### HTTP-методы
| Метод | Описание |
|--------|-------------|
| **ПОЛУЧИТЬ** | Получить ресурс (идемпотентный, безопасный) |
| **ПОСТ** | Отправить данные (не идемпотентные) |
| **ВСТАВИТЬ** | Обновить/заменить ресурс (идемпотент) |
| **ИСПРАВЛЕНИЕ** | Частичное обновление |
| **УДАЛИТЬ** | Удалить ресурс (идемпотент) |
### Коды состояния
| Код | Значение |
|------|---------|
| **1хх** | Информационный (100 Продолжить) |
| **2хх** | Успех (200 ОК, 201 Создано, 204 Нет содержимого) |
| **3хх** | Перенаправление (301 перемещено навсегда, 302 найдено, 304 не изменено) |
| **4хх** | Ошибка клиента (400 неверный запрос, 401 несанкционированный, 403 запрещенный, 404 не найден, 429 слишком много запросов) |
| **5хх** | Ошибка сервера (500 Внутренняя ошибка сервера, 502 Неверный шлюз, 503 Служба недоступна) |
### Заголовки
| Заголовок | Цель |
|--------|---------|
| `Content-Type`| Тип носителя (`application/json`,`text/html`) |
|  __ЗАЩИЩЕНО_3__ | Учетные данные (например,`Bearer <token>`) |
| `Cache-Control`| Политика кэширования |
| CORS-заголовки | `Access-Control-Allow-Origin`и т. д. |

## TLS/SSL
Шифрует HTTP-трафик (HTTPS = HTTP через TLS).
- Сертификаты центров сертификации (CA) подтверждают подлинность сервера.
- Проверьте цепочку сертификатов и имя хоста на стороне клиента.

## Межсетевые экраны и NAT
### Брандмауэр
- Фильтрует трафик на основе правил (IP-адрес источника, IP-адрес назначения, порт, протокол).
- Межсетевые экраны с отслеживанием состояния отслеживают состояния соединения.
### NAT (трансляция сетевых адресов)
- Преобразует частные IP-адреса в общедоступные IP-адреса для доступа в Интернет.
- Переадресация портов: сопоставляет общедоступный порт с внутренним хостом/портом.

## Общие сетевые команды
### Тесты подключения
```bash
ping google.com            # ICMP echo request
ping -c 4 8.8.8.8          # ping 4 times
traceroute google.com      # Trace the route (Linux)
tracert google.com         # Windows version
```

### Маршрутизация
```bash
ip route show              # Linux: routing table
route -n                   # Older Linux
netstat -r                 # Windows/Mac
```

### Сетевые интерфейсы
```bash
ip addr show               # List interfaces and IPs
ifconfig                   # Older command
```

### DNS
```bash
dig example.com
nslookup example.com
host example.com
```

### Подключение к порту
```bash
nc -zv google.com 443      # Netcat: check if port 443 is open
telnet google.com 443      # Telnet to port
curl -v https://google.com # Verbose output
```

### Брандмауэр (Linux iptables/nftables)
```bash
sudo ufw status            # Ubuntu: simple firewall
sudo iptables -L -n        # List rules
```

### Статистика сети
```bash
ss -tulpn                  # Show listening sockets (Linux)
netstat -an                # All sockets (all OS)
```

## Балансировка нагрузки и обратные прокси
### Nginx как обратный прокси
```nginx
server {
    listen 80;
    server_name example.com;
    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### Алгоритмы балансировки нагрузки
- **Круговой**
- **Минимум соединений**
- **хэш IP** (привязанность сеанса)
- **Взвешенный круговой турнир**
### Инструменты
- **Nginx, HAProxy** (программное обеспечение)
- **AWS ELB, Azure Load Balancer, облачная балансировка нагрузки GCP** (облако)

## Контрольный список устранения неполадок
1. Физическое соединение установлено? (Проверьте кабели, соединение Wi-Fi).
2. Можете ли вы пропинговать шлюз? (например,`ping 192.168.1.1`).
3. Можете ли вы пропинговать внешний IP? (например,`8.8.8.8`).
4. Можете ли вы разрешить домен? (`dig google.com`).
5. Прослушивает ли приложение ожидаемый порт? (`ss -tulpn | grep 8080`).
6. Блокирует ли порт брандмауэр? (Проверьте`iptables`/`ufw`или группы безопасности облака).
7. Есть ли ошибки в логах приложения?
8. Является ли сертификат TLS действительным и надежным? (`openssl s_client -connect example.com:443`).
