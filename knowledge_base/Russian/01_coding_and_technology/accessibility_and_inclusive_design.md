# Доступность и инклюзивный дизайн
Доступность (часто сокращенно a11y) — это практика, позволяющая сделать программное обеспечение доступным для использования всеми, включая людей с нарушениями зрения, слуха, моторики, когнитивных и неврологических нарушений. Это требование закона во многих юрисдикциях и стандартная инженерная практика. Доступное программное обеспечение — лучшее программное обеспечение для всех, поскольку дизайнерские решения, которые поддерживают пользователей с ограниченными возможностями — четкая структура, навигация с помощью клавиатуры, достаточный контраст, читаемый текст — улучшают работу для всех пользователей.
---

## Кому выгодна доступность?
| Тип инвалидности | Примеры | Вспомогательные технологии |
|----------------|---------|---------------------|
| **Визуальный** | Слепота, слабовидение, дальтонизм | Программы чтения с экрана (JAWS, NVDA, VoiceOver); лупы; высококонтрастные режимы |
| **Слуховой** | Глухота, слабослышание | Подписи; стенограммы; визуальные оповещения |
| **Мотор** | Ограничение ловкости, паралич, тремор | Навигация только с помощью клавиатуры; голосовое управление; коммутационные устройства; отслеживание глаз |
| **Когнитивный** | Дислексия, СДВГ, аутизм, нарушения памяти | Понятный язык; последовательная навигация; снижение отвлекающих факторов |
| **Временно** | Сломанная рука, яркий солнечный свет, шумная обстановка | Те же условия, что и с постоянной инвалидностью |
| **Ситуативный** | Держу ребенка за рулем, одна рука занята | Голосовые интерфейсы; большие сенсорные цели |
**Ключевая идея**: специальные возможности, разработанные для пользователей с ограниченными возможностями, помогают каждому. Бордюры (пандусы на тротуарах) были предназначены для инвалидных колясок, но ими пользуются родители с колясками, курьеры с тележками и путешественники с багажом.

## Веб-доступность (WCAG)
Рекомендации по обеспечению доступности веб-контента (WCAG) являются международным стандартом доступности веб-сайтов.
### Принципы WCAG (POUR)
| Принцип | Требование |
|-----------|-------------|
| **Ощутимое** | Информация должна быть представлена ​​так, чтобы ее могли воспринимать пользователи (варианты текста, подписи, адаптируемый макет) |
| **Работоспособ** | Интерфейс должен быть удобным в навигации и использовании (доступна клавиатура, достаточно времени, нет контента, вызывающего судороги) |
| **Понятно** | Информация и операции должны быть понятными (читабельными, предсказуемыми, облегчающими ввод) |
| **Надежный** | Контент должен работать с текущими и будущими ассистивными технологиями |
### Уровни соответствия WCAG
| Уровень | Требования | Типичная цель |
|-------|-------------|---------------|
| **А** | Минимальный уровень; 30 критериев успеха | Законный минимум в некоторых юрисдикциях |
| **АА** | Устраняет наиболее распространенные препятствия | Стандартная цель для большинства организаций |
| **ААА** | Высший уровень; не весь контент может достичь этого | Специализированный контент; образовательные сайты |
### Ключевые критерии успеха (уровень AA)
| Критерий | Требование | Как достичь |
|-----------|-------------|---------------|
| **1.1.1 Нетекстовое содержимое** | Все изображения имеют альтернативный текст |  Атрибуты `alt`; `aria-label`для иконок |
| **1.3.1 Информация и отношения** | Структура передается программно | Семантический HTML; заголовки; списки; достопримечательности |
| **1.4.3 Контрастность (минимум)** | Текст имеет коэффициент контрастности не менее 4,5:1 | Тест с контрастными шашками; выбирать доступные цветовые палитры |
| **1.4.4 Изменение размера текста** | Размер текста можно изменить до 200% без потерь | Используйте относительные единицы (бэр, эм); адаптивный дизайн |
| **2.1.1 Клавиатура** | Все функции доступны через клавиатуру | Никаких ловушек на клавиатуре; видимые индикаторы фокусировки |
| **2.4.3 Порядок фокусировки** | Порядок фокусировки сохраняет смысл и работоспособность | Логический порядок табуляции; Порядок DOM соответствует визуальному порядку |
| **2.4.7 Фокус виден** | Фокус клавиатуры отображается визуально | стили CSS `:focus-visible`; никогда`outline: none`без замены |
| **3.3.2 Этикетки или инструкции** | Входы имеют метки |  элементы `<label>`; `aria-label`|
| **4.1.2 Имя, роль, значение** | Компоненты пользовательского интерфейса имеют доступные имена и роли | атрибуты ARIA; семантический HTML |

## ARIA (Доступные многофункциональные интернет-приложения)
ARIA добавляет информацию о доступности к элементам HTML, которые не имеют встроенной семантики.
### АРИЯ Роли
| Роль | Цель | Пример |
|------|---------|---------|
| `button`| Идентифицирует элемент как кнопку |`<div>`в виде кнопки |
| `dialog`| Модальный или немодальный диалог | Пользовательские модальные компоненты |
| `tablist`/`tab`/`tabpanel`| Интерфейс вкладок | Пользовательские компоненты вкладок |
| `alert`| Важное сообщение, которое появляется динамически | Уведомления об ошибках |
| `progressbar`| Индикатор прогресса | Загрузка состояний |
| `menu`/`menuitem`| Навигация по меню | Выпадающие меню |
### ARIA-атрибуты
| Атрибут | Цель | Пример |
|-----------|---------|---------|
| `aria-label`| Доступное имя, когда нет видимого текста | Кнопка только со значком:`aria-label="Search"`|
| `aria-describedby`| Связывает элемент с его описанием | Поле формы со справочным текстом |
| `aria-expanded`| Указывает, расширен ли раздел | Аккордеон; раскрывающийся список |
| `aria-hidden`| Скрывает элемент от вспомогательных технологий | Декоративные иконки |
| `aria-live`| Объявляет об изменениях динамического контента | Живые обновления; уведомления |
| `aria-disabled`| Указывает, что элемент отключен | Серые кнопки |
### Первое правило ARIA
> **Не используйте ARIA, если вместо этого вы можете использовать собственный HTML.**`<button>`уже доступен.`<div role="button">`требует, чтобы вы вручную добавили обработку клавиатуры, управление фокусом и поддержку чтения с экрана. Сначала используйте семантический HTML; ARIA только тогда, когда собственные элементы не справляются со своей задачей.

## Навигация с помощью клавиатуры
| Ключ | Ожидаемое поведение |
|-----|-------------------|
| **Вкладка** | Переместить фокус на следующий интерактивный элемент |
| **Shift + Tab** | Переместить фокус на предыдущий интерактивный элемент |
| **Ввод/Пробел** | Активировать выделенный элемент (кнопку, ссылку) |
| **Клавиши со стрелками** | Навигация по компонентам (меню, вкладки, радиогруппы) |
| **Побег** | Закрыть диалоговое окно, меню или всплывающее окно |
| **Начало/Конец** | Перейти к первому/последнему элементу списка |
### Распространенные ловушки клавиатуры
| Problem | Fix |
|---------|-----|
| Фокус входит в компонент, но не может выйти | Убедитесь, что Tab перемещает фокус; handle Escape |
| Модальное окно не захватывает фокус | Фокус должен циклически перемещаться внутри модального окна; вернуться к триггеру при закрытии |
| Пользовательские компоненты не реагируют на клавиатуру | Добавьте обработчики нажатия клавиш для Enter, Space, стрелок |

## Цвет и визуальный дизайн
| Руководство | Требование |
|-----------|-------------|
| **Коэффициент контрастности** | 4,5:1 для обычного текста; 3:1 для крупного текста (18pt+ или 14pt+жирный) |
| **Не полагайтесь только на цвет** | Используйте значки, текст или узоры в дополнение к цвету |
| **Индикаторы фокуса** | Всегда виден; высокая контрастность; никогда не удалялся без замены |
| **Изменение размера текста** | Макет должен работать при масштабе 200% |
| **Отзывчивый** | Содержимое должно быть перекомпоновано на ширину 320 пикселей (мобильные устройства) |
### Рекомендации по цветовой слепоте
| Тип | Затронутые цвета | Совет по дизайну |
|------|-----------------|------------|
| **Дейтеранопия** | Красно-зеленый (наиболее распространенный) | Не используйте красный/зеленый для передачи статуса; использовать значки + цвет |
| **Протанопия** | Красно-зеленый | То же, что и выше |
| **Тританопия** | Сине-желтый | Не используйте синий/желтый как единственный отличительный признак |

## Тестирование доступности
| Метод | Инструмент | Что он ловит |
|--------|------|----------------|
| **Автоматическое сканирование** | топор, Маяк, ВОЛНА | Отсутствует альтернативный текст; проблемы контраста; Ошибки ARIA |
| **Тестирование клавиатуры** | Инструкция: отключить мышь, использовать только клавиатуру | Порядок фокусировки; клавиатурные ловушки; отсутствуют обработчики |
| **Тестирование программы чтения с экрана** | NVDA (бесплатно), VoiceOver (macOS), JAWS | Отсутствуют этикетки; плохая структура; необъявленные изменения |
| **Тестирование масштабирования** | Масштаб браузера: 200%, 400% | Поломка макета; обрезанный текст; проблемы с переполнением |
| **Цветовой контраст** | Проверка контрастности WebAIM, плагин Stark | Недостаточная контрастность |
| **Пользовательское тестирование** | Тестирование с участием пользователей с ограниченными возможностями | Реальные барьеры, которые не пропускают автоматизированные инструменты |

## Юридические требования
| Закон | Регион | Требования |
|-----|--------|-------------|
| **ADA** (Закон об американцах с ограниченными возможностями) | США | Веб-сайты общественных мест должны быть доступны |
| **Раздел 508** | США (федеральный) | ИКТ федеральных агентств должны быть доступны |
| **EAA** (Европейский закон о доступности) | ЕС (2025+) | Продукты и услуги должны соответствовать требованиям доступности |
| **ЕН 301 549** | ЕС | Технический стандарт доступности ИКТ |
| **ACA** (Закон Канады о доступности) | Канада | Государственные и регулируемые отрасли |
| **Закон о равенстве 2010 г.** | Великобритания | Поставщики услуг должны внести разумные коррективы |

## Доступность для мобильных устройств
| Платформа | Рекомендации | Ключевые инструменты |
|----------|-----------|-----------|
| **iOS** | Рекомендации Apple по пользовательскому интерфейсу (раздел «Специальные возможности») | Голос за кадром; Динамический тип; Переключатель управления |
| **Андроид** | Рекомендации по обеспечению специальных возможностей Android | TalkBack; Переключить доступ; Выберите, чтобы говорить |
| Мобильный концерн | Решение |
|---------------|----------|
| **Прикоснитесь к целям** | Минимум 44×44 точек (iOS) / 48×48 точек (Android) |
| **Поддержка чтения с экрана** | Описания контента; этикетки доступности |
| **Чувствительность к движению** | Уважайте`prefers-reduced-motion`; избегать автоматического воспроизведения анимации |
| **Динамический размер текста** | Поддержка размеров системных шрифтов; использовать масштабируемые текстовые блоки |

## Краткое содержание
Доступность — это принцип проектирования, который должен определять каждое решение с самого начала, а не функция, добавляемая в конце. Используйте семантический HTML. Убедитесь, что навигация с помощью клавиатуры работает. Поддерживайте достаточный цветовой контраст. Предоставьте текстовые альтернативы нетекстовому контенту. Протестируйте с помощью программ чтения с экрана и пользователей с ограниченными возможностями. В результате получается программное обеспечение, которое работает лучше для всех, включая людей с временными нарушениями, ситуативными ограничениями, старыми устройствами, медленными соединениями и многими другими отличиями реального использования от контролируемой среды разработки.
