# Мобильная разработка
Мобильная разработка — это практика создания приложений для смартфонов и планшетов, в первую очередь для iOS (Apple) и Android (Google). Он охватывает все: от дизайна пользовательского интерфейса для маленьких экранов до управления временем автономной работы, устранения нестабильности сети и распространения приложений через магазины. Эта область значительно повзрослела: кроссплатформенные платформы теперь конкурируют с собственной разработкой в ​​большинстве случаев использования.

## Нативная разработка
### Андроид
| Аспект | Подробности |
|--------|---------|
| **Язык** | Котлин (основной), Java (устаревший) |
| **Инфраструктура пользовательского интерфейса** | Jetpack Compose (современный), XML-макеты (устаревшие версии) |
| **Система сборки** | Градл |
| **IDE** | Android-студия |
| **Минимальный SDK** | Разработчик выбирает; наиболее целевой API 24+ (Android 7.0, 2016 г.) |
| **Распространение** | Магазин Google Play; альтернативные магазины на некоторых рынках |
### iOS
| Аспект | Подробности |
|--------|---------|
| **Язык** | Swift (основной), Objective-C (устаревший) |
| **Инфраструктура пользовательского интерфейса** | SwiftUI (современный), UIKit (зрелый) |
| **Система сборки** | Система сборки Xcode |
| **IDE** | Xcode (только для macOS) |
| **Минимальная версия** | Разработчик выбирает; наиболее целевая iOS 16+ |
| **Распространение** | Apple App Store (единственный вариант для большинства приложений) |

## Кроссплатформенные платформы
Создайте один раз, разверните как на iOS, так и на Android.
| Рамочная | Язык | Рендеринг | Производительность | Лучшее для |
|-----------|----------|-----------|-------------|----------|
| **Трехат** | Дарт | Кастомный двигатель (лыжи/крыльчатка) | Почти родной | Богатые пользовательские интерфейсы; единообразный взгляд на разные платформы |
| **React Native** | JavaScript/TypeScript | Родные компоненты через мост | Хорошо (Новая архитектура улучшает это) | Команды с опытом работы в Интернете/JS |
| **Мультиплатформенность Kotlin** | Котлин | Собственный пользовательский интерфейс для каждой платформы | Родной | Совместное использование бизнес-логики; собственный пользовательский интерфейс |
| **МАУИ** (.NET) | С# | Собственные элементы управления | Хорошо | .NET-команды; корпоративные приложения |
| **Ионный/Конденсатор** | HTML/CSS/JS | Веб-просмотр | Нижний | Простые приложения; веб-команды |
### Flutter против React Native
| Аспект | флаттер | Реагировать Нативный |
|--------|---------|-------------|
| **Язык** | Дарт | JavaScript/TypeScript |
| **Рендеринг пользовательского интерфейса** | Рисует все сам (одинаково на разных платформах) | Использует собственные компоненты (внешний вид зависит от платформы) |
| **Горячая перезагрузка** | Отлично | Хорошо |
| **Экосистема** | Быстро растет; на основе виджетов | Большой; экосистема npm |
| **Кривая обучения** | Нужно изучить дартс | Веб-разработчикам проще |
| **Интеграция платформы** | Каналы платформы для нативного кода | Родные модули через мост |
| **Производительность** | Отличный; почти родной | Хороший; надземная часть моста (уменьшена благодаря новой архитектуре) |

## Ключевые проблемы мобильных устройств
### Дизайн, ориентированный на офлайн-режим
Мобильные приложения должны работать без надежного Интернета.
| Стратегия | Описание |
|----------|-------------|
| **Локальная база данных** | Хранить данные на устройстве (SQLite, Room, CoreData, Realm) |
| **Стратегия синхронизации** | Синхронизация с сервером при подключении к сети; разрешать конфликты |
| **Оптимистичный интерфейс** | Немедленно обновите пользовательский интерфейс; согласовать, когда сервер отвечает |
| **Кэш** | Кэшировать ответы API; обслуживать из кеша в автономном режиме |
### Производительность
| Концерн | Решение |
|---------|----------|
| **Время запуска приложения** | Ленивая загрузка; минимизировать работу по инициализации |
| **Использование памяти** | Сжатие изображения; избегать утечек памяти; использовать инструменты профилирования |
| **Разряд батареи** | Уменьшите фоновую работу; пакетные сетевые запросы; использовать эффективные службы определения местоположения |
| **Эффективность сети** | Сжатие полезных данных; использовать нумерацию страниц; кэшировать агрессивно |
| **Прокрутка списка** | Перерабатывать просмотры; используйте отложенную загрузку изображений |
### Безопасность
| Концерн | Решение |
|---------|----------|
| **Неактивные данные** | Шифрование конфиденциальных данных (Связка ключей на iOS, EncryptedSharedPreferences на Android) |
| **Сеть** | Всегда HTTPS; закрепление сертификата для конфиденциальных приложений |
| **Аутентификация** | Биометрия (Face ID, отпечаток пальца); ОАутент; хранение токенов |
| **Обфускация кода** | ProGuard/R8 для Android; биткод для iOS |
| **Обнаружение джейлбрейка/рутирования** | Обнаружение скомпрометированных устройств; ограничить функциональность |

## Жизненный цикл приложения
| Государство | Описание | Что делать |
|-------|-------------|------------|
| **Передний план (активный)** | Пользователь взаимодействует с приложением | Нормальная работа |
| **Фон** | Приложение не видно, но все еще находится в памяти | Пауза анимации; сохранить состояние |
| **Приостановлено** | ОС заморозила приложение для экономии ресурсов | Ничего; приложение зависло |
| **Прекращено** | ОС убила приложение, чтобы освободить память | Восстановить состояние при следующем запуске |

## Краткое содержание
Мобильная разработка предлагает выбор между нативной (наилучшая производительность, зависит от платформы) и кроссплатформенной (общая база кода, более быстрая итерация). Flutter и React Native достигли такой степени, что кроссплатформенность является правильным выбором для большинства приложений. Основные проблемы остаются теми же, независимо от платформы: проектирование в автономном режиме, производительность на ограниченном оборудовании, эффективность использования батареи, безопасность на ненадежных устройствах и навигация по процессам проверки в магазине приложений. Эта область вознаграждает разработчиков, которые в первую очередь думают о пользовательском опыте — быстрый запуск, плавная прокрутка и изящное управление плохим подключением.
