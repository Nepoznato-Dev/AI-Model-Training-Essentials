# Low-Code и платформенная инженерия
Платформы с низким кодом позволяют людям создавать приложения с минимальным написанием вручную кода — обычно с помощью интерфейсов перетаскивания, визуальных рабочих процессов и готовых коннекторов. Проектирование платформ — это дисциплина создания внутренних платформ разработчиков (IDP), которые упрощают командам разработчиков самообслуживание инфраструктуры, CI/CD и операционных инструментов. Обе тенденции являются ответом на одну и ту же проблему: разрыв между спросом на программное обеспечение и предложением разработчиков, которые могут его создать.
---

## Платформы с низким кодом
### Что на самом деле означает Low-Code
| Аспект | Описание |
|--------|-------------|
| **Визуальная разработка** | Конструкторы пользовательского интерфейса с возможностью перетаскивания; визуальные редакторы рабочих процессов; дизайнеры форм |
| **Готовые компоненты** | Готовые виджеты, коннекторы, шаблоны и интеграции |
| **Декларативная логика** | Настраивайте поведение с помощью правил и условий, а не написания кода |
| **Расширяемость** | Возможность добавлять собственный код, когда встроенных возможностей платформы недостаточно |
| **Управляемая инфраструктура** | Платформа занимается хостингом, масштабированием и исправлениями безопасности |
### Популярные платформы с низким кодом
| Платформа | Сила | Типичный случай использования |
|----------|----------|-----------------|
| **Платформа Microsoft Power** | Глубокая интеграция Microsoft 365/Azure; Power Apps, Power Automate, Power BI | Корпоративные рабочие процессы; внутренние инструменты |
| **Платформа Salesforce** | CRM-родной; Apex для расширений; Построитель потока | Приложения для клиентов; рабочие процессы продаж |
| **СервисNow** | Управление ИТ-услугами; автоматизация рабочих процессов | ИТ-операции; HR; объекты |
| **Аппиан** | Технологический майнинг; ведение дел | Сложные бизнес-процессы; соответствие |
| **АутСистемс** | Полноценный веб и мобильный интерфейс; корпоративного уровня | Клиентские порталы; мобильные приложения |
| **Переоборудование** | Внутренний конструктор инструментов; подключается к базам данных и API | Админ-панели; приборные панели; операционные инструменты |
| **Эфирный стол** | Гибрид электронных таблиц и баз данных; автоматизация | Сопровождение проекта; легкий CRM |
### Когда Low-Code работает хорошо
| Сценарий | Почему подходит Low-Code |
|----------|-------------------|
| **Внутренние инструменты** | Быстро построить; пользователи являются внутренними, поэтому гибкость пользовательского интерфейса имеет меньшее значение |
| **Формы и разрешения** | Разработчики визуальных рабочих процессов преуспевают в этом |
| **CRUD-приложения** | Большинство low-code платформ оптимизированы для шаблонов «создание-чтение-обновление-удаление» |
| **Прототипирование** | Подтвердить идею за часы, а не за недели |
| **Гражданское развитие** | Бизнес-аналитики могут создавать свои собственные решения с помощью управления ИТ |
### Когда low-code не справляется
| Ограничение | Воздействие |
|------------|--------|
| **Привязка к поставщику** | Приложения нелегко перенести с платформы |
| **Потолки производительности** | Не подходит для приложений с высокой пропускной способностью или чувствительных к задержке |
| **Ограничения пользовательского интерфейса** | Индивидуальный дизайн труден; вы ограничены тем, что поддерживает платформа |
| **Сложность интеграции** | Для подключения к необычным API или устаревшим системам в любом случае может потребоваться специальный код |
| **Цена в масштабе** | Цены на пользователя или приложение могут стать дороже по мере роста использования |
| **Сложность отладки** | Визуальные абстракции затрудняют диагностику сложных проблем |

## Разработка платформы
### Проблемы, которые решает разработка платформы
| Без разработки платформы | с разработкой платформы |
|------------------------------|---------------------------|
| Каждая команда управляет собственной инфраструктурой | Платформа самообслуживания абстрагирует инфраструктуру |
| Несогласованный инструментарий в разных командах | Стандартизированный набор инструментов; золотые пути |
| Разработчики ждут, пока операторы предоставят ресурсы | Разработчики предоставляют ресурсы по требованию |
| Разрозненность знаний; племенные знания | Документировано; автоматизированный; обнаруживаемый |
| Медленная адаптация новых инженеров | Новых инженеров можно развернуть в первый же день |
### Основные компоненты внутренней платформы разработки
| Компонент | Цель | Примеры инструментов |
|-----------|---------|---------------|
| **Каталог услуг** | Центральный реестр всех сервисов и их владельцев | За кулисами; Порт; Кортекс |
| **Шаблон строительных лесов** | Создание новых услуг на основе утвержденных шаблонов | Шаблоны программного обеспечения Backstage; Формочка для печенья |
| **Инфраструктура самообслуживания** | Разработчики предоставляют облачные ресурсы без подачи заявок | Модули Терраформ; Пулуми; Поперечная плоскость |
| **Конвейеры CI/CD** | Стандартизированные конвейеры сборки, тестирования и развертывания | Действия GitHub; GitLab CI; Арго CD |
| **Управление окружающей средой** | Эфемерные среды разработки/промежуточной среды по требованию | Вкластер; Пространство имен; Гитпод |
| **Наблюдаемость** | Ведение журнала, метрики и трассировка встроены в каждый сервис | Прометей; Графана; ОпенТелеметрия; Датадог |
| **Секретное управление** | Безопасное хранение и ротация учетных данных | Сейф; Менеджер секретов AWS; СОПС |
| **Идентификация и доступ** | ССО; ролевой доступ; межсервисная аутентификация | Окта; плащ-ключ; СПИФФ |
### Золотые пути
Золотой путь — это поддерживаемый и самоуверенный способ что-то сделать. Это путь наименьшего сопротивления — если идти по нему, все работает. Ты можешь сбиться с пути, но ты сам по себе.
| Золотой Путь | Что это обеспечивает |
|-------------|-----------------|
| **Новая услуга** | Репозиторий шаблонов; CI/CD; мониторинг; регистрация; конфигурация развертывания |
| **Новая база данных** | Предоставленный экземпляр; строки подключения в секретах; резервное копирование настроено |
| **Новый интерфейс** | построить трубопровод; CDN; среды предварительного просмотра; проверки маяков |
| **Конвейер данных** | оркестровка; проверка схемы; мониторинг; оповещение |
### Решения о сборке и покупке
| Фактор | Создайте индивидуальный | Использовать существующий инструмент |
|--------|-------------|-------------------|
| **Основная компетенция** | Уникально для вашего бизнеса; конкурентное преимущество | Товар; это нужно каждой компании |
| **Обязательства по техническому обслуживанию** | У вас есть возможность его поддерживать | Инструмент хорошо поддерживается поставщиком/сообществом |
| **Потребности в интеграции** | Требуется глубокая интеграция с внутренними системами | Достаточно стандартных API и коннекторов |
| **Стоимость** | Дешевле построить, чем лицензировать | Дешевле лицензировать, чем строить |

## Связь между Low-Code и платформенной разработкой
| Размерность | Низкий код | Разработка платформ |
|-----------|----------|---------------------|
| **Целевой пользователь** | Бизнес-пользователи; гражданские разработчики | Профессиональные инженеры-программисты |
| **Цель** | Сократить код; увеличить скорость | Снизить когнитивную нагрузку; увеличить автономность |
| **Уровень абстракции** | Очень высокий; визуальный | Середина; на основе кода, но упрощенный |
| **Гибкость** | Ограничено возможностями платформы | Полная гибкость; вы можете написать любой код |
| **Управление** | Платформа обеспечивает соблюдение правил | Платформа обеспечивает золотые пути |
Они дополняют друг друга: разработка платформ позволяет профессиональным разработчикам работать быстрее, а low-code позволяет неразработчикам создавать простые приложения. Вместе они решают проблему разрыва в доставке программного обеспечения с разных точек зрения.

## Краткое содержание
Платформы Low-code и внутренние платформы разработчиков направлены на увеличение числа людей, которые могут доставлять программное обеспечение. Low-code делает это за счет полного абстрагирования кода — визуальных конструкторов, готовых коннекторов, декларативной логики. Проектирование платформ делает это для профессиональных разработчиков, предоставляя инфраструктуру самообслуживания, «золотые пути» и стандартизированные инструменты, чтобы они тратили меньше времени на операционную работу и больше времени на функции продукта. И это не панацея: low-code имеет привязку к поставщику и ограничения производительности, а разработка платформы требует постоянных инвестиций для ее поддержания. Но если их применить к правильным проблемам — внутренним инструментам, приложениям CRUD, стандартизированному предоставлению услуг — то и другое может значительно сократить время от идеи до производства.
