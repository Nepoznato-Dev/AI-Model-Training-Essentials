# Облачная архитектура
Облачные вычисления коренным образом изменили способы создания, развертывания и масштабирования программного обеспечения в организациях. Вместо покупки и обслуживания физических серверов вы можете предоставлять вычислительные ресурсы по требованию, платить за то, что используете, и масштабироваться по всему миру за считанные минуты. В этом файле описаны основные концепции, шаблоны архитектуры, сервисы и лучшие практики, которые вам необходимо знать.
---

## Основы облачных вычислений
### Что такое облачные вычисления?
Доставка вычислительных ресурсов по требованию — серверов, хранилищ, баз данных, сетей, программного обеспечения — через Интернет с оплатой по факту использования.
### Основные характеристики NIST
| Характеристика | Значение |
|---------------|---------|
| **Самообслуживание по требованию** | Предоставление ресурсов без участия человека |
| **Широкий доступ к сети** | Доступно по сети через стандартные механизмы |
| **Объединение ресурсов** | Мультитенантная модель; ресурсы, динамически назначенные |
| **Быстрая эластичность** | Быстро масштабируйтесь наружу и внутрь |
| **Измеренное обслуживание** | Использование контролируется и выставляется счет |
### Модели развертывания
| Модель | Описание | Когда использовать |
|-------|-------------|-------------|
| **Общественное облако** | Принадлежит провайдерам; общая инфраструктура (AWS, Azure, GCP) | Большинство рабочих нагрузок; экономически эффективный |
| **Частное облако** | Посвящается одной организации | Нормативные требования, конфиденциальные данные |
| **Гибридное облако** | Сочетание государственного и частного | Гибкость + соответствие |
| **Мультиоблако** | Использование нескольких поставщиков общедоступных облаков | Избегайте привязки к поставщику, лучшее в своем классе |
### Модели обслуживания
| Модель | Обеспечивает | Примеры | Варианты использования |
|-------|----------|----------|-----------|
| **IaaS** | ВМ, СХД, сети, ОС | AWS EC2, виртуальные машины Azure, вычислительная система GCP | Подвижные миграции, полный контроль |
| **ПааС** | Платформы разработки, базы данных, промежуточное ПО | Heroku, Google App Engine, AWS Elastic Beanstalk | Разработка приложений, развертывание API |
| **SaaS** | Полные приложения через Интернет | Salesforce, Google Workspace, Microsoft 365 | Электронная почта, CRM, сотрудничество |
| **FaaS/бессерверное** | Выполнение функций, управляемых событиями | AWS Lambda, Функции Azure, Облачные функции GCP | API, обработка событий, запланированные задачи |

| **Сеть** | VPC, Маршрут 53, CloudFront | Виртуальная сеть, диспетчер трафика | VPC, облачный DNS, облачный CDN |

## Шаблоны архитектуры
### Хорошо спроектированная платформа
Все три основных поставщика публикуют хорошо продуманные структуры, построенные на пяти столпах:
| Столб | Ключевые принципы |
|--------|---------------|
| **Операционное совершенство** | Автоматизировать операции; вносить частые обратимые изменения; предвидеть неудачу |
| **Безопасность** | Сильная основа идентичности; применять безопасность на каждом уровне; защитить данные при передаче и хранении |
| **Надежность** | Тестовые процедуры восстановления; автоматическое восстановление после сбоя; масштабировать по горизонтали |
| **Эффективность** | Используйте бессерверное использование; выйти на глобальный уровень за считанные минуты; часто экспериментируйте |
| **Оптимизация затрат** | Принять модель потребления; использовать управляемые сервисы; прекратить тратить деньги на недифференцированный труд |
### Общие шаблоны
| Узор | Описание | Преимущества | Проблемы |
|---------|-------------|----------|------------|
| **Микросервисы** | Разложить приложение на небольшие независимые сервисы | Масштабируемость, изоляция неисправностей, независимое развертывание | Распределенная сложность, согласованность данных |
| **Управление событиями** | Компоненты взаимодействуют через события | Слабая связь, обработка в реальном времени | Сложность отладки, конечная согласованность |
| **Бессерверная** | Никакого управления сервером; оплата за исполнение | Экономическая эффективность, быстрое развертывание | Холодный запуск, привязка к поставщику, ограничения выполнения |
| **Многослойный (N-уровневый)** | Презентация → Бизнес-логика → Доступ к данным → База данных | Разделение ответственности, ремонтопригодность | Может стать монолитным |
| **Космическое** | Распределенные данные по виртуализированным узлам памяти | Обеспечивает высокий уровень параллелизма и низкую задержку | Комплекс для проектирования и управления |

## Основные службы
### Вычислить
| Тип услуги | Подробности |
|-------------|---------|
| **Виртуальные машины** | Графический процессор общего назначения, оптимизированный для вычислений и памяти. Цены: по запросу, зарезервировано, спот. |
| **Контейнеры** | среда выполнения Docker; оркестровка через Kubernetes (EKS, AKS, GKE). Реестры: ECR, GCR, ACR. |
| **Бессерверные функции** | Запускается по событию, без сохранения состояния. Ограничения на время выполнения, память, параллелизм. |
### Хранилище
| Тип | Характеристики | Примеры | Лучшее для |
|------|----------------|----------|----------|
| **Объект** | Плоская структура, HTTP-доступ, большое количество метаданных | S3, облачное хранилище, Azure Blob | Статические ресурсы, резервные копии, озера данных |
| **Блокировать** | Необработанные тома, подключенные к виртуальным машинам | EBS, постоянный диск, диски Azure | Базы данных, загрузочные тома |
| **Файл** | Общие файловые системы (NFS/SMB) | EFS, хранилище файлов, файлы Azure | Управление контентом, общие конфигурации |
| **Архив** | Самая низкая стоимость, задержки при поиске | Ледник S3, Архив Azure | Соответствие требованиям, долгосрочное резервное копирование |
### Базы данных
| Категория | Услуги | Вариант использования |
|----------|----------|----------|
| **Управляемый реляционный** | RDS, Cloud SQL, Azure SQL | Традиционные приложения, транзакции ACID |
| **NoSQL — Документ** | DocumentDB, Firestore, Cosmos DB | Гибкие схемы, данные JSON |
| **NoSQL — ключ-значение** | DynamoDB, кэш Redis | Кэширование, сеансы, простой поиск |
| **NoSQL — широкая колонка** | Бигтабл, Кассандра | Тяжелая запись, временные ряды |
| **NoSQL — График** | Нептун, Cosmos DB (API графиков) | Отношения, социальные сети |
| **Хранилище данных** | Снежинка, Redshift, BigQuery, Synapse | Аналитика, BI |
| **Кэширование** | ElastiCache, облачное хранилище памяти | Хранение сеансов, кэширование запросов |

## Сеть
### Виртуальные сети
Каждое облачное развертывание находится внутри виртуального частного облака (VPC/VNet) — изолированной сети, которую вы определяете с помощью блоков CIDR, подсетей (публичных или частных), таблиц маршрутизации и шлюзов.
### Балансировка нагрузки и CDN
| Сервис | Цель |
|---------|---------|
| **Балансировщики нагрузки** | Распределить трафик между экземплярами (сеть L4, приложение L7) |
| **CDN** | Кэшируйте контент в пограничных расположениях для снижения задержки (CloudFront, Cloud CDN, Azure CDN) |
| **DNS** | Регистрация домена, политики маршрутизации, проверки работоспособности (Route 53, Cloud DNS, Azure DNS) |
### Варианты подключения
| Вариант | Описание |
|--------|-------------|
| **Интернет-шлюз** | Публичный доступ в Интернет для VPC |
| **NAT-шлюз** | Исходящий доступ к частной подсети |
| **VPN** | Зашифрованные туннели в локальную среду |
| **Прямое подключение/ExpressRoute** | Выделенные частные связи |
| **Пиринг VPC** | Подключите VPC внутри или между учетными записями |

## Безопасность
### Модель общей ответственности
| Слой | Провайдер | Клиент |
|-------|----------|----------|
| **Инфраструктура** (оборудование, оборудование) | ✅ | |
| **Вычислительные системы, системы хранения данных, сети** | ✅ (управляемый) | ✅ (самоуправление) |
| **Данные, Приложения, Личность** | | ✅ |
Чем лучше управляема услуга, тем больше ее обрабатывает провайдер. С IaaS вы управляете практически всем; в случае SaaS почти все это берет на себя провайдер.
### Управление идентификацией и доступом (IAM)
| Концепция | Описание |
|---------|-------------|
| **Пользователи** | Индивидуальные личности |
| **Группы** | Коллекции пользователей |
| **Роли** | Временные учетные данные для служб или пользователей |
| **Правила** | Документы, определяющие разрешения |
| **Принцип** | Наименьшие привилегии, разделение обязанностей |
### Защита данных
- **Шифрование хранения**: KMS, ключи, управляемые клиентом, HSM.
- **Шифрование при передаче**: TLS/SSL, HTTPS.
- **Управление секретами**: Менеджер секретов, Key Vault — никогда не запрограммируйте секреты жестко.

## Управление затратами
### Модели ценообразования
| Модель | Описание | Лучшее для |
|-------|-------------|----------|
| **По требованию** | Платите за то, что используете, посекундно/час | Переменные, краткосрочные нагрузки |
| **Зарезервированные экземпляры** | Срок действия 1–3 года, значительная скидка | Стабильные рабочие нагрузки |
| **Спотовые инстансы** | Заявка на неиспользованную мощность; можно прервать | Отказоустойчивая и гибкая работа |
| **Планы экономии** | Гибкая ценовая политика | Смешанные модели использования |
| **Уровень бесплатного пользования** | Ограниченное бесплатное использование для новых аккаунтов | Обучение, прототипирование |
### Стратегии оптимизации
Инстансы подходящего размера, соответствующие рабочим нагрузкам. Используйте автоматическое масштабирование, чтобы справляться с пиками спроса. Резервная мощность для прогнозируемых нагрузок. Используйте спотовые экземпляры для пакетных заданий. Переместите редко используемые данные на более дешевые уровни хранения. Удалите неиспользуемые ресурсы (потерянные снимки, простаивающие балансировщики нагрузки, неприсоединенные IP-адреса).

## Высокая доступность и аварийное восстановление
### Концепции доступности
| Концепция | Описание |
|---------|-------------|
| **Зона доступности (AZ)** | Физически отдельные центры обработки данных в пределах региона |
| **Регион** | Географическая зона с несколькими зонами доступности |
| **Расположение на краю** | Расположение кэша CDN для доставки контента |
### Стратегии аварийного восстановления
| Стратегия | Стоимость | РТО | РПО | Описание |
|----------|------|-----|-----|-------------|
| **Резервное копирование и восстановление** | Самый низкий | Часы | Часы–дни | Периодическое резервное копирование, восстановление при необходимости |
| **Пилотный свет** | Низкий | Минуты–часы | Минуты | Основные элементы всегда работают, масштабируйте работу в случае стихийных бедствий |
| **Теплый режим ожидания** | Средний | Минуты | Секунды–минуты | Уменьшенная версия всегда работает |
| **Многосайтовый активный/активный** | Самый высокий | Около нуля | Ноль | Полное производство в нескольких регионах |
**RTO** (целевое время восстановления) = максимально допустимое время простоя. **RPO** (Цель точки восстановления) = максимально допустимая потеря данных.

## Новые тенденции
| Тренд | Что происходит |
|-------|-----------------|
| **Периферийные вычисления** | Обработка данных ближе к источнику (AWS Outposts, Wavelength, Azure Edge) |
| **Мультиоблако** | Избежание привязки к поставщику; использование лучших в своем классе поставщиков |
| **Услуги искусственного интеллекта и машинного обучения** | Предварительно обученные модели (зрение, речь, язык) + индивидуальное обучение (SageMaker, Vertex AI) |
| **Квантовые вычисления** | Экспериментальные сервисы ранней стадии (AWS Braket, Azure Quantum) |
| **Устойчивое облако** | Отслеживание углеродного следа, обязательства по возобновляемым источникам энергии, зеленая архитектура |
