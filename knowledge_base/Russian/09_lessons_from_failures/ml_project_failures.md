# неудачных проектов машинного обучения
Проекты машинного обучения терпят неудачу с угрожающей скоростью — по отраслевым оценкам, 60-85% проектов ML никогда не доходят до производства. Сбои обычно не в алгоритмах; они находятся в процессе, данных, ожиданиях и организационном контексте. Понимание того, почему проекты ML терпят неудачу, важно для любого, кто создает системы ML, поскольку виды сбоев предсказуемы и в значительной степени их можно избежать.
---

## Почему проекты машинного обучения терпят неудачу
### Категории ошибок
| Категория | Доля неудач | Описание |
|----------|------------------|-------------|
| **Проблемы с данными** | ~30% | Данные недостаточны, предвзяты, устарели или недоступны |
| **Определение проблемы** | ~20% | Проблема машинного обучения не соответствует потребностям бизнеса |
| **Несоответствие ожиданий** | ~15% | Заинтересованные стороны ожидают волшебства; реальность — постепенное улучшение |
| **Ошибка развертывания** | ~15% | Модель работает в ноутбуках, но не может быть запущена в производство |
| ** организационные вопросы** | ~10% | Нет четкой принадлежности; команде не хватает навыков; нет поддержки со стороны руководства |
| **Производительность модели** | ~10% | Модель не обеспечивает требуемой точности или плохо обобщает |

## Сбои, связанные с данными
### Распространенные проблемы с данными
| Проблема | Описание | Пример |
|---------|-------------|---------|
| **Недостаточно данных** | Недостаточно примеров, чтобы изучить значимые закономерности | Обучение модели обнаружения мошенничества на 500 транзакциях |
| **Качество этикетки** | Ярлыки обучения неверны, непоследовательны или субъективны | Медицинские изображения, помеченные неспециалистами; ярлыки настроений с низким согласием между экспертами |
| **Утечка данных** | Информация из будущего или цель просачивается в функции | Использование результата оттока клиентов в качестве функции; включение тестовых данных в обучение |
| **Смещение выбора** | Данные обучения не отражают совокупность развертываний | Обучение медицинской модели на данных одной больницы; развертывание на национальном уровне |
| **Дрейф концепции** | Взаимосвязь между функциями и целями меняется со временем | Поведение потребителей меняется после пандемии; модель, обученная на данных до пандемии |
| **Несоответствие функций** | Функции, доступные во время обучения, отличаются от тех, которые доступны в рабочей версии | Обучение работе с ручными этикетками; производство использует автоматизированные этикетки с различным распределением |
| **Классовый дисбаланс** | Целевые классы сильно асимметричны | 99% отрицательных, 1% положительных; модель учится всегда предсказывать негатив |
### Проблема утечки данных
| Тип | Описание | Пример |
|------|-------------|---------|
| **Целевая утечка** | Функция доступна только после достижения цели | «Результат лечения» используется как признак для прогнозирования «успеха лечения» |
| **Загрязнение при тестировании поезда** | Данные испытаний влияют на обучение | Масштабирование с глобальной статистикой (включая тестовые данные); увеличение данных, которое утекает |
| **Смещение выборки** | Обучение и производство используют различные выборки | Обучение веб-трафику; развертывание на трафике мобильных приложений |
| **Утечка перед обработкой** | На этапе предварительной обработки используется информация из полного набора данных | Вменение пропущенных значений с помощью глобального среднего значения (включая тестовые данные) |

## Неудачи с определением проблемы
### Шаблоны смещения
| Узор | Описание | Следствие |
|---------|-------------|-------------|
| **Решение неправильной проблемы** | Бизнес-потребности X; команда строит Y | Модель технически хороша, но бесполезна |
| **ML, когда правил достаточно** | Задача имеет детерминированные правила; ML добавляет сложности | Перепроектированный; труднее поддерживать; менее интерпретируемый |
| **ML, когда данные не существуют** | Для решения проблемы требуются данные, которые не были собраны | Проект не может начаться; месяцы потрачены на технико-экономическое обоснование |
| **Целевая точность без учета бизнес-контекста** | «Нам нужна точность 95 %» — но что это значит для бизнеса? | Модель соответствует точности, но не решает бизнес-задачу |
| **Игнорируя цену ошибок** | Ложноположительные и ложноотрицательные результаты имеют разную стоимость | Модель оптимизирует не ту метрику |
| **Нет базовой линии** | Никакого сравнения с существующим подходом | Не могу сказать, действительно ли машинное обучение лучше простой эвристики |

## Ожидания не оправдываются
### Цикл ажиотажа в проектах машинного обучения
| Фаза | Описание | Риск |
|-------|-------------|------|
| **Волнение** | «ИИ все решит!» | Слишком многообещающий; недостаточное обеспечение |
| **Проверка концепции** | Модель работает над чистыми данными в блокнотах | Ложная уверенность; "оно работает!" |
| **Проверка реальности** | Производственные данные беспорядочны; производительность падает | Разочарование; «ML не работает» |
| **Марш смерти** | Команда пытается запустить его в производство | Технический долг; выгорание |
| **Отказ или тихое развертывание** | Проект отменен или развернут без мониторинга | Напрасные инвестиции |
### Управление ожиданиями
| Стратегия | Описание |
|----------|-------------|
| **Начните с базового уровня** | Сравните с простейшим возможным подходом (правила; деятельность человека) |
| **Определите показатели успеха заранее** | Бизнес-показатели (выручка; экономия затрат), а не только показатели машинного обучения (точность; F1) |
| **Исследование временных рамок** | Дайте команде 2–4 недели на оценку осуществимости перед принятием решения |
| **Покажите, чего не может ML** | Будьте честны в отношении ограничений; установить реалистичные ожидания |
| **Итерировать постепенно** | Сначала разверните простую модель; улучшать итеративно |
| **Подсчитайте цену ошибок** | Превратите эффективность модели в влияние на бизнес |

## Сбои развертывания
### Почему модели не доходят до производства
| Проблема | Описание | Решение |
|---------|-------------|----------|
| **Ноутбук для производственного разрыва** | Код работает в Jupyter, но не готов к использованию | практика MLOps; CI/CD для машинного обучения; проверка кода |
| **Требования к задержке** | Вывод модели слишком медленный для использования в реальном времени | оптимизация модели; квантование; кэширование |
| **Масштабируемость** | Модель не справляется с производственным трафиком | Пакетная обработка; горизонтальное масштабирование; модель обслуживающей инфраструктуры |
| **Пробелы в мониторинге** | Невозможно определить, когда модель ухудшается | Мониторинг дрейфа данных; мониторинг производительности; оповещение |
| **Управление зависимостями** | Условия обучения и обслуживания различаются | Контейнеризация; воспроизводимые среды |
| **Плана отката нет** | Невозможно вернуться к предыдущей модели, если новая модель выходит из строя | Модельный реестр; версионирование; автоматический откат |
### Распад модели
| Тип | Описание | Обнаружение |
|------|-------------|-----------|
| **Дрейф данных** | Изменение распределения входных объектов | Отслеживать статистику функций; Дивергенция КЛ; ПСИ |
| **Дрейф концепции** | Связь между функциями и целевыми изменениями | Отслеживание точности прогнозов с течением времени |
| **Смещение ярлыка** | Определение или распространение целевых изменений | Отслеживать распространение этикеток; корреляция бизнес-показателей |
| **Изменения в восходящем направлении** | Источник данных меняет формат, время или качество | Проверка схемы; контроль свежести |

## Организационные неудачи
| Неудача | Описание | Профилактика |
|---------|-------------|------------|
| **Нет четкого права собственности** | Никто не несет ответственности за модель в производстве | Назначьте владельцев модели; определить RACI |
| **Разрозненные команды** | Ученые, работающие с данными, строят модели; инженеры развертывают; никто не общается | Межфункциональные команды; общие цели |
| **Нет срока погашения MLOps** | Нет реестра моделей; нет CI/CD; нет мониторинга | Инвестируйте в инфраструктуру MLOps постепенно |
| **Нереальные сроки** | «Создайте производственную систему машинного обучения за 2 недели» | Исследование временных рамок; повторять; сообщить о сложности |
| **Недостаток знаний в предметной области** | Команда ML не понимает бизнес-проблем | Встраивайте экспертов предметной области в команды ML |
| **Нет системы оценки** | Не могу сказать, работает ли модель в производстве | Определить бизнес-метрики; настроить дашборды; регулярные обзоры |

## Извлеченные уроки
### Контрольный список проекта ML
| Фаза | Ключевой вопрос |
|-------|-------------|
| **Определение проблемы** | Это действительно проблема ML? Какова базовая линия? Как выглядит успех? |
| **Оценка данных** | Достаточно ли у нас данных? Это репрезентативно? Надёжны ли этикетки? |
| **Осуществимость** | Можем ли мы построить рабочий прототип за 2-4 недели? Каковы риски? |
| **Разработка** | Есть ли утечка данных? Используем ли мы правильную метрику оценки? |
| **Предварительная подготовка** | Работает ли он с производственными данными? Это достаточно быстро? Это контролируется? |
| **Развертывание** | Можем ли мы откатиться назад? Кто на связи? Что происходит, когда он деградирует? |
| **После развертывания** | Мы следим за дрейфом? Отслеживаются ли бизнес-показатели? Есть ли план переподготовки? |

## Краткое содержание
Проекты ML терпят неудачу не потому, что алгоритмы слишком сложны, а потому, что процесс вокруг них сломан. Проблемы с данными — недостаточность данных, плохая маркировка, утечка, дрейф — составляют наибольшую долю неудач. Неудачи в определении проблемы — решение неправильной проблемы, использование машинного обучения, когда правил достаточно, игнорирование цены ошибок — трата месяцев усилий. Неоправданные ожидания — чрезмерные обещания, недостаточный результат, неуправление заинтересованными сторонами — разрушают доверие организации к МО. Сбои при развертывании (отставание ноутбука от производства, проблемы с задержкой, отсутствие мониторинга) означают, что модели, которые работают в разработке, никогда не приносят пользы в производстве. Организационные сбои — отсутствие собственности, разрозненные команды, отсутствие MLOps — делают структурно невозможным достижение успеха. Противоядием является дисциплинированная практика: начните с базового уровня; исследование временных рамок; тщательно проверять данные; проверить на утечку; определить бизнес-метрики; развертывать постепенно; постоянно контролировать; и повторить. Лучшие команды ML тратят больше времени на данные и обработку, чем на модели.
