# Прометей и Графана
Prometheus — это набор инструментов для мониторинга и оповещения с открытым исходным кодом, разработанный для надежности и масштабируемости. Grafana — ведущая платформа с открытым исходным кодом для визуализации данных временных рядов. Вместе они образуют самый популярный стек мониторинга для современной инфраструктуры и приложений. Prometheus собирает и хранит метрики; Grafana отображает их на информационных панелях.
---

## Архитектура Прометея
| Компонент | Описание |
|-----------|-------------|
| **Сервер Прометея** | Собирает метрики с целей; хранит данные временных рядов; оценивает правила оповещений |
| **Экспортер** | Предоставляет метрики из системы (Node Exporter, cAdvisor и т. д.) |
| **Пушгейтвей** | Получает метрики от кратковременных заданий (пакетные задания, CI) |
| **Менеджер оповещений** | Обрабатывает оповещения: группировка, отключение звука, маршрутизация, блокировка |
| **Обнаружение службы** | Автоматически обнаруживает цели (Kubernetes, Consul, EC2 и т. д.) |
---

## Ключевые понятия
| Концепция | Описание |
|---------|-------------|
| **Метрика** | Именованное измерение с дополнительными метками и значением |
| **Временной ряд** | Поток точек данных для определенной комбинации метрики + метки |
| **Вакансия** | Коллекция мишеней с той же целью |
| **Экземпляр** | Одна цель для парсинга (обычно процесс) |
| **Поцарапать** | Prometheus извлекает метрики из цели через регулярные промежутки времени |
| **Ярлык** | Пара ключ-значение, определяющая метрику (например, `method="GET"`) |
| **Образец** | Значение в определенный момент времени: (метка времени, значение) |
---

## Типы метрик
| Тип | Описание | Вариант использования |
|------|-------------|----------|
| **Счетчик** | Монотонно увеличивающееся значение (только вверх) | Количество запросов; ошибки; выполненные задачи |
| **Датчик** | Значение, которое может увеличиваться или уменьшаться | Температура; использование памяти; длина очереди |
| **Гистограмма** | Наблюдения, распределенные по значениям | Задержка запроса; размер ответа |
| **Сводка** | Аналогично гистограмме; вычисляет квантили на стороне клиента | Процентили задержки |

## PromQL (язык запросов)
### Основные запросы
| Запрос | Описание |
|-------|-------------|
| `http_requests_total`| Необработанные временные ряды |
| `http_requests_total{method="GET"}`| Фильтровать по метке |
| `http_requests_total{method="GET", status="200"}`| Фильтры с несколькими метками |
| `rate(http_requests_total[5m])`| Посекундная ставка за 5 минут |
| `increase(http_requests_total[1h])`| Общий прирост за 1 час |
| `sum(rate(http_requests_total[5m])) by (status)`| Совокупная ставка по статусу |
| `histogram_quantile(0.95, rate(http_duration_bucket[5m]))`| Задержка 95-го процентиля |
| `avg(node_cpu_seconds_total{mode="idle"})`| Средний простой процессора |
| `1 - avg(rate(node_cpu_seconds_total{mode="idle"}[5m]))`| Загрузка процессора |
### Общие функции
| Функция | Описание | Пример |
|----------|-------------|---------|
| `rate()`| Среднесекундная скорость увеличения | `rate(requests_total[5m])`|
| `irate()`| Посекундная ставка на основе последних двух точек данных | `irate(requests_total[1m])`|
| `increase()`| Общий прирост за период времени | `increase(errors_total[1h])`|
| `sum()`| Сумма по сериям | `sum(rate(requests_total[5m])) by (service)`|
| `avg()`| Среднее значение по серии | `avg(node_memory_usage)`|
| `histogram_quantile()`| Рассчитать квантиль по гистограмме | `histogram_quantile(0.99, rate(duration_bucket[5m]))`|
| `topk()`| Топ серии K по стоимости | `topk(5, rate(requests_total[5m]))`|
| `predict_linear()`| Линейное предсказание | `predict_linear(disk_usage[1h], 4*3600)`|
| `absent()`| Проверьте, отсутствует ли метрика | `absent(up{job="myapp"})`|

## Графана
### Ключевые понятия
| Концепция | Описание |
|---------|-------------|
| **Источник данных** | Подключение к Prometheus (или другим бэкэндам) |
| **Панель управления** | Коллекция панно, расположенных в макете |
| **Панель** | Единая визуализация (график, датчик, таблица, тепловая карта) |
| **Переменная** | Динамический фильтр для информационных панелей (например, выбор экземпляра) |
| **Аннотация** | Отмечайте события на графиках (развертывания, инциденты) |
| **Правило оповещений** | Пороговые оповещения в Grafana |
| **Шаблоны** | Многоразовые шаблоны информационных панелей с переменными |
### Полезные шаблоны информационных панелей
| Узор | Описание |
|---------|-------------|
| **Строка обзора** | Краткий обзор ключевых показателей: частота ошибок, задержка, пропускная способность |
| **Детализация** | Нажмите от сводки к подробному представлению с использованием переменных |
| **Метод RED** | Частота, ошибки, продолжительность — три ключевых показателя сервиса |
| **Метод ИСПОЛЬЗОВАТЬ** | Использование, Насыщение, Ошибки — для инфраструктуры |
| **Золотые сигналы** | Задержка, трафик, ошибки, насыщенность (книга Google SRE) |

## Оповещение
### Структура правила оповещения
```yaml
groups:
  - name: example
    rules:
      - alert: HighErrorRate
        expr: rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m]) > 0.05
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "High error rate on {{ $labels.instance }}"
          description: "Error rate is {{ $value | humanizePercentage }}"
```

### Маршрутизация диспетчера оповещений
| Концепция | Описание |
|---------|-------------|
| **Группа** | Объедините похожие оповещения в одно уведомление |
| **Маршрут** | Дерево сопоставлений, определяющее, куда направляются оповещения |
| **Приёмник** | Куда отправлять оповещения (электронная почта, Slack, PagerDuty, вебхук) |
| **Запретить** | Подавлять оповещения при срабатывании другого оповещения |
| **Молчание** | Временно отключить оповещения с помощью средства сопоставления меток |

## Поиск неисправностей
| Проблема | Решение |
|---------|----------|
| **Цель вниз** | Проверьте, запущен ли экспортер; проверьте сеть/брандмауэр; проверить конфигурацию очистки |
| **Нет данных** | Проверьте правильность написания имени метрики; проверьте фильтры меток; проверить временной диапазон |
| **Высокая мощность** | Слишком много комбинаций ярлыков; уменьшить значения меток; использовать правила записи |
| **Медленные запросы** | Используйте правила записи для сложных запросов; увеличить интервал очистки |
| **Предупреждение об усталости** | Тюнинг порогов; добавить продолжительность `for`; оповещения, связанные с группой |
| **Отсутствуют метрики после перезапуска** | Prometheus хранит данные локально; проверить настройки хранения |

## Краткое содержание
Prometheus контролирует системы, регулярно собирая показатели от экспортеров. Метрики бывают четырех типов: счетчики (изменяются только вверх), датчики (вверх и вниз), гистограммы (группированные наблюдения) и сводки (квантили). PromQL — это язык запросов — `rate()`, `increase()`, `histogram_quantile()`, а функции агрегации (`sum`, `avg`) — наиболее распространенные операции. Grafana визуализирует данные Prometheus на информационных панелях с панелями, переменными и аннотациями. Alerting использует Alertmanager для группировки, маршрутизации, отключения звука и запрета оповещений. Ключевыми шаблонами мониторинга являются золотые сигналы Google (задержка, трафик, ошибки, насыщение) и метод RED (частота, ошибки, продолжительность) для сервисов и метод USE (загрузка, насыщение, ошибки) для инфраструктуры.
