# Конфигурация конвейера CI/CD
Конвейеры непрерывной интеграции (CI) и непрерывного развертывания (CD) автоматизируют процесс создания, тестирования и развертывания программного обеспечения. В этом справочнике рассматриваются шаблоны конфигурации для наиболее популярных платформ CI/CD: GitHub Actions, GitLab CI и общие принципы проектирования конвейеров.
---

## Действия GitHub
### Структура рабочего процесса
```yaml
name: CI Pipeline
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up language
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - name: Install dependencies
        run: pip install -r requirements.txt
      - name: Run tests
        run: pytest
      - name: Build
        run: python setup.py build
```

### Общие триггеры
| Триггер | Описание |
|---------|-------------|
| `on: push`| При каждом нажатии |
| `on: pull_request`| По PR открывайте, обновляйте, открывайте заново |
| `on: schedule`| Расписание на основе Cron |
| `on: workflow_dispatch`| Ручной триггер |
| `on: release`| О создании релиза |
| `on: workflow_call`| Вызывается другим рабочим процессом (многоразового использования) |
### Ключевые особенности
| Особенность | Описание |
|---------|-------------|
| **Матричная стратегия** | Запуск одного и того же задания с разными конфигурациями |
| **Секреты** | Зашифрованные переменные среды (`${{ secrets.MY_SECRET }}`) |
| **Окружающая среда** | Цели развертывания с правилами защиты |
| **Кэширование** | Зависимости кэша между запусками |
| **Артефакты** | Загрузка файлов из заданий (отчеты испытаний, сборки) |
| **Многоразовые рабочие процессы** | Совместное использование логики рабочего процесса в репозиториях |
| **Комплексные действия** | Объедините несколько шагов в одно действие |
### Матричная стратегия
```yaml
jobs:
  test:
    strategy:
      matrix:
        python-version: ['3.10', '3.11', '3.12']
        os: [ubuntu-latest, macos-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
```

## GitLab CI
### Структура конвейера
```yaml
stages:
  - build
  - test
  - deploy

build:
  stage: build
  script:
    - docker build -t myapp:$CI_COMMIT_SHA .
    - docker push myapp:$CI_COMMIT_SHA

test:
  stage: test
  script:
    - docker run myapp:$CI_COMMIT_SHA pytest

deploy:
  stage: deploy
  script:
    - deploy.sh $CI_COMMIT_SHA
  only:
    - main
  when: manual
```

### Ключевые слова
| Ключевое слово | Описание |
|---------|-------------|
| `stages`| Определение этапов конвейера и их порядок |
| `stage`| Назначить задание этапу |
| `script`| Команды для выполнения |
| `before_script`| Команды выполняются перед основным скриптом |
| `after_script`| Команды выполняются после основного сценария (даже в случае сбоя) |
| `only / except`| Контроль выполнения заданий (ветки, теги) |
| `rules`| Более гибкая версия только/кроме |
| `variables`| Определить переменные CI/CD |
| `cache`| Кэшировать файлы между запусками конвейера |
| `artifacts`| Файлы для передачи между заданиями |
| `environment`| Среда развертывания |
| `when`| Управление выполнением заданий (при_успехе, при_сбое, вручную, всегда) |
| `needs`| Укажите зависимости задания (режим DAG) |
| `extends`| Унаследовать конфигурацию от другого задания |
| `include`| Импорт внешних файлов YAML |
### Предопределенные переменные
| Переменная | Описание |
|----------|-------------|
| `$CI_COMMIT_SHA`| Текущий хеш коммита |
| `$CI_COMMIT_REF_NAME`| Имя ветки или тега |
| `$CI_PIPELINE_ID`| Идентификатор конвейера |
| `$CI_JOB_ID`| Идентификатор вакансии |
| `$CI_PROJECT_DIR`| Полный путь к проекту |
| `$CI_REGISTRY`| URL-адрес реестра контейнеров |
| `$CI_DEFAULT_BRANCH`| Имя ветки по умолчанию |

## Шаблоны проектирования конвейеров
### Общие шаблоны
| Узор | Описание |
|---------|-------------|
| **Создайте один раз, разверните много** | Постройте артефакт один раз; развернуть один и тот же артефакт в каждой среде |
| **Проверка ворот** | Утверждение вручную перед развертыванием производства |
| **Флаги функций** | Развернуть в рабочей среде, но спрятаться за флагом функции |
| **Канарское развертывание** | Развертывание на небольшой процент; монитор; развернуть |
| **Сине-зеленое развертывание** | Две идентичные среды; переключить трафик |
| **Параллельное тестирование** | Запускайте наборы тестов параллельно, чтобы сократить время конвейера |
| **Сначала ворс** | Запускайте линтеры перед дорогостоящими тестами; быстро потерпеть неудачу |
| **Зависимости кэша** | Кэшируйте node_modules, pip, Maven для ускорения сборки |
### Этапы конвейера (типично)
| Этап | Цель |
|-------|---------|
| **Линт** | Стиль кода и статический анализ |
| **Строить** | Скомпилировать; пучок; создавать артефакты |
| **Юнит-тест** | Быстрые тесты; нет внешних зависимостей |
| **Интеграционный тест** | Тесты с базами данных; API; внешние услуги |
| **Сканирование безопасности** | Уязвимости зависимостей; секретное сканирование; САСТ |
| **Пакет** | Создать образ Docker; построить артефакты выпуска |
| **Развертывание промежуточного уровня** | Развертывание в промежуточной среде |
| **Тест E2E** | Полные тесты системы на предмет постановки |
| **Развертывание производства** | Развертывание в производстве (ручное или автоматическое) |
| **Тест на дым** | Убедитесь, что развертывание работоспособно |

## Стратегии кэширования
| Язык/Инструмент | Путь к кэшу | Пример |
|----------------|-----------|---------|
| **Питон (пип)** | `~/.cache/pip`| `actions/cache`с ключом из хеша`requirements.txt`|
| **Node.js (npm)** | `~/.npm`| `actions/setup-node`со встроенным кэшированием |
| **Ява (Maven)** | `~/.m2/repository`| Кэш с ключом из хеша`pom.xml`|
| **Ява (Gradle)** | `~/.gradle/caches`| Кэш с ключом из хеша`build.gradle`|
| **Вперёд** | `~/go/pkg/mod`| Кэш с ключом из хеша`go.sum`|
| **Ржавчина (Груз)** | `~/.cargo/registry`| Кэш с ключом из хеша`Cargo.lock`|
| **Докер** | Кэширование слоев Docker | `docker/build-push-action`с кэшем |

## Поиск неисправностей
| Проблема | Решение |
|---------|----------|
| **Конвейер работает медленно** | Зависимости кэша; распараллеливать задания; используйте базовые изображения меньшего размера |
| **Секреты недоступны** | Проверьте секретное имя; проверить область действия среды; проверить вилку PR-ограничения |
| **Артефакт слишком велик** | Исключите ненужные файлы; компресс; используйте более короткое время хранения |
| **Матрица слишком велика** | Уменьшите комбинации; используйте `include`/`exclude` |
| **Ненадежные тесты** | Карантинные слоеные тесты; устранить первопричину; повторить попытку с помощью`retry:`|
| **В разрешении отказано** | Проверьте области действия токена; проверить разрешения бегуна |

## Краткое содержание
Конвейеры CI/CD автоматизируют сборку, тестирование и развертывание программного обеспечения. GitHub Actions использует рабочие процессы YAML, запускаемые событиями репозитория; GitLab CI использует этапы и задания с гибкими правилами. Ключевые шаблоны включают в себя: построить один раз, развернуть множество; проверка ворот перед производством; сначала проверьте для быстрой обратной связи; кэширование зависимостей для ускорения сборки; и распараллеливать тесты. Этапы конвейера обычно состоят из lint → сборка → тестирование → безопасность → пакет → развертывание → дымовое тестирование. Стратегии кэширования различаются в зависимости от языка, но следуют одному и тому же принципу: каталоги зависимостей кэша, защищенные хэшами файлов блокировки. Целью является быстрая и надежная обратная связь по каждому изменению и безопасное и воспроизводимое внедрение в рабочую среду.
