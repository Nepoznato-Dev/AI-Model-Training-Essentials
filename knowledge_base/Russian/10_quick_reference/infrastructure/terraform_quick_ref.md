# Терраформирование и инфраструктура как код
Terraform — наиболее широко используемый инструмент «Инфраструктура как код» (IaC). Он позволяет определять облачную инфраструктуру (серверы, базы данных, сети, разрешения) в декларативных файлах конфигурации, которые можно управлять версиями, просматривать, тестировать и автоматизировать. Вместо того, чтобы использовать облачную консоль, вы пишете код, описывающий желаемое состояние вашей инфраструктуры, а Terraform определяет, какие изменения следует внести.
---

## Основные понятия
| Концепция | Описание |
|---------|-------------|
| **Поставщик** | Плагин, управляющий конкретной облачной платформой (AWS, Azure, GCP и т. д.) |
| **Ресурс** | Объект инфраструктуры (сервер, база данных, сеть) |
| **Штат** | Информация Terraform о существующей инфраструктуре; хранится в файле состояния |
| **План** | Предварительный обзор изменений, которые внесет Terraform |
| **Применить** | Выполнить план; создать/обновить/уничтожить инфраструктуру |
| **Модуль** | Многоразовая коллекция ресурсов |
| **Переменная** | Входной параметр для конфигураций |
| **Выход** | Значение, экспортированное из модуля или конфигурации |
| **Источник данных** | Чтение информации из существующей инфраструктуры |
---

## Основной рабочий процесс
| Шаг | Команда | Описание |
|------|---------|-------------|
| **1. Запись конфигурации** | Создать файлы`.tf`| Определить поставщиков, ресурсы, переменные |
| **2. Инициализировать** | `terraform init`| Скачать провайдеров; настроить серверную часть |
| **3. Формат** | `terraform fmt`| Стандартизировать форматирование |
| **4. Подтвердить** | `terraform validate`| Проверьте синтаксис и конфигурацию |
| **5. План** | `terraform plan`| Предварительный просмотр изменений (пробный прогон) |
| **6. Подать заявку** | `terraform apply`| Создать или обновить инфраструктуру |
| **7. Уничтожить** | `terraform destroy`| Снести всю управляемую инфраструктуру |
---

## Общие команды
| Команда | Описание |
|---------|-------------|
| `terraform init`| Инициализировать рабочий каталог; поставщики и модули загрузки |
| `terraform plan`| Показать, какие изменения будут внесены |
| `terraform apply`| Применить изменения; добавьте `-auto-approve`, чтобы пропустить подтверждение |
| `terraform destroy`| Уничтожить все управляемые ресурсы |
| `terraform fmt`| Отформатировать файлы конфигурации в стандартном стиле |
| `terraform validate`| Проверка синтаксиса конфигурации |
| `terraform output`| Показать выходные значения |
| `terraform state list`| Перечислите все ресурсы в штате |
| `terraform state show <resource>`| Показать детали конкретного ресурса |
| `terraform import <resource> <id>`| Импортировать существующую инфраструктуру в штат |
| `terraform taint <resource>`| Отметить ресурс для отдыха при следующей подаче |
| `terraform refresh`| Обновление состояния в соответствии с реальной инфраструктурой |
| `terraform graph`| Создайте визуальный график зависимостей (формат DOT) |
| `terraform console`| Интерактивная консоль для проверки выражений |
---

## Управление состоянием
| Лучшая практика | Описание |
|--------------|-------------|
| **Удаленное состояние** | Сохраняйте состояние в S3, GCS, Azure Blob или Terraform Cloud — никогда локально |
| **Государственная блокировка** | Используйте DynamoDB (серверная часть S3) или встроенную блокировку для предотвращения одновременных изменений |
| **Государственное шифрование** | Включить шифрование неактивных файлов состояния (они содержат конфиденциальные данные) |
| **Государственное разделение** | Используйте отдельные файлы состояния для разных сред или команд |
| **Резервное копирование состояния** | Удаленные серверные части автоматически изменяют состояние версии; оставить это включенным |
| **Никогда не редактируйте состояние вручную** | Вместо этого используйте `terraform state mv`, `rm`,`import`|

## Структура модуля
```
module/
├── main.tf          # Primary resources
├── variables.tf     # Input variables
├── outputs.tf       # Output values
├── versions.tf      # Provider and Terraform version constraints
├── README.md        # Documentation
└── examples/        # Example usage
    └── basic/
        └── main.tf
```

## Типы переменных
| Тип | Пример | Вариант использования |
|------|---------|----------|
| **строка** | `variable "region" { type = string }`| Одно текстовое значение |
| **номер** | `variable "count" { type = number }`| Числовое значение |
| **бул** | `variable "enable" { type = bool }`| Флаг «истина/ложь» |
| **список** | `variable "zones" { type = list(string) }`| Заказанная коллекция |
| **карта** | `variable "tags" { type = map(string) }`| Пары ключ-значение |
| **объект** | `variable "config" { type = object({...}) }`| Структурированная конфигурация |

## Общие шаблоны
| Узор | Описание |
|---------|-------------|
| **Счет** | `count = 3`создает несколько экземпляров ресурса |
| **Для каждого** | `for_each = var.items`перебирает карту или набор |
| **Динамические блоки** | Генерировать повторяющиеся вложенные блоки (например, правила входа) |
| **Местные ценности** | `locals { ... }`для вычисления значений и уменьшения повторения |
| **Источники данных** | Прочтите существующую инфраструктуру (например, найдите существующий VPC) |
| **Поставщики** | Запускать сценарии на ресурсах после создания (используйте экономно) |
| **Рабочие пространства** | Отдельное состояние для разных сред в одной конфигурации |

## Поиск неисправностей
| Проблема | Решение |
|---------|----------|
| **Дрейф состояния** | Запустите `terraform plan`, чтобы увидеть различия; `terraform apply`для согласования |
| **Заблокированное состояние** | Проверьте, у кого есть замок; используйте `terraform force-unlock`, если безопасно |
| **Ошибки поставщика** | Проверьте учетные данные; обновить версию провайдера; проверить ограничения API |
| **Конфликты импорта** | Ресурс уже в состоянии; сначала используйте`terraform state rm`|
| **Циркулярные зависимости** | Реструктуризация ресурсов; используйте`depends_on`осторожно |
| **Большой штат** | Разделить на модули; используйте`-target`для частичных операций |
---

## Краткое содержание
Terraform управляет инфраструктурой с помощью файлов декларативной конфигурации. Рабочий процесс: запись конфигурации → инициализация → план → применение. Состояние отслеживает то, что существует, и должно храниться удаленно с блокировкой. Модули позволяют повторное использование. Переменные параметризируют конфигурации. Ключевыми принципами являются: относиться к инфраструктуре как к коду (контроль версий, проверка, тестирование); никогда не редактируйте состояние вручную; планируйте перед подачей заявки; использовать удаленное состояние с блокировкой; и структурировать конфигурации с модулями для удобства обслуживания.
