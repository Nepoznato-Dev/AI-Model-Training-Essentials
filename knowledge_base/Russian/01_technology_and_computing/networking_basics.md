# Основы сетевых технологий

Практический справочник для разработчиков и системных администраторов — основные понятия, протоколы, команды и методы устранения неполадок.

---

## Модель OSI (7 уровней)

Концептуальная модель для понимания сетевого взаимодействия.

| Уровень | Название | Функция | Примеры протоколов |
|-------|------|----------|-------------------|
| 7 | Прикладной | Сервисы для конечного пользователя | HTTP, HTTPS, FTP, SMTP, DNS, SSH |
| 6 | Уровень представления | Форматирование данных, шифрование, сжатие | TLS, JPEG, ASCII |
| 5 | Сеансовый | Управление соединением | NetBIOS, RPC |
| 4 | Транспортный | Сквозная доставка, исправление ошибок, управление потоком | TCP, UDP |
| 3 | Сетевой | Маршрутизация, адресация | IP, ICMP, OSPF, BGP |
| 2 | Канальный | Кадрирование, обнаружение ошибок, MAC-адреса | Ethernet, Wi-Fi, PPP |
| 1 | Физический | Передача необработанных битов | Ethernet-кабели, оптоволокно, радиоволны |

На практике для интернета чаще используется **модель TCP/IP** (4 уровня: канальный, интернет, транспортный, прикладной).

## IP-адресация

### IPv4
- 32-битный адрес, записывается как четыре октета: `192.168.1.1`
- Всего: ~4,3 миллиарда адресов (но на практике они исчерпаны).

### IPv6
- 128-битный адрес, записывается в шестнадцатеричном виде: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`
- Всего: 2¹²⁸ адресов (практически бесконечно).

### Диапазоны частных IP-адресов (RFC 1918)
Они не маршрутизируются в интернете; используются внутри локальных сетей:
- `10.0.0.0/8` (10.0.0.0 – 10.255.255.255)
- `172.16.0.0/12` (172.16.0.0 – 172.31.255.255)
- `192.168.0.0/16` (192.168.0.0 – 192.168.255.255)

### Нотация CIDR
`192.168.1.0/24` означает, что первые 24 бита — это префикс сети; последние 8 бит — хосты. Диапазон включает адреса от `192.168.1.0` до `192.168.1.255`.

## DNS (Domain Name System)

Сопоставляет доменные имена (например, `example.com`) с IP-адресами.

### Типы записей
| Тип | Назначение |
|------|---------|
| **A** | Сопоставляет домен с IPv4-адресом |
| **AAAA** | Сопоставляет домен с IPv6-адресом |
| **CNAME** | Псевдоним другого доменного имени |
| **MX** | Сервер обмена почтой |
| **TXT** | Произвольный текст (SPF, DKIM, подтверждение владения) |
| **NS** | Сервер имён для домена |
| **SRV** | Запись сервиса (например, для SIP) |

### Основные инструменты
```bash
dig example.com            # Подробный DNS-запрос
nslookup example.com       # Более простой DNS-запрос
host example.com           # Быстрая проверка
dig -x 8.8.8.8             # Обратный поиск (IP -> имя)
```

### TCP и UDP
| Характеристика | TCP | UDP |
|----------------|-----|-----|
| Соединение | С установлением соединения (handshake) | Без установления соединения |
| Надёжность | Гарантированная доставка, повторная передача | По возможности, возможна потеря пакетов |
| Порядок | Сохраняет порядок | Порядок не гарантируется |
| Управление потоком | Да (скользящее окно) | Нет |
| Сценарии использования | Веб (HTTP), почта, SSH, передача файлов | DNS, потоковое видео, VoIP, игры, SNMP |
| Размер заголовка | 20–60 байт | 8 байт |

## HTTP и HTTPS

### Методы HTTP
- **GET**: Получить ресурс (идемпотентный, безопасный).
- **POST**: Отправить данные (неидемпотентный).
- **PUT**: Обновить или заменить ресурс (идемпотентный).
- **PATCH**: Частично обновить ресурс.
- **DELETE**: Удалить ресурс (идемпотентный).

### Коды состояния
- **1xx**: Информационные ответы (100 Continue).
- **2xx**: Успех (200 OK, 201 Created, 204 No Content).
- **3xx**: Перенаправление (301 Moved Permanently, 302 Found, 304 Not Modified).
- **4xx**: Ошибка клиента (400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 429 Too Many Requests).
- **5xx**: Ошибка сервера (500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable).

### Заголовки
- **Content-Type**: Тип содержимого (`application/json`, `text/html`).
- **Authorization**: Учётные данные (например, токен доступа в заголовке Bearer).
- **Cache-Control**: Политика кэширования.
- **CORS-заголовки**: `Access-Control-Allow-Origin` и другие.

### TLS/SSL
- Шифрует HTTP-трафик (HTTPS = HTTP поверх TLS).
- Сертификаты от центров сертификации (CA) подтверждают подлинность сервера.
- На стороне клиента нужно проверять цепочку сертификатов и имя хоста.

## Брандмауэры и NAT

### Брандмауэр
- Фильтрует трафик по правилам (IP-источник, IP-назначение, порт, протокол).
- Stateful-брандмауэры отслеживают состояние соединений.

### NAT (Network Address Translation)
- Преобразует частные IP-адреса в публичный IP для доступа в интернет.
- Перенаправление портов сопоставляет публичный порт с внутренним хостом или портом.

## Частые сетевые команды

### Проверка связности
```bash
ping google.com            # ICMP echo request
ping -c 4 8.8.8.8          # Отправить ping 4 раза
traceroute google.com      # Трассировка маршрута (Linux)
tracert google.com         # Версия для Windows
```

### Маршрутизация
```bash
ip route show              # Linux: таблица маршрутизации
route -n                   # Более старая команда Linux
netstat -r                 # Windows/Mac
```

### Сетевые интерфейсы
```bash
ip addr show               # Список интерфейсов и IP-адресов
ifconfig                   # Более старая команда
```

### DNS
```bash
dig example.com
nslookup example.com
host example.com
```

### Проверка доступности порта
```bash
nc -zv google.com 443      # Netcat: проверить, открыт ли порт 443
telnet google.com 443      # Подключение Telnet к порту
curl -v https://google.com # Подробный вывод
```

### Брандмауэр (Linux iptables/nftables)
```bash
sudo ufw status            # Ubuntu: простой брандмауэр
sudo iptables -L -n        # Список правил
```

### Сетевая статистика
```bash
ss -tulpn                  # Прослушиваемые сокеты (Linux)
netstat -an                # Все сокеты
```

## Балансировка нагрузки и обратные прокси

### Nginx как обратный прокси
```nginx
server {
    listen 80;
    server_name example.com;
    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### Алгоритмы балансировки
- **Round-robin**: запросы поочерёдно распределяются между серверами.
- **Наименьшее число соединений**: трафик идёт на сервер с наименьшим числом активных соединений.
- **IP hash**: привязывает клиента к серверу по IP-адресу.
- **Взвешенный round-robin**: серверам назначаются веса в зависимости от мощности.

### Инструменты
- Nginx, HAProxy — программные балансировщики.
- AWS ELB, Azure Load Balancer, GCP Cloud Load Balancing — облачные сервисы балансировки.

## Чеклист устранения неполадок

- Поднят ли физический канал? (Проверьте кабели, подключение Wi‑Fi.)
- Пингуется ли шлюз? (например, `ping 192.168.1.1`)
- Пингуется ли внешний IP? (например, `8.8.8.8`)
- Разрешается ли доменное имя? (`dig google.com`)
- Слушает ли приложение ожидаемый порт? (`ss -tulpn | grep 8080`)
- Не блокирует ли брандмауэр нужный порт? (Проверьте `iptables`/`ufw` или облачные группы безопасности.)
- Есть ли ошибки в логах приложения?
- Действителен ли и доверен ли TLS-сертификат? (`openssl s_client -connect example.com:443`)
