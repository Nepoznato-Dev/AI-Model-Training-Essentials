# Оперативное проектирование
Оперативное проектирование — это практика проектирования, уточнения и оптимизации подсказок ввода для получения наилучшего результата от языковой модели. Это одновременно искусство и наука, и это основной интерфейс для управления поведением LLM без тонкой настройки.
---

## Основные принципы
### Ясность и конкретика
Четкая подсказка не оставляет места для двусмысленности. Укажите именно то, что вы хотите, включая формат, длину и перспективу.
**Неясно:**
> «Расскажи мне о Python».
**Конкретно:**
> «Объясните глобальную блокировку интерпретатора Python (GIL). Опишите ее влияние на многопоточность, дайте один обходной путь и не превышайте 200 слов в ответе».
### Предоставьте контекст
Модели работают лучше, когда знают роль, аудиторию и цель.
**Без контекста:**
> «Напишите функцию для сортировки списка».
**С контекстом:**
> «Вы старший разработчик Python. Напишите функцию для сортировки списка словарей по заданному ключу. Используйте подсказки по типу и обрабатывайте крайние случаи. Аудитория — младшие разработчики».
### Используйте позитивные инструкции
Расскажите модели, что делать, а не чего следует избегать. «Не используйте жаргон» слабее, чем «Используйте простой язык, доступный 10-летнему ребенку».

## Структуры подсказок
### Роли системы/пользователя/помощника
Большинство API LLM поддерживают многоэтапную структуру:
- **Системное сообщение**: устанавливает поведение, характер и ограничения модели (сохраняется на протяжении всего сеанса).
- **Сообщение пользователя**: текущий запрос или инструкция.
- **Сообщение Ассистента**: предыдущие ответы модели (используются для непрерывности).
**Пример (стиль OpenAI API):**
Система: Вы полезный помощник по программированию. Вы отвечаете краткими примерами кода и краткими пояснениями. Никогда не предоставляйте небезопасный код.
Пользователь: напишите функцию Python для загрузки файла по URL-адресу.
### Подсказка о нескольких кадрах
Прежде чем просить модель выполнить задачу, приведите 2–3 примера желаемого формата ввода-вывода. Это учит шаблону.
**Пример:**
Пользователь: Преобразуйте эти предложения в пассивный залог:
Входные данные: Кот погнался за мышью.
Вывод: За мышью погнался кот.
Входные данные: Шеф-повар приготовил блюдо.
Вывод: Блюдо приготовил шеф-повар.
Сырье: Шторм разрушил дом.
Результат: (модель завершена)
### Цепочка мыслей (CoT)
Предложите модели шаг за шагом продемонстрировать свои рассуждения. Это повышает точность выполнения арифметических, логических и многошаговых задач.
**Без ЦТ:**
> «Что такое 24 × 37?»
**С ЦТ:**
> «Посчитайте 24×37. Покажите свои рассуждения шаг за шагом».
Модель будет производить промежуточные шаги, уменьшая арифметические ошибки.
### Структурированные выходные данные
Запросите определенный формат, например JSON, YAML или таблицы уценки, чтобы сделать анализ надежным.
Пользователь: перечислите три плюса и три минуса микросервисов. Возвращайте только действительный объект JSON с ключами «за» и «против», каждый из которых представляет собой массив строк.

## Продвинутые методы
### Самосогласованность
Создайте несколько ответов на один и тот же запрос (с температурой > 0) и проголосуйте большинством голосов за окончательный ответ. Это особенно эффективно для задач рассуждения.
### Древо мыслей
Исследуйте несколько путей рассуждения параллельно, оцените каждый и выберите лучший. Это метод исследовательского уровня, но его можно аппроксимировать, попросив модель «изучить альтернативные решения».
### ReAct (Рассуждение + Действие)
Пусть модель чередует рассуждения с вызовами инструментов. Он может думать, затем действовать (например, выполнять поиск в Интернете, запускать код), а затем снова думать, основываясь на результате.
**Приблизительная структура:**
У вас есть доступ к калькулятору и поисковой системе. Для каждого шага выведите:
Мысль: (ваши рассуждения)
Действие: (имя инструмента, ввод)
Наблюдение: (выход инструмента)
... продолжайте, пока не получите окончательный ответ.
### Назначение персонажа
Назначьте конкретного человека, который будет формировать ответ.
**Примеры:**
- «Вы разработчик ядра Linux и объясняете управление памятью новому выпускнику».
- «Вы дружелюбный диетолог, дающий клиенту общие советы».
— «Вы циничный технический критик, делающий обзор нового гаджета».

## Настройка параметров
- **Температура** (0,0–1,0+): контролирует случайность. Ниже = более детерминированно, выше = более креативно. Используйте 0,0–0,3 для фактических ответов; 0,7–1,0 за творческое письмо.
- **Top-p** (выборка ядра): отсекает вероятностную массу при определенном совокупном пороге. 0,9 означает, что модель выбрана из 90% наиболее вероятных токенов. Обычно регулируют либо температуру, либо верхнее давление, а не то и другое.
- **Макс. токенов**: устанавливает максимальную длину вывода. Не забудьте зарезервировать место для ответа в контекстном окне.
- **Штраф за частоту**: уменьшает повторение одних и тех же токенов.
- **Наказание за присутствие**: поощряет модель представлять новые темы.

## Распространенные ошибки и исправления
| Проблема | Вероятная причина | Исправить |
|---------|--------------|-----|
| Модель игнорирует части приглашения | Подсказка слишком длинная или перегружена | Сократить; поместите самую важную инструкцию в конец |
| Вывод слишком подробный | Нет ограничений по длине | Добавьте «Ограничить до 3 предложений» или установите max_tokens |
| Вывод слишком краток | Чрезмерно ограничительный | Добавьте «Объясните подробно» или уменьшите температуру |
| Фактические галлюцинации | Недостаточный контекст или неоднозначный вопрос | Добавьте «Если вы не уверены, скажите: «Я не знаю»» и предоставьте контекст RAG |
| Несогласованное форматирование | Нет явной инструкции по форматированию | Запросить JSON, таблицу уценки или маркированный список |
| Модель отвечает на неправильном языке | Нет языкового обучения | Явно укажите «Ответить на английском языке» (или на целевом языке) |

## Шаблоны подсказок для распространенных задач
### Подведение итогов
Обобщите следующий текст, разделив его на 3 пункта. Сосредоточьтесь на главных аргументах и ​​избегайте деталей.
Текст: [вставить текст]

### Генерация кода
Напишите [языковую] функцию, которая [делает X].
Требования:
Используйте подсказки по типу.
Включите строку документации.
Обработка крайних случаев: [список].
Не используйте внешние библиотеки, если не указано иное.

### Объяснение
Объясните [концепцию] [неспециалисту/студенту университета/ребёнку]. Используйте аналогию там, где это уместно.
### Мозговой штурм
Сгенерируйте 10 идей по [теме]. Для каждой идеи дайте описание в одно предложение и одну потенциальную задачу.
текст
### Классификация
Классифицируйте следующие отзывы клиентов как [положительные, нейтральные, отрицательные].
Укажите оценку уверенности (0–100) и краткую причину.
Обратная связь: [вставить текст]
### Перевод со стилем
Переведите следующий текст с английского на испанский. Используйте неформальный тон, подходящий для публикации в социальных сетях.
Текст: [вставить текст]

## Оценка подсказок
Относитесь к подсказкам как к коду: создайте их версии, протестируйте и повторите.
- **A/B-тестирование** различных вариантов подсказок по заданному набору запросов.
– **Оценивайте успех** с помощью человеческой оценки или автоматизированных показателей (например, точное соответствие, BLEU, индивидуальная оценка).
- **Сохраняйте реестр подсказок** (простой текстовый файл или электронную таблицу) с указанием подсказки, версии и наблюдаемой производительности.
