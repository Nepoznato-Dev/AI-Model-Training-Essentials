# Инжиниринг данных и конвейеры
Инженерия данных — это дисциплина создания систем, которые перемещают, преобразовывают и хранят данные в больших масштабах. Без надежных конвейеров данных невозможно обучить модели машинного обучения, информационные панели показывают устаревшие цифры, а бизнес-решения основаны на догадках. В этом файле описаны архитектура, инструменты и методы построения работающей инфраструктуры данных.
---

## ETL против ELT
| Подход | Как это работает | Лучшее для | Инструменты |
|----------|-------------|----------|-------|
| **ETL** (Извлечение → Преобразование → Загрузка) | Преобразование данных *перед* загрузкой на склад | Традиционные склады с ограниченными вычислительными ресурсами | Информатика, Таленд, Apache NiFi |
| **ELT** (Извлечение → Загрузка → Преобразование) | Сначала загрузите необработанные данные; преобразить *внутри* склада | Современные облачные склады с эластичными вычислениями | dbt, Fivetran, Airbyte + BigQuery/Snowflake |
Переход от ETL к ELT был обусловлен появлением облачных хранилищ данных (BigQuery, Snowflake, Redshift), которые могут масштабировать вычисления независимо от хранилища. Больше нет необходимости предварительно обрабатывать все перед загрузкой.
---

## Озера данных и хранилища данных
| Особенность | Озеро данных | Хранилище данных |
|---------|-----------|---------------|
| **Формат данных** | Необработанный, собственный формат (схема при чтении) | Структурировано, обработано (схема при записи) |
| **Схема** | Определяется во время запроса | Определяется перед загрузкой |
| **Типы данных** | Структурированные, полуструктурированные, неструктурированные | Первично структурированный |
| **Пользователи** | Специалисты по данным, инженеры | Бизнес-аналитики, инструменты BI |
| **Стоимость** | Дешевое хранилище (хранилище объектов) | Дороже (оптимизировано под запросы) |
| **Примеры** | AWS S3, Azure Data Lake, GCS | Снежинка, BigQuery, Redshift |
Современный подход — это «дом у озера»: объедините дешевое и гибкое хранилище в озере с функциями управления и производительности склада. Ключевыми технологиями здесь являются Delta Lake, Apache Iceberg и Apache Hudi.

## Архитектура конвейера
### Пакетная обработка против потоковой передачи
| Режим | Описание | Задержка | Вариант использования |
|------|-------------|---------|----------|
| **Пакет** | Обработка данных большими порциями через запланированные промежутки времени | От минут до часов | Ежедневные отчеты, задания ETL, обогащение данных |
| **Потоковая передача** | Непрерывная обработка данных по мере их поступления | Миллисекунды в секунды | Панели мониторинга в режиме реального времени, обнаружение мошенничества, оповещения |
| **Микропартия** | Небольшие партии с очень короткими интервалами | Секунды | Почти в реальном времени с простотой пакетной обработки |
### Компоненты трубопровода
Типичный конвейер данных состоит из следующих этапов:
| Этап | Описание | Инструменты |
|-------|-------------|-------|
| **Проглатывание** | Собрать данные из источников | Кафка, Аирбайт, Файтран, Дебезиум |
| **Трансформация** | Очистить, обогатить, агрегировать | дбт, Искра, Панды |
| **Хранение** | Сохранение обработанных данных | BigQuery, Снежинка, S3, Дельта-Лейк |
| **Обслуживание** | Сделайте данные доступными для потребителей | API, информационные панели, хранилища функций машинного обучения |
| **Аранжировка** | Планирование и управление зависимостями | Воздушный поток, Префект, Дагстер |
| **Мониторинг** | Отслеживайте состояние конвейера и качество данных | Большие надежды, Монте-Карло, персонализированные оповещения |

## Инструменты оркестрации
| Инструмент | Подход | Сила |
|------|----------|----------|
| **Apache Airflow** | группы обеспечения доступности баз данных на основе Python; отраслевой стандарт | Огромная экосистема, зрелая, гибкая |
| **Префект** | Python-родной; более чистый API, чем Airflow | Современный дизайн, отличная обработка ошибок |
| **Дагстер** | Ориентированность на активы; подход к разработке программного обеспечения | Система типов, тестирование, наблюдаемость |
| **Луиджи** | Оригинальный инструмент конвейера Spotify | Простой, но менее активно разрабатываемый |

    # Clean and process

## Апач Кафка
Kafka является основой многих систем данных реального времени. Это распределенный журнал событий, обеспечивающий высокопроизводительный и отказоустойчивый обмен сообщениями.
### Основные понятия
| Концепция | Описание |
|---------|-------------|
| **Тема** | Категория сообщений (например,`orders`,`user-events`) |
| **Раздел** | Темы разбиты на разделы для параллелизма |
| **Продюсер** | Приложение, которое пишет сообщения в темы |
| **Потребитель** | Приложение, читающее сообщения из тем |
| **Группа потребителей** | Группа потребителей, которые разделяют нагрузку от чтения темы |
| **Смещение** | Положение потребителя внутри перегородки |
| **Брокер** | Серверный узел Kafka |
### Когда использовать Кафку
- **Потоковая передача событий**: обработка событий в реальном времени в любом масштабе.
- **Разделение услуг**: производителям и потребителям не обязательно знать друг о друге.
- **Повтор**: сообщения сохраняются; потребители могут перечитать с любого смещения.
- **Обратное давление**: Kafka естественным образом учитывает разницу в скорости между производителями и потребителями.

## Моделирование данных
### Схема «Звезда» против схемы «Снежинка»
| Схема | Структура | Плюсы | Минусы |
|--------|-----------|------|------|
| **Звезда** | Центральная таблица фактов, окруженная денормализованными таблицами измерений | Простые запросы, быстрое чтение | Избыточность данных |
| **Снежинка** | Таблицы измерений нормализованы (разбиты на подтаблицы) | Меньше избыточности | Больше объединений, медленнее запросы |
### Таблицы фактов и измерений
| Тип таблицы | Содержит | Пример |
|-----------|----------|---------|
| **Факт** | Измеримые события (метрики) | `orders`(идентификатор_заказа, идентификатор_продукта, идентификатор_клиента, сумма, дата) |
| **Размер** | Описательные атрибуты | `products`(идентификатор_продукта, название, категория, цена),`customers`(идентификатор_клиента, имя, город) |

## Магазины функций
Хранилище функций — это централизованное хранилище функций ML — производных значений, используемых в качестве входных данных для моделей (например, «средняя стоимость заказа пользователя за последние 30 дней»).
| Возможность | Описание |
|-----------|-------------|
| **Реестр функций** | Каталог доступных функций с метаданными |
| **Офлайн-магазин** | Исторические особенности обучения модели (пакетное) |
| **Интернет-магазин** | Функция с малой задержкой, обеспечивающая вывод в реальном времени |
| **Мониторинг функций** | Обнаружение дрейфа, пропущенных значений, изменений распределения |
| Инструмент | Описание |
|------|-------------|
| **Праздник** | Открытый исходный код; работает с любой платформой машинного обучения |
| **Тектон** | Коммерческий; функциональная платформа реального времени |
| **Хмель** | Открытый исходный код; полная платформа машинного обучения с хранилищем функций |
| **Магазин компонентов Databricks** | Интегрировано с Databricks/Spark |

## Качество данных
Качество данных — тихий убийца проектов машинного обучения. Мусор на входе, мусор на выходе.
### Измерения качества
| Размерность | Вопрос |
|-----------|----------|
| **Точность** | Отражают ли данные реальность? |
| **Полнота** | Заполнены ли обязательные поля? |
| **Постоянство** | Согласуются ли ценности в разных источниках? |
| **Своевременность** | Данные актуальны? |
| **Срок действия** | Соответствуют ли ценности установленным правилам? |
| **Уникальность** | Есть ли повторяющиеся записи? |
### Инструменты качества данных
| Инструмент | Подход |
|------|----------|
| **Большие надежды** | на основе Python; определить «ожидания» относительно данных |
| **Монте-Карло** | Платформа наблюдения за данными на базе машинного обучения |
| **тесты БДТ** | Встроенные тесты для данных хранилища (уникальные, not_null, отношения) |
| **Газировка** | Сканирование качества данных с открытым исходным кодом |

## Управление данными
Управление данными обеспечивает ответственное управление данными во всей организации.
| Площадь | Описание |
|------|-------------|
| **Каталог данных** | Инвентаризация наборов данных с метаданными с возможностью поиска (Amundsen, DataHub, Atlan) |
| **Происхождение данных** | Отслеживайте, откуда берутся данные и как они преобразуются |
| **Контроль доступа** | Разрешения на основе ролей; кто что умеет читать/писать |
| **Соответствие** | Соблюдение GDPR, CCPA, HIPAA |
| **Владение данными** | Четкое право собственности на каждый набор данных (управление) |
| **Политика хранения** | Определите, как долго хранятся данные и когда они удаляются |

## Современный стек данных
«Современный стек данных» относится к типичной комбинации инструментов, используемых сегодня группами данных:
| Слой | Типовые инструменты |
|-------|--------------|
| **Проглатывание** | Файтран, Эйрбайт |
| **Склад** | Снежинка, BigQuery, Redshift |
| **Трансформация** | дбт |
| **Аранжировка** | Воздушный поток, Префект, Дагстер |
| **BI/Визуализация** | Looker, Метабаза, Таблицы |
| **Обратный ETL** | Census, Hightouch (синхронизация данных хранилища с инструментами) |
| **Качество данных** | Большие надежды, Монте-Карло |
Тенденция заключается в использовании модульных лучших в своем классе инструментов, связанных открытыми стандартами (SQL, модели dbt, DAG Airflow), а не монолитных платформ.
