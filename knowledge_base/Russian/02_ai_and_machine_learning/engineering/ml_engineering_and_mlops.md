# ML Engineering и MLOps
Построить модель машинного обучения — это только полдела. Ввод в эксплуатацию, поддержание надежной работы, отслеживание отклонения и итерации — вот где на помощь приходят машинное обучение и MLOps. Этот файл охватывает полный жизненный цикл от эксперимента до производственной системы.
---

## Жизненный цикл машинного обучения
| Фаза | Описание | Ключевые виды деятельности |
|-------|-------------|---------------|
| **1. Определение проблемы** | Представьте бизнес-проблему как задачу машинного обучения | Определить показатели, ограничения, критерии успеха |
| **2. Сбор данных** | Сбор и маркировка данных обучения | ETL, маркировка, расширение |
| **3. Экспериментирование** | Обучение и оценка моделей | Разработка функций, настройка гиперпараметров |
| **4. Выбор модели** | Выберите лучшую модель | Сравните показатели, оцените компромиссы |
| **5. Развертывание** | Отправьте модель в производство | Сервисная инфраструктура, API, пакетная обработка |
| **6. Мониторинг** | Следите за дрейфом и деградацией | Дрейф данных, дрейф концепции, производительность |
| **7. Переподготовка** | Обновите модель новыми данными | Плановая или плановая переподготовка |
Большая часть ценности (и сложности) находится на этапах 5–7. Модель, сидящая в блокноте Jupyter, не создает ценности для бизнеса.

## Модельные реестры
Реестр моделей — это централизованное хранилище для управления моделями машинного обучения — их версиями, метаданными, метриками и статусом развертывания.
| Возможность | Описание |
|-----------|-------------|
| **Версии** | Отслеживайте каждую версию модели по уникальному идентификатору |
| **Метаданные** | Данные обучения, гиперпараметры, метрики, автор |
| **Переходы между этапами** | Перемещайте модели по этапам: Постановка → Производство → В архив |
| **Происхождение** | Проследите, какие данные и код создали каждую модель |
| Инструмент | Описание |
|------|-------------|
| **Млфлов** | Открытый исходный код; реестр моделей + отслеживание экспериментов |
| **Вес и предвзятость (W&B)** | Коммерческий; отслеживание экспериментов + реестр моделей |
| **ДВЦ** | Управление версиями данных и моделей с помощью Git |
| **Azure ML/SageMaker** | Облачное управление моделями |
---

## Отслеживание экспериментов
Каждый эксперимент ML должен отслеживаться: какие данные использовались, какие гиперпараметры, какие метрики получались.
| Инструмент | Ключевые особенности |
|------|-------------|
| **Млфлов** | Открытый исходный код, самостоятельное размещение, отслеживание параметров/метрик/артефактов |
| **В&Б** | Богатый пользовательский интерфейс, очистка, управление версиями артефактов, отчеты |
| **Нептун** | Хранилище метаданных для MLOps |
| **Тензорборд** | Встроенный в TensorFlow; визуализировать кривые обучения |
### Что отслеживать
| Категория | Примеры |
|----------|---------|
| **Параметры** | Скорость обучения, размер пакета, архитектура модели, количество эпох |
| **Показатели** | Точность, потери, F1, AUC-ROC (за эпоху и финал) |
| **Артефакты** | Веса моделей, матрицы путаницы, выборки прогнозов |
| **Данные** | Версия набора данных, коэффициенты разделения, этапы предварительной обработки |
| **Окружающая среда** | Версия Python, версии библиотек, аппаратное обеспечение |

## Стратегии развертывания моделей
| Стратегия | Как это работает | Риск |
|----------|-------------|------|
| **Теневое развертывание** | Новая модель работает рядом со старой; прогнозы сравниваются, но не исполняются | Нулевой риск; проверяет перед запуском в эксплуатацию |
| **Канарский выпуск** | Направьте небольшой процент трафика на новую модель; постепенно увеличиваться | Низкий риск; быстрый откат |
| **A/B-тестирование** | Разделение пользователей на старых и новых; сравнить бизнес-показатели | Измеряет фактическое воздействие |
| **Сине-зеленый** | Две идентичные среды; переключить весь трафик сразу | Мгновенный откат; двойная стоимость при переходе |
| **Флаги функций** | Включение/выключение модели для каждого сегмента пользователя | Детальный контроль |

## Мониторинг систем машинного обучения
Системы машинного обучения нуждаются в большем мониторинге, чем традиционное программное обеспечение, поскольку сами данные могут меняться.
### Виды дрифта
| Тип дрейфа | Что меняется | Пример |
|-----------|-------------|---------|
| **Дрейф данных** | Изменения в распределении входных данных | Демография клиентов изменилась после маркетинговой кампании |
| **Концептуальный дрифт** | Связь между входными и выходными изменениями | Поведение потребителей меняется во время рецессии |
| **Смещение метки** | Изменения целевого распределения | Уровень мошенничества увеличился с 1% до 5% |
### Что отслеживать
| Категория | Метрики |
|----------|---------|
| **Производительность модели** | Точность, точность, полнота, F1, AUC (по сравнению с базовым уровнем) |
| **Качество данных** | Отсутствующие значения, распределение признаков, выбросы |
| **Обнаружение дрейфа** | Статистические тесты (тест KS, PSI, расхождение KL) |
| **Инфраструктура** | Задержка, пропускная способность, загрузка графического процессора, память |
| **Бизнес-показатели** | Коэффициент конверсии, влияние на доход, удовлетворенность пользователей |
### Инструменты мониторинга
| Инструмент | Тип |
|------|------|
| **Очевидно, ИИ** | Дрейф данных с открытым исходным кодом и мониторинг производительности модели |
| **Графана** | Визуализация дашборда (работает с Prometheus) |
| **WhyLabs** | Платформа наблюдения за данными |
| **Аризе** | Наблюдаемость машинного обучения и анализ первопричин |
| **Прометей + Графана** | Метрики инфраструктуры и приложений |

## Воспроизводимое обучение
Воспроизводимость означает, что вы можете повторить эксперимент и получить тот же результат. Это важно для отладки, аудита и обеспечения соответствия.
### Требования
| Требование | Как этого достичь |
|-------------|-------------------|
| **Версии данных** | DVC, Delta Lake или снимки набора данных с хэшами |
| **Версия кода** | Git для всего обучающего кода |
| **Закрепление среды** |  `requirements.txt`, `conda env`, образы Docker с точными версиями |
| **Настройка семян** | Исправить случайные начальные значения для numpy, torch, tensorflow |
| **Управление конфигурациями** | Конфигурации Hydra, OmegaConf или YAML для всех гиперпараметров |
| **Отслеживание артефактов** | MLflow или W&B для регистрации каждого эксперимента |

## Вывод масштабирования
Когда модели необходимо обслуживать миллионы запросов в день, производительность имеет значение.
| Техника | Описание |
|-----------|-------------|
| **Пакетирование** | Группировать несколько запросов в один проход |
| **Квантование** | Уменьшите точность модели (FP32 → INT8 или INT4) для более быстрого вывода |
| **Модель дистилляции** | Обучите меньшую модель имитировать большую |
| **Обрезка** | Удалить неважные веса или нейроны |
| **Кэширование** | Кэшируйте частые прогнозы, чтобы избежать повторных вычислений |
| **Оптимизация графического процессора** | TensorRT, среда выполнения ONNX, Flash Внимание |
| **Горизонтальное масштабирование** | Запуск нескольких реплик модели за балансировщиком нагрузки |

## Флаги функций для машинного обучения
Флаги функций позволяют вам контролировать, какая версия модели обслуживает каких пользователей, без повторного развертывания.
| Вариант использования | Описание |
|----------|-------------|
| **Постепенное внедрение** | Предоставьте новую модель 5% пользователей, а затем увеличьте |
| **Аварийный выключатель** | Мгновенный возврат к предыдущей модели при обнаружении проблем |
| **На основе сегментов** | Различные модели для разных сегментов пользователей |
| **Эксперименты** | Варианты моделей A/B-тестирования с бизнес-метриками |
Инструменты: LaunchDarkly, Unleash, Flagsmith или простые флаги функций, поддерживаемые базой данных.

## Кривая зрелости MLOps
| Уровень | Характеристики |
|-------|----------------|
| **Уровень 0 — Ручной** | Ручное обучение, ручное развертывание, без мониторинга |
| **Уровень 1 — Экспериментирование** | Отслеживание экспериментов, реестр моделей, базовая CI |
| **Уровень 2 — Автоматизация** | Автоматизированное переобучение, CI/CD для моделей, автоматизированное тестирование |
| **Уровень 3 — Полный конвейер** | Сквозной автоматизированный конвейер с мониторингом, обнаружением отклонений и автоматическим переобучением |
Большинство организаций находятся где-то между уровнями 0 и 1. Целью является уровень 2–3, на котором жизненный цикл машинного обучения автоматизирован и самовосстанавливается.
