# Локальная архитектура искусственного интеллекта
Практическое руководство по запуску больших языковых моделей полностью на устройстве: аспекты аппаратного обеспечения, механизмы вывода, оптимизация памяти и проектирование системы для периферийного развертывания.
---

## Зачем запускать ИИ локально?
- **Конфиденциальность**: никакие данные не покидают устройство.
- **Стоимость**: плата за API за токен не взимается.
- **Задержка**: предсказуемый вывод без использования сети.
- **Доступность в автономном режиме**: работает без Интернета.
- **Контроль**: полный контроль над версией модели, ее настройкой и точной настройкой.
---

## Требования к оборудованию
### Память графического процессора (VRAM)
Самый критический ресурс. Размер модели в памяти ≈ **параметры × байты на параметр**.
| Точность | Байтов на параметр | Модель 3.8B | Модель 7Б | Модель 13Б | Модель 70Б |
|-----------|---------------------|------------|----------|-----------|-----------|
| ФП32 | 4 | ~15 ГБ | ~28 ГБ | ~52 ГБ | ~280 ГБ |
| РП16 | 2 | ~7,6 ГБ | ~14 ГБ | ~26 ГБ | ~140 ГБ |
| INT8 (8-битный) | 1 | ~3,8 ГБ | ~7 ГБ | ~13 ГБ | ~70 ГБ |
| INT4 (4-битный) | 0,5 | ~1,9 ГБ | ~3,5 ГБ | ~6,5 ГБ | ~35 ГБ |
**Практические рекомендации:**
- 8 ГБ видеопамяти → до моделей 7B с 4-битной памятью.
- 12 ГБ видеопамяти → до моделей 13 ГБ в 4-битном режиме.
- 24 ГБ видеопамяти → модели до 70 ГБ в 4-битном режиме (или 13 ГБ в 8-битном режиме).
- Apple Silicon (унифицированная память) может работать с моделями 70B на системах емкостью 64 ГБ и более.
### ОЗУ (системная память)
- Для вывода о ЦП вам необходимо достаточно системной оперативной памяти для загрузки модели (аналогично числам VRAM).
- Для вывода графического процессора системная оперативная память имеет значение для загрузки модели в память перед выгрузкой в ​​VRAM.
### Хранилище
- Веса квантованной модели занимают несколько ГБ (например, 4-битный 7B ≈ 4 ГБ на диске). Обеспечьте как минимум 20–50 ГБ свободного места для нескольких моделей.
### процессор
- Для быстрой обработки (предварительного заполнения) и разгрузки ЦП помогает современный многоядерный ЦП.
- Чипы Apple M-серии обладают отличной производительностью для LLM благодаря унифицированной памяти и Neural Engine.

## Квантование
Квантование снижает числовую точность весов, резко сокращая память и увеличивая скорость при небольших затратах на точность.
### Популярные форматы
| Формат | Биты | Описание | Типичное использование |
|--------|------|-------------|-------------|
| **ГГУФ** | 4–8 | Формат llama.cpp, оптимизированный для гибридного процессора и графического процессора | Лучшее для локального вывода |
| **GPTQ** | 4–8 | Только графический процессор, эффективен на CUDA | Лучшее для графических процессоров NVIDIA |
| **АВК** | 4 | С поддержкой активации, только для графического процессора | Подходит для пакетного вывода на графических процессорах |
| **ОННКС** | переменная | Стандартизированный, кроссплатформенный | Производство обслуживания |
### Выбор уровня квантования
- **Q8_0** (8 бит): минимальная потеря качества, наибольший размер.
- **Q6_K** (6 бит): хорошее качество, достойное сжатие.
- **Q5_K_M** (5 бит): общая золотая середина.
- **Q4_K_M** (4 бита): наименьшее, приемлемое качество для большинства задач.
- **IQ4_XS** / **IQ3_XS**: улучшенное квантование с лучшей запутанностью при 4/3 битах.
**Практическое правило:** используйте Q4_K_M для обеспечения хорошего баланса качества и размера. Если у вас есть дополнительная видеопамять, используйте Q5 или Q6.

## Механизмы вывода (локальные)
###лама.cpp
- Написан на С++.
- Поддерживает формат GGUF.
- Оптимизирован для процессора и графического процессора (через CUDA, Metal, OpenCL).
- Очень быстро, особенно на процессоре.
— Командная строка, режим сервера и привязки Python.
**Пример команды:**```bash
./llama-cli -m model.Q4_K_M.gguf -p "Tell me a joke" -n 100 -ngl 32
# -ngl 32 offloads 32 layers to GPU
```

### Оллама
— Обертывает llama.cpp простым интерфейсом командной строки и REST API.
- Автоматически загружает модели, управляет ими.
- Отлично подходит для прототипирования и настольных приложений.
- Поддерживает пользовательские файлы моделей для системных подсказок.
```bash
ollama run phi3:3.8b
ollama run llama3:8b
```

###ЛМ Студия
- Графическое настольное приложение для Windows, macOS, Linux.
- Загрузка в один клик и интерфейс чата.
- Встроенный локальный сервер с API, совместимым с OpenAI.
- Подходит для нетехнических пользователей и быстрого тестирования.
### Трансформеры обнимающего лица + биты и байты
— Стандартная библиотека Python для моделей HF.
- Используйте`bitsandbytes`для 4-битного квантования (`load_in_4bit=True`).
— Более гибкий для точной настройки, но медленнее, чем llama.cpp для вывода.
### ExLlamaV2
- Очень быстрый вывод графического процессора для GPTQ и AWQ.
- Лучшая производительность на графических процессорах NVIDIA.
- Поддерживает пакетную генерацию.
###mlx (Яблоко)
- Фреймворк Apple для чипов M-серии.
- Высокая оптимизация для Apple Silicon.
- API Python.

## Управление памятью
### Контекстное окно и кэш KV
Кэш KV хранит пары ключ-значение для каждого уровня и каждого токена в контексте. Он растет линейно с длиной контекста.
Стоимость памяти ≈ 2 × слои × (головки KV × размер головки) × токены × байты на значение
Для 32-слойной модели с 8 головками KV и 128 головками каждый токен стоит ~32 × 8 × 128 × 2 байта = 65 КБ на токен. Для токенов 128 тыс. это ~8 ГБ только для кеша.
### Стратегии разгрузки
- **Выгрузка слоев**: поместите одни слои на графический процессор, другие на процессор. Быстрее, чем чистый процессор, меньше требований к видеопамяти.
- **Потоковая передача токенов**: токены обрабатываются постепенно, а не все сразу.
### Кэширование подсказок
Повторно используйте кэши KV в аналогичных запросах, чтобы избежать повторного расчета фазы предварительного заполнения. Некоторые платформы поддерживают это (например, vLLM, llama.cpp с `--prompt-cache`).
### Файлы, отображаемые в памяти
Загружайте веса моделей непосредственно с диска, не загружая их полностью в оперативную память (полезно для огромных моделей в системах с ограниченной памятью). llama.cpp по умолчанию использует отображение памяти.

## Архитектуры развертывания
### Режим одного устройства
Одна модель работает на одном компьютере (ноутбуке, смартфоне, периферийном устройстве). Используется для личных помощников, приложений для заметок, завершения кода.
### Гибридное периферийное облако
Локальная модель обрабатывает общие запросы; возврат к облачной модели для решения сложных вопросов. Это дает лучшее из обоих миров — скорость/конфиденциальность для большинства, возможности для крайних случаев.
### Распределенный вывод (многочиповый процессор)
Для более крупных моделей разделите слои между несколькими графическими процессорами (тензорный параллелизм) или разделите контекст между устройствами (конвейерный параллелизм). Используйте llama.cpp с`-ngl`или ExLlamaV2 с `--num-gpu-layers`.
### Мобильное развертывание
- **Android**: используйте llama.cpp через привязки JNI или ML Kit.
- **iOS**: используйте llama.cpp через привязки Swift или mlx.
- **Интернет**: используйте WebLLM (работает на WebGPU через среду выполнения ONNX) или Transformers.js.

## Оптимизация производительности
### Вспышка внимания
Ускоряет обработку внимания и снижает использование памяти. Доступен в llama.cpp, ExLlamaV2 и современных библиотеках трансформеров.
### Пакетный вывод
Обработка нескольких запросов за один проход. Значительно увеличивает пропускную способность. Используйте`llama-batch`или vLLM.
### Ранняя остановка/бюджетирование токенов
Установите максимальный бюджет токена, чтобы предотвратить неограниченную генерацию.
### Спекулятивное декодирование
Используйте небольшую быструю модель (черновик) для прогнозирования токенов, а затем проверяйте ее параллельно с большой моделью. Может дать ускорение в 2–3 раза.

## Практическое руководство по настройке
### 1. Установите Олламу
```bash
curl -fsSL https://ollama.com/install.sh | sh
```

### 2. Извлечение модели
```bash
ollama pull phi3:3.8b-q4_K_M
```

### 3. Запуск через API
```bash
ollama serve
```

Затем отправьте запросы на `http://localhost:11434/api/generate`.
### 4. Интеграция Python
```python
import requests

response = requests.post(
    "http://localhost:11434/api/generate",
    json={"model": "phi3:3.8b", "prompt": "Hello", "stream": False}
)
print(response.json()["response"])
```

### 5. (Альтернатива) Использовать llama.cpp напрямую
```bash
# Download GGUF from Hugging Face
wget https://huggingface.co/microsoft/Phi-3-mini-4k-instruct-gguf/resolve/main/Phi-3-mini-4k-instruct-q4_K_M.gguf

# Run server
./llama-server -m Phi-3-mini-4k-instruct-q4_K_M.gguf --host 0.0.0.0 --port 8080
```

## Ограничения и компромиссы
- **Разрыв в качестве**. Маленькие локальные модели (3.8B–7B) обычно уступают моделям больших облаков (GPT-4, Claude 3.5) при сложных рассуждениях.
- **Ограничение знаний**: знания модели замораживаются во время обучения; используйте RAG для ввода текущей информации.
- **Многоязычный**: модели меньшего размера могут иметь менее многоязычные возможности.
- **Использование инструментов**: агентские рабочие процессы (вызов функций) могут быть менее надежными на небольших моделях.
Для многих повседневных задач (подведение итогов, вопросы и ответы, завершение кода, классификация) локальных моделей уже достаточно, и они быстро совершенствуются.
