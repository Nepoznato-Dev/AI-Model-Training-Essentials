# Наука о данных и аналитика
Наука о данных — это дисциплина, позволяющая превращать необработанные данные в полезную информацию. Он находится на стыке статистики, информатики и отраслевых знаний и стал незаменимым во всех секторах, от финансов до здравоохранения. В этом файле рассматриваются основные концепции, инструменты и рабочие процессы, которые должен знать каждый практикующий специалист.
---

## Процесс обработки данных
Большинство проектов следуют некоторым вариантам **CRISP-DM**, стандартного жизненного цикла:
| Фаза | Что происходит | Типичное время |
|-------|-------------|--------------|
| **Понимание бизнеса** | Определите цели, показатели успеха и ограничения | 10–15% |
| **Понимание данных** | Собирайте, исследуйте и профилируйте данные | 10–15% |
| **Подготовка данных** | Очистите, трансформируйте, спроектируйте функции | ~50–60% |
| **Моделирование** | Выбрать и обучить модели | 10–15% |
| **Оценка** | Оцените производительность в соответствии с бизнес-целями | 5–10% |
| **Развертывание** | Отправьте модель в производство | 5–10% |
По оценкам, подготовка данных, особенно очистка данных, занимает около 80% времени специалиста по обработке данных.

## Типы данных с первого взгляда
| Тип | Описание | Пример |
|------|-------------|---------|

## Основы статистики
### Описательная статистика против логической статистики
Описательная статистика суммирует то, что у вас *есть*; статистика выводов позволяет вам делать выводы о том, чего у вас *нет* (у более широких слоев населения).
| Концепция | Ключевые идеи |
|---------|-----------|
| **Центральная тенденция** | Среднее (чувствительность к выбросам), медиана (устойчивая), мода (наиболее частая) |
| **Дисперсия** | Диапазон, дисперсия, стандартное отклонение, межквартильный размах |
| **Форма распределения** | Асимметрия (асимметрия), эксцесс (тяжесть хвоста) |
| **Проверка гипотез** | Нулевая и альтернативная гипотезы, значения p, уровень значимости (α) |
| **Доверительные интервалы** | Диапазон, вероятно, содержащий истинный параметр популяции |
| **Ошибки типа I/II** | Ложное срабатывание (отклонение истинного нуля)/ложное отрицание (отсутствие реального эффекта) |
### Общие статистические тесты
| Тест | Когда использовать |
|------|-------------|
| **Т-тест** | Сравните средние значения между двумя группами |
| **АНОВА** | Сравните средние значения по трем или более группам |
| **Хи-квадрат** | Проверка независимости категориальных переменных |
| **Манн-Уитни Ю** | Непараметрическая альтернатива t-критерию (без предположения о нормальности) |
| **Корреляция Пирсона** | Линейная связь между двумя непрерывными переменными |
| **Корреляция Спирмена** | Монотонные отношения (ранговые, более надежные) |
### Распределения вероятностей, которые стоит знать
| Распространение | Вариант использования |
|-------------|----------|
| **Нормальный** | Природные явления, ошибки измерений — классическая гауссовая кривая |
| **Биномиальный** | Подсчет успехов/неуспехов (подбрасывание монеты, коэффициенты конверсии) |
| **Пуассон** | Подсчет событий осуществляется через фиксированный интервал (вызовов в час, дефектов в пакете) |
| **Экспоненциальный** | Время между событиями (время ожидания, интервалы сбоев) |
| **t-распределение** | Маленькие выборки или неизвестная популяционная дисперсия |
| **Хи-квадрат** | Категориальный анализ данных, критерии согласия |

## Сбор и хранение данных
### Откуда берутся данные
Реальные данные поступают из многих источников: реляционных баз данных, API (REST, GraphQL), плоских файлов (CSV, JSON, Parquet), потоковых платформ (Kafka, Kinesis), опросов и общедоступных репозиториев (Kaggle, правительственных порталов). Формат, который вы получаете, во многом определяет вашу стратегию предварительной обработки.
### Концепции хранения данных
| Концепция | Описание |
|---------|-------------|
| **ЭТЛ** | Извлечение → Преобразование → Загрузка — традиционный конвейерный подход |
| **ЭЛТ** | Извлечение → Загрузка → Преобразование — современный облачный подход (загрузка в исходном виде, преобразование на складе) |
| **Озеро данных** | Необработанные данные, хранящиеся в собственном формате (схема при чтении) |
| **Хранилище данных** | Структурированные, обработанные данные, оптимизированные для анализа (схема при записи) |
| **Витрина данных** | Подмножество склада, ограниченное одним отделом или доменом |
| **Звездная схема** | Центральная таблица фактов, окруженная таблицами измерений |
| **Схема снежинки** | Нормализованные таблицы измерений (меньше избыточности, больше объединений) |
### Типы баз данных
| Тип | Примеры | Лучшее для |
|------|----------|----------|
| **Реляционный (SQL)** | PostgreSQL, MySQL, Oracle | Структурированные данные, транзакции ACID |
| **Документ** | MongoDB, CouchDB | Гибкие схемы, данные в формате JSON |
| **Ключ-значение** | Редис, DynamoDB | Кэширование, сеансы, простой поиск |
| **Семейство столбцов** | Кассандра, HBase | Нагрузки с большим объемом записи, временные ряды |
| **График** | Neo4j, Amazon Нептун | Отношения, социальные сети |
| **Временной ряд** | InfluxDB, TimescaleDB | Метрики Интернета вещей, мониторинг |
| **Вектор** | Сосновая шишка, Милвус | Встраивание хранилища для поиска ML/AI |

## Предварительная обработка данных и разработка функций
### Контрольный список очистки
У каждого реального набора данных есть проблемы. Вот стандартная очистка:
| Выпуск | Подход |
|-------|----------|
| **Отсутствующие значения** | Вменение (среднее, медиана, прогноз) или удаление, если |
| **Выбросы** | Обнаружение с помощью IQR или Z-оценки; лечить укупориванием или трансформацией |
| **Дубликаты** | Выявить и удалить |
| **Несоответствия** | Стандартизируйте форматы, исправьте опечатки, нормализуйте единицы измерения |
### Техники трансформации
| Техника | Что он делает |
|-----------|-------------|
| **Нормализация** | Масштабирует значения в диапазоне 0–1 |
| **Стандартизация** | Z-показатель: среднее = 0, стандартное = 1 |
| **Горячее кодирование** | Преобразует категории в двоичные столбцы |
| **Кодировка этикетки** | Назначает целочисленные метки категориям |
| **Преобразование журнала** | Уменьшает перекос данных вправо |
| **Биннинг** | Группирует непрерывные значения в дискретные сегменты |
### Разработка функций
Разработка функций часто является отличием посредственной модели от отличной. Ключевые методы включают в себя:
– **Создание функции**: создание новых столбцов из существующих (например,`age_group`из`age`).
- **Выбор функций**: методы фильтрации (корреляция), методы-оболочки (рекурсивное исключение), встроенные методы (LASSO, важность дерева).
- **Уменьшение размерности**: PCA для линейной обработки, t-SNE или UMAP для визуализации.
– **Условия взаимодействия**: мультипликативное объединение функций для получения совместного эффекта.

## Исследовательский анализ данных (EDA)
EDA — это место, где вы развиваете интуицию в отношении своих данных перед моделированием. Цель состоит в том, чтобы выявить закономерности, аномалии и взаимосвязи.
### Выбор правильного графика
| Тип диаграммы | Лучшее для |
|-----------|----------|
| **Гистограмма** | Распределение одной переменной |
| **Коробчатый график** | Пятизначная сводка, обнаружение выбросов |
| **Точечная диаграмма** | Связь между двумя непрерывными переменными |
| **Тепловая карта** | Корреляционные матрицы, визуализация плотности |
| **Гистограмма** | Сравнение категорий |
| **Линейный график** | Тенденции с течением времени |
| **Скрипичный сюжет** | Плотность распределения + сводная информация по коробчатому графику |
| **Парный сюжет** | Краткий обзор всех пар переменных |
### Стек Python EDA
| Библиотека | Роль |
|---------|------|
| **панды** | Обработка и анализ данных |
| **пустой** | Численные вычисления |
| **matplotlib** | Планирование фундамента |
| **мореплаватель** | Статистическая визуализация (построенная на matplotlib) |
| **сюжетно** | Интерактивная веб-визуализация |
| **озорной** | Научные вычисления и статистика |

## Машинное обучение в науке о данных
### Обучение с учителем: краткий обзор
| Задача | Алгоритмы |
|------|-----------|
| **Регрессия** (прогнозировать число) | Линейный, Гребень/ЛАССО, Дерево решений, Случайный лес, Повышение градиента (XGBoost, LightGBM) |
| **Классификация** (предсказание категории) | Логистическая регрессия, k-NN, наивный Байес, SVM, деревья решений, случайный лес, нейронные сети |
### Обучение без учителя: краткий обзор
| Задача | Алгоритмы |
|------|-----------|
| **Кластеризация** | k-средние, иерархические, DBSCAN, модели гауссовой смеси |
| **Уменьшение размерности** | PCA, t-SNE, UMAP, автоэнкодеры |
| **Правила ассоциации** | Априори, ФП-Рост |
### Оценка модели
| Тип метрики | Ключевые показатели |
|-------------|-------------|
| **Классификация** | Точность, прецизионность, полнота, показатель F1, ROC-AUC, матрица путаницы |
| **Регрессия** | MAE, MSE, RMSE, R², скорректированный R² |
| **Проверка** | k-кратная перекрестная проверка, стратифицированная, разделение временных рядов |
| **Тюнинг** | Поиск по сетке, случайный поиск, байесовская оптимизация |

## Бизнес-аналитика и аналитика
### Сравнение инструментов BI
| Инструмент | Тип | Сила |
|------|------|----------|
| **Таблица** | Коммерческий | Богатая визуальная аналитика, перетаскивание |
| **Power BI** | Коммерческий (Microsoft) | Глубокая интеграция Office/Azure |
| **Смотритель** | Коммерческий (Google) | Исследование данных, моделирование LookML |
| **Метабаза** | С открытым исходным кодом | Простая настройка, поддержка SQL |
| **Суперсет** | Открытый исходный код (Apache) | Масштабируемость, ориентированность на SQL |
### Принципы проектирования информационной панели
Эффективные информационные панели следуют установленным принципам: определите аудиторию, выберите подходящую визуализацию для каждого показателя, стратегически используйте цвет (а не декоративно), поддерживайте согласованные масштабы и включите интерактивность (фильтры, детализация). Производительность также важна — информационные панели с медленным временем загрузки снижают эффективность пользователей.
### Общие категории KPI
| Категория | Примеры |
|----------|---------|
| **Финансовые** | Доход, размер прибыли, рентабельность инвестиций, пожизненная ценность клиента |
| **Клиент** | Стоимость приобретения (CAC), коэффициент оттока, NPS, оценка удовлетворенности |
| **Работает** | Показатели эффективности, время цикла, уровень дефектов |
| **Маркетинг** | Коэффициент конверсии, рейтинг кликов, рентабельность инвестиций в рекламу, атрибуция |
| **Продукт** | Ежедневно активные пользователи, вовлечение, удержание, внедрение функций |

## Расширенная аналитика
| Подход | Техники | Когда использовать |
|----------|-----------|-------------|
| **Прогнозирующий** | Временные ряды (ARIMA, Prophet, LSTM), моделирование рисков, прогнозирование оттока | Прогнозирование будущих ценностей |
| **Предписывающий** | Линейное программирование, моделирование Монте-Карло, A/B-тестирование, многорукие бандиты | Оптимизирующие решения |
| **Текстовая аналитика** | Токенизация, анализ настроений, тематическое моделирование (LDA), NER, встраивание слов (Word2Vec, BERT) | Извлечение информации из текста |

## Этика и управление данными
### Правила конфиденциальности
| Регулирование | Область применения |
|-----------|-------|
| **ВВП** | Субъекты данных ЕС; право на удаление, согласие, переносимость данных |
| **CCPA** | потребители Калифорнии; отказ от продажи данных |
| **HIPAA** | данные здравоохранения США; строгие правила конфиденциальности |
### Измерения качества данных
| Размерность | Вопрос |
|-----------|----------|
| **Точность** | Данные верны? |
| **Полнота** | Чего-то не хватает? |
| **Постоянство** | Источники согласны? |
| **Своевременность** | Это актуально? |
| **Срок действия** | Соответствует ли он ожидаемым форматам? |
| **Уникальность** | Есть ли дубликаты? |
### Предвзятость и справедливость
Систематическая ошибка может проявиться на любом этапе: систематическая ошибка выборки (нерепрезентативные данные), систематическая ошибка измерения (неправильные инструменты) или алгоритмическая ошибка (дискриминационные прогнозы). Стратегии смягчения последствий включают предварительную обработку (фиксацию данных), обработку (ограничение модели) и постобработку (корректировку выходных данных). Показатели справедливости, такие как демографический паритет и равные возможности, помогают количественно оценить проблему.

## Новые тенденции
- **AutoML**: автоматическое создание конвейера и выбор модели.
- **MLOps**: методы DevOps, применяемые к управлению жизненным циклом машинного обучения.
- **Хранилища функций**: централизованное управление функциями для повторного использования в разных командах.
- **Сетка данных**: децентрализованная архитектура данных, принадлежащая домену.
- **LLM и генеративный искусственный интеллект**: большие языковые модели, преобразующие рабочие процессы с текстом, кодом и изображениями.
- **Edge Analytics**: обработка данных на устройстве, а не в облаке.
- **Причинно-следственный вывод**: выход за рамки корреляции для понимания фактической причины и следствия.
- **Федеративное обучение**: обучение моделей на основе децентрализованных данных без их перемещения.
- **Ответственный ИИ**: этика, объяснимость и прозрачность становятся стандартными требованиями.
