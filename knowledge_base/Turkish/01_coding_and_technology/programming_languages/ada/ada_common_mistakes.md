# Ada — Yaygın Hatalar ve Anti-Kalıplar
Bu belge Ada'daki en yaygın hataları, tuzakları ve anti-kalıpları düzeltmelerle birlikte kataloglamaktadır.
---

## 1.`pragma Strict`Kullanılmaması
```ada
-- ❌ WRONG — allowing implicit conversions
X : Integer := 3.14;  -- may compile with warnings

-- ✅ CORRECT — strict mode catches issues
pragma Strict;
X : Integer := 3.14;  -- compile error: type mismatch
```

---

## 2. Alt Türlerde Aralık Hataları
```ada
-- ❌ WRONG — assuming subtype checks at compile time
type Day is range 1 .. 31;
D : Day := 32;  -- Constraint_Error at runtime

-- ✅ CORRECT — validate input
D : Day := Day'Value(Input);
exception
   when Constraint_Error => Put_Line("Invalid day");
```

---

## 3. Okunabilirlik için Adlandırılmış Parametreleri Kullanmamak
```ada
-- ❌ WRONG — positional parameters
Create(File, Out_File, "data.txt");

-- ✅ CORRECT — named association
Create(File => File, Mode => Out_File, Name => "data.txt");
```

---

## 4. İstisnalarla Başa Çıkmayı Unutmak
```ada
-- ❌ WRONG — no exception handling
procedure Process is
   F : File_Type;
begin
   Open(F, In_File, "data.txt");
   -- use F...
end Process;
-- raises Name_Error if file doesn't exist

-- ✅ CORRECT — handle exceptions
procedure Process is
   F : File_Type;
begin
   Open(F, In_File, "data.txt");
   -- use F...
   Close(F);
exception
   when Name_Error => Put_Line("File not found");
   when others => Put_Line("Unexpected error");
end Process;
```

---

## 5. Görev Kilitlenmesi
```ada
-- ❌ WRONG — tasks waiting on each other
task A is
   entry Start;
end A;
task body A is
begin
   B.Start;  -- waits for B
   accept Start do null; end Start;  -- B waits for A
end A;

-- ✅ CORRECT — design task communication carefully
-- Use protected objects for shared state
protected Counter is
   function Get return Integer;
   procedure Increment;
private
   Value : Integer := 0;
end Counter;
```

---

## Özet
Ada'nın güçlü yazımı birçok hatayı önler ancak disiplin gerektirir:`pragma Strict`kullanın, alt türler için `Constraint_Error`'yi kullanın, okunabilirlik için adlandırılmış parametre ilişkilendirmesini kullanın, her zaman istisnaları ele alın ve kilitlenmeyi önlemek için görev iletişimini dikkatli bir şekilde tasarlayın. Ada dikkatli ve güvenlik bilincine sahip programlamayı ödüllendirir.
