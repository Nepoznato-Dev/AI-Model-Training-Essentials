# ローコードおよびプラットフォーム エンジニアリング
ローコード プラットフォームを使用すると、通常はドラッグ アンド ドロップ インターフェイス、ビジュアル ワークフロー、事前構築されたコネクタを通じて、最小限の手書きコードでアプリケーションを構築できます。プラットフォーム エンジニアリングは、製品チームがインフラストラクチャ、CI/CD、および運用ツールを簡単にセルフサービスできるようにする内部開発者プラットフォーム (IDP) を構築する分野です。どちらの傾向も、ソフトウェアの需要とそれを構築できる開発者の供給との間のギャップという同じ問題への対応です。
---

## ローコード プラットフォーム
### ローコードの実際の意味
|側面 |説明 |
|----------|---------------|
| **ビジュアル開発** |ドラッグ アンド ドロップ UI ビルダー。ビジュアルワークフローエディター。フォームデザイナー |
| **事前に構築されたコンポーネント** |既製のウィジェット、コネクタ、テンプレート、統合 |
| **宣言ロジック** |コードを記述するのではなく、ルールと条件を通じて動作を構成します。
| **拡張性** |プラットフォームの組み込み機能が十分でない場合にカスタム コードを追加する機能 |
| **管理されたインフラストラクチャ** |プラットフォームはホスティング、スケーリング、セキュリティ パッチを処理します |
### 人気のローコード プラットフォーム
|プラットフォーム |強さ |典型的な使用例 |
|----------|----------|------|
| **マイクロソフト パワー プラットフォーム** | Microsoft 365 / Azure の緊密な統合。 Power Apps、Power Automate、Power BI |エンタープライズワークフロー。内部ツール |
| **Salesforce プラットフォーム** | CRMネイティブ。拡張機能の Apex。フロービルダー |顧客向けアプリ。営業ワークフロー |
| **ServiceNow** | ITサービス管理。ワークフローの自動化 | IT 運用。人事部;設備 |
| **アッピア** |プロセスマイニング;ケース管理 |複雑なビジネスプロセス。コンプライアンス |
| **OutSystems** |フルスタックのウェブとモバイル。エンタープライズグレード |顧客ポータル。モバイルアプリ |
| **再ツール** |内部ツールビルダー。データベースと API に接続します |管理パネル。ダッシュボード;運用ツール |
| **エアテーブル** |スプレッドシートとデータベースのハイブリッド。自動化 |プロジェクトの追跡。軽量CRM |
### ローコードがうまく機能する場合
|シナリオ |ローコードが適している理由 |
|----------|--------|
| **内部ツール** |構築が早い。ユーザーは社内にいるため、UI の柔軟性はそれほど重要ではありません。
| **フォームと承認** |ビジュアル ワークフロー ビルダーはこの点で優れています。
| **CRUD アプリケーション** |ほとんどのローコード プラットフォームは、作成、読み取り、更新、削除のパターンに最適化されています。
| **プロトタイピング** |アイデアを数週間ではなく数時間で検証 |
| **市民開発** |ビジネス アナリストは IT ガバナンスを備えた独自のソリューションを構築できます |
### ローコードでは不十分な場合
|制限 |影響 |
|-----------|----------|
| **ベンダーロックイン** |アプリケーションをプラットフォームから簡単に移行することはできません。
| **パフォーマンスの上限** |高スループットまたは遅延に敏感なアプリケーションには適していません。
| **UI の制約** |カスタム設計は困難です。プラットフォームがサポートするものに制限されます。
| **統合の複雑さ** |通常とは異なる API やレガシー システムに接続するには、とにかくカスタム コードが必要になる場合があります。
| **大規模なコスト** |ユーザーごとまたはアプリごとの料金は、使用量が増えるにつれて高価になる可能性があります。
| **デバッグの難易度** |視覚的な抽象化により、複雑な問題の診断が困難になります。

## プラットフォーム エンジニアリング
### プラットフォームエンジニアリングが解決する問題
|プラットフォームエンジニアリングなし |プラットフォームエンジニアリングとは |
|----------------------------|--------------------------|
|各チームは独自のインフラストラクチャを管理します。セルフサービス プラットフォームはインフラストラクチャを抽象化します |
|チーム間で一貫性のないツール |標準化されたツールチェーン。黄金の道 |
|開発者は運用担当者がリソースをプロビジョニングするのを待ちます。開発者はオンデマンドでリソースをプロビジョニング |
|知識のサイロ化。部族の知識 |文書化されています。自動化;発見可能 |
|新しいエンジニアのオンボーディングが遅い |新しいエンジニアは初日から導入可能 |
### 社内開発者プラットフォームのコアコンポーネント
|コンポーネント |目的 |ツールの例 |
|----------|-----------|----------|
| **サービスカタログ** |すべてのサービスとその所有者の中央レジストリ |舞台裏。ポート;コーテックス |
| **テンプレート化された足場** |承認されたテンプレートから新しいサービスを生成 |バックステージ ソフトウェア テンプレート。クッキーカッター |
| **セルフサービス インフラストラクチャ** |開発者はチケットを提出せずにクラウド リソースをプロビジョニング | Terraform モジュール。プルミ;クロスプレーン |
| **CI/CD パイプライン** |標準化されたビルド、テスト、デプロイ パイプライン | GitHub アクション。 GitLab CI;アルゴ CD |
| **環境管理** |オンデマンドの一時的な開発/ステージング環境 |仮想クラスター。名前空間。ギットポッド |
| **可観測性** |すべてのサービスに組み込まれたロギング、メトリクス、トレース |プロメテウス。グラファナ。オープンテレメトリ;データドッグ |
| **秘密管理** |資格情報の安全な保管とローテーション |保管庫; AWS シークレットマネージャー。 SOPS |
| **アイデンティティとアクセス** | SSO;役割ベースのアクセス。サービス間認証 |オクタ。キークローク;スパイフ |
### 黄金の道
ゴールデン パスとは、何かを行うためのサポートされ、意見がまとまった方法です。それは最も抵抗の少ない道です。これに従えば、すべてがうまくいきます。道を外れても構いませんが、自分自身で行動するのです。
|黄金の道 |提供するもの |
|-----------|------|
| **新しいサービス** |テンプレート リポジトリ。 CI/CD;監視;ロギング;デプロイメント構成 |
| **新しいデータベース** |プロビジョニングされたインスタンス。シークレット内の接続文字列。バックアップが構成されました |
| **新しいフロントエンド** |パイプラインを構築します。 CDN;プレビュー環境。灯台チェック |
| **データ パイプライン** |オーケストレーション;スキーマの検証。監視;警告 |
### 構築か購入かの決定
|係数 |カスタムビルド |既存のツールを使用する |
|--------|-------------|--------|
| **コアコンピテンシー** |あなたのビジネスに特有のもの。競争上の優位性 |商品;すべての企業がそれを必要としています |
| **メンテナンスの負担** |あなたにはそれを維持する能力があります |ツールはベンダー/コミュニティによって適切に保守されています。
| **統合のニーズ** |内部システムとの緊密な統合が必要 |標準の API とコネクタで十分 |
| **コスト** |ライセンスよりも構築の方が安い |構築よりもライセンスの方が安い |

## ローコードとプラットフォーム エンジニアリングの関係
|寸法 |ローコード |プラットフォームエンジニアリング |
|----------|----------|----------|
| **対象ユーザー** |ビジネスユーザー。シチズン開発者 |プロのソフトウェア エンジニア |
| **目標** |コードを削減します。速度を上げる |認知的負荷を軽減します。自主性を高める |
| **抽象化レベル** |非常に高い。ビジュアル |中くらい;コードベースだが簡素化された |
| **柔軟性** |プラットフォームの機能による制限 |完全な柔軟性。任意のコードを書くことができます |
| **ガバナンス** |プラットフォームはルールを強制します |プラットフォームはゴールデン パスを提供します |
これらは相互補完的であり、プラットフォーム エンジニアリングによりプロの開発者がより迅速に作業できるようになり、ローコードにより非開発者でも簡単なアプリケーションを構築できるようになります。これらは連携して、さまざまな角度からソフトウェア配信のギャップに対処します。
---

＃＃ まとめ
ローコード プラットフォームと社内開発者プラットフォームはどちらも、ソフトウェアを提供できる人の数を増やすことを目的としています。ローコードでは、ビジュアル ビルダー、事前構築されたコネクタ、宣言型ロジックなど、コードを完全に抽象化することでこれを実現します。プラットフォーム エンジニアリングは、プロの開発者がセルフサービス インフラストラクチャ、ゴールデン パス、標準化されたツールを提供することでこれを実現し、運用作業に費やす時間を減らし、製品機能により多くの時間を費やします。どちらも特効薬ではありません。ローコードにはベンダー ロックインとパフォーマンスの制限があり、プラットフォーム エンジニアリングには維持するための継続的な投資が必要です。しかし、内部ツール、CRUD アプリ、標準化されたサービス配信など、適切な問題に適用すると、どちらもアイデアから本番までの時間を大幅に短縮できます。
