# セキュリティのベストプラクティス
開発から実稼働まで、アプリケーション、インフラストラクチャ、データを保護するための実践的なガイド。
---

## OWASP トップ 10 (2021) — 概要
1. **アクセス制御の違反**: ユーザーはアクセスすべきではないリソースにアクセスできます。
2. **暗号化の失敗**: 暗号化が弱いか欠落しています。
3. **インジェクション**: SQL、NoSQL、OS コマンド、または LDAP インジェクション。
4. **安全でない設計**: アーキテクチャ上の欠陥。
5. **セキュリティの設定ミス**: デフォルトのパスワード、開いているポート、詳細なエラー。
6. **脆弱なコンポーネントと古いコンポーネント**: 依存関係にある既知の CVE。
7. **識別と認証の失敗**: 脆弱なパスワード、セッションの管理ミス。
8. **ソフトウェアとデータの整合性の失敗**: サプライ チェーン攻撃、署名のないアップデート。
9. **セキュリティのログ記録と監視の失敗**: 違反は検出されません。
10. **サーバーサイド リクエスト フォージェリ (SSRF)**: サーバーを悪用して内部システムにリクエストを送信します。
---

## 入力検証と出力エンコーディング
### 検証ルール
- **ホワイトリスト > ブラックリスト**: 既知の悪いパターンをブロックするのではなく、許可されるパターン (電子メールの正規表現など) を定義します。
- **長さ制限**: バッファ オーバーフローや DoS を防ぐために最大長を強制します。
- **型チェック**: 整数が整数であること、ブール値がブール値であることを確認します。
- **十分にテストされたライブラリを使用する**: 電子メール、URL、および日付の検証には、標準ライブラリ (例: Python の `email-validator`、Node の `validator.js`) を使用します。
### 出力エンコーディング
- **HTML エンコード**: XSS を防ぐために、`<`、`>`、`&`、`"`、`'`をエンコードします。
- **SQL パラメータ化**: ユーザー入力を SQL クエリに連結しないでください。パラメータ化されたクエリ (準備されたステートメント) または ORM を使用します。
- **シェル エスケープ**: ユーザー入力からシェル コマンドを構築することは避けてください。やむを得ない場合は、`shlex.quote()` などを使用してください。
---

## 認証と認可
### パスワード管理
- **ハッシュ**: 強力で遅いハッシュ アルゴリズムを使用してパスワードを保存します: **Argon2id** (推奨)、**bcrypt**、**scrypt**、または **PBKDF2**。
- **ソルト**: ユーザーごとに固有のソルトを追加します。
- **最小長**: 少なくとも 12 ～ 16 文字を強制します。
- **MFA (多要素認証)**: 機密性の高い操作には 2 番目の要素 (TOTP、SMS、ハードウェア キー) が必要です。
- **レート制限**: ログイン エンドポイントでのブルート フォース試行を防止します (例: IP/ユーザーごとに 5 分ごとに 5 回の試行)。
### セッション管理
- セッション トークンには、安全な HTTP 専用の SameSite Cookie を使用します。
- 適切な有効期限を設定します。
- ログアウト時およびパスワード変更時にセッションを無効にします。
- URL でセッション ID を公開しないようにします。
### OAuth2 / OIDC
- 確立されたライブラリ（Authlib、PyJWT、Passport.js、Spring Security など）を使用します。
- ID トークンを徹底的に検証します (署名、発行者、対象者、有効期限)。
- 状態パラメータを使用して CSRF を防止します。
- クライアントの秘密を機密に保ちます。
### JWT (JSON Web トークン)
- **署名**: セキュリティを向上させるには、RS256 または ES256 (非対称) を使用します。共有秘密が適切に管理されている場合は、HS256 (対称) が許容されます。
- **検証**: 署名、発行者 (`iss`)、対象者 (`aud`)、および有効期限 (`exp`) を常に検証します。
- **有効期限は短くしてください**: アクセス トークンの場合は 15 ～ 60 分。より長いセッションにはリフレッシュ トークンを使用します。
- **安全に保存**: JWT を localStorage に保存しないでください (XSS に対して脆弱です)。代わりに HTTP のみの Cookie を使用してください。

## API セキュリティ
### 認証
- API 呼び出しを常に認証します (パブリック エンドポイントを除く)。
- 基本認証 (リクエストごとに資格情報を送信する) よりも API キーまたは OAuth2 トークンを優先します。
### レート制限とスロットリング
- ユーザーごとおよび IP ごとのレート制限を適用して、悪用や DoS を防止します。
-`Retry-After`ヘッダーを付けて`429 Too Many Requests`を返します。
### CORS (クロスオリジンリソース共有)
- 特定のオリジンのみを許可します (運用環境では`*`を許可しない)。
- サーバー側で`Origin`ヘッダーを検証します。
### 入力の検証
- ヘッダーと本文を含むすべてのリクエスト パラメーターを検証します。
- 予期しないフィールド (JSON スキーマの`"strict": true`または `additionalProperties: false`) を拒否します。
### HTTPS / TLS
- 運用環境で HTTPS を強制します。
- HSTS (HTTP Strict Transport Security) を使用して、ブラウザに HTTPS の使用を強制します。
- TLS 1.2 または 1.3 を使用します (TLS 1.0/1.1 を無効にします)。
---

## 秘密の管理
### シークレットをハードコーディングしないでください
- シークレット (API キー、パスワード、データベース URL) をソース管理にコミットしないでください。
- 環境変数やシークレット管理ツールを使用します。
### ツール
|ツール |説明 |
|------|---------------|
| **HashiCorp 保管庫** |エンタープライズ グレードの動的なシークレット |
| **AWS Secrets Manager / Azure Key Vault / GCP Secret Manager** |クラウドネイティブ |
| **SOPS** |ファイル内のシークレットを暗号化してコミットする (KMS または GPG を使用) |
| **Docker の秘密** | Swarmモードの場合; Kubernetes シークレット (外部 Secrets Store CSI ドライバーを考慮してください) |
### 回転
- シークレットとサービス アカウントを定期的にローテーションします。
- 可能な場合はローテーションを自動化します。
---

## 依存関係の管理
### 脆弱性スキャン
|言語/プラットフォーム |ツール |
|----|------|
| **Python** | `safety`、`pip-audit`、`bandit`|
| **ノード** |  `npm audit`、`yarn audit`、`snyk` |
| **錆** | `cargo audit`|
| **行く** | `govulncheck`|
| **一般** | `Dependabot`(GitHub)、`Renovate`、`Trivy` |
### パッチ適用
- 依存関係をパッチ適用済みのバージョンに更新したままにします。
- マイナー/パッチ更新用の自動プル リクエストを設定します。
- 重大な変更がないか変更ログを確認します。
### サプライチェーンの完全性
- パッケージ ロックファイル (`package-lock.json`、`Cargo.lock`、`go.sum`) を使用して、ビルドの再現性を確保します。
- ダウンロードされた依存関係のチェックサムを検証します。
- 公式レジストリを優先し、検証済みの発行者のみを信頼します。
---

## インフラストラクチャのセキュリティ
### ファイアウォール
- 明示的に必要なポート (80、443 など) を除き、すべての受信ポートをブロックします。
- SSH アクセスを特定の IP 範囲に制限します (または VPN/要塞ホストを使用します)。
- きめ細かい制御には、セキュリティ グループ (AWS) または NSG (Azure) を使用します。
### OSの強化
- セキュリティ更新プログラムを定期的に適用します (`sudo apt upgrade`、`yum update`)。
- 不要なサービスとデフォルトのアカウントを無効にします。
- SSH でのブルート フォース試行をブロックするには、fail2ban を使用します。
- SSH の強化: root ログインを無効にし、キーベースの認証を使用し、デフォルトのポートを変更します (オプション)。
### ネットワークのセグメンテーション
- インターネットにアクセスできないプライベート サブネットにデータベースとキャッシュを配置します。
- 公開サービスには DMZ を使用します。
- ネットワーク アクセスに最小特権の原則を適用します。
### インフラストラクチャの秘密
- 暗号化しない限り、シークレットを CI/CD 環境変数に保存しないでください。
- 有効期間の長いキーの代わりに、EC2/VM インスタンスに対してクラウド プロバイダーの IAM ロールを使用します。
---

## ロギングとモニタリング
### ログに記録する内容
- 認証イベント (成功/失敗)。
- アクセス制御の決定 (認可の失敗)。
- 管理者のアクション (ユーザーの作成、削除、権限の変更)。
- データベーススキーマの変更。
- システムエラーと例外。
- API リクエストとレスポンス (機密データを秘匿化)。
### ログに記録しないもの
- ハッシュ化/編集されていない限り、パスワード、シークレット、トークン、PII (個人識別情報)。
- 完全なクレジット カード番号。
### アラート
- 次のアラートを設定します。
  - 複数回のログイン失敗 (総当たり攻撃の可能性)。
  - 異常なアクセス パターン (例: 新しい場所から、変な時間に)。
  - 新しい管理者アカウントが作成されました。
  - 高いエラー率または遅延のスパイク。
- 高度な関連付けには SIEM (セキュリティ情報およびイベント管理) を使用します。
### ログの保存期間
- 規制要件に応じて、ログを少なくとも 30 ～ 90 日間保持します。
- ログを一元化された改ざん明示システム (ELK Stack、Splunk、Datadog など) に保存します。
---

## 安全な開発ライフサイクル (SDL)
1. **トレーニング**: 開発者が一般的な脆弱性を理解していることを確認します。
2. **脅威モデリング**: 設計の早い段階で潜在的な脅威を特定します。
3. **安全なコーディング標準**: リンターとコード レビュー チェックリストを通じて強制します。
4. **SAST** (静的アプリケーション セキュリティ テスト): ソース コードの脆弱性をスキャンします (SonarQube、CodeQL)。
5. **DAST** (動的アプリケーション セキュリティ テスト): 実行中のアプリケーション (OWASP ZAP、Burp Suite) をスキャンします。
6. **SCA** (ソフトウェア構成分析): 依存関係をスキャンします。
7. **侵入テスト**: 定期的な倫理的ハッキング演習。
8. **バグ報奨金**: 外部の研究者が責任を持って脆弱性を発見するよう奨励します。
9. **インシデント対応計画**: 侵害が検出されたときの明確な計画を立ててください。
---

## 緊急チェックリスト (侵害が疑われる場合)
1. **パニックに陥らないでください** - すぐに行動してください。
2. 影響を受けるシステムを **隔離**します (必要に応じてネットワークから切断します)。
3. **証拠の保存**: ログ、メモリ ダンプ、およびディスク イメージをキャプチャします。
4. **範囲を特定**: どのシステム、どのデータ。
5. 侵害されたすべての資格情報とシークレットを **ローテーション**します。
6. 脆弱性を**パッチ**します。
7. 必要に応じて (法定の期限内に) 影響を受けるユーザーおよび規制機関に **通知**します。
8. **事後分析を実施**して根本原因を理解し、プロセスを改善します。
