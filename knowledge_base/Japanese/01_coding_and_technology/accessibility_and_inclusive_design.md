# アクセシビリティと包括的なデザイン
アクセシビリティ (a11y と略されることが多い) は、視覚障害、聴覚障害、運動障害、認知障害、神経障害のある人を含むすべての人がソフトウェアを使用できるようにする実践です。これは多くの法域で法的要件であり、標準的なエンジニアリング慣行です。アクセシブルなソフトウェアは、すべての人にとってより良いソフトウェアです。なぜなら、障害のあるユーザーをサポートする設計上の決定 (明確な構造、キーボード ナビゲーション、十分なコントラスト、読みやすいテキスト) によって、すべてのユーザーのエクスペリエンスが向上するからです。
---

## アクセシビリティの恩恵を受けるのは誰ですか?
|障害の種類 |例 |支援技術 |
|-----|----------|----------|
| **ビジュアル** |盲目、弱視、色覚異常 |スクリーン リーダー (JAWS、NVDA、VoiceOver);拡大鏡。ハイコントラストモード |
| **聴覚** |難聴、難聴 |キャプション;転写物;視覚的なアラート |
| **モーター** |器用さの制限、麻痺、震え |キーボードのみのナビゲーション。音声コントロール。スイッチデバイス。アイトラッキング |
| **認知** |ディスレクシア、ADHD、自閉症、記憶障害 |明確な言語。一貫したナビゲーション。気を散らすものを減らす |
| **一時的** |骨折した腕、明るい日差し、騒々しい環境 |永続的障害者と同様の配慮 |
| **状況** |赤ちゃんを抱いて、運転中、片手がふさがっている |音声インターフェース。大きなタッチターゲット |
**重要な洞察**: 障害のあるユーザー向けに設計されたアクセシビリティ機能は、すべての人に役立ちます。カーブカット (歩道のスロープ) は車椅子用に設計されていますが、ベビーカーを連れた親、カートを持った配達員、荷物を持った旅行者が使用します。

## ウェブ アクセシビリティ (WCAG)
Web コンテンツ アクセシビリティ ガイドライン (WCAG) は、Web アクセシビリティの国際標準です。
### WCAG 原則 (POUR)
|原則 |要件 |
|----------|---------------|
| **知覚可能** |情報は、ユーザーが認識できる方法で表示できる必要があります (代替テキスト、キャプション、適応可能なレイアウト)。
| **操作可能** |インターフェースはナビゲート可能で使用可能である必要があります (キーボードでアクセス可能、十分な時間があり、発作を引き起こすコンテンツがない)。
| **理解できます** |情報と操作は分かりやすくなければなりません（可読性、予測可能性、入力補助） |
| **堅牢** |コンテンツは現在および将来の支援技術で動作する必要があります。
### WCAG 適合レベル
|レベル |要件 |典型的なターゲット |
|------|-------------|------|
| **A** |最低レベル。 30 の成功基準 |一部の管轄区域における法的最低限度 |
| **AA** |最も一般的な障壁に対処します。ほとんどの組織の標準目標 |
| **AAA** |最高レベル。すべてのコンテンツがそれを達成できるわけではありません。専門的なコンテンツ。教育サイト |
### 主要な成功基準 (AA レベル)
|基準 |要件 |達成方法 |
|----------|---------------|----------|
| **1.1.1 非テキストコンテンツ** |すべての画像には代替テキストが含まれています | `alt`属性。  アイコン用`aria-label`|
| **1.3.1 情報と関係** |プログラムで伝達される構造 |セマンティック HTML。見出し。リスト;ランドマーク |
| **1.4.3 コントラスト (最小)** |テキストのコントラスト比は少なくとも 4.5:1 |コントラスト チェッカーでテストします。アクセシブルなカラー パレットを選択する |
| **1.4.4 テキストのサイズ変更** |テキストは損失することなく 200% までサイズ変更できます |相対単位 (rem、em) を使用します。レスポンシブデザイン |
| **2.1.1 キーボード** |すべての機能はキーボードから利用可能 |キーボードトラップはありません。目に見えるフォーカスインジケータ |
| **2.4.3 フォーカスの順序** |フォーカス順序は意味と操作性を維持します |論理的なタブオーダー。 DOM の順序は視覚的な順序と一致します。
| **2.4.7 焦点が表示されます** |キーボードのフォーカスは視覚的に示されます | CSS`:focus-visible`スタイル;交換せずに`outline: none`を使用することはありません。
| **3.3.2 ラベルまたは説明書** |入力にはラベルが付いています | `<label>`要素。 `aria-label`|
| **4.1.2 名前、役割、値** | UI コンポーネントにはアクセス可能な名前と役割があります。 ARIA 属性。セマンティック HTML |
---

## ARIA (アクセス可能なリッチ インターネット アプリケーション)
ARIA は、セマンティクスが組み込まれていない HTML 要素にアクセシビリティ情報を追加します。
### ARIA の役割
|役割 |目的 |例 |
|------|--------|----------|
| `button`|要素をボタンとして識別します |ボタンとしてスタイル設定された`<div>`|
| `dialog`|モーダルまたは非モーダル ダイアログ |カスタムモーダルコンポーネント |
| `tablist`/`tab`/`tabpanel`|タブインターフェイス |カスタムタブコンポーネント |
| `alert`|動的に表示される重要なメッセージ |エラー通知 |
| `progressbar`|進行状況インジケータ |ロード状態 |
| `menu`/`menuitem`|メニューナビゲーション |ドロップダウン メニュー |
### ARIA 属性
|属性 |目的 |例 |
|----------|-----------|----------|
| `aria-label`|テキストが表示されない場合のアクセシブルな名前 |アイコンのみのボタン:`aria-label="Search"`|
| `aria-describedby`|要素をその説明にリンクします |ヘルプ テキストを含むフォーム フィールド |
| `aria-expanded`|セクションが展開されているかどうかを示します。アコーディオン;ドロップダウン |
| `aria-hidden`|支援技術から要素を非表示にする |装飾的なアイコン |
| `aria-live`|動的なコンテンツの変更を発表 |ライブアップデート。通知 |
| `aria-disabled`|要素が無効であることを示します |グレー表示されたボタン |
### ARIA の最初のルール
> **代わりにネイティブ HTML を使用できる場合は、ARIA を使用しないでください。**`<button>`はすでにアクセス可能です。`<div role="button">`では、キーボード処理、フォーカス管理、およびスクリーン リーダーのサポートを手動で追加する必要があります。最初にセマンティック HTML を使用します。 ARIA は、ネイティブ要素が機能できない場合にのみ使用されます。

## キーボード ナビゲーション
|キー |期待される動作 |
|-----|---------------------|
| **タブ** |次のインタラクティブな要素にフォーカスを移動します |
| **Shift + Tab** |フォーカスを前のインタラクティブ要素に移動します |
| **入力/スペース** |フォーカスされた要素 (ボタン、リンク) をアクティブにする |
| **矢印キー** |コンポーネント内を移動 (メニュー、タブ、ラジオ グループ) |
| **脱出** |ダイアログ、メニュー、またはポップオーバーを閉じる |
| **ホーム / 最後** |リスト内の最初/最後の項目にジャンプ |
### 一般的なキーボード トラップ
|問題 |修正 |
|----------|-----|
|フォーカスはコンポーネントに入りますが、離れることはできません |タブでフォーカスを外に移動することを確認してください。ハンドル エスケープ |
|モーダルはフォーカスをトラップしません |フォーカスはモーダル内で循環する必要があります。閉じるとトリガーに戻る |
|カスタム コンポーネントがキーボードに応答しない | Enter、Space、矢印のキーダウン ハンドラーを追加します。

## 色とビジュアルデザイン
|ガイドライン |要件 |
|----------|---------------|
| **コントラスト比** |通常のテキストの場合は 4.5:1。大きなテキストの場合は 3:1 (18 ポイント以上または 14 ポイント以上の太字) |
| **色だけに依存しないでください** |色に加えてアイコン、テキスト、またはパターンを使用する |
| **フォーカスインジケーター** |常に表示されます。ハイコントラスト。交換せずに取り外すことはありません。
| **テキストのサイズ変更** |レイアウトは 200% ズームで機能する必要があります |
| **レスポンシブ** |コンテンツは幅 320 ピクセルでリフローする必要があります (モバイル) |
### 色覚異常に関する考慮事項
|タイプ |影響を受ける色 |デザインのヒント |
|------|------|-----------|
| **第二盲** |赤緑 (最も一般的) |ステータスを伝えるために赤/緑を使用しないでください。アイコン + カラーを使用する |
| **第二色覚** |赤緑 |同上 |
| **三色覚異常** |青黄 |青/黄色だけを差別化要因として使用しないでください。

## アクセシビリティのテスト
|方法 |ツール |何が釣れるのか |
|------|------|-----|
| **自動スキャン** |斧、灯台、波 |代替テキストがありません。コントラストの問題。 ARIA エラー |
| **キーボードのテスト** |手動: マウスを取り外し、キーボードのみを使用します。フォーカス順序。キーボードトラップ。ハンドラーが見つかりません |
| **スクリーン リーダーのテスト** | NVDA (無料)、VoiceOver (macOS)、JAWS |ラベルがありません。貧弱な構造。未発表の変更 |
| **ズームテスト** |ブラウザを 200%、400% にズーム |レイアウトの破損。切り取られたテキスト。オーバーフローの問題 |
| **色のコントラスト** | WebAIM コントラスト チェッカー、Stark プラグイン |コントラスト比が不十分 |
| **ユーザーテスト** |障害のあるユーザーを使用してテストする |自動化ツールが見逃す現実世界の障壁 |

## 法的要件
|法律 |地域 |要件 |
|-----|----------|---------------|
| **ADA** (アメリカ障害者法) |アメリカ |公共宿泊施設のウェブサイトはアクセス可能でなければなりません |
| **セクション 508** |米国 (連邦) |連邦政府機関の ICT はアクセス可能でなければなりません |
| **EAA** (欧州アクセシビリティ法) | EU (2025+) |製品とサービスはアクセシビリティ要件を満たさなければなりません |
| **EN 301 549** | EU | ICTアクセシビリティに関する技術基準 |
| **ACA** (カナダのアクセシビリティ法) |カナダ |政府および規制産業 |
| **2010 年平等法** |英国 |サービスプロバイダーは合理的な調整を行う必要があります。

## モバイル アクセシビリティ
|プラットフォーム |ガイドライン |主要なツール |
|----------|-----------|----------|
| **iOS** | Apple ヒューマン インターフェイス ガイドライン (アクセシビリティ セクション) |ボイスオーバー;ダイナミックタイプ。スイッチコントロール |
| **アンドロイド** | Android アクセシビリティ ガイドライン |トークバック;スイッチアクセス。選択して話す |
|モバイルに関する懸念 |ソリューション |
|---------------|----------|
| **タッチターゲット** |最小 44×44 ポイント (iOS) / 48×48 dp (Android) |
| **スクリーン リーダーのサポート** |コンテンツの説明。アクセシビリティラベル |
| **モーション感度** |`prefers-reduced-motion`を尊重します。アニメーションの自動再生を避ける |
| **動的なテキスト サイズ変更** |システムのフォント サイズをサポートします。スケーラブルなテキスト単位を使用する |

＃＃ まとめ
アクセシビリティは、最後に追加される機能ではなく、最初からすべての決定に通知される設計原則です。セマンティック HTML を使用します。キーボード ナビゲーションが機能することを確認します。十分な色のコントラストを維持します。非テキストコンテンツに代替テキストを提供します。スクリーン リーダーと障害のあるユーザーを使用してテストします。その結果、一時的な障害、状況による制限、古いデバイス、遅い接続、および実際の使用方法が管理された開発環境と異なる多くの点を持つ人を含む、すべての人にとってより適切に動作するソフトウェアが生まれます。
