# データベース システム
## データベースの基礎
### データベースとは何ですか?
データベースは、電子的に保存された構造化情報の組織的なコレクションであり、データの効率的な検索、挿入、更新、削除を行うために設計されています。
### データベース管理システム (DBMS)
エンドユーザー、アプリケーション、データベース自体と対話してデータを取得および分析するソフトウェア。例: MySQL、PostgreSQL、Oracle、MongoDB。
### 主要な概念
- **スキーマ**: データベースの構造/編成 (テーブル、フィールド、リレーションシップ)
- **インスタンス**: 特定の瞬間に保存された実際のデータ
- **ACID 特性**: 原子性、一貫性、分離性、耐久性
- **CAP 定理**: 一貫性、可用性、パーティション耐性 (2 つ選択)
- **正規化**: データを整理して冗長性を削減します。
- **非正規化**: 冗長性を追加して読み取りパフォーマンスを向上させます。
## リレーショナル データベース (SQL)
### 中心となる概念
- **テーブル**: 行 (レコード) と列 (フィールド)
- **主キー**: 各行の一意の識別子
- **外部キー**: 別のテーブルの主キーへの参照
- **インデックス**: クエリ速度を向上させるデータ構造
- **ビュー**: クエリ結果に基づく仮想テーブル
- **ストアド プロシージャ**: プリコンパイルされた SQL コード ブロック
- **トリガー**: データ変更時の自動アクション
### SQL 操作 (CRUD)```sql
-- Create
INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com');

-- Read
SELECT * FROM users WHERE id = 1;
SELECT name, email FROM users ORDER BY name LIMIT 10;

-- Update
UPDATE users SET email = 'new@example.com' WHERE id = 1;

-- Delete
DELETE FROM users WHERE id = 1;
```

### 結合
- **INNER JOIN**: 両方のテーブルから一致する行を返します。
- **LEFT JOIN**: 左のテーブルのすべての行、右から一致
- **RIGHT JOIN**: 右テーブルのすべての行、左から一致
- **FULL OUTER JOIN**: 両方のテーブルのすべての行
- **CROSS JOIN**: 両方のテーブルのデカルト積
- **SELF JOIN**: テーブル自体と結合されています
### 正規化形式
- **1NF**: 原子値、繰り返しグループなし
- **2NF**: 1NF + 部分的な依存関係なし (すべての非キー属性は主キー全体に依存します)
- **3NF**: 2NF + 推移的な依存関係なし (非キー属性は他の非キー属性に依存しません)
- **BCNF**: より強力な 3NF、すべての行列式が候補キーになります
- **4NF**: 複数値の依存関係はありません
- **5NF**: 結合依存関係なし
### 人気の RDBMS
- **PostgreSQL**: 高度な機能、拡張可能、ACID 準拠
- **MySQL**: 広く使用されている、高速読み取りの Web アプリケーション
- **Oracle**: エンタープライズ機能、拡張性、高価
- **SQL Server**: Microsoft エコシステム、統合ツール
- **SQLite**: 組み込み、サーバーレス、軽量
- **MariaDB**: MySQL フォーク、オープンソース
## NoSQL データベース
### NoSQL データベースの種類
#### ドキュメント ストア
- **構造**: JSON のようなドキュメント (BSON)
- **使用例**: コンテンツ管理、カタログ、ユーザー プロファイル
- **例**: MongoDB、CouchDB、DocumentDB
- **クエリの例** (MongoDB):```javascript
db.users.find({ age: { $gt: 25 } }).sort({ name: 1 });
```

#### Key-Value ストア
- **構造**: 単純なキーと値のペア
- **使用例**: キャッシュ、セッション、ショッピング カート
- **例**: Redis、DynamoDB、Riak
- **特徴**: 高速、シンプル、制限されたクエリ
#### カラムファミリーストア
- **構造**: ファミリにグループ化された列
- **ユースケース**: ビッグデータ、分析、時系列
- **例**: Cassandra、HBase、ScyllaDB
- **特徴**: 書き込み最適化、分散、スケーラブル
#### グラフ データベース
- **構造**: ノード、エッジ、プロパティ
- **使用例**: ソーシャル ネットワーク、不正行為の検出、推奨事項
- **例**: Neo4j、Amazon Neptune、ArangoDB
- **クエリ言語**: Cypher (Neo4j)、Gremlin
### NoSQL を使用する場合
- 柔軟で進化するスキーマ
- 水平スケーリング要件
- 高い書き込みスループット
- 階層/ネストされたデータ
- 分散システム
- リアルタイムアプリケーション
## データベース設計
### エンティティ関係モデリング
- **エンティティ**: オブジェクト/概念 (顧客、製品、注文)
- **属性**: エンティティのプロパティ (名前、価格、日付)
- **関係**: エンティティ間の接続 (1 対 1、1 対多、多対多)
- **カーディナリティ**: 関係内のインスタンスの数
### スキーマ設計パターン
- **単一テーブルの継承**: 型識別子を備えた 1 つのテーブル内のすべての型
- **クラス テーブルの継承**: ベースクラスとサブクラスの個別のテーブル
- **具象テーブルの継承**:具象クラスごとに個別のテーブル
- **ジャンクション テーブル**: 多対多の関係を解決します。
- **監査テーブル**: 変更の追跡 (created_at、updated_at、deleted_at)
### インデックス作成戦略
- **B ツリー**: デフォルト、範囲クエリ、並べ替え
- **ハッシュ**: 完全一致検索
- **ビットマップ**: カーディナリティの低い列 (性別、ステータス)
- **フルテキスト**: テキスト検索機能
- **空間**: 地理データ (GIS)
- **複合**: 複数の列を組み合わせたもの
- **対象範囲**: クエリに必要なすべての列が含まれます
## クエリの最適化
### 実行計画
- データベースがクエリを実行する方法を理解する
- ボトルネックの特定 (テーブル全体のスキャン、インデックスの欠落)
- ツール: EXPLAIN、EXPLAIN ANALYZE
### 最適化手法
- **インデックスの使用法**: クエリで適切なインデックスが使用されていることを確認します。
- **クエリの書き換え**: 複雑なクエリを簡素化します。
- **結合の最適化**: 正しい結合タイプと順序を選択します。
- **パーティショニング**: 大きなテーブルを分割します (範囲、ハッシュ、リスト)
- **マテリアライズド ビュー**: 事前に計算されたクエリ結果
- **クエリ キャッシュ**: 頻繁なクエリ結果を保存します
### 一般的なパフォーマンスの問題
- **N+1 クエリの問題**: 関連データのフェッチが非効率的である
- **インデックスがありません**: 大きなテーブルでの完全なテーブル スキャン
- **過剰なインデックス作成**: インデックスが多すぎるため、書き込みが遅くなります
- **ロック競合**: ロックを待機しているトランザクション
- **非効率なクエリ**: SELECT *、不要な結合
## トランザクションと同時実行性
### トランザクション分離レベル
- **READ UNCOMMITTED**: 分離性が最も低く、ダーティ読み取りが可能
- **READ COMMITTED**: コミットされたデータのみが表示されます (ほとんどの DB のデフォルト)
- **REPEATABLE READ**: 同じクエリはトランザクション内で同じ結果を返します
- **SERIALIZABLE**: 最も高い分離性、トランザクションは順次実行されます。
### 同時実行制御
- **悲観的ロック**: アクセス前にリソースをロックします。
- **楽観的ロック**: コミット前にバージョンを確認する
- **MVCC (マルチバージョン同時実行制御)**: 行の複数のバージョンを維持します。
- **行レベルのロック**: 特定の行をロックします。
- **テーブルレベルのロック**: テーブル全体をロックします
### デッドロック
- トランザクションが相互に待機する循環依存関係
- 防止: 一貫したロック順序、タイムアウト、デッドロック検出
- 解決策: 1 つのトランザクションを中止します。
## レプリケーションとスケーリング
### レプリケーションの種類
- **マスター/スレーブ**: 1 つのプライマリ、複数のリードレプリカ
- **マスター-マスター**: 複数のプライマリ、双方向レプリケーション
- **マルチマスター**: N プライマリ、競合解決が必要
- **チェーン レプリケーション**: ノードを介した順次レプリケーション
### スケーリングアプローチ
- **垂直スケーリング**: サーバー リソース (CPU、RAM、ストレージ) を増加します。
- **水平スケーリング**: サーバーを追加します (シャーディング、パーティショニング)
- **リードレプリカ**: 読み取りトラフィックのオフロード
- **シャーディング**: キー/範囲/ハッシュによってサーバー間でデータを分割します。
- **フェデレーション**: 機能/サービスごとに分割
### 一貫性モデル
- **強力な一貫性**: すべてのノードが同時に同じデータを参照します。
- **最終的な一貫性**: ノードは時間の経過とともに収束します
- **因果関係**: 因果関係が維持されます。
- **Read-Your-Writes**: ユーザーは自分の更新をすぐに確認できます
## バックアップとリカバリ
### バックアップ戦略
- **完全バックアップ**: データベースの完全なコピー
- **増分バックアップ**: 前回のバックアップ以降の変更
- **差分バックアップ**: 前回の完全バックアップ以降の変更
- **ポイントインタイムリカバリ**: 特定の時点に復元します
- **継続的バックアップ**: バックアップへのリアルタイム レプリケーション
### 回復手順
- **RTO (目標復旧時間)**: 許容可能な最大ダウンタイム
- **RPO (目標復旧時点)**: 許容可能な最大データ損失
- **災害復旧計画**: 障害に対する文書化された手順
- **テスト**: 定期的な回復訓練
＃＃ 安全
### アクセス制御
- **認証**: ユーザーの身元を確認します。
- **認可**: 権限の付与 (GRANT、REVOKE)
- **役割**: 管理を容易にするグループ権限
- **最小特権の原則**: 必要最小限のアクセス
### データ保護
- **保存時の暗号化**: 保存されたデータを暗号化します。
- **転送中の暗号化**: 接続用の TLS/SSL
- **マスキング**: 非運用環境では機密データを非表示にします
- **トークン化**: 機密データをトークンに置き換えます。
### 一般的な脆弱性
- **SQL インジェクション**: ユーザー入力内の悪意のある SQL
- **権限昇格**: 不正アクセスの取得
- **監査ログ**: すべてのデータベース アクティビティを追跡します。
- **コンプライアンス**: GDPR、HIPAA、PCI-DSS 要件
## 最新のデータベース テクノロジ
### クラウド データベース
- **AWS**: RDS、Aurora、DynamoDB、Redshift
- **Google Cloud**: Cloud SQL、Spanner、Bigtable、Firestore
- **Azure**: SQL データベース、Cosmos DB、Synapse
- **メリット**: マネージド サービス、自動スケーリング、バックアップが含まれます
### NewSQL データベース
- SQL の一貫性と NoSQL のスケーラビリティを組み合わせる
- **例**: CockroachDB、TiDB、YugabyteDB、Google Spanner
- **機能**: 分散、ACID トランザクション、水平スケーリング
### 時系列データベース
- タイムスタンプ付きデータ用に最適化
- **例**: InfluxDB、TimescaleDB、Prometheus
- **ユースケース**: IoT、モニタリング、財務データ
### ベクトル データベース
- 埋め込みベクトルの保存とクエリ
- **例**: 松ぼっくり、ミルバス、ウィービエイト、クドラント
- **ユースケース**: セマンティック検索、レコメンデーション システム、AI アプリケーション
### マルチモデル データベース
- 単一システムで複数のデータモデルをサポート
- **例**: ArangoDB、OrientDB、Azure Cosmos DB
- **利点**: 複数のデータベースを必要としない柔軟性
## ORM とデータ アクセス
### オブジェクト リレーショナル マッピング
- **目的**: データベース テーブルをプログラミング オブジェクトにマッピングする
- **人気の ORM**:
  - Python: SQLAlchemy、Django ORM、Peewee
  - JavaScript: Sequelize、Prisma、TypeORM
  - Java: 休止状態、JPA
  - Ruby：アクティブレコード
  - .NET: エンティティ フレームワーク
### メリット
- SQLからの抽象化
- タイプセーフティ
- 移行管理
- クエリ構築 API
### 欠点
- パフォーマンスのオーバーヘッド
- 複雑なクエリは書くのが難しい
- N+1 クエリの問題
- 学習曲線
## データベース管理
### DBA の責任
- インストールと構成
- パフォーマンスのチューニング
- バックアップとリカバリ
- セキュリティ管理
- キャパシティプランニング
- 監視と警告
- パッチ管理
### モニタリング指標
- クエリの応答時間
- スループット (1 秒あたりのトランザクション数)
- 接続数
- キャッシュヒット率
- ディスク I/O
- ロック待ち時間
- レプリケーションの遅延
### メンテナンスタスク
- **バキューム/分析**: 統計を更新し、スペースを再利用します
- **インデックスの再構築**: インデックスのデフラグ
- **統計の更新**: クエリ オプティマイザーに最新の情報を提供します
- **ログ ローテーション**: ログ ファイル サイズを管理します
- **容量計画**: 増加を予測し、アップグレードを計画します
