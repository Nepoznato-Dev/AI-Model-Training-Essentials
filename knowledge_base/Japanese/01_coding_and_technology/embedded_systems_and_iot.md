# 組み込みシステムとIoT
組み込みシステムは、車のエンジン コントロール ユニット、洗濯機のコントローラー、スマート サーモスタットのマイクロコントローラーなど、他のデバイスの中に隠されたコンピューターです。汎用コンピュータとは異なり、特定のタスク向けに設計されており、多くの場合、電力、メモリ、処理速度に厳しい制限があります。モノのインターネット (IoT) は、組み込みシステムをネットワークに接続することで拡張し、リモート監視、制御、データ収集を可能にします。これらは合わせて、物理世界と対話する数十億のコンピューティング デバイスを表します。
---

## 組み込みシステムの基礎
### Embedded の違い
|側面 |汎用コンピュータ |組み込みシステム |
|--------|-------------|------|
| **目的** |任意のソフトウェアを実行する |特定のタスクを実行する |
| **リソース** |豊富なCPU、RAM、ストレージ |制限あり (KB ～ MB の RAM、MHz ～ 低 GHz) |
| **パワー** |電源に接続されているか、大きなバッテリー |多くの場合、バッテリー駆動または環境発電 |
| **OS** |フル OS (Windows、Linux、macOS) | RTOS、ベアメタル、または組み込み Linux |
| **ユーザーインターフェイス** |リッチ (スクリーン、キーボード、マウス) |最小限 (LED、ボタン、センサー) またはなし |
| **リアルタイム** |ベストエフォート |多くの場合、リアルタイムの締め切りが厳しい |
| **生涯** | 3～7年 | 10～25 年以上 |
### マイクロコントローラーとマイクロプロセッサー
|特集 |マイクロコントローラー (MCU) |マイクロプロセッサ (MPU) |
|----------|-----------|----------|
| **統合** | CPU + RAM + フラッシュ + ペリフェラルを 1 つのチップ上に搭載 | CPUのみ。外部 RAM とストレージ |
| **パフォーマンス** |低から中程度 (MHz 範囲) |高 (GHz 範囲) |
| **パワー** |非常に低い (μA ～ mA) |より高い (数百 mA からアンペア) |
| **コスト** | $0.10 - $10 | $5 - $100+ |
| **例** | STM32、ESP32、Arduino (ATmega)、nRF52 | Raspberry Pi (BCM2835)、i.MX、Allwinner |
| **使用例** |センサー、アクチュエーター、簡易制御 |ディスプレイ、複雑な処理、Linux |

## 一般的な組み込みプラットフォーム
|プラットフォーム | MCU/MPU |主な機能 |最適な用途 |
|----------|----------|---------------|----------|
| **Arduino** | ATmega328P (その他) |単純;巨大なコミュニティ |学ぶ;プロトタイピング |
| **ESP32** | Espressif デュアルコア | Wi-Fi + Bluetooth。低コスト | IoT プロジェクト。接続されたデバイス |
| **Raspberry Pi Pico** | RP2040 (デュアルコア ARM) |手頃な価格; MicroPython のサポート |教育;趣味のプロジェクト |
| **STM32** | ARM Cortex-Mシリーズ |工業用グレード。広範囲 |プロフェッショナルが組み込まれています。工業用 |
| **nRF52/nRF53** |ノルディック・セミコンダクター | Bluetooth Low Energy スペシャリスト |ウェアラブル;ビーコン |
| **ラズベリーパイ** |ブロードコム BCM (ARM) |完全な Linux。 GPIO ピン |プロトタイピング;メディアセンター。ライトエッジコンピューティング |
| **ビーグルボーン** | TI シタラ (ARM) |リアルタイム PRU コア |産業用;リアルタイム アプリケーション |
| **ESP32-S3** |エスプレシフ | AIの加速。 USB |エッジAI。ビジョンアプリケーション |

## リアルタイム オペレーティング システム (RTOS)
RTOS は、重要なタスクが定義された時間枠内に完了することを保証します。
| RTOS |ライセンス |最適な用途 |
|------|--------|----------|
| **FreeRTOS** |マサチューセッツ工科大学 |最も一般的です。幅広い MCU サポート |
| **ゼファー** |アパッチ2.0 |モダンな; Linux財団;成長するエコシステム |
| **ThreadX (Azure RTOS)** |マサチューセッツ工科大学 |安全性が認定されています。 IoT |
| **エンボス** |コマーシャル |産業用;認証済み |
| **RT スレッド** |アパッチ2.0 |中国のエコシステム。世界的に成長する |
### RTOS vs ベアメタル
|側面 |ベアメタル | RTOS |
|----------|----------|------|
| **複雑さ** |単純なタスクにはシンプル |複雑な同時タスクに必要 |
| **スケジュール設定** |手動 (メインループ + 割り込み) |優先順位を付けたプリエンプティブなスケジューリング |
| **スケーラビリティ** |機能を追加するのが難しい |タスクの追加が簡単 |
| **メモリ** |最小限のオーバーヘッド |オーバーヘッドが小さい (数 KB) |

## 通信プロトコル
### 有線プロトコル
|プロトコル |スピード |距離 |使用例 |
|----------|----------|----------|----------|
| **UART** |最大1Mbps |ショート（オンボード） |デバッグコンソール。 GPSモジュール |
| **SPI** |最大100MHz |ショート（オンボード） |高速周辺機器 (ディスプレイ、フラッシュ) |
| **I²C** |最大3.4MHz |ショート（オンボード） |センサー;少ピン通信 |
| **できる** |最大1Mbps | 1kmまで |自動車;工業用 |
| **イーサネット** | 10Mbps - 100Gbps |最大100m |ネットワーキング;工業用 (拡張機能付き) |
| **USB** |最大 40 Gbps (USB4) |最大5m |周辺機器;充電 |
### ワイヤレスプロトコル
|プロトコル |範囲 |パワー |スピード |使用例 |
|----------|----------|----------|----------|----------|
| **Wi-Fi** | ～100メートル |高 |最大 Wi-Fi 7 (理論上 46 Gbps) |高帯域幅のIoT。ストリーミング |
| **Bluetooth クラシック** | ～100メートル |中 | 1～3Mbps |オーディオ;ファイル転送 |
| **BLE** (Bluetooth 低エネルギー) | ～100メートル |非常に低い | 1～2Mbps |ウェアラブル;ビーコン。センサー |
| **ジグビー** | ~100m (メッシュ) |低い | 250kbps |ホームオートメーション。産業用センサー |
| **Z ウェーブ** | ~100m (メッシュ) |低い | 100kbps |ホームオートメーション |
| **LoRa / LoRaWAN** |最大15km |非常に低い | 0.3～50kbps |農業;公共事業;都市全体のセンサー |
| **NB-IoT** |携帯電話の通信範囲 |低い | 250kbps |測光;資産追跡 |
| **スレッド/問題** | ~100m (メッシュ) |低い |中程度 |スマートホーム (Apple、Google、Amazon) |
| **セルラー (4G/5G)** |グローバル |高 |高 |コネクテッドビークル。遠隔監視 |

## IoT アーキテクチャ
### IoT スタック
|レイヤー |機能 |例 |
|----------|----------|----------|
| **デバイス** |センサー、アクチュエーター、マイクロコントローラー | ESP32、STM32、ラズベリーパイ |
| **接続性** |ネットワークプロトコル | MQTT、HTTP、CoAP、LoRaWAN |
| **エッジ コンピューティング** |デバイス付近での処理 | AWS グリーングラス、Azure IoT エッジ |
| **クラウド プラットフォーム** |データの取り込み、保存、処理 | AWS IoT、Azure IoT Hub、Google Cloud IoT |
| **アプリケーション** |ダッシュボード、分析、アラート | Grafana、カスタム Web アプリ |
### IoT 通信プロトコル
|プロトコル |パターン |最適な用途 |
|----------|-----------|----------|
| **MQTT** |発行/購読;軽量 |ほとんどの IoT アプリケーション。低帯域幅 |
| **HTTP/REST** |リクエスト/レスポンス |シンプルさが重要な場合。ウェブ統合 |
| **CoAP** |リクエスト/レスポンス。 UDP ベース |制約のあるデバイス。低電力 |
| **AMQP** |メッセージキュー |エンタープライズIoT。確実な配送 |
| **WebSocket** |双方向。永続的な接続 |リアルタイムのダッシュボード。ライブデータ |
### MQTT の詳細
|コンセプト |説明 |
|----------|---------------|
| **ブローカー** |メッセージをルーティングする中央サーバー (Mosquitto、EMQX、HiveMQ) |
| **トピック** |階層アドレス (例:`home/living-room/temperature`) |
| **QoS** | 0 (最大 1 回)、1 (少なくとも 1 回)、2 (厳密に 1 回) |
| **保持されたメッセージ** |トピックに関する最後のメッセージ。新規購読者に配信 |
| **最後の意志** |クライアントが予期せず切断されたときに発行されるメッセージ |

## エッジ コンピューティング
すべてをクラウドに送信するのではなく、ソースの近くでデータを処理します。
|メリット |説明 |
|----------|---------------|
| **待ち時間の短縮** |クラウドへの往復はありません。即時決定 |
| **帯域幅の節約** |概要または異常のみを送信する |
| **プライバシー** |機密データはオンプレミスに留まる |
| **信頼性** |インターネットがダウンしているときにも動作します |
|プラットフォーム |説明 |
|----------|---------------|
| **AWS グリーングラス** |エッジデバイスで Lambda 関数を実行する |
| **Azure IoT エッジ** |エッジデバイス上でコンテナを実行する |
| **NVIDIA Jetson** | GPU で高速化されたエッジ AI (Orin、Nano) |
| **ラズベリーパイ** |軽量エッジコンピューティング |
---

## ファームウェアアップデート (OTA)
無線アップデートを使用すると、バグを修正し、展開されたデバイスに機能を追加できます。
|懸念事項 |ソリューション |
|----------|----------|
| **信頼性** |デュアルバンクフラッシュ。失敗時のロールバック |
| **セキュリティ** |署名付き画像。暗号化された転送 |
| **サイズ** |デルタ更新 (変更部分のみ) |
| **接続性** |デバイスがオンラインになったときの更新をキューに入れる |

＃＃ まとめ
組み込みシステムと IoT は、ソフトウェアと物理世界の交差点を表します。モーターを制御するマイクロコントローラーからクラウドに接続されたセンサー ネットワークに至るまで、制約のあるリソース、リアルタイム要件、長い寿命、バグによる物理世界への影響など、Web やアプリの開発とは異なる考え方が必要です。エコシステムは大幅に成熟しました。ESP-IDF や Zephyr などのフレームワークにより専門能力開発が容易になり、AWS IoT や Azure IoT Hub などのプラットフォームがクラウド側を処理します。重要なスキルは、ハードウェア インターフェイス、通信プロトコル、電源管理、そして介入なしで何年も確実に実行する必要があるソフトウェアを作成する規律を理解することです。
