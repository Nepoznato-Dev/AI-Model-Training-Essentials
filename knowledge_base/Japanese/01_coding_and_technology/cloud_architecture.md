# クラウドアーキテクチャ
クラウド コンピューティングは、組織がソフトウェアを構築、展開、拡張する方法を根本的に変えました。物理サーバーを購入して維持する代わりに、オンデマンドでコンピューティング リソースをプロビジョニングし、使用した分だけ支払い、数分でグローバルに拡張できます。このファイルには、知っておくべき中心的な概念、アーキテクチャ パターン、サービス、ベスト プラクティスが含まれています。
---

## クラウド コンピューティングの基礎
### クラウド コンピューティングとは何ですか?
コンピューティング リソース (サーバー、ストレージ、データベース、ネットワーキング、ソフトウェア) をインターネット経由で従量課金制でオンデマンドで配信します。
### NIST の必須特性
|特徴 |意味 |
|--------------|----------|
| **オンデマンドのセルフサービス** |人間の介入なしでリソースをプロビジョニング |
| **ブロードネットワークアクセス** |標準メカニズムを介してネットワーク経由で利用可能 |
| **リソース プーリング** |マルチテナント モデル。動的に割り当てられるリソース |
| **急速な弾力性** |外側と内側に素早くスケール |
| **評価されたサービス** |使用量は監視され、請求されます。
### 導入モデル
|モデル |説明 |いつ使用するか |
|----------|---------------|---------------|
| **パブリック クラウド** |プロバイダーが所有。共有インフラストラクチャ (AWS、Azure、GCP) |ほとんどのワークロード。費用対効果の高い |
| **プライベート クラウド** |単一の組織に特化 |規制要件、機密データ |
| **ハイブリッド クラウド** |パブリックとプライベートの組み合わせ |柔軟性 + コンプライアンス |
| **マルチクラウド** |複数のパブリック クラウド プロバイダーの使用 |ベンダーロックインを回避し、最適な組み合わせを実現 |
### サービスモデル
|モデル | |を提供します例 |使用例 |
|----------|----------|----------|----------|
| **IaaS** | VM、ストレージ、ネットワーク、OS | AWS EC2、Azure VM、GCP Compute Engine |リフトアンドシフト移行、フルコントロール |
| **PaaS** |開発プラットフォーム、データベース、ミドルウェア | Heroku、Google App Engine、AWS Elastic Beanstalk |アプリ開発、API導入 |
| **SaaS** |インターネット経由で申請を完了 | Salesforce、Google Workspace、Microsoft 365 |電子メール、CRM、コラボレーション |
| **FaaS / サーバーレス** |イベント駆動型関数の実行 | AWS Lambda、Azure 関数、GCP クラウド関数 | API、イベント処理、スケジュールされたタスク |

## アーキテクチャ パターン
### 適切に設計されたフレームワーク
3 つの主要プロバイダーはすべて、次の 5 つの柱を中心に構築された、適切に設計されたフレームワークを公開しています。
|柱 |主要な原則 |
|------|------|
| **オペレーショナルエクセレンス** |操作を自動化します。頻繁に元に戻せる変更を加えます。失敗を予測する |
| **セキュリティ** |強力なアイデンティティ基盤。すべての層にセキュリティを適用します。転送中および保存中のデータを保護する |
| **信頼性** |回復手順をテストします。障害からの自動回復。水平方向に拡大縮小する |
| **パフォーマンス効率** |サーバーレスを使用します。数分でグローバル化します。頻繁に実験してください |
| **コストの最適化** |消費モデルを採用する。マネージド サービスを使用する。差別化のない仕事への支出をやめる |
### 一般的なパターン
|パターン |説明 |メリット |課題 |
|----------|---------------|----------|---------------|
| **マイクロサービス** |アプリを小さな独立したサービスに分解する |スケーラビリティ、障害分離、独立した展開 |分散された複雑性、データの一貫性 |
| **イベント駆動型** |コンポーネントはイベントを通じて通信します。疎結合、リアルタイム処理 |デバッグの複雑さ、最終的な整合性 |
| **サーバーレス** |サーバー管理は必要ありません。実行ごとに支払う |コスト効率、迅速な展開 |コールド スタート、ベンダー ロックイン、実行制限 |
| **階層化 (N 層)** |プレゼンテーション → ビジネス ロジック → データ アクセス → データベース |関心事の分離、保守性 |モノリシックになることができます |
| **宇宙ベース** |仮想化されたメモリ ノード間でデータを分散 |高い同時実行性、低いレイテンシを処理 |設計と管理が複雑 |

## ネットワーキング
### 仮想ネットワーク
すべてのクラウド デプロイメントは、Virtual Private Cloud (VPC / VNet) 内に存在します。これは、CIDR ブロック、サブネット (パブリックまたはプライベート)、ルート テーブル、およびゲートウェイで定義する分離されたネットワークです。
### ロードバランシングと CDN
|サービス |目的 |
|----------|----------|
| **ロード バランサ** |インスタンス間でトラフィックを分散する (L4 ネットワーク、L7 アプリケーション) |
| **CDN** |コンテンツをエッジ ロケーションにキャッシュしてレイテンシを低くする (CloudFront、Cloud CDN、Azure CDN) |
| **DNS** |ドメイン登録、ルーティング ポリシー、ヘルス チェック (Route 53、Cloud DNS、Azure DNS) |
### 接続オプション
|オプション |説明 |
|----------|---------------|
| **インターネット ゲートウェイ** | VPC のパブリック インターネット アクセス |
| **NAT ゲートウェイ** |プライベート サブネットの送信アクセス |
| **VPN** |オンプレミスへの暗号化されたトンネル |
| **直接接続 / ExpressRoute** |専用プライベート接続 |
| **VPC ピアリング** |アカウント内またはアカウント間で VPC を接続する |

＃＃ 安全
### 責任共有モデル
|レイヤー |プロバイダー |顧客 |
|----------|----------|----------|
| **インフラストラクチャ** (ハードウェア、設備) | ✅ | |
| **コンピューティング、ストレージ、ネットワーキング** | ✅ (管理) | ✅ (自己管理) |
| **データ、アプリケーション、アイデンティティ** | | ✅ |
サービスの管理が強化されると、プロバイダーが処理する量も増えます。 IaaS を使用すると、ほぼすべてを管理できます。 SaaS の場合、プロバイダーがほぼすべてを処理します。
### ID とアクセス管理 (IAM)
|コンセプト |説明 |
|----------|---------------|
| **ユーザー** |個人のアイデンティティ |
| **グループ** |ユーザーのコレクション |
| **役割** |サービスまたはユーザーの一時的な認証情報 |
| **ポリシー** |権限を定義するドキュメント |
| **原則** |最小限の特権、職​​務の分離 |
### データ保護
- **保存時の暗号化**: KMS、カスタマー マネージド キー、HSM。
- **転送中の暗号化**: TLS/SSL、HTTPS。
- **シークレット管理**: Secrets Manager、Key Vault — シークレットをハードコーディングしないでください。

## コスト管理
### 価格モデル
|モデル |説明 |最適な用途 |
|----------|---------------|----------|
| **オンデマンド** |使用した分を秒/時間単位で支払います |変動する短期的なワークロード |
| **予約済みインスタンス** | 1 ～ 3 年の契約、大幅な割引 |定常状態のワークロード |
| **スポット インスタンス** |未使用の容量を入札します。中断することができます |フォールトトレラントで柔軟なジョブ |
| **貯蓄プラン** |柔軟なコミットメント価格 |混合使用パターン |
| **無料利用枠** |新しいアカウントの無料使用は制限されています |学習、プロトタイピング |
### 最適化戦略
ワークロードに合わせてインスタンスのサイズを適切に調整します。自動スケーリングを使用して需要の急増に対処します。予測可能な負荷に備えて容量を確保します。バッチ ジョブにはスポット インスタンスを使用します。アクセス頻度の低いデータをより安価なストレージ層に移動します。未使用のリソース (孤立したスナップショット、アイドル状態のロード バランサー、接続されていない IP) を削除します。

## 高可用性と災害復旧
### 可用性の概念
|コンセプト |説明 |
|----------|---------------|
| **アベイラビリティーゾーン (AZ)** |リージョン内で物理的に分離されたデータセンター |
| **地域** |複数の AZ を持つ地理的エリア |
| **エッジ位置** |コンテンツ配信のための CDN キャッシュの場所 |
### 災害復旧戦略
|戦略 |コスト | RTO | RPO |説明 |
|----------|------|-----|-----|---------------|
| **バックアップと復元** |最低 |営業時間 |時間 – 日 |定期的なバックアップ、必要な場合の復元 |
| **パイロットライト** |低い |分–時間 |分 |コア要素は常に実行され、災害時にスケールアップ |
| **ウォーム スタンバイ** |中 |分 |秒–分 |縮小バージョンは常に実行中 |
| **マルチサイトアクティブ/アクティブ** |最高 |ゼロに近い |ゼロ |複数の地域で完全に生産 |
**RTO** (目標復旧時間) = 許容可能な最大ダウンタイム。 **RPO** (目標復旧時点) = 許容可能な最大データ損失。
