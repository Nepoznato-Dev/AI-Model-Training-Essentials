# データ構造とアルゴリズム
データ構造は、データに対する操作が効率的に行われるようにメモリ内でデータを編成する方法です。アルゴリズムは、問題を解決するための段階的な手順です。これらは一緒になってコンピューター サイエンスの基礎を形成します。これまでに使用したすべてのプログラムはそれらに依存しています。適切なデータ構造を選択すると、信じられないほど遅いプログラムを高速なプログラムに変えることができ、適切なアルゴリズムを知ることで、解決不可能な問題を些細な問題に変えることができます。

## 基本的なデータ構造
### 線状構造

|----------|----------|----------|----------|----------|----------|

| **デク** |両端の O(1) | O(n) |両端の O(1) |両端の O(1) |スライディングウィンドウ。仕事盗み |
### ハッシュベースの構造
|構造 |検索 |挿入 |削除 |使用例 |
|----------|----------|----------|----------|----------|

| **ハッシュ セット** |お(1) |お(1) |お(1) |メンバーシップテスト。重複排除 |

## アルゴリズムの複雑さ (Big-O)
Big-O 表記法は、入力サイズが増加するにつれてアルゴリズムの時間またはスペース要件がどのように増大するかを表します。
|複雑さ |名前 |例 |
|----------|------|----------|
| **O(1)** |定数 |ハッシュテーブルルックアップ。インデックスによる配列アクセス |
| **O(log n)** |対数 |二分探索。バランスのとれたツリー操作 |
| **O(n)** |リニア |線形検索。配列を反復する |
| **O(n log n)** |線形演算 |ソートをマージします。ヒープソート;最も効率的な汎用ソート |
| **O(n²)** |二次関数 |バブルソート;同じデータに対するネストされたループ |
| **O(2^n)** |指数 |ブルートフォースサブセット生成。単純再帰フィボナッチ |
| **O(n!)** |階乗 |巡回セールスマン（強引）。順列 |
### よくある誤解
|誤解 |現実 |
|--------------|----------|
| "O(n) は常に O(n²) よりも高速です" | n が小さい場合、定数係数がより重要になります。
| 「ビッグオーは常に低い方が良い」 |時空間のトレードオフが存在します。 O(1) ルックアップは O(n) メモリを使用します。
| 「ビッグオーは正確な速度を教えてくれます」 |絶対的な時間ではなく、成長率を表します。

## 並べ替えアルゴリズム
|アルゴリズム |ベスト |平均 |最悪 |スペース |安定 |インプレース |
|----------|------|----------|----------|----------|----------|----------|
| **バブルソート** | O(n) | O(n²) | O(n²) |お(1) |はい |はい |
| **挿入ソート** | O(n) | O(n²) | O(n²) |お(1) |はい |はい |
| **選択の並べ替え** | O(n²) | O(n²) | O(n²) |お(1) |いいえ |はい |
| **並べ替えを結合** | O(n log n) | O(n log n) | O(n log n) | O(n) |はい |いいえ |
| **クイックソート** | O(n log n) | O(n log n) | O(n²) | O(log n) |いいえ |はい |
| **ヒープソート** | O(n log n) | O(n log n) | O(n log n) |お(1) |いいえ |はい |
| **ティム・ソート** | O(n) | O(n log n) | O(n log n) | O(n) |はい |いいえ |
**実践的なアドバイス**: 言語の組み込みソート (Python の`sorted()`、JavaScript の`Array.sort()`) を使用してください。これらは、あらゆるエッジケースを処理する高度に最適化されたアルゴリズム (Tim Sort、Introsort) を使用します。

## 検索アルゴリズム
|アルゴリズム |データ構造 |複雑さ |要件 |
|----------|------|-----------|-------------|
| **線形検索** |任意 | O(n) |なし |
| **二分探索** |ソートされた配列 | O(log n) |データは並べ替える必要があります |
| **ハッシュ テーブル ルックアップ** |ハッシュテーブル | O(1) 平均 |優れたハッシュ関数 |
| **BFS*​​ (幅優先検索) |グラフ/ツリー | O(V + E) |重み付けされていない最短パス |
| **DFS** (深さ優先検索) |グラフ/ツリー | O(V + E) |パスの検索。サイクル検出 |
| **ディクストラの** |加重グラフ | O((V + E) log V) |負でない重み。最短経路 |
| **A* 検索** |加重グラフ | O((V + E) log V) |ヒューリスティックに基づいたガイド。許容可能なヒューリスティックを使用して最適化 |

## 主要なアルゴリズム パターン
|パターン |説明 |問題例 |
|----------|---------------|------|
| **分割統治** |問題をサブ問題に分割します。再帰的に解決します。組み合わせる |ソートをマージします。クイックソート;二分探索 |
| **動的プログラミング** |重複するサブ問題に分割します。結果をキャッシュする |フィボナッチ;ナップザック;最長共通部分列 |
| **貪欲** |各ステップで局所的に最適な選択を行う |ディクストラの。ハフマン符号化。アクティビティの選択 |
| **後戻り** |可能性を試してください。悪い選択を取り消します。代替案を試す |数独ソルバー; N-クイーン。順列 |
| **引き違い窓** |要素のウィンドウを維持します。データ上でスライドさせます |サイズ K の最大合計部分配列。繰り返しのない最長の部分文字列 |
| **2 つのポイント** |互いに向かって移動するか、同じ方向に移動する 2 つのポインターを使用します。ソートされた配列のペアの合計。重複を削除 |
| **答えの二分探索** |解答空間の二分探索 |最小限のページを割り当てます。攻撃的な牛 |

## いつ何を使用するか
|問題 |データ構造 |アルゴリズム |
|----------|---------------|----------|
|高速なキーと値のルックアップ |ハッシュテーブル/辞書 |ハッシュ |
|並べ替え順序を維持する |バランスの取れた BST (ツリーマップ、std::set) |ツリー操作 |
|優先順位に基づいた処理 |ヒープ / 優先キュー |ヒープ操作 |
|最短パス (重み付けなし) |グラフ（隣接リスト） | BFS |
|最短パス (加重) |グラフ（隣接リスト） |ダイクストラの / A* |
|メンバーシップテスト |ハッシュセット / ブルームフィルター |ハッシュ |
|プレフィックス マッチング |トライ |トラバーサルを試す |
|範囲クエリ |セグメントツリー / フェンウィックツリー |ツリー操作 |
| LRUキャッシュ |ハッシュマップ + 二重リンクリスト |複合操作 |
|接続されたコンポーネント |素集合和集合 (和集合検索) |結合と検索 |

＃＃ まとめ
データ構造とアルゴリズムは単なるインタビューのトピックではなく、効率的なソフトウェアの構成要素です。配列とハッシュ テーブルは、日常的なニーズのほとんどを処理します。ツリーとグラフは、階層データとリレーショナル データを処理します。並べ替えと検索は、標準ライブラリの問題を解決します。アルゴリズム パターン (分割統治、動的プログラミング、貪欲、バックトラッキング) は、新しい問題に取り組むための再利用可能な戦略です。重要なスキルはアルゴリズムを暗記することではありません。どのパターンが特定の問題に適合するかを認識し、ジョブに適したデータ構造を選択します。
