# モバイル開発
モバイル開発は、主に iOS (Apple) と Android (Google) 用のスマートフォンやタブレット用のアプリケーションを構築する実践です。これには、小さな画面用の UI デザインから、バッテリー寿命の管理、ネットワークの不安定性の処理、ストアを通じたアプリの配布まで、あらゆるものが含まれます。この分野は大幅に成熟し、クロスプラットフォーム フレームワークはほとんどのユースケースでネイティブ開発と競合するようになりました。

## クロスプラットフォーム フレームワーク
一度ビルドすれば、iOS と Android の両方にデプロイできます。
|フレームワーク |言語 |レンダリング |パフォーマンス |最適な用途 |
|----------|----------|---------------|---------------|----------|
| **フラッター** |ダーツ |カスタムエンジン(Skia/インペラー) |ネイティブに近い |豊富なカスタム UI。プラットフォーム間で一貫した外観 |
| **ネイティブに反応** | JavaScript/TypeScript |ブリッジ経由のネイティブ コンポーネント |良い (新しいアーキテクチャはこれを改善します) | Web/JS 経験のあるチーム |
| **Kotlin マルチプラットフォーム** |コトリン |プラットフォームごとのネイティブ UI |ネイティブ |ビジネスロジックの共有。ネイティブ UI |
| **マウイ** (.NET) | C# |ネイティブ コントロール |良い | .NET チーム。エンタープライズ アプリ |
| **イオン/コンデンサ** | HTML/CSS/JS |ウェブビュー |下 |シンプルなアプリ。ウェブチーム |
### Flutter vs React Native
|側面 |フラッター |ネイティブに反応する |
|----------|----------|---------------|
| **言語** |ダーツ | JavaScript/TypeScript |
| **UI レンダリング** |すべてをそれ自体で描画します (プラットフォーム間で一貫性があります) |ネイティブ コンポーネントを使用します (プラットフォーム固有の外観)。
| **ホットリロード** |素晴らしい |良い |
| **生態系** |急速に成長しています。ウィジェットベース |大きい; npmエコシステム |
| **学習曲線** |ダーツを学ぶ必要があります | Web 開発者にとってより簡単 |
| **プラットフォームの統合** |ネイティブ コードのプラットフォーム チャネル |ブリッジ経由のネイティブモジュール |
| **パフォーマンス** |素晴らしい;ネイティブに近い |良い;ブリッジのオーバーヘッド (新しいアーキテクチャで削減) |

|パターン |説明 |いつ使用するか |
|----------|---------------|---------------|

## モバイルに関する主な懸念事項
### オフラインファーストの設計
モバイル アプリは信頼できるインターネットなしで動作する必要があります。
|戦略 |説明 |
|----------|---------------|
| **ローカル データベース** |デバイス上にデータを保存 (SQLite、Room、CoreData、Realm) |
| **同期戦略** |オンライン時にサーバーと同期します。競合を解決する |
| **楽観的な UI** | UI をすぐに更新します。サーバーが応答したら調整する |
| **キャッシュ** | API 応答をキャッシュします。オフライン時にキャッシュから提供 |
＃＃＃ パフォーマンス
|懸念事項 |ソリューション |
|----------|----------|
| **アプリの起動時間** |遅延読み込み;初期化作業を最小限に抑える |
| **メモリ使用量** |画像圧縮。メモリリークを回避します。プロファイリング ツールを使用する |
| **バッテリーの消耗** |バックグラウンド作業を削減します。バッチネットワークリクエスト。効率的な位置情報サービスを使用する |
| **ネットワーク効率** |ペイロードを圧縮します。ページネーションを使用します。積極的にキャッシュする |
| **リストのスクロール** |ビューをリサイクルします。画像の遅延読み込みを使用する |
＃＃＃ 安全
|懸念事項 |ソリューション |
|----------|----------|
| **保存中のデータ** |機密データの暗号化 (iOS ではキーチェーン、Android では EncryptedSharedPreferences) |
| **ネットワーク** |常に HTTPS。機密性の高いアプリの証明書の固定 |
| **認証** |生体認証 (Face ID、指紋); OAuth;トークンストレージ |
| **コードの難読化** | Android 用 ProGuard/R8。 iOS 用ビットコード |
| **脱獄/ルート検出** |侵害されたデバイスを検出します。機能を制限する |

## アプリのライフサイクル
|状態 |説明 |何をすべきか |
|----------|---------------|---------------|
| **フォアグラウンド (アクティブ)** |ユーザーがアプリを操作中 |通常動作 |
| **背景** |アプリは表示されませんがメモリ内に残っています |アニメーションを一時停止します。状態を保存する |
| **一時停止中** | OS はリソースを節約するためにアプリをフリーズしました |何もない;アプリがフリーズしています |
| **終了** | OS がメモリを解放するためにアプリを強制終了しました |次回の起動時に状態を復元する |

＃＃ まとめ
モバイル開発では、ネイティブ (最高のパフォーマンス、プラットフォーム固有) とクロスプラットフォーム (コードベースの共有、反復の高速化) のどちらかを選択できます。 Flutter と React Native は、ほとんどのアプリケーションにとってクロスプラットフォームが正しい選択となるまでに成熟しました。主要な課題は、フレームワークに関係なく同じままです。それは、オフラインファーストの設計、限られたハードウェアでのパフォーマンス、バッテリー効率、信頼できないデバイスでのセキュリティ、アプリストアのレビュープロセスのナビゲートです。この分野では、高速起動、スムーズなスクロール、接続不良時の適切な処理など、ユーザー エクスペリエンスを第一に考える開発者が表彰されます。
