# アンサンブルメソッド
アンサンブル手法は、複数の機械学習モデルを組み合わせて、単一モデルが単独で達成できるよりも優れた予測を生成します。直感は簡単です。それぞれがある程度正確であるものの、異なるエラーを起こす複数のモデルがある場合、それらの予測を組み合わせることで、個々のエラーが相殺され、より堅牢な結果が得られます。アンサンブルは、ほとんどの競争力のある機械学習ソリューションの背後にあり、実稼働システムでは依然として最も信頼性の高い技術の一部です。
---

## アンサンブルが機能する理由
|原則 |説明 |
|----------|---------------|
| **群衆の知恵** |複数の不完全な推定値を平均すると、単一の推定値よりも優れています。
| **バイアスと分散のトレードオフ** |アンサンブルは、他の要素を犠牲にすることなく分散 (バギング) またはバイアス (ブースティング) を削減できます。
| **エラーの多様性** |モデルが異なるエラーを起こした場合、それらを組み合わせることで個々のエラーが相殺されます。
| **決定境界平滑化** |複数のモデルは、1 つのモデルよりも堅牢な意思決定面を作成します。
---

## バギング (ブートストラップ集約)
### 仕組み
|ステップ |説明 |
|------|---------------|
| **1.ブートストラップ サンプリング** |トレーニング データから複数のランダム サンプル (置換あり) を抽出する |
| **2.基本モデルのトレーニング** |各ブートストラップ サンプル (通常はデシジョン ツリー) で 1 つのモデルをトレーニングします。
| **3.集計** |回帰の場合: 平均予測。分類: 多数決 |
### 主な特徴
|特徴 |説明 |
|--------------|---------------|
| **分散を削減** |平均化により個々のモデルの変動が平滑化されます。
| **並行トレーニング** |各基本モデルは独立しています。同時にトレーニングすることができます |
| **袋から出しての評価** |各サンプルは一部のブートストラップ サンプルから除外されます。それらを検証に使用します。
| **無相関** |各分割でのランダムな特徴選択により、ツリー間の相関が減少します。
### ランダムフォレスト
|側面 |説明 |
|----------|---------------|
| **基礎学習者** |ディシジョンツリー |
| **重要な追加** | At each split, consider only a random subset of features (typically sqrt(n_features)) |
| **機能する理由** | Random feature selection decorrelates trees, making the ensemble more robust |
| **ハイパーパラメータ** |木の数。最大深度。葉ごとの最小サンプル。最大の機能 |
| **強み** |高次元データを扱います。外れ値に対して堅牢。機能の重要性を提供します |
| **弱点** |単一のツリーよりも解釈が困難です。ノイズの多い回帰タスクではオーバーフィットする可能性があります。
---

## ブースト
### 仕組み
|ステップ |説明 |
|------|---------------|
| **1.最初のモデルを訓練** |データに基づいて基本モデル (多くの場合、浅い木/「切り株」) をトレーニングします。
| **2.エラーを特定します** |モデルが間違っていたインスタンスを見つける |
| **3.次のモデルをトレーニングする** |間違いに焦点を当てた新しいモデルをトレーニングする (再重み付けまたは残差フィッティング) |
| **4.順番に結合** |新しいモデルはそれぞれ、以前のすべてのモデルで蓄積されたエラーを修正します。
| **5.繰り返し** |指定されたラウンド数だけ継続する |
### ブーストアルゴリズム
|アルゴリズム |損失関数 |主な機能 |
|----------|--------------|---------------|
| **アダブースト** |指数 |誤って分類されたインスタンスの重みを再設定します。単純;ノイズに敏感 |
| **勾配ブースティング** |微分可能な損失 |残差 (損失の勾配) を適合させます。より柔軟 |
| **XGブースト** |正規化された勾配ブースティング | L1/L2 正則化。二次勾配。ハードウェアの最適化 |
| **ライトGBM** |勾配ベースの片側サンプリング |葉ごとの成長。ヒストグラムベース。大規模なデータセットで高速 |
| **キャットブースト** |順序付けされたブースティング |カテゴリ特徴をネイティブに処理します。過学習を減らす |
### ブースティングとバギングの比較
|寸法 |袋詰め |ブースト |
|----------|-----------|----------|
| **トレーニング** |パラレル |シーケンシャル |
| **焦点** |分散を減らす |バイアスを軽減 |
| **ベースモデル** |高分散、低バイアス (深いツリー) |低分散、高バイアス (浅い木/切り株) |
| **組み合わせ** |等しい重み |パフォーマンスによる重み付け |
| **過学習** |傾向が少ない |ラウンド数が多すぎるとオーバーフィットする可能性があります。
| **ノイズ感度** |堅牢 |ノイズの多いデータに敏感 |

## スタッキング
### 仕組み
|ステップ |説明 |
|------|---------------|
| **1.基本モデルのトレーニング** |多様なモデルをトレーニング (ランダム フォレスト、SVM、ニューラル ネットワーク、勾配ブースティングなど) |
| **2.予測を生成** |入力特徴としてアウトオブフォールド予測 (相互検証) を使用する |
| **3.メタモデルを訓練する** |基本モデルの予測に基づいて第 2 レベルのモデルをトレーニングする |
| **4.最終予測** |基本モデルは予測します。メタモデルはその予測を結合します。
### スタッキングのベスト プラクティス
|練習 |理由 |
|----------|----------|
| **多様なベースモデルを使用** |アルゴリズムが異なれば、発生するエラーも異なります。多様性が重要です |
| **基本予測には相互検証を使用します** |メタモデルがオーバーフィット基本モデルを悪用することを学習するのを防ぎます。
| **メタモデルはシンプルにしてください** |ロジスティック回帰または浅いツリー。基本モデルは重労働を行います。
| **生の特徴をメタモデルに含める** |メタモデルに元の機能へのアクセスを与えると役立つ場合もあります。

## 実践的なガイダンス
### どのアンサンブルをいつ使用するか
|シナリオ |推奨される方法 |
|----------|--------|
| **素早いベースライン。表形式のデータ** |ランダムフォレスト |
| **最大の精度。表形式のデータ** | XGBoost / LightGBM / CatBoost |
| **ノイズの多いデータ** |バギング (ブーストするとノイズがオーバーフィットします) |
| **解釈が必要** |機能が重要な単一モデルまたは小規模アンサンブル |
| **多様なモデルタイプ** |スタッキングまたは投票 |
| **オンライン学習** |ストリーミングアンサンブルメソッド。適応ブースティング |
| **不均衡なデータ** |バランスの取れたランダムフォレスト。コスト重視のブースト |
### アンサンブルの多様性戦略
|戦略 |説明 |
|----------|---------------|
| **さまざまなアルゴリズム** |ツリーベース、線形、ニューラル モデルを組み合わせる |
| **さまざまな機能** |さまざまな機能サブセットでモデルをトレーニングする |
| **さまざまなデータのサブセット** |袋詰め;サブサンプリング |
| **さまざまなハイパーパラメータ** |同じアルゴリズムをさまざまな構成で使用する |
| **異なる期間** |異なる時間枠でトレーニングする |

＃＃ まとめ
アンサンブル手法が機能するのは、複数の不完全なモデルを単一の堅牢な予測子に結合するためです。バギング (ランダム フォレスト) は、ブートストラップ サンプルと平均化でモデルを並行してトレーニングすることで分散を削減します。ブースティング (XGBoost、LightGBM、CatBoost) は、モデルを順番にトレーニングし、それぞれ以前のエラーを修正することでバイアスを軽減します。スタッキングでは、メタモデルを使用して、多様な基本モデルを組み合わせます。投票と平均化は最も単純なアンサンブルです。共通点は多様性です。アンサンブルは、コンポーネント モデルが個別に合理的であるにもかかわらず、さまざまなエラーが発生する場合に最適に機能します。実際には、表形式のデータに対する勾配ブースティングが単一のアプローチで最も高いパフォーマンスを発揮することがよくありますが、競技や一か八かのアプリケーションでは、多様なモデルを積み重ねることで精度がさらに向上します。
