# 特徴量エンジニアリング
特徴エンジニアリングは、生データを機械学習モデルをより効果的な表現に変換するプロセスです。これは、ML パイプラインの最も重要なステップであるとよく説明されます。つまり、選択したアルゴリズムよりもモデルに与える機能の方が重要です。通常、巧みに作成された特徴を備えた単純なモデルは、生の未処理の入力を備えた複雑なモデルよりも優れたパフォーマンスを発揮します。技術の要点は、モデルが学習できる信号を作成できるよう、ドメインとデータの両方を十分に理解することにあります。
---

## 特徴量エンジニアリングが重要な理由
|係数 |影響 |
|----------|----------|
| **信号品質** |より優れた機能 = モデルが学習する明確なパターン |
| **モデルの単純さ** |優れた機能により、単純なモデルでも適切なパフォーマンスが得られます。複雑なアーキテクチャの必要性が減ります。
| **トレーニング速度** |関連性があり、適切に拡張された機能はより速く収束します。
| **一般化** |ドメイン情報に基づく機能は、モデルが目に見えないデータを処理するのに役立ちます。
| **解釈可能性** |意味のある機能は関係者に説明しやすくなります。
---

## 特徴変換の種類
### 数値変換
|変換 |式 / 説明 |いつ使用するか |
|---------------|---------------------|---------------|
| **ログ変換** | log(x) または log(x + 1) |右に歪んだ分布。金銭的価値 |
| **平方根** | sqrt(x) |中程度のスキュー。カウントデータ |
| **ボックスコックス** |最適なべき乗変換を見つけるパラメトリック変換 |データをより正規分布にする |
| **ヨー・ジョンソン** | Box-Cox と似ていますが、負の値を処理します。負の値を含む偏ったデータ |
| **標準化** | (x - 平均) / 標準 |さまざまなスケールの特徴。正規性を仮定したアルゴリズム |
| **最小-最大スケーリング** | (x - 最小) / (最大 - 最小) |特徴を [0, 1] に境界付けします。画像のピクセル値 |
| **堅牢なスケーリング** | (x - 中央値) / IQR |外れ値のあるデータ |
| **ビニング** |連続値をカテゴリ値に変換する |非線形な関係。デシジョン ツリー |
| **多項式の特徴** | x²、x³、x₁×x₂ |線形モデルでの非線形関係のキャプチャ |
### カテゴリカルなエンコーディング
|エンコーディング |説明 |いつ使用するか |
|----------|---------------|---------------|
| **ワンホット エンコーディング** |カテゴリごとにバイナリ列を作成する |カーディナリティの低いカテゴリ。ツリーベースのモデルはネイティブに処理します。
| **ラベルエンコーディング** |各カテゴリに整数を割り当てる |順序カテゴリ。ツリーベースのモデル |
| **ターゲットエンコーディング** |カテゴリをターゲット変数の平均値に置き換える |高カーディナリティのカテゴリ。スムージングによる過学習を避ける |
| **周波数エンコード** |カテゴリをその数または頻度に置き換えます。頻度自体が有益な場合 |
| **バイナリエンコーディング** |整数でエンコードされたカテゴリを 2 進数に変換する |高いカーディナリティ。ワンホットと比較して次元を削減 |
| **埋め込み** |密なベクトル表現を学ぶ |非常に高いカーディナリティ。 NLP;推薦システム |
| **ハッシュ エンコーディング** |カテゴリを固定数の特徴にハッシュする |非常に高いカーディナリティ。オンライン学習 |
### 日付と時刻の機能
|特集 |説明 |
|----------|---------------|
| **時刻** |日々のパターン（ラッシュアワー、夜間）をキャプチャ |
| **曜日** |平日と週末の影響 |
| **月/四半期** |季節の模様 |
| **週末です** |週末のバイナリ フラグ |
| **休日です** |祝日のバイナリ フラグ |
| **イベントからの経過時間** |最後の購入からの日数。前回のログインからの時間 |
| **循環エンコーディング** | sin(2π × 時間 / 24)、cos(2π × 時間 / 24) — 時間の循環性を保持します |

## 欠損値の処理
|戦略 |説明 |いつ使用するか |
|----------|---------------|---------------|
| **行を削除** |欠損値のある行を削除する |欠損データはごく一部です。 MCAR (完全にランダムに欠落) |
| **列を削除** |欠損値が多すぎるフィーチャを削除する |機能はほとんど欠落しています。重要ではない |
| **平均/中央値の代入** |特徴の平均値または中央値を入力します |単純;平均は維持されますが、分散は減少します。
| **モード代入** |カテゴリカルに最も頻度の高い値を入力する |カテゴリ特徴 |
| **KNN 補完** | k 最近傍を使用して欠損値を推定する |類似のインスタンスが欠損値の予測に役立つ場合 |
| **モデルベースの代入** |モデルをトレーニングして欠損値を予測する |より正確;計算コストが高い |
| **インジケーターがありません** |欠落をフラグするバイナリ列を追加します。欠落自体が有益な場合 |
| **補間** |補間値で埋める (線形、スプライン) |時系列;順序付けされたデータ |
---

## 機能の選択
### フィルターメソッド
|方法 |説明 |
|----------|---------------|
| **相関関係** |相互に相関性の高い特徴を削除する |
| **分散しきい値** |分散がゼロに近い特徴を削除する |
| **相互情報** |各機能がターゲットについて提供する情報を測定します。
| **カイ二乗** |カテゴリ特徴とターゲットの間の独立性をテストする |
| **ANOVA F 検定** |数値特徴平均がターゲット クラス間で異なるかどうかをテストする |
### ラッパーメソッド
|方法 |説明 |
|----------|---------------|
| **前方選択** |空から始めてください。最高の機能を一度に 1 つずつ追加します |
| **後方消去** |すべてから始めてください。最悪の機能を一度に 1 つずつ削除する |
| **再帰的機能削除 (RFE)** |モデルを繰り返しトレーニングします。最も重要でない機能を削除する |
### 埋め込みメソッド
|方法 |説明 |
|----------|---------------|
| **L1 正則化 (なげなわ)** |無関係な特徴の重みをゼロに縮小します。
| **ツリーベースの重要性** |ツリー モデルからの特徴重要度を使用する |
| **SHAP 値** |各特徴の予測への寄与を測定する |

## ドメイン固有の機能エンジニアリング
### テキスト機能
|特集 |説明 |
|----------|---------------|
| **TF-IDF** |逆文書頻度で重み付けされた用語頻度 |
| **単語の埋め込み** |意味論的な意味を捉える高密度ベクトル (Word2Vec、GloVe) |
| **文字 N グラム** |サブワードパターンをキャプチャします。タイプミスや形態論に役立ちます |
| **テキスト統計** |長さ;単語数。文数。平均単語長 |
| **可読性スコア** |フレッシュキンケイド;ガンニングフォグインデックス |
### 時系列の特徴
|特集 |説明 |
|----------|---------------|
| **ラグ機能** |以前の値: y(t-1)、y(t-7)、y(t-30) |
| **ローリング統計** |ウィンドウ全体の平均、標準、最小、最大 |
| **違い** | y(t) - y(t-1);トレンドを捉える |
| **季節の違い** |年間季節性のある月次データの場合は y(t) - y(t-12) |
| **フーリエ項** |季節パターンのサイン項とコサイン項 |
### 画像の特徴 (深層学習以前)
|特集 |説明 |
|----------|---------------|
| **HOG** (方向性のある勾配のヒストグラム) |エッジ方向の分布 |
| **LBP** (ローカル バイナリ パターン) |テクスチャの説明 |
| **SIFT** (スケール不変特徴変換) |キーポイント記述子 |
| **カラーヒストグラム** |画像内の色の分布 |

## 特徴エンジニアリングのベスト プラクティス
|練習 |説明 |
|----------|---------------|
| **データ漏洩を回避** |将来の情報やテスト セットを使用して機能を作成しないでください。
| **すべてを文書化** |どのような変換が適用されたのか、そしてその理由を記録します。
| **機能のバージョンを設定** |モデルの変更とともに機能の変更を追跡する |
| **有無を検証** |新しい機能が実際にモデルのパフォーマンスを向上させるかどうかをテストします。
| **再現性を維持してください** |特徴エンジニアリング パイプラインは決定論的で再現可能である必要があります。
| **機能のドリフトを監視** |機能の分布は時間の経過とともに変化する可能性があります。監視と再トレーニング |
---

＃＃ まとめ
特徴量エンジニアリングでは、ドメインの知識と機械学習が融合します。これは、乱雑で不完全な高次元の生データを、モデルが学習できるクリーンで有益な表現に変換するプロセスです。数値変換はスキューとスケールを処理します。カテゴリカル エンコーディングは、ラベルをモデルが使用できる数値に変換します。日付特徴は時間的パターンを捉えます。欠損値戦略は不完全なデータを処理します。機能を選択すると、ノイズと冗長性が除去されます。最高の機能エンジニアは探偵のように考えます。データ内にどのようなシグナルが存在するべきなのか、それらのシグナルがどこに隠されているのか、そして誠実 (データ漏洩がない)、再現可能で時間の経過に伴う変化に強い方法でシグナルを抽出する方法を考えます。
