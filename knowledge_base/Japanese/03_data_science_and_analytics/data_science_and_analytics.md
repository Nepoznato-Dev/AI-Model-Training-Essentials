# データサイエンスと分析
データ サイエンスは、生のデータを実用的な洞察に変える学問です。これは統計、コンピューター サイエンス、専門知識の交差点に位置し、金融から医療に至るまであらゆる分野で不可欠なものとなっています。このファイルでは、すべての実務者が知っておくべき中心的な概念、ツール、ワークフローについて説明します。
---

## データサイエンスのプロセス
ほとんどのプロジェクトは、業界標準のライフサイクルである **CRISP-DM** のバリエーションに従います。
|フェーズ |何が起こるのか |通常の時間 |
|----------|---------------|--------------|
| **ビジネスの理解** |目標、成功指標、制約を定義する | 10～15% |
| **データの理解** |データを収集、探索、プロファイリングする | 10～15% |
| **データの準備** |機能のクリーンアップ、変換、エンジニアリング | ~50–60% |
| **モデリング** |モデルの選択とトレーニング | 10～15% |
| **評価** |ビジネス目標に照らしてパフォーマンスを評価する | 5～10% |
| **展開** |モデルを本番環境に出荷する | 5～10% |
データ準備、特にデータクレンジングは、データサイエンティストの時間の約80%を消費すると広く推定されています。

|タイプ |説明 |例 |
|------|-------------|----------|
| **構造化** |行と列で構成 | SQL テーブル、スプレッドシート |

## 統計の基礎
### 記述統計と推論統計
記述統計は、あなたが「持っているもの」を要約したものです。推論統計を使用すると、自分が「持っていない」もの (より広範な集団) について結論を導き出すことができます。
|コンセプト |主要なアイデア |
|----------|----------|
| **中心的な傾向** |平均値 (外れ値に敏感)、中央値 (堅牢)、最頻値 (最も頻繁) |
| **分散** |範囲、分散、標準偏差、四分位範囲 |
| **分布形状** |歪度 (非対称性)、尖度 (尾部の重さ) |
| **仮説検証** |帰無仮説と対立仮説、p 値、有意水準 (α) |
| **信頼区間** |真の母集団パラメータが含まれる可能性がある範囲 |
| **タイプ I / タイプ II エラー** |偽陽性 (真のヌルを拒否) / 偽陰性 (実際の効果を欠落) |
### 一般的な統計検定
|テスト |いつ使用するか |
|------|---------------|
| **t 検定** | 2 つのグループ間の平均値を比較する |
| **分散分析** | 3 つ以上のグループの平均を比較する |
| **カイ二乗** |カテゴリ変数の独立性をテストする |
| **マン・ホイットニー U** | t 検定のノンパラメトリック代替法 (正規性の仮定なし) |
| **ピアソン相関** | 2 つの連続変数間の線形関係 |
| **スピアマン相関** |単調な関係 (ランクベース、より堅牢) |
### 知っておく価値のある確率分布
|配布 |使用例 |
|---------------|----------|
| **通常** |自然現象、測定誤差 — 古典的な釣鐘曲線 |
| **二項** |成功/失敗のカウント (コイン投げ、変換率) |
| **ポアソン** |一定間隔のイベント数 (1 時間あたりのコール数、バッチあたりの欠陥) |
| **指数関数** |イベント間の時間 (待機時間、障害間隔) |
| **t-分布** |サンプルが少ないか母集団分散が不明 |
| **カイ二乗** |カテゴリカル データ分析、適合度検定 |

## データの収集と保存
### データの出所
実世界のデータは、リレーショナル データベース、API (REST、GraphQL)、フラット ファイル (CSV、JSON、Parquet)、ストリーミング プラットフォーム (Kafka、Kinesis)、アンケート、パブリック リポジトリ (Kaggle、政府ポータル) など、多くのソースから到着します。受け取る形式によって、前処理戦略の大部分が決まります。
### データ ウェアハウジングの概念
|コンセプト |説明 |
|----------|---------------|
| **ETL** |抽出 → 変換 → ロード — 従来のパイプライン アプローチ |
| **ELT** |抽出 → ロード → 変換 — 最新のクラウド アプローチ (生のロード、倉庫内での変換) |
| **データ レイク** |ネイティブ形式 (スキーマオンリード) で保存された生データ |
| **データ ウェアハウス** |分析用に最適化された構造化され処理されたデータ (スキーマオンライト) |
| **データマート** | 1 つの部門またはドメインを範囲とする倉庫のサブセット |
| **スター スキーマ** |中央のファクト テーブルがディメンション テーブルで囲まれている |
| **スノーフレーク スキーマ** |正規化されたディメンション テーブル (冗長性が減り、結合が増加) |
### データベースの種類
|タイプ |例 |最適な用途 |
|------|----------|----------|
| **リレーショナル (SQL)** | PostgreSQL、MySQL、Oracle |構造化データ、ACID トランザクション |
| **ドキュメント** | MongoDB、CouchDB |柔軟なスキーマ、JSON のようなデータ |
| **キーと値** | Redis、DynamoDB |キャッシュ、セッション、単純なルックアップ |
| **列ファミリー** |カサンドラ、HBase |書き込みの多いワークロード、時系列 |
| **グラフ** | Neo4j、Amazon Neptune |人間関係、ソーシャルネットワーク |
| **時系列** | InfluxDB、TimescaleDB | IoT メトリクス、モニタリング |
| **ベクトル** |松ぼっくり、ミルバス | ML/AI 検索用の組み込みストレージ |

## データの前処理と特徴エンジニアリング
### 清掃チェックリスト
実際のデータセットには必ず問題があります。標準的なクリーンアップは次のとおりです。
|問題 |アプローチ |
|------|----------|
| **欠損値** |代入 (平均、中央値、予測)、または疎な場合は削除 |
| **外れ値** | IQR または Z スコアによって検出します。キャッピングまたは変換で処理する |
| **重複** | | を特定して削除します
| **矛盾** |フォーマットの標準化、タイプミスの修正、単位の正規化 |
### 変換テクニック
|テクニック |何をするのか |
|----------|---------------|
| **正規化** |値を 0 ～ 1 の範囲にスケールします。
| **標準化** | Z スコア: 平均 = 0、標準 = 1 |
| **ワンホット エンコーディング** |カテゴリをバイナリ列に変換します。
| **ラベルエンコーディング** |カテゴリに整数のラベルを割り当てます。
| **ログ変換** |データの右歪みを軽減 |
| **ビニング** |連続値を離散バケットにグループ化します。
### 特徴量エンジニアリング
多くの場合、特徴量エンジニアリングが平凡なモデルと優れたモデルの違いになります。主なテクニックには次のようなものがあります。
- **フィーチャーの作成**: 既存の列から新しい列を派生します (例:`age`から`age_group`)。
- **機能の選択**: フィルター メソッド (相関)、ラッパー メソッド (再帰的削除)、埋め込みメソッド (LASSO、ツリーの重要度)。
- **次元削減**: 線形の場合は PCA、視覚化の場合は t-SNE または UMAP。
- **相互作用用語**: 共同効果を捉えるために特徴を乗算的に組み合わせる。

## 探索的データ分析 (EDA)
EDA は、モデル化する前にデータに関する直感を養う場所です。目標は、パターン、異常、関係を特定することです。
### 適切なチャートの選択
|グラフの種類 |最適な用途 |
|----------|----------|
| **ヒストグラム** |単一変数の分布 |
| **箱ひげ図** | 5 つの数値サマリー、外れ値の検出 |
| **散布図** | 2 つの連続変数間の関係 |
| **ヒートマップ** |相関行列、密度の可視化 |
| **棒グラフ** |カテゴリの比較 |
| **折れ線グラフ** |時間の経過に伴う傾向 |
| **ヴァイオリンプロット** |分布密度 + 箱ひげ図の概要 |
| **ペアプロット** |すべての変数ペアの概要 |
### Python EDA スタック
|図書館 |役割 |
|-------|------|
| **パンダ** |データ操作と分析 |
| **ヌルヌル** |数値計算 |
| **matplotlib** |基礎のプロット |
| **シーボーン** |統計的視覚化 (matplotlib 上に構築) |
| **プロット** |インタラクティブな Web ベースの視覚化 |
| **scipy** |科学計算と統計 |

## データ倫理とガバナンス
### プライバシー規定
|規制 |範囲 |
|----------|----------|
| **GDPR** | EU データ主体。消去の権利、同意、データポータビリティ |
| **CCPA** |カリフォルニアの消費者。データ販売のオプトアウト |
| **HIPAA** |米国の医療データ。厳格な機密保持規則 |
### データ品質の次元
|寸法 |質問 |
|----------|----------|
| **精度** |データは正しいですか? |
| **完全性** |何か足りないものはありますか？ |
| **一貫性** |情報筋も同意しているのでしょうか？ |
| **適時性** |現在のものですか？ |
| **有効性** |期待される形式に準拠していますか? |
| **独自性** |重複はありますか? |
### バイアスと公平性
サンプリングバイアス (代表的ではないデータ)、測定バイアス (欠陥のある機器)、またはアルゴリズムバイアス (差別的な予測) など、どの段階でもバイアスが入り込む可能性があります。軽減戦略には、前処理 (データの修正)、中処理 (モデルの制約)、後処理 (出力の調整) が含まれます。人口統計上の平等や機会均等などの公平性の指標は、問題を定量化するのに役立ちます。

## 新しいトレンド
- **AutoML**: 自動化されたパイプラインの作成とモデルの選択。
- **MLOps**: ML ライフサイクル管理に適用される DevOps プラクティス。
- **フィーチャー ストア**: チーム全体で再利用できる一元的な機能管理。
- **データ メッシュ**: 分散型のドメイン所有のデータ アーキテクチャ。
- **LLM と生成 AI**: テキスト、コード、画像のワークフローを変換する大規模な言語モデル。
- **エッジ分析**: クラウドではなくデバイス上でデータを処理します。
- **因果推論**: 相関関係を超えて、実際の原因と結果を理解します。
- **フェデレーション ラーニング**: 分散データを移動せずにモデルをトレーニングします。
- **責任ある AI**: 倫理、説明可能性、透明性が標準要件になります。
