# 地理空間分析
地理空間分析は、地理的要素 (座標、住所、境界、または地球上の場所に関連付けられたあらゆるデータ) を含むデータを検査するプロセスです。 「顧客はどこにいますか?」、「最適なルートは何ですか?」、「土地利用は時間の経過とともにどのように変化していますか?」などの質問に答えます。すべてのデータセットには空間次元があり、それを理解することで、純粋な統計分析では見逃している洞察が得られます。
---

## コアコンセプト
### 座標系
|システム |説明 |使用例 |
|----------|---------------|----------|
| **WGS 84 (EPSG:4326)** |世界標準。緯度/経度 (度) | GPS;ほとんどの Web マッピング。ジオJSON |
| **Web メルカトル (EPSG:3857)** |地球を円柱に投影します。極の領域が歪む | Googleマップ;マップボックス;ほとんどの Web タイル サービス |
| **UTM** (ユニバーサル横メルカトル図法) |地球を 60 のゾーンに分割します。メートルベース |軍隊;測量;高精度な局所作業 |
| **英国ナショナル グリッド (EPSG:27700)** | OSGB36 データム。メートルベース |英国の地図 |
| **地域の予測** |特定の地域のカスタム投影 |特定の領域の歪みを最小限に抑える |
### ジオメトリ タイプ
|タイプ |説明 |例 |
|------|-------------|----------|
| **ポイント** |単一座標 |レストラン。センサー。顧客 |
| **ラインストリング** |順序付けられた点のシーケンス |道路。川。ルート |
| **ポリゴン** |内部を備えた閉じた形状 |国。湖。配達ゾーン |
| **マルチポイント** |ポイント集め |市内のすべてのバス停 |
| **複数行文字列** |線のコレクション |ネットワーク内のすべての道路 |
| **マルチポリゴン** |ポリゴンのコレクション | 写真群島。島のある国 | 島のある国
| **ジオメトリコレクション** |混合タイプ |都市、道路、川のある国 |

## データ形式
|フォーマット |タイプ |主な機能 |
|----------|------|---------------|
| **GeoJSON** |テキスト (JSON) |人間が読める形式。ウェブフレンドリー。すべてのジオメトリ タイプをサポート |
| **シェイプファイル** |バイナリ (複数ファイル) | ESRI のレガシー形式。 .shp + .shx + .dbf + .prj |
| **KML** | XML |グーグルアース; 3D と時間をサポート |
| **ジオパッケージ** | SQLite ベース |単一ファイル。ラスターとベクターをサポートします。モダンスタンダード |
| **ジオパーケット** |円柱状 (寄木細工) |大規模なデータセットの場合は効率的です。データ エンジニアリング ツールと統合 |
| **WKT / WKB** |テキスト / バイナリ |よく知られたテキスト。有名なバイナリ。データベースストレージに使用 |
| **MVT** |バイナリ |マップボックス ベクター タイル。地図データを Web クライアントに提供するため |

## 空間操作
### 基本的な操作
|操作 |説明 |例 |
|----------|---------------|----------|
| **距離** |ジオメトリ間の距離を計算する | 「10 km 以内のすべての病院を検索」 |
| **バッファ** |ジオメトリの周囲に指定された距離でポリゴンを作成する | 「学校の周囲500メートルゾーンを表示」 |
| **交差点** |ジオメトリ間の重複領域を見つける | 「洪水地帯にあるのはどの区画ですか?」 |
| **組合** |ジオメトリを 1 つに結合する | 「すべての土地区画を 1 つの地域に結合する」 |
| **違い** |あるジオメトリを別のジオメトリから減算する | 「保護区域を除く建築可能エリア」 |
| **内容 / 範囲内** |あるジオメトリが別のジオメトリの内側にあるかどうかをテストする | 「この配達エリア内にいるのはどの顧客ですか?」 |
| **最も近い隣人** |最も近いジオメトリを見つける | 「一番近い消防署はどこですか？」 |
| **空間結合** |空間関係に基づいて属性を結合する | "各ポイントをその含まれる国勢調査地域に割り当てます" |
### 空間インデックス作成
|インデックスの種類 |説明 |使用例 |
|----------|---------------|----------|
| **R ツリー** |境界ボックス階層。最も一般的な |ポストGIS; SQLite;汎用 |
| **四分木** |象限への再帰的細分 |ポイントデータ;ゲームエンジン |
| **ジオハッシュ** |階層グリッド。文字列にエンコードします |近接検索。データベースシャーディング |
| **H3** (ウーバー) |六角形の階層グリッド |分析;ライドシェアリング。制服用ゴミ箱 |
| **S2** (Google) |球上のセルベースの階層 |大規模な空間インデックス作成 |

## 地理空間分析パターン
### 一般的な分析タイプ
|パターン |説明 |使用例 |
|----------|---------------|----------|
| **ポイントパターン分析** |ポイントの分布を調べる |犯罪マッピング。病気の発生の検出 |
| **ホットスポット分析** |統計的に有意なクラスターを見つける |小売店の場所。犯罪;疫学 |
| **ネットワーク分析** |ルートの最適化。サービスエリア |ロジスティクス;緊急対応。ユーティリティ |
| **空間補間** |サンプリングされていない位置での値を推定する |空気の質。土壌の性質。天気 |
| **土地利用変更の検出** |衛星画像を経時的に比較する |都市のスプロール化。森林伐採。農業 |
| **適合性分析** |複数の条件を満たす場所を検索 |サイトの選択;保全計画 |
| **空間自己相関** |近くの値がどのように関連しているかを測定する |不動産価格。病気の蔓延 |
### 修正可能な面積単位問題 (MAUP)
|側面 |問題 |
|--------|--------|
| **スケール効果** |結果は分析単位のサイズ (国勢調査区域、郡、州) に応じて変化します。
| **ゾーニング効果** |同じ縮尺であっても、境界の引き方によって結果が変わります。
| **意味** |ある集計レベルの結果が別の集計レベルにも適用されるとは決して想定しないでください。境界に対する感度を常にテストする |

## 実際的な考慮事項
|懸念事項 |ガイダンス |
|----------|----------|
| **座標参照系** |常に CRS を確認してください。計算に投影を決して混ぜないでください。距離を計算する前に変換する |
| **精度** |浮動小数点の精度は小規模なスケールでは重要です。適切なデータ型を使用する |
| **パフォーマンス** |空間操作はコストがかかります。空間インデックスを使用します。表示用にジオメトリを簡略化する |
| **トポロジ** |解析前にジオメトリが有効であること (自己交差がないこと、閉じたポリゴンがないこと) を確認してください。
| **スケール** | Web メルカトル図法は領域を歪めます。面積の計算には使用しないでください。
| **データ品質** | Null ジオメトリ、重複した頂点、細いポリゴンをチェックします。

＃＃ まとめ
地理空間分析は、位置データを実用的な洞察に変えます。点、線、多角形は現実世界のエンティティを表します。空間操作 - 距離、バッファー、交差、結合 - は、近接性、重なり、包含に関する質問に答えます。ツールの範囲は、データベース規模の分析用の PostGIS から、Python ワークフロー用の GeoPandas、Web 視覚化用の Deck.gl まで多岐にわたります。主な課題は、適切な座標系を選択すること、大規模なデータセットでのパフォーマンスを管理すること、そして MAUP (集計境界の選択が結果に影響するという事実) を意識することです。配送ルートの最適化、病気の蔓延の分析、都市の成長のマッピングのいずれの場合でも、地理空間分析は、純粋な数値では把握できない空間コンテキストを提供します。
