# モデルの最適化と展開
大規模な AI モデルのトレーニングは印象的ですが、エンジニアリングのほとんどはそれを効率的にデプロイすることで行われます。応答に 10 秒かかるモデル、または 8 つの A100 GPU を必要とするモデルは、ほとんどの実際のアプリケーションには役に立ちません。モデルの最適化は、品質をあまり犠牲にすることなく、モデルをより小さく、より速く、より安くする技術であり科学です。このファイルには、量子化、枝刈り、蒸留、およびモデルを実稼働環境に導入するための実用的なツールが含まれています。
---

## なぜ最適化するのか?
|懸念事項 |影響 |
|----------|----------|
| **レイテンシ** |ユーザーは 1 秒以内の応答を期待しています。 100ms が増えるごとにエンゲージメントが失われます |
| **コスト** | GPU 推論は高価です。 70B モデルのコストは、クラウド ハードウェア上の 100 万トークンあたり ~0.05 ～ 0.15 ドルです。
| **メモリ** | FP32 の 7B モデルには 28 GB の VRAM が必要です。ほとんどのコンシューマー向け GPU は 8 ～ 24 GB です。
| **エネルギー** |大規模なモデルを実行すると、大量の電力が消費されます。モバイルとエッジの問題 |
| **スケール** |数百万のユーザーにサービスを提供するには、利用可能なハードウェアに適合するモデルが必要です。
---

## 量子化
量子化により、モデルの重みの精度が 32 ビット浮動小数点 (FP32) から INT8、INT4、またはそれ以下のより小さい形式に低下します。
### 高精度フォーマット
|フォーマット |重量あたりのビット数 | 7Bモデル用メモリ |品質 |
|----------|----------------|----------|----------|
| **FP32** | 32 | 28GB |ベースライン (完全精度) |
| **FP16 / BF16** | 16 | 14GB | FP32とほぼ同じ |
| **INT8** | 8 | 7GB |品質の低下が非常に小さい |
| **INT4** | 4 | 3.5GB |中程度の品質低下。まだ使える |
| **INT3 / INT2** | 3-2 | 2.6～1.75GB |重大な品質の低下。研究段階 |
### 量子化方法
|方法 |それが起こったとき |仕組み |品質 |
|--------|----------------|--------------|----------|
| **トレーニング後の量子化 (PTQ)** |トレーニングが完了したら |小規模なデータセットでモデルを調整します。最適なスケールを見つける | INT8に適しています。 INT4 で劣化 |
| **GPTQ** |トレーニング後 |近似二次情報を使用した GPU フレンドリーな INT4 量子化 | INT4 で高品質 |
| **AWQ** (アクティベーション対応重み量子化) |トレーニング後 |活性化の大きさに基づいて顕著な重みを保護する | INT4 で GPTQ よりも優れています |
| **GGUF** (llama.cpp 形式) |トレーニング後 | CPU に優しい量子化。レイヤーごとの混合精度 | CPU 推論用に最適化 |
| **量子化対応トレーニング (QAT)** |トレーニング中 |モデルが対処方法を学習できるように、トレーニング中に量子化をシミュレートします。最高の品質。再トレーニングが必要です |
### 実際の影響
|モデル | FP16 サイズ | INT4 サイズ |スピードアップ |品質の損失 |
|----------|-----------|---------------|-----------|-------------|
| **ラマ 7B** | 14GB | 3.5GB | 2～4倍 |ベンチマークに対して ~1 ～ 2% |
| **ラマ 70B** | 140GB | 35GB | 2～3倍 |ベンチマークの ~2 ～ 3% |

## 剪定
枝刈りは、トレーニングされたモデルから不要な重みやニューロンを削除します。
|タイプ |説明 |利点 |チャレンジ |
|------|---------------|-----------|-----------|
| **非構造化** |個々の重みを削除します (ゼロに設定) |最高の圧縮率 |スパースなハードウェアのサポートが必要 |
| **構造化** |ニューロン全体、アテンションヘッド、またはレイヤーを削除する |モデルのサイズを直接縮小します |さらに品質が低下する可能性があります |
| **マグニチュードベース** |絶対値が最小の重みを削除する |単純;うまくいきます |重要な小さな重みを見逃す可能性があります |
| **重要度ベース** |出力への寄与に基づいて重みを削除します。品質保持の向上 |計算コストが高くなる |
### パイプラインのプルーニング
|ステップ |説明 |
|------|---------------|
| 1. 電車 |完全なモデルを通常どおりトレーニングします。
| 2. スコア |各重み/ニューロンの重要度スコアを計算する |
| 3. プルーン |最も重要でない要素を削除する |
| 4. 微調整 |失われた精度を回復するために再トレーニング |
| 5. 繰り返し |プルーニングと微調整を繰り返して圧縮率を高める |

## 知識の蒸留
大規模な「教師」モデルを模倣するように小規模な「生徒」モデルをトレーニングします。
|コンポーネント |役割 |
|-----------|------|
| **先生** |大型・高品質モデル |
| **学生** |先生から学ぶ小さな模型 |
| **蒸留損失** |生徒は教師の出力分布と一致させようとします (ソフトラベル) |
### 蒸留の種類
|タイプ |説明 |例 |
|------|-------------|----------|
| **ロジットベース** |生徒は教師の出力確率と一致します。ヒントン独自の蒸留 |
| **機能ベース** |生徒は教師の中間表現と一致します。フィットネッツ |
| **関係ベース** |学生はサンプル間の関係を照合します。 RKD (リレーショナルナレッジ蒸留) |
| **データフリー** |元のトレーニング データは必要ありません。教師の世代を使用する | DAFL、ディープインバージョン |
### 注目すべき蒸留例
|先生 |学生 |結果 |
|----------|----------|----------|
| **GPT-4** | GPT-3.5-ターボ (噂) | GPT-4 の品質を多く備えた小型モデル |
| **BERT-Large** |ディスティルバート | BERT の 40% 小型化、60% 高速化、97% のパフォーマンス |
| **ラマ 70B** | LLaMA 7B (蒸留経由) |オープンソースの小規模モデルが大規模モデルの品質に近づく |

## LLM 固有の最適化
### KV キャッシュの最適化
大規模な言語モデルは、再計算を避けるために、以前のトークンからのキーと値のペアをキャッシュします。
|テクニック |説明 |影響 |
|----------|---------------|----------|
| **マルチクエリ アテンション (MQA)** |すべてのアテンション ヘッドは 1 つの KV ペアを共有します。メモリを減らします。わずかな品質の低下 |
| **グループ化されたクエリ アテンション (GQA)** |ヘッドのグループが KV ペアを共有する | MQA と標準的な注意のバランス |
| **スライディングウィンドウ注意** |最後の W トークンのみに注目する |長いコンテキストの KV キャッシュ サイズを削減 |
### 投機的デコード
|ステップ |説明 |
|------|---------------|
| 1 |小規模な「ドラフト」モデルは K 個のトークンを迅速に生成します。
| 2 |大規模モデルは、1 回の順方向パスですべての K トークンを検証します。
| 3 |受け入れられたトークンは保持されます。拒否されたものは再生成されます。
結果: 品質を損なうことなく、生成速度が 2 ～ 3 倍向上します (最終決定権は常に大規模モデルにあります)。
### フラッシュアテンション
|特集 |説明 |
|----------|---------------|
| **問題** |標準的なアテンションには、アテンション行列用に O(n²) メモリが必要です。
| **解決策** |アテンションをブロック単位で計算します。完全な行列をメモリ内に実体化することはありません。
| **結果** | 2 ～ 4 倍高速。より長いコンテキスト ウィンドウを有効にする |
| **バリエーション** | Flash アテンション 2 (高速)、FlashDecoding (推論用に最適化) |

|パターン |説明 |いつ使用するか |

## ベンチマーク
|メトリック |何を測定するのか |
|------|------|
| **1 秒あたりのトークン数** |生成スループット (高いほど良い) |
| **最初のトークンまでの時間 (TTFT)** |最初の出力トークンが表示されるまでの待ち時間 |
| **リクエストごとのレイテンシ** |入力から出力が完了するまでの合計時間 |
| **メモリ使用量** |推論中に消費される VRAM または RAM |
| **スループット** | 1 秒あたりに処理されるリクエスト |
| **100 万トークンあたりのコスト** | 100万トークンの処理にかかるドルコスト |

## 実践的なヒント
- **量子化から始めます。** INT4 量子化 (AWQ または GPTQ) は、品質とサイズの最適なトレードオフを実現します。ほとんどの 7B モデルは、単一のコンシューマ GPU で INT4 で快適に動作します。
- **LLM の提供には vLLM を使用します。** これは、高スループットの LLM 推論のための最速のオープンソース オプションです。
- **最適化する前のプロファイル。** 実際に時間が費やされた場所を測定します。多くの場合、ボトルネックとなるのはコンピューティングではなくメモリ帯域幅です。
- **モデルをタスクに合わせます。** 7B モデルはほとんどのタスクに適しています。 7B で十分な場合は 70B を使用しないでください。
- **蒸留を検討してください。** 実稼働用に小さくて高速なモデルが必要な場合は、最初からトレーニングするのではなく、より大きなモデルから蒸留します。
- **継続的に監視します。** データ分布が変化すると、モデルのパフォーマンスが時間の経過とともに低下する可能性があります。レイテンシ、スループット、品質の指標を追跡します。

＃＃ まとめ
モデルの最適化は、研究と運用の間の架け橋です。量子化により、品質の低下を最小限に抑えながらモデルが 4 ～ 8 倍縮小されます。剪定により死重が除去されます。蒸留により、大きなモデルから小さなモデルに知識が伝達されます。フラッシュ アテンションと KV キャッシュ トリックにより、推論が高速化されます。これらの技術を組み合わせることで、データセンターを必要とするモデルが、ラップトップまたは電話で実行されるモデルに変わります。この分野の進歩は速く、昨年は 8 台の A100 が必要でしたが、現在はコンシューマ GPU で実行できます。
