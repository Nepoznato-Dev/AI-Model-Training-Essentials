# フェデレーテッド ラーニングとプライバシー
フェデレーテッド ラーニングは、生データを共有せずに、複数のデバイスまたは組織間で機械学習モデルをトレーニングするための手法です。データを中央サーバーに送信する代わりに、各デバイスはローカル モデルをトレーニングし、モデルの更新 (勾配または重み) のみを共有します。中央サーバーはこれらの更新を集約して、グローバル モデルを生成します。これは、Android スマートフォンでキーボード言語モデルをトレーニングするために Google によって設計されたものであり、それ以来、プライバシーを保護する AI の重要な技術となっています。
---

## なぜフェデレーション ラーニングを使用するのでしょうか?
|モチベーション |説明 |例 |
|-----------|---------------|----------|
| **データプライバシー** |生データがデバイスの外に出ることはありません |医療記録は病院に保管されます。写真は携帯電話に残る |
| **規制遵守** | GDPR、HIPAA、およびその他の規制によりデータ共有が制限されています。銀行は顧客データを共有せずに連携できる |
| **データ量** |データの移動は高価で遅い |データをアップロードする必要がある場合、数十億台の携帯電話でのトレーニングは非現実的です。
| **データの機密性** |一部のデータは機密性が高すぎるため、同意があっても共有できません |政府諜報機関。個人の健康データ |
---

## Federated Learning の仕組み
### 基本プロトコル (FedAvg)
|ステップ |何が起こるのか |
|------|---------------|
| **1.初期化** |中央サーバーはランダムな重みを使用してグローバル モデルを作成します。
| **2.配布** |サーバーは現在のグローバル モデルを選択されたデバイスに送信します。
| **3.ローカルトレーニング** |各デバイスは、いくつかのエポックにわたってローカル データに基づいてモデルをトレーニングします。
| **4.アップロード** |デバイスは更新されたモデルの重み (データではない) をサーバーに送り返します。
| **5.集計** |サーバーは重みを平均化し (Federated Averaging)、新しいグローバル モデルを作成します。
| **6.繰り返し** |モデルが収束するまでステップ 2 に戻ります。
```
Server: global_model = average(local_model_1, local_model_2, ..., local_model_n)
```

### 主要なプロパティ
|プロパティ |説明 |
|----------|---------------|
| **非 IID データ** |各デバイスは異なるデータ分散を持っています (独立したものではなく、同一に分散されています)。
| **不均衡データ** |多くのデータを持っているデバイスもあれば、ほとんどデータを持っていないデバイスもあります |
| **部分参加** |すべてのラウンドですべてのデバイスが使用できるわけではありません。
| **コミュニケーション効率** |ボトルネックは計算ではなく通信です |
---

## Federated Learning のバリアント
|バリアント |説明 |利点 |
|----------|---------------|----------|
| **連邦平均** |デバイス間のモデルの平均重み |単純; IID データに適しています。
| **フェデプロックス** |ローカル トレーニングに近位項を追加します。非 IID データに適しています |
| **足場** |制御変数を使用してデータの不均一性を修正します。非 IID データに対するより高速な収束 |
| **FRBSGD** | FedAvg と似ていますが、ラウンドごとに 1 つの勾配ステップがあります。ラウンドあたりの通信コストの削減 |
| **パーソナライズされたフロリダ州** |各デバイスは、グローバル モデルと並行してパーソナライズされたモデルを維持します。デバイスごとのパフォーマンスの向上 |
| **垂直 FL** |関係者間で異なる機能 (異なるサンプルではない) |当事者が同じデータの異なる側面を保持している場合 |
---

## 差分プライバシー
差分プライバシー (DP) は、アルゴリズムの出力に個人のデータが含まれているかどうかを明らかにしないという数学的保証を提供します。
### コアの定義
メカニズム M は、1 つのレコード内で異なる 2 つのデータセット D および D' について、(ε, δ) の差分プライバシーを満たします。
```
P(M(D) ∈ S) ≤ e^ε × P(M(D') ∈ S) + Î´
```

|パラメータ |意味 |
|----------|----------|
| **ε (イプシロン)** |プライバシーの予算。小さい = よりプライベートになります。一般的な値: 0.1 ～ 10。 |
| **δ(デルタ)** |プライバシー保証が失敗する可能性。通常は 1/N (データセット サイズの逆数) に設定します。 |
### プライバシーを追加するためのメカニズム
|メカニズム |仕組み |使用例 |
|----------|---------------|----------|
| **ガウスメカニズム** |クエリの感度に合わせて調整されたガウス ノイズを追加します。連続値 (モデルの重み) |
| **ラプラス機構** |ラプラス ノイズを追加する |クエリのカウント |
| **指数関数メカニズム** |効用に比例する確率で出力を選択する |個別の選択肢 |
### DP-SGD (差分プライベート確率的勾配降下法)
|ステップ |説明 |
|------|---------------|
| 1. サンプルごとの勾配を計算する |バッチグラデーションの代わりに |
| 2. グラデーションをクリップする |各勾配の最大ノルムを制限します (単一サンプルの影響を制限します)。
| 3. ノイズを追加する |調整されたガウス ノイズを集約された勾配に追加します。
| 4.パラメータを更新する |標準的な勾配降下ステップ |
|トレードオフ |説明 |
|----------|---------------|
| **プライバシーと精度** |プライバシーが強化される (ε が小さくなる) と、より多くのノイズが必要となり、モデルの精度が低下します。
| **プライバシーとトレーニング時間** |ノイズが増えると収束が遅くなります。
| **プライバシー予算の追跡** |トレーニングの各ステップでは、プライバシー予算の一部が消費されます。一度消費すると回復することはできません。

## フェデレーテッド ラーニングと差分プライバシーの組み合わせ
|レイヤー |保護 |
|------|-----------|
| **フェデレーション ラーニング** |生データはデバイス上に残ります |
| **差分プライバシー** |モデルの更新でもノイズが多く、個人の貢献を保護します。
| **安全な集約** |サーバーはすべての更新の集約のみを参照し、個々の更新は参照しません。
この組み合わせにより、強力なプライバシー保証が提供されます。サーバーが侵害された場合でも、特定の個人のデータがトレーニングに使用されたかどうかを判断することはできません。
---

## その他のプライバシー保護技術
### 安全なマルチパーティ コンピューティング (SMPC)
複数の当事者が、個々の入力を明らかにすることなく、結合されたデータに対して関数を計算します。
|特集 |説明 |
|----------|---------------|
| **仕組み** |データは複数の関係者に分散される共有に分割されます。計算は株式で行われます。
| **保証** |他の当事者の入力については何も学習しません。
| **オーバーヘッド** |多大な通信コストと計算コスト |
| **使用例** |銀行は顧客データを共有せずに共同リスクモデルを計算 |
### 準同​​型暗号化 (HE)
暗号化されたデータに対して直接計算を実行します。
|タイプ |サポート内容 |オーバーヘッド |
|------|------|----------|
| **部分的に HE** | 1 つの演算 (加算 OR 乗算) |低い |
| **やや彼** |両方の操作の数は限られています |中 |
| **完全な HE** |任意の計算 |非常に高い (100 ～ 1000 倍の速度低下) |
|アプリケーション |説明 |
|---------------|---------------|
| **私的な推論** |暗号化されたデータに対して ML モデルを実行します。暗号化された予測を返す |
| **暗号化されたトレーニング** |暗号化されたデータでトレーニングする (まだほとんどがディープラーニングの理論上のもの) |
| **プライベート クエリ** |クエリやデータを公開せずにデータベースにクエリを実行する |
### 信頼された実行環境 (TEE)
OS からもデータを保護するハードウェア ベースの分離 (Intel SGX、ARM Trustzone)。
|利点 |制限 |
|----------|---------------|
|ネイティブに近いパフォーマンス |特定のハードウェアが必要です |
|強力なセキュリティ保証 |限られたメモリ (エンクレーブ サイズ) |
|暗号化オーバーヘッドなし |サイドチャネル攻撃の可能性 |

## プライバシー規制と ML
|規制 |地域 | ML への影響 |
|-----------|----------|---------------|
| **GDPR** | EU |説明を受ける権利。データの最小化。処理に対する同意。消去する権利 |
| **CCPA** |カリフォルニア |データ販売を知り、削除し、オプトアウトする権利 |
| **HIPAA** |米国 (ヘルスケア) |健康データの厳格な管理。匿名化の要件 |
| **PIPL** |中国 |データのローカリゼーション。同意要件。国境を越えた転送ルール |
| **AI 法** | EU |透明性要件;リスク分類。禁止行為 |
### ML ワークフローへの影響
| GDPR 原則 | ML への影響 |
|----------------|--------------|
| **データの最小化** |必要なものだけを集めてください。フェデレーション ラーニングが役立ちます |
| **目的の制限** |新たな同意なしにデータを再利用することはできません |
| **消去する権利** |トレーニング済みモデルから個人のデータを削除できる必要があります (機械の非学習) |
| **説明を受ける権利** |モデルは個々の予測を説明できるほど解釈可能でなければなりません。
| **設計によるプライバシー** |プライバシーは最初からシステムに組み込まれなければなりません |

## 課題
|チャレンジ |説明 |
|----------|---------------|
| **通信費** |モデルの更新を数百万台のデバイスに送信するにはコストがかかります。
| **非 IID データ** |デバイスのデータ分布は大きく異なり、コンバージェンスに悪影響を及ぼします。
| **はぐれ者** |遅いデバイスはラウンド全体を遅らせます。
| **プライバシーとユーティリティのトレードオフ** |プライバシーが強化されると、モデルのパフォーマンスが低下します。
| **中毒攻撃** |悪意のある参加者はグローバル モデルを破壊する可能性があります。
| **モデル抽出** |共有モデルの更新でも、トレーニング データに関する情報が漏洩する可能性があります。
| **ハードウェアの異質性** |デバイスが異なれば、コンピューティング機能も異なります。

＃＃ まとめ
フェデレーテッド ラーニングとプライバシー保護技術は、データが分散されている、機密性が高い、または規制されている場合に、強力な AI モデルをどのように構築するかという根本的な緊張に対処します。フェデレーテッド ラーニングはデータをデバイス上に保持し、モデルの更新のみを共有します。差分プライバシーにより、個人の貢献が検出できないという数学的保証が追加されます。安全な計算と準同型暗号化はさらに進化し、暗号化されたデータの計算が可能になります。各手法には通信オーバーヘッド、精度の低下、計算コストなどのコストがかかりますが、これらを組み合わせることで、世界中のデータから学習しながらプライバシーを尊重する AI を構築するためのツールキットが形成されます。
