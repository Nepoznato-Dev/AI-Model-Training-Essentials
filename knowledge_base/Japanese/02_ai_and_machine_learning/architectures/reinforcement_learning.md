# 強化学習
強化学習 (RL) は、機械が試行錯誤によって一連の意思決定を学習する方法です。すべての例に対して正しい答えが提供される教師あり学習とは異なり、RL ではエージェントに報酬シグナルのみが与えられます。エージェントは、時間の経過とともにどのアクションが最良の結果につながるかを理解する必要があります。これは、AlphaGo、ロボット制御、ゲームプレイ AI、そして重要なことに、現代の大規模な言語モデルを人間の好みに合わせるために使用される技術である RLHF の背後にあるアプローチです。
---

## コアコンセプト
RL は、意思決定を **エージェント** と **環境** の間のループとして枠組み化します。
|コンポーネント |役割 |例 |
|----------|------|----------|
| **エージェント** |意思決定者 |チェス プログラム、ロボット、言語モデル |
| **環境** |エージェントが対話する世界 |チェス盤、倉庫、会話 |
| **州** |現状 |ボードの位置、ロボットセンサーの読み取り値、チャット履歴 |
| **アクション** |エージェントができること |駒を移動し、左に曲がり、トークンを生成します |
| **報酬** |フィードバック信号 (スカラー数) |勝利の場合は +1、クラッシュの場合は -1、人間の好みのスコア |
| **ポリシー** |状態をアクションにマッピングする戦略 | 「王が脅されているなら、動かせ」
| **値関数** |州からの期待される累積報酬 | 「このボードの位置は約 +3 ポイントの価値があります」 |
### RL ループ
```
Agent observes State → chooses Action → Environment returns new State + Reward
        ↑                                                                         |
        └─────────────────────────────────────────────────────────────────────────┘
```

エージェントの目標は、目先の報酬だけでなく、時間の経過とともに**累積報酬**を最大化することです。これが、RL が教師あり学習と根本的に異なる点です。

## 他の学習パラダイムとの主な違い
|側面 |教師あり学習 |教師なし学習 |強化学習 |
|----------|---------------------|---------------------|---------------------|
| **シグナル** |すべての例のラベルを修正する |ラベルはありません。構造を見つける |スカラー報酬、遅延が多い |
| **フィードバック** |即時 |なし |遅れてまばら |
| **シーケンス** |各例は独立しています。各例は独立しています。アクションは将来の状態に影響を与えます。
| **目標** |予測誤差を最小限に抑える |パターンを発見する |累積報酬を最大化 |

## マルコフ決定プロセス (MDP)
MDP は RL の数学的フレームワークです。彼らは、未来は現在の状態のみに依存し、そこに到達するまでの経緯 (**マルコフ特性**) には依存しないと想定しています。
|コンポーネント |表記法 |意味 |
|----------|----------|----------|
| **州** | S |エージェントが陥り得るすべての状況 |
| **アクション** |あ |エージェントができるすべてのこと |
| **遷移関数** | P(s' \| s, a) |状態 s でアクション a を実行した後、状態 s' に到達する確率 |
| **報酬機能** | R(s, a, s') |移行で受け取った報酬 |
| **割引率** | γ（ガンマ） |将来の報酬と当面の報酬をどの程度評価するか (0 から 1) |
**リターン** (割引された報酬の合計) は次のとおりです。
```
G = R₁ + γR₂ + γ²R₃ + ...
```

高い割引係数 (γ が 1 に近い) は、エージェントが先見の明があることを意味します。値が低いと近視であることを意味します。

## 古典的な RL アルゴリズム
### 値ベースのメソッド
これらは、各状態 (または状態とアクションのペア) がどれほど優れているかを学習します。
|アルゴリズム |主要なアイデア |制限 |
|----------|----------|---------------|
| **Q ラーニング** | Q 値の表を学習します。Q(状態、アクション) = 期待される報酬 |大規模な状態空間にはスケールしません。
| **ディープ Q ネットワーク (DQN)** |ニューラル ネットワークを使用して Q 値を近似する |個別のアクションのみを処理します。不安定になる可能性があります |
| **ダブル DQN** | Q ラーニングの過大評価バイアスを修正する |まだ個別のアクションに限定されています |
Q ラーニングの更新ルール:
```
Q(s, a) ← Q(s, a) + α [r + γ max Q(s', a') - Q(s, a)]
```

### ポリシーベースのメソッド
これらは価値を見積もることなく、方針（戦略）を直接学習します。
|アルゴリズム |主要なアイデア |利点 |
|----------|----------|----------|
| **補強** |モンテカルロ政策の勾配。良い結果に向けて政策を更新する |単純;連続アクションで動作します |
| **PPO** (近接ポリシーの最適化) |ポリシーの更新をクリップして、不安定な大規模な変更を防止 |安定した;広く使用されています。良いデフォルト |
| **TRPO** |ポリシー更新のための信頼領域メソッド | PPO よりも原則に基づいています。実装が難しい |
### 俳優と批評家の手法
**俳優** (政策) と **批評家** (価値観) の両方の長所を組み合わせます。
|アルゴリズム |主要なアイデア |
|----------|----------|
| **A2C / A3C** |アドバンテージ俳優・批評家。利点の推定を使用して分散を削減します。
| **SAC** (ソフト アクター - 批評家) |探索を維持しながら報酬を最大化する (エントロピー正則化) |
| **TD3** (ツイン遅延 DDPG) |継続的なアクション空間における過大評価に対処する |

## RLHF: 人間のフィードバックからの強化学習
RLHF は ChatGPT を可能にした技術です。これは、テキストを予測できるモデルと、人間が実際に役立つと考える出力を生成するモデルとの間のギャップを埋めます。
### 3 つのステップ
|ステップ |何が起こるのか |出力 |
|------|---------------|----------|
| **1.教師あり微調整 (SFT)** |人間が書いた高品質のサンプルに基づいて事前トレーニングされたモデルを微調整する |指示にかなりよく従うモデル |
| **2.報酬モデル トレーニング** |人間はモデル出力のペアを比較します。人間の好みを予測するモデルをトレーニングする |出力品質をスコアリングする報酬モデル |
| **3. RL の最適化** | PPO を使用して SFT モデルを微調整し、報酬モデルのスコアを最大化します。人間の好みに合わせたモデル |
### なぜ RLHF が重要なのか
RLHF がなければ、言語モデルはあらゆる本を読んだものの、会話の中でどのように振る舞えばよいのかわからない学生のようなものです。テキストを生成することはできますが、そのテキストは役に立たなかったり、有害だったり、まったく的外れだったりする可能性があります。 RLHF は、テキストがどのように見えるかだけでなく、*人間が望むもの* をモデルに教えます。
### バリエーションと代替案
|方法 |説明 |利点 |
|----------|---------------|----------|
| **DPO** (直接優先最適化) |報酬モデルをスキップします。人間の好みに基づいてポリシーを直接最適化する |よりシンプルに。個別の報酬モデルをトレーニングする必要はありません |
| **RLAIF** | (人間ではなく) AI を使用して嗜好ラベルを生成する |人間によるラベル付けよりも安価 |
| **憲法上の AI** |一連の原則を使用して、人間によるラベルを付けずにモデルの動作をガイドする |よりスケーラブル。 Anthropic のアプローチ |
| **GRPO** (グループ相対ポリシー最適化) |個別のモデルに対して出力を比較するのではなく、グループ内で出力を比較します。 DeepSeek-R1 で使用されます。バリューネットワークの必要性を軽減 |

## 探索 vs 搾取
これが RL の中心的な緊張です。 **悪用** とは、うまくいくことがわかっているアクションを選択することを意味します。 **探索** とは、より良い戦略を見つけるために新しいことに挑戦することを意味します。
|戦略 |仕組み |トレードオフ |
|----------|---------------|----------|
| **ε-貪欲** |ほとんどの場合、最適なアクションを選択します。確率 ε | を持つランダムなアクションシンプルだが非効率 |
| **ボルツマン探査** |推定値に基づいて確率的にアクションを選択する | ε-greedy よりもスムーズ |
| **UCB** (上限信頼限界) |不確実性の高い行動を好む (不確実性に直面しても楽観的) |優れた理論的保証 |
| **エントロピーの正則化** |多様な州を訪問するためのボーナスを追加 (SAC、PPO で使用) |自然探求を奨励します |

## マルチエージェント強化学習
複数のエージェントが同時に学習すると、ダイナミクスははるかに複雑になります。
|シナリオ |チャレンジ |例 |
|----------|-----------|----------|
| **協同組合** |エージェントは調整する必要があります。単位の割り当ては難しい |ロボットサッカーチーム。分散型センサーネットワーク |
| **競争力** |対戦相手は適応します。環境は非定常です |ゲーム AI (ポーカー、StarCraft);サイバーセキュリティ |
| **混合** |協力するエージェントもいれば、競合するエージェントもいます |オークション市場。交通システム |
|アルゴリズム |説明 |
|----------|---------------|
| **MADDPG** | DDPG のマルチエージェント バージョン。中央集権的な批評家、分散型のアクター |
| **マッポ** |マルチエージェント PPO。実際に広く使用されています |
| **セルフプレイ** |エージェントは自分自身のコピーに対してトレーニングします (AlphaGo、AlphaStar) |

## Sim から Real への転送
現実世界でロボットを訓練するのは時間がかかり、危険です。代わりに、エージェントはシミュレーションでトレーニングし、現実に移行します。
|チャレンジ |ソリューション |
|----------|----------|
| **現実のギャップ** (シミュレーション ≠ 現実世界) |ドメインのランダム化: トレーニング中に物理パラメータを変更する |
| **サンプルの非効率** |モデルベースの RL を使用するか、大規模な並列シミュレーションでトレーニングする |
| **安全性** |制約付き RL: トレーニング中の危険な行為にペナルティを与える |
| **部分的な可観測性** |ノイズの多いセンサーと遅延した観測を使用してトレーニングする |
Boston Dynamics や Tesla などの企業はシミュレーションを広く使用していますが、シミュレーションと物理的なパフォーマンスの間のギャップは依然としてこの分野の最大の課題の 1 つです。

## 実践的なヒント
- **PPO から始めましょう** これは、最も信頼性の高い汎用アルゴリズムです。何を使用すればよいかわからない場合は、PPO がデフォルトです。
- **報酬を正規化します。** 報酬のスケーリングはトレーニングの安定性に劇的に影響します。
- **ベクトル化された環境を使用します。** 多くの環境 (8 ～ 64 など) を並行して実行すると、勾配の推定が安定し、トレーニングが大幅に高速化されます。
- **報酬とエントロピーの両方を監視します。** エントロピーがゼロに低下した場合、エージェントは探索を停止し、局所最適値に陥っている可能性があります。
- **報酬の形成は芸術です。** 適切な報酬関数を設計することは、多くの場合最も難しい部分です。報酬が少ない（最後だけ）と、学習が非常に遅くなります。緻密で整った報酬はエージェントを導きますが、意図しない動作を引き起こす可能性があります。
- **RLHF は脆弱です。** 報酬モデルまたは PPO ハイパーパラメータへの小さな変更は、品質の大幅な低下を引き起こす可能性があります。完全な RLHF パイプラインが必要ない場合は、DPO がより安定した代替手段となります。
---

＃＃ まとめ
強化学習は、エージェントが対話を通じて意思決定をどのように学習するかを研究するものです。これは、Q ラーニングなどの古典的なアルゴリズムから、PPO や SAC などの最新のディープ RL 手法にまで及び、ゲームプレイから言語モデルの調整に至るまで、AI における最近の最も重要な進歩の一部を支えています。中心的な課題は変わりません。フィードバックが遅れ、まばらで、ノイズが多い場合に最適な動作をどのように学習するかです。その答え、つまり賢い数学に導かれた試行錯誤は、人工知能全体の中で最も強力なアイデアの 1 つであることがわかります。
