# レコメンデーションシステム
レコメンデーション システムは、ユーザーが次に見たいもの、購入したいもの、または操作したいものを予測します。これらは、ソーシャル メディア上のコンテンツ フィード、電子商取引サイト上の製品提案、ストリーミング プラットフォーム上の映画の選択、および検索結果を強化します。ほとんどのユーザーには見えないにもかかわらず、これらは世界で最も商業的に影響力のある AI システムの 1 つです。Netflix は、そのレコメンデーション エンジンが加入者の解約を減らし、年間 10 億ドル以上を節約すると推定しています。
---

## 推奨が難しい理由
|チャレンジ |説明 |
|----------|---------------|
| **スケール** |数百万のユーザー × 数百万のアイテム = 数十億の可能なペア |
| **疎性** |各ユーザーが操作したのは、利用可能なアイテムのごく一部です。
| **コールドスタート** |新しいユーザーと新しいアイテムにはインタラクション履歴がありません。
| **動的な設定** |ユーザーの好みは時間の経過とともに変化します |
| **精度を超えて** |推奨事項はまた、多様で、斬新で、思いがけないものでなければなりません。
| **ビジネス目標** |エンゲージメントの最大化 ≠ ユーザーの幸福の最大化 |
---

## 主要なアプローチ
### 協調フィルタリング
ユーザー A と B が過去に同意した場合、おそらく将来も同意するだろうという考えです。
|タイプ |仕組み |例 |
|------|-------------|----------|
| **ユーザーベース** |似たようなユーザーを見つけます。気に入ったものを勧める | 「これを気に入ったユーザーはこちらも気に入っています...」 |
| **アイテムベース** |ユーザーがすでに気に入っているものと類似したアイテムを見つける | 「あなたが見ていたから...」 |
| **行列因数分解** |ユーザーとアイテムの相互作用マトリックスを潜在的な要素に分解する | SVD、ALS (交互最小二乗法) |
|強さ |弱点 |
|----------|----------|
|アイテム自体を理解する必要はありません |コールド スタートの問題: 新しいアイテムを推奨できない |
|複雑な暗黙の設定をキャプチャ |大量のインタラクション データが必要 |
|あらゆるコンテンツ タイプで機能します |人気バイアス: すでに人気のあるアイテムを推奨 |
### コンテンツベースのフィルタリング
アイテムの特徴に基づいて、ユーザーがすでに気に入っているアイテムに類似したアイテムを推奨します。
|機能タイプ |例 |
|-----------|-----------|
| **テキスト** |ジャンル、説明、キーワード、キャスト |
| **オーディオ** |テンポ、ジャンル、雰囲気（音楽の場合） |
| **ビジュアル** |カラーパレット、スタイル（イメージ・ファッション用） |
| **メタデータ** |価格、ブランド、カテゴリー |
|強さ |弱点 |
|----------|----------|
|アイテムのコールド スタートはありません (機能はわかっています)。ユーザーの既存の好みから外れたアイテムは推奨できません |
|少ないインタラクション データで動作します |優れた特徴量エンジニアリングが必要 |
|説明可能 (「X に似ているため推奨」) |偶然が減る |
### ハイブリッドアプローチ
ほとんどの制作システムは、共同作業とコンテンツベースの方法を組み合わせています。
|ハイブリッド戦略 |説明 |
|-----|---------------|
| **加重** |複数のモデルのスコアを結合する |
| **スイッチング** |新規ユーザーにはコンテンツベースを使用し、既存ユーザーにはコラボレーションを使用します |
| **カスケード** |最初に単純なモデルを使用し、次に複雑なモデルで改良します。
| **機能の組み合わせ** |共同作業機能とコンテンツ機能を単一のモデルに統合 |
| **メタ学習** |さまざまなレコメンダーを組み合わせる方法を学びましょう |

## 最新の深層学習アプローチ
### 2 タワー モデル
大規模なレコメンデーションのための主要なアーキテクチャ (YouTube、Pinterest、Spotify で使用)。
|コンポーネント |役割 |
|-----------|------|
| **ユーザータワー** |ユーザーの特徴と履歴を埋め込みにエンコードするニューラル ネットワーク |
| **アイテムタワー** |アイテムの特徴を埋め込みにエンコードするニューラル ネットワーク |
| **類似性** |ユーザーとアイテムの埋め込み間のドット積またはコサインの類似性 |
|ステップ |説明 |
|------|---------------|
| 1 |両方のタワーをトレーニングして、相互作用するユーザーとアイテムのペアに対して同様の埋め込みを生成します。
| 2 |サービス提供時に、アイテムの埋め込みを事前計算します。
| 3 |ユーザーリクエストの場合、ユーザーの埋め込みを計算します。
| 4 |近似最近傍 (ANN) 検索を使用して、最も類似したアイテムを見つけます。
### 推奨事項のシーケンス モデル
ユーザーの行動は連続的です。昨日見たものが今日見るものに影響を与えます。
|モデル |アプローチ |
|------|----------|
| **GRU4Rec** |セッションベースの推奨事項のための GRU ベースのモデル |
| **SASRec** |自己注意ベースの逐次レコメンダー |
| **BERT4Rec** |逐次的な推奨事項のための双方向トランス |
| **YouTube DNN** |視聴履歴をシーケンスとして扱うディープ ニューラル ネットワーク |
### 検索とランキング
最新のシステムでは、推奨事項が 2 つの段階に分かれています。
|ステージ |目的 |方法 |
|------|-----------|----------|
| **検索 (候補生成)** |数百万のアイテムを最大 1,000 の候補に絞り込む | 2塔モデル。 ANN検索。速いがおおよそ |
| **ランキング (スコア)** |候補者を正確に採点して順序付けする |多くの機能を備えたディープなモデル。遅いが正確 |
| **再ランキング** |多様性、ビジネスルール、鮮度を調整 |文脈上の盗賊。制約の最適化 |

## 評価指標
|メトリック |何を測定するのか |いつ使用するか |
|----------|------|---------------|
| **Precision@K** |関連する上位 K 件の推奨事項の割合 |トップピックの精度が気になる場合 |
| **リコール@K** |トップ K | で見つかった関連アイテムの割合良いものを逃さないようにしたいときに |
| **NDCG** (正規化割引累積ゲイン) |ランキングの品質。関連アイテムを上位に置く報酬 |ランキングの順序が重要な場合 |
| **MAP** (平均平均精度) |全ユーザーの平均精度 |総合ランキングの品質 |
| **ヒット率@K** |少なくとも 1 つの関連項目が上位 K に表示されるかどうか |バイナリ関連性シナリオ |
| **対象範囲** |推奨されるアイテムの割合 |多様性と公平性 |
| **セレンディピティ** |予想外だが関連性のある推奨事項 |ユーザー満足度 |

## コールドスタートの問題
|シナリオ |チャレンジ |ソリューション |
|----------|-----------|----------|
| **新規ユーザー** |インタラクション履歴なし |人口統計を使用します。人気のアイテムを表示します。コンテキスト信号 (場所、デバイス、時間) を使用する |
| **新商品** |まだ誰もそれと対話していません |コンテンツ機能を使用します。探索と活用の戦略。バンディットアルゴリズム |
| **新システム** |データがまったくありません |同様のドメインからの転移学習。初期コンテンツを厳選する |

## 探索 vs 搾取
|戦略 |説明 |トレードオフ |
|----------|---------------|----------|
| **ε-貪欲** |確率 ε | でランダムなアイテムを表示します。シンプルだが非効率 |
| **トンプソンサンプリング** |品目の品質の事後分布からのサンプル |原則的。優れた理論的特性 |
| **信頼限界 (UCB)** |不確実性の高い項目を優先 |探索と活用のバランスが良い |
| **コンテキスト盗賊** |ユーザーのコンテキストに基づいた探索 |やみくもに探索するより効率的 |
| **多様性の注入** |多様なアイテムや斬新なアイテムを意図的に含める |単純;短期的なエンゲージメントが減少する可能性があります |
---

## バイアスと公平性
|バイアスタイプ |説明 |影響 |
|----------|---------------|----------|
| **人気の偏り** |人気アイテムはさらにおすすめされ、さらに人気が高まります |ロングテール商品は十分なサービスを受けられていない |
| **選択バイアス** |モデルは、考えられるすべての相互作用ではなく、観察された相互作用から学習します。アクティブ ユーザーに偏る |
| **位置バイアス** |上位に表示されるアイテムは、品質に関係なく、より多くのクリック数を獲得します。上位陣を補強 |
| **露出バイアス** |表示されたアイテムは、より多くのトレーニング信号を受け取ります。フィードバックループ |
| **人口統計上の偏り** |推奨事項は人口統計によって不公平な形で異なります。差別;一部のグループでは経験が乏しい。
### 緩和戦略
|戦略 |説明 |
|----------|---------------|
| **逆傾向の重み付け** |トレーニングに人気のダウンウェイトアイテム |
| **デバイアス層** |モデルにバイアス除去コンポーネントを追加する |
| **公平性の制約** |公平な扱いを確保するために制約を追加する |
| **さまざまな推奨事項** |関連性とともに多様性を明示的に最適化する |
| **監査と監視** |グループ間の偏りに関する推奨事項を定期的に確認する |

＃＃ まとめ
レコメンデーション システムは、業界で最も影響力のある AI アプリケーションの 1 つです。この分野は、単純な協調フィルタリングから、ユーザー履歴、アイテムのコンテンツ、コンテキスト信号、ビジネス目標を組み合わせたディープラーニング アーキテクチャへと進化しました。最新のシステムは、検索、ランキング、再ランキングのパイプラインを使用しており、候補を迅速に生成するための 2 つのタワー モデルと、正確なスコアリングのためのディープ モデルを備えています。コールド スタート、バイアス、調査、ユーザー満足度とビジネス目標のバランスなどの課題は、依然として研究とエンジニアリングの活発な領域です。
