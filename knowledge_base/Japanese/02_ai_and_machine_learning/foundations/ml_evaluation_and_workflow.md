# 機械学習の評価とワークフロー
メトリクス、検証、デバッグに焦点を当てた、問題の枠組みから運用監視までの ML ライフサイクルの実践的なガイド。
---

## ML ワークフロー (CRISP-ML)
1. **ビジネスの理解**: 目的と成功基準を定義します。
2. **データの理解**: 利用可能なデータを調査し、品質の問題を特定します。
3. **データの準備**: データをクリーンアップ、変換、分割します。
4. **モデリング**: モデルをトレーニングし、ハイパーパラメーターを調整します。
5. **評価**: 指標に照らしてパフォーマンスを評価します。
6. **デプロイ**: 実稼働環境でモデルを提供します。
7. **モニタリング**: ドリフト、パフォーマンス、異常を追跡します。
これは反復ループです。評価結果に基づいて前のステップに戻ります。
---

## データの分割
### トレーニング/検証/テストの分割
- **トレーニング セット** (~70%): モデル パラメーターを適合させるために使用されます。
- **検証セット** (~15%): ハイパーパラメーターの調整とモデル バリアントの選択に使用されます。
- **テスト セット** (~15%): 一般化パフォーマンスを推定するために、最後に 1 回だけ使用されます。
**重要:** データ漏洩を防ぐため、テスト セットは最終評価まで完全に手を加えないでください。
### 相互検証 (k 分割)
小さなデータセットの場合は、k 分割相互検証を使用します。データを k 分割に分割し、k-1 でトレーニングし、残りで検証し、k 回繰り返します。パフォーマンスを平均します。 k=5 または k=10 が一般的です。
### 層別分割
不均衡なクラスによる分類の場合は、層別分割を使用して、各サブセット内のクラスの比率を維持します。
### 時間ベースの分割
時系列データの場合は、ランダムではなく時系列に分割します (過去でトレーニング、未来でテスト)。
---

## 評価指標
### 分類メトリック
|メトリック |何を測定するのか |最適な用途 |
|------|---------------|---------------|
| **精度** | (TP + TN) / (TP + TN + FP + FN) |バランスの取れたデータセット |
| **精度** | TP / (TP + FP) |誤検知にコストがかかる場合 (スパム検出など) |
| **思い出してください** | TP / (TP + FN) |偽陰性により費用がかかる場合 (例: がん検診) |
| **F1 スコア** |精度と再現率の調和平均 |不均衡なデータセット、単一数値メトリック |
| **AUC-ROC** | ROC 曲線の下の領域。 TPR と FPR の間のトレードオフ |しきい値に依存しない一般的な分類器のパフォーマンス |
| **AUC-PR** |適合率-再現率曲線の下の領域 |非常に不均衡なデータセット |
**定義:**
- TP = 真陽性
- TN = 真陰性
- FP = 誤検知 (タイプ I エラー)
- FN = 偽陰性 (タイプ II エラー)
### 回帰指標
|メトリック |何を測定するのか |異常値に対する感度 |
|----------|------|---------------|
| **MSE** (平均二乗誤差) |平均二乗差 |高 |
| **RMSE** (二乗平均平方根誤差) | MSE の平方根 (ターゲットと同じ単位) |高 |
| **MAE** (平均絶対誤差) |平均絶対差 |低い |
| **R²** (決定係数) |分散の割合の説明 |直接的にはありませんが、間接的に異常値の影響を受けます。
### ランキングと取得のメトリクス
- **Precision@k**: 上位 k 個の推奨事項のうちの関連項目の割合。
- **Recall@k**: 上位 k に表示されるすべての関連項目の割合。
- **NDCG** (正規化割引累積利益): ポジションの関連性を考慮します。
- **ヒット率**: 関連項目が上位に表示されるかどうか。
### 生成/LLMメトリクス
- **当惑**: 差し出されたテキストにモデルがどの程度「驚いているか」(数値が低いほど良い)。
- **BLEU**: n グラムは参照翻訳と重複します (精度重視)。
- **ROUGE**: 要約のための回想指向の重複。
- **BERTScore**: コンテキスト埋め込みを使用した意味的類似性 (BLEU よりも堅牢)。
- **METEOR**: WordNet の同義語および語幹に合わせます。

## 評価の落とし穴
### データ漏洩
テスト セットからの情報がトレーニングに誤って影響を与えた場合に発生します。
- **予防策:** テスト データを特徴量エンジニアリング、正規化、またはハイパーパラメーター調整に使用しないでください。
- **検出:** モデルのスコアが疑わしいほど高い場合は、漏れが疑われます。
### 過学習
モデルはトレーニング データでは良好に機能しますが、検証/テストでは不十分です。
- **緩和:** 正規化、早期停止、アーキテクチャの簡素化、またはより多くのデータの収集を使用します。
### アンダーフィッティング
モデルはトレーニングと検証の両方でパフォーマンスが低下します。
- **軽減:** より複雑なモデルを使用するか、機能を追加するか、正則化を減らします。
### 不均衡なデータ
- **軽減:** 精度ではなく、クラスの重み、オーバーサンプリング (SMOTE)、アンダーサンプリング、または適切なメトリクス (F1、AUC-PR) を使用します。
### 時間的ドリフト (概念ドリフト)
機能とターゲットの関係は時間の経過とともに変化します。
- **軽減:** 定期的に再トレーニングし、パフォーマンスを監視し、ドリフト検出アルゴリズムを使用します。
---

## ハイパーパラメータの調整
- **グリッド検索**: 事前定義されたハイパーパラメータのセットのすべての組み合わせを徹底的に試します。シンプルですが、計算コストが高くつきます。
- **ランダム検索**: 分布からランダムな組み合わせをサンプルします。高次元空間のグリッド検索よりも効率的です。
- **ベイジアン最適化**: 目的関数の確率モデルを構築し、ハイパーパラメーターをインテリジェントに選択します。ライブラリ: Optuna、Hyperopt、scikit-optimise。
- **自動チューニング**: 分散チューニングには、Optuna、Ray Tune、重みとバイアス スイープなどのツールを使用します。
**一般的なハイパーパラメータの推奨検索範囲:**
|パラメータ |推奨範囲 (対数スケール) |
|----------|----------------------------|
|学習率 | 1e-5 から 1e-1 |
|バッチサイズ | 16、32、64、128、256 |
|層数 (NN) | 2～6 |
|ニューロンの数 (NN) | 32 ～ 1024 |
|正則化 (L2) | 1e-6 から 1e-2 |
|ツリーの深さ (XGBoost) | 3 ～ 12 |

## モデルの選択と検証
1. **ベースライン モデル**: 単純なヒューリスティック モデルまたは単純なモデル (ロジスティック回帰、平均予測子など) から開始して、下限を確立します。
2. **候補モデル**: 複数のモデル ファミリ (ランダム フォレスト、XGBoost、ニューラル ネットワークなど) をトレーニングします。
3. 検証セットの各候補を **相互検証**します。
4. **メトリクスを比較** (信頼区間あり) し、最適な候補を選択します。
5. 保持されたテストセットの **最終評価**。
6. **エラー分析**: モデルが間違っている例を見てください。パターン (稀なクラス、あいまいな入力など) を特定し、洞察をデータ準備や特徴エンジニアリングにフィードバックします。
---

## 導入と監視
### 提供パターン
- **バッチ推論**: 大量のデータをオフラインで処理します (夜間の推奨事項など)。
- **オンライン推論**: API を介したリアルタイム予測 (信用スコアリング、不正行為検出など)。
- **ストリーミング推論**: イベント駆動型、低遅延のリアルタイム (例: IoT センサー アラート)。
### モデルのモニタリング
- **パフォーマンス監視**: ライブ データの長期にわたる精度/F1 を追跡します (グラウンド トゥルースが利用可能な場合)。
- **データ ドリフト**: 入力特徴分布の変化を監視します (例: PSI – Population Stability Index を使用)。
- **コンセプトドリフト**: 入力と出力の間の関係の変化を監視します。
- **予測ドリフト**: 予測された出力の分布を追跡します。
- **遅延とスループット**: SLA (サービス レベル アグリーメント) が満たされていることを確認します。
### ロギングとアラート
- すべての予測リクエストと応答をログに記録します (匿名化付き)。
- アラートを設定:
  - パフォーマンスの大幅な低下。
  - 欠落または無効な入力の割合が高い。
  - モデルの出力が予想範囲を超えます。
### モデルのバージョン管理とレジストリ
- モデル レジストリ (MLflow、Weights & Biases、Sagemaker Model Registry など) を使用して、モデル、メタデータ、評価結果を保存し、バージョン管理します。
- トレーニング コードとデータ バージョン (DVC または Git LFS 経由) をモデルと一緒に保存します。
