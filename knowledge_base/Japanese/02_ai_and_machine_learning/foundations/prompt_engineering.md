# 迅速なエンジニアリング
プロンプト エンジニアリングは、言語モデルから可能な限り最高の出力を得るために、入力プロンプトを設計、改良、最適化する実践です。これは芸術であり科学でもあり、微調整せずに LLM の動作を制御するための主要なインターフェイスです。
---

## 基本原則
### 明確さと具体性
明確なプロンプトには、曖昧さの余地がありません。形式、長さ、視点など、希望する内容を正確に指定します。
**曖昧:**
> 「Python について教えてください。」
**具体的:**
> 「Python のグローバル インタプリタ ロック (GIL) について説明します。マルチスレッドへの影響を説明し、回避策を 1 つ挙げ、回答を 200 ワード以内にしてください。」
### コンテキストを提供する
モデルは、役割、対象者、目標を理解している場合、パフォーマンスが向上します。
**コンテキストなし:**
> 「リストをソートする関数を作成します。」
**コンテキスト付き:**
> 「あなたは上級 Python 開発者です。指定されたキーで辞書のリストを並べ替える関数を作成してください。タイプ ヒントを使用し、特殊なケースに対処してください。対象者はジュニア開発者です。」
### 積極的な指示を使用する
何を避けるべきかではなく、何をすべきかをモデルに伝えます。 「専門用語を含めない」は、「10 歳児が理解できる簡単な言葉を使用する」よりも弱いです。
---

## プロンプト構造
### システム/ユーザー/アシスタントの役割
ほとんどの LLM API はマルチターン構造をサポートしています。
- **システム メッセージ**: モデルの動作、ペルソナ、および制約を設定します (セッション全体にわたって持続します)。
- **ユーザー メッセージ**: 現在のクエリまたは指示。
- **アシスタント メッセージ**: モデルの以前の応答 (継続のために使用されます)。
**例 (OpenAI API スタイル):**
システム: あなたは有能なコーディングアシスタントです。簡潔なコード例と簡単な説明を返信します。安全でないコードは決して提供しないでください。
ユーザー: URL からファイルをダウンロードする Python 関数を作成します。
### 数ショットのプロンプト
モデルにタスクの実行を依頼する前に、必要な入出力形式の例を 2 ～ 3 つ提供してください。これはパターンを教えます。
**例:**
ユーザー: これらの文を受動態に変換します。
入力: 猫はネズミを追いかけました。
出力: ネズミは猫に追いかけられました。
入力: シェフが食事を作りました。
出力: 食事はシェフによって調理されました。
入力: 嵐で家が壊れました。
出力: (モデルが完成)
### 思考連鎖 (CoT)
モデルがその推論を段階的に示すよう促します。これにより、算術、論理、および複数ステップのタスクの精度が向上します。
**CoT なし:**
> 「24×37って何？」
**CoT あり:**
> 「24 × 37 を計算してください。推論を段階的に示してください。」
モデルは中間ステップを生成し、算術エラーを減らします。
### 構造化された出力
解析の信頼性を高めるために、JSON、YAML、マークダウン テーブルなどの特定の形式をリクエストします。
ユーザー: マイクロサービスの長所と短所を 3 つ挙げてください。キー「pros」と「cons」（それぞれ文字列の配列）を持つ有効な JSON オブジェクトのみを返します。

## 高度なテクニック
### 自己一貫性
同じプロンプト (温度 > 0) に対して複数の応答を生成し、最終的な回答に対して多数決を取ります。これは、推論タスクに特に効果的です。
### 思考の木
複数の推論パスを並行して探索し、それぞれを評価して、最適な推論パスを選択します。これは研究レベルの手法ですが、モデルに「代替ソリューションを探索する」ように依頼することで近似できます。
### ReAct (推論 + 行動)
モデルに推論とツール呼び出しをインターリーブさせます。考えてから行動し (Web を検索したり、コードを実行したり)、その結果に基づいて再度考えることができます。
**プロンプト構造:**
計算機と検索エンジンにアクセスできます。ステップごとに、次を出力します。
考え: (あなたの推論)
アクション: (ツール名、入力)
観察：（ツールの出力）
...最終的な答えが見つかるまで続けます。
### ペルソナの割り当て
応答を組み立てるために特定のペルソナを割り当てます。
**例:**
- 「あなたは Linux カーネル開発者で、新卒者にメモリ管理について説明しています。」
- 「あなたはクライアントに一般的なアドバイスをするフレンドリーな栄養士です。」
- 「あなたは新しいガジェットをレビューしている皮肉な技術評論家です。」
---

## パラメータのチューニング
- **温度** (0.0 – 1.0+): ランダム性を制御します。低い = より決定的、高い = より創造的です。事実に基づく回答には 0.0 ～ 0.3 を使用します。クリエイティブ ライティングの場合は 0.7 ～ 1.0。
- **Top-p** (核サンプリング): 特定の累積しきい値で確率質量をカットオフします。 0.9 は、モデルが可能性の高いトークンの上位 90% からサンプリングすることを意味します。通常は、両方ではなく、温度またはトップ温度のいずれかを調整します。
- **最大トークン数**: 出力の最大長を設定します。コンテキスト ウィンドウ内で応答用のスペースを忘れずに予約してください。
- **頻度ペナルティ**: 同じトークンの繰り返しを減らします。
- **プレゼンス ペナルティ**: モデルに新しいトピックを導入することを奨励します。

## よくある落とし穴と修正
|問題 |考えられる原因 |修正 |
|----------|--------------|-----|
|モデルはプロンプトの一部を無視します |プロンプトが長すぎるか過負荷です |短くしてください。最も重要な指示を最後に置きます |
|出力が冗長すぎます |長さの制限なし | 「3 文に制限」を追加するか、max_tokens を設定します。
|出力が簡潔すぎる |過度に制限的 | 「詳しく説明します」を追加するか、温度を下げる |
|事実上の幻覚 |文脈が不十分または曖昧な質問 | 「わからない場合は、「わかりません」と言ってください」を追加し、RAG コンテキストを提供します。
|一貫性のない書式設定 |明示的なフォーマット指示がない | JSON、マークダウン テーブル、または箇条書きリストを要求する |
|間違った言語での模範解答 |言語指導なし | 「英語で応答してください」（またはターゲット言語）と明示的に述べてください。

## 一般的なタスクのプロンプト テンプレート
### 要約
次の文章を 3 つの箇条書きで要約してください。主要な議論に焦点を当て、詳細は避けます。
テキスト: [テキストを挿入]

### コード生成
[X を実行する] [言語] 関数を作成します。
要件：
型ヒントを使用します。
docstring を含めます。
エッジケースの処理: [リスト]。
指定がない限り、外部ライブラリを使用しないでください。

### 説明
[非専門家/大学生/子供]に[コンセプト]を説明します。必要に応じて、たとえ話を使用します。
### ブレーンストーミング
[トピック] について 10 個のアイデアを生成します。各アイデアについて、一文で説明し、潜在的な課題を 1 つ説明します。
文章
### 分類
次の顧客フィードバックを [肯定的、中立、否定的] に分類します。
信頼度スコア (0 ～ 100) と簡単な理由を入力します。
フィードバック: [テキストを挿入]
### スタイリッシュな翻訳
次の英語の文章をスペイン語に翻訳してください。ソーシャルメディアの投稿に適したカジュアルな口調を使用してください。
テキスト: [テキストを挿入]

## プロンプトの評価
プロンプトをコードとして扱います。プロンプトをバージョン管理し、テストし、反復します。
- **A/B テスト** 保留された一連のクエリに対してさまざまなプロンプト バリアントをテストします。
- **人間による評価または自動化された指標 (完全一致、BLEU、カスタム スコアリングなど) によって成功を測定します**。
- **プロンプト、バージョン、および観察されたパフォーマンスを含むプロンプト レジストリ** (単純なテキスト ファイルまたはスプレッドシート) を保管します。
