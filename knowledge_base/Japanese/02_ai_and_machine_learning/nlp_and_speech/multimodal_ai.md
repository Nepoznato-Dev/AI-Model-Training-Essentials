# マルチモーダル AI
マルチモーダル AI システムは、テキスト、画像、音声、ビデオなど、複数の種類のデータからの情報を同時に処理して組み合わせます。以前の AI システムは通常、単一モーダル (テキストのみ、画像のみ) でしたが、最も機能的な最新のシステムはマルチモーダルです。 GPT-4V は画像とテキストを一緒に読み取ります。 Gemini はテキスト、画像、オーディオ、ビデオをネイティブに処理します。 Sora のようなシステムはテキストの説明からビデオを生成します。このファイルでは、マルチモーダル AI の仕組み、その背後にあるアーキテクチャ、およびモダリティの組み合わせが非常に強力である理由について説明します。
---

## なぜマルチモーダルなのか?
|メリット |説明 |例 |
|----------|---------------|----------|
| **より深い理解** |さまざまなモダリティが補完的な情報を提供します。動画は、テキストだけでは表現できない動き、音、コンテキストを伝えます。
| **より良い一般化** |モダリティを超えた学習により、より堅牢な表現が作成されます。 「猫」の画像とテキストの説明の両方を見たモデルは、その概念をよりよく理解します。
| **より自然なインタラクション** |人間は複数のチャネルを通じてコミュニケーションします |あなたが指しているものを認識する音声アシスタント |
| **クロスモーダル転送** |あるモダリティからの知識は別のモダリティに役立ちます。画像の理解によりテキスト生成が向上し、その逆も同様です。

## コア アーキテクチャ
### 視覚言語モデル (VLM)
画像とテキストを一緒に処理するモデル。
|建築 |仕組み |例 |
|---------------|---------------|----------|
| **デュアルエンコーダ** |画像とテキストのエンコーダを個別に設定します。後の段階で結合する |クリップ、整列 |
| **フュージョン エンコーダー** |画像とテキストのトークンはインターリーブされ、一緒に処理されます。フラミンゴ、ジェミニ |
| **クロス注意** |テキスト トークンは画像の特徴に対応します (またはその逆)。フラミンゴ、CoCa |
| **統合トークナイザー** |画像はトークンに変換され、テキスト トークンと一緒に処理されます。ジェミニ、カメレオン |
### 視覚言語モデルの仕組み
|ステップ |説明 |
|------|---------------|
| **1.画像をエンコード** |ビジョン エンコーダ (ViT、SigLIP) は、画像を一連の特徴ベクトルに変換します。
| **2.テキストをエンコード** |言語エンコーダーはテキスト トークンを処理します。
| **3.融合モダリティ** |画像の特徴は言語モデルの埋め込み空間に投影されます。
| **4.生成** |言語モデルは、画像とテキストの両方の入力に基づいてテキストを生成します。
### 主要な視覚言語モデル
|モデル |開発者 |建築 |注目の機能 |
|------|-----------|---------------|------|
| **クリップ** |オープンAI |デュアルエンコーダー (ViT + テキストエンコーダー) |テキストによるゼロショット画像分類 |
| **LLaVA** |オープンソース | LLaMA + CLIP ビジュアルエンコーダー |オープンソース VLM。強力なコミュニティ |
| **GPT-4V / 4o** |オープンAI |統合されたマルチモーダル |テキスト、画像、音声を一緒に処理 |
| **ジェミニ** | Google ディープマインド |トレーニングからネイティブにマルチモーダル |マルチモーダル向けにゼロから構築 |
| **クロード** |人類 |ビジョン + テキスト |文書や図表の理解が得意 |
| **クウェン VL** |アリババ |無差別ウェイト VLM |クローズドモデルとの競争力 |
| **インターンVL** |オープンソース |マルチスケールビジョンエンコーダ |強力なオープンソース オプション |

## ビデオモデル
ビデオは画像、音声、テキスト、時間を組み合わせたもので、最も複雑なモダリティです。
|モデル |タイプ |能力 |
|------|------|---------------|
| **ソラ** (OpenAI) |テキストからビデオへ |最大1080p。物理学を理解しています |
| **ジェミニ** |ビデオの理解 |音声付きの長いビデオを分析できます |
| **ビデオ-LLaVA** |ビデオ + テキスト |オープンソースビデオの理解 |
| **滑走路 Gen-3** |テキスト/画像からビデオへ |コマーシャルビデオの生成 |
| **クリング** |テキストからビデオへ |長編ビデオの生成 |
### ビデオ理解の課題
|チャレンジ |説明 |
|----------|---------------|
| **時間的推論** |時間の経過とともに展開するイベントを理解する |
| **長い文脈** |ビデオは数時間にも及ぶ場合があります。すべてのフレームの処理は高価です |
| **視聴覚同期** |語られた内容と示された内容を結び付ける |
| **因果関係** |ビデオ シーケンスにおける原因と結果を理解する |

## クロスモーダル検索
さまざまなモダリティにわたる関連コンテンツの検索。
|タスク |説明 |例 |
|------|-------------|----------|
| **テキスト → 画像** |テキストクエリに一致する画像を検索 |写真ライブラリで「山に沈む夕日」を検索 |
| **画像 → テキスト** |画像に関連するテキストを検索する |画像のキャプションを生成する |
| **テキスト → オーディオ** |説明に一致するサウンドを検索 |サウンドデザイン：「砂利の上の足音」 |
| **画像 → 画像** |視覚的に類似した画像を見つける |画像から商品を探す |
### クロスモーダル検索用の CLIP
CLIP の共有埋め込みスペースにより、ゼロショットのクロスモーダル検索が可能になります。
|ステップ |説明 |
|------|---------------|
| 1 |ビジョンエンコーダーを使用してすべての画像をエンコード |
| 2 |テキスト エンコーダを使用してテキスト クエリをエンコードする |
| 3 |テキスト埋め込みとすべての画像埋め込みの間のコサイン類似度を計算します。
| 4 |最も類似性の高い画像を返します。
これは、タスク固有のトレーニングを必要とせずに機能します。これは **ゼロショット** 機能と呼ばれる特性です。

## 身体化された AI
身体化された AI は、マルチモーダルな知覚と物理的な動作を組み合わせます。
|システム |モダリティ |アプリケーション |
|----------|----------|---------------|
| **RT-2** (Google) |視覚 + 言語 → ロボットの動作 |テキスト命令による汎用ロボット制御 |
| **10月** |オープンソースロボットポリシー |多様なロボットデータでトレーニング |
| **テスラ オプティマス** |視覚 + 言語 → 身体的作業 |一般作業用人型ロボット |
| **図 01** |視覚 + 言語 + 音声 |会話能力を持つ人型ロボット |
### 身体化された AI における課題
|チャレンジ |なぜ難しいのか |
|----------|--------------|
| **シミュレーションと実際のギャップ** |シミュレーションは現実世界の物理学を完全に捉えているわけではありません。
| **器用さ** |細かい運動制御（手、指）は非常に難しい |
| **安全性** |物理的なロボットは実害を引き起こす可能性があります |
| **リアルタイム処理** |ミリ秒単位で認識、決定、行動する必要があります |
| **一般化** |赤いカップを拾うように訓練されたロボットは、青いカップでは失敗する可能性がある |

＃＃ まとめ
マルチモーダル AI は、単一目的のモデルから、あらゆる形式のデータを認識して推論するシステムへの移行を表しています。 GPT-4V や Gemini などの視覚言語モデルは、画像とテキストを一緒に理解できます。 Whisper や VALL-E などの音声モデルはオーディオを処理します。ビデオ モデルは、音声付きの動画の複雑さを完全に処理し始めています。傾向は明らかです。将来の最も有能な AI システムは、ネイティブにマルチモーダルであり、あらゆる種類の情報を同時に処理することになります。データの調整、計算コスト、評価、具体的な導入などの課題は重大ですが、2024 年から 2026 年にかけての進歩は急速でした。
