# NLP の基礎
自然言語処理 (NLP) は、人間の言語を理解し、生成し、操作するように機械に教える分野です。これは、検索エンジン、チャットボット、翻訳システム、センチメント分析、および 2020 年以降 AI を変革してきた大規模言語モデル (LLM) を強化します。このファイルは、古典的な技術から最新の Transformer ベースのアーキテクチャへの進化をカバーしています。
---

## テキストの前処理
生のテキストは乱雑です。モデルで使用するには、事前にクリーニングして構造化する必要があります。
|ステップ |何をするのか |例 |
|------|-------------|----------|
| **トークン化** |テキストをトークン (単語、サブワード、または文字) に分割する | 「NLPが大好きです」 →`["I", "love", "NLP"]`|
| **小文字** |小文字に変換 | 「こんにちは」→「こんにちは」 |
| **ストップワードの削除** |一般的な単語 (the、is、at) を削除する | 「猫が座った」→「猫が座った」 |
| **ステミング** |語尾を切り取る（粗雑） | 「走る」→「走る」 |
| **見出し語化** |辞書形式に変換 (コンテキスト認識) | 「良い」→「良い」 |
| **正規化** |エンコーディングを修正し、特殊文字を削除し、短縮形を拡張します。 「しない」→「しない」 |
最新の Transformer モデルは、ストップワードの削除とステミングをスキップすることが多く、これらのパターンをデータから学習します。
---

## テキスト表現
機械には言葉ではなく数字が必要です。テキストをベクトルとしてどのように表現するかが基本です。
### 古典的なアプローチ
|方法 |説明 |制限 |
|----------|---------------|----------|
| **ワンホット エンコーディング** |各単語は巨大なベクトル内で一意の位置にあります。まばら。意味論的な意味はありません |
| **バッグ オブ ワーズ (BoW)** |単語の頻度を数えます。順序を無視する |語順が完全に失われます |
| **TF-IDF** |文書内の頻度×コーパス全体の希少性によって単語を重み付けする |依然として順序とコンテキストを無視します。
### 単語の埋め込み
埋め込みは、類似した単語が互いに近接している密なベクトルに単語をマップします。
|モデル |主要なアイデア |
|------|----------|
| **Word2Vec** (2013) |コンテキストから単語を予測 (CBOW) または単語からコンテキストを予測 (スキップグラム) |
| **グローブ** (2014) |グローバル共起統計 → 密ベクトル |
| **FastText** (2016) | Word2Vec + サブワード情報 (まれな単語をより適切に処理) |
有名な例:`king - man + woman ≈ queen`。埋め込みは意味的な関係をキャプチャします。
**制限事項**: 従来の埋め込みでは単語ごとに 1 つのベクトルを割り当てるため、多義性 (複数の意味を持つ単語) を処理できません。 「川の銀行」と「銀行口座」の「銀行」は同じベクトルを取得します。

## シーケンスモデル
Transformers が登場する以前は、NLP の標準的なアプローチはテキストを順番に処理することでした。
|建築 |仕組み |強さ |弱点 |
|---------------|---------------|----------|----------|
| **RNN** |トークンを一度に 1 つずつ処理します。非表示状態を維持する |可変長入力を処理します。消えるグラデーション。長い依存関係をキャプチャできません |
| **LSTM** |情報フローを制御するためのゲート (忘れ、入力、出力) を備えた RNN |長距離の依存関係に優れています |まだシーケンシャルです。トレーニングが遅い |
| **GRU** |簡素化された LSTM (ゲート数が少ない) | LSTM よりも高速です。同様のパフォーマンス |基本的な制限は同じです |
これらのモデルはテキストを左から右に処理するため、トレーニングが遅く (並列化できない)、長距離の依存関係に苦労します。
---

## アテンションのメカニズム
アテンションを使用すると、モデルはシーケンス内のすべての位置を同時に調べて、どの位置が現在の予測に最も関連しているかを判断できます。
### 重要な洞察
(RNN のように) 文全体を 1 つの隠れ状態に圧縮する代わりに、attention はすべての隠れ状態の重み付けされた合計を計算し、重みが学習されます。
```
Attention(Q, K, V) = softmax(QK^T / √d_k) V
```

|コンポーネント |役割 |
|-----------|------|
| **クエリ (Q)** |私は何を探しているのでしょうか？ |
| **キー (K)** |私には何が入っているのでしょうか？ |
| **値 (V)** |どのような情報を提供すればよいですか? |
| **√d_k** |大きなドット積を防ぐためのスケーリング係数 |

## トランスフォーマーのアーキテクチャ
The Transformer (Vaswani et al., 2017 — "Attending Is All You Need") は、再発を完全に注意に置き換えました。これは、事実上すべての現代の NLP の基礎です。
＃＃＃ 建築
|コンポーネント |説明 |
|----------|---------------|
| **エンコーダ** |入力テキストを読み取ります。コンテキスト表現を生成します |
| **デコーダ** |出力テキストを生成します。エンコーダ出力を処理します |
| **自注意** |各トークンは、同じシーケンス内の他のすべてのトークンに対応します。
| **マルチヘッドへの注意** |複数のアテンションヘッドを並行して実行します。さまざまな関係を捉える |
| **位置エンコーディング** |位置情報を注入（再発がないので） |
| **フィードフォワード ネットワーク** |各位置に個別に適用される |
| **レイヤーの正規化** |トレーニングを安定させる |
| **残留接続** |勾配フローのスキップ接続 |
### エンコーダのみ、デコーダのみ、エンコーダ-デコーダ
|バリアント |建築 |最適な用途 |例 |
|----------|---------------|----------|-----------|
| **エンコーダのみ** |テキストを理解する |分類、NER、感情分析 |バート、ロベルタ、デベルタ |
| **デコーダのみ** |テキストを生成します |言語モデル、チャットボット、コード生成 | GPT-3/4、LLaMA、クロード |
| **エンコーダ-デコーダ** |テキストを変換する |翻訳、要約 | T5、BART、mBART |

## 主要なモデル ファミリ
### BERT ファミリ (エンコーダのみ)
|モデル |主な機能 |
|------|-----------|
| **バート** (2018) |マスクされた言語モデル + 次の文の予測 |
| **ロベルタ** | NSP を削除しました。より多くのデータでより長くトレーニング |
| **アルバート** |パラメータの共有。設置面積が小さい |
| **デベルタ** |もつれた注意を解きほぐす。 NLU の改善 |
| **蒸留BERT** | 40% 小型化、60% 高速化、BERT のパフォーマンスの 97% を維持 |
### GPT ファミリ (デコーダのみ)
|モデル |パラメータ |メモ |
|------|-----------|------|
| **GPT-2** | 1.5B |示されたデコーダ専用モデルは一貫したテキストを生成できます。
| **GPT-3** | 175B |数回の学習で学習可能。微調整ではなくプロンプトを表示 |
| **GPT-3.5 / GPT-4** |未公開 |命令チューニング + RLHF;会話 |
| **LLaMA** (メタ) | 7B～70B |無差別ウェイト。オープンソース LLM エコシステムを生み出した |
| **ミストラル / ミストラル** | 7B / 8×7B (MoE) |強力なパフォーマンスを備えた効率的なオープン モデル |

## コア NLP タスク
|タスク |説明 |代表的なモデル |
|------|---------------|--------------|
| **テキストの分類** |テキストにラベルを割り当てる (スパム/スパムではない、肯定的/否定的) | BERT、微調整された分類器 |
| **固有表現認識 (NER)** |テキスト内の人物、組織、場所を特定する | BERT + CRF 層 |
| **感情分析** |感情のトーンを決定する |微調整された BERT またはゼロショット LLM |
| **機械翻訳** |言語間の翻訳 | T5、mBART、マリアンMT |
| **質問への回答** |コンテキストを考慮して質問に答える | BERT (抽出)、GPT (生成) |
| **要約** |長いテキストを圧縮する | T5、BART、GPT |
| **テキスト生成** |一貫したテキストを作成する | GPT-4、LLaMA、クロード |

## 微調整 vs プロンプト
|アプローチ |仕組み |いつ使用するか |
|----------|---------------|---------------|
| **微調整** |タスク固有のデータに基づいてモデルの重みを更新する |データにラベルを付けました。最大のパフォーマンスが必要 |
| **プロンプト** |自然言語でモデルに指示を与える |素早いプロトタイピング。限られたデータ。 LLM の使用 |
| **数ショット** |プロンプトに例を含める |いくつかの例があるが、微調整するには十分ではない場合 |
| **LoRA / QLoRA** |効率的な微調整。小さな低ランク行列を更新する |限られた GPU メモリで大規模なモデルを微調整する |

## LLM の風景
現代の NLP 環境は大規模言語モデルによって支配されています。
|カテゴリー |例 |メモ |
|----------|-----------|----------|
| **独自仕様** | GPT-4、クロード、ジェミニ |最高のパフォーマンス。 API アクセスのみ |
| **無差別ウェイト** | LLaMA 3、ミストラル、クウェン |利用可能な重み。ローカルで実行する |
| **オープンソース** |ピシア、オプト |フルオープン (データ、重み、コード) |
| **マルチモーダル** | GPT-4V、ジェミニ、LLaVA |テキスト + 画像を処理する |
| **コードに特化した** | CodeLlama、StarCoder、DeepSeek コーダー |コードのトレーニング |
| **小型 / 効率的** |ファイ-3、ジェマ、タイニーラマ |小規模でも優れたパフォーマンス |
現場は急速に動いています。現在最先端のものは、数か月後には取って代わられる可能性があります。注意、トークン化、微調整、評価といった基本は安定しています。
