# Base de connaissances
Une collection complète de documents de référence couvrant le codage, la technologie, l'IA, la science, les affaires, les sciences humaines et bien plus encore, rédigés dans un style conversationnel naturel conçu à la fois pour la formation en IA et l'apprentissage humain.
**Dernière mise à jour :** août 2026  
**Total des fichiers :** plus de 138 documents démarques  
**Organisation :** 10 répertoires thématiques + 34 références de langages de programmation
---

## Consignes d'utilisation
### Pour les systèmes d'IA
- Tous les fichiers utilisent des titres hiérarchiques clairs (titre `#`, sections `##`, sous-sections `###`).
- Les tableaux sont utilisés pour des comparaisons structurées tout au long
- Les exemples de code incluent la coloration syntaxique
- Les références croisées utilisent des liens de démarque relatifs
### Pour les lecteurs humains
- Les fichiers sont rédigés sur un ton conversationnel et neutre
- Des tableaux et des comparaisons structurées sont utilisés à la place de paragraphes denses
- Des exemples et des analogies du monde réel aident à ancrer des concepts abstraits
- Chaque fichier comprend une section récapitulative

## Contribution et métadonnées
Chaque fichier de contenu de cette base de connaissances (tout sauf ce`README.md`) s'ouvre avec un bloc frontal YAML. Il suit le même modèle de suivi des contributeurs utilisé par[skills](../../skills/skill-creator.md), de sorte que la paternité, les modifications et les critiques restent traçables dans les deux collections. Pour le flux de travail général de contribution (duplication, branchement, demandes d'extraction, placement de fichiers et conventions de dénomination) voir la racine[CONTRIBUTING.md](../../CONTRIBUTING.md).

### Modification d'un fichier
Lorsque vous modifiez un fichier de base de connaissances, gardez son contenu synchronisé :
1. **Bump`version`** suite à [SemVer](https://semver.org/) :
   - Patch (`1.0.x`) : fautes de frappe, formatage, corrections mineures
   - Mineur (`1.x.0`) : nouvelles sections, contenu étendu, nouveaux exemples
   - Majeur (`x.0.0`) : réécriture ou restructuration complète
2. **Ajoutez une entrée du journal des modifications** (la plus récente en premier) décrivant ce que vous avez modifié :   ```yaml
   changelog:
     - version: "1.1.0"
       date: "2026-08-05"
       author: "Your Name"
       changes: "Expanded the ecosystem section with packaging tools"
     - version: "1.0.0"
       date: "2026-08-05"
       author: "AI Model Training Team"
       changes: "Added YAML frontmatter metadata for contributor tracking"
   ```
3. **Mettez à jour`last_modified`** à la date de votre modification
4. **Ajoutez-vous à`contributors`** s'il s'agit de votre première modification du fichier :   ```yaml
   contributors:
     - name: "Your Name"
       email: "you@example.com"
       role: "contributor"
   ```

### Liste de contrôle qualité
Avant de soumettre un fichier de base de connaissances nouveau ou modifié, vérifiez :
- [ ] Le contenu YAML est complet et valide (les cinq sections sont présentes, entre les délimiteurs `---`)
- [ ]`title`,`description`,`category`,`version`,`status`sont définis
- [ ] Au moins un auteur est répertorié dans`authors`
- [ ]`changelog`a une entrée documentant le changement (le plus récent en premier)
- [ ]`last_modified`reflète la date d'aujourd'hui
- [ ]`tags`inclut 3 à 6 mots-clés pertinents plus le mot-clé de catégorie propre
- [ ]`difficulty_level`est défini (débutant / intermédiaire / avancé)
-[ ]`estimated_reading_time`est réaliste pour la longueur du contenu
-[ ] Le contenu du corps suit le[Usage Guidelines](#usage-guidelines)ci-dessus
-[ ] Pas de références croisées brisées
