#พร้อมวิศวะ

วิศวกรรมพร้อมท์คือแนวทางปฏิบัติในการออกแบบ ปรับแต่ง และเพิ่มประสิทธิภาพพรอมต์อินพุตเพื่อให้ได้ผลลัพธ์ที่ดีที่สุดเท่าที่จะเป็นไปได้จากโมเดลภาษา เป็นทั้งศิลปะและวิทยาศาสตร์ และเป็นอินเทอร์เฟซหลักสำหรับการควบคุมพฤติกรรม LLM โดยไม่ต้องปรับแต่งอย่างละเอียด

---

## หลักการสำคัญ

### ความชัดเจนและความเฉพาะเจาะจง
ข้อความแจ้งที่ชัดเจนทำให้ไม่มีที่ว่างสำหรับความคลุมเครือ ระบุสิ่งที่คุณต้องการให้แน่ชัด รวมถึงรูปแบบ ความยาว และเปอร์สเปคทีฟ

**คลุมเครือ:**
> "บอกฉันเกี่ยวกับ Python"

**เฉพาะ:**
> "อธิบาย Global Interpreter Lock (GIL) ของ Python อธิบายผลกระทบของมันต่อมัลติเธรด ให้วิธีแก้ปัญหาหนึ่งอย่าง และทำให้คำตอบของคุณมีความยาวไม่เกิน 200 คำ"

### ระบุบริบท
โมเดลจะทำงานได้ดีขึ้นเมื่อทราบบทบาท ผู้ชม และเป้าหมาย

**ไม่มีบริบท:**
> "เขียนฟังก์ชันเพื่อจัดเรียงรายการ"

**พร้อมบริบท:**
> "คุณเป็นนักพัฒนา Python อาวุโส เขียนฟังก์ชันเพื่อจัดเรียงรายการพจนานุกรมตามคีย์ที่กำหนด ใช้คำใบ้ประเภทและจัดการกับกรณีขอบ ผู้ฟังคือนักพัฒนารุ่นน้อง"

### ใช้คำแนะนำเชิงบวก
บอกโมเดลว่าต้องทำอะไร ไม่ใช่สิ่งที่ควรหลีกเลี่ยง “อย่าใส่ศัพท์แสง” อ่อนกว่า “ใช้ภาษาง่ายๆ ที่เด็กอายุ 10 ขวบเข้าถึงได้”

## โครงสร้างที่รวดเร็ว

### บทบาทระบบ / ผู้ใช้ / ผู้ช่วย
LLM API ส่วนใหญ่รองรับโครงสร้างแบบหลายเทิร์น:

- **ข้อความของระบบ**: ตั้งค่าพฤติกรรม บุคลิก และข้อจำกัดของโมเดล (คงอยู่ตลอดทั้งเซสชัน)
- **ข้อความผู้ใช้**: ข้อความค้นหาหรือคำสั่งปัจจุบัน
- **ข้อความผู้ช่วย**: การตอบกลับก่อนหน้าของโมเดล (ใช้เพื่อความต่อเนื่อง)

**ตัวอย่าง (รูปแบบ OpenAI API):**
ระบบ: คุณเป็นผู้ช่วยเขียนโค้ดที่มีประโยชน์ คุณตอบกลับด้วยตัวอย่างโค้ดที่กระชับและคำอธิบายสั้นๆ อย่าให้รหัสที่ไม่ปลอดภัย
ผู้ใช้: เขียนฟังก์ชัน Python เพื่อดาวน์โหลดไฟล์จาก URL

### พร้อมท์ไม่กี่ช็อต
ให้ตัวอย่างรูปแบบอินพุต-เอาต์พุตที่ต้องการ 2–3 ตัวอย่างก่อนขอให้แบบจำลองดำเนินการ สิ่งนี้จะสอนรูปแบบ

**ตัวอย่าง:**
ผู้ใช้: แปลงประโยคเหล่านี้เป็นเสียงที่ไม่โต้ตอบ:
ข้อมูลเข้า: แมวไล่หนู
ผลลัพธ์: หนูถูกแมวไล่ล่า
ข้อมูลนำเข้า: พ่อครัวปรุงอาหาร
ผลลัพธ์: อาหารปรุงโดยเชฟ
ข้อมูลเข้า: พายุทำลายบ้าน
เอาท์พุต: (โมเดลเสร็จสมบูรณ์)

### ห่วงโซ่แห่งความคิด (CoT)
ส่งเสริมให้แบบจำลองแสดงเหตุผลทีละขั้นตอน ซึ่งช่วยปรับปรุงความแม่นยำในงานเลขคณิต ตรรกะ และงานหลายขั้นตอน

**ไม่มีเปล:**
> "24 × 37 คืออะไร"

**มีเตียงเด็กอ่อน:**
> "คำนวณ 24 × 37 แสดงเหตุผลของคุณทีละขั้นตอน"

แบบจำลองจะสร้างขั้นตอนกลาง ซึ่งช่วยลดข้อผิดพลาดทางคณิตศาสตร์

### ผลลัพธ์ที่มีโครงสร้าง
ขอรูปแบบเฉพาะ เช่น JSON, YAML หรือตารางมาร์กดาวน์เพื่อให้การแยกวิเคราะห์เชื่อถือได้
ผู้ใช้: ระบุข้อดีสามประการและข้อเสียสามประการของไมโครเซอร์วิส ส่งคืนเฉพาะออบเจ็กต์ JSON ที่ถูกต้องซึ่งมีคีย์ "pros" และ "cons" โดยแต่ละรายการเป็นอาร์เรย์ของสตริง

## เทคนิคขั้นสูง

### ความสม่ำเสมอในตนเอง
สร้างคำตอบหลายรายการสำหรับข้อความแจ้งเดียวกัน (ที่มีอุณหภูมิ > 0) และลงคะแนนเสียงข้างมากในคำตอบสุดท้าย สิ่งนี้มีประสิทธิผลโดยเฉพาะสำหรับงานการให้เหตุผล

### ต้นไม้แห่งความคิด
สำรวจเส้นทางการให้เหตุผลหลายเส้นทางพร้อมกัน ประเมินแต่ละเส้นทาง และเลือกเส้นทางที่ดีที่สุด นี่เป็นเทคนิคระดับการวิจัย แต่สามารถประมาณได้โดยการขอให้แบบจำลอง "สำรวจวิธีแก้ปัญหาทางเลือก"

### ปฏิกิริยา (การใช้เหตุผล + การแสดง)
ให้แบบจำลองแทรกการใช้เหตุผลด้วยการเรียกเครื่องมือ สามารถคิดแล้วดำเนินการ (เช่น ค้นหาเว็บ รันโค้ด) แล้วคิดใหม่ตามผลลัพธ์

**โครงสร้างพร้อมท์:**
คุณสามารถเข้าถึงเครื่องคิดเลขและเครื่องมือค้นหาได้ สำหรับแต่ละขั้นตอน ผลลัพธ์:
คิด: (เหตุผลของคุณ)
การดำเนินการ: (ชื่อเครื่องมือ อินพุต)
การสังเกต: (เอาท์พุตเครื่องมือ)
...ทำต่อไปจนกว่าจะได้คำตอบสุดท้าย

### การกำหนดบุคคล
กำหนดบุคลิกเฉพาะเพื่อกำหนดกรอบการตอบสนอง

**ตัวอย่าง:**
- "คุณเป็นนักพัฒนาเคอร์เนล Linux ที่กำลังอธิบายการจัดการหน่วยความจำให้กับบัณฑิตใหม่"
- "คุณเป็นนักโภชนาการที่เป็นมิตรคอยให้คำแนะนำทั่วไปแก่ลูกค้า"
- "คุณเป็นนักวิจารณ์เทคโนโลยีที่เหยียดหยามวิจารณ์อุปกรณ์ใหม่"

## การปรับพารามิเตอร์

- **อุณหภูมิ** (0.0 – 1.0+): ควบคุมการสุ่ม ต่ำ = กำหนดได้มากขึ้น สูงขึ้น = สร้างสรรค์มากขึ้น ใช้ 0.0–0.3 สำหรับคำตอบที่เป็นข้อเท็จจริง 0.7–1.0 สำหรับการเขียนเชิงสร้างสรรค์
- **Top-p** (การสุ่มตัวอย่างนิวเคลียส): ตัดมวลความน่าจะเป็นออกที่เกณฑ์สะสมที่แน่นอน 0.9 หมายถึงตัวอย่างโมเดลจาก 90% แรกของโทเค็นที่เป็นไปได้ มักจะปรับอุณหภูมิหรือ top-p ไม่ใช่ทั้งสองอย่าง
- **โทเค็นสูงสุด**: ตั้งค่าความยาวเอาต์พุตสูงสุด อย่าลืมจองพื้นที่สำหรับการตอบกลับภายในหน้าต่างบริบท
- **การลงโทษความถี่**: ลดการทำซ้ำของโทเค็นเดียวกัน
- **การลงโทษการแสดงตน**: ส่งเสริมให้โมเดลแนะนำหัวข้อใหม่

## การประเมินคำแนะนำ

ถือว่าพรอมต์เป็นโค้ด: กำหนดเวอร์ชัน ทดสอบ และทำซ้ำ

- **การทดสอบ A/B** รูปแบบข้อความแจ้งที่แตกต่างกันสำหรับชุดข้อความค้นหาที่ถูกระงับ
- **วัดความสำเร็จ** ผ่านการประเมินโดยมนุษย์หรือตัวชี้วัดอัตโนมัติ (เช่น การจับคู่แบบตรงทั้งหมด, BLEU, การให้คะแนนแบบกำหนดเอง)
- **เก็บพรอมต์รีจิสทรี** (ไฟล์ข้อความธรรมดาหรือสเปรดชีต) พร้อมด้วยพรอมต์ เวอร์ชัน และประสิทธิภาพที่สังเกตได้
