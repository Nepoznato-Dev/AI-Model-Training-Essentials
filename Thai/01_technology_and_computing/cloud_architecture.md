# สถาปัตยกรรมคลาวด์

## พื้นฐานคอมพิวเตอร์คลาวด์

### Cloud Computing คืออะไร?
การจัดส่งทรัพยากรคอมพิวเตอร์ตามความต้องการ (เซิร์ฟเวอร์ พื้นที่เก็บข้อมูล ฐานข้อมูล ระบบเครือข่าย ซอฟต์แวร์) ผ่านทางอินเทอร์เน็ต โดยมีการกำหนดราคาแบบจ่ายตามที่ใช้งาน

### ลักษณะสำคัญ (คำจำกัดความของ NIST)
- **การบริการตนเองตามความต้องการ**: จัดเตรียมทรัพยากรโดยไม่ต้องมีปฏิสัมพันธ์กับมนุษย์
- **การเข้าถึงเครือข่ายแบบกว้าง**: ใช้งานได้ผ่านเครือข่ายผ่านกลไกมาตรฐาน
- **การรวมทรัพยากร**: โมเดลที่มีผู้เช่าหลายรายพร้อมการมอบหมายแบบไดนามิก
- **ความยืดหยุ่นอย่างรวดเร็ว**: ขยายขนาดทั้งด้านนอกและด้านในอย่างรวดเร็ว
- **บริการที่วัดผล**: มีการตรวจสอบและเรียกเก็บเงินการใช้ทรัพยากร

### โมเดลการใช้งานคลาวด์
- **คลาวด์สาธารณะ**: เป็นเจ้าของโดยผู้ให้บริการ โครงสร้างพื้นฐานที่ใช้ร่วมกัน (AWS, Azure, GCP)
- **Private Cloud**: เฉพาะองค์กรเดียว (ภายในองค์กรหรือโฮสต์)
- **ไฮบริดคลาวด์**: การผสมผสานระหว่างคลาวด์สาธารณะและคลาวด์ส่วนตัว
- **Multi-Cloud**: ใช้ผู้ให้บริการคลาวด์สาธารณะหลายราย
- **Community Cloud**: แบ่งปันโดยองค์กรที่มีข้อกังวลร่วมกัน

### รูปแบบการให้บริการ

#### โครงสร้างพื้นฐานเป็นบริการ (IaaS)
- **ให้**: เครื่องเสมือน พื้นที่เก็บข้อมูล เครือข่าย ระบบปฏิบัติการ
- **ตัวอย่าง**: AWS EC2, Google Compute Engine, Azure VM
- **กรณีการใช้งาน**: การโยกย้ายแบบยกและเปลี่ยน สภาพแวดล้อมการพัฒนา ความต้องการการควบคุมระดับสูง

#### แพลตฟอร์มเป็นบริการ (PaaS)
- **ให้**: แพลตฟอร์มการพัฒนา ฐานข้อมูล มิดเดิลแวร์
- **ตัวอย่าง**: Heroku, Google App Engine, AWS Elastic Beanstalk
- **กรณีการใช้งาน**: การพัฒนาแอปพลิเคชัน, การปรับใช้ API, ไมโครเซอร์วิส

#### ซอฟต์แวร์เป็นบริการ (SaaS)
- **ให้**: กรอกใบสมัครผ่านอินเทอร์เน็ต
- **ตัวอย่าง**: Salesforce, Google Workspace, Microsoft 365, Slack
- **กรณีการใช้งาน**: อีเมล, CRM, การทำงานร่วมกัน, แอปพลิเคชันทางธุรกิจ

#### ฟังก์ชั่นเป็นบริการ (FaaS) / ไร้เซิร์ฟเวอร์
- **ให้**: การเรียกใช้ฟังก์ชันที่ขับเคลื่อนด้วยเหตุการณ์
- **ตัวอย่าง**: AWS Lambda, ฟังก์ชัน Azure, ฟังก์ชัน Google Cloud
- **กรณีการใช้งาน**: การประมวลผลเหตุการณ์, API, งานที่กำหนดเวลาไว้, การประมวลผลแบบเรียลไทม์

## ผู้ให้บริการคลาวด์รายใหญ่

### อเมซอนเว็บเซอร์วิส (AWS)
- **ส่วนแบ่งการตลาด**: ~32% (ผู้ให้บริการรายใหญ่ที่สุด)
- **บริการสำคัญ**:
  - คำนวณ: EC2, แลมบ์ดา, ECS, EKS
  - ที่เก็บข้อมูล: S3, EBS, กลาเซียร์
  - ฐานข้อมูล: RDS, DynamoDB, ออโรร่า
  - ระบบเครือข่าย: VPC, เส้นทาง 53, CloudFront
  - AI/ML: SageMaker, การรับรู้, เข้าใจ

### ไมโครซอฟต์ อาซัวร์
- **ส่วนแบ่งการตลาด**: ~23%
- **จุดแข็ง**: การบูรณาการระดับองค์กร, ไฮบริดคลาวด์, ระบบนิเวศของ Microsoft
- **บริการสำคัญ**:
  - คำนวณ: เครื่องเสมือน, ฟังก์ชัน Azure, AKS
  - ที่เก็บข้อมูล: ที่เก็บข้อมูล Blob, ที่เก็บข้อมูลดิสก์
  - ฐานข้อมูล: ฐานข้อมูล SQL, ฐานข้อมูลคอสมอส
  - ระบบเครือข่าย: เครือข่ายเสมือน, ตัวจัดการการรับส่งข้อมูล
  - AI/ML: Azure ML บริการด้านความรู้ความเข้าใจ

### แพลตฟอร์มคลาวด์ของ Google (GCP)
- **ส่วนแบ่งการตลาด**: ~10%
- **จุดแข็ง**: การวิเคราะห์ข้อมูล, AI/ML, Kubernetes
- **บริการสำคัญ**:
  - คำนวณ: Compute Engine, ฟังก์ชันคลาวด์, GKE
  - ที่เก็บข้อมูล: ที่เก็บข้อมูลบนคลาวด์, ดิสก์ถาวร
  - ฐานข้อมูล: Cloud SQL, Firestore, Bigtable
  - การวิเคราะห์: BigQuery, Dataflow, Pub/Sub
  - AI/ML: จุดยอด AI, AutoML

### ผู้ให้บริการรายอื่น
- **IBM Cloud**: การมุ่งเน้นระดับองค์กร, Watson AI
- **Oracle Cloud**: ปริมาณงานฐานข้อมูล แอปพลิเคชันระดับองค์กร
- **Alibaba Cloud**: โดดเด่นในเอเชียแปซิฟิก
- **DigitalOcean**: ข้อเสนอที่เป็นมิตรกับนักพัฒนาและเรียบง่าย

## รูปแบบสถาปัตยกรรมคลาวด์

### หลักการกรอบงานที่มีการออกแบบอย่างดี

#### ความเป็นเลิศในการปฏิบัติงาน
- การดำเนินการอัตโนมัติ
- ทำการเปลี่ยนแปลงบ่อยครั้งและย้อนกลับได้
- ปรับปรุงขั้นตอนอย่างต่อเนื่อง
- คาดการณ์ความล้มเหลว

#### ความปลอดภัย
- ใช้รากฐานอัตลักษณ์ที่แข็งแกร่ง
- เปิดใช้งานการตรวจสอบย้อนกลับ
- ใส่ความปลอดภัยทุกชั้น
- แนวทางปฏิบัติที่ดีที่สุดด้านความปลอดภัยโดยอัตโนมัติ
- ปกป้องข้อมูลระหว่างการขนส่งและที่เหลือ

#### ความน่าเชื่อถือ
- ทดสอบขั้นตอนการกู้คืน
- กู้คืนจากความล้มเหลวโดยอัตโนมัติ
- ปรับขนาดในแนวนอนเพื่อความพร้อมใช้งาน
- หยุดคาดเดาความสามารถ
- จัดการการเปลี่ยนแปลงในระบบอัตโนมัติ

#### ประสิทธิภาพการทำงาน
- ทำให้เทคโนโลยีขั้นสูงเป็นประชาธิปไตย
- ไปทั่วโลกในไม่กี่นาที
- ใช้สถาปัตยกรรมแบบไร้เซิร์ฟเวอร์
- ทดลองให้บ่อยขึ้น
- พิจารณาความเห็นอกเห็นใจทางกล

#### การเพิ่มประสิทธิภาพต้นทุน
- ใช้รูปแบบการบริโภค
- วัดประสิทธิภาพโดยรวม
- หยุดใช้จ่ายเงินกับงานที่ไม่แตกต่าง
- วิเคราะห์และระบุรายจ่าย
- ใช้บริการที่มีการจัดการ

### รูปแบบสถาปัตยกรรมทั่วไป

#### สถาปัตยกรรมไมโครเซอร์วิส
- แยกแอปพลิเคชันออกเป็นบริการขนาดเล็กและเป็นอิสระ
- แต่ละบริการเป็นเจ้าของข้อมูลและตรรกะ
- สื่อสารผ่าน API (REST, gRPC, การส่งข้อความ)
- ปรับใช้อย่างอิสระ
- **คุณประโยชน์**: ความสามารถในการปรับขนาด การแยกข้อผิดพลาด ความหลากหลายของเทคโนโลยี
- **ความท้าทาย**: การกระจายความซับซ้อน ความสอดคล้องของข้อมูล การตรวจสอบ

#### สถาปัตยกรรมที่ขับเคลื่อนด้วยเหตุการณ์
- ส่วนประกอบสื่อสารผ่านเหตุการณ์
- ผู้ผลิตปล่อยกิจกรรม ผู้บริโภคโต้ตอบ
- **รูปแบบ**: การจัดหากิจกรรม, CQRS, pub/sub
- **เทคโนโลยี**: Kafka, SNS/SQS, EventBridge, Pub/Sub
- **ข้อดี**: การมีเพศสัมพันธ์แบบหลวม ความสามารถในการขยายขนาด การประมวลผลแบบเรียลไทม์

#### สถาปัตยกรรมแบบไร้เซิร์ฟเวอร์
- ไม่จำเป็นต้องจัดการเซิร์ฟเวอร์
- จ่ายต่อการดำเนินการ
- ปรับขนาดอัตโนมัติ
- **ส่วนประกอบ**: ฟังก์ชัน, เกตเวย์ API, บริการที่ได้รับการจัดการ
- **ข้อดี**: ประหยัดค่าใช้จ่าย ลดการดำเนินงาน ปรับใช้อย่างรวดเร็ว
- **ข้อควรพิจารณา**: Cold Start, การล็อคอินของผู้ขาย, ขีดจำกัดการดำเนินการ

#### สถาปัตยกรรมแบบเลเยอร์ (N-Tier)
- ชั้นการนำเสนอ (UI)
- เลเยอร์ตรรกะของแอปพลิเคชัน/ธุรกิจ
- ชั้นการเข้าถึงข้อมูล
- ชั้นฐานข้อมูล
- **ข้อดี**: การแยกข้อกังวล ความสามารถในการบำรุงรักษา
- **ทั่วไป**: เว็บแอปพลิเคชัน 3 ระดับ

#### สถาปัตยกรรมบนอวกาศ
- จัดการการทำงานพร้อมกันในระดับสูงด้วยข้อมูลที่กระจาย
- หน่วยความจำเสมือนข้ามเซิร์ฟเวอร์
- การประมวลผลโหนดปรับขนาดได้อย่างอิสระ
- **กรณีการใช้งาน**: แอปพลิเคชันปริมาณมากและเวลาแฝงต่ำ

## บริการคอมพิวเตอร์

### เครื่องเสมือน
- **ประเภท**: วัตถุประสงค์ทั่วไป, เพิ่มประสิทธิภาพการประมวลผล, เพิ่มประสิทธิภาพหน่วยความจำ, GPU
- **ราคา**: อินสแตนซ์แบบตามความต้องการ อินสแตนซ์แบบเหมาจ่าย และอินสแตนซ์สปอต
- **การจัดการ**: กลุ่มการปรับขนาดอัตโนมัติ ตัวจัดสรรภาระงาน
- **แนวทางปฏิบัติที่ดีที่สุด**: การกำหนดขนาดที่เหมาะสม การแท็ก การตรวจสอบ และการแพตช์

### คอนเทนเนอร์
- **นักเทียบท่า**: มาตรฐานรันไทม์ของคอนเทนเนอร์
- **การเรียบเรียง**: Kubernetes (EKS, AKS, GKE), ECS, Fargate
- **คุณประโยชน์**: ความสะดวกในการพกพา ประสิทธิภาพ ความสม่ำเสมอ
- **รีจิสทรี**: ECR, GCR, ACR, Docker Hub

### ฟังก์ชั่นไร้เซิร์ฟเวอร์
- **โมเดลการดำเนินการ**: กระตุ้นด้วยเหตุการณ์ ไร้สัญชาติ
- **ข้อจำกัด**: เวลาดำเนินการ หน่วยความจำ การดำเนินการพร้อมกัน
- **กรณีการใช้งาน**: API, การประมวลผลไฟล์, งานที่กำหนดเวลาไว้, แบ็กเอนด์ IoT
- **การตรวจสอบ**: จำนวนการเรียกใช้ ข้อผิดพลาด ระยะเวลา การเริ่มเย็น

## โซลูชั่นการจัดเก็บข้อมูล

### การจัดเก็บวัตถุ
- **ลักษณะเฉพาะ**: โครงสร้างแบบเรียบ ข้อมูลเมตา การเข้าถึง HTTP
- **ตัวอย่าง**: AWS S3, Google Cloud Storage, Azure Blob
- **กรณีการใช้งาน**: สินทรัพย์คงที่ การสำรองข้อมูล ที่จัดเก็บข้อมูลดิบ คลังข้อมูล
- **คลาสการจัดเก็บ**: ร้อน เย็น เย็น เก็บถาวร (ต้นทุน/การเข้าถึงที่แตกต่างกัน)

### บล็อกพื้นที่เก็บข้อมูล
- **ลักษณะเฉพาะ**: วอลุ่มดิบ ที่แนบกับ VM
- **ตัวอย่าง**: AWS EBS, Google Persistent Disk, Azure Disk
- **กรณีการใช้งาน**: ฐานข้อมูล วอลลุมสำหรับบูท ความต้องการประสิทธิภาพสูง
- **ประเภท**: SSD, HDD, IOPS ที่จัดเตรียมไว้

### การจัดเก็บไฟล์
- **ลักษณะเฉพาะ**: ระบบไฟล์ที่ใช้ร่วมกัน โปรโตคอล NFS/SMB
- **ตัวอย่าง**: AWS EFS, Google Filestore, ไฟล์ Azure
- **กรณีการใช้งาน**: การจัดการเนื้อหา การกำหนดค่าที่ใช้ร่วมกัน การยกและเปลี่ยน

### พื้นที่เก็บข้อมูลถาวร
- **ลักษณะเฉพาะ**: ต้นทุนต่ำสุด ความล่าช้าในการเรียกค้น
- **ตัวอย่าง**: S3 Glacier, Azure Archive Storage
- **กรณีการใช้งาน**: การปฏิบัติตามข้อกำหนด การสำรองข้อมูลระยะยาว ข้อมูลประวัติ

## บริการฐานข้อมูล

### ฐานข้อมูลเชิงสัมพันธ์ที่ได้รับการจัดการ
- **บริการ**: AWS RDS/Aurora, Google Cloud SQL, ฐานข้อมูล Azure SQL
- **คุณสมบัติ**: การสำรองข้อมูลอัตโนมัติ การแพตช์ การปรับขนาด การจำลองแบบ
- **เครื่องยนต์**: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server

### ฐานข้อมูล NoSQL
- **เอกสาร**: DocumentDB, Firestore, Cosmos DB
- **คีย์-ค่า**: DynamoDB, แคช Redis
- **คอลัมน์กว้าง**: Bigtable, Cassandra (จัดการ)
- **กราฟ**: ดาวเนปจูน, Cosmos DB (กราฟ API)

### คลังข้อมูล
- **บริการ**: สโนว์เฟลก, Redshift, BigQuery, ไซแนปส์
- **ลักษณะเฉพาะ**: การจัดเก็บแบบเรียงเป็นแนว สถาปัตยกรรม MPP
- **กรณีการใช้งาน**: การวิเคราะห์, BI, การวิเคราะห์ข้อมูลขนาดใหญ่

### บริการแคช
- **ในหน่วยความจำ**: ElastiCache (Redis/Memcached), Cloud Memorystore
- **การแคช CDN**: CloudFront, Cloud CDN, Azure CDN
- **กรณีการใช้งาน**: พื้นที่จัดเก็บเซสชัน การแคชแบบสอบถาม การจัดส่งเนื้อหา

## เครือข่าย

### เครือข่ายเสมือน
- **VPC/VNet**: สภาพแวดล้อมเครือข่ายแบบแยก
- **ซับเน็ต**: สาธารณะ (เชื่อมต่ออินเทอร์เน็ต), ส่วนตัว (ภายในเท่านั้น)
- **การกำหนดที่อยู่ IP**: บล็อก CIDR, IPv4/IPv6
- **ตารางเส้นทาง**: ควบคุมการไหลของการจราจร

### โหลดบาลานซ์
- **ประเภท**: แอปพลิเคชัน (L7), เครือข่าย (L4), เกตเวย์
- **คุณสมบัติ**: การตรวจสุขภาพ การยกเลิก SSL เซสชันที่ติดหนึบ
- **บริการ**: ELB/ALB/NLB, Cloud Load Balancing, Azure Load Balancer

### เครือข่ายการจัดส่งเนื้อหา (CDN)
- **วัตถุประสงค์**: เนื้อหาแคชที่ตำแหน่ง Edge
- **ข้อดี**: เวลาแฝงที่ลดลง โหลดต้นทางที่ลดลง การกระจายทั่วโลก
- **บริการ**: CloudFront, Cloud CDN, Azure CDN, Akamai

### บริการ DNS
- **ฟังก์ชัน**: การจดทะเบียนโดเมน การกำหนดเส้นทาง การตรวจสุขภาพ
- **บริการ**: เส้นทาง 53, Cloud DNS, Azure DNS
- **นโยบายการกำหนดเส้นทาง**: แบบง่าย ถ่วงน้ำหนัก อิงตามเวลาแฝง ตำแหน่งทางภูมิศาสตร์ เฟลโอเวอร์

### ตัวเลือกการเชื่อมต่อ
- **เกตเวย์อินเทอร์เน็ต**: การเข้าถึงอินเทอร์เน็ตสาธารณะ
- **เกตเวย์ NAT**: การเข้าถึงเครือข่ายย่อยส่วนตัวขาออก
- **VPN**: อุโมงค์ที่เข้ารหัสไปยังภายในองค์กร
- **Direct Connect/ExpressRoute**: การเชื่อมต่อส่วนตัวโดยเฉพาะ
- **การเพียร์ VPC**: เชื่อมต่อ VPC ภายใน/ระหว่างบัญชี

## ความปลอดภัยในระบบคลาวด์

### โมเดลความรับผิดชอบร่วมกัน
- **ความรับผิดชอบของผู้ให้บริการ**: ความปลอดภัยของระบบคลาวด์ (โครงสร้างพื้นฐาน)
- **ความรับผิดชอบของลูกค้า**: ความปลอดภัยในระบบคลาวด์ (ข้อมูล แอปพลิเคชัน การเข้าถึง)
- **แตกต่างกันไปตามบริการ**: มีการจัดการมากขึ้น = ความรับผิดชอบของผู้ให้บริการมากขึ้น

### การจัดการข้อมูลประจำตัวและการเข้าถึง (IAM)
- **ผู้ใช้**: ตัวตนส่วนบุคคล
- **กลุ่ม**: คอลเล็กชันของผู้ใช้
- **บทบาท**: ข้อมูลรับรองชั่วคราวสำหรับบริการ/ผู้ใช้
- **นโยบาย**: เอกสาร JSON ที่กำหนดสิทธิ์
- **หลักการ**: สิทธิพิเศษน้อยที่สุด การแบ่งแยกหน้าที่

### ความปลอดภัยเครือข่าย
- **กลุ่มความปลอดภัย**: ไฟร์วอลล์เก็บสถานะสำหรับอินสแตนซ์
- **Network ACLs**: ไฟร์วอลล์ไร้สัญชาติสำหรับซับเน็ต
- **ไฟร์วอลล์แอปพลิเคชันเว็บ (WAF)**: ป้องกันการโจมตีจากเว็บ
- **การป้องกัน DDoS**: โล่, เกราะคลาวด์, การป้องกัน DDoS

### การปกป้องข้อมูล
- **การเข้ารหัสเมื่อพัก**: KMS คีย์ที่จัดการโดยลูกค้า
- **การเข้ารหัสระหว่างทาง**: TLS/SSL, HTTPS
- **การจัดการคีย์**: HSM, การหมุนเวียนคีย์, เส้นทางการตรวจสอบ
- **การจัดการความลับ**: ผู้จัดการความลับ, Key Vault

### การปฏิบัติตามและการกำกับดูแล
- **ใบรับรอง**: SOC 2, ISO 27001, HIPAA, PCI-DSS, GDPR
- **เครื่องมือ**: การบังคับใช้นโยบาย การรายงานการปฏิบัติตามข้อกำหนด บันทึกการตรวจสอบ
- **เฟรมเวิร์ก**: Cloud Security Alliance, NIST CSF

## การจัดการต้นทุน

### โมเดลการกำหนดราคา
- **จ่ายตามการใช้งาน**: จ่ายตามที่คุณใช้
- **อินสแตนซ์แบบเหมาจ่าย**: ข้อผูกพัน 1-3 ปี พร้อมส่วนลดจำนวนมาก
- **สปอตอินสแตนซ์**: การประมูลสำหรับความจุที่ไม่ได้ใช้ สามารถถูกขัดจังหวะได้
- **แผนการออมทรัพย์**: การกำหนดราคาตามสัญญาที่ยืดหยุ่น
- **ระดับฟรี**: การใช้งานฟรีแบบจำกัดสำหรับบัญชีใหม่

### กลยุทธ์การเพิ่มประสิทธิภาพต้นทุน
- **ขนาดที่เหมาะสม**: จับคู่ประเภทอินสแตนซ์กับความต้องการปริมาณงาน
- **ปรับขนาดอัตโนมัติ**: ปรับขนาดตามความต้องการ
- **ความจุที่สงวนไว้**: ยอมรับภาระงานในสภาวะคงที่
- **การใช้งานเฉพาะจุด**: ใช้สำหรับปริมาณงานที่ยืดหยุ่นและทนทานต่อข้อผิดพลาด
- **ระดับการจัดเก็บข้อมูล**: ย้ายข้อมูลไม่บ่อยนักไปยังระดับที่ถูกกว่า
- **การล้างข้อมูล**: ลบทรัพยากร สแน็ปช็อต และ AMI ที่ไม่ได้ใช้

### เครื่องมือบริหารจัดการต้นทุน
- **AWS**: ตัวสำรวจต้นทุน งบประมาณ ที่ปรึกษาที่เชื่อถือได้
- **Azure**: การจัดการต้นทุน, ที่ปรึกษา
- **GCP**: รายงานการเรียกเก็บเงิน ผู้แนะนำ
- **บุคคลที่สาม**: CloudHealth, CloudCheckr, Datadog

## ความพร้อมใช้งานสูงและการกู้คืนความเสียหาย

### แนวคิดเรื่องความพร้อมใช้งาน
- **Availability Zones**: ศูนย์ข้อมูลที่แยกจากกันทางกายภาพภายในภูมิภาค
- **ภูมิภาค**: พื้นที่ทางภูมิศาสตร์ที่มี AZ หลายรายการ
- **ตำแหน่ง Edge**: ตำแหน่งแคช CDN ทั่วโลก

### กลยุทธ์ HA
- **หลาย AZ**: ปรับใช้ข้ามโซนความพร้อมใช้งาน
- **การรักษาอัตโนมัติ**: แทนที่อินสแตนซ์ที่ล้มเหลวโดยอัตโนมัติ
- **การปรับสมดุลโหลด**: กระจายการรับส่งข้อมูลไปยังอินสแตนซ์ที่มีประสิทธิภาพ
- **การจำลองฐานข้อมูล**: การปรับใช้หลาย AZ, การจำลองการอ่าน

### กลยุทธ์การกู้คืนความเสียหาย
- **สำรองและกู้คืน**: สำรองข้อมูลเป็นระยะ กู้คืนเมื่อจำเป็น (ต้นทุนต่ำสุด)
- **ไฟนำร่อง**: องค์ประกอบหลักที่ทำงานอยู่ ขยายขนาดระหว่างเกิดภัยพิบัติ
- **Warm Standby**: เวอร์ชันลดขนาดจะทำงานอยู่เสมอ
- **ใช้งานหลายไซต์/ใช้งานอยู่**: การผลิตเต็มรูปแบบในหลายภูมิภาค (ต้นทุนสูงสุด)

### RTO และ RPO
- **วัตถุประสงค์เวลาการกู้คืน (RTO)**: เวลาหยุดทำงานสูงสุดที่ยอมรับได้
- **Recovery Point Objective (RPO)**: การสูญเสียข้อมูลสูงสุดที่ยอมรับได้
- **การเลือกกลยุทธ์**: ตามความต้องการทางธุรกิจและงบประมาณ
